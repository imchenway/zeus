# TASK_20260724_001 创建任务弹窗精简与优先级下拉

## 任务状态

已完成。

## 用户反馈

1. 创建任务弹窗的说明性文字过多，影响信息密度。
2. 优先级不应是只读文本框，应改成可以真实保存的下拉框。

## 已确认决策

- 删除弹窗标题下说明、字段下重复帮助文案、上下文来源卡片、Runtime 提示和空附件占位。
- 保留字段标签、简短占位、错误反馈和附件操作。
- 附件区只提示“支持粘贴或选择本机文件”。
- 优先级使用以下五级：
  - P0：立即开始处理
  - P1：紧急且重要
  - P2：紧急不重要
  - P3：重要不紧急
  - P4：不重要不紧急
- 新建任务默认 P3。
- P0 只表示最高处理优先级，不自动启动 AI、会话或执行轮次。
- 历史 `normal` 数据不兼容、不迁移。

## 源码事实

- 原创建弹窗把优先级渲染成禁用的只读输入框，固定显示 `normal`。
- 原创建请求没有传递优先级。
- 原任务仓储在创建记录时固定写入 `normal`。

## 本轮实现

- 在共享领域类型中新增 `TaskPriority`、固定顺序和运行时校验。
- 创建任务表单状态、draft、renderer API、local-server 和 SQLite 写入链路贯通 `p0` 至 `p4`。
- 所有未显式指定优先级的新任务默认写入 `p3`。
- 创建任务弹窗复用 `ZeusSelect`，短列表关闭搜索框，并保留键盘、焦点和禁用状态。
- 删除已确认的冗余文案和对应 DOM/CSS 残留。

## 2026-07-24 下拉浮层回归修复

- 现场反馈：展开优先级时，下拉内容扩大了弹窗正文的滚动区域，视觉上把弹窗底部撑开。
- 根因：原 `ZeusSelect` 的绝对定位弹层仍是滚动容器的后代；它虽不参与普通布局，仍会进入滚动溢出范围。
- 修复：共享 `ZeusSelect` 将展开层 portal 到应用壳层，按触发器视口坐标固定定位，并在窗口尺寸、触发器尺寸和祖先滚动变化时同步锚点。
- 防回归：`DESIGN.md` 新增 Select 原语硬约束，禁止业务页面把展开层留在滚动容器内；不增加项目已禁止的 DOM/CSS 契约测试。
