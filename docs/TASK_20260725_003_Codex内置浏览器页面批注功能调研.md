## 1. 调研目标

用户提供 `/Users/david/Downloads/iShot_2026-07-25_16.34.44.mp4`，要求先确认视频中的功能是否来自 Codex App，并调研其真实产品语义、数据边界和 Zeus 的实现路径。调研完成后，用户确认继续实施：范围是 Zeus 自身的内置浏览器、页面批注和 Agent 浏览器工具，不包含 Chrome 扩展、云端浏览器或插件市场。

## 2. 结论

视频展示的是当前 Codex App 内置 Browser 的页面批注功能，不是截图涂鸦，也不是代码审查评论。

该功能的核心不是“在网页上放一个评论气泡”，而是把下列能力组合成一个闭环：

1. 会话拥有一个关联的内置浏览器标签；
2. 用户点击元素、选择文本或拖选区域，形成可恢复的页面锚点；
3. 用户保存一条或多条页面批注，页面持续显示编号标记；
4. 可选的 `Adjust` 允许用户预览文字、字体、间距、颜色等变化；
5. 点击浏览器中的 `Send` 后，批注集合暂存到该浏览器标签所属会话的输入框，再由输入框沿用正常的发送、排队或 steer 链路；
6. 提交给 Codex 的内容包括结构化页面描述和可选标注截图，而不是只提交评论正文。

Codex App 当前做法表明：Zeus 首版不需要修改 Codex app-server 协议。页面批注可以在 Electron 产品层被序列化成普通文本输入，并把标注截图作为现有 `localImage` 输入一同发送。真正需要新增的是内置浏览器、页面注入运行时、批注领域数据和会话提交编排。

## 4. 页面批注实际携带的信息

Codex App 的单条页面批注至少包含以下几类上下文。

### 4.1 公共页面上下文

- 页面 URL；
- frame URL 与 frame 层级；
- 页面标题；
- App 主题；
- 批注时的 viewport 尺寸；
- 浏览器标签 ID；
- 标记在 viewport 中的位置。

### 4.2 元素锚点

- 可访问性 role 与 name；
- 稳定 selector；
- DOM element path；
- 元素即时文本；
- 邻近文本；
- 元素几何位置；
- iframe 路径；
- Shadow DOM host 路径；
- 滚动容器与 fixed 定位信息。

### 4.3 区域锚点

- 页面内矩形 `x / y / width / height`；
- 所在 frame；
- 对应 DOM 路径或文档上下文；
- 可选的多个附加选择。

### 4.4 文本锚点

- 选中文本；
- selection rects；
- DOM Range 的 selector、offset 和方向；
- 表单控件文本选择的 selector 与 offset。

因此，页面锚点不能退化为单个屏幕坐标。坐标只能用于展示；目标语义、selector、路径和邻近文本共同承担定位与恢复。

## 5. `Adjust` 的真实边界

`Adjust` 不是直接改项目源码。它先在当前页面中预览一组临时设计变化，再把变化作为“期望结果”交给 Codex。

已确认的变化数据包括：

- 文本 before / after；
- CSS property 的 previous / next；
- 目标 selector 和目标标签；
- viewport 与主题；
- 可选样式来源：selector、source URL、source line、source column；
- 用户补充评论。

页面预览使用临时属性和临时高优先级样式；提交给 Codex 时会明确要求修改真正拥有该 UI 的源码或设计令牌，不能把临时预览属性复制进项目。

这使 `Adjust` 比普通评论复杂一个数量级。本次实现仍将它纳入闭环，但只记录用户实际触碰的字段，并明确把页面预览标记为“实现意图”，不声明源码已经被修改。

## 6. 截图策略

当前 Codex App 有 `always / necessary` 两种页面批注截图策略，当前构建默认值为 `always`。

提交时：

- 元素批注可以附带带编号标记的页面截图；
- 区域批注可以附带带蓝色区域轮廓的页面截图；
- 评论可以另附用户图片；
- 多批注或大页面时可以使用裁剪/紧凑截图；
- 截图作为视觉佐证，结构化页面锚点仍是主要定位信息。

Zeus 已提供“始终截图 / 仅必要时截图”设置，默认“始终截图”。若系统暂时不能捕获显示表面，批注仍会保存并给出非阻塞错误，避免截图失败导致评论丢失。

## 7. 发送与会话语义

### 7.1 已确认事实

- 浏览器标签保存 `conversationId + browserTabId + browserStorageId`；
- 页面批注默认可以先保存多条，再一次发送；
- 浏览器中的 `Send N` 只负责把当前批注集合暂存到会话输入框，不直接提交模型；
- 批注提交被整理到 `Browser comments` 上下文；
- 每条批注会被编号，并描述 URL、frame、目标、selector、path、区域/文本、样式变化、评论和截图；
- 最终 provider 输入仍是普通 `text` 与可选 `localImage`；
- 当前执行中的会话可以 steer，空闲会话可以启动新 turn，其他情况进入既有队列。

### 7.2 对 Zeus 的直接含义

Zeus 不应为页面批注另造“批注会话”或“批注任务”。页面批注属于当前会话的一次提交，其发送状态必须复用当前 `conversation_submissions` 和队列状态机。

## 8. Zeus 实现前现状与缺口

### 8.1 已有能力

- Electron `42.4.0` 已提供 `WebContentsView`；
- 会话已经拥有 native Codex thread/turn、queue 和 steer；
- `conversation_submissions.input_json` 可以持久化扩展后的提交上下文；
- provider 输入已经支持普通文本、`localImage` 和文件 mention；
- Renderer 已有会话附件草稿、幂等发送和失败恢复；
- Zeus 随包内置 `codex-cli 0.145.0-alpha.30`。

### 8.2 实现起点的缺口

- 没有内置浏览器标签或浏览器 profile；
- 没有 `WebContentsView` 生命周期与布局协调；
- 没有页面注入 preload、锚点采集或页面覆盖层；
- 没有批注草稿、编号标记和页面导航后的恢复；
- 没有浏览器标签与 Zeus 会话的显式归属；
- 会话附件目前只表达本地文件，不能表达页面锚点和样式变化；
- 消息 API 当前要求非空文本，因此批注提交必须生成结构化文本上下文；
- 主窗口当前禁止外部导航并默认拒绝网页权限，不能直接拿主 Renderer 当浏览器；
- 没有站点 allow/block、下载、弹窗、权限、Cookie/profile 清理等浏览器安全策略。

### 8.3 版本差异

当前 Codex App 内置 Runtime 为 `0.146.0-alpha.3.1`，Zeus 内置 Runtime 为 `0.145.0-alpha.30`。但页面批注在 Codex App 产品层被降解为 app-server 已支持的普通文本和图片输入，因此首版不依赖升级 app-server。实现前仍应使用 Zeus 当前内置 Runtime 做真实双轮 probe，不能仅依据类型推断。

## 9. 建议的 Zeus 架构

### 9.1 Main 进程：Browser Host

新增由 Main 进程拥有的浏览器主机：

- 使用 `WebContentsView`，不使用已经弃用的 `BrowserView`；
- 每个标签拥有稳定 `browserTabId`；
- 标签显式绑定一个 `conversationId`；
- 使用独立持久化 partition，与 Zeus 主 Renderer 和系统浏览器隔离；
- 统一管理导航、弹窗、下载、权限、崩溃和销毁；
- 只通过窄 IPC 向 Renderer 暴露状态与命令。

### 9.2 页面注入：Annotation Runtime

浏览器页面使用专用 preload/isolated world：

- 捕获点击、拖选和文本选择；
- 生成页面锚点；
- 渲染元素轮廓、区域轮廓和编号标记；
- 监听页面滚动、resize、DOM mutation 和导航；
- 只把经过 schema 校验的锚点发给 Main；
- 不向第三方页面暴露 Zeus IPC。

### 9.3 评论编辑器

`WebContentsView` 是原生合成表面，Zeus 主 Renderer 的普通 React DOM 不能可靠覆盖在其上。调研阶段评估了两个位置：

1. 独立无边框子窗口：与当前 Codex App 的职责形状最接近，能稳定盖在页面之上；
2. 注入页面内部：实现较轻，但会受到目标页面 CSS、CSP、全屏和层叠上下文影响。

最终实现选择页面内注入，但使用最高层级的封闭 `ShadowRoot` 隔离编辑器、轮廓和编号标记，并由 Main 进程保存状态。这个方案减少了额外窗口的定位、焦点和跨显示器同步成本，也让编辑器能随页面元素定位；代价是仍需处理目标页面的全屏、frame 和极端布局场景。页面 JavaScript 可以看到宿主节点，但不能读取封闭 ShadowRoot 内的评论内容。

### 9.4 会话提交编排

新增纯函数式序列化器：

```text
BrowserAnnotationDraft[]
  -> 编号化 Browser comments 文本
  -> 可选标注截图文件
  -> NativeConversationSubmission
  -> text + localImage
  -> turn/start | queue | turn/steer
```

提交仍使用现有幂等键、`clientUserMessageId`、队列和失败恢复。批注原始结构应保存在 submission 的 durable input 中，序列化文本只是 provider projection，避免恢复后只剩不可编辑字符串。

## 10. 原建议的交付阶段

### 阶段 A：本地页面批注 MVP

- 仅允许 `localhost / 127.0.0.1 / ::1 / file://` 和项目内产物；
- 单个会话内置浏览器标签；
- 元素点击与区域拖选；
- 多条保存、编号、删除、全部发送；
- URL、role/name、selector、DOM path、附近文本和矩形；
- 始终附带标注截图；
- 发送复用现有 queue/steer；
- 导航或刷新后可安全失效，先不承诺恢复旧锚点。

优点：最短路径覆盖视频中的主闭环，安全面可控。

缺点：文本选区、iframe、Shadow DOM 和跨导航恢复暂不完整。

### 阶段 B：稳定锚点与恢复

- 文本批注；
- iframe 与 Shadow DOM；
- 多选；
- DOM mutation 后重新定位；
- 草稿跨刷新/重启恢复；
- allow/block、下载和 profile 管理；
- `always / necessary` 截图策略。

优点：达到长期可用的页面审阅能力。

缺点：锚点重定位、页面安全策略和恢复测试成本明显增加。

### 阶段 C：`Adjust` 与 agent 浏览器控制

- 文字和 CSS 属性的临时预览；
- 样式 provenance；
- 设计变化结构化提交；
- Browser agent 自动化、页面检查和修改后复验。

优点：接近 Codex App 的完整设计反馈闭环。

缺点：需要 CSSOM/CDP、样式来源分析、临时变化回滚和更严格的注入隔离，不应与 MVP 一次性交付。

## 11. 明确不建议

- 不把整页截图加一句评论当成页面批注；
- 不只保存 `x/y` 坐标；
- 不用主 Renderer 直接导航第三方页面；
- 不让页面 JavaScript直接访问 Zeus preload API；
- 不为每次批注新建任务或会话；
- 不把临时 `Adjust` 样式写回源码；
- 不复制 Codex App 的专有 Browser 插件、源码或品牌资产；
- 不在首版同时承诺通用互联网浏览器、自动化 agent 和完整 `Adjust`。

## 13. 已实现范围

### 13.1 内置浏览器与全局 Profile

- Main 进程新增 `BrowserHost`，使用 `WebContentsView` 管理标签、显示区域、导航、崩溃、下载、权限和销毁；
- 浏览器使用独立持久化 partition `persist:zeus-browser`，Profile 在会话之间共享，并跨应用重启保留；
- 标签仍显式归属当前 Zeus 会话，Renderer 可打开、激活、关闭、导航、前进、后退、刷新和停止；
- 设置页新增“内置浏览器”，支持启停、下载目录、下载询问、截图策略、全 CDP 开关和 Agent 全站授权；
- “清除浏览器数据”会清理缓存、站点存储、认证缓存、站点授权、待审批、下载记录、导航历史、标签、批注和批注截图。

### 13.2 页面批注

- 专用页面 preload 支持元素点击、文本选区和区域锚点；
- 锚点保存 URL、frame、标题、role/name、selector、DOM path、Shadow host path、邻近文本、矩形、viewport 和滚动信息；
- 批注编辑器、元素轮廓、区域轮廓和编号标记位于封闭 ShadowRoot；
- 批注、编号、临时设计变化和标记可跨导航、刷新及应用重启恢复；
- `Adjust` 支持文本、字号、间距、文字色和背景色预览，只持久化用户实际修改的字段；
- 文本预览只修改可见文本节点，不替换整个 `textContent`，因此不会破坏图标或嵌套子节点；
- 点击图标或内层文字时会提升到最近的可交互语义祖先，避免把批注错误锚定到装饰性 `span`；
- 可访问名称的兜底计算忽略 `aria-hidden` 装饰节点；
- 可保存多条页面草稿；浏览器 `Send N` 把批注集合暂存到会话输入框，再由输入框统一复用现有提交、排队和 steer 链路。

### 13.3 Agent 浏览器工具

新会话在 `thread/start` 注册 `zeus_browser` 动态工具命名空间，共 17 个工具：

`open`、`list_tabs`、`select_tab`、`close_tab`、`navigate`、`history`、`snapshot`、`element`、`click`、`type`、`press`、`scroll`、`wait`、`screenshot`、`clipboard`、`downloads`、`developer`。

Codex app-server 的 `item/tool/call` 会被转发给当前会话的 BrowserHost，结果再按动态工具协议返回。安全边界如下：

- 页面标题、URL、元素文本和附近文本统一视为不可信数据，序列化时使用 JSON 字符串并附安全提示；
- Agent 首次访问每个站点需要确认，可记住站点授权；
- 密码、支付、提交、删除、剪贴板等敏感行为始终需要显式确认；
- `Meta/Ctrl + C/V/X` 不通过普通按键工具绕过剪贴板审批；
- `Enter`、`Return`、`Delete` 和敏感默认提交按钮需要审批；
- 文件输入不允许自动操作；
- 跨站链接、表单和历史导航会重新进入站点审批；
- 任意 CDP 方法只有在设置中启用后，仍需对本次操作单独确认。

### 13.4 会话提交与持久化

- 页面批注被序列化为 `Browser comments` 结构化上下文，并可附带本地 PNG 截图；
- 原始 `browserComments` 同时写入 durable submission input，恢复时不依赖反解析提示词；
- 截图附件必须位于 Main 进程认可的批注附件根目录；
- 锚点、样式变化和批注输入都有数量、类型和总体积校验；
- 截图捕获失败不会回滚已经保存的批注。

## 14. 实施中发现并修复的问题

1. 批注校验器曾读取不存在的 `comment.pageUrl`，已改为校验 `comment.anchor.pageUrl`；

## 22. 2026-07-27 最后一个标签关闭语义纠正

### 22.1 问题与根因

用户确认，点击最后一个浏览器标签的 `X` 后，右侧浏览器应随最后一个标签一起关闭；下次点击会话标题栏“浏览器”时才创建新的空标签。

Main 侧 `BrowserHost.closeTab` 已经能把标签集合归零，问题发生在 Renderer：

- `BrowserWorkspace.closeTab` 收到零标签快照后立即调用 `openBrowserTab`；
- 因此旧标签虽已关闭，却被新的 `about:blank` 标签同步替代；
- 用户看到的结果是最后一个标签始终无法关闭。

### 22.2 修复

- 关闭标签后始终采用 Main 返回的真实快照，不再由 Renderer 自动补建标签；
- 若快照中的标签数量为零，调用会话工作区的浏览器关闭动作；
- 再次打开浏览器分栏时，既有初始化流程才为零标签会话创建新的空标签；
- 多标签场景保持原行为：关闭当前标签后选中剩余标签，浏览器分栏继续显示。
- 标签 `X` 的可访问名称独立为“关闭标签”，不再与关闭整个右侧工作面的“关闭浏览器”混用。
