# Zeus 会话输入通用附件开发设计

## 1. 任务目标

对齐当前安装的 Codex App 会话输入体验，补齐 Zeus 新建会话与既有会话中的通用输入资源能力：

- `+` 入口允许选择多个文件与文件夹，不再以图片类型作为默认范围；
- 支持从 Finder、截图工具、Paste.app 等来源粘贴图片、文件与文件夹；
- 支持拖放图片、文件与文件夹；
- 粘贴超长文本时自动生成 `Pasted text.txt` 会话资源；
- 图片显示缩略图，其他资源显示统一资源条目；任意二进制文件“可以附加”不等于“承诺解析其内容”；
- 允许仅发送资源、不输入正文；
- 收集、校验或发送失败时不静默丢失原文本、草稿或已选资源。

本文件先记录调研与建议设计；用户确认继续后，已按第 4～7 节的边界完成首轮实现。第 9 节记录实际代码落点、正式打包验收证据与仍未覆盖的运行场景。

## 2. 已核对的实现事实

### 2.1 Zeus 当前实现

- `apps/desktop/src/main/main.ts` 中现有 `zeus:choose-task-attachments` 由任务域持有，虽然包含 `All Files` 过滤器，但默认首先展示图片过滤器，只支持 `openFile + multiSelections`，不支持文件夹。
- `apps/desktop/src/renderer/App.tsx` 中会话附件选择复用了任务附件选择器，导致会话域依赖任务域命名和信任边界。
- `ConversationComposer.tsx` 与 `SessionWorkspace.tsx` 的输入框目前没有粘贴、拖放资源处理。
- `useSessionController.ts` 和新建会话提交逻辑要求正文非空，因此资源单独发送会被拦截。
- `codexNativeConversationCoordinator.ts` 已具备基础映射：受支持图片映射为 `localImage`，其他本地资源映射为 `mention`。
- Zeus 已有较完整的任务剪贴板处理，覆盖原生位图、Finder 文件 URL、URI 列表、HTML 引用、Paste.app，以及 macOS 未触发 DOM paste 事件时的原生剪贴板兜底；可抽取底层通用能力，但不应继续让会话调用任务专用 IPC。
- 现有会话正文没有超长文本转资源逻辑，本地服务对 `displayText` 仍存在固定上限。

### 2.2 当前安装 Codex App 的静态实现

调研对象为 `/Applications/Codex.app`，版本 `26.721.41059`，构建 `5848`：

- 通用选择器不设置文件类型过滤，macOS 属性为 `openFile + openDirectory + multiSelections`；
- 输入菜单在能力可用时显示 “Files and folders”，并将图片与其他资源分流；
- 粘贴和拖放都会把图片与普通文件分开处理；
- 长文本阈值为 `5000` 字符，生成 `Pasted text.txt`；静态实现中 `5000–25000` 字符支持恢复到编辑器；
- 图片进入图片预览链路，其他文件与文件夹进入通用文件资源链路。

以上属于安装包静态证据；Zeus 对齐后的打包运行效果仍需单独验收。

## 3. 实现路线比较

| 路线 | 核心做法 | 优点 | 主要问题 | 结论 |
| --- | --- | --- | --- | --- |
| A. 最小补丁 | 修改现有任务选择器默认过滤器，并在两个输入框分别增加粘贴处理 | 改动小、上线快 | 继续耦合任务域；重复逻辑；文件夹、拖放、超长文本与失败恢复难以统一 | 不推荐作为最终方案 |
| B. 通用输入资源管线 | 新增会话通用资源 Broker、统一归一化契约和共享输入控制器 | 最接近 Codex；两个输入框行为一致；安全与恢复边界清晰 | 需要中等规模重构 | **推荐** |
| C. 纯渲染层 Web API | 仅使用 `input[type=file]`、`clipboardData`、`DataTransfer` | 前端实现直接 | 无法可靠覆盖 Finder、Paste.app、无 DOM paste、目录选择等已知 macOS 场景 | 排除 |
| D. 仅路径 mention | 所有外部资源仅保留原路径，不复制 | 实现简单、无额外存储 | 文件移动/删除后失效；剪贴板位图和生成文本没有稳定路径；恢复与权限风险高 | 只能作为项目内文件的局部策略 |

推荐采用 B，并使用“混合持久化策略”：

- 用户通过原生选择器明确选择、且位于允许范围内的现有文件或目录：规范化真实路径后以 `mention` 引用；
- 剪贴板位图、没有稳定路径的数据、自动生成的长文本：写入会话专用资源目录，再进入统一资源契约；
- 图片最终映射为 `localImage`，普通文件、目录和文本资源映射为 `mention`。

## 4. 推荐架构

### 4.1 共享输入控制器

新建 `ComposerInputResourceController`，同时由新建会话输入框与既有会话输入框使用。控制器统一接收：

- 原生选择器返回；
- DOM paste；
- 原生剪贴板兜底；
- drag/drop；
- 超长纯文本。

控制器只管理状态与交互，不自行信任或落盘任意本地路径。

### 4.2 主进程资源 Broker

新增会话域 IPC，例如：

- `zeus:choose-conversation-resources`
- `zeus:read-conversation-clipboard`
- `zeus:materialize-conversation-resources`

主进程负责：

- 校验调用窗口；
- 规范化路径并校验存在性；
- 区分文件、目录、图片和生成文本；
- 为剪贴板数据、位图及长文本创建稳定文件；
- 在发送前再次校验资源，降低符号链接和时序变更风险；
- 返回逐项成功或逐项错误，不静默丢弃失败资源。

任务剪贴板模块中与业务无关的解析器应抽取到通用底层模块，任务和会话各自保留领域 IPC。

### 4.3 建议资源契约

```ts
type ComposerInputResource =
  | {
      id: string
      kind: 'image'
      source: 'picker' | 'paste' | 'drop'
      name: string
      mime: string
      size: number
      localPath: string
    }
  | {
      id: string
      kind: 'file'
      source: 'picker' | 'paste' | 'drop'
      name: string
      mime?: string
      size: number
      localPath: string
    }
  | {
      id: string
      kind: 'directory'
      source: 'picker' | 'paste' | 'drop'
      name: string
      localPath: string
    }
  | {
      id: string
      kind: 'pasted_text'
      source: 'paste'
      name: 'Pasted text.txt'
      characterCount: number
      localPath: string
      preview: string
    }
```

Provider 映射保持窄接口：

- `image` → `localImage`
- `file | directory | pasted_text` → `mention`

“所有文件类型可选择”只承诺资源可以进入会话上下文，不承诺 Zeus 或模型能够预览、解压或理解每种二进制格式。

## 5. 状态与失败恢复

建议共享状态流：

`idle → collecting → ready → validating → sending → sent`

异常状态：

- `collect_failed`：保留原文本和现有资源，显示来源级错误；
- `invalid`：资源条目标红并阻止发送，用户删除或重新选择后恢复；
- `send_failed`：恢复冻结前的正文和资源快照，允许原样重试。

关键规则：

- 选择器取消是无操作，不显示错误；
- 图片预览读取失败时降级为普通文件条目，不静默删除；
- 长文本落盘失败时保留编辑器原文；
- 发送时冻结 `displayText + resources + idempotencyKey`，避免发送途中编辑影响当前请求；
- 只有服务端返回持久化回执后才清空草稿与资源；
- 附件去重优先使用规范化真实路径与资源类型，剪贴板生成资源使用稳定 ID。

## 10. 新建任务与会话输入统一（2026-07-28）

### 10.1 用户确认口径

新建任务和会话输入在提交前统一建模为“待提交资源”：

- 外观统一采用当前 Codex App 截图中的紧凑横向资源条；
- 图片使用方形缩略卡，文件、文件夹和粘贴文本使用带类型图标、单行名称与类型摘要的横向卡；
- 移除动作叠放在卡片右上角，不再占用名称内容列；
- 两个入口统一支持任意文件、文件夹、截图/图片、拖放和超长文本自动转附件；
- 可恢复长文本、单项失败不阻断同批成功项、去重和错误反馈使用同一产品语义；
- 创建任务后资源持久化到任务记录与任务附件目录；发送会话时继续使用精确路径 capability。提交后的存储生命周期保持独立。

### 10.2 当前实现差异与改造目标

改造前，新建任务使用 `TaskAttachmentPreviewList` 的 `88px` 竖向 filmstrip，仅选择文件；会话输入使用 `ConversationComposerAttachments` 的横向列表，已经支持文件夹和长文本。两者在卡片尺寸、文件类型表达、选择器范围、剪贴板兜底、拖放和恢复能力上均不一致。

本阶段将抽取共享“待提交资源”卡片原语，并扩展任务附件输入 Broker：

- 原生 picker 改为 `openFile + openDirectory + multiSelections`，不限制文件类型；
- Finder 路径、DOM `File`、原生剪贴板图片和生成文本统一保存到 Zeus 托管的任务附件根；
- 目录在 Main 进程完成受限复制，任务推送阶段允许可信任务附件目录；
- `5000` 字符起自动生成 `Pasted text.txt`，不超过 `25000` 字符时保留恢复正文；
- 新建任务和会话输入共享资源卡 DOM 与 CSS，业务容器只提供数据、预览和提交生命周期。

### 10.3 验收边界
