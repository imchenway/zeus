# TASK_20260728_003 Zeus 命令中心与用户脚本配置

## 目标

在 Zeus 中实现通用命令中心，支持全局命令、项目命令、声明式参数、逐次确认、Runtime 执行、历史、终端日志、产物与 Telegram 远程入口。Git、微信开发者工具和 `agents-sync` 只作为用户提供的脚本配置，不进入 Zeus 内置业务能力。

## 已确认边界

- 产品默认不注入任何命令或业务脚本。
- 全局命令在用户当前选择的项目根目录执行；项目命令只在所属项目执行。
- 每次执行都需要一次性确认；Git 写入、项目外写入或外部服务写入显示高风险摘要，但桌面端与 Telegram 都不要求额外确认短语。
- 命令参数通过声明式环境变量传递，敏感参数不得进入历史、日志和审计。
- 项目必须开启 `allowShell`；声明 Git 写入的命令还必须开启 `allowGitWrite`。
- 导出包含命令定义，不包含用户脚本、命令执行记录或产物；导入后的命令默认停用且关闭 Telegram。
- 本次额外在当前用户的 Electron `userData/command-scripts` 中配置八条脚本和全局命令，但不执行真实 Git 同步、微信上传/预览/真机调试或真实 `agents-sync`。
- 不新增或恢复单元测试；验证使用静态检查、构建、正式打包和隔离运行检查。

## 实施阶段

1. 领域术语、ADR、SQLite 迁移和仓储。
2. CRUD、确认、执行、停止、历史、产物和导入导出 API。
3. 修复 Generic Shell 项目根校验并完善 Runtime 强制终止。
4. 项目命令页、全局设置命令管理和实时执行详情。
5. Telegram 项目选择、命令菜单、状态更新和产物回传。
6. 创建用户脚本，并通过 Zeus 本地 API 写入八条全局命令。
7. 隔离 `ZEUS_USER_DATA_DIR` 运行验收、静态检查、构建和 macOS 正式打包。

## 实现结果

- 新增命令定义、参数、执行、产物领域模型，SQLite 增加命令定义、别名、执行记录和产物表。执行记录保存命令快照，命令软删除后仍可审计。
- 全局命令与项目命令的名称、别名、长度、数量、超时和跨作用域冲突规则与计划一致；不同项目之间允许项目命令同名。
- 参数以字符串、数字、布尔值环境变量传入；`ZEUS_*` 为保留前缀，敏感值不进入执行快照、Runtime 日志或审计载荷。
- 已提供全局/项目 CRUD、一次性确认、运行、历史、详情、停止和产物内容 API；确认绑定命令版本、项目、目录和参数摘要。
- 命令在当前项目真实 `localPath` 执行；Generic Shell 也改为使用目标项目根目录。`allowShell` 和 `allowGitWrite` 均由现有项目安全配置控制；运行时如缺少权限，只有用户在独立弹窗点击“开启并继续”才持久化本命令所需权限，随后仍需确认本次运行。
- Runtime 超时先发送 `SIGTERM`，三秒后仍存活则对进程组发送 `SIGKILL`；服务关闭时同步清理活动命令，避免遗留子进程。
- 运行时注入 `ZEUS_PROJECT_ROOT`、`ZEUS_COMMAND_SCRIPTS_DIR`、`ZEUS_COMMAND_RUN_DIR`、`ZEUS_COMMAND_ID` 和 `ZEUS_COMMAND_RUN_ID`；只接受执行产物目录内的真实文件。
- 数据导出升级为版本 2，包含命令定义但不包含脚本、执行记录和产物；仍兼容版本 1，导入命令默认停用并关闭 Telegram。
- 项目侧栏新增“命令”页，合并展示全局与项目命令；全局设置新增“命令”分类。命令创建、编辑、权限开启与运行确认使用居中弹窗，历史、终端日志、停止和产物查看继续在页面内完成。
- Telegram 支持 `/commands [项目]`、项目选择、合并命令菜单、逐次确认、同消息状态更新和产物回传；命令定义维护仍只在桌面端完成。
