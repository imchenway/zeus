# 新增项目入口与单目录创建

## 需求与决策

用户希望参考 Codex App，在项目侧栏标题右侧提供明确的新增入口，并确认当前工作习惯是把前后端仓库放在共同父级目录下，因此本次只实现单目录项目：

- 一个 Zeus 项目只绑定一个本地目录。
- 项目名称默认取所选目录的末级名称，同时允许创建前编辑。
- 创建成功后自动选中新项目。
- 不增加无功能的折叠箭头或更多菜单。

单目录的优点是模型、终端、Git 与文件授权都围绕同一个工作根目录，边界清楚，当前数据模型无需扩展；缺点是不能把互不相邻的目录组合为同一个项目。用户当前的共同父级目录工作方式可以覆盖这一缺点。

## 原有缺口

- `apps/desktop/src/renderer/App.tsx` 原来只有零项目空态中的“选择真实本地代码库”按钮。
- 一旦已经存在项目，侧栏和项目菜单都没有新增第二个项目的入口。
- 原有创建链路在 `apps/desktop/src/renderer/main.tsx` 中直接打开目录选择器，并用目录名创建项目，没有创建前编辑名称的界面。

## 实现内容

### 项目侧栏

- 在“项目”标题右侧增加真实可用的加号按钮。
- 加号使用现有 Phosphor 图标和 Zeus 主题 token，并提供中英文辅助名称、键盘焦点态、禁用态和忙碌态。
- 用户指出零项目时原有“空状态卡片里再放同文案按钮”存在重复文案、边框套边框和层级抢占问题。该侧栏卡片已删除；零项目侧栏只保留“项目 +”，不再重复创建动作。

### 创建项目弹窗

- 使用现有 `ModalPortal`、`Button` 和纯色表面规范。
- 支持项目名称输入、单目录选择、目录名称自动回填、目录更换、取消和创建。
- 未填写名称或未选择目录时禁用创建按钮；提交失败时保留输入并显示错误。
- 支持首次聚焦名称输入框、`Escape` 关闭、`Tab` 焦点循环、关闭后焦点回到触发入口。

### 创建链路

- Renderer 将“选择目录”和“提交创建”拆成两个明确步骤。
- 创建请求使用用户确认后的名称与目录，并保留项目默认模型、工作模式和任务提示配置。
- 创建成功后刷新仪表盘、自动选择目标项目并清理旧任务详情。

## 范围与限制

- 本次不支持多目录、跨目录授权合并或目录排序。
- 没有新增 TDD、单元测试、组件测试或测试依赖。
- 没有执行 Git 提交、推送、合并或回滚。
- 项目要求的 `domain-modeling` skill 当前不在可用 skill 列表中，无法执行该 skill；本次以现有 `ProjectRecord.localPath`、`CreateProjectRequest.localPath` 和用户确认的单目录边界为领域依据。
