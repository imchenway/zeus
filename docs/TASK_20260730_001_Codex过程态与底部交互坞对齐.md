# TASK_20260730_001 Codex 过程态与底部交互坞对齐

## 1. 任务目标

基于用户提供的 Codex App 截图和 Zeus 正式包运行现场，修复以下体验差异：

- 运行开始及回答阻塞问题后，持续显示可感知的“正在思考”或最新工作活动；
- 可读 reasoning summary 按语义块刷新，不使用逐字打字机效果；
- 工作活动默认收起，只在运行时露出最新一项，用户主动展开后查看完整历史；
- 所有阻塞请求统一占用底部交互坞并临时替换 composer，不再进入可滚动对话流。

本任务覆盖 Plan 和普通工作模式，不新增外部 RPC、数据库表或迁移。

### 2.3 协议和源码

- 固定 Codex 协议声明 `item/reasoning/summaryTextDelta` 为可读 reasoning summary，`summaryPartAdded` 为摘要分段边界；
- `item/reasoning/textDelta` 是原始 reasoning，仅适用于部分开放模型，本任务不把它引入用户界面；
- 原实现只匹配小写 `/delta`，因此遗漏 `summaryTextDelta`、`commandExecution/outputDelta` 和 `mcpToolCall/progress`；
- 原 `item/completed` 会以空完成内容覆盖已经收到的流式内容；
- 原提问卡位于 transcript 内，同时 composer 始终渲染，形成两个主操作区。

## 3. 实现记录

### 3.1 运行时事件和持久化

- 为会话 item repository 增加“进行中权威投影”写入，保持现有表结构不变；
- 显式归一化可读 reasoning summary、摘要分段、命令输出和 MCP 进度；
- 每次 `turn/start` 显式传递协议支持的 `summary: "auto"`；真实验收证明仅实现 delta 解析而不请求摘要时，
  provider 会继续返回空 reasoning；
- 在 `itemPayload.presentation` 中保存 `kind`、`segmentIndex`、`summarySegments` 和 `liveText`；
- reasoning 完成内容为空时保留流式摘要；完成内容非空时仍以 provider 完成投影为准；
- turn 完成时收口同一 turn 的遗留 `in_progress` item；若遗留文本是后续完整 item 的严格前缀，则记录
  `presentation.supersededBy` 并清空重复展示，否则保留已收到文本并结束进行中状态；
- Renderer 对 reasoning 只读取 `summary` 或已归一化文本，不回退显示 raw `content`。

### 3.2 连续反馈

- 会话状态增加 `feedbackEpoch` 和 `visibleFeedbackEpoch`；
- turn 开始及真实阻塞请求解决时开启新反馈段；
- 新反馈段尚无可见摘要或活动时显示“正在思考”，同一 turn 的旧 item 不再抑制它；
- reasoning summary 在完整句或换行到达时立即刷新；其余增量在 80ms 空闲时合并，最迟 180ms 刷新；
- 普通动态效果下只对最新 Markdown 块做 140ms 轻量淡入和位移；减少动态效果时立即显示且不执行空间动画。

### 3.3 工作活动

- 连续活动组使用稳定 key，不因新 item 加入而重建；
- 历史活动默认收起，运行时只显示最新进行中的一行；
- 阶段结束时自动隐藏最新行并收起自动展开状态；
- 读取、搜索、终端、文件变更、MCP、图片使用现有 Phosphor 图标；
- 展开活动后仍可查看命令、工作目录和实时/最终输出。

### 3.4 底部交互坞

- `request_user_input`、计划实施确认、命令、文件、权限和 MCP 请求统一移出 transcript；
- 普通 server request 优先于计划实施确认，一次只渲染队首请求；
- 交互坞存在时不挂载 composer；草稿与附件由会话状态保留，未提交的模型和推理强度由
  `SessionWorkspace` 暂存并在 composer 恢复时回填；
- 当前请求解决后，如无后续请求则恢复 composer；长卡片只在交互坞内部滚动；
- 请求出现或解决不再驱动 transcript 自动滚到底部。

## 4. 设计取舍

- 最新活动单行降低长任务噪音，代价是历史详情需要点击展开；
- 统一交互坞避免两个主操作区，代价是长审批内容需要独立滚动；
- 增量合批改善中文和英文句子的阅读节奏，代价是最多增加 180ms 的展示延迟；
- 只展示 readable summary 避免暴露原始 reasoning，开放模型的 raw reasoning 不在本任务范围内。
