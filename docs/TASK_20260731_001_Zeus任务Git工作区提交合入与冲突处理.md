# Zeus 任务 Git 工作区、提交、合入与冲突处理

## 任务目标

把 Zeus 任务推送、Codex 会话、Git worktree、提交审查、任务终态和后续代码交付连接成一条可恢复、可审计的真实链路：

1. 任务第一次推送时选择来源分支并创建 `zeus/` 任务分支和独立 worktree。
2. 再次推送时可以选择该任务已有分支，创建新会话并继续使用同一 worktree。
3. 任务完成或取消前逐分支提交、推送或明确放弃；成功后回收 worktree。
4. 任务完成后由用户显式一键合入来源分支或主工作区当前分支。
5. 有冲突时进入可跨重启恢复的三方冲突编辑器。

## 领域模型

### TaskWorkspace

`TaskWorkspace` 是任务开发线，不是会话：

- `taskId / projectId`：所属任务和项目。
- `branchName`：统一为 `zeus/` 前缀的任务分支。
- `sourceBranch / sourceHeadSha`：第一次创建任务开发线时冻结的来源基线。
- `worktreePath`：存在物理 worktree 时记录路径；回收后为空。
- `remoteName / remoteBranch`：任务交付分支。
- `state`：`ready / reclaimed / merged / discarded / failed`。

一个 TaskWorkspace 可以关联多个会话；同一时刻只允许一个可写 Codex turn。会话通过 `workspaceId` 关联，并把 worktree 路径写入持久 submission context，恢复 thread 时继续使用原目录。

### TaskIntegration

`TaskIntegration` 记录一次显式合入：

- 合入方式：`merge / squash`。
- 目标分支与启动时目标 HEAD。
- integration worktree 路径。
- 冲突文件和结果提交。
- 状态：`preparing / conflicted / merged / failed`。

冲突时记录和目录都保留，因此应用重启后仍能读取 Git index 的 base、ours、theirs 和工作区结果。

## 关键实现

### 任务编码与分支

- 新任务编码使用 `ZEUS-000001`。
- 数据库打开时按原 `task_sequence` 把旧 `ZEU-*` 迁移为 `ZEUS-*`。
- 默认分支为 `zeus/<task-code>-<task-slug>-<sequence>`。
- 最终合法性由 `git check-ref-format --branch` 判断。
- 来源只允许选择主仓库的本地命名分支，避免把远端跟踪 ref 误当作后续可检出的合入目标。
- 任务分支优先使用 `origin`，仓库没有 `origin` 时使用首个已配置远端；没有远端时在推送前直接拒绝创建任务工作区。

### worktree 创建与复用

- 物理路径位于仓库同级 `.zeus-worktrees`。
- 创建 worktree 不切换主工作区分支。
- Git 已登记同名分支 worktree 时直接复用。
- 回收后本地和远端分支保留；再次选择已有分支时重新挂载 worktree。
- 已合入或已放弃分支不再作为可写分支提供。

优点：

- 多任务可以真正并行，主工作区仍保持用户当前分支。
- 会话重启和新会话复用都具有明确 cwd。
- 任务终态后释放物理目录，避免 worktree 越积越多。

代价：

- 分支数仍会增长，需要后续提供独立的已交付分支清理策略。
- 同一任务分支禁止并发写 turn，牺牲少量并发换取工作区确定性。

### IDEA 风格提交

提交窗口提供：

- 左侧任务分支选择。
- 上方可勾选的 staged、unstaged、untracked 文件集合。
- 下方当前文件双栏差异。
- 右侧真实来源、远端、ahead/behind 和项目提交检查。
- 普通入口的“提交”“提交并推送”。
- 任务终态入口的“提交并推送”或“确认无变更并回收”。

勾选结果在提交时才写入 index。未选变更仍然存在时，任务终态流程不会继续回收。

### 任务完成与取消

- 终态状态修改由服务端再次校验所有 TaskWorkspace 已是 `reclaimed / merged / discarded`。
- 活动 turn 或队列存在时可以从提交窗口停止。
- 有变化的分支必须 push 后通过 `ls-remote` 验证远端 SHA 等于本地 HEAD。
- 无变化分支以 `HEAD === sourceHeadSha` 判断，可不创建空提交或远端分支。
- 放弃操作必须输入完整分支名；远端分支不自动删除。

### 一键合入

无冲突路径：

1. 捕获目标分支 HEAD。
2. 创建 detached integration worktree。
3. 在隔离目录执行 merge 或 squash。
4. 重新确认主工作区目标分支、HEAD 和干净状态。
5. 用 `--ff-only` 应用候选结果。
6. 推送目标分支并校验远端 SHA。
7. 删除 integration worktree。

优点：

- 简单合入只需一次点击。
- 合入准备不会污染主工作区。
- 用户在准备期间切换分支或产生修改时会安全停止。

限制：

- 当前实现要求最终目标分支正由主工作区检出；否则需要用户先切换主工作区。
- 推送失败时目标分支可能已经在本地快进，界面会报告失败并保留证据，不会伪装为远端已交付。

### 三方冲突处理

- 左侧：目标分支版本。
- 中央：最终结果，可编辑。
- 右侧：任务分支版本。
- 支持采用来源、采用任务、两者都采用、手工编辑。
- “请 Codex 协助”启动只读临时 turn，返回完整建议内容并填入中央结果，不自动写盘。
- 用户保存结果后执行 `git add`；全部冲突解决后才生成合入提交并进入最终校验和推送。

## 安全边界

- 不通过 shell 拼接 Git 命令，所有参数使用 `execFile` 数组。
- 文件路径必须是 worktree 内相对路径。
- worktree 回收前验证 Git 登记路径、工作区干净和远端提交。
- 删除只针对精确 TaskWorkspace 路径和本地任务分支。
- 不自动删除远端分支，不自动 rebase，不自动改写已推送历史。
- 用户未触发提交、推送或合入按钮时，不执行相应 Git 写操作。
