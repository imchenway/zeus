# Zeus 0.1.4 升级发布

## 任务目标

把用户已合并的 `0.1.3` 发布基线与当前工作区全部实现整合为新的不可变公开稳定版 `v0.1.4`，完成版本、用户向 Release notes、完整本地门禁、真实发行包运行、GitHub Release、更新清单与 Homebrew Tap 的一致发布。

## 已确认口径

- 目标版本：`v0.1.4`。
- 发布类型：公开稳定版，不覆盖既有 `v0.1.3`。
- 发布范围：当前工作区全部已修改和未跟踪内容。
- 已授权动作：创建发布分支、提交、推送、快进更新 `main`、创建不可变标签、GitHub Release 和 Homebrew Tap。
- 发布分支：`zeus/release-0.1.4`。
- 不执行强推、历史改写或同版本二进制替换。

## 发布基线

- 发布开始时 `main` 与 `origin/main` 均位于 `8be7eef`，现有公开稳定版为 `v0.1.3`。
- `v0.1.3` GitHub Release 已存在且为 Latest Release，不能用相同版本替换本次二进制。
- 工作区包含任务 Git 工作区与交付、代码图谱工作台、无损升级执行宿主、测试版隔离及相关文档变更。
- 本机 GitHub CLI 已登录并具备仓库与 workflow 权限。

## 签名与升级边界

- 本机 codesign 身份为 0 个，Developer ID、Apple 公证和 Keychain profile 均未配置。
- 本次只能沿用既有 ad-hoc 实用发布：GitHub、DMG 与 Homebrew 可手动升级，但 manifest 必须保持 `signed=false`、`notarized=false`。
- `0.1.3` 不包含本次新增的无损安装器，因此 `0.1.3 → 0.1.4` 不能通过应用内自动切换验证。
- `0.1.4` 会首次交付独立执行宿主和安装事务代码；缺少真实签名、公证时，应用内自动安装仍必须保持关闭。

该方案优点是无需等待外部 Apple 凭据即可交付当前功能；缺点是本次不能验证用户最关心的正式应用内自动升级体验，首次启动仍可能遇到 Gatekeeper 提示。

## 发布步骤

1. 同步根包与桌面包版本为 `0.1.4`。
2. 完成 `docs/releases/v0.1.4.md` 用户向 Release notes。
3. 执行 `pnpm verify:release`，生成真实 App、DMG、manifest 和 Homebrew Cask。
4. 只使用仓库生成的 `dist/mac-arm64/Zeus.app` 做真实启动、宿主连接和 `/health` 验收。
5. 核对 codesign、DMG、manifest、Cask、版本和摘要。
6. 提交并推送发布分支，快进更新 `main`，创建 annotated tag `v0.1.4`。
7. 发布 GitHub Release 的 DMG 与 manifest，同步 Homebrew Tap。
8. 反查 Release 页面、公开资产、摘要、Release notes、manifest、tag、main 和 Tap。
