# Zeus 执行宿主重连与历史消息恢复

## 用户现场

仓库打包应用在会话页长期显示“正在重新连接”，重试次数持续增加，同时顶部显示 `Failed to fetch`。用户补充确认历史消息也无法查看，当前画布错误显示“发送第一条消息后，真实 app-server 对话会显示在这里”。

## 现场证据

- 应用 Main 和 Renderer 仍存活，但业务 Local Server 与 Codex app-server 已退出；Main 只保留内置浏览器桥监听端口。
- `execution-host/host.log` 依次记录 `execution_host.ui_lease_expired`、多次 `execution_host.monitor_failed`，最终以 `detached_idle` 关闭。
- Main 的界面租约心跳失败被静默忽略，没有重新登记 BrowserHost 租约，也没有重新发现或启动执行宿主。
- Renderer 会话控制器在旧 Local Server 地址上持续重试，没有可获得的新端点。
- 当前 `zeus.db` 的 `PRAGMA quick_check` 返回 `ok`。
- Fast 任务两条会话的持久数据仍存在：一条包含 18 条消息、429 个 item、4 个 turn；另一条包含 7 条消息、70 个 item、1 个 turn。
- 会话记录组件只用 `items.length === 0` 判断空态，没有区分“权威 snapshot 已加载且为空”和“snapshot 尚未加载”。

## 根因

### 界面租约过期后没有恢复

执行宿主使用 15 秒界面租约和 5 秒心跳。系统休眠、进程长时间暂停或事件循环延迟后，宿主可能先判定租约过期；Main 后续心跳收到失败时只吞掉异常，不重新登记租约。宿主在没有活跃工作时进入空闲回收，但 Main 与 Renderer 仍持有旧的 Local Server 地址和凭据，最终形成永久重试。

### 历史加载失败被误报为空会话

会话历史依赖 Local Server 返回权威 snapshot。执行宿主失联后，新选中的会话无法完成 snapshot hydration；组件仍把空的初始 `items` 当作真实空会话，导致用户误以为历史丢失。

## 已确认修复边界

1. Main 的界面租约维护必须串行执行，避免重叠心跳和重复恢复。
2. 心跳失败后先重新登记当前执行宿主；当前宿主已经退出时，通过安全 rendezvous 发现或启动唯一新宿主。
3. 执行宿主或 Local Server 地址、凭据变化后，Main 原地更新 Renderer 可读取的连接配置。
4. Renderer 在 WebSocket 或 HTTP 失败后通过 Main 刷新配置，并在新地址上重新执行权威 snapshot hydration。
5. 已成功加载的历史在短暂断线时继续保留；尚未加载成功时显示“历史消息暂不可用”，不能显示空会话文案。
6. 只有权威 snapshot 已成功加载且确实没有可见消息时，才显示“发送第一条消息”。
7. 不自动重放未知状态的旧 submission，不创建第二数据库写入者，不改变 provider thread 身份。

## 方案取舍

### 采用：Main 维护可恢复界面租约

优点：

- 修复休眠、唤醒和宿主空闲回收后的真实断链。
- 继续保持执行宿主是数据库唯一写入者。
- 复用现有安全 rendezvous、回环端点和随机凭据，不引入 Renderer 直接读取敏感元数据的旁路。

缺点：

- Main 与执行宿主之间需要增加串行恢复状态，必须处理恢复与退出并发。
- Local Server 地址变化后，Renderer 需要再次执行 snapshot hydration。

### 不采用：只增加 Renderer 重试次数或延长租约

优点是改动小；缺点是旧端点已经失效时永远不会恢复，延长超时也只能推迟故障，因此不采用。

### 不采用：Renderer 直接读取 SQLite 历史

优点是宿主失联时仍可读取；缺点是破坏执行宿主唯一数据库所有者边界，并可能与保存过程并发读取不完整状态，因此不采用。

## 实施结果

### Main 与执行宿主

- 界面租约登记和心跳改为只返回轻量租约状态，不再把 Local Server 的业务健康状况混入租约续期结果。
- Main 串行维护心跳；租约失效时优先在当前宿主重新登记，当前控制端点已经失效时再通过安全 rendezvous 发现或启动唯一宿主。
- 执行宿主发生替换后，Main 原地更新 Local Server 地址、凭据和宿主元数据，并通知既有重启回调。
- Renderer 每次获取 Local Server 配置时由 Main 主动刷新连接，不再永久返回启动时缓存的失效地址。
- 状态读取和停止活动工作在控制端点失效时各执行一次受控恢复，不自动重放未知状态的 submission。

### 历史消息

- 会话记录组件只有在权威 snapshot 已成功加载且没有可见内容时才展示空会话文案。
- snapshot 尚未加载且连接处于重连或失败状态时，展示“历史消息暂不可用；连接恢复后会自动显示”。
- 已持久化的会话、消息、item、turn 和 provider thread 身份均未迁移或改写。
