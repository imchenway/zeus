# Zeus 0.1.5 升级发布

## 任务目标

把执行宿主永久重试和历史消息误空态修复发布为新的不可变公开稳定版 `v0.1.5`，完成版本、用户向 Release notes、完整本地门禁、仓库发行包真实验收、GitHub Release、更新清单与 Homebrew Tap 的一致发布。

## 已确认口径

- 目标版本：`v0.1.5`。
- 发布类型：公开稳定版，不覆盖既有 `v0.1.4`。
- 发布范围：当前工作区中的两个问题修复、领域术语、任务证据和发布文档。
- 已授权动作：创建发布分支、提交、推送、合入 `main`、创建不可变标签、GitHub Release 和 Homebrew Tap。
- 发布分支：`zeus/release-0.1.5`。
- 不执行强推、历史改写或同版本二进制替换。

## 发布基线

- 发布开始时 `main` 与 `origin/main` 均位于 `bd7dccc0ec8b2e3e1a825757221bcf150b4a56cd`。
- 现有公开稳定版 `v0.1.4` 解引用到 `31775ad56a9f3ff8caf6b774786f3681af756ff5`，不能用相同版本覆盖本次二进制。
- 本机 GitHub CLI 已登录 `imchenway`，具有 `repo` 和 `workflow` 权限。
- 工作区没有发现用户无关变更；全部修改均属于本次故障修复、领域记录和发布交付。

## 签名与升级边界

- 本次沿用现有 ad-hoc 实用发布；manifest 必须如实记录 `signed=false`、`notarized=false`。
- 缺少 Developer ID 签名和 Apple 公证时，只支持 GitHub DMG 与 Homebrew 的用户确认后手动升级，不宣称应用内自动安装已经启用。
- 状态未知的旧 submission 不自动重放；执行宿主仍是数据库唯一写入者。

该方案优点是立即交付永久重试和历史误空态修复，并保持公开升级渠道一致；缺点是首次启动仍可能遇到 Gatekeeper 提示，无法验证 Apple 已认证的自动安装体验。

## 发布步骤

1. 同步根包与桌面包版本为 `0.1.5`，完成用户向 Release notes 与发布工程记录。
2. 退出仓库打包应用，执行 `pnpm verify:release` 生成真实 App、DMG、manifest 和 Homebrew Cask。
3. 只使用仓库生成的 `dist/mac-arm64/Zeus.app` 做启动、历史、租约过期和宿主重启验收。
4. 核对 codesign、DMG、manifest、Cask、版本、大小和摘要。
5. 提交并推送发布分支，通过 PR 与远端 CI 后合入 `main`。
6. 创建 annotated tag `v0.1.5`，发布 GitHub Release 的 DMG 与 manifest，同步 Homebrew Tap。
7. 反查 Release 页面、公开资产、摘要、Release notes、manifest、tag、main 和 Tap。
