# 不可继续会话未发送内容恢复

## 当前状态

- 阶段：已完成实现与隔离测试包真实验收
- 用户现场：执行轮次失败并使会话不可继续后，原先排队的用户输入仍显示“待发送”，但输入框和队列操作均不可用。
- 用户决策：继续修复，不再补问；采用“保留为未发送内容，带入新会话草稿但不自动发送”的推荐语义。
- Git 边界：本任务不执行 commit、push、merge 或 revert。

## 源码事实

1. `codexNativeConversationCoordinator.ts` 在 provider turn 失败时，把仍为 `queued` 的提交改为 `paused/recovery_required`，同时把会话 `providerState` 改为 `failed`。
2. `SessionWorkspace.tsx` 将 `providerState=failed/closed` 的原生会话判定为不可继续，并把原 composer 设为只读。
3. `ConversationComposer.tsx` 仍会把 `queued/paused/failed` 快照统一显示为“待发送”；只读状态又会禁用编辑、删除、排序和发送操作。
4. 因此当前界面把不会再被原会话派发的内容描述成“待发送”，并且没有可达恢复动作。

对用户现场数据库进行只读核对后确认存在两种不同事实：

- 截图中的“自己打包到 Zeus Test 去测试”为 `status=failed` 且已有 `providerTurnId`，同一内容也已持久化在 `conversation_messages`；底部“待发送”是失败轮次输入的重复投影，必须从队列表面移除，不能再次迁移或重放。
- 另一个同任务会话中的“继续”为 `status=queued`、没有 `providerTurnId`，conversation 保留 `providerState=paused`。隔离测试包启动后，API 快照显示 idle，但 Coordinator 仍由 paused 推导 `recovery_required`，队列持续三秒未派发，证明存在真实状态死锁。

## 领域决策

### 未发送内容判定

只有同时满足以下条件的提交才属于“未发送内容”：

- 状态为 `queued` 或 `paused`；
- 尚未取得 `providerTurnId`。

已经取得 `providerTurnId` 的失败提交属于失败轮次，不能自动重放或带入新会话，避免重复副作用。

### 恢复交互

不可继续或要求权威恢复的会话不再显示可操作的“待发送”队列，而是显示只读“未发送内容”：

1. 按原队列顺序展示每条文字与附件；
2. 主操作改为“带入新会话”；
3. 多条文字用空行按原顺序合并为新会话草稿；
4. 附件按真实资源身份去重后带入；
5. 新会话输入框只预填，必须由用户再次确认发送。

优点：不丢失用户输入，不会在新上下文中误发，也不会重放已经到达 provider 的失败轮次。

缺点：多条队列消息进入新会话时会成为一条可编辑首发草稿，原队列的逐条轮次边界不再保留；用户需要再次点击发送。

不采用自动创建并发送新会话：它虽然减少一次操作，但会在上下文已经变化后产生未再次确认的 provider 写入。

### Paused 状态归一

应用重启后，Coordinator 必须以恢复后的 provider thread 快照作为权威依据：

1. 本地没有 `dispatching/active` submission；
2. provider 快照中不存在活动 turn；
3. provider 快照能够按 `providerTurnId` 确认至少一个本地终态 turn。

三项同时满足时，`providerState=paused` 归一为 `ready`，run state 归一为 idle，随后只派发新建的 queued submission；旧的 interrupted turn 永不重放。

任一条件不满足时保持 fail-closed：queued/dispatching/active submission 统一转为 `paused/recovery_required`，providerState 保持 paused，要求用户新建会话，不能猜测继续。

优点：消除“UI 已就绪但 Coordinator 禁止 drain”的分裂状态，同时保留未知 provider 写窗口的防重复保护。

缺点：恢复依赖 `thread/read` 返回可识别的 turn 状态与稳定 `providerTurnId`；上游协议缺失这些事实时只能进入人工恢复，不能自动降级。

4. **运行时健康**：隔离执行宿主日志只有 ready、runtime activated 与 UI attached 事件，没有新增相关错误；测试 App 随后正常终止。
