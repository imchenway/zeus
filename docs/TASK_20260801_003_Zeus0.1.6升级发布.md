# Zeus 0.1.6 升级发布

## 任务目标

把不可继续会话的队列死锁与“待发送”误投影修复发布为新的不可变公开稳定版 `v0.1.6`，完成版本、用户向 Release notes、完整本地门禁、仓库正式包真实验收、GitHub Release、更新清单与 Homebrew Tap 的一致发布。

## 已确认口径

- 目标版本：`v0.1.6`。
- 发布类型：公开稳定版，不覆盖已经公开的 `v0.1.5`。
- 发布范围：未发送内容领域术语、paused 状态权威归一、不可继续会话恢复界面、任务证据与发布文档。
- 已授权动作：用户明确要求“升级发布”，因此允许创建发布分支、提交、推送、合入 `main`、创建不可变标签、GitHub Release 和 Homebrew Tap。
- 发布分支：`zeus/release-0.1.6`。
- 不执行强推、历史改写或同版本二进制替换。

## 发布基线

- 发布开始时 `main` 与 `origin/main` 均位于 `f43ad8a`。
- 当前公开稳定版 `v0.1.5` 解引用到 `9ae882e971ecec7c676fb5b1e81b76e7832f1e6c`，GitHub Release 为非草稿、非预发布，公开资产为 DMG 与 manifest。
- 本机 GitHub CLI 已登录 `imchenway`，具有 `repo` 和 `workflow` 权限。
- 工作区修改均属于本次会话恢复修复及其领域、任务和发布记录；未发现需要纳入的用户无关改动。

## 领域与发布边界

- “公开稳定版”继续以不可变 Git 标签、GitHub Release、更新清单和 Homebrew Cask 的一致事实为完成口径。
- 本次继续采用 ad-hoc“实用发布”：manifest 必须保持 `signed=false`、`notarized=false`，只支持用户确认后的手动安装。
- 已有 `providerTurnId` 的失败提交属于失败执行轮次，不属于未发送内容，不能因升级恢复而自动重放。
- 无 `providerTurnId` 的 queued/paused 输入可以进入新会话草稿，但不能自动发送。
- 正常退出 Zeus 仍会中断活动执行轮次；本次修复的是重启后的状态对账与未发送内容恢复，不宣称无损后台执行已经实现。

该方案优点是立即消除不可操作的“待发送”死锁，同时保留未知 provider 写窗口的防重复保护；缺点是上游快照事实不足时仍需要用户显式新建会话，且 ad-hoc 包无法提供 Apple 已认证的自动安装体验。

## 发布步骤

1. 同步根包与桌面包版本为 `0.1.6`，完成用户向 Release notes 与发布工程记录。
2. 退出仓库打包应用，执行 `pnpm verify:release` 生成真实 App、DMG、manifest 和 Homebrew Cask。
3. 只使用仓库生成的 `dist/mac-arm64/Zeus.app` 做启动、健康检查和本次修复的正式包验收。
4. 核对 codesign、DMG、manifest、Cask、版本、大小和摘要。
5. 提交并推送发布分支，通过 PR 与远端 CI 后合入 `main`。
6. 创建 annotated tag `v0.1.6`，发布 GitHub Release 的 DMG 与 manifest，同步 Homebrew Tap。
7. 反查 Release 页面、公开资产、摘要、Release notes、manifest、tag、main 和 Tap，并把最终事实写回本任务文档与 `docs/release.md`。
