# Fast 模式支持

## 任务目标

让 Fast 服务档位覆盖任务推送、项目对话、任务会话首轮和已有会话后续轮次，并按 Codex app-server 的真实 `serviceTier` 三态传输与展示。

原计划指定的 `docs/TASK_20260801_005_Fast模式支持.md` 已被同日现有任务“回答选项内容垂直居中”占用。为避免覆盖其他任务记录，本任务按当天递增规则使用 `TASK_20260801_007`。

## 真实依据

- 仓库内置 Codex app-server 的模型目录包含可选 `serviceTiers` 与 `defaultServiceTier`。
- `serviceTier` 的协议语义区分字段省略、显式 `null` 和目录字符串 ID；三者不能用推理强度代替。
- 当前主工作区已有“会话交互自动恢复”的未提交修改，Fast 实现只在其上增量修改，未回退这些改动。
- `provider_settings_json` 与 submission `input_json` 已能承载新增字段，不需要新增数据库列。

## 领域决策

| 用户选择 | app-server 请求 | 适用入口 |
| --- | --- | --- |
| 跟随 Codex | 省略 `serviceTier` | 新 thread |
| 标准 | `serviceTier: null` | 新 thread、已有 thread 后续 turn |
| 目录档位 | `serviceTier: "<catalog id>"` | 新 thread、已有 thread 后续 turn |

用户选择、项目偏好和 provider 实际档位是三个不同事实。项目偏好只在首轮已经真实开始后写入；已有会话改档不改项目偏好。`thread/resume` 只恢复 provider 实际状态，不发送档位覆盖。

## 实现记录

### AI Runtime

- 模型能力增加服务档位目录及默认档位解析，并拒绝空 ID、异常目录结构和模型不支持的目录档位。
- `thread/start`、`turn/start` 保留字段省略、`null`、字符串三态。
- `thread/start` 与 `thread/resume` 解析模型、推理强度和实际服务档位，形成当前 Runtime 世代序号为零的初始权威快照。

### Local Server 与存储

- 任务推送、项目/任务首发、已有会话发送、排队、幂等指纹和 WebSocket 快照贯通 `serviceTier`。
- `thread/settings/updated` 与 start/resume 初始响应进入同一有序 provider settings 存储路径。
- 当前模型不支持请求的目录档位时，Local Server 保留模型并规范化为标准；provider 在目录仍宣称支持时拒绝请求，不自动降级或重放。
- 尚未 durable acceptance 的失败发送只改服务档位时复用原幂等身份；已经接受的失败轮次由下一次明确提交创建新身份。

### Renderer

- 任务推送与新建项目/任务会话提供“跟随 Codex、标准、目录档位”。
- 已有会话只提供“标准、目录档位”，并且只在会话空闲时允许切换。
- 模型切换后若原目录档位不受支持，保留模型、切换标准并显示就地提示。
- 目录说明始终使用模型目录原文；会话实际档位缺失时显示“未同步”，未知 ID 原样显示。
- 项目偏好键独立且无版本后缀；任务推送和普通新建入口共享同一偏好。

## 取舍

- 优点：目录驱动避免把特定模型或 `priority` 硬编码成产品规则，后续 Runtime 能力变化可自动同步。
- 缺点：目录可能缺失、过期或与 provider 接受结果不一致，因此前后端都要复验，并保留拒绝现场。
- 优点：实际档位只读 provider 返回，避免把请求值误报为已生效。
- 缺点：provider 未返回时只能显示“未同步”，不能为了界面完整而猜测状态。
