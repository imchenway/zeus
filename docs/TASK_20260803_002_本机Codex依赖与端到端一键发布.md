# 本机 Codex 依赖与端到端一键发布

## 目标

- 完全移除 Zeus 内置 Codex 的源码锁、补丁、构建、缓存、打包、物化与完整性校验链路。
- Zeus 只使用用户本机安装的 Codex CLI；缺失或能力不兼容时阻断 AI 执行，并展示官方安装或升级引导。
- 将四条阶段发布命令收敛为一条 `zeus-release` 项目命令。用户只确认一次高风险操作，命令随后从本地 `main`
  候选提交持续执行到公开发布和产物回验完成。

## 已确认发布契约

- 候选来源固定为本地 `main` 的当前 `HEAD`；允许本地 `main` 领先 `origin/main`，但远端领先或分叉时阻断，不自动合并、不强推。
- 新版本默认取最新公开稳定版的补丁位加一。
- Release notes 的范围固定为“最新公开稳定标签（不含）到本地候选提交（含）”。
- 发布开始时工作区必须干净。AI 生成失败、生成结果声明不确定、或确定性格式校验失败时，在版本写入和远端写入前阻断。
- 成功主链路为：生成 Release notes、写入双包版本与仓库发布正文、提交到 `main`、执行本地发布门禁、推送 `main`、等待同一提交
  CI、创建并推送不可变标签、触发 Release Workflow、回验 GitHub Release、DMG、manifest 与 Homebrew Tap。
- 命令重跑必须识别同一版本的已完成阶段并继续，不创建新版本、不改写标签、不做破坏性清理。
- 当前继续允许明确披露限制的 ad-hoc、未公证发布；不把它描述为已签名、公证或可静默安装。
- Zeus 命令管理只保留 `zeus-release`；旧四条命令仅作为仓库内部阶段脚本保留。

## 本机 Codex 契约

- 发现顺序：用户显式配置的 Codex 可执行文件绝对路径优先，其次当前 PATH、macOS 常见本机目录与登录 Shell。
- 设置与探针展示真实解析路径、版本、检测时间和能力结果；重新检查必须重新执行真实探针。
- Zeus 不下载、不安装、不升级 Codex，也不把 Codex 放入 App、DMG、Release Workflow 缓存或用户数据目录。
- 缺失或 `app-server` 能力不可用时，AI 功能 fail-closed，并引导用户按 OpenAI 官方方式自行安装或升级后重新检查。
- 已开始的执行轮次不迁移、不重放；新的本机 Codex 路径只影响后续新建的进程世代。

## 方案取舍

### 优点

- Release Workflow 不再编译 Rust Codex Runtime，显著缩短缓存未命中的发布路径并减小 DMG。
- Zeus 与 Codex 解耦，用户可以独立升级 Codex，发行包不再承担上游二进制和补丁供应链。
- 单命令发布消除四阶段参数传递和人工漏步，同时保留 main、CI、标签和公开资产的 fail-closed 门禁。

### 代价

- 首次使用依赖用户自行安装并登录 Codex；环境差异会成为明确的本机前置条件。
- Codex 上游升级可能产生协议兼容变化，Zeus 必须通过真实能力探针阻断，而不能依赖内置固定版本兜底。
- 一键发布会在一次确认后产生提交、分支推送、标签、GitHub Release 和 Tap 变更；因此前置检查和幂等恢复必须比阶段命令更严格。

## 尚未执行

- 没有用真实新版本跑完整 `zeus-release` 写链路，因为那会立即创建发布提交并推送 main。首次真实使用时仍需以干净、已提交的
  main 候选执行，并以 GitHub CI、Release、回下载 DMG 与 Homebrew Tap 的结果作为最终证据。
