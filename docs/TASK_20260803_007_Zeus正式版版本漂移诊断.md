# Zeus 正式版版本漂移诊断

## 用户现象

用户通过 macOS“应用程序”目录启动 Zeus。升级到 `0.1.13` 后，界面有时仍显示 `0.1.11 (0.1.11)`。

本任务只做现场诊断，没有启动、替换、移动或删除任何 Zeus 应用包，也没有清理 macOS 应用登记表。

## 术语边界

- **本机正式应用**：只指 `/Applications/Zeus.app`。
- **开发验收包**：仓库 `dist`、任务 worktree 或临时目录中的 `Zeus.app`；不得作为本机正式版本事实。
- **版本漂移**：相邻启动实际进入不同版本应用进程，不是同一包的版本字段自行变化。

## 现场证据

1. `/Applications/Zeus.app` 的 `CFBundleIdentifier` 为 `dev.hypha.zeus`，`CFBundleShortVersionString` 与
   `CFBundleVersion` 均为 `0.1.13`。
2. Homebrew 本机安装记录为 `zeus 0.1.13`，安装时间是 2026-08-03 16:25:03（Asia/Shanghai）。
3. 当前运行主进程路径是 `/Applications/Zeus.app/Contents/MacOS/Zeus`；当前执行宿主和更新接口均报告 `0.1.13`。
4. 执行宿主日志证明版本确实发生过切换：
    - 2026-08-03 14:52:50 启动 `0.1.12`；
    - 2026-08-03 16:25:02 该宿主正常退出；
    - 2026-08-03 16:25:10 启动 `0.1.11`；
    - 2026-08-03 17:00:23 启动 `0.1.13`。
5. 机器上真实存在任务 worktree 打包产物
   `/Users/david/hypha/.zeus-worktrees/zeus-e2e-oBLuqT/ZEUS-000038/f2bb104cd74b114b/dist/mac-arm64/Zeus.app`。它的版本是
   `0.1.11`，bundle ID 同样是 `dev.hypha.zeus`，创建于 2026-08-03 15:20 左右。
6. macOS LaunchServices 已登记上述 `0.1.11` worktree 应用，同时还登记了正式 `/Applications/Zeus.app`、仓库 `dist`
   和多份历史验收包。
7. 当前 Dock 没有持久化 Zeus 项，因此本次不属于 Dock 图标固定到旧路径。
8. 唯一留存的应用内安装事务状态为 `completed`，没有本次从 `0.1.13` 自动回滚到 `0.1.11` 的记录；当前 `/Applications`
   下也没有升级备份或 staging 应用残留。
9. Zeus Main 使用 Electron 单实例锁。任意同身份 Zeus 先取得锁后，再启动另一份包只会唤起既有窗口并退出新进程。因此即使用户随后从“应用程序”目录双击
   `0.1.13`，也可能继续看到先启动的 `0.1.11`。

## 结论

根因是开发验收包与本机正式应用复用了同一个 bundle ID `dev.hypha.zeus`，并且开发包曾被真实启动、进入 macOS LaunchServices
应用登记表。正式版替换期间，系统仍可能把同标识的 worktree 包解析为 Zeus 启动候选，因此 16:25 实际启动了 `0.1.11`
；该进程取得单实例锁后，从“应用程序”再次打开也只会唤起旧窗口。17:00 才启动当前 `/Applications` 中的 `0.1.13`。

历史日志没有记录当时主进程的绝对可执行路径，因此“16:25 的 `0.1.11` 精确来自该 ZEUS-000038 路径”是由版本、创建时间、同
bundle ID 和 LaunchServices 登记共同支持的高可信归因，不冒充为已直接记录的历史进程路径。

## 修复方向及取舍

### 立即止血

- 退出所有 Zeus 进程后，只从 `/Applications/Zeus.app` 启动，并清理 LaunchServices 中已经失效或不应作为正式入口的 Zeus 登记。
- 优点：可以快速停止错误解析，不改变应用数据。
- 缺点：只要后续开发验收包继续复用生产 bundle ID 并被启动，问题可能再次出现。

### 永久修复

- 所有开发、worktree 与隔离验收包统一使用 `dev.hypha.zeus.test` 等测试 bundle ID，并使用 `Zeus Test`
  产品名和独立用户数据目录；发布门禁阻止非正式路径的包使用生产 bundle ID。
- 优点：从身份层隔离正式应用和验收包，LaunchServices、运行进程、登录项与用户数据都不会再混淆。
- 缺点：打包脚本、验收流程和相关文档需要统一调整，历史开发包仍需一次性清理登记。
