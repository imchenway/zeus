# Zeus 0.1.14 自动整理与恢复发布

## 目标

- 修复 `0.1.14` 发布候选被 Prettier 门禁阻断的问题，并继续完成公开发布。
- 让 `pnpm release` 在生成版本提交前，只对本次待发布且受 Prettier 管理的文件执行自动整理。
- 发布候选尚未推送时，允许用户提交修复后继续同一版本，不再被旧恢复状态卡死。
- 阻止 AI 生成过程说明混入公开 Release notes。

## 现象与根因

- 当前公开稳定版是 `0.1.13`，本地 `main` 已有功能提交 `938be6647f4218ef5a97df2ade4b1bd6def4ad18` 和版本提交 `ce62a4b432185cb5340f57aa5f4afe360ca1d97d`。
- `pnpm release` 在本地门禁中对 `origin/main...HEAD` 执行 Prettier 只读检查，发现 13 个 TypeScript 文件未格式化并退出。
- 该检查在 `v0.1.13` 已存在，当前失败不是规则临时变化，而是新候选没有在版本提交前完成格式整理。
- 编排器先创建版本提交、后执行完整门禁；失败后恢复状态固定在旧版本提交，无法自然吸收后续修复提交。
- `docs/releases/v0.1.14.md` 尾部还混入了 AI 的结构化输出说明，现有 Release notes 校验没有识别该泄漏。

## 已确认领域边界

- 继续沿用 `CONTEXT.md` 中的“公开稳定版”“实用发布”“真实交付验收”和“发布阻断项”，本任务不新增领域术语。
- **自动整理范围**：稳定版标签到当前候选提交之间，仍存在且扩展名受 Prettier 管理的文件。
- **候选修复提交**：自动整理确实产生变化时创建的独立提交；它属于最终发布候选，但不改写已有提交。
- **未推送恢复**：只允许在版本提交、门禁摘要、标签、main 推送和公开发布均未发生远端写入时，把恢复状态重新绑定到旧候选的本地后继提交。

## 实现设计

1. 发布状态确定后、Release notes 和版本提交生成前，运行候选自动整理。
2. 自动整理只接收本次 Git 范围内的受支持文件；若出现范围外变化立即阻断。
3. 产生变化时先复查 Prettier 和 Git 空白错误，再创建 `chore: format release candidate` 独立提交并更新候选状态。
4. 已生成版本提交但尚未产生远端写入时，允许本地后继修复提交成为新的固定候选；同步仓库内已修正的 Release notes 快照后继续门禁。
5. Release notes 生成、候选准备、本地门禁和公开发布四个入口都拒绝常见 AI 过程说明标记。
6. 脏工作区仍使用隔离发布副本；已有版本提交但尚未推送时，将受控恢复状态重建到隔离副本，恢复判断同时兼容“格式提交 + 版本提交”的多提交链路。

## 优缺点

### 优点

- 一条发布命令可以处理纯格式差异，减少在最后阶段人工来回修复。
- 自动变化有独立提交和明确日志，能够审计，不会改写已有历史。
- 尚未推送的失败候选可继续使用同一版本，避免手工修改恢复状态。
- 公开说明增加过程内容泄漏保护。

### 缺点

- 发布命令会主动修改候选文件并创建提交，职责比原先只检查更重。
- 自动整理只解决确定性的格式问题；lint、类型、构建或真实运行问题仍会阻断。
- 已经推送 main、创建标签或产生门禁摘要后不允许重新绑定，仍需人工处理不可变发布边界。
