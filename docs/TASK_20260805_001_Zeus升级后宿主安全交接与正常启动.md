# Zeus 升级后宿主安全交接与正常启动

## 任务目标

修复 Zeus 从 `0.1.19` 手动升级到 `0.1.20` 后，新界面连接旧执行宿主并进入“界面已安全暂停”，随后应用退出的问题。修复后，执行宿主交接不得影响应用正常启动；旧会话继续运行时，新版主窗口和工作台仍需正常打开。

## 用户确认口径

1. 直接在 `main` 分支开发，不创建或切换任务分支。
2. 新版应用必须先正常打开；宿主交接只能限制相关局部操作，不能阻断整个应用启动。
3. 旧宿主仍在持续生成结果或产生副作用的执行阶段不能因升级被强制终止或自动重跑；一旦进入等待用户回答、等待用户选择、等待审批或其他已持久化的阶段性完成状态，就应立即切换到新宿主。
4. 待处理交互切换后由新宿主恢复原会话，用户回答时自动重连并继续，不能要求旧宿主为了等待用户回复而继续存活。
5. 不能启动第二个数据库写入者；旧宿主完全退出并释放写入权后，才能启动唯一的新宿主。
6. 修复完成后使用独立身份 `Zeus Test.app` 做真实运行验收，再提交、推送并发布 `0.2.0`。
7. 不使用或修改日常正式 `/Applications/Zeus.app` 作为开发验收对象。

## 现场证据

- `/Applications/Zeus.app` 已更新为 `0.1.20`，bundle id 为 `dev.hypha.zeus`。
- 2026-08-05 10:29 的执行宿主日志显示，仍存活的宿主由 `0.1.19` 启动；`0.1.20` 界面三次附着后都很快退出。
- Renderer 恢复页来自 `apps/desktop/src/renderer/ErrorBoundary.tsx`，说明应用主进程和 Renderer 已经启动，实际失败是界面运行期异常，不是应用包完全无法执行。
- `0.1.20` 的 dashboard 新增 `conversationAttentionByProject`；旧 `0.1.19` 宿主返回的 snapshot 没有该字段，`App.tsx` 直接读取后触发顶层错误边界。
- 当前宿主发现只校验 `executionHostProtocolVersion = 1`；`0.1.19` 与 `0.1.20` 使用相同控制协议号，因此旧宿主被误判为完整界面 API 兼容。

## 修复设计

### 应用启动边界

Renderer 在消费本机 API 响应前统一补齐跨版本可选字段。上一正式版宿主缺少新增投影字段时，使用真实空状态或派生默认值，不允许因为属性缺失进入顶层崩溃页。

优点：新版窗口可以立即读取旧宿主中的真实数据，已有会话不受影响。

缺点：只适合兼容可安全默认的新增字段；语义不兼容的写接口仍需单独限制，不能用默认值掩盖。

### 宿主兼容事实

界面配置携带当前应用版本、宿主应用版本和交接状态。相同版本表示当前宿主；不同版本表示正在使用上一正式版宿主完成存量工作。该事实用于局部能力限制和用户提示，不用应用版本字符串冒充底层运行时世代。

优点：用户能区分“应用已经打开”和“部分新版能力等待宿主切换”。

缺点：版本只能说明宿主代码来源，真正的长期兼容仍需显式能力表与发布门禁。

### 安全交接

旧宿主只在执行轮次仍持续生成结果或产生副作用时继续存活；所有活动轮次一旦进入等待用户回答、等待选择、等待审批或已经完成的可恢复阶段边界，就立即持久化交互断点并关闭旧宿主。旧宿主完全退出并释放 SQLite 写入权后，启动唯一新版宿主；用户后续回答由新版宿主恢复原 thread 并继续处理。

优点：不丢正在执行的工作，不因用户暂时没有回答而长期保留旧宿主，也不产生双写。

缺点：当前 app-server 的待处理请求绑定旧运行代和实时请求编号，不能只删除十秒等待；必须增加可恢复交互断点，把旧请求安全转换为新宿主能够续接的原会话输入，且不能重复执行旧轮次已经产生的副作用。

## 实施范围

- `apps/desktop/src/renderer/apiClient.ts`：统一规范化 dashboard snapshot，补齐跨版本可选字段。
- `apps/desktop/src/main/localServerRuntime.ts`：按“真实执行数 = 活动轮次 - 等待交互轮次”判断可恢复边界；交接前通过旧宿主只读 API 保存待回复项，关闭旧宿主后再恢复到唯一新宿主。
- `packages/storage` 与 `packages/local-server`：持久化宿主交接标记；用户回复时重新校验原问题和答案，并在同一 provider thread 创建恢复轮次。命令、文件和权限决定只绑定原操作，新宿主仍需按当前策略再次校验。
- `apps/desktop/src/renderer/apiClient.ts`、`App.tsx` 与样式：删除交接期间的新执行全局封锁和顶部长期横幅；真实端点切换造成的短暂连接失败继续由 Main 刷新端点并重试。
- 发布门禁：使用“上一测试版宿主 + 当前候选 `Zeus Test.app`”完成真实等待、切换和续接验收。

## 验收条件

1. 使用隔离用户数据启动上一正式版宿主，再启动当前 `Zeus Test.app`，主窗口正常出现且不进入界面错误页。
2. 旧宿主仍在持续生成结果或产生副作用时保持原宿主 PID 和执行轮次，不启动第二数据库写入者。
3. 轮次进入等待用户回答、等待选择或等待审批后，不再等待固定十秒，旧宿主安全退出并启动唯一新版宿主。
4. 用户在切换后回答原待处理问题时，新宿主自动恢复原 thread 并继续，不显示请求运行代失效或恢复失败。
5. 交接期间项目、任务、会话和上一正式版已有的新建会话、任务推送能力继续正常使用；旧宿主缺少的新版专属能力只在对应入口说明。
6. Renderer 使用刷新后的本机端点继续工作，旧宿主 PID、子进程和数据库写入权均已释放。
7. SQLite `quick_check` 与应用 `/health` 均为真实成功。
8. `pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac` 和 `pnpm verify:release` 按阶段通过；静态与构建结果不替代 GUI 验收。
