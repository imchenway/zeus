# Zeus 升级后旧数据目录恢复

## 任务目标

恢复 Zeus `0.2.5` 升级后未加载的旧正式数据。恢复必须保留旧目录原件与当前新目录回滚副本，迁移数据库、附件、命令脚本、会话文件和改动记录，并排除旧执行宿主与单实例锁。

## 用户确认口径

1. 本机当前问题只做数据恢复，不修改迁移代码。
2. 采用完整稳定数据迁移，不只替换 `zeus.db`。
3. 正常退出当前空白 Zeus 后再操作，禁止在执行宿主写库期间覆盖数据库。
4. 当前 `~/.zeus` 必须整体保留为可回滚备份；旧目录 `~/Library/Application Support/@zeus/desktop` 保持原样。
5. 不执行 Git 提交、推送、合并或发布。

## 现场证据

- 当前正式应用为 `/Applications/Zeus.app`，版本 `0.2.5`，bundle ID 为 `dev.hypha.zeus`。
- 当前 Renderer 进程使用 `--user-data-dir=/Users/david/.zeus`，执行宿主读取 `~/.zeus/zeus.db`。
- `~/.zeus/zeus.db` 创建于 2026-08-06 17:42，包含 0 个项目、0 个任务、0 个会话和 0 条会话内容，`PRAGMA quick_check` 为 `ok`。
- 旧正式库仍位于 `~/Library/Application Support/@zeus/desktop/zeus.db`，包含 8 个项目、192 个任务、93 个会话、22,068 条会话内容和 2,116 条消息，`PRAGMA quick_check` 为 `ok`。
- 旧目录另有约 115 MB 任务附件、112 MB 会话改动记录、27 MB 命令脚本、16 MB 会话文件和 2 MB 会话附件；只替换数据库会造成这些关联资源继续缺失。
- `0.2.5` 迁移代码寻找的旧目录是 `~/Library/Application Support/Zeus`，但本机真实旧目录是 `~/Library/Application Support/@zeus/desktop`；前者不存在，因此首次迁移被跳过并创建了空库。

## 领域结论

本次现象是“业务数据未从权威本机目录加载”，不是“业务数据被删除”。空白侧边栏只反映当前新库为空，不能作为历史数据丢失证据。

## 恢复设计

1. 正常退出当前 Zeus，确认 Main、Renderer 和 execution-host 全部关闭。
2. 将当前 `~/.zeus` 整体改名为带时间戳的回滚目录，不删除其中任何内容。
3. 从旧正式目录复制稳定数据到新的 `~/.zeus`，排除 `execution-host`、`SingletonCookie`、`SingletonLock` 和 `SingletonSocket`。
4. 保留当前新目录中的 `agent-runtimes` 和首次启动导入文件，避免重复准备新版运行内核；如果复制冲突则停止，不覆盖旧业务数据。
5. 启动 `/Applications/Zeus.app`，等待 execution-host 就绪，再核对数据库数量、健康状态和真实项目列表。

优点：数据库与关联文件一起恢复，旧附件、Review、脚本和会话文件不会因只换库而断链；旧目录和当前新目录均可回滚。

缺点：复制数据量明显大于单个数据库，恢复时间更长；不修迁移代码意味着其他尚未迁移的旧用户仍可能遇到同一问题，但本机形成有效 `~/.zeus` 后不会再次走首次迁移。

## 验收条件

1. 旧目录保持原样，当前空目录备份可定位并可恢复。
2. 新 `~/.zeus/zeus.db` 的项目、任务、会话和会话内容数量与旧库一致。
3. 新库 `PRAGMA quick_check` 返回 `ok`。
4. `0.2.5` execution-host 健康状态为数据库和运行环境正常。
5. 真实界面重新显示项目列表，至少打开一个既有会话确认历史与输入区可用。
