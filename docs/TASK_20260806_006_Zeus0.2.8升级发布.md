# Zeus 0.2.8 升级发布

## 任务目标

把远程公开稳定版 `0.2.7` 之后的会话失败原因展示、内置模型供应商和思考档位改动交付为 `0.2.8`，完成 GitHub Release、公开安装资产和 Homebrew 稳定入口对账。

## 已确认边界

1. 用户确认发布 `0.2.8`，基线固定为远程 `v0.2.7` 发布提交 `5f8ae9ea586411e4870030c9ba16dac1a77e7345`。
2. 功能范围只包含会话失败原因投影与展示、DeepSeek / 百炼 / Kimi / Z.AI 内置连接、DeepSeek V4 思考档位和相关控件显隐。
3. `0.2.7` 已经发布的旧数据目录恢复和 Codex 登录门禁不重复作为本次新内容。
4. 原始脏工作区保持原样：不拉取、不 stash、不重置、不暂存，所有候选与发布动作在隔离副本中完成。
5. 原始任务还记录了 Pi 与 App Server 共用公共工具、标准 MCP 和审批的平台改造；该范围尚未实现，不进入 `0.2.8`。

## 领域口径

- **会话失败原因**：已建立会话或执行轮次失败后，留在原会话时间线中的可理解说明；需要包含恢复建议并允许查看脱敏技术详情。
- **公开稳定版**、**发布候选应用包**和**完整升级发布**继续沿用项目 `CONTEXT.md` 的既有定义，本次不新增重叠术语。

## 发布方案

1. 从 `origin/main@v0.2.7` 建立独立候选，只迁移用户确认的十二个源码文件、领域术语和任务文档。
2. 审查候选差异，用独立功能提交固定发布源。
3. 执行格式、`pnpm lint`、`pnpm typecheck`、`pnpm build` 和 `pnpm package:mac`，对 `Zeus Test.app` 的身份、签名结构、失败原因 API 投影和内置模型能力做真实验收。
4. 由仓库端到端发布编排生成用户 Release notes、升级版本、执行正式门禁、推送 `main`、创建不可变标签并发布 GitHub / Homebrew。
5. 回下载公开 DMG 和 manifest，核对摘要、`hdiutil verify`、Release 正文、Homebrew Cask、签名和公证真实状态。

## 优点与代价

### 从远程 0.2.7 建隔离候选

优点：避免本地 `0.2.5` 旧基线导致版本回退，也不会重复发布已经进入 `0.2.7` 的改动。

代价：公开发布后原工作区仍落后远程，需要在当前未提交现场处理完成后再显式同步。

### 只发布已确认新增范围

优点：发布说明、代码差异和用户可见变化可以直接对账，减少无关回归面。

代价：Pi 平台级公共工具与 MCP 改造需要后续单独交付，不能在本次 Release notes 中宣称已支持。

## 验收口径

- 候选基于 `v0.2.7`，只包含确认功能、对应文档和发布编排生成物。
- `pnpm verify:publish`、`pnpm verify:release`、正式打包、CI 和 Release Workflow 全部以同一候选提交为准。
- 仓库版本、`v0.2.8` 标签、GitHub Release、DMG、manifest 与 Homebrew Cask 的版本及摘要一致。
- 失败原因真实投影和模型能力档案必须由测试包中的实际代码验证，静态构建不单独作为完成证据。
- GUI 真实目视如果继续被 macOS 锁屏阻断，必须单列为未覆盖项，不改写为已验收。
- 签名与公证按公开 manifest 的真实值报告；ad-hoc 或未公证产物不描述为 Apple 认证。
