# Zeus 任务工作区远端最新基线与安全合入

## 任务目标

降低任务推送和目标分支合入中由过期分支记录、原工作区未提交内容和重复吸收历史造成的冲突。剩余冲突应尽量只来自两个分支真实修改同一段代码的业务差异。

## 已确认产品规则

1. 有远端的仓库采用远端权威模式：来源选择前必须成功刷新远端，只展示该次刷新得到的远端分支。
2. 纯本地仓库保留本地模式，不因缺少远端失去任务开发能力。
3. 新任务工作区只从来源分支的精确提交创建，不自动携带原工作区的已暂存、未暂存或未跟踪内容；本地模式只有显式选择时才允许带入。
4. 不把目标分支先合进任务分支，不自动 rebase，不改写任务分支历史。最终候选始终从最新目标分支创建，只合入当前任务 HEAD 一次。
5. 远端模式下，远端任务分支必须与本地任务 HEAD 完全相同才能进入目标合入；缺失、领先或分叉都阻断，不允许强制推送。
6. 远端刷新失败时直接阻断当前动作，不能使用缓存远端记录冒充最新状态。
7. 冲突处理期间目标分支前进时废弃旧候选并安全重建。没有用户草稿时自动继续；已有草稿时保留，只有冲突指纹一致才回填，并要求用户确认。

## 方案与取舍

### 创建任务开发线

远端模式选择一个明确远端，优先使用 `origin`
，否则使用首个已配置远端。服务端执行刷新后返回远端分支快照；用户选择的分支以远端跟踪引用对应的精确提交创建任务分支。刷新、创建和保存工作区之间任何一步失败，都不能回退到本地同名分支。

优点：任务一开始就建立在团队最新已提交事实之上，并彻底隔离其他本机工作的未提交现场。

代价：断网、远端凭据失效或远端不可达时不能创建远端模式任务；用户必须先修复远端访问。

### 推送任务分支

推送前刷新远端。远端任务分支不存在时允许普通首次推送；远端是本地 HEAD 的祖先时允许普通快进推送；远端领先或分叉时阻断。推送后反查远端提交必须与本地
HEAD 相同。

优点：不会强制覆盖同名远端任务分支，合入前也能确认远端证据完整。

代价：同名任务分支被其他人推进后，需要用户先明确处理差异，Zeus 不替用户决定历史。

### 合入目标分支

开始合入前刷新远端并校验任务分支一致性，隔离候选从远端目标精确提交创建。真正推送前再次刷新并比较目标提交；发生推进时旧候选转为失败审计记录，再从最新目标提交重建。

优点：最大限度减少旧目标基线制造的冲突，不触碰任务分支历史，也不改变原项目工作区现场。

代价：目标分支持续高频推进时，候选可能重复重建；真实修改重叠仍需人工判断。

## 修改范围

- `packages/git-core/src/index.ts`：远端刷新、远端来源 worktree、任务分支非强制一致性推送、最新远端目标候选和冲突指纹。
- `packages/local-server/src/index.ts`：远端能力快照、创建与交付门禁、目标推进检测和安全重建接口语义。

- `apps/desktop/src/renderer/task/TaskModelPushModal.tsx`：远端来源展示和本地模式提示。
- `apps/desktop/src/renderer/task/TaskGitMergeModal.tsx`：远端目标展示、任务分支一致性提示、过期候选重建和草稿确认。
- `apps/desktop/src/renderer/session/sessionTypes.ts`、`apps/desktop/src/renderer/apiClient.ts`：前后端数据契约。
- `CONTEXT.md`、`docs/adr/0009-任务工作区采用远端权威基线与安全重建.md`：领域语言和架构决策。
