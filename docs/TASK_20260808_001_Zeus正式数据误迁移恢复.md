# Zeus 正式数据误迁移恢复

## 事故结论

2026-08-08，ZEUS-0135 一次性维护器使用尚未进入正式发布提交的分层目录实现，将正式数据从旧平铺布局迁移到分层布局，并在校验后回收旧数据根。随后重新打开的
`/Applications/Zeus.app` 版本为 `0.2.14`，该正式安装包仍按旧平铺路径读取数据库，因此新建并打开了空的 `~/.zeus/zeus.db`
，界面表现为项目、任务和会话全部消失。

本次不是核心业务数据被全部删除。完整数据库仍在迁移后的 `~/.zeus/data/zeus.db`，迁移前数据库备份仍在
`~/.zeus/backups/database/`。但是旧的 `~/Library/Application Support/@zeus/desktop`
数据根和部分旧备份、生成缓存已被维护器物理回收，不能把本次事故描述为“没有发生删除”。

## 根因

1. 目录迁移能力只存在于 ZEUS-0135 工作区的未提交修改中，没有进入 `0.2.14` 对应的正式源码提交。
2. 一次性维护器可以运行这套未提交迁移代码，并在成功后继续回收旧根。
3. 维护器没有校验待重启的正式安装包是否包含并启用了同一套分层路径读取能力。
4. 正式包重启后继续读取 `~/.zeus/zeus.db`，而完整主库已经被移动到 `~/.zeus/data/zeus.db`，最终创建空库并展示空白界面。

## 恢复边界

- 先正常退出正式 Zeus，并确认 Main、Renderer、execution-host 和 `~/.zeus` 数据库句柄全部关闭。
- 不删除迁移后数据库，不覆盖当前空库现场。
- 当前空库、迁移后完整数据库、迁移清单和操作报告统一保存在 `/Users/david/.zeus-incident-backup-20260808-095937`。
- 正式数据库使用迁移前备份恢复，保证数据库内的绝对路径仍指向旧平铺目录。
- 附件、会话改动、运行会话、命令脚本和 Provider 数据按迁移清单反向搬回旧平铺目录。
- `zeus.config.json` 内的分层绝对路径同步恢复为旧平铺路径。
- 不执行 Git 提交、推送、合并、发布或再次目录迁移。

## 当前状态

本机正式数据已经恢复，正式 Zeus 当前可读取旧平铺数据库和关联资料。事故备份目录必须保留，不得清理。

ZEUS-0135 的分层目录能力仍不能视为正式完成。后续若继续该需求，必须先把完整实现纳入可追溯提交，并增加“迁移器版本与待启动正式包能力一致”的硬校验；在修复、打包和隔离验证完成前，不得再次对正式
`~/.zeus` 执行迁移或回收旧根。

## 方案评价

优点：本次恢复使用迁移前数据库备份，数据库路径和旧正式包完全一致；迁移后数据库与当前空库均保留，可追溯、可回滚；真实接口和 GUI
均已恢复。

缺点：当前正式环境暂时回到旧平铺布局，目录整顿目标尚未交付；维护器已经回收的旧重复根和旧缓存不会自动重建；如果再次误运行
ZEUS-0135 维护器，事故仍可能复发。
