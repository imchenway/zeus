# v0.3.4 发布失败类型契约修复与续发

## 任务目标

修复 v0.3.4 首次发布工作流中的 TypeScript 类型错误，保持专用会话首发输入透明规则，并继续完成尚未公开的 v0.3.4 发布。

## 现场事实

- 本地与远端 `main` 当前都位于发布提交 `ff06e0f087cafba57e507617629a0acffedae4df`。
- GitHub Actions 运行 `31690615300` 的 `typecheck` 与 `package-mac` 都因同一组类型错误失败。
- v0.3.4 尚无远端标签和公开 GitHub Release；发布恢复状态停在 `main_pushed`。
- 失败调用重新传入了已被 ZEUS-0268 删除的专用会话 `displayText`，同时仍按旧分支参数调用冲突会话标题构造器。

## 已确认决策

### 保持专用会话首发输入透明

冲突处理会话继续只保存和展示实际发送给模型的完整提示词，不恢复摘要覆盖字段。冲突会话标题使用当前任务名称，分支方向继续属于完整提示词和代码交付上下文。

优点：用户可以直接审计模型收到的完整要求，不回退 ZEUS-0268 已确认的透明展示规则。

代价：冲突会话首条消息保持完整长度，不能再用一句短摘要降低首屏信息密度。

### 继续完成 v0.3.4

v0.3.4 从未形成公开标签、Release、DMG 或 Homebrew 版本，因此修复后追加独立提交，并通过发布脚本的恢复路径继续同一版本。

优点：避免为未公开候选跳过版本号，保留现有发布状态和说明。

代价：v0.3.4 的版本提交之后会存在一笔发布修复提交，公开标签应指向修复后的最终候选。
