# TASK_20260814_001 移除任务推送状态同步校验

## 问题

任务推送后，Renderer 会额外调用 `POST /api/tasks/:taskId/model-push-management-status`。无损升级期间如果新界面仍连接旧执行宿主，旧宿主没有这条后来新增的路由，会返回 `Route POST ... not found`。Renderer 随后在会话中持续展示“任务状态未同步”和重试入口，给用户造成会话被状态校验卡住的直接感受。

同一截图中的模型回复还受到 Vibego 全局 `grilling + domain-modeling` 无条件确认门禁影响，要求用户再次确认文档后才继续。该问题在 Vibego 仓库单独收口，本任务只记录 Zeus 会话主路径的修复。

## 当前决策

- 任务推送不再自动修改任务管理状态。
- 推送弹窗不再根据任务当前状态增加确认步骤。
- 删除推送专用状态同步接口、客户端调用、乐观投影、后台重试和会话警告。
- 任务状态继续通过已有统一状态入口由用户手动修改。

优点：会话创建不再依赖附属状态路由，新旧宿主并存时不会因接口代差反复报错；任务状态也不会被创建会话隐式改写。

缺点：任务进入开发后需要用户手动修改状态，侧边栏分组不会自动移动。

## 实现范围

- `apps/desktop/src/renderer/App.tsx`：删除状态确认、同步、投影、重试和警告编排。
- `apps/desktop/src/renderer/task/TaskModelPushModal.tsx`：删除推送状态确认区。
- `apps/desktop/src/renderer/task/TaskModelPushPendingWorkspace.tsx`：删除待处理工作面的状态同步字段。
- `apps/desktop/src/renderer/apiClient.ts`：删除专用客户端接口。
- `packages/local-server/src/index.ts`：删除专用服务端路由。
- `CONTEXT.md`、`DESIGN.md`：更新当前领域语言与设计契约。
