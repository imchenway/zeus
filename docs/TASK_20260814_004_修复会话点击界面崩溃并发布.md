# TASK_20260814_004 修复会话点击界面崩溃并发布

## 目标与影响

修复 Zeus 0.3.6 点击任意会话后进入全局界面错误页的致命问题，并按用户授权完成补丁版本发布。故障影响会话详情主路径，列表和执行宿主本身仍在运行，但用户无法查看或继续会话。

## 根因与现场证据

- 当前正式界面版本为 `0.3.6`，复用的 execution host 于 2026-08-12 启动，宿主版本为 `0.2.38`。
- 真实宿主的 `/api/projects/:projectId/codex-conversation-capabilities` 响应是合法能力对象，但只包含账户、模型、代次和项目字段，没有 0.3.6 新增的 `goals` 字段。
- 0.3.6 Renderer 在会话工作区和新会话输入区直接读取 `capabilities.goals.supported`。可选链只保护了 `capabilities`，没有保护缺失的 `goals`，因此旧宿主能力一进入渲染就抛出未捕获异常。
- 全局错误边界按设计隐藏堆栈和敏感信息，所以用户只看到“Zeus 遇到界面错误”，与截图一致。

## 修复方案与取舍

- 将跨版本传输契约中的 `goals` 标记为可缺失，类型检查会阻止后续再次无保护读取。
- 在 Renderer API 边界统一把缺失或无效的 `goals` 降级为“不支持、未启用、阶段未知”。
- 会话工作区保留第二层安全读取，覆盖本地乐观状态等不经过 API 归一化的输入。
- 不停止或替换当前正式 execution host，不迁移数据库，不伪造旧宿主具备目标能力。

优点：旧宿主可以继续承载正在运行或待交互的会话，升级后的界面不会因新增可选能力崩溃；目标能力在新宿主上保持原行为。

代价：旧宿主排空前，目标模式会按真实能力降级为不可用；以后新增宿主能力字段仍需要在同一兼容边界明确默认值。

## 验证记录

- 真实旧宿主响应：`executionHostVersion=0.2.38`、`capabilityObject=true`、`hasGoals=false`。
- 用缺少 `goals` 的旧宿主能力对象直接运行 API 边界归一化，结果为 `supported=false`、`enabled=false`、`stage=null`。
- `pnpm lint`、`pnpm typecheck`、`pnpm build` 全部通过；构建仅有既有大分块告警。
- `pnpm package:mac` 通过，产出独立身份 `Zeus Test.app`；实测 Bundle ID 为 `dev.hypha.zeus.test`，`codesign --verify --deep --strict` 通过。
- 用 `Zeus Test.app` 和独立用户数据创建验收项目，项目页与新会话输入区均可正常打开，未出现全局界面错误。
- 测试身份没有登录 Zeus 专属 Codex，因此未在隔离 GUI 中生成新会话；目标的新界面加旧宿主组合已由真实旧宿主响应和运行时归一化验证覆盖。
- 正式发布目标为 `0.3.7`；Workflow、公开资产、Homebrew、签名与公证状态将在发布后分别回验，不以本地构建代替公开完成事实。
