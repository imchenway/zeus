# 任务推送会话与详情错误修复

## 背景

2026-08-17 现场同时出现三类现象：

- 任务推送选择 1xm 的 Sonnet 5 后先提示 Pi 预检失败，随后又出现一条真实会话并长期停在“正在思考”；
- 任务推送选择 Codex 后提示 Zeus 专属 Codex 未登录；
- 推送失败后点击任务卡片查看详情，会再次弹出“会话创建失败”。

## 现场证据与根因

### Pi 预检竞态

真实数据库中只有一条新 Pi 产品会话，但同一提交同时留下了“Renderer 收到创建失败”和“服务端已持久接纳、轮次仍为
running”的矛盾状态。Pi SDK 的 `prompt()` 是异步函数，内部会先等待认证、压缩检查和扩展钩子，再在真正进入 Agent run 前调用
`preflightResult`。Zeus 过去在拿到 `prompt()` 返回的 Promise 后立刻判断“回调缺失”，因此先拒绝创建；稍后到达的回调仍执行了持久接纳事务，最终造成失败工作面和真实运行会话并存。

### Codex 登录状态过期

Zeus 专属 `CODEX_HOME` 中存在本地登录文件，普通账号读取因此显示已登录；真正创建前的权威令牌刷新返回未登录。能力弹窗和最终提交使用了不同强度的账号检查，导致用户先进入创建态，提交后才被登录门禁拒绝。

### 任务详情重复上报旧错误

任务详情本身已经成功打开。详情组件挂载时把任务推送工作面中持久保存的旧失败再次上报到全局错误队列，所以每次打开详情都像是发生了新的错误。

## 修复方案

1. Pi 驱动等待真实预检回调，不再把异步 `prompt()` 的 Promise 返回误判成缺失回调；增加有限等待保护，超时才中止。回调在失败或超时后到达时不得再执行持久接纳。
2. 任务推送能力加载使用权威账号刷新，提前识别过期 Codex 登录。
3. 即使账号在弹窗打开后才失效，提交端仍保留第二道门禁；Renderer 收到稳定的登录错误后撤销本次未接纳的乐观工作面，恢复原模型、工作区、权限、补充信息和附件，并继续既有登录流程。
4. 任务详情不再上报历史推送失败。新的创建失败只在真实失败发生时上报一次，同时保留当前工作面的失败状态和重试入口。

## 取舍

### 优点

- Pi 的界面失败状态与服务端持久接纳边界重新一致，不再产生“报错后又新建并卡住”的双重表象。
- Codex 登录问题在创建产品会话与工作区前暴露，用户填写内容不会丢失。
- 打开任务详情不再消费一次与当前操作无关的旧错误弹窗。

### 代价

- 打开任务推送弹窗时会多一次 Codex 账号权威刷新，网络异常时能力加载时间可能增加。
- Pi 预检增加有限等待窗口；SDK 若真的不再回调，需要等到保护时间到达后才明确失败，而不是立即误判。

- `pnpm lint`：通过。

- `pnpm build`：通过；只有既有的大分块提示。
- `pnpm package:mac`：最终通过，产物为独立身份 `dist/test/mac-arm64/Zeus Test.app`
  ；包体磁盘校验和指定要求校验通过。测试包使用临时签名且未公证，不代表正式发布完成。
- 隔离启动：使用独立 `ZEUS_USER_DATA_DIR=/tmp/zeus-test-task-push-qa.HOjsFL` 启动最终测试包，Renderer
  正常显示隔离任务，没有启动失败页或全局错误弹窗；退出后隔离数据库 `PRAGMA quick_check` 为 `ok`。正式
  `/Applications/Zeus.app` 始终保持运行，未被启动、退出或替换。
- Codex 未登录：全新测试数据打开任务推送时，在创建任何会话前显示“Zeus 专属 Codex 需要登录”，主操作为“登录并继续”。
- Codex 提交瞬间失效：在隔离 Renderer 中只模拟第一次能力读取为已登录、第一次创建请求返回稳定的 `ZEUS_CODEX_LOGIN_REQUIRED`
  ，随后恢复真实未登录能力。结果为乐观工作面撤销、原任务详情与推送表单恢复、进入既有配置导入和登录流程；没有“会话创建失败”弹窗、没有“正在思考”、没有第二条会话，也没有真的打开登录网页。
- 任务详情：上述恢复后关闭并重新打开同一任务详情，详情正常出现，全局 `alertdialog` 数量为 0，页面没有重新出现“会话创建失败”。
- Pi 时序：对照当前打包依赖 `@earendil-works/pi-coding-agent@0.83.0` 的真实 `AgentSession.prompt()`
  实现复核，认证检查、上下文压缩和扩展钩子均可能先异步等待，`preflightResult` 只保证在整轮 Promise 完成前触发，不保证在
  Promise 返回时同步触发；修复后的驱动按该契约等待真实回调，并在失败收口后忽略迟到回调。
