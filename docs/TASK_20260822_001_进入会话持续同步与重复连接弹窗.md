## 只读证据

- 正式应用版本为 `0.3.29`。
- 正式执行宿主健康端点一度返回数据库、运行时和存储均正常；本轮未据此把完整会话链路判断为正常。
- 正式数据库 `/Users/david/.zeus/data/zeus.db` 为约 4.4 GB，`PRAGMA quick_check` 返回 `ok`；本轮没有写入正式数据库。
- 目标标题对应三条会话，其中当前 `open` 会话 `conversation_b91052424bae446f8c7bfa73` 有 75 条消息、708 个 item、10 个
  turn、885 条模型历史。
- 该会话耐久事件流基线为 1、最新序号为 483，共 483 条、载荷约 3,157,896 字节；418 条为 `conversation.item.completed`。
- 现有 Renderer 冷打开时以 `afterSequence=0` 建立 WebSocket，同时读取权威快照；连接断开后又从 0 重放同一批历史。
- `conversationSyncProtocol` 原先在 Provider Coordinator 创建、恢复与后台用量刷新之后才初始化，但这些较早阶段已经持有会发布会话事件的回调，存在真实的词法暂时性死区。
- `SessionWorkspace` 会把每一次 `transportState=failed` 都送入全局错误弹窗；自动重连又会清空错误，下一轮失败因此被当成新错误再次弹出。

## 根因

1. 后端耐久会话协议的初始化顺序晚于事件发布者，异步发布可访问尚未初始化的 `conversationSyncProtocol`。
2. 冷会话 hydration 在取得快照水位之前从 0 订阅耐久事件，历史较大时会无谓重放整段事件；断开后的每轮重连重复相同工作，无法前进。
3. 可自动恢复的 transport 错误同时采用“会话内持续状态”和“全局瞬时弹窗”两套反馈，重连状态切换使相同错误无限重新入队。

## 修复设计与取舍

### 协议先于发布者初始化

- 在任何 Provider 恢复、后台刷新或路由注册前创建 `ConversationSyncProtocol` 及 WebSocket 高水位配置。
- 优点：消除 `conversationSyncProtocol` 的初始化时序窗口，所有发布路径共享已就绪协议。
- 缺点：协议对象生命周期更靠前，后续新增依赖时必须保持它只依赖已建立的存储、订阅集合和流控对象。

### 快照水位之后订阅增量

- 冷打开先取得一致的 Snapshot V2、尾部历史、队列、请求、会话摘要和目标，再用 `snapshot.throughEventSeq` 建立事件连接。
- 快照读取期间的新事件由服务端按该游标补发，不从 0 重放旧历史。
- 优点：避免大历史会话反复重放，并继续保证快照与增量之间不漏事件。
- 缺点：WebSocket 建连发生在快照读取之后，冷打开时实时连接建立时间略晚；这是用少量连接延迟换取有界重放和可靠收敛。

### 自动重连不重复弹窗

- `retryable=true` 的 transport 错误只显示会话内失败或重连状态，不再进入全局错误弹窗。
- 非可重试连接错误、会话读取失败和用户主动操作失败仍保留统一弹窗。
- 优点：用户可以持续查看重连进度，不再被相同弹窗阻断。
- 缺点：自动重连错误详情不再主动抢占界面，需要从会话内状态或诊断信息查看。

## 完成口径

- 初始化、Provider 恢复和会话已读确认不再触发 `conversationSyncProtocol` 暂时性死区。
- 冷会话首次 WebSocket 订阅游标等于刚取得的权威快照水位，不再固定从 0 重放。
- 事件在快照读取后到达时仍按连续序号应用，历史和最新状态都能收敛。
- 自动重连可以持续，但同一可恢复 transport 错误不再反复弹出全局弹窗。
- 通过 `pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac` 与现有事件流行为探针；只把 `Zeus Test.app` 作为测试产物。
- 真实 GUI、正式安装版发布与正式应用升级必须单列，不得由静态检查或打包成功替代。

## 2026-08-22 `0.3.30` 正式回归失败补录

### 新现场

- 正式版进入 `ZEUS-0263` 会话 `conversation_d1d266c5bd24a3c1d734b6f4` 后，HTTP
  权威快照和历史正文能够显示，但顶部持续出现“正在同步会话状态”和“正在重新连接”，页面反复闪烁。
- 同一版本还出现安全退出等待超过 45 秒、任务模型推送弹出 `Task model push did not return a durable accepted operation.`。
- 这些现场证明此前静态检查和测试包构建不能作为正式会话链路验收；原“通过”结论作废。

### 新根因

1. `registerLocalServerPlatformRoutes` 在 HTTP 服务监听前把 `boundPort=null` 按值解构；后续 WebSocket 首帧调用
   `serverIdentity()` 时永远读取旧值并抛错，服务端以 `1011` 关闭每一条事件连接。只读正式历史副本已稳定复现该关闭码。
2. 已有快照的重连仍在 `reconnecting` 与 `hydrating` 间切换，并重复提交相同水位快照；持续断线时造成顶部状态和页面投影反复刷新。
3. 任务推送客户端把表单原始幂等键与 Graph 命令派生的耐久操作身份直接比较，服务端已返回 `accepted` 也会被误判失败。
4. 同时存在原生 Codex 和外部 Pi 的同名模型时，任务推送用裸模型名首个命中，可能把界面选中的外部模型路由到原生
   Codex；该错误会进一步触发无可核验上下文窗口的预检拒绝。
5. 最终退出逐个等待 Provider 请求取消，再等待其他 turn interrupt；多个 30 秒超时会串行超过 Main 的 45 秒安全退出门限。现场宿主实际在约
   55 秒后完成，导致 UI 先报清理失败。

### 本阶段修复

- 本地服务路由改为在请求发生时读取当前绑定端口，禁止初始化阶段复制 `null`。
- 已有快照的后台重连保持单一 `reconnecting` 状态；相同事件水位不重复提交权威快照，也不重新打开会话首帧门。
- 任务推送统一解析完整模型身份；同名裸模型只允许由项目默认来源解除歧义，否则要求用户重选。
- 任务推送校验 Graph 命令实际派生的 `operationIdentity`，不再拿错误层级的幂等键比较。
- 最终退出的 Provider 取消和中断并行等待；失败仍按 `outcome_unconfirmed` 留存审计，不伪造成功。
- 只读验证中的原生会话不再因 `readOnly=true` 被误归类为旧版只读会话；仍使用 Snapshot V2 读取完整历史，同时禁用交互写入。
