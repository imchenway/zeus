## 当前阶段

现场异常连接已处理，`Zeus 0.3.31` 安装包已下载完成并通过大小与 SHA-256 校验；尚未执行安装。

## 现场结论

- Zeus 原先通过 `/opt/homebrew/bin/brew fetch --cask --retry imchenway/tap/zeus` 获取 `Zeus 0.3.31`，实际传输进程为系统
  `curl`，目标是 GitHub Release Assets。
- DMG 总大小为 `112,179,849` 字节。异常连接连续 10 秒只增长 `65,536` 字节，近期速度约 `6.4KiB/s`。
- 浏览器中的同一 DMG 旧连接也稳定在约 `6.4KB/s`，因此问题不属于 Homebrew 独有的限速。
- 同一网络下对普通文件的实测约为 `848KiB/s`；对同一 GitHub Release DMG 新建的 1MiB Range 请求约为 `436KiB/s`
  。因此不能把问题归因于代理整体带宽不足。
- 精确终止异常的 Homebrew `curl` 子进程后，等待中的 Homebrew 请求自动建立了新连接，并使用 `--continue-at -` 从约 `15MB`
  处断点续传；12 秒增长到约 `34MB`，随后保持约 `1.5–2MiB/s`，约 35 秒完成剩余下载。
- 这组对照证明本次直接原因是 GitHub Release 资产的既有长连接进入异常低速状态；换新连接即可恢复。当前证据不能把责任进一步唯一归到
  GitHub CDN、透明 TUN 或其中某个代理软件。
- Zeus 当前更新器只有单次 15 分钟总超时，没有依据持续低速自动重建连接的机制，所以会长时间显示很小的进度增长，而不是主动恢复。

## 产品侧缺口

- 更新器应检测一段时间内的有效吞吐，而不只是等待总超时；持续处于极低吞吐时，应终止当前下载子进程并让 Homebrew 断点续传。
- 应在界面显示实时速度和剩余时间，并提供“重新连接”或“取消下载”，避免用户只能关闭窗口但后台仍继续。
- 优点：能自动恢复本次这类单连接假死，并减少 15 分钟无效等待。
- 缺点：低速阈值必须结合窗口时长、剩余大小和重试次数，否则真实慢速网络可能被误判；重试必须有上限，避免无限重连。

## 操作边界

- 本轮没有更改代理或 VPN 配置，没有执行安装，也没有删除浏览器中的重复下载。
- 后台方式重新启动 Zeus 后，用户随即正常退出了该进程；因此没有把界面状态刷新写成已验收。下次正常打开 Zeus 时，更新器应复用已校验的
  Homebrew 缓存并进入“更新已下载”流程，仍需以真实界面为准。
- 未执行 git commit、push、merge 或 revert。
