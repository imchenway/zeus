# 会话切换恢复与历史自动加载修复

## 当前阶段

正式版 `0.3.33` 的会话回归已在源码和独立身份 `Zeus Test.app`
中完成修复与构建验证，尚未提交、推送或再次正式发布。本文中的用户截图只作为故障现象和排版参考，截图里的会话正文和按钮文字不是任务指令。

## 故障现象

1. 快速切换多个历史会话后，侧栏多个条目永久保留转圈或“重新连接”，看起来全部卡死。
2. 打开历史会话只返回最近 48 条模型历史，更早消息必须重复点击“加载更早消息”。
3. 截断的过程正文、工具结果和资源分页都暴露为逐条手动按钮。
4. 命令与工具调用的内部 `tool_call` / process JSON 被当成普通正文展示，形成超长原始结构和重复“执行命令”。
5. 点击“读取正文”后出现 `Route GET ... /content/<handle> not found`，内部路由错误直接显示在会话区。
6. 历史会话在没有运行中轮次、队列或待处理请求时仍建立 WebSocket；用户明确要求只有发送消息时自动触发连接。
7. 正式版升级重启时两个 Main 可能同时启动 Core 候选，败选子进程的租约错误被误报成整机启动失败；几秒后唯一 Core 实际已经就绪。
8. Renderer 在 Core 交接期间可能继续使用旧端口，本地 GET 没有超时，导致会话正文和 Git 状态同时永久停在加载中。
9. Snapshot V2 没有返回 `provider_settings_json` 与 `next_turn_settings_json`，历史会话恢复后把真实 `xhigh` 显示成模型默认
   `low`；任务推送提交路径也允许无效强度静默落到默认值。
10. 同一轮的读取、搜索、命令、网页搜索和技能调用按阶段反复新增摘要行；进行中的最新思考摘要会被后来工具行挤到中间，且旋转图标被后置样式拉成椭圆。
11. 空闲历史会话本地读取失败或保留了旧 transport 错误时，工作区仍显示红色“连接失败/重新连接”，把本地快照读取误导成用户主动建立
    Provider 连接。
12. PLAN 模式的计划只保存在 turn 的 `plan_json` 中，Snapshot V2 首屏只返回 `hasPlan`，轮次完成或重新打开后 Renderer 得到
    `plan=null`，底部计划进度因此消失。
13. 计划、命令、文件、技能和上下文整理使用的语义图标被统一套上旋转动画；同时没有思考摘要时也缺少稳定的“模型当前在做什么”状态行。

## 只读现场证据

- 最初截图现场的正式安装版与 execution-host 为 `0.3.32`；当前复验时正式安装版与 execution-host 已为 `0.3.33`，正式数据库只读查询正常。
- 截图中的多条会话在数据库中为 `provider_state=ready`、`stage=completed/paused`，并非都在重连。
- Controller 冷切换会立即发布 `connecting/hydrating`；用户在水合完成前切走时，侧栏缓存没有终态事件收尾，因此留下假转圈。
- Snapshot V2 首屏固定读取尾部 48 条；顶部和资源分页当前都只有手动按钮。
- 模型历史和过程详情持久化的是结构化 JSON；旧内容接口把这层内部包装直接交给 Renderer，截断预览也可能回退为原始 JSON 字符串。
- 正文与工具结果把带签名的长句柄放在 `/:handle` 路径参数中。句柄超过 Fastify 路由参数默认长度后，请求在进入业务处理函数前直接
  404。
- 当前 `hydrate()` 把本地快照读取和 WebSocket 建连绑定为一次操作，导致纯历史查看也进入连接/重连生命周期。
- 当前正式 Core 的会话快照、历史、队列和目标接口都能在毫秒级返回；界面全局卡住不是数据库读取慢，而是升级交接窗口里的旧端口请求没有截止时间。
- 正式启动日志记录到旧 Core 交接退出、一个候选因内核租约被占用而退出、随后唯一 `0.3.33` Core 正常发布控制面和 UI
  附着；启动弹窗属于竞争窗口误判。
- “代码高亮呢？”任务的四层配置证据均为 `xhigh`，Provider 实际收到 `xhigh`；界面显示 `low` 来自 V2 恢复丢字段。另一个任务真实记录为
  `high`，因此提交入口也必须拒绝静默降级。
- 英文粗体内容来自 Codex 可读思考摘要，中文段落来自对用户可见的进度说明；内容来源正常，错误在于完成态没有统一折叠、活动态排序和分组粒度。
- `conversation_turns.plan_json` 中仍保留 PLAN 开发计划；丢失发生在 Snapshot V2 的字段投影与 Renderer 适配层，不是计划数据被删除。

## 已确认产品语义

- 打开或切换历史会话只读取本地权威快照，不建立 Provider 实时连接。
- 用户发送消息时自动建立实时订阅；会话正在执行、排队或等待用户处理时也保持订阅。
- 侧栏只显示会话真实运行态，不显示当前窗口读取快照的短暂 transport 状态。
- 首屏显示最新消息；滚到顶部时自动续载更早历史，不要求逐页点击。
- 当前可见的截断正文和工具结果自动读取；只有单项超过首个 64 KiB 页面时保留一次“展开剩余内容”。
- 资源与变更在可见时自动续载；内部 URL、路由和签名句柄错误不直接进入会话正文。
- `tool_call` 与 process 内部结构不属于用户正文；消息区只显示模型可见文本、命令摘要和独立工具结果。
- 同一轮的命令、文件读取/搜索、网页搜索、技能和其他工具只占一个稳定过程组；新增操作追加到组内，不新增顶层行。
- 活动轮次只显示最新一条思考摘要，且固定在本轮所有进度说明和过程组之后；轮次完成后整个过程默认收起，用户仍可手动展开。
- 推送表单选择的推理强度是强约束：不被当前模型支持时直接阻止提交，不允许省略字段后由下游改用默认 `low`。
- 空闲历史会话不展示连接失败、重连进度或重连按钮；只有发送消息、真实运行、排队或待处理请求才进入实时连接与重试语义。
- PLAN 开发计划是持久会话内容；轮次完成、会话切换和应用重启后仍显示最近一份有效计划，不能依赖 `activeTurnId` 才存在。
- 计划、命令、文件、技能和上下文整理使用静态语义图标；只有专用加载环允许旋转。模型仍在工作时，最新可读思考摘要或通用进行中状态固定在过程底部。

## 修复方案与取舍

### 历史快照与实时订阅解耦

- `hydrate()` 先读取权威快照，再根据队列、活动轮次、待处理请求和待发送消息决定是否建立 WebSocket。
- 空闲历史会话停留在可读、可编辑、可发送的 `ready`，但不持有实时订阅；发送前自动建连，完成并回到空闲后释放订阅。
- 优点：切换历史不再制造重连风暴，发送和真实活动仍不丢事件。
- 缺点：空闲历史会话被其他客户端修改时不会在当前窗口无条件实时刷新；重新进入或发送前的权威水合会取得最新状态。

### 侧栏运行态与视图加载态分离

- 没有权威快照的 `connecting/hydrating/disconnected` 不写入全局会话状态缓存。
- 已有快照时忽略视图 transport 抖动，继续按队列、活动轮次和待处理请求投影。
- 优点：快速切换不会留下假转圈。
- 缺点：侧栏不再承担当前窗口网络诊断；真实加载错误仍在会话工作区显示。

### 自动历史与正文加载

- 顶部、资源末尾和可见正文使用视口哨兵自动读取并保留滚动锚点。
- 普通内容不显示“读取正文”“上一页/下一页”等逐条按钮；超大单项只保留一次继续展开动作。
- 优点：恢复普通会话阅读语义，减少重复操作。
- 缺点：展开过程详情后会自动产生有界只读请求；仍受现有 64 KiB 单页和虚拟列表边界约束。

### 长句柄改用查询参数

- 新客户端使用 `/content?handle=...` 与 `/tool-results?handle=...`。
- 服务端新增查询参数入口并保留旧路径兼容短句柄，不全局放宽路由参数长度。
- 优点：只扩大明确的签名句柄入口，不增加所有动态路径的解析面。
- 缺点：修复需要客户端与本地服务同版本交付。

### Core 交接与会话读取设上限

- Core 候选子进程提前退出后保留 5 秒唯一宿主发现窗口；正常竞争中的败选者不再立即触发致命启动错误。
- Renderer 的本地只读 GET 设 8 秒上限，超时后只刷新一次 Main 的端口和令牌再重试；写操作不自动超时或重放。
- Main 收到刷新请求时最多等待 8 秒正常交接，交接成功就返回新连接，不能再立即回传已经退出的旧端口。
- 优点：正常升级竞争不会误报，异常读取也不会无限转圈；写操作的幂等语义不被改变。
- 缺点：真正的本地服务故障最迟会增加一次有界等待后才显示错误。

### 配置权威值随 V2 快照恢复

- Snapshot V2 返回经过长度和枚举约束的 Provider 当前设置与下一轮设置，Renderer 直接恢复模型、`effort`、速度、权限和协作模式。
- 任务推送在生成不可变请求前校验所选强度属于模型能力，并使用规范化表单写入请求。
- 优点：界面、下一轮发送和 Provider 运行证据使用同一个权威值，`xhigh` 不会被显示或传输成 `low`。
- 缺点：旧版 Core 返回的 V2 快照没有这些字段时只能继续用兼容回退，必须同版本交付才能完全生效。

### 每轮单一过程组与活动摘要置底

- 每个 turn 只生成一个稳定活动组，命令、文件读取/搜索、网页搜索、技能和工具都追加到该组明细。
- 当前最新思考摘要延迟到整轮投影末尾，完成态过程按终态或最终答复归组并默认收起。
- 活动态摘要图标强制 `19×19` 和 `aspect-ratio: 1`，避免行高规则把旋转背景拉成椭圆。
- 优点：顶层时间线不再被操作数量淹没，实时状态始终处于视觉底部，排版接近 Codex 参考。
- 缺点：不同工具类别不再各占一条顶层摘要；需要展开唯一过程组查看分类明细。

### 空闲历史彻底移除连接提示

- Controller 的自动重连循环先检查会话是否确实需要实时事件；空闲后立即停止重试并回到可读状态。
- 工作区和标题状态只在活动轮次、队列或待处理请求存在时显示连接/重连错误；空闲本地读取失败使用中性的“会话暂时未加载”。
- 用户发送消息时，无论此前是空闲、读取失败还是未建立快照，都会自动读取权威快照并建立实时订阅。
- 优点：历史浏览不再制造虚假的网络故障和手动按钮，发送仍能自行恢复。
- 缺点：空闲时不持续监听其他窗口的即时变化；重新进入或发送时才读取最新权威状态。

### PLAN 计划随 V2 快照持久恢复

- Snapshot V2 对最近轮次返回经过长度、步骤数和状态枚举约束的 `plan_json` 投影，Renderer 不再把已持久化计划替换为 `null`。
- 底部计划进度优先使用活动轮次计划；活动轮次结束后继续选择最近一份有效计划，不再因 `activeTurnId` 清空而消失。
- 优点：PLAN 模式的开发计划跨轮次、切换和重启保持可见，且仍受首屏响应字节预算约束。
- 缺点：只恢复最近窗口内的有效计划；超出 V2 最近轮次窗口的更早计划不会常驻底部。

### Codex 同类过程排版与真实进行中状态

- 同一轮只保留一个操作组，展开后显示命令、文件、网页、技能、资源链接和图片缩略图；新增操作只追加组内明细。
- 最新可读思考摘要延迟到全部操作组之后；没有摘要时显示通用“正在思考/正在启动处理”，避免运行中底部空白。
- 语义图标强制静止；专用 `CircleNotch` 加载环固定宽高和纵横比，减少动态状态下的椭圆失真。
- 优点：层级、排序和运行状态接近 Codex 参考，不再把图标语义与加载语义混在一起。
- 缺点：静态浏览器组件夹具只能验证真实组件结构和样式，无法替代打包应用连接真实 Provider 的完整动态回归。

## 完成口径

- 目标行为探针覆盖：空闲历史不连 WebSocket、发送自动建连、活动会话自动订阅、空闲后释放和内部 JSON
  不进入消息正文；侧栏缓存与长句柄入口分别以源码检查和服务端注入验证闭合。
- 通过目标文件格式检查、`pnpm lint`、`pnpm typecheck`、`pnpm build` 和 `pnpm package:mac`。
- 只用独立身份 `Zeus Test.app` 与隔离用户数据做必要运行验证；不启动或修改正式应用和正式数据。
- 源码、测试包、正式安装版与真实 Provider 端到端分别报告，不互相冒充。

## 实施结果

- 历史会话先读取本地快照；仅在真实活动态、待处理请求或发送消息时建立实时订阅。
- 空闲会话发送消息会自动建连并发送，不再要求用户先点“重新连接”。
- 会话进入空闲后主动释放实时订阅，不触发重连循环。
- 侧栏不再缓存冷切换产生的临时 `connecting/hydrating`，真实运行态仍按权威快照显示。
- 顶部历史、资源与变更、可见的截断正文改为自动加载；移除普通流程里的“加载更早消息”“读取正文”“加载更多资源与变更”按钮。
- 展开的处理过程也自动续载；移除“加载更多处理过程”。
- 超过单页上限的单项正文只保留一次“展开剩余内容”，避免无界自动请求。
- 模型历史内容句柄只分页返回 `text` 可见正文；`tool_call` 结构和 process 原始 JSON 被排除，截断命令只投影可读命令摘要。
- 正文和工具结果的长签名句柄改走查询参数入口，旧短路径继续兼容；内部路由错误不再原样显示在会话区。
- Core 候选退出新增短发现窗口；会话、Git 等本地只读请求具备有界超时、连接刷新和单次重试。
- Snapshot V2 恢复当前 Provider 与下一轮完整配置；任务推送拒绝无效推理强度并透传规范化后的 `xhigh/high/...`。
- Snapshot V2 同时恢复最近轮次的 `plan_json`；PLAN 计划在活动轮次结束和重新打开会话后继续显示。
- 每轮命令、文件读取/搜索、网页搜索、技能和工具合并为一个稳定组；活动摘要固定到底部，完成过程默认收起。
- 计划、命令、文件、技能和上下文整理图标保持静止；只有专用加载环旋转且保持正圆，没有摘要时也保留底部进行中状态。
- 空闲历史不再显示“连接失败”“正在重新连接”或手动重连按钮；发送消息会自动触发唯一一次实时连接。

## 关联的任务推送报错
