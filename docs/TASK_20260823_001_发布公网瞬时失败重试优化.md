# 发布公网瞬时失败重试优化

## 任务目标

降低 `pnpm release` 因 GitHub 网络握手或钥匙串登录探测的单次瞬时异常而中断的概率，并在修复提交后通过既有恢复机制继续尚未公开的 v0.3.35。

## 现场事实

- v0.3.35 发布提交 `037ebdd892ad74efd33441a6ab61584c88d71d95` 已推送到 `origin/main`。
- 远端尚无 `v0.3.35` 标签和 GitHub Release，发布恢复状态停在 `main_pushed`，尚未触发 Release Workflow。
- 首次失败是 `git ls-remote` 返回 `LibreSSL SSL_connect: SSL_ERROR_SYSCALL`；原脚本虽然配置三次读取机会，但没有把该错误识别为瞬时故障，所以实际只执行一次。
- 第二次失败是 `gh auth status` 单次返回钥匙串令牌无效；随后使用同一账号和钥匙串现场复验已成功，说明单次探测不足以区分真实凭据失效与短暂读取异常。
- 公开发布包含远程 main、标签、GitHub 登录、Workflow、Secrets、Release、资产和 Homebrew 多项外部读取；每项都单次失败会放大整条链路的中断概率。

## 已确认设计

### 只重试远程读取

远程读取统一最多执行三次，失败后分别等待 1 秒和 3 秒。覆盖 TLS 握手提前断开、`SSL_ERROR_SYSCALL`、连接重置、临时 DNS、GitHub 429/5xx，以及钥匙串登录探测的瞬时失败。连续失败后仍保持失败关闭并保留最后一次原始原因。

优点：短暂网络抖动和钥匙串读取异常可在发布命令内部自行恢复，不需要用户从头重跑。

缺点：真实凭据失效或持续网络中断会比原来晚约 4 秒报告。

### 不盲重试远程写入

main push、Release Workflow 派发、标签、GitHub Release 和 Homebrew 写入不进入通用重试器。写操作异常后继续依赖既有的远端事实回读和恢复状态决定下一步。

优点：避免请求已经被 GitHub 接收但本地未收到响应时重复派发或重复创建远程对象。

缺点：写操作遇到瞬时故障时仍可能中断一次，需要同一发布命令通过恢复状态续跑。

## 实施范围

1. 提取发布公网只读失败分类、有限次数和退避策略，供端到端发布与公开发布脚本复用。
2. 公开发布前置的 GitHub 登录、远程引用、Workflow、Release、Actions Secrets、运行状态和公开资产下载全部使用统一策略。
3. 远程标签和 Secrets 读取失败必须报告真实读取错误，不能误判成“标签不存在”或“Secret 缺失”。
4. 增加无远程写入的行为探针，覆盖瞬时 TLS 恢复、钥匙串恢复、连续失败关闭和确定性错误不重试。
5. 完成本地格式、静态、类型、构建和行为验证后提交，再由 `pnpm release` 安全重绑定并继续 v0.3.35。
