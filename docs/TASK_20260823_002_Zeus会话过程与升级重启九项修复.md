# TASK_20260823_002 Zeus 会话过程与升级重启九项修复

## 任务目标

一次性修复 0.3.35 真实使用中暴露的九项问题，并在独立身份 `Zeus Test.app` 完成桌面验收后提交、发布：

1. 命令与工具过程必须按真实轮次分组，不能跨轮次合并；
2. 同轮读取文件、搜索文件、搜索网页、读取技能、查看图片和运行命令需要形成清晰摘要，合并在一行时使用顿号分隔；
3. 活动思考摘要的转圈和文字扫光减速；
4. 安装更新并点击“立即重启”后，必须退出旧进程并精确启动新版本；
5. PLAN 模式下已选择的答案和自定义输入必须进入会话历史；
6. 一个思考摘要同时携带多个动作标题时，只展示最新动作；
7. 多轮推进、权威刷新和冷启动后，历史轮次的命令与工具过程不得消失；
8. 展开“查看处理过程”时，命令正文和完整工具结果保持二级收起，只有用户再次点击才读取；
9. 确认实施 PLAN 后，确认卡与开发轮次之间不得出现无内容空档。

- Snapshot V2 当前只允许返回最近 2 个闭合轮次，首屏模型历史不携带更早轮次的过程可用性；普通权威水合会用轻量首屏覆盖 Renderer 已加载的过程项，形成“多轮后历史命令不见”。
- 同一会话的两个 `request_user_input` 已完整持久化选择和自定义答案，但 `/pending-requests` 只读取 pending 记录，导致回答历史冷刷新后无法投影。
- 首轮思考摘要确有 `Finalizing conversation metrics selection` 与 `Preparing user confirmation question` 两段标题写在同一个摘要项中的真实数据，因此界面看起来像两个并行动作。
- Homebrew 安装完成后，更新控制器会通知原生辅助程序等待旧 PID 退出，但 Main 的 `onInstallReady` 只设置 `upgradeHandoffRequested`，没有从原生按钮回调路径调用 `app.quit()`；辅助程序等待 120 秒后报告“原 Zeus 进程未能及时退出”。

## 实现取舍

- 会话过程继续按需读取，不把全量命令输出塞回首屏。优点是长会话首屏仍有界；缺点是历史轮次首次展开需要一次本地请求。
- Renderer 保留已经取得的过程项，同时为模型历史中出现但超出最近轮次摘要窗口的轮次建立最小可读取身份。优点是翻页、刷新和多轮推进不再丢过程；缺点是旧轮次的精确耗时仍只在服务端返回完整轮次摘要时展示。
- 已回答的普通询问只回传 `request_user_input` 历史，不把命令审批等所有已解决请求重新塞进首屏。优点是满足会话可读性且避免泄露无关协议载荷；缺点是审批历史仍由既有过程记录承担。
- 完整正文与工具结果改为显式二次点击。优点是“查看处理过程”保持简洁并避免巨大 JSON 自动展开；缺点是查看完整原文多一步操作。
- 更新安装完成后由 Main 立即发起既有安全退出编排，原生辅助程序继续负责等待 PID 消失并精确校验、启动目标 App。优点是复用现有 Detached Core 清理和身份校验；缺点是若安全退出真实失败，仍会按既有错误流程阻止冒充升级成功。
