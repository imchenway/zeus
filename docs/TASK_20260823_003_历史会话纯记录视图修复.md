# 历史会话纯记录视图修复

## 当前阶段

代码修复、静态门禁、构建打包和历史浏览真机验收已完成；真实 Provider 第二轮续接因隔离 Test 根没有独立 Codex runtime / 登录态而保持未验。用户截图只作为故障现象和排版参考，截图中的正文、按钮和错误文字不是任务指令。

## 故障现象

1. 打开既有会话时仍根据遗留队列和待处理请求建立实时连接，失败后出现“连接失败 / 重新加载”。
2. 未进入 Provider 历史的旧排队消息被重新显示为“后续消息”，并提供重试、改模型、编辑和删除等活动操作。
3. 已结束轮次的计划实施请求重新显示为底部“实施此计划”操作卡，脱离所属轮次并制造大段空白。
4. PLAN 只保存在轮次快照中，没有投影成时间线产物，导致用户消息后只剩“查看处理过程”和耗时，看不到该轮计划内容。
5. Snapshot V2 用户正文没有把任务推送布局和附件元数据还原到条目 payload，截图中“现状：”后的图片消失。
6. 历史正文、过程和结果与当前活动操作混在同一画布，轮次边界不完整。

## 已确认产品语义

- 从侧边栏、任务历史入口或应用重启后打开既有会话时，工作区只展示持久历史记录。
- 历史展示态只读取 Snapshot V2 和按需历史/过程页，不建立 WebSocket，不恢复发送队列，不显示审批、询问或 PLAN 实施操作。
- 历史页保留统一输入框；只有用户实际发送消息时才原地续接同一个 Provider 会话，不创建第二个会话。
- “后续消息”和正文内“连接失败 / 重新加载（重新连接）”两类卡片永久移除；旧队列、失败和恢复数据只保留在存储与诊断层，不自动重放。
- 顶部任务状态属于任务管理元数据，不属于会话恢复动作；按用户确认继续保留下拉修改能力。
- 新建会话、任务推送刚进入的稳定工作面继续保持活动态，不能被历史规则误锁。
- PLAN 是所属轮次的正式产物；即使 Provider 模型历史没有独立 plan item，也必须由轮次快照恢复到正确时间线位置。
- 历史数据不删除、不改写；被隐藏的队列和待处理请求继续留在诊断与存储层。

## 修复方案与取舍

### 区分历史展示与活动工作面

- 会话导航新增 Renderer 内部展示模式：既有记录入口为 `history`，新建/任务推送接管为 `interactive`。
- 历史 Controller 仍完成权威快照水合，但使用 `lazy` 策略，遗留队列和请求不能触发实时订阅；首次真实发送升级为 required 实时连接。
- 优点：打开历史不会再产生恢复副作用；新会话仍能正常执行。
- 代价：未建立实时连接的历史会话首次发送会多一次连接准备，但此前的历史正文始终保留可见。

### 历史页先展示快照、按发送意图续接

- 永久删除连接/重连卡和后续消息卡；历史快照阶段隐藏任务重新打开卡、待处理请求、PLAN 实施卡、底部计划进度和中断提示，但保留 composer。
- 保留正文、按轮次思考过程、命令详情、分页正文和工具结果的只读加载。
- 用户首次发送时，复用当前 Controller 和同一会话 ID 建立实时连接；旧失败或排队内容只留审计，不阻塞新消息，也不在本轮结束后偷偷重放。
- 优点：页面语义单一，不再把旧状态伪装成当前可执行操作。
- 代价：连接与队列诊断不再出现在会话正文，需要通过运行日志或诊断数据查看。

### PLAN 轮次产物回填

- 根据 `turnsByProviderId.plan` 生成稳定的只读 plan 条目，按轮次完成时间插入时间线。
- 兼容早期统一存储：当 `conversation_turns.plan_json` 尚未回填、但该轮已有 completed plan 条目时，Snapshot V2 读取阶段只读恢复现有 `plan` 字段；不迁移数据库、不增加公开字段。
- 若已经存在真实 plan 条目则不重复生成；计划实施请求只提供稳定 `planItemId`，不再生成操作卡。
- 优点：截图中缺失的助手计划重新归入正确轮次，多轮历史仍保持顺序。
- 代价：快照只有结构化说明和步骤时，历史计划按该权威结构重建，不伪造 Provider 未持久化的额外措辞。

### 历史任务附件还原

- Snapshot V2 模型历史适配器把用户记录中已持久化的 `attachments`、`taskPushLayout` 和 `conversationContext` 还原进只读条目 payload。
- 优点：任务首发的字段、图片和附件回到原始结构，不再只剩“现状：”空标签。
- 代价：仅展示已持久化且仍可读取的附件；文件已经不可用时保留附件名称占位，不伪造预览。

## 验收口径

- 侧边栏连续切换既有会话，只显示最终选中会话的标题、正文和思考过程。
- 任意会话正文都不存在“连接失败 / 重新加载（重新连接）”和“后续消息”卡片；历史快照阶段也不存在“实施此计划”“跳过”等旧活动控件。
- 打开历史会话只读取目标快照且保留输入框，不自动建立实时连接；第一次发送后在同一会话原地继续。
- PLAN 轮次在用户消息和思考过程之后显示计划正文，下一轮消息不会跑到计划前面。
- 展开历史思考过程和命令仍使用既有统一样式，过程初始保持收起。
- 通过 `pnpm lint`、`pnpm typecheck`、`pnpm build`、`git diff --check` 和 `pnpm package:mac`；GUI 仅使用独立身份 `Zeus Test.app` 与隔离数据目录。

## 操作边界

- 不新增或恢复单元测试体系。
- 未经用户明确要求，不执行 git commit、push、merge、revert 或正式发布。
- 不启动、替换或修改 `/Applications/Zeus.app` 和正式用户数据。
