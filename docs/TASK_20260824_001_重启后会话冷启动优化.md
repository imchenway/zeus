# TASK_20260824_001 重启后会话冷启动优化

## 任务目标

解决 Zeus 重启后重新打开历史会话时长时间停留在“正在加载会话”、正文空白的问题。目标不是隐藏加载状态，而是在不改变数据库权威事实、不误恢复审批或发送动作的前提下，优先恢复最近一次可信的会话显示内容，并在后台完成最新快照刷新。

## 2026-08-24 现场基线

- 用户截图中的正式安装版为 `0.3.42`，应用外壳、项目和会话列表已经出现，但正文仍显示整页“正在加载会话”。
- 正式数据目录只读核查：数据库约 4.8 GB，包含 508 个会话、132,922 条会话项、179,528 条模型历史和 75,665 条同步事件。
- 正式运行现场的执行宿主从启动到控制面就绪约 3.52 秒。
- 应用已运行后的只读接口实测：目标会话 Snapshot V2（不含指标）约 1.2～2.8 ms，模型历史尾页约 3～4 ms，队列、待处理请求和选择状态均为毫秒级；因此截图中的持续空白不能归因于当前单会话数据库查询。
- 当前 Renderer 的 `sessionHotCache` 仅由 React `useRef(new Map())` 保存，进程退出后必然丢失。它能优化同一次运行中的会话切换，却不能覆盖用户反馈的“每次重启”。
- Renderer 启动阶段依次等待动态模块、Dashboard 和外壳设置，存在可消除的串行瀑布。

## 根因结论

主因是会话显示热缓存没有重启边界：应用退出后最近会话的可信显示态全部丢失，重启首屏只能等待新的会话控制器创建和冷水合，期间 Renderer 用整页骨架遮住正文。

次因是 Renderer 启动的独立读取串行执行，放大了从窗口出现到会话控制器开始水合的等待时间。

## 实施设计

### 1. 重启可用的会话显示缓存

- 复用现有内存热缓存的条目数、单条 8 MiB 和总计 32 MiB 预算，只持久化已经取得权威快照的最近会话。
- 缓存写入 Electron 用户数据目录的独立文件，使用版本号、保存时间、过期时间、原子替换和仅当前用户可读写的文件权限。
- 启动时在 Main/Preload 边界读取，Renderer 在 React 首次渲染前校验并预热现有热缓存。
- 缓存只作为显示副本；进入会话后仍立即读取最新 Snapshot V2 并覆盖缓存，数据库和 Provider 仍是唯一业务事实。
- 不持久化输入草稿、附件、浏览器提交、上下文草稿、瞬时错误、正在执行的本地操作及待审批/待用户输入表单，避免把过期交互状态恢复成可操作现场。
- 从磁盘恢复的 Transport 状态固定为未连接，所有发送、审批和继续动作仍要等待当前会话控制器完成最新水合。

### 2. 启动并行化

- 将 App 动态加载、Dashboard、外壳设置和会话显示缓存读取合并为同一组并行任务。
- 在首次 React render 前完成缓存预热，使选中会话首帧直接命中最近可信内容。

### 3. 写入节流与失效

- 只在权威会话状态进入现有热缓存后安排持久化，使用尾随节流，避免流式输出期间频繁序列化和写盘。
- 窗口卸载前再发送一次最新缓存快照；Main 端串行合并写入，避免并发覆盖。
- 缓存格式不兼容、内容损坏、超出预算或过期时直接忽略并退回现有冷水合流程，不阻断应用启动。

## 方案优缺点

优点：

- 重启后不再以空白骨架作为唯一首屏，最近会话可以立即阅读。
- 不需要改变 4.8 GB 正式数据库的结构，也不扩大 Snapshot V2 查询范围。
- 复用现有“缓存先显示、权威快照后台刷新”的会话切换语义，风险面较小。
- 文件有严格数量、体积、版本和时效边界，失败时可安全降级。

缺点：

- 启动首帧可能短暂显示上次退出时的内容，必须明确保持“正在刷新会话”状态并禁止依赖旧状态执行动作。
- 会增加一个受控的本地显示缓存文件和少量退出前写盘。
- 超过体积上限、长期未打开或首次打开的会话仍需走冷水合，不能承诺所有历史会话都零等待。

## 实施结果

### 跨重启显示缓存

- 新增 Main 进程拥有的 `session-view-cache-v1.json`，路径位于当前身份独立的 Electron 用户目录。
- Renderer 继续复用原有会话热缓存语义，在最新权威水合完成后 2.5 秒尾随写入，并在页面退出时补发一次。
- Main 使用原子临时文件替换，读取时要求普通文件、非符号链接、单硬链接、当前用户所有、权限精确为 `0600`，并限制信封、条目数和实际 UTF-8 文件体积。
- 缓存格式固定为 `zeus-session-view-cache-v1`，单条最多 8 MiB、总状态最多 32 MiB、最多 32 个信封条目、最长 14 天；运行期普通会话仍遵守既有 6 条 LRU 和关键会话保护策略。
- 跨重启副本强制使用 `disconnected` Transport，仅保留正文、轮次、指标和显示进度；草稿、附件、浏览器提交、上下文草稿、审批/回答请求、计划实施请求、发送队列、本地执行态、瞬时错误和 optimistic 项全部剔除。
- 磁盘缓存只在本次进程已经完成权威水合后续期；旧缓存刷新失败不会通过启动或退出流程延长条目寿命。

### 启动并行化

- App 动态模块、纯本地会话显示缓存与执行宿主就绪检查并行启动。
- 服务配置取得后，Dashboard、外壳设置、App 模块和显示缓存统一汇合，不再依次串行等待。
- React 首次 render 前完成缓存校验和热缓存预热；目标会话控制器随后继续读取最新 Snapshot V2，缓存不替代数据库与 Provider 权威事实。

- Browser 不能承载 Electron `file://`、Preload IPC 和真实 Main/Execution Host 边界，因此没有用普通网页壳冒充桌面验收；最终界面由 macOS 应用控制直接核对。
