# TASK_20260824_004 会话工作态动效停顿与上滚闪烁诊断

## 任务目标

诊断两个 Renderer 现象：进行中灰色文字扫光到最后一个单词后周期性停顿，以及长会话向上滚动时页面闪烁。用户截图只用于识别视觉对象；截图中的英文正文不是任务指令。

## 根因结论

### 1. 灰色文字在末词停顿

- 该文字使用 `session-working-sweep 3.4s linear infinite`。
- `session-working-sweep` 在 `0%～18%` 固定为 `background-position: 120% 0`，在 `72%～100%` 固定为 `-120% 0`；一轮有 46% 的时间没有位移。
- 本地真实 DOM 以 100ms 采样一轮，累计约 `1500ms` 的 `background-position` 完全不变。末端停驻约 `0.95s`，再加循环起点约 `0.61s` 的静止区，形成“扫到最后一个词后卡住”的主观感受。
- 这是当前关键帧主动设计出的停驻，不是 Provider 停止输出、浏览器掉帧或英文单词宽度计算错误。

### 2. 会话向上滚动闪烁

- JavaScript 虚拟列表将未测量行统一按 `132px` 估高，并用 `ResizeObserver + getBoundingClientRect()` 将当前 DOM 高度写入测量缓存。
- 同一个虚拟行又启用了 `content-visibility: auto` 和 `contain-intrinsic-block-size: auto 132px`。内容尚未真实绘制时，`getBoundingClientRect()` 会返回 CSS 固有占位的 `132px`，测量器把占位高度误当成真实高度。
- 用户向上跨虚拟窗口时，新挂载行先按 `132px` 进入占位和前缀高度树；浏览器真正绘制后，现场普通消息行实际只有约 `44px`，随后 `ResizeObserver` 再次回写。上下占位、总滚动高度、窗口起止行和浏览器滚动锚点因此在连续帧内一起变化。
- 本地真实 `ConversationTranscript` 夹具扩展到 63 行后复现：第一次向上跨窗口，`scrollHeight` 从 `4702px` 瞬间变为 `5521px`，约 250ms 后回到 `4702px`；同时 `scrollTop` 从 `4191.5` 校正为 `3371.5`，回跳约 `820px`。
- 第二次继续上滚时，首末挂载行从 `qa-send-14～40` 变为 `qa-send-17～43`，随后又回到 `qa-send-14～40`；`scrollHeight` 在 `5726px`、`5248px`、`5317px` 之间继续收敛。画面闪烁来自这条“假测量 → 重投影 → 真测量 → 再重投影”的反馈链。
- 复现过程没有控制台 error 或 warning；这不是 React 错误边界或 Vite 遮罩，而是合法布局状态之间的可见跳变。

## 修复取舍

### 推荐方案

1. 为文字扫光使用连续的专用关键帧，不再复用带两端停驻的 `session-working-sweep`；扫光离开文字后直接进入下一轮，或只在文字完全恢复为均匀灰色时留空档。
2. 保留 JavaScript 虚拟窗口，但从 `.session-transcript-window-row` 移除 `content-visibility: auto` 与 `contain-intrinsic-block-size`。虚拟器已经将基础 DOM 限制为最多 48 行并带 900px overscan，不需要在已挂载窗口内再做第二层假高度虚拟化。
3. 测量高度变化时，以当前第一条可见稳定行做显式滚动锚点补偿；这样图片、展开过程和 Markdown 延迟布局造成的真实变高也不会推走阅读位置。

优点：直接切断 `132px` 假高度被缓存的反馈环，同时保留长历史 DOM 上限；滚动锚点补偿还能覆盖真实变高内容。

代价：最多 48 条已挂载行都会参与布局与绘制；另外需要维护一条明确的锚点校准路径。相对当前无限制历史 DOM，这个成本仍是有界的。

### 不推荐方案

- 只把 `132px` 调小：只能缩小部分普通短消息的误差，长 Markdown、图片、工具组和展开内容仍会产生反向误差。
- 继续保留双层虚拟化，只过滤“看起来等于 132px”的测量：真实高度恰好为 132px 时无法区分，且 `content-visibility` 的绘制时机由 Chromium 决定，判断不稳定。
- 仅依赖浏览器默认 `overflow-anchor: auto`：虚拟窗口会替换锚点候选，默认锚定无法保证跨挂载窗口保持同一条消息。

## 实施阶段

### 动效

- reasoning 灰色文字改为专用 `session-reasoning-continuous-sweep`，从 `120%` 连续移动到 `-120%`，周期 `1.85s`、`linear infinite`。
- 没有修改其他状态继续使用的 `session-working-sweep`，避免改变创建、思考等既有节奏。
- `prefers-reduced-motion: reduce` 下专用扫光和原状态文字都关闭动画，并恢复静态灰色。

### 上滚稳定性

- 从 `.session-transcript-window-row` 移除 `content-visibility: auto` 与 `contain-intrinsic-block-size: auto 132px`，切断 CSS 假高度进入 JavaScript 测量缓存的反馈环。
- 保留最多 48 行与 900px overscan；已挂载窗口行使用真实布局高度。
- 新增共享的视口锚点捕获和补偿：历史分页与 `ResizeObserver` 高度测量都以前台第一条可见稳定行为锚点，投影提交后校正 `scrollTop`。
- 自动跟随底部时跳过普通锚点补偿，继续由既有底部控制器接管；历史分页期间暂停自动测量补偿，防止两套规则叠加。

### 真实 QA 夹具

- 会话 QA 扩展为 72 条混合高度消息，提供第 25 条延迟增高/恢复入口，用于反复核对上滚锚点、窗口方向和 DOM 上限。
- 动效验收继续使用真实 `ConversationTranscript` 与计算样式，不使用静态 HTML 模拟业务组件。

## 实施取舍

- 优点：消除已确认的两端停驻和双层假高度反馈；滚动补偿同时覆盖 Markdown、图片和展开内容的真实延迟布局。
- 代价：虚拟窗口内最多 48 行都参与绘制，并新增一条显式锚点维护路径；仍由现有 DOM 上限控制总成本。
