# 历史分页提示位置修复

## 用户现象

向上滚动长会话时，“正在读取更早消息…”出现在消息区正文流中，位于旧消息与计划卡片上方，并额外撑开明显空白，看起来像一条悬空消息。

## 根因

`V2HistoryPageControl` 同时承担 IntersectionObserver 分页哨兵和可见加载文案。组件作为 `.session-transcript` 的第一个 flex 子项参与消息布局，叠加 `gap: 14px` 与自身 `min-block-size: 28px`，导致提示占据正文高度并影响历史锚点位置。

## 修复

- 分页哨兵改成滚动容器顶部的绝对定位 1px 非可见元素，只负责触发历史读取，不参与 flex 排版。
- 加载与错误状态拆成 `.session-transcript-shell` 顶部居中的轻量覆盖层，不改变消息高度，不拦截鼠标操作。
- 状态直接从 Snapshot V2 分页对象派生，不增加镜像 React state；加载使用 `status`，错误使用 `alert`。

## 取舍

- 优点：提示位置稳定，不再挤动旧消息、虚拟窗口或滚动锚点；错误状态仍然可见。
- 缺点：加载期间顶部会覆盖很小一块内容；使用半透明背景和不可交互样式降低遮挡影响。

## 验证边界

- 执行格式、lint、typecheck、build，并通过会话 QA 页面检查真实渲染位置。
- 不新增或恢复单元测试、组件测试和 DOM/CSS 契约测试。
- 用户已于 2026-08-24 明确授权将本任务与 PLAN 投递优化作为 v0.3.48 候选提交并正式发布。

## 验证结果

- `pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac` 与架构门禁均通过。
- 应用内浏览器打开本地会话 QA 页，加载提示真实计算样式为 `position: absolute`、顶部偏移 `10px`、`pointer-events: none`；分页哨兵为绝对定位 `1px × 1px`。
- 提示节点的父级为 `.session-transcript-shell`，不在 `.session-transcript` 正文节点内。
- 相同八条消息的有提示与无提示夹具 `scrollHeight` 均为 `1204px`，差值为 `0`；提示不再占据正文高度。
- QA 控制台无 warning/error，浅色实际渲染确认提示位于滚动区顶部，不再出现在消息流中。
- 测试包身份为 `dev.hypha.zeus.test` / `Zeus Test`，包健康、严格签名结构和测试 DMG 校验通过；没有启动或修改正式应用。
