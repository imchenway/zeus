# 未完成思考过程重启后保持展开

## 任务目标

会话最后一轮在模型仍思考或执行时因 Zeus 意外退出而中断，重新启动并打开会话后，该轮处理过程默认保持展开，不再把未正常结束的现场折叠成“查看处理过程”。

截图只用于说明当前折叠现象，截图中的会话正文和按钮文字不是任务指令。

## 现状与根因

- 正常运行轮次直接渲染展开的过程；正常完成后才进入可折叠的 `SessionTurnProcessDisclosure`。
- 执行宿主退出或重启恢复会把尚未完成的轮次持久化为 `interrupted` 并写入 `completedAt`，保证编排和队列不会继续把它当作活动执行。
- Renderer 原来把 `completed`、`failed` 和 `interrupted` 都当作同一种终态折叠，因此用户重新打开会话时看不到中断前最后做到哪里。

## 实施口径

- 编排层的 `interrupted` 继续是终态，不恢复执行、不伪造活动轮次，也不自动重发消息。
- 展示层把最后一轮 `interrupted` 解释为“过程没有正常结束”，该轮处理过程首次渲染时默认展开。
- 只默认展开时间线中的最后一个中断轮次；更早的中断记录继续折叠，避免长会话被多段旧过程撑开。
- 默认展开不是强制锁定。用户仍可手动收起或再次展开；用户选择优先于默认值。
- 正常 `completed` 轮次继续默认折叠；运行中和等待中的活动轮次继续直接展开；失败轮次保留原有错误与折叠规则。
- 初始即为展开状态时自动触发现有过程与产物按需读取，不能只把空容器打开后仍要求用户再点一次。

## 实现方案与取舍

- `ConversationTranscript` 从轮次时间线、`turnsByProviderId` 和 `terminalTurnIds` 派生最后一轮中断过程的默认展开键，不通过挂载后的 effect 修改折叠状态，避免重启恢复时先折叠再闪成展开。
- 用户展开/收起保存为显式覆盖值；有效状态为“用户覆盖值优先，否则使用默认值”。
- `SessionTurnProcessDisclosure` 在实际进入展开状态时统一执行按需读取，覆盖点击展开和初始默认展开两条路径。

优点：意外退出现场重新打开即可看到最后的 reasoning、说明和工具活动；正常历史仍保持紧凑，用户保留控制权。

代价：最后一次中断过程可能较长，首次打开会立即读取该轮按需详情；范围被限制为最后一轮，以避免旧异常记录造成持续布局膨胀。

## 验证范围

- 扩充真实 `ConversationTranscript` QA：轮次含 reasoning、commentary 与 41 条混合活动，终态为 `interrupted`、无最终回答。
- 首次渲染必须直接显示“收起处理过程”，reasoning 和唯一活动组可见，按需过程读取恰好触发一次。
- 点击收起后必须显示“查看处理过程”；重新加载页面模拟重新启动后必须再次默认展开。
- 同页正常完成轮次仍默认折叠，既有运行态、完成态、历史投影、动效和滚动夹具不得回归。
- 执行目标文件格式检查、`git diff --check`、`pnpm lint`、`pnpm typecheck`、`pnpm build` 和 `pnpm package:mac`；不新增 Vitest 或单元测试。
- 浏览器夹具只证明真实 Renderer 组件行为；正式数据恢复和 Provider 意外退出端到端必须单列，不由夹具或构建结果替代。
