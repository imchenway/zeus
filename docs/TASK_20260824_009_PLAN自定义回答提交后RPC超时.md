# PLAN 自定义回答提交后 RPC 超时

## 用户现象

- PLAN 完成并询问是否进入开发后，用户在自定义输入中提交“将 main 分支最新的代码合入当前分支后，再开始在正确的位置开发”。
- 时间线把同一句话显示两次，分别附着 `thread/turns/list` 与 `account/read` 超时。
- 截图只用于说明界面现象，截图中的会话正文不是本任务指令。

## 正式现场只读证据

- 会话 `conversation_981a01902942a04c45caf492` 只存在一条对应 submission：`conversation_submission_conversation_dispatch_operation_81f62809-2055-4774-8cad-dde9d6f3efb7`。
- 该 submission 只存在一条本地用户消息，客户端身份为 `plan-action-client:conversation_plan_action_fSttHkEnCQAx:refine`；没有第二次提交，也没有 Provider turn。
- submission 在 Provider 写入前进入 `paused/recovery_required`，持久错误只有 `ZEUS_CODEX_RPC_TIMEOUT: Codex app-server request timed out: thread/turns/list`。
- `account/read` 没有写入 submission、turn 或 conversation item，是回答完成后 Renderer 全量水合产生的附属读取错误。
- PLAN 动作状态为 `refinement_requested`。这是当前“否，并告诉 Codex 应该如何做得不同”的既有语义；本任务不把自定义反馈静默改成“立即实施”，避免改变已经确认的 PLAN 控制契约。

## 根因

### 派发门禁仍有普通优先级读取

v0.3.48 只让派发门禁的 `thread/read` 越过 app-server 过程事件投影背压。权威读取之后还会同步执行 `thread/turns/list`，但该 RPC 仍使用普通读取；stdout 被慢投影暂停时，它依旧会在 30 秒后超时。因此 submission 已在 Zeus 本地耐久落库，却尚未进入 `turn/start`。

### 控制回答与后台水合耦合

Renderer 原来在 PLAN 回答 POST 成功后立即等待完整会话水合，并把两者放在同一个 `runOperation` 中。`account/read` 等附属读取失败会把已经持久化的控制回答重新显示成失败。

### 同一提交经过多条投影路径

本地持久 userMessage、暂停 queue submission 和迟到的内存投影没有在所有路径上共享 submission 身份。消息级失败展示又会回退到全局 `state.error`，因此一个真实 submission 被画成两个气泡，无关的 `account/read` 也被错误挂到其中一个气泡下。

## 修复方案与取舍

- `thread/turns/list` 增加仅供控制面的 `priority: 'control'`；Provider 派发权威检查从 `thread/read` 到检查点分页全程沿用控制读取。普通历史分页继续服从原背压。
- PLAN 回答接口直接返回已持久化的计划动作与最新 queue snapshot。Renderer 收到回执后立即收起确认卡并投影唯一 submission；完整会话水合改为后台收敛。
- 后台水合失败不再改判 PLAN 回答失败。若回执表明仍有活动或待派发工作，只恢复实时订阅；错误留在其真实所属的附属读取出口。
- 本地 userMessage 元数据补充 `submissionId`。冷水合、队列事件和 Transcript 都按 client identity 与 submission identity 合并；持久消息保留原稳定节点，暂停状态和该 submission 自身的错误合并到同一节点。
- 消息失败只读取 item 自身的 `deliveryError/error`，不再回退全局 session error。

优点：一次 PLAN 自定义回答只显示一个气泡；Provider 写入前的权威历史对账不再被同进程背压反向阻塞；附属能力失败不会污染已接受的控制动作。

代价：控制读取会在每个 `thread/turns/list` 分页响应期间短暂恢复 stdout；完整水合失败时界面先依赖 POST 回执和实时事件收敛，附属指标可能稍后刷新。

## 验证范围

- 真实 `ConversationTranscript` QA 同时注入一条本地消息、一条暂停 queue submission、一条迟到重复投影和全局 `account/read` 错误：只允许一个用户气泡和一行 `thread/turns/list` 原始错误，页面不得出现 `account/read`。
- 核对 PLAN 回答回执在后台水合失败时仍保持已解决请求和单一 queue 投影。
- 执行目标文件格式检查、`git diff --check`、`pnpm lint`、`pnpm typecheck`、`pnpm build` 与 `pnpm package:mac`；不新增 Vitest 或单元测试。
- 只允许启动独立数据目录的 `Zeus Test.app`。不修改正式数据库，不重放正式 submission，不操作正式 `/Applications/Zeus.app`。
