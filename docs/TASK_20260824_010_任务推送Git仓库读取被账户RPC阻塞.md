# 任务推送 Git 仓库读取被账户 RPC 阻塞

## 用户现场

- 打开“推送到新会话”并选择 Worktree 后，界面长时间停在“正在扫描项目目录下的 Git 仓库…”，创建按钮持续禁用。
- 现场任务为 Zeus 项目的 `ZEUS-0338`；项目目录 `/Users/david/hypha/zeus` 已登记一个根仓库，不是空项目或未登记仓库。

## 只读诊断证据

- 正式版为 `0.3.49`，本轮未点击、关闭或修改正式应用与正式数据。
- 正式数据库确认项目扫描状态为 `completed`，仓库 `/Users/david/hypha/zeus` 已登记为相对路径 `.`。
- 对同一仓库逐项读取当前分支、HEAD、引用、worktree 和工作区状态，单项耗时为 `0.01s` 至 `0.08s`，整条 Git 读取不构成长时间等待。
- 对正式本机服务执行一次相同的只读任务推送能力请求，`30.024s` 后返回：
  `ZEUS_CODEX_RPC_TIMEOUT: Codex app-server request timed out: account/read`；`Server-Timing` 中核心处理耗时为 `30009.80ms`。

结论：界面文案把整个任务推送能力请求统称为“Git 扫描”，但服务端在返回已登记仓库之前同步等待了 Codex `account/read`。账户 RPC 超时会错误地阻断与账户无关的 Git、任务上下文和 Worktree 选择。

## 修复规则

1. 任务推送能力查询只读取已经登记的 Git 仓库、任务上下文、模型目录和本地工作区事实，不同步调用 Provider 账户 RPC。
2. Codex 账户状态继续通过独立的会话能力后台请求读取；已有缓存可用于首帧登录判断，但其失败或超时不得阻断 Git 与 Worktree 表单收敛。
3. 用户选择 Codex 且服务端在真正提交时返回 `ZEUS_CODEX_LOGIN_REQUIRED`，恢复弹窗后把这一权威结果投影为“需要登录”，进入现有登录流程；不得因省略预读账户而循环重试创建。
4. 加载文案改为“正在读取任务工作区与 Git 仓库…”，不再声称每次打开都会递归扫描项目目录。
5. Provider、Git 和任务写入仍在真正创建会话前由服务端按原安全规则复验；本次不降低 Worktree 来源分支、仓库修订值和上下文修订值门禁。

## 优缺点

优点：Git 与任务能力可以独立、快速收敛；Codex 账户通道繁忙或超时时，DeepSeek 等非 Codex 模型和 Worktree 选择不再被无关依赖锁死，界面状态也与真实工作一致。

代价：没有账户缓存时，Codex 登录状态不会在 Git 能力响应中提前确认；若用户选择 Codex，最迟会在提交前的服务端权威校验中进入登录流程。相比让所有模型等待 30 秒，这个延后只影响真正需要 Codex 登录的分支。
