# 会话同步、完成态、任务历史与审查启动修复

## 目标

本任务一次性修复并发布以下现场问题：

1. Remote Control 移动端发送的新消息不能及时出现在 Zeus。
2. 已完成轮次仍显示 `Defining runtime paths and execution contracts` 一类思考摘要。
3. `account/read` 超时会阻断继续会话或创建代码审查。
4. “已处理 X”没有位于本轮正文和交付文件卡片之后。
5. 代码审查弹窗长期停留在“正在启动”。
6. 已完成任务不能查看关联会话，恢复到待验收后又只显示一条。
7. 点击任务关联会话后历史消息为空。
8. 历史会话的环境卡片经常不显示。
9. 创建失败后仍同时显示“正在思考”，且错误文本被挤成逐词换行。
10. Provider 已经结束或会话创建已经失败时，侧栏和正文仍长期显示转圈、停止按钮与未结束过程。

## 现场结论

- `account/read` 是账号状态探测，不是发送消息本身；普通创建和恢复路径却强制使用 `refreshToken: true`，网络刷新超时会把本可继续的会话一并阻断。
- Zeus 只在恢复、发送和 Provider 事件到达时补齐远端轮次；已打开的 Remote Control 会话缺少持续的增量拉取，因此移动端消息可能停留在 Provider 侧而不进入 Zeus 投影。
- 会话正文投影会在每轮末尾重新追加最新 reasoning；没有限制为活动轮次，导致完成后仍保留内部英文摘要。
- 轮次时长以最后一条普通消息为锚点，交付物卡片另行插入，所以时长会出现在正文或交付物之前。
- 代码审查启动会同步等待账号刷新和首次 Provider 派发；任何慢调用都会锁住弹窗。
- 任务详情在非终态过滤归档会话；手工从完成态改回非终态时，服务端又会自动恢复排序靠前的任意归档会话。现场因此恢复了一个没有 Provider 线程、首次提交已取消的代码审查壳，会话为空且其他真实历史仍被隐藏。
- 历史快照模式直接关闭了环境快捷卡片，而不是只把操作置为只读。
- 创建失败卡片沿用了三列网格，但失败分支只渲染两项，错误内容落入 20px 窄列；失败态也没有抑制独立“正在思考”状态。
- 正式 v0.3.51 的代码审查线程 `01a0367e-253e-7392-8be7-21f33ebee2af` 已于 09:38:22 写入 `task_complete`，数字员工线程 `01a034ab-3587-7ca1-9c55-ca50ac4f5f8a` 已于 09:59:51 写入 `task_complete`；正式 SQLite 却仍把对应轮次保留为 `running`，侧栏分别持续显示 55 分钟和 2 小时以上。点击前者后才补齐终态，证明是 Provider 终态通知遗漏后的被动对账缺口，不是模型仍在执行。
- “侧边栏会话数量优化”创建失败发生在服务端接受会话之前，正式 SQLite 没有该任务的会话记录；Renderer 本地待处理工作面仍保留 `active_prework`、活动 turn 和 `connecting` choice，因此即使错误已经显示，侧栏、正文和停止按钮仍冒充运行中。

## 实施原则与取舍

- 普通执行只读取本地账号快照，并允许在 app-server 瞬时传输失败时回退到同一运行世代的最后成功账号快照；显式登录或用户主动刷新仍走严格刷新。优点是网络波动不再阻断会话，缺点是极短时间内可能使用稍旧的登录状态，因此真正派发失败仍必须保留可见审计。
- 对当前打开且已绑定 Provider 的会话做低频水位补齐，不依赖 Remote Control 开关；只有 Provider 出现新轮次或本地活动态与 Provider 终态不一致时才做完整对账。优点是移动端消息与遗漏终态都能回流且不会扫描全部历史，缺点是上游 Provider 从未收到的消息无法由 Zeus 凭空恢复。
- 任务历史显示所有有意义的真实会话；未绑定 Provider 且首次提交已取消或删除的壳不作为关联会话展示，但数据库审计记录保留。
- 手工修改任务状态不再猜测要恢复哪条会话；只有用户明确点击某条历史会话继续时，才恢复该精确会话。
- 代码审查在本地持久化成功后立即切入新会话，首次 Provider 派发异步进入统一队列。优点是弹窗不再等待网络，缺点是后续 Provider 失败会在新会话中展示并允许重试。
- 会话创建失败会原子地把本地 choice、活动 turn、队列和会话状态收口为失败态，同时保留原始输入用于重试；优点是不会再出现失败、转圈和停止按钮并存，代价是失败后必须显式重试，不能假定首次请求已被 Provider 接受。

## 验收分层

- 源码：逐项核对状态机、投影顺序、任务历史和同步边界。
- 工程门禁：`pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac`。
- 真实运行：仅启动独立身份 `Zeus Test.app`，使用独立用户数据目录验证会话、任务历史、错误态、环境卡片和审查启动。
- 发布：升级版本、提交并推送；核对远端主分支、标签、Workflow、Release、DMG、清单和 Homebrew。签名或公证只按公开产物和发布检查的真实结果报告。

## 实施结果

- 当前打开会话每 5 秒检查一次 Provider 最新轮次；当前项目的未归档 Codex 会话在既有 10 秒列表刷新中触发 30 秒节流水位检查，每批最多并发 4 条。只有出现新轮次，或 Provider 终态与本地活动态不一致时，才读取完整增量并持久化。这样未打开会话的侧栏假死和移动端新增轮次也会自动收敛，不会调用模型或消耗推理 Token。
- 普通会话创建和恢复优先复用当前 app-server 世代内的账号快照，并允许 `account/read` 传输瞬断时回退；用户主动刷新登录态仍严格读取 Provider。
- 完成轮次不再把最后一条内部 reasoning 摘要追加到正文；失败创建态也会抑制独立“正在思考”。
- “已处理 X”与交付文件共用最终产物锚点，顺序固定为正文、显式交付资源、交付卡片、时长。
- 代码审查在本地会话与只读约束持久化成功后立即关闭启动弹窗并切入新会话，首次 Provider 派发进入统一异步队列。
- 任务详情同时返回归档与未归档历史，剔除未绑定 Provider 且首次提交已取消或删除的空壳；状态从终态改回非终态时不再擅自恢复任意历史会话。
- 历史快照继续隐藏写操作，但不再隐藏环境入口。
- 创建失败原子收口 choice、任务运行态、活动 turn、队列和乐观消息；错误行使用剩余宽度，重试按钮独占尾列。

## 验收证据

### 正式现场只读对账

- 正式 Zeus 0.3.51、正式 SQLite 和 Provider JSONL 三方一致证明两条假死线程已经在 Provider 结束，但本地仍为 `running`；没有向正式会话发送消息、停止任务或修改数据库。
- “侧边栏会话数量优化”在正式 SQLite 中没有会话记录，证明它失败于服务端接纳之前；旧 Renderer 却仍显示 Stop 与转圈，创建失败收口修复覆盖了这一分支。
- ZEUS-0315 的正式数据中存在 3 条有消息的归档任务会话和 1 条未绑定 Provider、首次提交取消的空壳，修复后的查询精确返回 3 条真实历史。

### 定向行为探针

- Provider 最新轮次为 `completed`、本地为 `running` 时，触发一次完整对账和一次持久化；同一会话并发检查只执行一次。
- 项目批量追赶对两条会话各检查一次，重复 ID 自动去重；30 秒内再次刷新不重复访问 Provider。
- 创建失败后 choice=`error`、任务运行态=`failed`、会话=`turn_failed`、活动 turn 为空、队列=`idle`、原始乐观消息=`failed`，同时保留显式重试。

### 独立 GUI

- 使用 `dev.hypha.zeus.test` 的 `Zeus Test.app` 和正式数据库只读副本验收；正式应用与正式数据库未被修改。
- ZEUS-0315 任务详情显示 3 条关联会话，打开第一条后可见完整历史消息，不再出现空白会话。
- 完成会话只显示最终正文，处理过程默认收起；“已处理 1分44秒”位于该轮正文最下方。
- 历史会话顶部重新出现“环境”入口；只读验收模式按设计阻止进一步连接 Runtime、Provider、Git 或 Keychain。
- 浏览器渲染夹具确认：创建失败只显示单行自适应错误与“重试”，不再同时显示“正在思考”；完成态内部英文 reasoning 不再回显，时长位于正文和交付资源之后。
