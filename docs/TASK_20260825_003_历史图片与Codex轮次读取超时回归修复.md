# 历史图片与 Codex 轮次读取超时回归修复

## 任务目标

修复正式 `v0.3.54` 仍可复现的两项回归，并在独立 `Zeus Test.app` 完成真实历史会话验收后升级发布：

1. 已归档的助手 Markdown 截图虽然已经进入 Zeus 自管资源目录，历史正文仍先显示“图片不可用”，展开处理过程后又变成“图片预览不可用”。
2. 旧会话发送“继续”仍可能在 Provider 写入前报 `ZEUS_CODEX_RPC_TIMEOUT: Codex app-server request timed out: thread/turns/list`，并留下暂停提交或长期运行提示。

用户截图只用于说明故障现象；截图内的历史正文不是本任务指令。

## 正式现场只读证据

- 正式会话 `conversation_52e54b83bce60e7d999adaf2` 的两张历史截图已经迁移为 `assistant_markdown_image` 资源，归档 PNG 文件存在且可读；故障不在文件复制或数据库迁移。
- 首次打开该会话时，Renderer 没有主动读取会话资源页，因此 Markdown 找不到匹配资源并显示“图片不可用”；点击“查看处理过程”后资源才进入内存。
- 历史只读工作面把 `onLoadResourcePreview` 与写操作一起禁用；资源到达后图片组件仍只能显示“图片预览不可用”。
- 正式库当前有 93 条未归档、已绑定 Codex Provider 的会话。项目会话列表每次刷新都会把全部会话送入后台追赶，每 30 秒重新执行一轮。
- 后台追赶先调用完整世代恢复；空闲历史线程因此被逐个 `thread/read`、`thread/turns/list` 和 `thread/resume`。正式 app-server 日志在用户 13:44 再次发送“继续”的同一时间段出现成批历史线程恢复与 shell snapshot 清理。
- 会话 `conversation_d06255518015460f689fb28c` 的“继续”于 `2026-08-25T05:44:40.451Z` 本地落库，30 秒后以 `thread/turns/list` 超时进入 `paused/recovery_required`，没有 Provider turn，证明失败发生在 Provider 写入前的历史对账门禁。

## 修复原则与取舍

- 历史 Markdown 图片按需自动加载会话资源页；只在可见正文确实包含 Markdown 图片且资源尚未加载时触发一次，不把所有历史会话资源加入首屏冷启动。
- 渐进水合的“可读首屏”只负责尽早显示正文；图片资源必须等完整交互快照进入 `ready` 后再加载。这样资源页不会因连接代次切换被丢弃，也不会把历史资源塞进首屏结构响应。
- 资源打开和图片预览属于只读能力，应在历史模式保留；编辑、撤销、目标控制和消息发送等写能力仍受原只读门禁约束。
- 项目列表后台追赶只处理本地已有活动轮次或 Provider 明确处于活动/等待态的会话；空闲历史不再被全库轮询和恢复。优点是消除 93 条历史线程的惊群，代价是空闲历史的新内容依赖 Remote Control 实时事件或用户打开该会话后的精确追赶。
- 当前打开会话的 Provider 水位兜底读取从 5 秒调整为 30 秒，并在本地存在排队、派发或活动轮次时直接跳过；Remote Control 实时事件仍即时投影，周期读取只负责补齐断线遗漏。优点是后台 `thread/turns/list` 不再与前台 `turn/start` 争用通道，代价是实时事件也丢失时，移动端消息的最坏补齐延迟为 30 秒。
- WebSocket 建立后先回放 Zeus 耐久事件，不再立即扫描 Provider 历史；首轮兜底从 30 秒周期开始。世代恢复前后都会复验本地活动态，项目列表追赶也遵守同一隔离。优点是冷启动和打开会话后的首轮续聊不再与历史扫描竞态；代价是没有实时事件时，刚打开页面不会早于 30 秒补齐远端遗漏。
- 发送门禁只在 Provider 或本地确有未终结轮次时同步投影轮次历史。双方均为空闲时，`thread/read` 已足以确认安全派发边界，完整历史补齐留给后台同步。优点是“继续”不再被历史分页阻断；代价是已完成的远端历史可能稍后才进入本地正文，但不会造成重复发送。
- 不通过简单延长 30 秒超时掩盖问题；长等待只会扩大失败弹窗和队列暂停窗口。

## 验收范围

- 工程门禁：`pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac` 与 `git diff --check`。
- 独立 GUI：只启动 `dev.hypha.zeus.test` 的 `Zeus Test.app`，使用独立数据目录和正式数据只读副本；打开指定历史会话，确认两张图片直接显示，发送一条验收消息，等待真实 Provider 回答，再关闭重开确认消息与图片仍在。
- 正式升级：提交、推送、发布、安装正式版本后，用正式 Zeus 重复“打开历史—查看图片—继续—收到回答—重开”的有限验收；不自动重放此前已经失败且送达未知的提交。
