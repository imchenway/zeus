# TASK_20260827_001 内置浏览器导航失败不再触发全局错误弹窗

## 文档状态

- 任务类型：缺陷；
- 当前阶段：实现与独立 `Zeus Test.app` 真实界面验收完成；用户已授权升级发布，目标版本 `v0.3.65`；
- Git 边界：未执行 `commit`、`push`、`merge` 或 `revert`。

## 用户反馈

内置浏览器打开无法连接的页面时，页面区域已由浏览器自身显示失败状态，Zeus 仍额外弹出 `ERR_CONNECTION_REFUSED (-102)` 全局错误对话框并用遮罩模糊整个应用。

用户明确要求：修复这个错误弹窗与遮罩的重复展示；页面无法打开由浏览器内部自然提示。

## 根因

1. `BrowserHost.openTab` 先建立浏览器标签，再异步调用 `WebContents.loadURL` 。
2. 连接拒绝时，Chromium 会在页面内显示网络错误页，同时 `loadURL` Promise 会拒绝。
3. 异步打开和恢复历史标签的拒绝被 `emitError` 提升为 `ZeusBrowserEvent.error`；`BrowserWorkspace` 再将它交给全应用错误对话框。
4. 用户在地址栏手动导航时，`runManualCommand` 直接等待 `loadURL`，拒绝还会通过 IPC 回到 Renderer 并触发同一全局弹窗。

## 实施决策

将“用户面向的页面导航”与“Zeus 浏览器功能失败”分开：

- 用户打开新标签、恢复已有标签和在地址栏导航时，消费 `loadURL` 对页面级失败的 Promise 拒绝；
- 保留 Chromium 原生失败页、地址栏和标签状态；
- URL 协议、嵌入账号密码等 Zeus 输入安全校验仍在 `loadURL` 前执行，仍会作为应用级错误反馈；
- 浏览器桥接不可用、标签操作失败、批注截图失败等 Zeus 功能错误继续使用全局错误对话框。

### 优缺点

- 优点：错误归属清晰，页面网络失败不再阻断 Zeus 会话交互，且不影响原生浏览器诊断信息。
- 缺点：网络错误不再额外出现于 Zeus 错误队列；需通过浏览器页面与地址栏判断导航失败。这是用户已确认的产品取舍。

## 验证口径

1. 打开一个未监听端口，确认右侧浏览器显示 Chromium 连接失败页。
2. 确认 DOM 中不存在 `application-error-dialog`，主界面不存在对应模态遮罩。
3. 修改地址栏后再次导航到未监听端口，确认仍不弹窗。
4. 运行 `pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac` 与 `git diff --check`。
5. 真实界面验收只使用 `dev.hypha.zeus.test` 身份的 `Zeus Test.app` 和独立用户数据目录。
