# TASK_20260827_002 会话执行期摘要收口与工具图标样式修复

## 文档状态

- 任务类型：缺陷；
- 当前阶段：已随 `v0.3.65` 完成公开发布，用户自行升级；

## 用户反馈

1. 已完成轮次的“查看处理过程”中仍保留多条英文 reasoning 摘要，例如 `Planning targeted code extraction` 和 `Analyzing branch divergence and file status`；这些执行期状态应在轮次完成后消失。
2. 正在运行的命令/工具图标出现了不需要的蓝色圆底与光晕。
3. 进行中 reasoning 摘要 `Preparing to access design prototype memory` 显示在命令上方；这类当前状态在执行过程中应始终位于所有命令和工具活动之后，即当前会话最底部。

## 已有产品契约

- `ZEUS-0321`：Reasoning 摘要只表达活动轮次当前状态；最终回答开始、轮次完成或切换到历史后不再显示。原始事件仍持久化用于审计与恢复。
- `ZEUS-0338`：当前 reasoning 摘要使用轮次级稳定身份，并随最新进度保持在过程区最底部。

## 回退根因

1. `projectTranscriptRows` 当前只在“活动轮次的最后阶段”去掉部分旧 reasoning，并明确把已结束阶段和历史轮次的全部 reasoning 重新保留。这与 `ZEUS-0321` 契约相反。
2. Reasoning 仍按 Provider 原始时间线就地投影；后到的命令自然显示在它下方，没有实现“当前状态固定在底部”。
3. 活动图标的后续最终覆盖只停止了旋转和 transform，先前活动态规则添加的蓝色 `background` 和 `box-shadow` 仍然生效。

## 实施决策

1. 投影时隐藏所有历史和已结束轮次的 reasoning 条目。
2. 活动轮次只选取最新一条 reasoning，不在原始时间线位置绘制；完成其他条目投影后，把它插到该轮次的最后一行。
3. Reasoning 可见 DOM key 改回轮次级身份，Provider 换 item 时原位更新文字，不重建成新行。
4. 命令与工具活动图标的最终覆盖强制使用透明背景且移除光晕；不改变图标本身、文字、状态和可点击区域。
5. 终态表优先于 Provider 条目的临时 `in_progress` 状态；完成、中断或失败轮次即使残留未收口 reasoning，也不能重新被判成活动轮次。

### 优缺点

- 优点：进行中只有一条可理解的当前状态，且位置稳定；轮次完成后过程区只保留可追溯的操作记录；命令图标不再出现多余蓝底。
- 缺点：主会话 UI 不再提供逐条 reasoning 回看；需调试此类历史时必须依赖底层持久化事件。这是已有产品契约，不删除数据。

## 验证口径

1. 进行中轮次构造多条 reasoning 和命令/工具活动，DOM 只存在最新 reasoning，且它在该轮次所有命令/工具活动之后。
2. 最终回答开始或轮次进入终态后，DOM 中 reasoning 数量为零；展开处理过程后仍为零。
3. 活动命令/工具图标的计算样式为透明背景且无 `box-shadow`。
4. 运行目标文件 Prettier、`pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac` 与 `git diff --check`。
5. 真实界面验收只使用 `dev.hypha.zeus.test` 身份的 `Zeus Test.app` 和独立用户数据目录。
