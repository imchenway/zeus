# TASK_20260828_001 推送任务与归档会话错误修复

## 当前阶段

- 状态：源码修复完成，独立测试包回归完成
- 日期：2026-08-28
- 范围：任务推送、会话同步事件、未绑定会话归档、归档生命周期响应
- 边界：不修改正式数据库，不启动或替换正式 `Zeus.app`，不执行提交或发布。

## 用户现象

1. 推送任务弹出 `ZEUS_CONVERSATION_SYNC_EVENT_IDENTITY_CONFLICT`。
2. 对推送失败后留下的会话点击归档，弹出 `ZEUS_CONVERSATION_COMMAND_OUTCOME_UNKNOWN`。
3. 其他归档动作可能弹出 `ZEUS_CONVERSATION_NOT_FOUND`。
4. 其他会话回答交互问题时弹出 `ZEUS_CONVERSATION_DISPATCH_COMMAND_OUTCOME_UNKNOWN`，底层仍是同一个同步事件身份冲突。

## 现场证据

- 失败的 `conversation.task.create` 命令在外部写入前被同步事件冲突阻断，回执中的原始错误为
  `ZEUS_CONVERSATION_SYNC_EVENT_IDENTITY_CONFLICT`。
- 同一进程随后在多个会话、多个 Provider 事件方法上持续记录相同同步冲突，说明单个增量失败被进程级失败状态扩散。
- 本次推送已留下一个 `provider_state=unbound`、`stage=queued` 的本地会话和一条未绑定 Provider 回合的排队提交。
- 两次归档命令都被记录为 `outcome_unknown_after_write`，但底层原始错误实际是本地前置条件
  `ZEUS_NATIVE_CONVERSATION_IN_PROGRESS`，没有证据证明 Provider 归档写入已经发生。
- 截图中的 `ZEUS_CONVERSATION_NOT_FOUND` 没有带出会话 ID；当前推送失败留下的目标会话仍真实存在，因此不能把该 404
  归因为数据已被删除。现有证据只支持“客户端选择与稳定预留状态失配”，精确触发路由仍需在测试包复现。
- 新增现场中的两条 `conversation.server_request.respond` 命令虽然被记成 `outcome_unknown_after_write`，但对应请求均已持久化为
  `resolved`，对应 Provider 回合也仍为 `running`。这证明交互回答已经被业务链接受，随后 UI 增量发布失败反向污染了命令结果；两条回答都不得重放。

## 根因

### 1. 变更集事件身份只使用毫秒时间

变更集增量的稳定 `eventId` 只包含会话、变更集和 `updatedAt`。Provider 可以在同一毫秒内产生内容不同的 pre/post
投影，导致不同内容获得同一个事件身份，触发存储身份冲突。

### 2. 单个增量失败污染整个进程

增量刷新失败被保存到全局失败变量。之后任何会话发布任何事件都会直接抛出旧错误，因此一个会话的可重建过程投影会阻断其他任务推送。

### 3. 未外发队列没有可归档路径

尚未绑定 Provider、也没有 Provider 回合的本地排队消息仍被通用“会话进行中”校验拦截。命令框架又在进入协调器前就标记“外部写入已开始”，最终把明确的本地拒绝误报为外部结果未知。

### 4. 业务接受结果被可重建投影错误覆盖

Provider
写入或本地业务状态已经成功后，同步增量发布仍位于命令调用栈内。进程级旧错误从发布函数抛出，会让命令框架把已经接受的回答记成“外部结果未知”。任务推送的准备阶段也会先留下稳定会话预留，再因同一个发布错误返回失败，客户端随后可能持有与真实预留状态不同步的会话选择；这是当前对
`ZEUS_CONVERSATION_NOT_FOUND` 的最强推断，但还不是已复现根因。

### 5. 未绑定会话归档后的恢复投影不完整

真实测试包发现，首次提交在归档时被安全取消后，归档列表仍沿用“已取消提交等于空壳”的筛选规则，导致归档条目不可见；恢复时又错误要求不存在的任务
worktree。即使纯本地恢复成功，旧筛选也会继续隐藏仍保留用户消息的会话。

## 修复设计与取舍

### 变更集事件身份

- 做法：稳定事件身份增加规范化变更集投影的 SHA-256 指纹。
- 优点：相同内容重放仍幂等；同一毫秒内内容不同的投影不再碰撞。
- 缺点：事件身份计算增加一次小型投影哈希，但投影本身已受事件大小预算约束，成本可控。

### 增量失败隔离

- 做法：移除永久进程级失败闩锁；批量遇到身份冲突后逐条重放，只丢弃可由 Snapshot V2 重建的冲突过程投影，保留其他会话事件。
- 优点：单个会话不会继续阻断任务推送；非冲突存储错误仍会抛出并重排，不会被静默吞掉。
- 缺点：发生旧版身份冲突时会少一条过程增量，但客户端可从权威快照恢复完整状态。

### 未绑定会话归档

- 做法：仅当会话未绑定 Provider、没有未完成回合或待处理请求，且所有非终态提交都从未获得 Provider 回合时，取消本地队列并归档；侧边栏对
  `providerState=unbound` 且没有 Provider 线程身份的本地队列开放归档按钮。未绑定归档会话恢复时只恢复本地归档标记，不要求
  Provider 或 worktree；历史投影以真实消息判断是否为空壳。
- 优点：推送失败留下的本地会话可以安全清理并可见地恢复，不会产生未知的 Provider 结果；恢复后仍回到原任务。
- 缺点：恢复该会话后不会自动重发旧消息；这是避免用户未确认重放的必要约束。历史投影需要额外读取一次目标会话消息，但范围只限未绑定原生会话。

### 命令结果与生命周期

- 做法：同步身份冲突只在可重建投影层隔离，不再作为永久进程错误进入后续命令调用栈；真实进行中拒绝明确归类为
  `explicitly_rejected`。
- 优点：已经接受的交互回答不会被 UI 投影失败反报为未知；明确拒绝不再伪装为外部结果未知；任务推送的稳定预留可以按原幂等身份恢复。
- 缺点：旧冲突发生当下可能缺少一条过程增量，需要依靠权威快照补齐 UI；不能用自动重放来修复历史未知回执。
