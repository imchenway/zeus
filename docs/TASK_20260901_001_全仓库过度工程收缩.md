# 全仓库过度工程收缩

## 目标

按 2026-09-01 的 Ponytail 全仓库审计建议完成收缩：删除无引用的一次性脚本和依赖，去掉重复 UI 运行时，合并单消费者包，收敛命令封装、查询
Store、图算法、发布脚本和副作用治理校验。

## 约束

- 不新增或恢复单元测试、组件测试及相关依赖。
- 不执行 `git commit`、`push`、`merge`、`revert` 或发布。
- 保留现有对外行为和发布门禁语义；只删除无调用路径或已有主实现可替代的代码。
- 验证使用 `pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac`，运行包必须是 `Zeus Test.app`。

## 实施记录

- [完成] 删除 10 个无调用方的一次性探针/验证脚本，并删除手工维护的内部副作用注册表。
- [完成] 删除 React Flow、Sigma 诊断运行时及其样式，代码图谱只保留产品实际使用的 SVG 画布；源码预览统一使用
  `ConversationMarkdown`。
- [完成] 删除 9 个不再需要的直接依赖：`@xyflow/react`、`graphology`、`sigma`、`react-markdown`、`remark-gfm`、
  `@vitejs/plugin-react-swc`、`simple-git`、`zustand`、`nanoid`。
- [完成] 将 `project-core`、`release-core`、`task-core`、`telegram-adapter` 四个单消费者包收回 `local-server`，工作区包数量由
  16 个降为 12 个。
- [完成] 以 Node `crypto.randomBytes` 替换服务端 `nanoid`，Renderer 随机身份统一走 Web Crypto。
- [完成] 12 个 Renderer 命令客户端统一复用 `commandRequest.ts`；7 个 Query Store 统一复用 `externalStore.ts`。
- [完成] 图谱 CLI 直接复用 `buildProjectGraph`，由 1084 行降为 163 行，不再维护第二套图算法。
- [完成] 发布版本、布尔参数、Release Notes、SHA-256 校验统一到 `release-script-utils.mjs`。
- [完成] Command、Electron IPC、内部副作用审计改为 TypeScript AST 自动发现；三个审计脚本由 4074 行降为 354 行，并保留既有命令行门禁入口。
- [完成] 修正事件耐久门禁的既有口径冲突：允许已登记的 `plugin.*` 事件，并精确登记三个 Provider stop 恢复事实。

## 验证证据

- `pnpm verify:zarch-gates`：通过。
- `pnpm audit:conversation-event-durability`：通过，47 个源码字面量事件均有精确口径。
- `pnpm lint`：通过。
- `pnpm typecheck`：通过；架构治理确认 126 张 Core 表、11 张可重建辅助表及包依赖环均符合策略。
- `pnpm build`：通过；仅保留第三方 `markstream-react` 的 Rolldown 注释与大 chunk 警告。
- `pnpm package:mac`：通过，生成并校验 `dist/test/mac-arm64/Zeus Test.app`。
- `CFBundleIdentifier`：`dev.hypha.zeus.test`；`codesign --verify --deep --strict`：通过。
- `git diff --check`：通过。
- 未执行 GUI/真实外部联调、正式发布、提交、推送或远端写入。

## 收缩结果

- 计入新增共享实现和四个包的同文件搬迁后，约净删除 9770 行。
- 直接依赖减少 9 个，工作区包减少 4 个，废弃脚本/手工注册表减少 11 个。
- 命令封装、查询发布机制、图构建和发布校验均只保留一个事实源。

## 权衡

- 优点：减少依赖、构建面和重复实现，后续修改只有一个事实源。
- 缺点：副作用门禁从逐项手写清单改为 AST 约定扫描，维护成本大幅下降，但对动态计算出来的调用名只能依赖失败安全策略和边界级门禁；这次没有做
  GUI 或真实外部联调。
