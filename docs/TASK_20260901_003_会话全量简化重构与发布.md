# 会话全量简化重构与发布

## 目标

在当前 `main` 会话收口基线上，一次候选版本完成会话专项 Ponytail 审查中的全部十项优化，并通过独立身份的真实
`Zeus Test.app`、真实 Codex/Pi、直接推送、数字员工、模型切换和恢复验收；完成后提交、推送、升级版本并正式发布 Zeus。

## 本轮范围

1. 删除 `session.css` 中经过证明的重复规则，同时保持层叠结果不变。
2. 将 Desktop QA 场景收敛成数据驱动场景与少量真实主链场景，不恢复 Vitest/组件测试体系。
3. 提取 Command Application 中完全相同的校验、身份和外部派发生命周期，保留各领域策略和事务边界。
4. 迁移并下线 `digital_employee_executions` 旧运行事实；历史证据只读保留或导出，活动执行先对账和排空。
5. 删除无生产调用的 Cold Evidence 子系统，不破坏既有数据。
6. 将版本化会话 Wire DTO 收敛到 `@zeus/shared`，Storage 记录、Wire DTO 与 Renderer 状态继续分层。
7. 删除无效的 Snapshot V1 内存兼容追踪，保留 410 tombstone 与可观测日志。
8. 删除 Side Chat 产品分支及其 API/状态，不影响主会话引用、选区和正常续聊。
9. 用 CSS/Web Animations 覆盖三个会话组件的动画需求并删除 `framer-motion` 直接依赖。
10. 删除 `codexNativeRuiValidation.ts` 单行转发层，调用方直接引用事实源。

## 不得破坏的会话不变式

- 产品会话身份与 Provider 原生会话身份分离；每轮保存实际 Provider、模型和运行证据。
- 同 Provider 原生切换、原生恢复重启、跨 Provider 分段交接和不支持是四种明确能力。
- 本地入队、Provider 写出、明确接纳、明确拒绝和写出后结果未知不能合并。
- Renderer 不拥有服务端运行真相；旧快照经版本化边界显式解码。
- 数字员工执行复用普通任务工作项和普通会话，等待人工、未知结果、验收和交付物不得丢失。
- Provider 明确拒绝必须在直接推送、数字员工、Telegram、Automation 和 UI 中得到一致终态和真实详情。
