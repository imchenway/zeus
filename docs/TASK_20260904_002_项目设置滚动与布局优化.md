# 项目设置滚动与布局优化

## 当前阶段

界面、样式、静态门禁、独立测试包和真实界面验收均已完成。

## 原始问题

- 项目设置内容超过窗口高度后无法滚动，底部配置不可达。
- “项目可用模型”和“数字员工”两块长内容纵向拼接，进入页面时看不到原本应优先展示的数字员工。
- 超宽窗口把说明列和模型控件拉到页面两端，扫描距离过长；默认模型与保存按钮也会被长列表推到首屏之外。

## 根因

`.project-detail-pane` 同时被代码工作台和项目设置复用，但后续样式把它统一设为 `overflow: hidden`
。代码工作台确实需要由内层区域管理滚动，项目设置却因此失去了唯一的页面滚动容器。

## 实现决策与取舍

### 两个同级设置入口

- 决策：项目设置增加“数字员工”和“可用模型”分页，默认展示数字员工；两个面板保持挂载，切换时不丢失尚未保存的界面状态。
- 优点：两块长内容不再互相挤压，进入页面仍延续数字员工优先的既有产品决策。
- 缺点：管理项目模型时需要多一次分页切换。

### 单一页面滚动

- 决策：只把 `overflow: hidden` 保留给代码工作台，项目设置恢复纵向滚动；不再给模型列表增加第二层滚动。
- 优点：滚轮、触控板和键盘只面对一个滚动容器，不会形成滚动陷阱。
- 缺点：模型很多时页面仍然较长，因此把保存区固定在窗口底部。

### 有限宽度与常驻操作

- 决策：项目设置内容居中并限制为 `1120px`；模型页改为单列，提供供应商、模型名称和模型 ID 搜索，底部常驻默认模型与保存按钮。
- 优点：超宽屏不再拉散内容，模型数量增加时仍能随时保存。
- 缺点：宽屏两侧会保留留白，但阅读和操作距离更稳定。

## 实现范围

- `WorkspaceView.tsx`：增加项目设置分页、默认数字员工入口和面板状态保留。
- `ProjectModelsSettings.tsx`：增加搜索、数量反馈、单列结构和常驻保存区。
- `styles.css`：修正滚动所有权，增加有限宽度、分页、响应式和固定操作栏样式。
- `digitalEmployees.css`：移除项目设置内重复内边距，使两个分页共享同一内容基线。

### 真实界面验收

验收使用独立项目“布局验收”和“切换验收”，并建立仅供本地界面检查的供应商与 26 个模型。没有请求真实供应商网络，也没有改动日常
Zeus 数据。

- `1981×1265` 宽屏：内容保持在 1120px 内居中，标题、分页、模型列表与操作区没有被拉散。
- `1240×820` 常规窗口：进入项目设置默认展示“数字员工”；切换到“可用模型”后，长列表可连续滚动，底部默认模型、保存状态和保存按钮始终可见。
- `760×820` 窄窗口：标题与分页、搜索统计、默认模型和保存按钮均退回单列，没有水平溢出。
- 分页使用左右方向键移动焦点，并可用空格切换；分页切换后，未保存的搜索内容和复选状态仍然保留。
- 搜索供应商名称可命中 26 个模型，搜索模型 ID `alpha-model-24` 可精确命中 1 个；同一搜索索引还包含模型显示名称。
- 切换项目后搜索框清空，项目原有的已选模型不受搜索状态影响。
- 使用键盘依次访问搜索框、复选框、默认模型和保存按钮，通过空格选择 `alpha-model-24`；保存后界面显示“项目可用模型已保存。”，重启独立应用仍能读回该模型及默认模型。
- 首轮窄窗口键盘检查发现靠近底部的复选框焦点会被固定操作栏遮挡；已为滚动容器和模型选项增加焦点滚动留白。重新构建、打包并复测后，焦点会完整停在操作栏上方。
- 三种窗口尺寸及焦点修复结果均在真实应用窗口中完成截图核对。
