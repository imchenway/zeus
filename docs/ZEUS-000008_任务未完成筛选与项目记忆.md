# ZEUS-000008 任务未完成筛选与项目记忆

## 当前阶段

需求口径、领域词汇、业务代码和设计契约已经落地；静态检查、生产构建、正式打包、持久化、真实应用验收与 `0.1.3` 正式发布均已完成。

## 用户目标

- 在任务页快捷状态筛选中，把“未完成”放在“全部”右侧。
- 新项目或没有历史偏好的项目默认选择“未完成”。
- 用户显式切换筛选按钮后，按项目持久化最后一次选择；退出并重新启动 Zeus 后仍恢复。
- “未完成”展示任务管理状态不是 `completed` 且不是 `cancelled` 的全部任务。
- 点击“清除筛选”或“查看全部状态”会选择“全部”，并把“全部”记为该项目最后一次选择。
- 创建任务、从图谱创建任务或打开新对话等自动流程不得覆盖项目记忆；只有用户显式操作筛选控件才写入偏好。

## 领域口径

“未完成”是任务管理状态之上的派生筛选，不是新的任务状态，也不读取 Coding Agent 运行状态。其唯一判定为：

```text
managementStatus !== "completed" && managementStatus !== "cancelled"
```

因此 `todo`、`in_development`、`in_testing`、`awaiting_acceptance` 和 `blocked` 均属于“未完成”；`completed` 与 `cancelled` 不属于“未完成”。

## 真实源码依据

### 实施前筛选行为

- `apps/desktop/src/renderer/App.tsx` 中 `taskStatusFilterValues` 当前由“全部”加全部任务管理状态组成，但 `taskStatusFilter` 的初值是空字符串，即“全部”。
- `apps/desktop/src/renderer/task/TaskWorkspace.tsx` 当前把候选值截取为前四项，因此快捷按钮实际为“全部、待开始、开发中、测试中”。
- `apps/desktop/src/renderer/task/taskWorkspaceModel.ts` 的 `filterVisibleTasks` 当前只支持“全部”或单个 `managementStatus` 精确匹配，没有组合筛选语义。
- `apps/desktop/src/renderer/styles.css` 已提供分段按钮的 `aria-pressed`、hover、focus-visible、选中态和 `760px` 窄窗口布局；新增第五个按钮需要真实检查可用宽度与文字压缩。

### 实施前项目偏好链路

- `apps/desktop/src/renderer/apiClient.ts` 的 `AppShellSettings` 已承载项目置顶、项目折叠和任务表布局等本机偏好，但没有任务状态筛选偏好。
- `apps/desktop/src/renderer/App.tsx` 已有 `taskTableColumnsByProject` 的项目级解析、保存载荷、响应合并和默认值处理，可作为项目筛选记忆的结构参考。
- `packages/local-server/src/index.ts` 通过 `app.shell.settings` JSON 保存 App Shell 设置，并负责设置读取、更新、审计与设置导入导出；筛选偏好必须贯通这些入口，不能只写 Renderer 内存或浏览器临时状态。
- 设置导出当前直接包含 App Shell 设置；设置导入分别经过 Renderer 安全转换和 Local Server 归一化。新增偏好必须在两端拒绝未知筛选值和非法项目标识。

### 实施前自动重置

- `apps/desktop/src/renderer/App.tsx` 在创建普通任务、从图谱创建任务和准备新对话时会调用 `setTaskStatusFilter("")`。
- 已确认这些自动流程不能覆盖项目记忆。创建成功仍可直接打开任务详情；如果新任务不符合当前精确筛选，允许任务行暂时不出现在当前结果中。

## 方案与取舍

### 方案

1. 定义任务筛选值类型，区分“全部”、派生值“未完成”和既有单个任务管理状态；不扩展 `TaskManagementStatus`。
2. 快捷分段按钮使用明确顺序“全部、未完成、待开始、开发中、测试中”，不再依赖对完整管理状态数组做位置截取。
3. 在 `filterVisibleTasks` 中增加“未完成”分支；搜索词和标签筛选继续与状态筛选取交集。
4. 在 App Shell 设置中新增按项目映射的筛选偏好。项目没有合法记录时返回“未完成”；合法的空字符串表示用户明确选择“全部”，不能与缺失值混淆。
5. 用户点击快捷按钮、清除筛选或查看全部状态时，先乐观更新当前界面，再通过现有 App Shell 设置接口落库；响应合并必须保护较新的项目筛选选择，避免迟到响应回滚界面。
6. 自动创建和导航流程不调用持久化筛选处理器，也不改写已保存映射。
7. 组合筛选继续在 Renderer 对项目完整任务集执行。现有任务列表 API 只支持单个 `managementStatus`，本任务不为“未完成”新增第二套服务端任务查询事实源；需要重试加载时，“未完成”先加载项目任务，再在 Renderer 排除两个终态。
8. 同步更新中英文文案、App Shell API 类型、Local Server 归一化与审计、设置导入导出安全转换、默认设置和响应合并。

### 优点

- 不改变任务状态数据库、状态迁移或任务管理语义，影响范围集中在视图筛选与本机偏好。
- 项目切换和应用重启都能恢复用户选择，且缺失旧设置时自然迁移为“未完成”。
- 明确区分缺失偏好与用户选择“全部”，不会在重启后错误恢复默认值。
- 复用现有 App Shell 本机设置和数据可携带链路，不额外建立 localStorage 或新的配置文件事实源。

### 缺点

- App Shell 设置契约、审计及导入导出都需要同步扩展，修改面大于只保存在 React 状态中的轻量方案。
- “未完成”是组合筛选，不能直接复用当前单状态 API 参数；项目任务量很大时仍由 Renderer 做一次线性过滤。
- 保留用户精确筛选时，新建任务可能只打开详情而不出现在当前表格结果中；这是为避免自动覆盖用户记忆而接受的交互代价。

- 无历史偏好的项目首次进入任务页时，“未完成”处于选中态。
