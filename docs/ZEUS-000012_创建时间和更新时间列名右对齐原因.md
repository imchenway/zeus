# ZEUS-000012 创建时间和更新时间列名右对齐原因

## 用户目标

确认任务表“创建时间”和“更新时间”列名为何靠右，并将两个短表头真正恢复为列内居中；19 位时间值继续右对齐。

## 真实原因

- `TaskWorkspace.tsx` 的列对齐表把 `createdAt` 与 `updatedAt` 标记为 `end`，表头和数据行都会得到 `task-table-align-end`。
- `styles.css` 已有时间列表头居中规则，但交互表头后来改为 `display: flex`，`justify-items: center` 对 flex 容器不生效。
- 排序按钮同时命中右对齐列规则，实际使用 `justify-content: flex-end`、`text-align: end` 和左侧 `32px` 操作区，因此列名仍显示在右侧。
- 这不是浏览器或表格组件的默认行为，而是“时间值右对齐”与后续可排序表头样式叠加后造成的回归。

## 已确认口径

- 普通文本列标题和值继续左对齐。
- 创建时间、更新时间的短标题在各自列内居中。
- 时间值继续右对齐并保留等宽数字，方便纵向扫描。
- 排序箭头出现或隐藏时不能推动时间列标题。

## 方案与取舍

### 采用方案：时间列表头使用对称网格

排序按钮使用“左侧弹性槽 / 居中标题 / 右侧弹性槽”三列网格；标题固定在中心列，排序箭头放在左侧槽的末端。

- 优点：默认、悬停和排序状态下，标题都保持真实居中；时间值的右侧数字扫描基线不变。
- 缺点：时间列表头拥有一条专用布局规则，后续调整排序图标或表头操作区时必须同时维护该规则。

### 未采用方案：仅覆盖为 `justify-content: center`

- 优点：改动更少。
- 缺点：排序箭头出现后，“标题 + 箭头”整体居中，标题文字本身会偏移，不满足稳定锚点要求。

### 未采用方案：标题和值全部左对齐

- 优点：标题和值共享同一左边缘，规则简单。
- 缺点：19 位时间值失去右侧扫描基线，连续多行时间的比较效率下降。

## 修改点

- `apps/desktop/src/renderer/styles.css`：拆开一般右对齐列与两个时间列表头的排序按钮规则；时间列表头改为对称网格，排序指示不再推动标题。
- `CONTEXT.md`：把“任务表列内容锚点”更新为标题与数据值各自保持稳定参照。
- `DESIGN.md`：明确短时间列表头居中、时间值右对齐及排序指示的独立布局槽。
