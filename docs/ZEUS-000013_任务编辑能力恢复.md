# ZEUS-000013 任务编辑能力恢复

## 当前阶段

原因分析、需求澄清和产品源码修改已完成。静态检查、构建以及隔离 API／SQLite 验证均已通过；真实浏览器交互验收因当前 Browser runtime 没有任何可用浏览器而未执行，不能据此宣称界面验收通过。

## 任务目标

恢复任务详情中的任务内容编辑能力，同时保持任务、会话和执行轮次的领域边界：用户可以直接修改标题、说明、优先级、标签和附件关联，但修改只作用于任务本身与未来新建会话，不追改已有会话或正在执行的上下文。

## 真实现象与结论

当前“任务不能编辑”不是权限、任务管理状态或 Runtime 状态造成的禁用，而是 Renderer 在任务详情重构后只保留了任务管理状态写入入口：

- `TaskDetailPaneContent.tsx` 使用 `<strong>` 展示标题和优先级、使用 `<p>` 展示任务说明，附件组件显式传入 `mode="readonly"`。
- 任务详情只接收 `onManagementStatusChange`，没有标题、说明、优先级、标签或附件更新回调。
- `App.tsx` 仍声明 `onUpdateTask` 和 `onUpdateTaskTags`，`main.tsx` 也仍把它们接到本机 API，但当前渲染路径不调用这两个能力。
- `App.tsx` 仍维护只有 setter 的 `setTaskEditForm` 并在加载、创建和切换任务时写入；没有任何 UI 读取该状态，属于旧编辑路径残留。
- 本机 API 仍有 `PATCH /api/tasks/:taskId`，存储层仍有 `tasks.update(...)`；因此底层标题和说明写入能力没有被删除，只是前端调用链断开。
- 现有更新契约不包含优先级，也没有 `updatedAt` 并发前置条件；标签使用独立接口，附件只能通过整个 `sourceContext` 间接替换。

## 已确认需求

### 任务与会话边界

- 编辑只更新任务本身。
- 此后“推送到新会话”读取最新任务内容。
- 已有会话历史和正在执行的上下文保持不变；需要补充已有会话时由用户在会话中单独发送消息。
- 已完成或已取消的任务仍可编辑任务内容，编辑不自动改变管理状态。

### 字段交互

- 不增加全局“编辑”和“保存”按钮。
- 标题、说明和标签点击后进入编辑态，失焦自动保存。
- 标题按 Enter 立即保存，Escape 放弃；空白标题拒绝保存并保留编辑态。
- 说明普通 Enter 换行，Escape 放弃；说明允许清空。
- 优先级和任务管理状态通过下拉框选择后直接保存。
- 标签支持逗号或回车分隔，保存时去空格、去空值并去重；标签允许清空。

### 附件

- 附件区域提供添加入口，新增后立即关联。
- 移除附件立即解除关联并提供短时撤销。
- 解除关联不删除 Zeus 托管文件；既有会话和历史证据仍可继续引用。

### 保存、错误与并发

- 输入期间不按每次按键调用 API，只在确定提交边界后保存。
- 保存失败保留用户输入和编辑态，展示真实错误与重试入口，不静默回退旧值。
- 每次更新携带开始编辑时的 `updatedAt`；版本已变化时拒绝覆盖并显示冲突。
- 冲突时允许用户“保留本地内容重试”或“载入最新值”。
- 同一窗口的连续字段修改串行提交，并在成功后使用新的 `updatedAt`，避免自身请求互相冲突。

### 事件证据

- 每次真实修改记录任务事件。
- 事件只记录变更字段、标签或附件数量变化和更新时间，不复制完整说明或本机附件路径。
- 没有实际变化时不更新 `updatedAt`，也不创建事件。

## 方案比较

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 全局编辑态与保存按钮 | 实现集中，提交边界直观 | 多一次操作，与已确认的直接编辑不符 | 不采用 |
| 输入时逐键自动保存 | 表面上实时 | 请求频繁、中文输入法风险高、并发与失败恢复复杂 | 不采用 |
| 点击字段进入编辑、失焦保存 | 无额外编辑按钮，阅读态安静，写入次数可控 | 必须清晰表达失焦保存和失败状态 | 采用 |
| 最后写入直接覆盖 | 实现简单 | 多窗口或后台刷新会静默丢失修改 | 不采用 |
| 使用 `updatedAt` 乐观并发 | 无需数据库迁移，可拒绝过期写入 | 需要补齐 API、错误和冲突 UI | 采用 |
| 移除附件时删除托管文件 | 节省磁盘 | 可能破坏会话历史和审计证据 | 不采用 |
| 移除附件只解除关联 | 保留历史可追溯性，可安全撤销 | 托管目录需要独立清理策略 | 采用 |

## 代码级修复计划

### 1. 统一任务内容更新契约

涉及：

- `packages/shared/src/index.ts`
- `packages/storage/src/index.ts`
- `packages/local-server/src/index.ts`
- `apps/desktop/src/renderer/apiClient.ts`

将任务内容更新收敛到 `PATCH /api/tasks/:taskId`。Renderer 使用的请求体包含：

```ts
{
  expectedUpdatedAt: string;
  title?: string;
  description?: string;
  priority?: TaskPriority;
  tags?: string[];
  attachments?: TaskAttachmentReference[];
}
```

具体规则：

- 在 `@zeus/shared` 定义不含预览和可恢复正文的 `TaskAttachmentReference`，Renderer、API 和 Local Server 共用同一持久化附件结构，避免各层复制不一致的对象类型。
- 标题服务端统一 `trim`，空标题返回 `400 ZEUS_TASK_TITLE_REQUIRED`。
- 优先级只接受 `p0` 至 `p4`，非法值返回 `400 ZEUS_INVALID_TASK_PRIORITY`；历史任务保留旧值，用户选择新优先级后写成合法枚举。
- 标签在服务端去空格、去空值、去重；不能只依赖 Renderer 归一化。
- `attachments` 表达保存后的完整关联集合；服务端只替换 `sourceContext.attachments`，必须保留 `path`、图谱来源等其他上下文字段。
- 为兼容既有内部调用，原 `sourceContext` 字段暂不删除；同一请求同时提供 `sourceContext` 与 `attachments` 时返回明确参数错误，避免覆盖规则不确定。
- 请求没有实际字段变化时直接返回当前任务，不更新时间、不写事件、不发布实时更新。

任务管理状态接口同步增加 `expectedUpdatedAt`。切换到完成或取消仍先进入已有 Git 工作区处置流程，完成处置后再使用最新任务版本提交状态。

### 2. 在存储层实现原子版本检查

`TaskRepository` 增加面向任务内容的单次更新方法，替代路由连续调用 `update`、`updateTags` 和 `updateSourceContext`：

1. 在同一事务读取当前任务并核对 `expectedUpdatedAt`。
2. 计算规范化后的新值与真实 `changedFields`。
3. 使用带 `updated_at = expectedUpdatedAt` 条件的单条 `UPDATE` 写入标题、说明、优先级、标签和上下文。
4. 再次确认实际修改行数；不匹配时返回 `ZEUS_TASK_EDIT_CONFLICT`，不得部分写入。
5. 新时间必须严格晚于旧 `updatedAt`，避免同一毫秒内连续更新无法推进版本。

该方案复用现有 `tasks.updated_at`，不增加数据库迁移。独立标签接口继续作为兼容入口保留，但必须接入相同版本检查，不能成为绕过并发保护的旁路；任务详情统一使用主 `PATCH`，不再拆成多条不同更新路径。

### 3. 返回可识别冲突并记录最小事件

本机 API 在版本不匹配时返回：

```json
{
  "error": "ZEUS_TASK_EDIT_CONFLICT",
  "message": "Task changed after editing started.",
  "currentUpdatedAt": "真实最新时间"
}
```

成功修改后：

- 创建 `task.updated` 事件，payload 只包含 `changedFields`、标签或附件变更前后数量、旧版和新版时间。
- 不写入说明正文、标签全文或附件路径。
- 发布 `task.updated` 实时事件，只携带任务 ID、项目 ID、`changedFields` 和新 `updatedAt`。
- 保存 SQLite 后返回最新任务记录。

### 4. 恢复 Renderer 更新协调器

涉及：

- `apps/desktop/src/renderer/main.tsx`
- `apps/desktop/src/renderer/App.tsx`
- `apps/desktop/src/renderer/task/TaskDetailPaneContent.tsx`

在 `App.tsx` 建立单一任务更新入口，负责：

- 按任务串行提交本窗口产生的字段更新。
- 每次成功后同时更新 `snapshot.tasks`、`taskDetail` 和任务抽屉当前对象。
- 当前任务抽屉打开时重新加载任务事件。
- 识别 `ZEUS_TASK_EDIT_CONFLICT` 后加载最新任务，并把“本地草稿 + 最新任务”作为冲突结果交回字段组件。
- 扩展现有实时事件订阅；其他窗口修改任务时刷新对应任务，正在编辑的字段保留本地草稿并在保存时进入版本冲突，不被后台数据静默覆盖。
- 删除只有 setter 的旧 `setTaskEditForm` 残留，避免继续维护无消费者状态。

建议让任务详情更新回调返回明确结果，而不是只抛出普通错误：

```ts
type TaskEditResult =
  | { kind: 'updated'; task: TaskRecord }
  | { kind: 'conflict'; latest: TaskRecord };
```

### 5. 实现字段级编辑状态

在 `TaskDetailPaneContent.tsx` 中使用原生 `input`、`textarea` 和 `ZeusSelect`，不使用 `contenteditable`：

- 标题：阅读文本点击进入单行输入；失焦或 Enter 保存；Escape 恢复服务器值。
- 说明：阅读文本点击进入文本域；失焦保存；Enter 换行；Escape 恢复服务器值。
- 优先级：把只读 `<strong>` 改为 `ZeusSelect`，选择后立即排队保存。
- 标签：新增可阅读标签列表，点击后切换输入；逗号或回车完成标签，失焦保存。
- 附件：复用现有 `TaskAttachmentPreviewList` 的 `editable` 模式和 Main 进程附件选择能力，不新增 IPC。

每个字段维护 `view / editing / queued / saving / error / conflict` 状态。字段状态通过文字和 `aria-live` 表达，不能只靠颜色；保存失败继续显示本地草稿，重试只覆盖当前字段。

### 6. 附件关联与撤销

复用 `onChooseTaskAttachments`，选择结果已经由 Main 保存到 Zeus 托管目录。Renderer 构造完整附件关联列表并立即提交：

- 新增成功后刷新任务与附件计数。
- 移除成功后显示短时撤销；撤销以最新 `updatedAt` 重新加入同一附件记录。
- 新增或移除失败时恢复可解释 UI；新选择但尚未关联成功的托管文件不擅自删除。
- `taskAttachments.ts` 复用现有“合并并输出完整附件关联列表”的纯转换方法；`sourceContext` 其他键由服务端更新契约统一保留。

### 7. 样式与可访问性

在 `apps/desktop/src/renderer/styles.css` 增加任务字段阅读态、悬停提示、编辑态、保存中、错误、冲突和撤销提示样式：

- 阅读态仍保持任务详情的信息密度，不绘制常驻输入框边框。
- hover、focus-visible 和 editing 必须可区分；错误与冲突提供文字说明。
- 窄抽屉下输入框、文本域、下拉框和冲突动作不得横向溢出。
- 中文输入法组合期间不响应 Enter 保存。
- reduced-motion 下不依赖位移或动画表达状态。

### 隔离 API 与数据库验证

使用 `/tmp/zeus-task-edit-validation.*` 临时目录、真实 Fastify `server.inject` 和真实 sql.js 数据库完成验证，不修改用户正式任务。最终成功输出：

```json
{"result":"TASK_EDIT_API_VALIDATION_OK","changedFields":["title","description","priority","tags","attachments"],"staleStatus":409,"blankTitleStatus":400,"managementConflictStatus":409,"linkedFilePreserved":true}
{"result":"TASK_EDIT_NOOP_UNDO_VALIDATION_OK","noOpVersionUnchanged":true,"noOpEventCountUnchanged":true,"attachmentCounts":[{"before":1,"after":0},{"before":0,"after":1}],"linkedFilePreserved":true}
```

真实断言覆盖：

1. 同一次请求更新标题、说明、优先级、标签和附件，返回值与 SQLite 记录一致，标签完成去空格和去重，`updatedAt` 严格推进。
2. 使用旧 `updatedAt` 更新内容和管理状态，均返回 `409 ZEUS_TASK_EDIT_CONFLICT`。
3. 提交空白标题返回 `400 ZEUS_TASK_TITLE_REQUIRED`；说明和标签可清空。
4. 清空附件关联后 `sourceContext.origin` 仍存在，真实临时文件仍可访问，证明接口只解除关联。
5. `task.updated` 的 `changedFields` 为标题、说明、优先级、标签和附件；事件 JSON 不包含说明正文或附件绝对路径。
6. 提交与当前值完全相同的内容后 `updatedAt` 与事件数量均不变化。
7. 附件从 1 条移除到 0 条、再从 0 条恢复到 1 条，两次事件只记录数量变化；关联往返后真实文件始终存在。

验证脚本前两次中止均为脚本预期错误，不是产品结果：第一次把创建接口真实的 `201` 误写成 `200`，得到 `201 !== 200`；第二次使用不存在的管理状态 `in_progress`，路由正确返回 400，随后改为真实枚举 `in_development` 并在全新临时库完整通过。四个 API 验证目录均已删除并确认不存在。

8. 已完成和已取消任务可以修正内容，管理状态不改变。
9. 编辑任务后打开既有会话，确认历史未变化；再推送到新会话，确认首条任务内容使用最新值。
10. 检查浅色、深色、窄抽屉、键盘焦点、中文输入法和 reduced-motion。

## 风险与回滚

- **失焦误保存**：通过字段级保存中与失败提示、Escape 取消降低风险；仍需真实桌面验收焦点切换。
- **同窗口伪冲突**：通过按任务串行提交并推进 `updatedAt` 避免。
- **外部更新覆盖草稿**：通过服务端版本检查和冲突选择阻断。
- **附件上下文误覆盖**：服务端只替换 `attachments` 键并使用同一版本前置条件。
- **事件泄露正文或路径**：事件 payload 使用字段名和数量白名单。
- **终态状态绕过 Git 门禁**：保留现有完成／取消处置流程，不把普通字段编辑与任务关闭混合。
- **回滚方式**：恢复任务详情只读渲染和旧更新请求类型即可；本方案不需要数据库迁移，已保存任务字段仍是现有列和 JSON 字段，可继续读取。
