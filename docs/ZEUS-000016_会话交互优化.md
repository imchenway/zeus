# ZEUS-000016 会话交互优化

## 任务目标

优化会话中连续思考摘要的展示：减少重复堆叠，尊重来源语言，并为进行中的最新摘要补充可识别图标和状态动效。

## 当前事实

- 截图红框中的内容是 Codex JSONL `reasoning.summary` 提供的思考摘要，不是命令或工具活动。
- 同一份 JSONL 可以同时包含英文思考摘要与中文助手消息；界面不能假设思考摘要必然为中文。
- 现有会话界面会把多个 reasoning item 逐条加入对话记录，因此同一执行轮次会连续堆叠多条摘要。
- 现有“正在思考”是 Zeus 根据运行状态生成的本地提示，不是 JSONL 中与每条摘要对应的中文版本。
- 命令和工具活动已有中文标题、图标及“运行中仅显示最新活动”的交互，但思考摘要尚未复用该收敛方式。

## 已确认口径

### 思考摘要语言

- 显示 JSONL 中最新思考摘要的原文。
- 原文是中文时显示中文；没有中文时保留英文。
- 禁止用“正在处理”等固定中文占位替代具体摘要。
- 本任务不默认增加额外翻译调用，避免延迟、成本和误译。

优点：忠实保留原始事实，不伪造翻译，也不丢失具体进度语义。

缺点：当 Codex 只提供英文摘要时，中文界面仍会出现英文；这是来源事实，而不是界面漏翻译。

### 执行结束后的展示

- 执行中只显示最新一条思考摘要，并显示进行中的图标与动效。
- 执行轮次结束后保留最后一条摘要，停止动效并切换为静态完成图标。

优点：用户能识别当前是否仍在运行，同时每轮保留一条真实过程线索。

缺点：相比结束后完全隐藏，会占用一行历史空间。

### 最新摘要的计算范围

- 每个执行轮次独立保留自己的最后一条思考摘要。
- 同一轮次新摘要出现时替换上一条，不继续向下堆叠。
- 新执行轮次不会删除旧轮次已经保留的最后一条摘要。

优点：单轮页面保持简洁，同时多轮对话仍能看出每轮最后处理到了哪里。

缺点：长会话仍会随执行轮次数量增加摘要行，但不会再按单轮摘要数量快速膨胀。

### 改动对象

- “只保留最新一条”只作用于思考摘要。
- 命令、搜索、工具活动和最终回答继续按现有方式展示，不因本次改动删减。
- 运行中使用现有图标体系内的进度图标和旋转动效；结束后切换为静态完成图标。
- 系统开启“减少动态效果”时停止旋转，但继续通过图标和可读状态表达运行中。

优点：直接解决截图中的摘要堆叠，同时保留命令详情和真实执行证据。

缺点：命令与工具活动仍会占用独立空间，需要继续通过现有折叠交互查看。

## 实现记录

- 新增思考摘要专用展示组件，不再把 reasoning 当作普通 Markdown 消息逐条渲染。
- 每个执行轮次只投影最后一个含可读内容的 reasoning item。
- 同一个 reasoning item 包含多个 `summarySegments` 时，只显示最后一个非空段。
- 优先读取结构化摘要段；来源是中文则显示中文，来源只有英文则保留英文，不增加固定中文替换或额外翻译调用。
- 活动轮次使用进度图标，完成、失败、中断和等待分别使用可区分的静态图标；运行图标通过外层容器旋转。
- 活动摘要使用礼貌播报区，辅助功能名称同时包含状态和完整摘要；视觉文字过长时单行截断，但辅助技术仍可读取全文。
- 现有全局 `prefers-reduced-motion` 规则会取消旋转与过渡，状态图标和文字继续保留。
- 命令、搜索、工具活动、最终回答和每轮耗时没有进入摘要筛选范围。

## 设计取舍

- 每轮只保留一条能显著降低长任务噪音；代价是旧摘要不再提供逐段阅读入口。
- 保留来源原文避免误译与额外模型调用；代价是中文界面中仍可能出现英文摘要。
- 完成后保留静态摘要提供最小过程线索；代价是每个执行轮次仍增加一行历史内容。
