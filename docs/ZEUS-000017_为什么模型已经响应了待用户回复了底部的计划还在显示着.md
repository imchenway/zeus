# ZEUS-000017 为什么模型已经响应了，待用户回复了，底部的计划还在显示着

## 当前阶段

产品边界已确认，代码修复、静态回归、测试包和真实会话验收已完成。

## 截图现象

- 模型已经输出完整回复，并说明等待用户确认。
- 输入区已恢复普通续写状态。
- 输入框上方仍显示“第 3 / 3 步”计划进度。

## 真实原因

`selectDockedTurnPlan` 在存在活动执行轮次时返回当前轮次的计划；但在执行轮次已终止、`activeTurnId` 为空时，它会继续从会话记录中倒序寻找最近一份非空计划并返回。因此，该计划被当成持久的“最近计划”，而不是仅在当前轮次执行期间显示的“执行进度”。

`SessionPlanProgress` 在找不到“进行中”或“待执行”步骤时，会默认选择最后一步。所以三步都完成后，紧凑条仍显示“第 3 / 3 步”，没有表达“计划已完成”。

## 已确认的领域边界

“待用户回复”存在两种不同状态：

1. 模型已完成本轮输出，只是在文案中邀请用户发起下一轮；此时本轮已终止。
2. 模型发起了正式用户输入请求，当前轮次仍处于等待交互状态。

当前截图更符合第一种：界面是普通续写输入框，没有展示正式待处理问题面板。

用户已确认本任务采用“本轮结束后立即隐藏”：底部展示的是“活动计划进度”，不是“最近计划”。

## 建议口径

- 当前轮次已终止时，输入框上方不再显示历史计划进度。
- 计划内容仍保留在会话记录和计划工作区中，不删除历史证据。
- 只有当前轮次仍处于运行、等待审批或正式等待用户输入时，底部才展示该轮次的计划进度。

### 优点

- 底部计划只表达真实活动轮次，不会让用户误以为模型还在执行。
- 历史计划仍然可查，不丢信息。
- 正式等待交互仍可继续展示当前轮次的上下文。

### 代价

- 用户在本轮结束后不能从输入框上方的紧凑条快速回看计划，需要从会话记录或计划工作区打开。
