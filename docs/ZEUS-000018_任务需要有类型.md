# ZEUS-000018 任务需要有类型

## 任务状态

已完成，尚未提交 Git。

## 用户目标

Zeus 的每个任务必须有明确类型，并根据类型展示和发送对应字段。Vibego 只作为字段口径参考，不参考其状态、存储、流程、提示词或界面实现。

## 已确认产品口径

### 任务类型

- 固定为“需求、缺陷、优化”三类，不增加“风险”。
- 新建任务时类型必选，不提供默认值。
- 历史无类型任务统一迁移为“需求”。
- 类型只表达任务工作目标，不改变任务状态、优先级、标签、附件或执行方式。

### 类型专属字段

- 需求：需求描述。
- 缺陷：现状、预期、复现步骤。
- 优化：现状、预期。
- 标题和类型必填，类型专属字段允许为空。
- 字段顺序按以上口径，不沿用 Vibego 的缺陷字段顺序。

### 类型切换

- 创建后允许修改类型。
- 切换类型时保留其他类型已经填写的内容，避免数据丢失。
- 界面只展示当前类型字段；切回原类型时恢复此前内容。
- 推送新会话时只发送当前类型和当前类型字段，不发送隐藏内容。

### 界面范围

- 创建任务弹窗增加必选类型，并按类型切换专属字段。
- 任务详情支持查看、修改类型和当前类型字段。
- 任务主列表新增默认可见、可排序的“类型”列。
- 本任务不增加任务工具条类型筛选。

## 方案取舍

### 采用结构化类型内容

优点：字段可以单独编辑、展示和发送；类型切换不会依赖解析自由文本；以后增加筛选或统计时不需要从说明中猜测。

缺点：需要增加数据库迁移、接口校验、历史数据回填和多处界面适配。

### 不照搬 Vibego 的正文拼接存储

优点：避免把现状、预期和复现步骤塞进一段文本后再反向解析，数据边界更清楚。

缺点：实现范围比只增加一个类型字符串更大。

## 实现范围

- 共享任务类型、固定顺序和运行时校验。
- SQLite 字段、历史数据迁移、仓储创建与内容更新。
- Local Server 创建、更新、列表排序、事件与审计字段。
- Renderer API 类型、创建弹窗、任务详情和任务表类型列。
- 正式任务首发正文增加任务类型与当前类型字段。
- `CONTEXT.md` 与 `DESIGN.md` 契约更新。

## 明确不做

- 不引入 Vibego 的风险类型、任务状态、优先级、编号或关联任务字段。
- 不照搬 Vibego 的 Telegram 分步创建流程。
- 不把类型变成标签、来源或执行配置。
- 不增加类型工具条筛选。
- 不创建或恢复项目已退役的单元测试体系。
