# ZEUS-000024 点击打开会话自动定位最新消息

## 1. 任务目标

用户点击打开或重新切回任一已有会话时，首帧直接显示底部最新消息，不再先显示顶部历史内容后播放滑到底部的动画。

## 2. 已确认产品口径

- 每次打开或重新切回已有会话，都无视上一次离开时的阅读位置并直接显示最新消息；
- 初始定位不播放滚动动画；
- 用户停留在当前会话期间，新消息继续沿用现有跟随体验；
- 用户主动向上阅读历史后，当前会话继续保留“返回最新消息”入口。

优点：切换会话后立即看到当前结果，长会话不会产生明显的从头滑到底部过程。

代价：用户离开会话前正在阅读的历史位置不会在下次切回时恢复。

## 3. 只读诊断

- `App.tsx` 以会话 ID 作为 `ConnectedSessionWorkspace` 的 React key，因此每次切换会话都会创建新的会话工作区；
- `useThreadScrollController` 默认进入消息跟随状态；
- `ConversationTranscript` 在历史数据进入后，把首次 transcript 更新与后续新消息更新都按平滑滚动处理，导致长会话先显示顶部再滑到底部；
- 会话滚动容器自身声明了平滑滚动样式，因此 `behavior: auto` 仍会继承平滑行为，不能保证初始定位无动画；
- 数据加载、会话恢复和消息顺序本身不需要修改。

## 4. 实现方案

在 `ConversationTranscript` 中单独处理每个会话首次取得可用历史后的初始定位：在浏览器绘制前，显式使用 `instant` 把消息容器定位到末尾，不继承容器的平滑滚动样式。后续 transcript 更新继续交给原有滚动控制器，避免改变停留期间的新消息跟随和用户主动阅读历史的行为。

本任务是局部、可逆的界面行为修复，不新增 ADR，不新增或恢复单元测试体系。

### 5.2 渲染与真实会话切换

- 浏览器开发地址 `http://127.0.0.1:4179/` 的页面标题为 `Zeus`，但脱离 Electron 后报“本地桥接未就绪”并停留在启动壳；该路径不能验证会话数据与滚动行为；
- 真实验收使用本任务生成的 `Zeus Test.app`，没有启动、替换或修改 `/Applications/Zeus.app`；
- 为避免污染其他测试任务，从现有测试数据库通过 SQLite backup 复制到一次性用户数据目录；副本包含 8 个会话、52 个消息项，目标长会话包含 19 个消息项；
- 通过只作用于测试 Renderer 的调试协议把 `prefers-reduced-motion` 设为 `no-preference`，并把页面视口设为 `900 × 500`，确保消息区真实溢出且平滑滚动不会被系统设置自动关闭；
- 使用 `behavior: auto` 的中间实现复现失败：切回长会话后首个溢出帧 `scrollTop=0`、距底部 `265px`，随后逐帧滑动到 `scrollTop=266`；这证明容器的 `scroll-behavior: smooth` 仍被继承；
- 改为 `behavior: instant` 后，首次打开长会话的首个溢出帧 `scrollTop=265`、距底部 `0px`，所有采样帧最大距底部为 `0px`；
- 切到第二个会话再切回后，首个溢出帧仍为 `scrollTop=265`、距底部 `0px`，所有采样帧最大距底部为 `0px`；
- 最终截图和辅助功能树都显示目标会话的最后一条回复、轮次耗时和底部 composer，没有停留在顶部历史消息；
- 精确切换期间没有 `Runtime.exceptionThrown`。控制台记录一个既有 CSP meta 提示，以及快速卸载第二个会话时 WebSocket 尚未连接完成的警告；两者不影响本次滚动结论，也未在本任务中扩展处理。
