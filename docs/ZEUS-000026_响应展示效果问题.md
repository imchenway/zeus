# ZEUS-000026 响应展示效果问题

## 任务目标

修复会话回复中附件不可用和 Markdown 展示不完整的问题，使常用 GitHub 风格 Markdown 能稳定呈现，并让受信附件与正文图片可以在 Zeus 内安全打开。

## 用户现场

- GitHub 风格表格被压成普通段落，竖线和分隔符直接显示。
- `![说明](路径)` 图片语法只剩下 `!说明`，没有正文缩略图。
- 文件名虽被识别成资源样式，但用户无法稳定通过回复内容查看对应文件。

## 已核对事实

- 当前 `SafeMarkdown` 是自研 Markdown 子集，支持标题、普通列表、引用、代码块、粗体、斜体、行内代码和资源链接。
- 当前解析器不支持表格、任务清单、删除线、嵌套列表和图片节点；连续表格行会进入普通段落并被浏览器折叠换行。
- Local Server 已把受支持 Markdown 链接归一化为会话资源，打开前会重新校验项目根或附件根。
- Zeus 已有源码预览、图片预览、内置浏览器、系统默认应用、Finder 和复制路径等资源打开目标；图片默认目标已经是 Zeus 预览。
- 因而本任务不应新增绕过授权的本机路径打开方式，重点是补齐 Markdown 解析和正文图片呈现。

## 已确认产品口径

2026-08-04 用户逐项确认：

1. 附件单击默认进入 Zeus 应用内预览；代码文件定位源码视图，其他类型保留“打开方式”。
2. 回复支持常用 GitHub 风格 Markdown，包括表格、图片、任务清单、删除线、嵌套列表、链接和代码块。
3. 消息内嵌 HTML 不执行。
4. Markdown 图片在正文显示受限尺寸缩略图，单击进入 Zeus 应用内预览。
5. 只有服务端已经识别和授权的项目文件或附件可点击；路径失效时就地提示，不静默失败，也不放宽权限。
6. 本次不包含富文本编辑、远程图片无条件加载或可执行 HTML。

## 方案比较

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 继续给自研解析器逐项打补丁 | 初始改动小，容易复用现有节点 | 嵌套语法和边界组合复杂，后续仍会重复出现兼容缺口 | 不采用 |
| 使用成熟 Markdown 渲染器并启用 GFM | 常用语法覆盖完整，行为可预期，维护成本较低 | 增加前端依赖，需要重新接入资源授权和复杂度限制 | 采用 |
| 支持 Markdown 内嵌 HTML | 表达能力最强 | 扩大脚本、样式和内容注入风险，不符合本地研发工具的可信边界 | 排除 |

## 实现边界

- 保留消息总长度和结构复杂度限制，避免异常回复拖垮会话界面。
- 普通网站链接、项目文件、任务附件继续由 Local Server 生成受信会话资源；Renderer 只渲染已授权资源的交互。
- 图片节点只加载受信资源的预览数据，不直接加载 Markdown 原文中的远程地址或任意 `file://` 地址。
- 无法匹配受信资源的链接保留可读文本；无法匹配受信资源的图片显示安全降级说明。
- 表格和长内容必须限制在消息宽度内，窄窗口允许表格自身横向滚动，不推动整个会话页面溢出。
- 交互必须支持键盘焦点、忙碌状态、错误提示和图片替代文本。

## 实施结果

- 会话回复改用成熟 Markdown 渲染链，并启用 GFM 表格、任务清单、删除线、嵌套列表、链接、图片和代码块。
- 文件链接只在匹配到服务端授权的会话资源后才显示为按钮；源码文件继续进入 Zeus 源码预览并保留行号定位。
- 正文图片先通过受信预览接口延迟加载为缩略图，单击后进入 Zeus 图片预览；未授权或失效图片显示就地说明。
- Markdown 原文中的远程地址、任意本机地址和 HTML 不会直接加载或执行。
- 保留消息总长度、代码块长度、块数量和节点数量限制；表格、缩略图均限制在消息宽度内。
- 新增 Markdown 独立打包组。首次真实启动发现解析依赖被全局体积规则拆成循环代码包，打包应用报错并停在启动页；将该依赖链固定在单一 153.78 KB 代码包后恢复正常启动。
