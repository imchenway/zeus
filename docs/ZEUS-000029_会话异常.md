# ZEUS-000029 会话异常

## 任务目标

修复同一现场中的三个关联问题：

1. 应用重启或重新连接后，可安全续接的原会话没有自动恢复；
2. 尚未进入 Codex 执行轮次的用户输入卡在队列中；
3. 恢复态额外渲染的新会话输入框出现在聊天记录顶部，形成两个主输入区。

本任务不执行 commit、push、merge 或 revert；真实桌面验收只使用独立身份的 `Zeus Test.app`，不生成或启动任务 worktree 中的生产身份 `Zeus.app`。

## 用户确认的领域口径

### 恢复与发送分离

- 会话自动恢复只把可安全续接的原会话恢复为“可继续”，不自动发送任何队列消息。
- 只有尚未取得 `providerTurnId` 的 `queued / paused` 输入属于未发送内容。
- 已经取得 `providerTurnId` 的失败提交属于失败执行轮次，不回填、不重放，避免命令或文件修改执行两次。

### 草稿去向

- 原 Codex 线程能够被权威快照确认安全续接时，未发送内容回到原会话输入框，等待用户再次点击发送。
- 原线程身份或终态无法确认时，保留原聊天记录，并把未发送内容带入新会话草稿；仍然不自动发送。

### 恢复态布局

- 会话页始终只保留一个底部主输入区。
- 顶部恢复提示只解释原因和影响，不渲染输入框。
- 原会话无法安全续接时，底部原输入框位置显示预填的新会话输入区。

## 取舍

优点：保留可续接会话的上下文，同时杜绝应用重启后突然执行和重复执行；恢复态也不会再出现上下两个输入框。

缺点：恢复出的未发送内容必须由用户再次点击发送，比自动续发多一步；无法权威确认的原会话仍然只能新建会话。

不采用无条件自动续发：它无法排除 provider 已经接受写入但本地未收到确认的时间窗，可能重复执行带副作用的工具调用。

## 当前源码证据

1. `codexNativeConversationCoordinator.ts` 在安全恢复后会继续执行 `drainQueuedSubmissions()`，导致未发送内容自动派发，与本次确认口径冲突。
2. `useSessionController.ts` 会把本机持久化的 `recoveryRequired` 错误一直保留；即使后端快照已经恢复为安全状态，原会话仍会被前端写入门禁阻断。
3. Coordinator 的队列事件没有携带 `providerTurnId` 与附件，而完整会话快照有这些字段，事件覆盖后会让前端无法可靠区分失败轮次与未发送内容。
4. `SessionWorkspace.tsx` 在恢复错误出现时，无条件在聊天记录上方挂载 `NewConversationComposer`；底部又保留未发送恢复表面，因此形成截图中的顶部漂移和双输入区。

## 实现范围

- `CONTEXT.md`：明确会话自动恢复和未发送内容的产品含义。
- `packages/local-server/src/codexNativeConversationContracts.ts`：补齐队列提交的事实字段并增加人工确认恢复原因。
- `packages/local-server/src/codexNativeConversationCoordinator.ts`：安全恢复时把未发送内容转为待人工确认，不自动 drain；完整输出队列提交身份与附件。
- `packages/local-server/src/index.ts`：优先保留真实恢复错误，避免人工确认队列遮蔽会话仍需恢复的事实。
- `apps/desktop/src/renderer/session/useSessionController.ts`：权威快照确认安全后清理粘滞恢复错误，并把待人工确认内容持久回填到原会话草稿。
- `apps/desktop/src/renderer/session/ConversationComposer.tsx`：人工确认内容回填草稿后，不再重复显示成队列卡片。
- `apps/desktop/src/renderer/session/SessionWorkspace.tsx`：恢复态只在底部输入区挂载新会话输入框；新会话被服务端接受后再软删除原会话未发送记录。
- `apps/desktop/src/renderer/App.tsx`：向恢复输入框返回新会话是否已被服务端接受的明确结果，失败时不得清理原内容。
- `apps/desktop/src/renderer/session/session.css`：补齐底部恢复 composer 的布局边界。

### 真实恢复与界面

全部运行证据来自独立用户目录中的 `Zeus Test.app`，未启动或修改生产身份 `Zeus.app`。

1. 创建真实 Codex 原生会话并取得终态回复，随后在隔离数据库写入一条没有 `providerTurnId` 的未发送提交并重启应用。
2. 重启后原 provider 会话从 `paused` 自动恢复为 `ready`；未发送提交变为 `paused / user_confirmation`，队列运行态为 `idle`，没有自动创建新的 provider turn。
3. Renderer 将该内容持久回填到原会话底部输入框；随后服务端旧记录软删除。界面只有一个底部输入框，没有顶部漂移组件，也没有重复队列卡片。
4. 将同一隔离会话置为无法安全续接后重启：原记录保持只读，顶部只显示原因与“带入新会话”，预填的新会话输入框位于页面底部。
5. 用户点击底部发送前，原提交始终没有 `providerTurnId`；点击后才创建新 provider 会话。新会话被服务端接受后，原异常会话记录变为 `deleted`；再次打开原会话时底部输入框为空，未发送内容不再重复出现。

### 未纳入本次修改的现场风险

正式用户数据库的宽范围只读查询曾返回 `database disk image is malformed (11)`。本任务没有修复、重写或替换正式数据库，也不把该现象直接归因为本次三个界面与恢复问题；真实验收改用独立临时数据库完成。该数据库健康问题需要单独备份和诊断。
