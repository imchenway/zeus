# ZEUS-000034 会话列表状态自动刷新

## 当前阶段

已完成实现、静态检查、构建、隔离测试包打包与真实界面验收。

## 任务目标

会话列表中的后台会话发生生命周期变化时自动更新展示状态。用户不需要先点击会话，列表就应正确显示响应中、等待批准、需要用户输入、完成、失败、暂停或排队。

## 用户确认

- 不只修复“需要用户输入”一个状态，而是覆盖后台会话的全部运行状态。
- 采用现有实时事件驱动，并从服务端重新读取该会话的权威摘要；不为每一行新建 controller，也不使用定时轮询。
- 保留现有等待态的“胶囊 + 转圈”视觉，本任务不调整样式。
- 点击会话只负责打开内容，不再承担状态刷新职责。

## 根因证据

- `ProjectConversationTree` 优先读取 `nativeConversationRuntimeStates`，没有实时状态时才从会话选择摘要推断。
- `nativeConversationRuntimeStates` 只由当前选中的 `ConnectedSessionWorkspace` 通过 `onStateChange` 写入。
- 全局实时事件监听当前只处理完成未读、任务刷新和旧 Runtime 输出，没有把 Codex native 会话生命周期事件投影到列表。
- 服务端收到 `request_user_input` 后已经持久化 pending request、把 provider 状态更新为 `waiting`，并广播 `conversation.request.created`。
- 因此后台会话仍保留此前的 `streaming` 展示；用户点击后，选中会话 controller 重新读取权威快照，列表才显示“需要用户输入”。

## 实现设计

1. 把会话生命周期事件限定为列表摘要失效信号，包括连接、线程、轮次、队列、阻塞请求和 native 错误变化。
2. 按 `conversationId` 合并并发刷新，关键事件到达时读取该会话的权威快照；刷新期间再次到达事件时，在当前读取完成后补一次读取，避免请求创建和解决快速连续发生时覆盖成旧状态。
3. 用权威快照更新任务级或项目级会话选择缓存，并同步列表状态与任务运行状态投影。
4. 未知会话不凭事件载荷伪造列表项；先取得权威快照，再按其真实任务归属刷新对应列表。

## 取舍

- 优点：后台会话与当前会话使用同一服务端事实，解决同类状态陈旧问题；单一全局事件连接和按会话合并读取不会随列表行数增加常驻连接。
- 缺点：每次关键生命周期变化会增加一次本机摘要读取；快速连续事件需要补偿刷新，代码比只映射一个 `request_user_input` 事件更完整。
- 不采用仅修单一事件：改动较小，但等待批准、完成或失败仍可能陈旧。
- 不采用定时轮询：实现直观，但产生持续无效读取，且状态变化仍存在轮询延迟。

## 验收口径

- 未选中的会话从响应中进入需要用户输入时，列表自动显示蓝色胶囊。
- 未选中的会话进入等待批准、完成、失败、暂停或排队时，列表自动切换到对应状态。
- 阻塞请求解决后，仍在执行的轮次回到响应中；只有轮次结束后才显示就绪、完成未读或失败。
- 用户点击会话前后，同一时刻的列表展示状态保持一致。
- 不新增或恢复单元测试、组件测试、DOM/CSS 契约测试和 TDD 流程。
- 未获得授权前不执行 git 历史或远端操作；用户后续明确授权本任务的 commit 和 push，不包含 merge、revert 或创建 PR。
