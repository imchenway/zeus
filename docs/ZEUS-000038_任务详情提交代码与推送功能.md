# ZEUS-000038 任务详情提交代码与推送功能

## 任务目标

任务详情的“代码交付”区域直接提供“提交代码”和“推送代码”两个独立入口，让用户无需先进入完整代码交付流程，也能处理任务开发线的日常 Git 操作。

## 用户确认

- “提交代码”只创建本地提交，不自动推送。
- “推送代码”只推送当前任务开发线已经存在的本地提交，未提交和已暂存改动保持原样。
- 推送禁止强制推送，不自动提交、不回收 worktree、不合入目标分支；成功后必须校验远端 SHA 与本地 HEAD 一致。
- 两个入口放在任务详情现有“代码交付”区域；已有会话 `Cmd+K` 和代码交付准备中的“提交并推送”继续保留。
- 入口不受任务管理状态限制，由任务开发线、活动会话、冲突和真实 Git 状态决定是否可执行。

## 领域边界

### 代码提交

用户选择任务开发线、审查差异、选择文件并填写提交说明后创建本地 Git commit。它不改变任务管理状态，也不推送、回收或合入。

优点：提交内容和说明由用户明确确认，复用已有完整差异审查。

代价：用户如果还要同步远端，需要再执行一次“推送代码”。

### 代码推送

用户选择任务开发线并确认真实远端后，只把当前 HEAD 推送到该开发线记录的远端分支。工作区中的未提交和已暂存内容不会进入远端。

优点：本地提交和远端同步责任清晰，脏工作区也能安全同步已有提交。

代价：未提交改动仍需后续单独提交；远端非快进时必须由用户先处理分支差异，Zeus 不使用 force push。

### 与代码交付的关系

代码提交和代码推送是任务开发线的日常操作；代码交付仍负责远端校验后的 worktree 回收与目标分支合入。三个概念不能互相替代。

## 实现范围

1. Git 核心新增只推送任务开发线 HEAD 的能力，且不读取或写入 index。
2. 本机 API 新增受控的任务开发线推送接口，复用活动会话门禁并写入任务事件和审计日志。
3. Renderer API 增加类型化推送方法。
4. 提交审查弹窗增加任务详情专用的“仅提交”和“仅推送”模式；既有组合流程保持不变。
5. 任务详情“代码交付”区域增加两个独立入口，覆盖中英文、忙碌、错误、冲突和无可用开发线状态。

## 安全约束

- 不执行 force push、rebase、远端分支删除、worktree 回收或目标分支合入。
- 活动会话可能继续写入任务开发线时禁止提交和推送。
- 冲突未解决时禁止提交和推送。
- 推送参数使用结构化 `execFile` 调用，远端和分支继续经过 Git ref 校验。
- 推送成功后读取远端分支 SHA；与本地 HEAD 不一致时报告失败，不伪装成功。
- 本任务开发和验收不对用户真实项目执行 commit 或 push。
