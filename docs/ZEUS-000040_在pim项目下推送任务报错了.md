# ZEUS-000040 在 pim 项目下推送任务报错了

## 任务目标

修复项目容器不是单一可交付 Git 仓库、但内部包含多个前后端 Git 仓库时，任务推送被 `ZEUS_TASK_GIT_REMOTE_REQUIRED` 阻断的问题，并打通项目仓库登记、多仓任务环境、会话权限与逐仓代码交付全链路。

## 现场证据

- Zeus 中 `pim` 项目真实路径为 `/Users/david/cckg/tcapp/Back-End/pim`。
- 该目录自身不是 Git 根；Git 向上查找时可能识别到父级仓库，因此产品不能只凭 `git status` 成功就把它静默当成唯一项目仓库。
- 容器内 `tc-app-goods` 与 `web-base` 是独立 Git 仓库，各自拥有自己的 remote。
- `packages/local-server/src/index.ts` 的 `resolveTaskPushCapabilities` 在读取任务权限和仓库选择前，强制要求项目根仓库存在 remote；因此截图中的“只读”推送也会失败。
- 当前 `projects` 只保存单个 `localPath`，`task_workspaces` 也把一个任务开发线固定为单仓分支和单个 worktree，无法诚实表达多仓任务。

## 用户确认的领域边界

1. 项目是容器目录，可以登记零到多个嵌套 Git 仓库。
2. Zeus 扫描容器内仓库，由用户勾选确认后加入项目；不静默纳入全部扫描结果。
3. 新建任务环境时包含项目登记的全部仓库，每个仓库的来源分支都必须由用户手动选择。
4. 各仓库先从所选分支 `HEAD` 创建 worktree，再按 Codex App 的行为尝试带入该仓库当前未提交改动；被 Git 忽略的文件只按 `.worktreeinclude` 规则处理。
5. 多仓环境按原项目相对路径镜像，例如 `tc-app-goods/`、`web-base/`；会话 cwd 指向任务环境根目录，不能继续指向原项目容器。
6. 同一任务再次推送默认复用既有任务环境，也允许显式新建并重新逐仓选择来源分支。
7. 项目没有登记 Git 仓库时，任务直接使用项目容器，不要求选择分支，也不创建 worktree。
8. `docs/` 等路径可登记为共享可写目录，任务直接写回真实目录；其他非 Git 内容默认只读。
9. 创建多仓任务环境必须是应用级原子流程：任一仓库创建或带入改动失败时回滚本次已创建工作区，不创建会话，不遗留半套环境。
10. task push 不要求 remote。无 remote 的仓库可以本地开发和合入，只是不提供远端推送结果。
11. 多仓交付逐仓独立完成；所有仓库都已交付、放弃或确认无变化后，才能整体回收任务环境。
12. 本次先打通任务全链路。其他项目页面尚未多仓化时必须显示真实限制，不能继续把项目容器伪报成唯一仓库。

## 方案优缺点

### 采用项目仓库与任务环境两层模型

优点：项目归属、任务隔离和逐仓 Git 生命周期边界清楚；前后端可以在同一任务中协作；无 Git 项目也能继续创建任务会话。

缺点：需要扩展存储、API、权限根、恢复和交付状态；每次新建环境会为全部项目仓库创建 worktree，耗时和磁盘占用随仓库数量增长。

### 未采用只绕过 remote 门禁

优点：改动小，可以快速让弹窗继续提交。

缺点：会话仍只绑定一个错误的项目根，提交、推送、合入和回收都会继续操作错误仓库，无法满足多仓任务。

### 未采用静默扫描全部嵌套仓库

优点：无需首次配置。

缺点：容易把示例、缓存、依赖或临时仓库纳入每个任务，扩大写入范围和 worktree 成本。

## 实现范围

- 存储项目仓库、共享可写目录、任务环境和逐仓任务工作区。
- 提供容器内 Git 仓库发现、用户确认和项目配置接口。
- 扩展任务推送能力与表单，逐仓选择来源分支，支持既有环境复用和新环境创建。
- 在隔离任务根中按相对路径创建全部仓库 worktree，并将共享可写目录映射为受控额外写入根。
- 把会话执行上下文从单一 cwd 扩展为任务环境根与多个受控写入根。
- 把代码审查、提交、可选推送、合入和回收改为逐仓事实与整体收敛状态。
- 未全面多仓化的项目级 Git 状态、差异、快照和补丁入口显示明确限制。

## 验收要求

- `pim` 容器不再因顶层没有 remote 而阻断任务推送。
- 项目仓库发现结果需要用户确认，未登记仓库不会进入任务环境。
- 新建环境时全部仓库都要求显式来源分支；零仓库项目不显示分支选择。
- 多仓环境保持原相对路径，并能在同一会话中读写各仓库 worktree。
- 原仓库未提交改动按 Codex 行为带入；任一仓库失败时完整回滚。
- `docs/` 写入直接落到项目容器真实目录，其他非 Git 路径保持只读。
- 同一任务默认复用环境，显式新建时生成另一套环境。
- remote 只影响对应仓库的推送能力，不影响任务环境创建。
- 各仓库可以独立提交、推送、合入；整体回收前所有仓库必须收敛。
- 完成 `pnpm lint`、`pnpm typecheck`、`pnpm build`、`git diff --check`、必要的隔离 Git 验证与仓库生成桌面包真实交互验证；静态检查或构建成功不冒充运行验收。

## 实施结果

- 新增项目仓库、共享可写目录、任务环境和逐仓工作区的持久模型，并兼容回填旧的单仓任务工作区。
- 项目设置可扫描容器内真实 Git 根，由用户勾选登记仓库并逐行登记 `docs/` 等共享可写目录。
- 推送弹窗会为全部登记仓库显示独立的来源分支和新分支；来源分支没有默认值，全部确认后才允许创建。
- 尚未登记仓库但扫描到候选时，能力接口和创建接口都会阻止误走零仓路径；真正零仓项目继续直接使用项目目录。
- 多仓任务环境按原相对路径聚合 worktree，复制 staged、unstaged、untracked 以及 `.worktreeinclude` 命中的忽略文件；创建失败逐仓回滚。
- 会话 cwd 指向聚合环境根，写权限只覆盖逐仓 worktree 与显式共享目录；其他容器内容仅通过镜像链接读取。
- 代码审查、提交、可选推送、合入、放弃和回收均按仓库执行；全部成员收敛后才回收环境。
- 无远端仓库可本地提交和合入。原目标分支不干净时保留隔离合入结果，进入等待本地同步，清理原目录后可重试。
- 旧项目级 Git 页面在多仓、嵌套仓或非 Git 根场景返回明确能力限制，不再向上误认父级仓库。
