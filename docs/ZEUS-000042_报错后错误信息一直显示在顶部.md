# ZEUS-000042 报错后错误信息一直显示在顶部

## 任务目标

修复任务推送失败后，同一错误既出现在当前操作区、又长期停留在整个工作区顶部的问题。错误应跟随可恢复的业务操作显示，不把任务推送失败误报为 Zeus 应用全局故障。

## 现场证据

- 截图中的顶部提示为 `Task model push requires a Git remote so the task branch can be delivered before worktree cleanup.`。
- `apps/desktop/src/renderer/App.tsx` 的 `recordLocalError()` 会写入全局 `localError`；工作区根部只要存在该状态，就持续渲染顶部 `.inline-status.failed`。
- 当前实现没有为 `localError` 提供关闭、超时或任务切换清理路径，因此一旦写入就会一直显示到 Renderer 状态重建。
- 任务推送能力加载失败已经由推送弹窗的 `taskModelPushError` 展示。
- 任务发送失败已经由 `TaskModelPushPendingWorkspace` 在对应会话中展示错误原因和“重试发送”。
- `openTaskModelPush()` 与 `dispatchTaskModelPush()` 又分别调用 `recordLocalError()`，造成同一任务推送错误重复进入全局顶部。

## 用户确认的领域边界

1. 任务推送失败是局部可恢复错误，不是应用全局故障。
2. 推送能力加载失败只留在推送弹窗。
3. 任务发送失败只留在对应失败会话，并保留错误原因与“重试发送”。
4. 重试开始时清除旧局部错误；成功后进入真实会话。
5. 其他本地操作的全局错误机制不在本次修改范围内。

## 方案与取舍

### 采用任务推送错误全部局部化

优点：错误与恢复动作位于同一操作面；避免重复提示；切换到其他页面后不再被已离开的任务错误持续打断。

缺点：用户离开失败会话后，不会再收到跨页面的持续提醒，需要回到该会话查看和重试。

### 未采用顶部条增加关闭按钮或自动超时

优点：可以保留跨页面提醒，并让用户手动关闭或等待自动消失。

缺点：任务推送错误仍与局部错误重复；超时时长难以代表问题是否已解决；关闭按钮只是清理展示，没有提供恢复动作。

### 未扩展到全部全局错误

优点：避免一次小修改变其他操作失败的产品语义，范围可控。

缺点：其他业务如果也重复调用 `recordLocalError()`，仍需后续按各自恢复边界单独梳理。

## 实现记录

- `openTaskModelPush()` 的能力加载失败只更新弹窗状态，不再调用 `recordLocalError()`。
- `dispatchTaskModelPush()` 的发送失败只更新失败会话状态，不再调用 `recordLocalError()`。
- 保留现有弹窗错误、失败会话错误、脱敏处理和重试逻辑。

## 验收要求

- 推送能力加载失败时，错误只出现在推送弹窗，不出现工作区顶部全局错误条。
- 任务发送失败时，错误只出现在对应会话，并可通过“重试发送”恢复。
- 重试开始后旧错误消失；成功后进入真实会话。
- 其他调用 `recordLocalError()` 的操作行为保持不变。
- 完成 `pnpm lint`、`pnpm typecheck`、`pnpm build` 与 `git diff --check`；静态检查和构建成功不冒充真实运行验收。
