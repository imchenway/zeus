# ZEUS-000044 任务完成状态不强制代码交付

## 用户问题

任务状态变更为“已完成”时，为什么会弹出代码交付弹窗，并且必须“放弃分支”或“提交并推送”后才能完成状态修改。

## 当前阶段

实现与静态、构建及隔离 Git 生命周期验证已完成；尚未进行带真实任务数据的桌面点击验收。

## 现状与根因

当前行为不是偶发界面问题，而是前端和服务端共同实现的一条旧规则：

- Renderer 在任务管理状态切换到 `completed` 或 `cancelled` 时，直接打开 `TaskGitReviewModal`，不先提交状态修改。
- 弹窗把未关闭的任务开发线引导到“提交并推送”“确认无变更并回收”或“放弃分支”。
- 即使调用方绕过弹窗，服务端仍会检查任务开发线；只要存在非 `reclaimed / merged / discarded` 状态，就返回 `ZEUS_TASK_GIT_DISPOSITION_REQUIRED`。

这条规则来自 2026-07-31 的早期任务终态设计，目的是避免任务标记完成后遗留仍可写的 worktree 和未处置代码。

## 与当前领域规则的冲突

仓库后续已经明确：

- “任务管理状态”只表达工作推进阶段，不是 Git 权限。
- “任务开发线”可以在任务管理状态变化前后继续处置。
- 代码提交、代码推送、代码交付准备和代码交付都应由用户显式触发，不能由任务状态变化隐式启动。

因此，当前弹窗与服务端终态门禁属于旧规则残留；它把“任务管理完成”和“代码开发线处置完成”错误合并成一个动作。

## 待确认的产品决策

推荐边界：任务状态可以直接改为“已完成”或“已取消”，不弹出代码交付弹窗，也不要求提交、推送、回收或放弃分支；任务详情继续独立展示未处置开发线，并由用户从“代码交付”区域显式处理。

优点：状态语义清楚，非代码任务、阶段性完成、暂存分支和稍后交付都不会被 Git 流程阻断。

缺点：已完成任务可能仍保留可写 worktree 或未提交代码，需要在任务详情和任务列表中持续显示“开发线待处置”，避免遗忘和磁盘占用。

## 第二轮边界澄清：任务完成后的 worktree

用户提出：任务完成后应移除 worktree 相关内容。

当前实现中存在两个不同动作：

- “回收 worktree”删除物理 worktree 目录和 Git worktree 登记，但保留任务分支、远端分支和 Zeus 开发线记录；当前只允许在工作区干净，且代码无变化或远端已经精确包含本地 HEAD 时执行。
- “放弃分支”会强制删除物理 worktree 和本地任务分支，远端分支仍保留；这是破坏性更强的明确放弃动作。

建议把“任务完成后的清理目标”定义为回收物理 worktree，而不是删除任务分支或交付记录。需要继续确认的异常边界是：当 worktree 仍有未提交变化、冲突或活动会话时，任务状态应被阻断，还是先完成并把该开发线标记为“待回收”。

## 第三轮用户反馈

用户否决新增“开发线待回收”状态，要求任务完成时直接删除 worktree，不增加额外生命周期概念。

当前只剩破坏性边界待确认：Git 强制移除脏 worktree 会永久删除未提交和未跟踪文件；本地任务分支只能保留已经提交的内容，不能恢复这些文件。需要明确任务完成是否授权这种不可恢复删除。

## 已确认的终态清理语义

用户明确确认：任务标记为“已完成”和“已取消”都采用同一规则。干净的物理 worktree 直接删除；存在未提交或未跟踪内容时只给一次危险询问，用户确认后强制删除，用户取消则不修改任务状态。不弹出代码交付弹窗，不新增“待回收”状态。

任务分支、远端分支和 Zeus 的开发线及交付记录继续保留；本任务所说的“删除”只针对物理 worktree 目录及 Git worktree 登记。

尚待确认：仍有活动会话可能写入 worktree 时，是否先停止会话再删除。

## 最终确认

- “已完成”和“已取消”采用同一套任务终态清理。
- 干净且没有活动会话时直接回收物理 worktree。
- 存在未提交、未跟踪内容、冲突或活动会话时，只显示一次危险询问；用户确认后继续，取消则任务状态保持不变。
- 确认继续后停止活动会话，并把该任务关联的 Codex 会话与 Runtime 会话归档。
- 归档保留会话消息历史；清理保留本地任务分支、远端分支、Zeus 开发线记录和代码交付记录。
- 不再弹出代码交付审查窗口，不要求用户提交、推送或放弃分支，也不新增“待回收”状态。

优点：任务终态动作清晰，worktree 和会话不会长期占用活动空间，代码交付仍可独立进行。

缺点：用户确认危险询问后，worktree 中尚未提交和未跟踪的内容不可恢复；因此询问必须明确说明永久删除范围。

## 实现结果

- Renderer 不再把 `completed / cancelled` 路由到 `TaskGitReviewModal`，并移除了提交审查弹窗中的任务终态模式。
- 任务状态接口先检查任务版本，再检查所有任务 worktree、Codex 会话和 Runtime 会话。
- worktree 干净且没有活动会话时，服务端直接执行终态清理并保存任务状态。
- 存在本机变化、检查失败或活动会话时，服务端返回 `ZEUS_TASK_WORKTREE_CLEANUP_CONFIRMATION_REQUIRED`；Renderer 使用一次系统危险确认询问，确认后携带显式清理授权重试。
- 终态清理会停止活动 Codex 轮次与 Runtime 会话，取消尚未执行的提交请求，归档该任务的全部未归档会话。
- 物理 worktree 通过精确的 Git worktree 登记路径删除；确认后允许强制删除脏目录。本地任务分支和远端分支不会删除。
- TaskWorkspace 保留并进入 `reclaimed`，已合入或已放弃记录继续保持原状态；多仓任务环境在所有成员清理后回收聚合目录。
- 批量状态修改复用同一终态逻辑，不再绕过确认门禁。
