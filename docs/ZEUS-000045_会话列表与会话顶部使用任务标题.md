# ZEUS-000045 会话列表与会话顶部使用任务标题

## 当前阶段

已完成实现、静态检查、构建、隔离测试包打包与真实界面验收。

## 任务目标

- 任务会话在左侧会话列表中只显示所属任务标题，不显示任务编码。
- 任务会话在右侧会话工作区顶部只显示所属任务标题，不再显示会话自身标题与重复任务副标题。
- 右侧任务标题可点击和键盘操作，打开现有任务详情抽屉；当前会话、消息和输入现场保持不变。
- 项目自由对话继续显示自身会话标题，不伪造任务归属。

## 用户确认

- 同一任务关联多个会话时，列表和会话顶部仍严格只显示任务标题，允许出现同名会话。
- 任务编码不作为会话列表或会话顶部的可见标题。
- 项目自由对话不受任务标题规则影响。

## 源码事实

- `ProjectConversationTree.flattenProjectConversations()` 当前把任务编码和任务标题拼接成任务会话的列表标题。
- `createSessionHeaderSnapshot()` 当前把会话记录标题作为主标题，把任务标题作为第二行上下文。
- `App.tsx` 已有 `openTaskDetailPane()` 和任务详情 `WorkspaceDrawer`，可以在会话页复用，不需要新建详情页面或跳转任务页。
- 一个任务可以关联多个会话，因此只显示任务标题会牺牲同任务多会话的文字区分度；用户已明确接受。

## 实现范围

1. 任务会话列表展示标题改为任务标题；项目自由对话保持会话标题。
2. 任务会话顶部主标题改为任务标题，并移除重复副标题；项目自由对话保持现有标题与项目上下文。
3. 为任务会话顶部标题增加明确按钮语义、可见焦点和点击回调，复用现有任务详情抽屉。
4. 补齐中英文可访问名称，不新增单元测试、组件测试或 DOM/CSS 契约测试。

## 取舍

- 优点：任务会话两处标题一致，任务编码不再抢占列表宽度；用户可从会话现场直接查看任务详情。
- 缺点：同一任务的多条会话会显示相同标题，只能结合状态、选中位置和内容判断具体会话。
- 不采用“任务标题 + 会话副标题”：更容易区分多会话，但不符合用户确认的“只显示任务标题”。
- 不采用点击后跳转任务页：实现更简单，但会打断当前会话阅读与输入现场，也不符合“打开任务详情抽屉”。

## 验收口径

- 任务会话列表行不再出现 `ZEUS-000045` 这类任务编码，只显示任务标题。
- 任务会话顶部只出现一次任务标题，不显示“任务会话：”等会话自身标题。
- 鼠标点击或键盘激活顶部任务标题后，在当前会话页打开对应任务详情抽屉。
- 关闭抽屉后仍停留在原会话，原消息与输入内容不丢失。
- 项目自由对话仍显示自身会话标题，标题不可误开任务详情。
- `pnpm lint`、`pnpm typecheck`、`pnpm build` 通过；静态检查与构建结果不冒充真实界面验收。
