# ZEUS-000047 推送分支创建 worktree 目录与任务编码一致

## 任务信息

- 任务标题：推送分支创建 worktree 的目录名称是否可以和任务编码一致？
- 任务描述：未提供。
- 任务编码：`ZEUS-000047`。

## 现场事实

当前新任务推送生成的路径为：

```text
.zeus-worktrees/<项目>/<任务编码>/<内部工作区短标识>
```

例如本任务当前历史目录是：

```text
.zeus-worktrees/zeus-e2e-oBLuqT/ZEUS-000047/b033ee19e465cb9bfdbe
```

因此路径已经包含任务编码，但会话 cwd 的最后一级仍是内部短标识。旧推送弹窗还允许复用既有任务环境，这与本任务确认的重复推送语义冲突。

## 已确认规则

1. 会话 cwd 的最后一级必须与任务编码一致，例如 `ZEUS-000047`。
2. 同一任务每次推送都按首次推送的完整流程处理，创建独立会话、独立任务分支和独立 worktree。
3. 第二次推送只读取本次选择的来源分支和提交，不读取、不继承、也不依赖第一次推送的分支或未提交内容。
4. 重复推送允许并行，因为它们使用彼此隔离的工作区和分支。
5. 新路径采用 `.zeus-worktrees/<项目>/<推送标识>/<任务编码>`；唯一推送标识负责隔离，任务编码负责 cwd 可读性。
6. 已经创建并被历史会话引用的旧格式 worktree 不迁移；新规则只影响升级后的新推送。

## 优缺点

### 优点

- 终端和会话顶部看到的 cwd 可以直接对应任务编码。
- 重复推送互不读取对方的分支与未提交修改，可以安全并行。
- 唯一推送标识仍然避免同一项目、同一任务重复推送时发生物理目录冲突。
- 不迁移旧目录，避免破坏运行中会话、Git worktree 登记和持久恢复记录。

### 代价

- 同一任务会产生多条独立开发线，需要在代码交付时分别审查和合入。
- 重复推送会占用额外磁盘空间。
- 升级后的过渡期内，历史会话与新会话会同时存在两种路径结构。

## 实现范围

- 调整新推送工作区根路径，使任务编码成为最后一级目录。
- 推送弹窗不再提供复用既有任务环境；每次推送都要求重新选择来源分支并创建新分支。
- 服务端任务首发拒绝客户端请求复用既有任务环境，但保留同一次幂等重试对已预留工作区的内部恢复。
- 更新领域词汇、设计契约和相关代码注释。
- 不移动、不重命名、不删除任何已有 worktree。
