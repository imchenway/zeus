# ZEUS-000048 答案选项自定义输入崩溃

## 任务目标

修复普通用户询问中启用“其他回答”后，键盘输入自定义答案会让 Zeus 界面崩溃的问题。

## 领域边界

- “普通用户询问”是 app-server 的 `request_user_input`，不是会话普通消息输入框。
- “自定义答案入口”是同一问题的 Other 回答方式；输入内容仍作为当前问题答案提交，不创建普通用户消息。
- 本次不改变选项选择、跳过、自动解决、敏感回答和服务端响应格式。

## 真实复现

1. 从当前源码执行 `pnpm package:mac`，生成独立身份的 `dist/test/mac-arm64/Zeus Test.app`，bundle ID 为 `dev.hypha.zeus.test`。
2. 在测试应用中创建真实 Codex 会话，让 provider 发出带 Other 的 `request_user_input`。
3. 点击“其他回答”后输入框正常启用。
4. 键盘输入有效字符后，Renderer 立即进入“界面已安全暂停 / Zeus 遇到界面错误”；Main 与执行宿主进程仍存活。

## 根因

`PendingRequestSurface.tsx` 的四条输入路径都在 React 状态更新函数中延迟读取 `event.currentTarget.value`。事件分发结束后 `currentTarget` 会被清空，状态更新执行时再读取 `.value` 会触发界面异常。

受影响路径：

- 普通 Other 文本域；
- 敏感 Other 输入框；
- 普通纯自由输入问题；
- 敏感纯自由输入问题。

## 修复方案

每个输入事件先同步读取并保存字符串值，再把该字符串传入状态更新函数。保留函数式状态更新，避免连续键盘输入覆盖前一轮草稿。

优点：

- 直接覆盖四条同源崩溃路径；
- 不改变请求协议、答案语义和服务端校验；
- 修改范围小，便于真实应用复验。

缺点：

- 只修复已复现的输入事件生命周期问题，不重构整个交互面板；
- 仍需打包后的真实键盘输入与提交闭环证明运行结果。
