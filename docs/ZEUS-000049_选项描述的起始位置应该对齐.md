# ZEUS-000049 选项描述的起始位置应该对齐

## 当前阶段

实现与同图视觉校验完成。

## 任务目标

整理普通用户询问面板的答案布局，直接复现 Codex App 已有的文字基线、行高和底部无边框输入节奏，解决主描述未垂直居中和底部输入框突兀的问题。

## 最终口径

- 用户补充的 Codex App 截图是本任务视觉事实，取代此前“固定描述列、所有普通行严格等高”的推导方案。
- 主描述、推荐标记和补充说明沿同一文字基线自然接排；没有推荐标记时不预留空槽。
- 普通答案使用一致的 `44px` 最小行高，长内容自然撑高，不用最长答案强行拉高其他答案。
- 编号、整组答案文案和右侧反馈图标按各自行中线垂直居中。
- 自定义回答是无边框的一行输入，初始高度与普通答案的 `44px` 最小节奏一致；选中并输入多行后允许继续增高。
- 本次只修改普通用户询问面板，不改变计划实施确认等其他交互卡。

## 实现记录

- 普通答案继续直接使用面板既有的 `2px` 网格间距，不新增等高容器或额外布局层。
- 恢复答案文案的弹性换行布局：主描述、推荐标记和补充说明按基线接排，说明可占用剩余空间并自然换行。
- 普通答案和自定义回答行使用一致的 `44px` 最小高度；自定义回答文本域以 `30px` 控件高度起步，由外层负责与普通答案对齐。
- 自定义回答输入显式去除阴影；禁用态保持完整不透明度和弱化文字色，复现 Codex App 的无边框占位文字。
- 自定义回答继续复用会话现有的自适应高度能力，多行内容增长到窗口高度的 `24%` 后转为内部滚动。
- 首轮真实输入检查暴露了既有事件生命周期问题：自定义回答和自由输入在函数式状态更新中继续读取界面事件，可能触发错误边界；现已改为先同步取值、再更新草稿。

## 方案取舍

- 自然接排的优点是与 Codex App 一致、文字关系紧密且没有无意义空槽；代价是不同选项的补充说明不会形成绝对垂直列。
- 内容驱动行高的优点是短答案紧凑、长答案不裁切；代价是长短答案不会严格等高。
- 自定义回答行允许内容驱动增高，可以避免长输入被裁切；代价是输入多行后不再与普通答案保持同高。
