# ZEUS-000050 对话进行中也可以修改配置项

## 任务状态

已完成代码实施、静态检查、构建、打包、持久化冒烟验证和真实 `Zeus Test.app` 关键链路验收。

## 原始要求

对话进行中也需要可以修改会话输入区里的模型、推理强度、服务档位、权限模式和计划模式。

## 已确认口径

- 五个控件在可继续的 Codex 原生会话中始终可以修改，包括正在响应、等待授权、等待用户回答、断线和恢复异常现场。
- 修改不影响已经开始执行的当前轮，只影响尚未开始执行的轮次。
- 已排队但尚未开始执行的消息不保留入队时旧配置，开始执行时统一采用会话最新配置。
- 下一轮配置按会话永久保存，切换会话、断线和重启 Zeus 后仍保留。
- 只读导入旧会话没有下一轮，继续保持不可修改。
- 界面只更新控件选择，不额外增加“下一轮生效”提示。

## 领域定义

- **当前轮配置**：当前轮开始时运行服务已经采用的五项配置，执行期间不热切换。
- **下一轮配置**：用户为会话最后选择并持久保留的五项配置，所有尚未开始轮次在启动时读取最新值。
- **尚未开始轮次**：已经排队或将在之后提交、但运行服务尚未开始执行的轮次。

## 取舍

### 下一轮统一生效

- 优点：不会中途更换模型、权限或计划模式，当前执行结果可追溯。
- 缺点：用户无法用配置控件改变已经生成中的响应；需要停止后重新提交才可能改变当前工作。

### 排队消息统一采用最新配置

- 优点：修改一次即可覆盖所有尚未执行的消息，符合“会话下一轮配置”的直觉。
- 缺点：排队消息不再保留入队时选择，必须以真正开始执行时的会话配置为准。

### 仅更新控件，不显示生效提示

- 优点：输入区保持简洁，不增加额外状态文案。
- 缺点：用户可能误以为正在执行的当前轮已经切换配置；这是本任务明确接受的产品取舍。

## 实施范围

- 为会话增加可持久化的下一轮配置。
- 让五个配置控件不再因运行、等待、断线或恢复异常而禁用。
- 新提交与尚未执行队列在真正开始执行时读取会话最新配置。
- 保持当前活动轮次不停止、不回滚、不重发。
- 更新本文档并记录静态、构建、打包与真实运行验证结果。

## 非目标

- 不支持当前活动轮次热切换配置。
- 不为只读导入旧会话提供无法生效的配置编辑。
- 不新增或恢复 Vitest、组件测试、DOM/CSS 契约测试及相关产物。
- 不执行 git commit、push、merge、revert 等修改历史或远端动作。

## 实施结果

### 会话持久化

- 会话表新增“下一轮配置”字段，完整保存模型、推理强度、服务档位、权限模式和计划模式。
- 新增数据库迁移，旧会话继续可用，第一次读取时从已有会话状态补齐默认值。
- 界面同时保留按会话分隔的本地备份，断线时修改也不会被旧快照覆盖，恢复连接后再同步给服务端。

### 队列生效时机

- 发送和排队时仍记录当时请求，但真正开始执行前会重新读取该会话最新配置。
- 正在进行的当前轮不修改内存中的执行上下文，不停止、不重发、不热切换。
- 断线或重启后恢复正在进行的轮次时，优先使用该活动轮次原本的配置，避免“下一轮配置”误污染当前轮。

### 界面交互

- 响应中、等待授权、等待用户回答、断线和恢复异常时，五个配置控件不再因当前轮状态被禁用。
- 待处理的用户问题或授权保留在会话上方，不再整块替换输入区；消息文本输入继续锁定，五项配置仍可修改。
- 只读导入的旧会话仍不提供无法生效的修改。
- 按已确认产品口径，没有新增“下一轮生效”提示文案。
