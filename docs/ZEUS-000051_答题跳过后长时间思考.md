# ZEUS-000051 答题跳过后长时间思考

## 问题

会话中的 `request_user_input` 选项卡点击“跳过”后，卡片虽然消失，但界面可能长期停留在“正在思考”。同时，“已处理”时长把用户等待选择的时间也算成模型处理时间，造成 Codex 持续思考一小时以上的错误观感。

## 现场证据

- Zeus 向 Codex 回填的跳过结果为 `{"answers":{}}`，与当前 Codex App 的空回答语义一致；跳过不等于终止轮次，也不自动选择推荐项。
- 现场 provider thread `019fcb58-db2b-7ff2-a874-22ef109c7611` 在 `2026-08-04T07:17:15.558Z` 收到空回答，随后在 `2026-08-04T07:17:35.893Z` 完成，跳过后的真实处理时间约为 20 秒。
- Zeus 数据库已经保存跳过后的 reasoning、command、final answer 和 completed turn，说明 Codex 与持久化链路能够完成；长时间“正在思考”来自 Renderer 实时状态没有及时与执行宿主重新对账。
- 原界面时长直接使用 `turn.completedAt 或当前时间 - turn.startedAt`，没有扣除请求创建到解决之间的外部等待区间。

## 领域口径

- **跳过**：本次问题不提供答案，向 Codex 提交空 `answers`。
- **请求解除**：提问不再阻塞当前轮次，但当前轮次仍然存在。
- **轮次继续**：继续接收同一 provider turn 的 reasoning、item 与最终完成事件。
- **处理时长**：模型实际可工作的轮次时长，不包含等待用户回答或审批的区间。

## 实现

1. 请求回答成功后，Renderer 立即把请求标记为已解决。
2. 主动重建本机事件 WebSocket，并按既有“先连接、后读取快照、连接期间缓冲事件”的流程读取一次权威会话快照。
3. 后续仍由同一事件流接收当前轮次内容，直到 `conversation.turn.completed` 收口。
4. 轮次时长合并同一轮的所有请求等待区间，避免重叠请求被重复扣减，再从总时长中扣除。

## 优缺点

优点：

- 用户可见行为与 Codex App 一致：跳过后继续当前轮次，不伪造选择，不永久停在思考态。
- 即使用户等待期间本机 WebSocket 已经半失活，回答动作也会建立一条新的可靠事件流。
- 历史轮次与当前轮次的处理时长都不再把人工等待误报为模型计算。

代价：

- 每次回答阻塞请求后会发生一次本机 WebSocket 重连和会话快照读取，增加一次很小的本机请求开销。
- 该修复保证 Zeus 界面与本机执行宿主收敛；Codex 自身仍可能在空回答后继续提问，这是空回答的正常语义，不应被 Zeus 自动改成推荐答案。

## 验收口径

- 点击“跳过”发送空 `answers`，不发送推荐项。
- 请求卡片立即消失，界面进入同一轮继续处理状态。
- 跳过后的 reasoning、工具活动、最终回复和完成状态能够自动出现，无需切换会话或重启应用。
- 长时间停留在问题卡片期间，“已处理”时长不继续累计该等待区间。
- 执行 `pnpm lint`、`pnpm typecheck`、`pnpm build` 和 `pnpm package:mac`，并仅使用独立身份的 `Zeus Test.app` 做真实交互验证。

## 本次验证结果

- `pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac` 均已通过。
- 测试包为 `dist/test/mac-arm64/Zeus Test.app`，bundle ID 为 `dev.hypha.zeus.test`，并通过 `codesign --verify --deep --strict`。
