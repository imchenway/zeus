# ZEUS-000052 文件内容自动软换行显示

## 当前结论

任务代码差异视图中的长行被强制保持单行，同时左右内容栏各自保留固定最低宽度。当代码交付弹窗被任务分支栏和操作栏压窄时，长文本会横向伸展并覆盖另一侧内容。

本任务统一修复“代码交付”和“提交审查”中的左右代码差异：长行只在各自内容栏内自动软换行，连续中文、URL 和其他无空格长串允许在任意字符处断行；视觉换行不改变文件真实内容、源码行号或左右差异对应关系。

## 用户确认

- 统一覆盖代码交付和提交审查，不只修复截图中的单一入口。
- 左右内容分别在自身栏宽内自动软换行，同一条差异保持左右等高。
- 行号只显示一次，软换行后的延续内容不重复行号。
- 连续中文、URL 或其他无空格长串允许在任意字符处视觉断行。
- 所有换行仅影响显示，不写回文件内容。

## 根因证据

- `task-git-review-diff-table` 设置了 `760px` 最低宽度，窄空间下必须横向溢出。
- 每个左右内容栏设置了 `330px` 最低宽度，无法随弹窗剩余空间继续收缩。
- 差异行所有单元格使用 `white-space: pre`，明确禁止自动换行。
- 代码交付和提交审查使用相同样式，因此问题会在两个入口同时出现。

## 实现边界

1. 差异表允许收缩到当前可用宽度，左右内容栏平均使用剩余空间。
2. 代码内容保留原始空白，同时允许软换行和连续字符断行。
3. 行号栏保持固定宽度，不参与连续字符断行。
4. 同一差异行继续使用同一个网格行，任一侧换行后另一侧背景与行高同步延展。
5. 不修改差异数据、Git 操作、提交或合入流程。

## 优缺点

优点：

- 长文本不再覆盖另一侧内容，左右差异可以在当前窗口直接阅读。
- 两个任务代码差异入口保持一致，不遗留同类问题。
- 不改变文件内容和 Git 结果，风险集中在展示层。

缺点与代价：

- 超长源码行会占用更多纵向空间，需要增加向下滚动。
- 视觉换行后的代码不再严格保持“一条源码行只占一条屏幕行”，但行号与左右对应关系仍保留。
