# ZEUS-000053 代码对比高亮与冲突快捷处理

## 任务目标

修复 Zeus 合入冲突窗口只有三栏纯文本、缺少差异高亮和逐块快捷处理的问题，并移除含义不清且会让模型整文件改写的“请 Codex 协助”。

## 已确认范围

1. 目标分支、合并结果和任务分支三栏都提供代码语法着色。
2. 新增、删除、修改和未解决冲突使用低饱和语义色直接标出。
3. 每个未解决冲突块分别提供“采用目标”“采用任务”“两者都采用”，只改变当前块。
4. 工具栏提供魔法笔入口，只处理当前文件中能从共同基线确定为互不覆盖的简单冲突。
5. 魔法笔无法可靠处理的冲突继续保留，交给用户逐块选择或手工编辑。
6. 删除“请 Codex 协助”及后台临时 Codex 会话路径；确定性冲突处理不调用模型。
7. 所有编辑都先进入中间结果，只有用户点击“保存结果并继续”后才写入文件并加入 Git 暂存区。

## 产品边界

### 简单冲突自动合并

简单冲突指两侧对共同基线的修改可以证明互不覆盖，例如同一行的开头和结尾分别被修改。魔法笔可以确定地组合这两处修改；两侧改到同一位置且结果不同、代码语义需要判断或缺少共同基线时，不自动选择。

优点：结果可解释、可复核，不会把模型猜测伪装成 Git 的确定结果。

代价：复杂业务冲突仍需用户处理，无法承诺“一键解决全部”。

### 冲突块选择

逐块动作只替换一个冲突标记区，不再使用顶部整文件覆盖按钮。每个块保留目标、任务和两者三种明确选择，并能定位到中间编辑结果中的对应位置。

优点：不会因为解决一个小冲突而覆盖同文件中已经手工整理的其他内容。

代价：冲突块很多时需要逐项确认，因此必须提供清晰计数、定位和已解决反馈。

## 验收要求

- 三栏代码具有可见语法着色，目标与任务相对共同基线的变化行具有差异底色。
- 中间结果中的未解决冲突块有独立底色和逐块快捷动作。
- 魔法笔只修改当前文件，并报告自动解决数量与剩余数量。
- 无法确定的冲突块不会被自动采用任一侧。
- 手工编辑、逐块选择和魔法笔都不会在点击保存前写入工作区。
- 窗口中不再出现“请 Codex 协助”，服务端不再启动临时 Codex 冲突会话。
- 完成 `pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac`，并使用独立身份的 `Zeus Test.app` 做真实界面检查；构建成功不等于界面验收完成。

## 当前状态

代码实现、目标文件静态检查和补充组件交互验证已完成。当前任务基线自身仍保留 3 个源文件中的 Git 冲突标记，因此完整项目构建、`Zeus Test.app` 打包和真实应用验收被基线阻断；本任务没有擅自替其他任务选择冲突内容。

## 实现结果

- 新增三栏代码展示与编辑组件，统一显示行号、语法着色以及新增、修改、冲突行底色。
- 中间结果保留完整手工编辑能力；高亮层延后更新，输入本身不等待大段代码重新计算。
- 每个冲突块提供独立定位和“采用目标 / 采用任务 / 两者都采用”，操作后只替换该块。
- 新增魔法笔动作“合并简单冲突”。它基于冲突块中的共同基线执行字符级非重叠修改组合；旧冲突结果没有内嵌共同基线时，会从完整共同基线中唯一匹配，无法唯一证明时保持未解决。
- 新创建的 Git 合入冲突显式使用 `diff3` 格式，确保结果中包含共同基线并兼容较广的 Git 版本。
- 当前文件仍有冲突标记时禁用“保存结果并继续”；全部处理后才允许写入文件和 Git 暂存区。
- 删除渲染层“请 Codex 协助”、客户端方法和服务端临时 Codex 会话接口，冲突确定性合并不再依赖模型。
