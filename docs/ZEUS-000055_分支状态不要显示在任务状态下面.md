# ZEUS-000055 分支状态不要显示在任务状态下面

## 任务目标

任务列表的“任务状态”单元格只展示任务管理状态，不再在下方混排“开发分支进行中”“分支已推送”“代码已合入”或“Git 待处理”等任务开发线状态。

## 已确认边界

- 移除任务列表“任务状态”单元格下方的任务开发线状态，并新增独立“分支状态”列承载该信息。
- 任务管理状态下拉、独立运行状态列、任务详情和代码交付区域保持原样。
- 不删除任务开发线数据，不改变 Git 生命周期、任务状态排序或任务状态保存逻辑。
- “分支状态”默认位于“任务状态”和“运行状态”之间；默认布局自动显示，已有自定义布局不强制显示，可从“自定义列”开启。
- 同一任务存在多条开发线时按“Git 待处理、开发中、已推送待合入、已合入、已放弃”的关注顺序汇总；没有开发线时显示“未创建”。

优点：任务列表恢复单一语义和单行状态展示，用户不会把 Git 生命周期误认为任务管理状态，同时仍可直接扫描分支进度。

缺点：多开发线任务在列表中只展示最需关注的汇总状态，用户仍需进入任务详情或代码交付区域查看每条开发线。

## 领域说明

“任务管理状态”表示工作推进阶段；“任务开发线状态”表示任务分支、worktree 和代码交付所处阶段。两者是独立事实，分别使用“任务状态”和“分支状态”列展示。

仓库 `CONTEXT.md` 已补充“任务开发线状态”定义；该展示决策可通过列设置调整，不需要架构决策记录。

## 实现记录

- 移除任务列表模型向 `managementStatus.secondary` 写入任务开发线摘要的逻辑。
- 新增 `branchStatus` 列键、默认宽度、中英文列名、状态标签、语义色和固定关注顺序排序。
- Renderer 与本机设置服务同步支持新列，并区分默认布局迁移和已有自定义布局。
- 通用单元格第二行能力继续保留，避免影响运行会话等其他字段。
