# ZEUS-000056 P 应该显示大写且点击可修改

## 当前阶段

需求口径和源码实现已完成。定向代码规范、定向类型检查与差异检查通过；完整检查、构建、打包和真实界面验收被当前 worktree 中与本任务无关的既有 Git 冲突标记阻断。

## 用户反馈

- 任务表格“优先级”列把 `p3` 直接显示成小写，应该显示为大写 `P3`。
- 点击优先级后需要可以直接修改。

## 已确认口径

- 任务表格中的正式优先级常态只显示紧凑的大写 `P0` 至 `P4`。
- 点击优先级单元格后，在表格内展开 P0 至 P4 的完整含义，选择后立即保存，不打开任务详情抽屉。
- 历史 `normal` 不迁移、不冒充 P3，常态显示“历史值”，仍可点击改成正式优先级。
- 保存过程必须真实显示保存中、已保存、失败或冲突；失败和冲突保留用户选择，并提供重试或载入最新值。
- 优先级只表达任务相对处理顺序，不自动启动 AI、会话或执行轮次。

## 方案比较

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 点击后打开任务详情 | 复用已有详情编辑入口 | 修改一次优先级需要切换上下文，和用户指出的表格入口不一致 | 不采用 |
| 表格内显示完整优先级含义 | 信息完整 | 需要扩大列宽，破坏任务表格的信息密度 | 不采用 |
| 表格内显示短值并展开完整下拉 | 常态紧凑，修改路径短，和任务状态列一致 | 需要把任务内容更新与冲突反馈接入表格 | 采用 |
| 把历史 `normal` 显示为 P3 | 视觉统一 | 未保存前会伪造真实数据 | 不采用 |

## 源码事实

- 任务表格当前直接渲染 `task.priority`，因此数据库值 `p3` 被原样显示为小写。
- 优先级单元格当前只是静态标签，点击会冒泡并打开整行对应的任务详情。
- 任务详情已经具备 P0 至 P4 下拉、立即保存、`updatedAt` 并发校验、失败重试和冲突处理能力。
- `App.tsx` 已有统一的 `updateTaskContent` 更新协调器，可以把成功结果合并回任务表格快照。
- 当前工作区已有 `ConversationResources.tsx` 和 `ThreadItemView.tsx` 两处与本任务无关的修改，本任务必须保持原样。

## 实现计划

1. 为任务表格增加优先级选项、可访问名称和内容更新回调。
2. 正式优先级触发器只显示大写短值，展开列表显示完整含义；历史值显示“历史值”。
3. 复用统一任务内容更新入口，补齐保存中、已保存、失败、冲突、重试和载入最新值。
4. 阻止优先级控件点击冒泡，避免修改时同时打开任务详情。
5. 执行 `pnpm lint`、`pnpm typecheck`、`pnpm build`、`git diff --check`，再只生成并启动独立身份的 `Zeus Test.app` 做真实界面验收。

## 实际实现

- 任务表格优先级从静态标签改为表格内下拉，控件点击会停止冒泡，不再同时打开任务详情。
- 正式值在触发器中显示为大写 `P0` 至 `P4`；展开层继续显示完整含义，并设置独立最小宽度，避免被紧凑任务列裁掉。
- 历史 `normal` 常态显示“历史值”，下拉中的历史选项只读，用户仍可选择任一正式优先级完成更新。
- 表格复用 `App.tsx` 的统一任务内容更新协调器，提交真实 `priority + expectedUpdatedAt`，成功后同步任务快照。
- 单元格覆盖保存中、已保存、失败和冲突；失败保留用户选择并提供重试，冲突提供重试和载入最新值。
- `ZeusSelect` 新增独立触发器文案、可访问描述和展开层最小宽度能力；选项事实值与完整文案保持不变。
- `CONTEXT.md` 把 P0 收紧为“应最先处理”，消除“立即开始处理”和“不自动启动”之间的歧义。
