# ZEUS-000059 点击运行状态应该直接进入对应的会话

## 当前阶段

已完成源码与文档实现；本任务 TypeScript 文件的格式、ESLint、定向类型检查和差异检查通过。仓库基线存在已提交的未解决合并标记，全量 lint、类型检查、构建、测试包打包和真实界面验收被阻断，当前不能描述为完整验收通过。

## 任务目标

任务表中的运行状态不再只是只读标签。只要当前状态来自真实关联会话，用户点击状态胶囊即可直接进入该会话，不必先打开任务详情再查找会话。

## 用户确认

- 除“未启动”外，所有存在真实关联会话的运行状态都可以点击。
- 同一任务关联多个会话时，打开当前运行状态所依据的最近更新会话。
- 只有运行状态胶囊进入会话；任务行其他区域继续打开任务详情。
- 运行状态入口同时支持鼠标和键盘操作，并显示可见焦点。
- “未启动”没有对应会话，继续显示为普通状态，不自动创建新会话。

## 源码事实

- 任务运行状态由 `resolveTaskAgentRunStatus()` 从任务最近更新的关联会话派生；实时状态优先于持久化会话状态。
- 任务表当前整行点击打开任务详情，运行状态只是 `span`，没有独立交互语义。
- `App.tsx` 已有 `openTaskConversation()`，能够选择准确会话、切换到会话页、关闭任务详情层并保留既有会话加载逻辑。

## 实现设计

1. 让运行状态解析同时暴露其所依据的最近关联会话，状态显示和跳转共用同一事实。
2. 有对应会话时把运行状态胶囊渲染为原生按钮；点击时阻止任务行事件并调用既有会话打开路径。
3. 没有对应会话时继续渲染普通状态胶囊。
4. 补齐中英文可访问名称、鼠标指针、悬停和键盘焦点反馈。

## 取舍

- 优点：从任务表一步进入正在运行、等待处理、空闲、失败、暂停或历史只读会话；显示状态与打开对象来自同一规则，不会错跳。
- 缺点：一行内增加第二个操作目标，用户需要通过悬停、焦点和按钮语义区分“打开会话”与“打开任务详情”。
- 不采用整行进入会话：会破坏任务表既有的任务详情主路径。
- 不采用只让活动状态可点击：空闲、失败和历史只读状态仍然对应真实会话，限制点击会让规则不一致。

## 验收口径

- “运行中”“等待用户回复”“等待授权”“等待新指令”“运行失败”“已暂停”和“历史只读”等有会话状态均可直接打开准确会话。
- 同一任务有多条会话时，打开的会话与当前运行状态使用的最近更新时间规则一致。
- 点击运行状态不会同时打开任务详情。
- 点击任务行其他区域仍打开任务详情。
- “未启动”不可点击，不创建新会话。
- 键盘可以聚焦并激活运行状态入口，焦点清晰可见。
- 不新增或恢复单元测试、组件测试、DOM/CSS 契约测试和 TDD 流程。
- 静态检查、构建、测试身份打包与真实界面验收分别记录，不互相冒充。

## 实现结果

- `taskWorkspaceModel.ts` 新增运行状态来源会话解析，状态文字与跳转目标共用最近更新时间规则。
