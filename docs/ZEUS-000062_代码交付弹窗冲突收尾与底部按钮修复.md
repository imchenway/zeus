# ZEUS-000062 代码交付弹窗冲突收尾与底部按钮修复

## 任务目标

修复代码交付弹窗中的两个连续问题：

1. 最后一个冲突文件保存后错误停留在空白的“解决合入冲突”界面。
2. 普通代码交付阶段内容高度超过弹窗时，底部操作区被挤出可视范围，用户无法点击。

## 现场判断

用户截图中的界面不是新的业务页面，而是代码交付弹窗的冲突处理状态。截图同时出现“冲突文件 0”和“完成合入并推送”，说明所有冲突已经处理完，但界面仍按冲突编辑器渲染。

代码中的直接原因有两项：

- 冲突记录在最后一个文件保存后仍保持 `conflicted`，直到用户明确完成合入；界面只判断状态，没有同时判断剩余冲突文件数量，因此渲染了没有文件的空编辑器。
- 同一弹窗为普通交付态预设了六行网格，但反馈和错误区域按条件增删；底部操作区依赖自然排列，子元素数量变化时会落入错误网格行。冲突态继续复用普通交付态的六行结构，进一步放大了空白和按钮错位。

## 用户确认

- 最后一个冲突文件保存后保留一次明确确认，不自动合入或推送。
- 该状态使用紧凑的“冲突已全部处理”摘要，并明确展示目标分支和任务分支。
- 用户点击固定底部主按钮后，才真正完成合入并推送；没有远端时改为同步本地目标分支。
- 普通交付态与冲突态都必须保证正文独立滚动，底部操作区固定留在弹窗内。

## 领域口径

本次新增“冲突收尾确认”：最后一个冲突文件保存后、真正合入并推送目标分支前的明确确认状态。它不是仍有冲突，也不是自动完成推送。

## 方案与取舍

### 采用方案

把弹窗稳定拆成四个纵向区域：标题、正文、状态提示、底部操作区。

- 普通交付正文内部再承载步骤条和三栏工作区。
- 仍有冲突时展示冲突文件与三方编辑器。
- 冲突数归零时展示收尾确认摘要，不再渲染空编辑器。
- 状态提示区域始终存在，错误和操作结果只在其中增删，不再影响底部操作区所在位置。

优点：两类问题一次收口，子状态变化不会再推动底部按钮；最终远端写入仍由用户明确触发。

代价：弹窗正文增加一层稳定容器，需要同步调整现有网格样式和窄窗口滚动规则。

### 未采用方案：最后一个冲突保存后自动推送

优点：少一次点击。

缺点：保存文件会隐式升级为远端 Git 写入，动作影响明显扩大，也失去合入前最后一次确认机会。

## 验收范围

- 普通代码交付态在窗口高度不足时，正文可以滚动，底部“关闭”等操作始终可见且可点击。
- 有冲突文件时，冲突列表、三方内容和保存操作正常显示。
- 最后一个冲突文件保存后，界面切换到冲突收尾确认，不出现“冲突文件 0”的空编辑器。
- 收尾确认中的“完成合入并推送”只在用户点击后执行。
- 完成 `pnpm lint`、`pnpm typecheck`、`pnpm build`、`git diff --check`，并使用独立身份的 `Zeus Test.app` 做真实界面检查；静态检查或构建通过不等于界面验收完成。

## 实现结果

- “仍有冲突”和“冲突已经清零”改为两个派生状态；只有前者渲染三方冲突编辑器。

- 保存最后一个冲突文件不会自动推送；固定底部主按钮继续承担最终合入确认。
- 弹窗统一为标题、正文、状态提示和底部操作区四行。普通交付步骤条进入正文内部，反馈和错误是否出现都不会再改变 footer 所在位置。
