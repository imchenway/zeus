# ZEUS-000064 正文显示保留输入格式

## 任务目标

任务说明、会话消息和思考摘要等可阅读正文在展示时保留输入中的空格、Tab、换行和连续空行，不再被压成单行或普通段落；超出容器宽度的内容仍允许视觉软换行。

## 用户现场

- 任务详情中的“任务要求”输入时包含回车换行，展示时被合并为连续文字。
- 会话中的思考摘要原本包含分段，展示时被强制压成单行并省略。
- 其他正文入口缺少统一口径，逐点补样式仍会继续遗漏同类问题。

## 已确认产品口径

2026-08-05 用户逐项确认：

1. 统一覆盖用户与智能体产生的可阅读正文，不只修两张截图。
2. 原始空格、Tab、换行和连续空行全部保留。
3. 超宽内容允许视觉软换行，软换行不改变原文。
4. 标题、按钮、任务表格等紧凑信息维持现有单行或截断布局。
5. 本次只修空白格式，不扩大 Markdown 或富文本支持范围。
6. 历史数据不迁移，使用同一展示规则重新渲染后直接生效。

## 领域口径

本任务统一使用“保真正文”：任务说明、用户消息、智能体正文和思考摘要中需要忠实呈现来源排版的可阅读内容。标题、按钮文案和表格摘要不属于保真正文。

## 方案比较

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 只修截图中的两个选择器 | 改动最小 | 其他正文继续丢格式，后续仍需逐点返工 | 不采用 |
| 所有文本全局保留空白 | 覆盖最广 | 标题、表格和按钮会异常增高或错位 | 不采用 |
| 以保真正文类统一、紧凑信息显式排除 | 同类入口口径一致，不破坏高密度区域 | 正文高度可能增加，需要真实界面核对 | 采用 |

## 实现记录

- 增加跨任务与会话共用的保真正文样式，使用浏览器原生空白保留和软换行能力，不改写存储值。
- 任务说明、会话 Markdown 正文、思考摘要、审批影响说明、回答问题正文与计划说明接入统一规则。
- 思考摘要取消单行省略，图标与多行正文顶部对齐。
- Markdown 继续沿用既有安全解析、授权资源和复杂度限制，不执行 HTML，也不新增富文本编辑能力。
