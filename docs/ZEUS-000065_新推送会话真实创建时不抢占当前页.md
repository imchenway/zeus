# ZEUS-000065 新推送会话真实创建时不抢占当前页

## 当前阶段

产品边界与实现已完成。格式、差异检查和整仓 lint 已通过；整仓类型检查、构建、本地页面与测试身份打包被工作树中既有的重复源码阻断，尚未完成真实界面验收。

## 用户现场

任务推送后，Renderer 先创建并选中一个与任务同名的临时会话；本机服务返回真实会话后，列表又出现一个同名会话，界面再次选中新会话并删除旧临时项。用户在等待期间切换到其他页面或会话时，迟到的成功回调还会强行抢回当前页。

## 源码事实

- 临时会话 ID 使用 `pending-task-push:<clientUserMessageId>`，真实会话 ID 由本机服务持久化生成，两者不是同一对象。
- 提交回调会立即把临时对象写入会话列表、选中它并切换到会话页。
- 成功回调随后把真实对象写入列表、再次无条件选中它，并过滤临时对象。
- 当前全局只保存一条任务推送待处理状态；不同任务并行推送时，后一次会覆盖前一次的界面反馈。

## 已确认产品规则

1. 取消临时会话 tab。会话创建操作处于进行中或失败时，不进入会话列表。
2. 提交后关闭推送弹窗，不跳页；任务入口非阻塞显示“正在创建”。
3. 同一任务创建期间禁止重复提交，不同任务允许各自后台创建。
4. 真实会话持久化成功后，会话列表只新增一次真实对象。
5. 用户等待期间仍停留在提交时页面，成功后自动打开真实会话一次。
6. 用户已切换页面或会话，成功后只更新列表与成功反馈，不抢占当前页。
7. 创建失败不产生会话 tab；错误和重试回到对应任务入口，重试沿用原请求身份，避免重复创建。
8. 点击提交后的界面反馈必须立即发生：弹窗马上关闭、当前页面保持可操作，不等待真实会话创建、不展示整页加载，也不通过假会话制造即时完成的错觉。

## 方案取舍

采用“后台会话创建操作与真实会话分离”。

优点：

- 会话列表只展示真实持久化对象，不再出现重复 tab、替换闪动或假身份。
- 迟到的异步成功不会覆盖用户后续导航。
- 不同任务的推送状态互相隔离，符合 Zeus 并行任务工作方式。
- 失败恢复归属任务推送入口，不再伪装成会话消息发送失败。

代价：

- 点击推送后不会提前显示会话正文页，需要在任务入口提供清楚的创建中、失败和重试反馈。
- Renderer 需要把单个待处理状态改为按任务保存，并保存提交时的导航位置用于成功回调判断。

不采用“临时 tab 原位升级”：

- 优点是点击后可以立刻看到会话形态。
- 缺点是仍需维护临时身份到真实身份的映射，列表继续承载尚不存在的业务对象，刷新、重试和并行场景更容易出现身份竞态。

## 实现范围

1. 移除临时会话 choice、临时会话工作区和提交时的强制导航。
2. 把任务推送操作改为按任务 ID 保存。
3. 在任务详情主操作区展示创建中、失败重试和成功反馈。
4. 成功回调比较提交时与当前导航位置，只在用户没有切走时打开真实会话。
5. 保留真实会话首条消息的乐观展示与既有幂等请求、项目偏好更新和历史刷新逻辑。
6. 不新增或恢复单元测试、组件测试、DOM/CSS 契约测试及 TDD 流程。

## 验收口径

- 推送提交后，会话列表不出现临时 tab，当前页面不跳转。
- 提交动作不等待后台请求后才关闭弹窗，后台创建期间页面无冻结、无整页遮挡且其他任务仍可操作。
- 同一任务的推送按钮显示创建中并禁止重复提交；其他任务仍可推送。
- 成功后只出现一个真实会话 tab。
- 未主动切走时只自动打开一次真实会话；主动切走后不抢页。
- 失败时不出现会话 tab，并能从原任务入口重试。
- 状态反馈具有可读文字、动态状态播报、键盘可用的重试与打开操作，不能只依赖颜色。
- 分别记录格式、lint、类型检查、构建、`Zeus Test.app` 打包和真实界面结果，不互相冒充。
