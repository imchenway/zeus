# ZEUS-0020 禅道链接一键解析并自动填入任务信息

## 目标

在创建任务弹窗中粘贴禅道缺陷/需求/任务详情页链接，一键解析并自动填入标题、任务类型与正文草稿，减少手动搬运信息。

## 范围与假设

- 首轮只解析链接与页面内容；第二轮升级为 REST 优先：按链接 host 匹配已配置实例时先走禅道 REST API，失败自动回退 HTML 抓取；不写入禅道数据。
- 识别现代路径 `/bug-view-123.html` 与旧版参数 `?m=bug&f=view&bugID=123` 两种链接形式。
- 类型映射：禅道缺陷 → Zeus 缺陷；禅道需求、任务 → Zeus 需求（Zeus 无独立“任务”类型）。
- 优先级不自动映射：禅道各版本优先级口径不一致，避免错误暗示；后续有真实实例时可补充。

## 实现

- `packages/shared/src/index.ts`：`parseZentaoTaskUrl`、`extractZentaoTaskLink`、`zentaoTaskType` 与 `ZentaoTaskExtract` 类型。
- `apps/desktop/src/main/zentaoTaskExtract.ts`：主进程抓取页面（先默认会话，再内置浏览器会话复用登录 cookie），检测登录页，解析 `<title>` 与正文字段标签，返回可填入表单的字段。
- IPC `zeus:zentao:parse-link` 经 preload 暴露为 `window.zeus.parseZentaoTaskLink`。
- `TaskCreateModal` 新增“禅道链接”输入行：粘贴链接自动解析（标题栏直接粘贴链接同样触发），按钮与 Enter 可手动重试；成功、需登录、非禅道链接、失败四种提示状态。
- 字段填入策略：缺陷填现状/复现步骤/预期；需求与任务填描述；非空覆盖，保留用户已填的父任务、优先级、标签与附件。

## 已知限制

- 外部浏览器（Chrome/Safari）中的禅道登录态无法复用；仅复用 Zeus 内置浏览器会话。
- REST 访问令牌只存在主进程内存、不落盘；应用重启或实例密码变更后解析时重新换取。
- REST 仅对「host 匹配且已配置账号密码」的实例生效；同 host 只保留一个实例配置。
- 禅道页面结构差异较大，正文按常见字段标签（重现步骤/描述/期望结果等）尽力提取，其余内容保留原文供人工调整。

## 第二轮：凭据配置与 REST 优先解析（2026-08-20）

### 设计

- 设置页新增「集成 → 禅道」分类，支持配置多个禅道实例，按链接 host 自动匹配。
- 账号密码分离存储：实例地址、basePath、账号存本地 SQLite settings（键 `zentao.instances`）；密码只写入 macOS 钥匙串（服务名 `Zeus`，账户名 `zentao:<实例 id>`）。列表/详情响应只含元数据与 `passwordConfigured` 状态，密码永不出主进程，日志不落凭据。
- 允许实例只配置地址不配置账号：解析走 HTML 抓取路径，保持首轮行为；账号为空时密码输入禁用，保存会自动清除该实例旧密码。
- 解析链路 REST 优先：`POST /api.php/v1/tokens` 用账号密码换 token（仅内存），`GET /api.php/v1/{stories|bugs|tasks}/{id}` 带 `Token` 头取详情；详情 401/403 自动重换一次 token 再试。REST 失败（凭据无效、接口未开启、404、网络失败）一律回退现有 HTML 抓取，登录页场景沿用 `login_required` 提示。
- 解析状态扩展：`ZentaoTaskExtract.failed` 增加可区分原因 `credential_missing` / `auth_failed` / `network`，`ok` / `login_required` / `failed` 原有形状不变，现有调用方无需改动。
- REST 字段映射沿用首轮口径：需求 `title/spec/verify` → 标题/描述；缺陷 `title/steps`（按 `[步骤][结果][期望]` 分段）→ 标题/复现步骤/现状/预期；任务 `title/desc` → 标题/描述。任务类型映射不变（缺陷 → 缺陷；需求、任务 → 需求）。

- `packages/local-server/src/zentaoCredentialService.ts`：SQLite 元数据 + SecretStore 密码分离读写、换 token 验证登录；路由 `GET/POST/PUT/DELETE /api/zentao-instances`、`DELETE /api/zentao-instances/:id/password`、`POST /api/zentao-instances/:id/verify`。

## 第三轮：附件随任务信息带入（2026-09-02）

### 问题与决策

- 用户用真实缺陷 `https://zentao.cckggroup.com/zentao/bug-view-17732.html` 反馈：标题与正文可解析，但禅道任务的附件没有带入 Zeus 创建任务草稿。
- 根因是 `ZentaoTaskExtract.ok` 只承载文本字段；REST 详情中的 `files` 与 HTML 附件下载链接都被主进程忽略，Renderer 无法接入已有任务附件链路。
- 采用“真实下载并物化为 Zeus 本机任务附件”，不只在正文追加远程 URL。优点是后续预览、打开和任务推送均复用现有受信任附件路径；代价是解析时需要等待附件下载。
- REST 路径使用当次内存 token 读取 `/api.php/v1/files/{id}`；HTML 回退路径只接受同 origin 的禅道附件下载链接，并复用当次默认或 Zeus 内置浏览器 cookie 会话。
- 边界沿用现有任务附件口径：最多带入 24 个，单件最大 100 MB，单次批量最大 256 MB；单个附件失败不使文本解析失败，但成功提示要显示带入数与失败数。

### 实施阶段

- 已完成：扩展解析结果、安全下载/物化、表单合并与双语提示。

### 实现

- `ZentaoTaskExtract.ok` 新增已物化 `attachments` 和 `attachmentFailedCount`；附件不会把 token、cookie、远程 URL 或服务端真实路径暴露给 Renderer。
- `zentaoApi.ts` 复用详情请求的当次 token 读取 `/files/{id}`，流式读取时同时校验声明长度与实际长度，拒绝重定向以免自定义 `Token` 头泄漏到其他 origin。
- `zentaoTaskExtract.ts` 兼容 REST `files` 的数组/数字键对象形状，HTML 回退只识别同 origin 的 `file-download-{id}` 或旧版 `m=file&f=download&fileID={id}`；登录页、JSON 错误响应、空响应与越界大小都只记为附件失败。
- `zeus:zentao:parse-link` 改为受 Main Command ledger 保护的 `desktop.task_resources.import_zentao`；每个成功下载的附件通过现有 `saveTaskAttachmentPayloads` 落入受信任任务附件目录，单件失败不阻断其他附件。
- 创建任务表单保留用户已有附件并按本机路径合并；禅道缺陷附件归属“复现步骤”，需求/任务附件归属“描述”，成功提示显示带入数和失败数。

### 验证

- 目标文件 ESLint、`git diff --check`、完整 `pnpm typecheck`、`pnpm --filter @zeus/desktop build` 均通过。
- 临时 Electron 主进程 probe（已删除）通过：REST 模拟 1 个 PNG 成功 + 1 个 HTTP 500 失败，结果为 `attachments=1/attachmentFailedCount=1`；HTML 模拟 1 个日志成功 + 1 个登录页失败，结果同样为 `1/1`，登录页没有被物化。
- `pnpm package:mac` 通过，只生成并签名 `dist/test/mac-arm64/Zeus Test.app`（bundle id `dev.hypha.zeus.test`）与测试 DMG，本轮未启动 GUI。构建仅有既有 `markstream-react` Rolldown 注解与 chunk-size 警告。
- 真实地址 `https://zentao.cckggroup.com/zentao/bug-view-17732.html` 在当前 Zeus 内置浏览器会话中重定向到登录页；本轮不读取、不使用真实禅道凭据，因此没有宣称该真实缺陷已做 GUI 端到端验收。

### 已知限制

- 当前带入禅道对象 `files`/页面“附件”区的独立附件，以及富文本中可识别为禅道 `file-read` 资源的同 origin 内嵌图片；外部图片 URL 与 data URL 不自动转存。
- 下载链接的跨 origin 重定向按失败处理；若后续真实禅道实例使用已签名的对象存储跳转，需根据真实 host 白名单再放开，不会默认跟随。

## 第四轮：富文本内嵌图片带入（2026-09-02）

### 问题与根因

- 真实缺陷解析成功后，创建任务表单没有展示任何附件，成功提示也没有附件数量。
- 禅道会将富文本编辑器中粘贴的图片作为 editor 资源，对象详情的 `files` 列表不返回这类资源，但 `steps`/`spec`/`verify`/`desc` 富文本会保留 `file-read-{id}` 图片地址。
- 原实现只识别 `files` 和 `file-download-{id}`，因此对 editor 图片误报为“没有附件”，而不是“下载失败”。

### 实现

- REST 详情在独立 `files` 之外，补充扫描与当前对象类型相关的富文本字段，仅接受同 origin 的禅道 `file-read-{id}`/`m=file&f=read&fileID={id}` 内嵌图片，并通过现有 REST 文件下载与任务附件物化链路带入。
- HTML 回退同样识别详情页中的同 origin `file-read` 图片，并复用当次登录 cookie 下载。
- 已有字段归属不变：缺陷图片展示在“复现步骤”，需求/任务图片展示在“需求描述”；成功提示在零附件时也明确显示“未发现可带入的附件”，不再静默省略。

### 验证

- 目标文件 Prettier、ESLint、`git diff --check`、完整 `pnpm typecheck`、`pnpm --filter @zeus/desktop build` 均通过。
- 临时 Electron 主进程探针（已删除）通过：mock 缺陷详情的 `files={}`，`steps` 仅包含同 origin `file-read-41.png` 与一个跨 origin 伪造图片；结果仅下载 41，物化为 `image/png`，归属 `defectReproductionSteps`，`attachments=1/attachmentFailedCount=0`。
- `pnpm package:mac` 通过，只生成并签名 `dist/test/mac-arm64/Zeus Test.app`（bundle id `dev.hypha.zeus.test`）与测试 DMG；构建仅有既有 `markstream-react` Rolldown 注解与 chunk-size 警告。
- 本轮当前会话未启用 Computer Use，不使用 CDP/外部 Playwright 替代，因此不宣称已完成真实 GUI 验收；真实 `17732` 也未读取或使用真实禅道凭据复验。
