# ZEUS-0028 检查更新页

## 任务目标

修正“发现新版本后只让用户打开下载页”的断裂升级体验。Zeus 代用户编排 Homebrew Cask 升级，显示更新预取进度；预取完成后等待用户点击“立即重启”，再安装并切换到新版 Zeus。

## 需求输入

- 任务类型：需求。
- 用户反馈：检查更新弹窗发现新版本后，不应再让用户自己前往下载页完成升级。
- 截图现状：当前版本 `0.1.2`，最新版本 `0.1.4`，安装包 `Zeus-0.1.4-arm64.dmg`；界面因产物未同时完成签名和公证，只提供“打开下载页”。

## 已核对的事实

- `ReleaseUpdateDialog` 只有在 `automaticInstallEnabled=true` 且建议动作为 `download_and_install` 时显示“下载并安装”；否则显示“打开下载页”。
- `packages/release-core` 只有在发布清单同时声明已签名、已公证且执行宿主协议兼容时，才开放应用内安装。
- Main 进程已经接入更新包下载、受信 GitHub Release 地址校验、下载大小和 SHA-256 校验、DMG 挂载与 App 复验。
- 安装器已经具备原子替换、新版自动重开、重连执行宿主、失败恢复旧 App 的交易链路。
- 当前发布编排默认允许未签名、未公证产物；只有显式开启 Apple 分发门禁并配置相关凭据时，才会产生可信任的自动安装清单。

## 根因判断

截图中的“打开下载页”是未签名、未公证发布产物触发的安全降级。仅把按钮文案改成“下载并安装”会绕过现有的可信分发门禁，并不是真正修复。要达成用户目标，需要让公开发布链路稳定产出已签名、已公证的安装包和一致发布清单，再复用已有应用内安装交易。

## 用户已确认方向

- 不再把“打开下载页”作为发现新版本后的主路径。
- Zeus 代用户执行 Homebrew Cask 升级，目标命令为 `brew upgrade --cask imchenway/tap/zeus`。
- 下载期间显示进度弹窗。
- 下载完成后不自动重启 Zeus，等待用户点击“立即重启”。
- 不在用户点击前使用 `brew upgrade --no-quit` 提前替换运行中的 `/Applications/Zeus.app`，避免旧进程与新版磁盘资源长时间混用。
- 用户点击“立即重启”后，界面进入不可重复操作的短暂安装状态；独立辅助进程使用已缓存产物执行 Homebrew 升级，禁止 Homebrew 自动退出和重开，成功后再由 Zeus 完成升级切换与新版重开。
- 更新预取使用真实 macOS 原生进度窗口，不使用 Renderer 内容弹窗仿冒原生外观。
- 原生进度窗口不得以模态方式锁定 Zeus；下载、Homebrew 信息更新与校验期间，用户仍可继续使用主窗口、发送消息、处理交互请求和执行其他工作。
- 已确认允许新增 Swift/AppKit 原生辅助程序；它作为 Zeus 应用包内组件与外层 App 一起构建和签名，不要求用户额外授权。
- 原生进度窗口已确认采用真实进度规则：更新 Homebrew 信息和校验阶段显示不确定进度；下载阶段只在取得真实已下载字节与可靠总大小时显示容量和百分比；命中已校验缓存时直接显示完成；无法取得总大小时只显示已下载容量，不伪造百分比。

## 原生进度窗口现状

- 项目当前没有 Swift、Objective-C 或其他 AppKit 辅助程序。
- Electron `dialog.showMessageBox` 可以显示 macOS 原生消息框，但不提供可持续更新的原生进度条。
- 真实非模态原生进度窗口需要新增独立 AppKit 辅助程序，由 `NSPanel` 承载 `NSProgressIndicator`；它与 Homebrew 预取工作分离，窗口异常退出不得中断下载。
- 该辅助程序需进入构建、App 资源封装、签名和发布产物健康检查。

## 权限边界

- AppKit 进度辅助程序只创建本机原生窗口，通过受控本机通道接收阶段、进度和结果；它不申请管理员权限、辅助功能、屏幕录制、完全磁盘访问或 Apple Events 自动化权限。
- 辅助程序作为 Zeus App 包内组件与外层 App 一起签名，不作为独立应用让用户另行安装或批准。
- 当前 `imchenway/tap/zeus` Cask 只包含普通 `app "Zeus.app"` 安装、退出标识和 zap 清理声明，没有系统扩展、驱动、特权守护进程或需要 `sudo` 的自定义安装脚本。
- 当前本机 `/Applications/Zeus.app` 与 `/opt/homebrew` 都由当前用户持有，标准升级不需要管理员弹窗。
- 如果用户将 App 或 Homebrew 安装到当前账号不可写的位置，Zeus 不在原生进度窗口中索要或代传管理员密码；本次升级应停止并说明权限阻断。

## Homebrew 能力核对

- 本机 Homebrew 版本为 `6.0.15-174-g3ecc9ef`。
- `brew upgrade --cask imchenway/tap/zeus` 把下载、安装、旧 App 退出和替换组成一次连续操作，没有“下载完成后暂停”参数。
- `brew fetch --cask imchenway/tap/zeus` 只下载 Cask 产物并输出 SHA-256，可作为不替换 App 的更新预取阶段。
- 当前 Cask 为 `imchenway/tap/zeus 0.2.28`，安装位置为 `/Applications/Zeus.app`，并声明升级时退出 bundle ID `dev.hypha.zeus`。
- 当前 Cask 没有自定义重开脚本，但 Homebrew 核心在升级时会记录因 `uninstall quit` 成功关闭的 bundle ID，替换成功后重新向 Launch Services 登记新 App，并执行 `open -b dev.hypha.zeus`。这是当前命令会自动重开 Zeus 的真实来源。
- Homebrew 支持 `brew upgrade --cask --no-quit imchenway/tap/zeus`；它会禁止关闭和自动重开 Zeus，但仍会在命令执行期间立即替换 `/Applications/Zeus.app` 并更新 Homebrew 登记。
- 因此 `--no-quit` 可以形成“新 App 已替换、旧 Zeus 进程暂时继续运行、等用户点击后重启”的状态，但它不提供“新 App 只安装到旁边，点击后再原子替换”的 Homebrew 托管交易。
- 运行中直接替换 App 会让旧界面进程与磁盘上新版资源暂时并存；如果用户长时间不重启，新建窗口、加载 preload 或启动应用包内辅助进程可能读到与当前进程不同版本的资源。

## 用户确认结果

1. 已确认：一次 Homebrew 升级拆成“`brew fetch --cask imchenway/tap/zeus` 更新预取”和“用户点击后执行缓存安装、升级成功后重新打开”两个阶段。
2. 已确认：使用独立、非模态的 macOS 原生进度窗口，不影响 Zeus 继续工作；允许新增无额外用户授权的 AppKit 辅助程序作为发布包组成部分。
3. 已确认：进度窗口在更新信息和校验阶段使用不确定进度，实际下载可取得真实字节与总大小时显示容量和百分比，不伪造进度。
4. 已确认：关闭原生进度窗口只隐藏窗口，后台预取继续；再次检查更新时恢复同一任务，预取完成后可发送桌面通知。
5. 已确认：Homebrew 未安装、Zeus 不是由指定 Cask 管理、下载或安装失败时停止升级并保留当前 App；已是最新版时直接显示结果，不回退到下载页。

## 实现结果

- 新增 `HomebrewUpdateService`，只接受 `imchenway/tap/zeus`，并在操作前后核对 Cask tap、当前与目标版本、下载地址、SHA-256、安装位置和执行宿主协议。
- 预取实际执行 `brew update`、`brew info --cask --json=v2`、`brew --cache --cask` 和 `brew fetch --cask --retry imchenway/tap/zeus`；命中已校验缓存时不重复下载。
- 用户点击“立即重启”后，实际执行 `brew upgrade --cask --no-quit --yes --require-sha imchenway/tap/zeus`。`--no-quit` 禁止 Homebrew 自行退出和重开 Zeus，安装成功且版本复验通过后才退出当前进程并由辅助程序重新打开对应 bundle ID。
- 新增 Swift/AppKit `ZeusUpdateProgress` 辅助程序，使用非模态 `NSPanel` 和原生 `NSProgressIndicator`。窗口隐藏、关闭或辅助程序重建不会取消 Main 进程中的唯一预取任务。
- 进度刷新只更新已显示窗口，不重复激活 App 或抢夺用户焦点；下载阶段只解析 Homebrew 实际输出的字节进度，信息更新与 SHA-256 校验阶段使用不确定进度。
- 菜单“检查更新”不再向 Renderer 投递旧弹窗事件；旧 Renderer 下载、安装和“打开下载页”桥接不再暴露给界面。设置页仅保留发布清单证据，并明确升级入口由原生 Homebrew 窗口承载。
- 构建流程新增原生辅助程序编译、asar 解包资源声明和打包健康检查；缺少或不可执行的辅助程序会让打包失败。

## 方案优缺点

- 优点：用户不再离开 Zeus 手动下载；预取不替换正在运行的 App；安装发生在明确确认之后；Cask 与发布清单双重校验；窗口不阻断现有工作；不新增管理员或隐私权限。
- 缺点：依赖 Homebrew 和指定 Cask 已正确管理当前正式 Zeus；`brew update` 的耗时无法提供可靠百分比；点击“立即重启”后仍需等待短暂安装完成，不能做到零等待切换；Homebrew 或 App 路径不可写时会失败关闭，不会弹出提权密码框。
