# ZEUS-0066 命令日志自动显示最新内容

## 任务目标

命令中心的执行详情在打开时直接显示终端日志底部；运行中的命令追加新日志时，如果用户仍在查看最新内容，日志视口持续跟随到底部。

## 产品口径

- 首次选择一条执行记录时，终端日志直接定位到最新内容，不从顶部开始展示。
- 运行日志继续增长时，已位于底部的视口持续跟随最新输出。
- 用户主动向上滚动查看历史日志后暂停自动跟随，避免每秒轮询把阅读位置强行拉走。
- 用户手动回到距底部很近的位置后恢复自动跟随；命令状态、轮询频率、日志截断和持久化规则保持不变。

优点：默认路径始终优先展示当前执行进展，同时保留排查历史输出的能力。

代价：用户主动上滚后，需要手动回到底部才能恢复自动跟随；本次不增加新的悬浮按钮和视觉噪音。

## 根因

`CommandCenterPanel` 每秒增量读取运行日志并更新 `<pre>` 内容，但日志容器只有 `overflow: auto`，没有记录用户跟随意图，也没有在内容高度变化后更新滚动位置。因此日志真实追加成功后，视口仍停留在旧位置。

## 实现计划

- 把命令日志展示收口为独立组件，使用 DOM 引用保存高频滚动跟随状态，避免为每次滚动引入 React 重渲染。
- 在记录身份或日志正文变化后的布局阶段执行即时底部定位。
- 通过距底部阈值区分“继续跟随”与“用户阅读历史”。
- 执行格式、静态检查、构建和可行的真实界面验证，并如实记录未覆盖边界。

## 实现记录

- 新增 `CommandRunLog`，把终端日志容器、当前运行记录身份和跟随意图收口到同一个组件。
- 运行记录首次显示或日志正文追加后，在浏览器绘制前使用即时滚动定位到底部，避免先闪现顶部再移动。
- 跟随意图使用 `ref` 保存；滚动事件只计算距底部距离，不触发父页面状态更新。
- 距底部不超过 `24px` 时视为继续跟随；超过阈值视为用户正在阅读历史，后续轮询更新不改变当前位置。
- 未修改日志 API、每秒轮询、展示预算、Runtime 执行、命令确认或状态终结逻辑。
