# ZEUS-0068 点击停止按钮后输入框漂移

## 任务目标

修复活动轮次停止后，恢复态输入框覆盖会话正文或漂到页面顶部的问题。停止、恢复、草稿、附件和任务执行现场的既有语义保持不变。

## 现场与历史证据

- 用户截图中，输入框覆盖在历史正文上方，右上角同时出现恢复状态；这说明界面已经从普通会话输入框切换到恢复用的新会话输入框。
- 既有 `ZEUS-000029` 已要求恢复态只保留一个底部主输入区，`2026-08-05` 的输入框常驻修订进一步要求用户继续从原底部位置输入。
- 当前源码虽然为恢复组件传入 `docked`，但仍先渲染一层 `.session-new-conversation` 弹性容器，再依赖 `data-docked` 属性选择器取消它的剩余空间。恢复输入框的位置因此同时依赖 React 分支和 CSS 级联。

## 修复方案

- 停靠态的 `NewConversationComposer` 直接返回 `.session-composer-shell`，使它与普通输入框一样成为 `.session-conversation-pane` 的直接子项。
- 只有真正的新会话空态继续使用 `.session-new-conversation` 和占位元素，把输入框放在空页面底部。
- 删除停靠态不再需要的属性选择器，避免同一布局事实分别由组件属性和 CSS 覆盖表达。

优点：停止或恢复引发组件切换时，两个输入框占用同一个底部布局槽；正文继续独立滚动，输入框不会覆盖历史内容。

代价：新会话输入组件存在停靠与空态两个明确的返回结构；后续调整输入区外壳时需要同时确认这两个结构仍复用同一 composer 内容。
