# ZEUS-0071 为什么这么多技术错误的报错

## 需求

会话中同一轮出现多条相同的 Provider 技术错误；同时，打开 PLAN 工作区后，计划正文没有稳定地保持在右侧工作区的内容列中。

## 调研结论

### 重复错误

服务端的 Provider 事件处理器在捕获异常后，会把每个失败事件写成一个 `error` 条目。`item/completed` 等事件连续触发同一个异常时，数据库中会留下多条条目，渲染器再逐条显示为“本轮错误”。截图中的两条错误代码和正文完全相同，因此不是两次独立失败，而是同一失败链路在多个事件上的重复诊断。

错误 `ZEUS_TURN_CHANGE_SET_PATH_FORBIDDEN` 仍然是实际的项目授权边界失败。本任务只整理用户看到的重复错误，不放宽文件授权、不重放失败事件，也不把失败状态改成成功。

### PLAN 对齐

当前 DOM 已经把 PLAN 放在通用的 `session-conversation-browser-layout` 右侧 sidecar 中，但样式仍保留早期 `session-thread-split[data-plan-*]` 的外层两列规则。旧规则与当前 DOM 属性和层级不一致，导致 PLAN 不能依赖同一套右侧工作区布局；PLAN 根节点也没有明确填满 sidecar 的尺寸。

## 实现

1. 在会话渲染层按“轮次 + 错误代码 + 错误正文”合并重复的错误条目，只保留首条原始诊断。
2. 当轮次失败快照已经提供失败卡片时，不再额外渲染相同的底层错误条目；首条诊断中的代码、正文和 Provider 事件会进入该卡片的技术详情。
3. 保留没有轮次失败快照时的首条原始错误，因此实时状态尚未同步时仍能看到真实原因。
4. 移除失效的外层 PLAN 两列选择器，恢复当前外层容器的单一弹性布局；让 PLAN 工作区和正文容器填满右侧 sidecar，并保留正文最大宽度和水平居中。
5. 整理 `PlanWorkspace` JSX 排版，避免后续样式层级判断被格式噪声干扰。

## 方案权衡

- 优点：相同错误不再重复占据会话正文；首条诊断和真实失败状态仍保留；不同代码或不同正文的错误不会被误合并。PLAN 的布局职责回到当前通用右侧工作区，浏览器、源码和变更审核不会继续依赖旧的 PLAN 选择器。
- 代价：多个事件产生相同代码和正文时，只展示首条事件的元信息；如果需要查看全部事件序列，仍应查看本机诊断数据，而不是让普通会话正文重复展示。底层授权问题本身不在本任务中修复，仍需要单独的授权解析任务处理。
