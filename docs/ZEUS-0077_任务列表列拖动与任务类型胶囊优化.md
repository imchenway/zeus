# ZEUS-0077 任务列表列拖动与任务类型胶囊优化

## 当前阶段

已完成需求确认、实现、静态检查、构建和测试包校验；浏览器渲染与排序交互已验证。

## 已确认产品口径

- 列宽和列顺序两种拖动都需要。
- 列宽在按内容设置的可读下限与 `640px` 安全上限之间连续调整。
- 任务类型在列表中是只读彩色胶囊，不提供列表内下拉修改。
- 需求使用蓝紫色，缺陷使用红色，优化使用绿色；均使用低饱和浅底、同色文字和细边框。

## 原始需求

- 任务列表的列应该可以自由拖动。
- “任务类型”列需要从普通文字改为带颜色的胶囊，并与其他下拉框使用同一套视觉语言。

## 已核对事实

- 任务表已有两种独立交互：列头换位和右边界调整列宽。
- 换位把手和列宽把手默认不可见，只在当前列头悬停、获得焦点或正在拖动时显示；命中区分别只有 `24px` 和 `8px`，可发现性较弱。
- 前端根据列类型把可调范围限制为 `72–420px`、`120–520px` 或 `140–560px`，服务端则接受 `64–640px`，两端口径不一致。
- 列宽、列顺序、列显隐和排序状态已共用任务表布局草稿与保存机制，不需要新增第二套持久化。
- “任务类型”列当前只渲染普通粗体文字；任务管理状态、运行状态和优先级已有低饱和色胶囊或带色下拉触发器。
- 工作树已存在其他任务的未提交修改，其中 `styles.css` 和 `CONTEXT.md` 有重叠文件；后续实现必须仅追加本任务的局部改动，不覆盖现有工作。

## 范围说明

“自由拖动”可能同时指向两件事：

- 列宽调整：直接拖动表头分隔线，在保证文字和控件可用的最小宽度与防止失控的最大宽度之间连续调整。
- 列顺序调整：拖动列头进行左右换位，并保留独立的排序点击区，避免拖动误触排序。

## 建议方案与取舍

### 推荐：列宽与列顺序都支持，分隔线直接拖动，列头使用明确换位热区

优点：符合桌面表格的常见心智；用户不需要先猜隐藏把手在哪；排序、换位和改宽仍然可以分清。

缺点：列头需要重新分配命中区；如果整个列头都可拖换位，必须设置小幅移动阈值，否则容易与单击排序冲突。

### 保守：只放大现有两个把手

优点：改动范围小，能保持现有排序语义和事件结构。

缺点：仍然要求用户在狭小区域精确命中，与“自由拖动”的直觉预期有距离。

## 任务类型视觉建议

- 需求、缺陷、优化使用三种可区分的低饱和色，始终保留完整文字，不只靠颜色识别。
- 胶囊的高度、内边距、边框、深浅色主题与焦点语言应复用现有带色下拉触发器，但任务列表中的类型仍是只读标签，不伪装成可点击下拉框。
- 推荐颜色方向：需求用蓝紫色，缺陷用红色，优化用绿色。

优点：扫读更快，与现有状态及优先级的低饱和表达一致。

缺点：表格会新增一组颜色语义；需要严格控制饱和度，否则会和任务状态、运行状态、优先级互相抢层级。

## 实现记录

- 列标题本身支持拖动换位，原有独立换位把手继续保留，供键盘和精确操作使用；单击标题仍只负责排序。
- 列宽分隔线命中区由 `8px` 扩大为 `12px`，默认显示低对比度提示线，悬停、聚焦或拖动时增强。
- 前端与本地服务统一列宽规则：编码等紧凑列最小 `72px`，会话类列最小 `120px`，任务和描述类列最小 `140px`，所有可调列最大 `640px`。
- 任务类型改为只读彩色胶囊：需求为蓝紫色、缺陷为红色、优化为绿色；继续显示文字，避免只靠颜色传达含义。
- 列顺序、列宽、显隐和排序继续复用现有任务表布局偏好，不新增业务字段或第二套持久化。
