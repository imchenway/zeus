# ZEUS-0079 会话列表排序规则优化

## 任务信息

- 任务类型：优化
- 当前阶段：实现完成，待真实 GUI 验收
- 现状：会话列表按会话主记录的通用 `updatedAt` 倒序排列。用户打开会话后，后台同步可能改写该字段，造成所打开会话看起来被置顶。
- 预期方向：会话列表只按会话阶段状态发生变化的时间倒序排列，例如进入待回复状态时更新排序位置。

## 现状调研

1. 会话树、任务关联会话和会话快照合并均直接按 `updatedAt` 倒序排列。
2. 点击会话的界面处理只更新选中会话，不直接写入置顶时间。
3. `updatedAt` 不是阶段状态专用时间：消息追加、运行态、模型设置、Token 用量、权限与协作模式等变化都会改写它。
4. 因此当前排序表达的是“会话主记录最近被任意内容改写”，不是“会话阶段最近发生变化”。

## 已确认规则

- 排序只在会话阶段真正变化时更新。
- 同一阶段内新增模型输出、阅读会话、同步配置或重复收到同阶段事件，都保持原排序位置。
- 会话阶段包括排队、响应、待回复、待批准、完成、失败和暂停等列表生命周期状态。
- 任务更新时间、会话最后更新时间和会话阶段更新时间是三个独立事实，不得互相回填或借用。
- 打开任务详情不更新任务时间、会话最后更新时间或会话阶段更新时间；任务内容与任务管理状态变化也不改变会话排序。
- 新建会话以创建时间作为初始会话阶段更新时间。
- 旧会话优先从历史排队、执行轮次和交互请求还原最近阶段变化时间；无法还原时使用创建时间，不沿用通用 `updatedAt`。
- 会话阶段更新时间相同时，以创建时间倒序、会话 ID 倒序保证顺序稳定。
- 左侧普通会话列表按会话阶段更新时间倒序；任务详情中的关联会话列表独立按创建时间从早到晚排列，不复用左侧列表规则。
- 已归档会话列表不在本任务范围内，保持现有排序规则。

### 历史会话推导取舍

- 优点：升级后旧会话也立即遵循阶段语义，不继续保留点击、配置和 Token 同步造成的污染顺序。
- 缺点：首次升级后旧列表可能出现一次合理重排；迁移逻辑需要对多种历史阶段事实进行统一归一化。

### 两类会话列表采用不同顺序

- 优点：左侧列表突出最近阶段变化，任务详情按时间线表达一个任务下会话的产生顺序，各自符合使用目的。
- 缺点：同一批会话在两个入口的顺序可能不同，不能用一个模糊的通用排序函数覆盖所有页面。

## 方案方向与取舍

### 独立记录会话阶段更新时间

- 优点：排序语义准确；打开、阅读、Token 刷新和配置同步不会扰动列表；服务端与多个界面可共享同一事实源。
- 缺点：需要补充持久字段、迁移旧数据，并梳理所有真实阶段迁移入口。

### 继续从现有子记录临时推导

- 优点：可能少加一个数据库字段。
- 缺点：阶段由会话、执行轮次、排队消息和交互请求共同派生，查询复杂且容易出现不同界面排序不一致，不建议采用。

## 实现记录

1. 会话持久化新增 `stage` 和 `stageUpdatedAt`，不再用通用 `updatedAt` 表示排序时间。
2. 只有排队、执行轮次、交互请求、计划操作、归档等会改变阶段事实的写入才同步阶段；消息、配置、Token 和阅读状态不同步。
3. 迁移会从历史轮次、提交、交互请求和计划操作回填阶段与时间；无证据时回退到创建时间。
4. 服务端输出阶段字段，左侧会话树、快照合并和任务工作区选择统一按阶段时间倒序。
5. 任务详情关联会话单独按创建时间正序；已归档会话保持原规则。
