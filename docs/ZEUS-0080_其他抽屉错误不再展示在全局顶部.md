# ZEUS-0080 其他抽屉错误不再展示在全局顶部

## 任务信息

- 类型：缺陷
- 现状：项目配置抽屉中的工作区配置错误会同时显示在抽屉内和整个工作区顶部；关闭抽屉后，全局顶部仍保留该错误。
- 预期：错误只跟随产生它的项目配置抽屉展示，并保留原输入与重试入口；不得把局部配置失败升级为 Zeus 全局故障。
- 复现步骤：打开项目配置抽屉，保存互相包含或其他不合法的工作区目录，触发服务端路径校验失败，然后关闭抽屉或切换页面。

## 现场与根因

- 截图错误为 `Project repositories cannot contain one another.`，来源是历史项目仓库嵌套校验。
- 当前项目仓库已改为任务推送时自动发现，项目配置抽屉只保留共享可写目录；共享目录重叠、路径不存在等失败仍会经过同一前端捕获链路。
- `loadProjectWorkspaceConfig()` 与 `saveProjectWorkspaceConfig()` 已将脱敏后的错误写入抽屉局部状态 `projectWorkspaceConfigError`。
- 两个异常分支又调用 `recordLocalError()`，把同一错误写入应用级 `localError`。应用工作区根部会无条件渲染该状态，因此关闭抽屉不能清除全局副本。
- 服务端路径校验和保存原子性没有问题，本次缺陷位于 Renderer 的错误归属。

## 方案与取舍

### 采用局部错误不再升级为全局错误

- 优点：错误、用户输入和“保存共享目录”重试动作位于同一个抽屉；关闭抽屉后不会污染其他页面；不改变服务端校验和持久数据。
- 缺点：用户离开抽屉后不再持续看到这次失败，需要重新打开项目配置才能查看并重试。

### 不采用关闭全局顶部错误或自动超时

- 优点：可以暂时消除常驻提示。
- 缺点：同一错误仍会重复出现在两个位置；关闭或超时只处理展示，没有修正错误归属。

### 不采用删除服务端路径校验

- 优点：可以让当前保存请求通过。
- 缺点：会允许互相包含或越界的共享目录进入任务环境，扩大并发写入和回收风险，属于绕过数据保护而非修复界面缺陷。

## 实现记录

- 项目工作区配置加载失败只更新 `projectWorkspaceConfigStatus` 与 `projectWorkspaceConfigError`。
- 项目工作区配置保存失败只更新同一组抽屉局部状态。
- 保留错误脱敏、表单输入、服务端校验和原有重试入口。
- 不修改其他尚未具备局部错误承载区的全局错误调用，避免把错误静默吞掉。

## 验收要求

- 项目工作区配置加载或保存失败时，错误只显示在项目配置抽屉内。
- 关闭抽屉或切换页面后，工作区顶部不出现该错误。
- 保存失败后保留共享目录输入，用户可修改后再次保存。
- 服务端继续拒绝无效、重复、互相包含、越界或过宽的共享目录。
- 完成 `pnpm lint`、`pnpm typecheck`、`pnpm build` 与 `git diff --check`；静态检查和构建成功不等同于真实 Electron 界面验收。
