# ZEUS-0082 自由输入按键误选并提交 PLAN 答案

## 任务目标

修复 PLAN 会话的普通用户询问中，用户正在输入自定义答案时，某个编辑按键被错误识别为选项快捷键并自动提交预设答案的问题。

## 用户现场

- 用户在另一个会话的自由输入过程中，询问框自动选择答案并发出。
- 截图显示询问“项目级默认分支第一次应如何生成？”已经变成“已回答”，实际答案为“统一分支名”。
- 用户明确：导致问题的绝对不是 Escape；自由输入时任何键都不得选择、提交、跳过或关闭 PLAN 选项框。Escape 只能退出输入状态，不能结束询问。

## 证据与根因

正式 Zeus 数据库中对应 `request_user_input` 的选项顺序为：

1. 首次当前分支（推荐）
2. 统一分支名
3. 首次必须配置

持久响应为第二项“统一分支名”，解决时间为 `2026-08-05T07:32:09.353Z`，与用户截图时间一致。

当前 `RequestUserInputPanel` 在整个询问面板上监听键盘：

- `1` 至 `9` 会按序点击对应选项；单选题随后立即提交；
- 自由输入框没有阻止这些按键继续冒泡；
- 键盘 `2` 位于 W 上方，并确定性地映射到第二项“统一分支名”；
- 自由输入里的 Enter 还被单独映射为表单提交。

系统没有持久化原始 keydown，因此不能把“用户当时按下了 2”描述成直接日志事实；但截图答案、持久选项顺序、响应结果与代码映射共同证明了数字快捷键越过自由输入边界的根因。

## 领域口径

- “普通用户询问”是 app-server 的 `request_user_input`；本次现场发生在 PLAN 会话，但不是独立的计划实施请求。
- “询问自由输入状态”是自定义答案或纯自由输入获得编辑焦点的状态。
- 自由输入状态内，数字、方向键、Enter、空格和普通字符都只编辑草稿；Enter 正常换行。
- Escape 只退出编辑焦点，保留当前回答方式和完整草稿。
- 只有点击明确的提交、跳过、关闭或预设答案控件，才能改变或结束当前询问。

## 修复方案

采用双层隔离：

1. 所有自定义答案和纯自由输入控件统一截断键盘事件，避免外层选项快捷键收到编辑按键；
2. 外层选项快捷键额外拒绝处理来自 input、textarea 和可编辑元素的事件，避免未来新增输入路径再次漏掉；
3. 移除自由输入 Enter 提交，文本域 Enter 恢复正常换行，单行敏感输入 Enter 不提交；
4. Escape 保留草稿和回答方式；自定义答案焦点回到“其他回答”入口，纯自由输入只退出编辑焦点；
5. 面板非输入区域的数字键和方向键快捷导航继续保留。

优点：

- 所有编辑按键都被限制在输入控件内，不再误选或自动提交；
- 双层防护同时覆盖当前四条输入路径和未来遗漏；
- 保留非输入区域的键盘选项导航与显式按钮操作。

缺点：

- 自由输入不能再按 Enter 快速提交，必须点击明确的“提交”按钮；
- 纯自由输入没有“其他回答”入口，Escape 后只能退出焦点，不能回到同类触发按钮。
