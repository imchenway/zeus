# ZEUS-0087 配置保存

## 任务信息

- 类型：优化
- 现状：用户修改会话输入区配置后，不发送消息，直接切换到其他会话再切回，刚才的配置恢复为旧值。
- 用户未单独提供预期；本任务沿用既有会话配置契约：模型、推理强度、服务档位、权限模式和计划模式属于当前会话的下一轮配置，选择后立即保存，不依赖发送消息。

## 产品口径

- 配置按会话隔离，切换会话和重启应用后仍保留。
- 修改只影响尚未开始的下一轮，不热切换已经开始执行的当前轮。
- 本地会话缓存先保留用户最后一次选择，服务端持久化成功后同步更新当前权威快照。
- 只读旧会话继续不可编辑，不新增虚假的保存入口。

## 根因

会话工作区重新挂载时存在两个连续的初始化动作：先从按会话存储的本地缓存读取用户刚才的选择，随后又从热缓存中的旧会话快照生成配置。由于组件状态初值固定为 `null`，旧快照初始化会在同一轮副作用中覆盖本地选择。

配置保存接口成功后，控制器也没有把服务端返回的下一轮配置写回当前会话快照。因此父层热缓存仍可能保存旧配置，进一步放大了切换后回退的问题。

## 修复方案

1. 会话工作区首次渲染时直接以当前会话的本地配置作为状态初值，不再先以空值挂载后再补读。
2. 本地已经存在用户选择时，不允许旧热快照在首轮副作用中覆盖它；后续仍通过既有接口同步到服务端。
3. 下一轮配置保存成功后，控制器立即更新当前会话快照，使当前界面和父层热缓存都获得已确认的新值。

## 方案取舍

### 本地选择优先接管，再与服务端同步

- 优点：用户刚修改就切换会话时不会丢失选择；即使服务端保存仍在进行，切回后也能继续展示并重试最新配置。
- 缺点：短时间内本地缓存可能领先于服务端快照，因此必须保留后续同步，不能把本地值直接冒充服务端已确认事实。

### 保存成功后更新控制器快照

- 优点：当前界面、会话热缓存和服务端返回值及时一致，减少再次切换时读取旧数据的窗口。
- 缺点：控制器增加一类局部状态更新；未来若服务端扩展配置字段，返回类型和快照字段需要同步维护。

## 非目标

- 不改变已经执行中的当前轮配置。
- 不修改模型能力目录和各配置选项本身。
- 不新增或恢复单元测试、组件测试、DOM/CSS 契约测试及相关脚本。
