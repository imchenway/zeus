# ZEUS-0088 关于对话信息的整理

## 需求与确认口径

- 所有共享原生会话渲染器的会话统一采用 Codex 风格。
- 进行中的轮次展开显示过程；轮次完成后默认折叠过程，但用户可以重新展开查看完整记录。
- 每个轮次都有自己的“已处理”耗时，位置在用户消息之后、过程入口处；轮次完成后耗时固定，不再继续读秒。
- 最终回复依据 provider item 的 `phase=final_answer` 识别，不根据“结论”等正文关键字截断。
- 变更卡片、失败卡片和用户确认历史保持独立，不被过程折叠隐藏。

## 根因

渲染端原本只在每轮最后一个可见 item 后追加 `SessionTurnDuration`。实时完成事件只更新 `activeTurnId` 和 `terminalTurnIds`，没有同步更新 `turnsByProviderId`，导致已完成轮次仍可能用当前时间计算耗时。

Pi 运行内核在完成持久化时还会丢失原轮次的 `startedAt`，重载后的历史轮次因此无法恢复真实耗时。

## 实现

- `conversation.turn.started/completed` 事件携带后端产生的 `startedAt`、`completedAt`。
- Reducer 在实时事件中创建或更新 `NativeTurnSnapshot`，保持轮次状态、起止时间和已有计划、错误信息。
- Codex 与 Pi 的持久化起止时间作为耗时事实源；Pi 完成时保留已有 `startedAt`。
- transcript 先按原始时间线投影，再按轮次把 reasoning、plan、commentary、工具活动等合并到一个过程入口；最终回复保持独立可见。
- 当前轮次的“正在思考”状态放在当前轮次入口内；不再渲染置底的全局耗时或思考状态。
- 计时刷新限制在活动的 `SessionTurnDuration` 组件内，使用现有等待确认扣除规则。
- 样式只作用于 `.session-codex-parity-v1`，支持折叠摘要、键盘焦点、窄窗口和 reduced-motion。

## 取舍

过程默认折叠可以让最终回复成为主要阅读内容，同时保留展开后的审计能力；代价是 transcript 需要额外的轮次投影和嵌套布局。失败和中断轮次继续保留失败证据，不伪装成普通成功回复。
