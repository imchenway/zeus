# ZEUS-0091 归档不需要显示在更多菜单里

## 当前阶段

已完成需求核对、实现、工程门禁、测试身份打包和真实启动检查；由于本任务隔离数据根没有会话，未制造 Provider 会话或 Git 工作区来冒充目标悬停与点击验收。

## 任务目标

- 归档不再收进会话行的“···”菜单。
- 对应会话行被鼠标悬停时，行尾显示小型归档图标，点击直接发起归档。
- 产品表达参考 Codex App，但不复制外部代码或品牌资产。

## 现状核对

- 归档与恢复的 Provider 同步、本地记录、审计和设置页恢复链路已在 `ZEUS-000067` 完成。
- 会话列表当前先显示“更多会话操作”按钮，再从只有一个选项的菜单中选择“归档会话”，增加了没有必要的操作层级。
- 现有服务端仍会在归档前检查活动轮次、排队消息和待处理请求，本任务不改变这些安全语义。
- 尝试通过本机界面控制读取当前 Codex App 可见实现时，安全策略禁止控制 `com.openai.codex`；因此不冒充完成了当前版本的像素级对照。

## 实现设计

1. 删除任务会话行的更多菜单状态、外部点击监听和弹层。
2. 使用 Phosphor 归档图标作为行尾 `26px` 命中区，默认透明，只在行 hover 或 focus-within 时显示。
3. 保留可访问名称、原因提示、键盘焦点和 `aria-disabled`；不可归档时不发起请求。
4. 归档中展示旋转图标，完成后继续由既有列表刷新与归档恢复链路收敛状态。

## 取舍

- 优点：归档从两步收紧为一步，无鼠标悬停时不增加列表噪音。
- 优点：使用语义图标和明确提示，不会把归档伪装成删除。
- 缺点：列表行尾需要预留固定命中区，很长的会话标题会更早省略。
- 不采用“仅对可归档会话显示图标”：这会让正在运行的会话缺少原因说明，用户难以理解入口为何突然消失。

## 验收口径

- 默认状态不显示会话行归档图标，悬停对应行后才显示。
- 点击可用的归档图标直接触发归档，不再出现更多菜单。
- 键盘聚焦能显示图标和焦点环；浅色、深色和跟随系统主题使用语义色。
- 运行中、排队中、等待交互和旧版只读会话不能触发归档，后端保护不变。
- `pnpm lint`、`pnpm typecheck`、`pnpm build`、`git diff --check` 与必要的真实 `Zeus Test.app` 交互验证分别记录，不互相冒充。
