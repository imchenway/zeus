# ZEUS-0092 模型按供应商分组

## 当前阶段

实现、静态验证和隔离打包已完成。真实 GUI 启动因首次窗口落到主屏而立即停止，未形成目标界面验收证据。

## 已确认口径

- “供应商”指 DeepSeek、阿里云百炼等模型接入渠道品牌，不指 Agent、模型发行方或用户命名的模型连接。
- 模型列表的第一层排序与分组都按供应商组织。
- 现有“连接名称”改为“供应商名称”：内置模板提供默认名称，自定义兼容连接由用户填写。
- Agent 身份继续作为真实路由和会话事实保留，但模型选择列表的模型行不显示 Agent，只显示模型名称。
- 同一供应商可以包含多个模型连接；连接与模型的复合身份仍是实际选择和持久化依据。
- 主界面不显示模型连接层。同一供应商下存在两套同名模型时保留两个同名项，不追加连接备注或服务地址；后台仍按复合身份精确选择。
- 只有一个供应商时隐藏供应商分组标题；存在两个及以上供应商时才显示分组标题。
- 供应商分组内的模型行只显示模型名称，不显示供应商、连接、服务地址或 Agent。
- 下拉框收起后固定显示“供应商 / 模型”，即使当前只有一个供应商也不省略供应商名称。
- 多个供应商按当前项目最近使用优先排列，其余按供应商名称排序；不同项目的使用记录互不影响。
- 同一供应商内按当前项目最近使用优先排列模型，其余按模型名称排序。
- 未配置密钥、已停用或当前不可运行的模型不进入任何模型选择入口；模型供应商设置继续保留真实配置与不可用原因。
- 任务推送、会话输入区、项目可用模型及默认模型等所有模型选择入口采用同一供应商分组、显示与排序规则。
- 历史模型连接原有名称直接作为供应商名称保留，不猜测、不重写；用户可以在设置页修正。
- 模型行以模型名称为主，并继续显示高速、Flash 或 Turbo 等速度标签；不显示供应商、连接、服务地址或 Agent。
- 搜索模型后继续保留供应商分组；搜索范围包含供应商名称、模型名称和模型 ID，不搜索服务地址或密钥信息。

## 实现结果

- 新增统一模型展示层，负责过滤不可运行模型、按当前选择优先排序、合并同名供应商分组、生成速度标签和“供应商 / 模型”收起态文案。
- 任务推送、进行中会话、新会话、代码审查、项目可用模型与默认模型均复用统一展示层。
- 会话紧凑下拉支持供应商分组与搜索；通用下拉搜索补充供应商名称、模型名称和模型 ID。
- 模型供应商设置中的“连接名称”已改为“供应商名称”；历史数据继续读取原 `name` 字段，不迁移、不猜测。
- 本地服务在生成项目会话能力时过滤不可运行的 Pi 模型；供应商管理目录仍保留配置、密钥状态和能力原因。
- 选择、持久化与派发仍使用“连接 ID + 模型 ID”的复合身份；展示层没有改写 Agent 或运行路由。

## 方案权衡

- 优点：多供应商时可以先按实际接入和计费渠道定位模型；单供应商时保持紧凑，不把账号和接口细节带进常用选择器。
- 缺点：新增第二个供应商后列表会增加一层标题；按已确认口径，同一供应商内跨连接的同名模型在界面上仍然无法区分，但后台不会串用身份。
