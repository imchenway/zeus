# ZEUS-0093 已完成的任务查看详情

## 当前阶段

已完成实现、整仓静态检查、构建、测试身份打包和隔离界面验收。

## 任务目标

已完成或已取消的任务继续保留任务详情和关联会话入口。归档会话可以读取完整历史，但不能继续发送、重试、编辑消息或处理待交互请求。用户需要继续时，必须在同一个动作中重新打开任务并取消归档当前选中的会话。

## 源码事实

- 任务会话选择接口原先只读取 `archived = 0`，任务详情又二次过滤归档项，因此完成任务后看不到被终态清理归档的会话。
- 原生会话工作区可以读取归档会话快照和完整消息，但归档线程仍保留恢复入口；只隐藏任务详情行不足以阻止通过会话接口继续。
- 任务终态清理会归档该任务当前未归档的会话并回收 worktree。恢复原生任务会话时会重新建立可验证的任务执行目录，因此恢复动作不能脱离任务重新打开单独执行。
- 项目允许自定义任务管理状态；完成、取消和默认重新打开状态必须读取项目状态角色，不能写死枚举值。

## 实现边界

1. 任务会话历史接口合并读取未归档和已归档记录，继续按会话阶段时间稳定排序；普通会话树仍只展示未归档会话。
2. 任务处于项目配置的完成或取消状态时，任务详情展示归档关联会话并标明“已归档”，同时禁用“推送到新会话”。
3. 点击归档会话后仍加载真实原生快照和完整历史；会话顶部显示终态只读说明，隐藏 composer、待交互区和队列操作，并关闭消息编辑、重试、浏览器评论提交及轮次变更写操作。
4. “重新打开任务并继续”把任务改回项目默认状态，只恢复当前选中的归档会话。其他历史会话继续归档，避免一次重新打开产生多条活跃线程。
5. 用户直接从任务状态下拉把终态改为非终态时，服务端恢复最近一条归档会话；没有归档会话时只修改任务状态。
6. 服务端拒绝终态任务直接创建会话、发送消息、恢复 Provider 线程、恢复归档记录、运行或继续 Runtime。恢复执行目录也检查终态任务，界面不是唯一门禁。
7. 重新打开先复验任务版本和会话归属，再恢复会话并同步修改任务状态；恢复期间若任务版本变化，会补偿归档会话并再次清理恢复出的终态资源，不留下可继续对话的半状态。
8. 从任务详情显式打开的归档会话会作为当前焦点保留在会话工作区；普通会话分组接口后续刷新时不会把它抹掉。离开该会话或重新打开成功后，临时焦点随即清除，普通会话树不会长期混入全部归档记录。

## 取舍

### 只恢复当前会话

- 优点：用户明确知道接下来在哪条上下文中继续，普通会话树不会一下出现多条旧线程，并发写入风险更低。
- 缺点：如果用户想改在另一条历史会话中继续，需要重新结束任务后再选择，或后续通过明确的会话切换能力处理。

### 状态下拉恢复最近会话

- 优点：保留现有任务状态编辑习惯，重新打开不会产生“任务已开放但没有任何可继续会话”的割裂状态。
- 缺点：状态下拉没有显式选择会话，因此只能采用最近归档会话；需要精确选择时应先打开目标归档会话，再点击重新打开。

### 不采用批量取消归档

- 优点：不会把一个任务的全部历史线程重新放回活跃列表，也不会同时重建多个任务工作目录。
- 缺点：其余历史会话继续只读归档，不能在一次动作中全部恢复。

## 验收口径

- 完成或取消任务的详情中可以看到全部归档关联会话，标题、模型、时间和消息历史保持真实。
- 打开归档会话后没有发送、重试、编辑、审批、排队恢复或会话写入入口，并清楚说明恢复条件。
- 点击“重新打开任务并继续”后，任务回到项目默认状态，当前会话取消归档并恢复输入区；其他归档会话保持归档。
- 直接把任务状态从终态改为非终态时，最近归档会话同步恢复。
- 单独调用会话恢复、发送、任务运行或继续接口时，终态任务返回 `ZEUS_TASK_REOPEN_REQUIRED`。
- 会话恢复失败、任务版本冲突或执行目录无法安全恢复时，任务状态保持终态，不显示虚假成功。
- 静态检查、构建、测试身份打包和真实界面检查分别记录，不互相替代。
