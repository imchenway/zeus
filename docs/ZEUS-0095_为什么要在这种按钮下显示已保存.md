# ZEUS-0095 为什么要在这种按钮下显示已保存

## 问题

任务表格的“优先级”下拉框在修改成功后，会在控件下方额外显示“已保存”。这条文字不提供新信息：下拉框中已经显示服务端确认后的最终值，额外文案反而会抬高当前行、打破表格对齐，并让每次修改都产生短暂的布局跳动。

## 产品口径

- 保存中：在当前下拉框右侧显示小型加载动效，并临时禁止重复选择。
- 保存成功：只保留最终优先级值，不再显示“已保存”。
- 保存失败：保留用户所选值，在控件下方显示失败原因和“重试”。
- 并发冲突：保留用户所选值，显示“重试”和“载入最新”，禁止静默覆盖。

## 方案权衡

### 优点

- 成功后表格行高保持稳定，优先级列与其他列继续对齐。
- 加载动效和当前操作的控件绑定，不需要用额外文字解释。
- 失败和冲突仍然显式展示，错误恢复能力不变。

### 代价

- 成功后不再有额外文字确认，用户需要通过最终值和加载动效结束来判断保存已完成。

## 实施记录

- `apps/desktop/src/renderer/task/TaskWorkspace.tsx`：去除优先级的成功文字反馈，保存中改为控件内加载动效，失败和冲突处理保持不变。
- `apps/desktop/src/renderer/styles.css`：为表格优先级控件提供加载动效定位，保存时用动效替代下拉箭头。
