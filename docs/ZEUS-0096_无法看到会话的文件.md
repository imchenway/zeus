# ZEUS-0096 无法看到会话的文件

## 任务问题

用户在任务会话执行期间曾看到模型修改的文件，离开后重新打开同一会话时，轮次底部不再显示文件变更卡。用户未保留精确复现步骤，任务附件只有一张受影响会话的截图。

## 现场取证

- 根据截图中的唯一回复文本，在当前正式数据的在线备份中反查到原会话 `conversation_5ddfbb0c952250ff019e5d89`。
- 截图对应轮次 `019fd010-97ed-78a0-84cc-37368da22a4f` 持久化了 16 条 `fileChange`，包含两张 HTML 指南图和任务文档的真实路径与 diff。
- 同一轮次的 `turn_change_sets` 记录却停在 `capturing`，`turn_change_files` 为 0，因此历史快照不会投影轮次变更卡。
- 该轮次执行目录是任务 worktree，而当时的变更集采集以项目主目录做路径边界。worktree 中的绝对路径全部被拒绝，只留下了由 `turn/diff/updated` 预先创建的空 `capturing` 记录。
- 后续提交 `0654f35` 已把新轮次采集改为使用会话真实执行目录，但没有补齐此前已经持久化的空变更集。

## 根因

这不是文件本身被删除，也不是会话消息丢失。真实失败链是：

1. 运行中的 provider 事件让界面短暂显示文件变更活动；
2. Local Server 使用错误的项目主目录校验 worktree 路径，没有形成可回放的文件变更集；
3. 重新进入会话时，Renderer 只从持久变更集显示轮次文件卡，空的 `capturing` 记录被隐藏；
4. 数据库仍保留完整 `fileChange` payload，但当前历史恢复链路没有使用这份事实做可见性降级。

## 修复方案

在会话快照组装阶段增加历史文件变更投影：

- 正常完整的持久变更集仍是唯一权威来源；
- 只对已终止轮次中“不存在变更集”或“变更集仍为 `capturing` 且没有文件”的异常历史做降级投影；
- 从已持久化的 `fileChange.changes` 还原文件路径、变更类型、增删行数和 unified diff，同一路径多次修改按轮次聚合；
- 只接受位于该轮次持久执行目录内的路径，不把不受信的 provider 绝对路径直接交给 Renderer；
- 投影状态固定为 `unavailable`，明确说明“历史轮次保留了变更记录，但缺少可安全撤销的文件快照”；
- Review 可查看已持久化的真实 diff，Undo / Reapply 保持禁用。

优点：旧会话重新进入后可以看到真实文件列表和差异，又不会伪造已丢失的恢复快照。

代价：受影响的历史轮次只能审查，无法安全撤销或重新应用；查看已被回收的 worktree 时，源码跳转也可能因目录不存在而不可用。

## 验证结果

- 使用隔离数据库调用完整会话快照接口：受影响轮次返回 `unavailable`；同一会话后续已有完整快照的轮次仍为 `applied`，5 个聚合文件继续支持撤销，没有被降级投影覆盖。
