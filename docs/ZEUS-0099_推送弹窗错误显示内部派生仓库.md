# ZEUS-0099 推送弹窗错误显示内部派生仓库

## 现象

Zeus 项目的“推送到新会话”弹窗把 `.tmp/zeus-release-isolated/<commit>` 下的多个发布隔离副本列为项目仓库，并要求逐仓选择来源分支和新分支。

截图中的目录不是任务 worktree，而是发布脚本通过 `git clone --shared` 创建的完整 Git 副本。产品语义上两者都属于 Zeus 自己生成的内部工作目录，不应暴露为用户业务仓库。

## 根因

任务推送会在打开弹窗时递归扫描项目容器内的 Git 根。扫描器已经排除 `.zeus-worktrees`、依赖目录和构建产物，但没有排除 `.tmp`，因此继续进入 `.tmp/zeus-release-isolated` 并把其中的每个发布副本识别为独立仓库。

## 确认边界

- 仓库发现只展示用户业务仓库。
- Zeus 自己生成的内部目录至少排除 `.tmp` 与 `.zeus-worktrees`。
- 项目容器中的真实嵌套业务仓库继续独立发现，不能因为项目根本身是 Git 仓库就停止递归。

### 优点

- 推送弹窗只保留真实业务仓库，不再为发布副本创建无意义的任务分支和工作区。
- 继续兼容 PIM 等父仓、子仓并存的真实多仓项目。

### 代价

- 用户若刻意把业务仓库存放在项目容器的 `.tmp` 中，该仓库不会被自动发现；`.tmp` 在 Zeus 项目内统一视为内部临时边界。
- 后续新增其他内部派生目录时，仓库发现排除清单也需要同步维护。

## 实现

- `packages/git-core/src/index.ts`：仓库递归发现跳过 `.tmp`；原有 `.zeus-worktrees` 排除继续保留。
- `CONTEXT.md`：补充“内部派生仓库”定义，明确它不属于任务推送的项目仓库集合。

## 验证记录

- `pnpm lint`：通过。
- `pnpm typecheck`：通过。
- `pnpm build`：通过，包含全部工作区包、Renderer、Preload 与 Electron Main。
- `ZEUS_PACKAGE_OUTPUT_DIR=dist/zeus-0099 pnpm package:mac`：通过，生成独立测试身份 `Zeus Test.app` 和 DMG；应用签名结构校验通过，未启动或改动 `/Applications/Zeus.app`。
- 使用构建后的 `@zeus/git-core` 扫描真实 Zeus 项目，只返回根仓库 `.`；`.tmp/zeus-release-isolated` 下现存的 8 个发布隔离副本均未返回。
- 使用同一产物扫描真实 PIM 多仓项目，仍返回根仓与 13 个嵌套业务仓库，共 14 个仓库，证明真实父子仓发现未被截断。
