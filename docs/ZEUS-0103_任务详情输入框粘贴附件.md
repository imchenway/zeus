# ZEUS-0103 任务详情输入框粘贴附件

## 任务目标

让任务详情中的文本编辑框与创建任务表单保持一致：普通文字正常粘贴，图片、文件、文件夹和超长文本自动转为任务附件。

## 已确认范围

- 覆盖标题、需求描述、缺陷现状、缺陷预期、复现步骤、优化现状、优化预期和标签。
- 粘贴附件完成本机校验后立即关联任务，文字草稿仍按原有失焦规则独立保存。
- 附件保存期间保留当前文字草稿、选区和焦点；保存成功后推进输入框使用的任务版本。
- 资源处理失败时保留文字草稿，显示明确错误并允许重试。
- 不改变添加附件按钮、附件预览、移除关联和撤销移除。

## 事实与根因

- 创建任务表单已经接入任务资源管线，覆盖 DOM 粘贴、Finder 与 Paste.app 原生剪贴板兜底、文件授权和超长文本物化。
- 任务详情使用 `InlineTaskTextField` 做即时编辑；当前控件只有文字变更、键盘和失焦保存，没有资源粘贴入口。
- 任务附件保存会推进 `updatedAt`。若输入控件继续使用粘贴前版本，后续失焦保存会产生本窗口自触发的伪冲突。

## 方案与取舍

采用现有任务资源桥接能力，由任务详情负责收集粘贴资源并立即更新附件关联；编辑控件只负责拦截粘贴、保留文字选区，并接收附件保存后的最新任务版本。

优点：复用现有本机安全边界，创建与详情行为一致，不需要新增附件存储或第二套剪贴板协议。

代价：附件与文字采用两个保存时点；实现必须在附件保存后同步字段版本，并处理没有 DOM 粘贴事件的快捷键兜底。

## 验收口径

- 普通短文本仍进入当前光标位置。
- 图片、文件、文件夹和至少 5000 字符的文本自动成为任务附件。
- 没有 DOM 粘贴事件的 Finder 或 Paste.app 场景仍能新增附件，并且不会重复新增。
- 粘贴附件后输入框保持编辑状态，已有文字和选区不丢失。
- 随后失焦保存文字时不出现由本次附件更新造成的冲突。
- 资源处理失败时草稿不丢失，错误可见并可以重试。
- 执行 `pnpm lint`、`pnpm typecheck`、`pnpm build`；静态检查成功不等于真实运行验收完成。

## 实施记录

- `apps/desktop/src/renderer/task/TaskDetailPaneContent.tsx`
  - `InlineTaskTextField` 接入 DOM 粘贴与 `Cmd/Ctrl + V` 原生剪贴板兜底；正常 paste 到达后取消兜底，避免重复新增。
  - 标题、当前任务类型专属内容和标签统一接入资源粘贴。
  - 短文本按原选区回填；附件粘贴不改动文字草稿和选区。
  - 任务详情优先读取原生剪贴板资源，失败时回退 DOM 文件；超长文本使用既有任务资源物化能力。
  - 附件立即保存并把最新 `updatedAt` 回传编辑控件；应用层既有任务更新队列继续串行化并发字段修改。
  - 资源读取、物化和保存失败时保留草稿，并复用附件区错误与重试入口。
- `apps/desktop/src/renderer/task/taskAttachments.ts`
  - 提取任务资源载荷和授权结果类型，供创建任务与任务详情共用。
- `apps/desktop/src/renderer/App.tsx`
  - 把现有任务文件授权、资源物化和原生剪贴板读取能力传给任务详情，不新增 IPC 或附件存储。
- `CONTEXT.md` 与 `DESIGN.md`
  - 记录任务编辑中的待提交资源，以及附件立即关联、文字草稿独立保存的产品边界。
