# ZEUS-0104 进行中会话切入后显示真实最新内容

## 任务目标

修复点击进行中会话后，界面仍需要手动点击“返回最新消息”或手动滚动，且最新内容下方出现大块空白的问题。

## 已确认产品口径

- 每次打开或重新切回已有会话，都直接显示真实最新消息，不恢复上一次的历史阅读位置；
- 切入一个已经在执行的会话时，不把已有活动轮次误判为当前页面刚开始的新轮次；
- 用户已经停留在同一会话时，新轮次开始仍保留现有的预留回复空间；
- 用户主动向上阅读历史后仍暂停自动跟随，并保留“返回最新消息”入口。

优点：切回进行中会话时，整个可用视口用于展示真实最新内容，不再让临时空白成为滚动底部。

代价：切入已经执行中的会话时，不再保留新轮次刚开始时用于承接后续回复的预留空白；该空白只服务于用户停留在当前会话期间真正开始的新轮次。

## 根因

- 会话工作区按会话 ID 使用 React `key` 隔离，每次切换都会创建新的 `ConversationTranscript`；滚动控制器不会继承上一会话状态。
- 新组件挂载后，`previousTurnIdRef` 初始为空。首次历史快照如果已经包含 `activeTurnId`，轮次监听会把这个既有活动轮次当作刚开始的新轮次。
- 错误的新轮次判定会注入至少 `240px`、通常约三分之二视口高的 `session-latest-turn-spacer`，再把滚动位置放到 spacer 末端。
- 因此 DOM 的“底部”与用户理解的“真实最新消息”不再一致：最新内容只占视口顶部一小段，其余区域是空白，后续跟随和“返回最新消息”判断也围绕错误底部工作。

## 实现方案

- 等待首次历史快照可用后，把快照中的活动轮次登记为当前会话基线，不触发 `onTurnStarted`；
- 首次登记同时清除待定位标记和临时 spacer，首次无动画底部定位继续使用现有逻辑；
- 完成首次登记后，只有同一已打开会话中的 `activeTurnId` 真正变化时，才执行原有的新轮次预留空间逻辑；
- 不修改 provider、Reducer、数据库、消息顺序、流式正文或底部距离阈值。
