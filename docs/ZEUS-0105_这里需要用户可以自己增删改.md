# ZEUS-0105 这里需要用户可以自己增删改

## 当前阶段

需求澄清中。尚未进入设计、计划或实现。

已确认“增删改”针对任务管理状态，不针对 Coding Agent 运行状态。

## 原始需求

- 任务标题：这里需要用户可以自己增删改
- 任务类型：需求
- 需求描述：还需要可以自己配置选项框的颜色
- 批注位置：全局设置中的“任务列表 / 枚举值升序规则”，当前包含优先级、管理状态和运行状态三组固定值。

## 已核对事实

- 当前页面只允许调整三组枚举的升序先后，降序使用反向顺序，配置对所有项目生效。
- 优先级是固定的 P0 至 P4；它只表达处理顺序。
- 管理状态是任务交付阶段，参与状态筛选、批量修改和完成／取消时的终态清理。
- 运行状态来自关联会话与 Coding Agent 的真实运行事实，不是用户填写的任务字段。
- 三组值当前都由固定 TypeScript 联合类型、校验函数、格式化文案和业务分支共同约束，不是普通的自由文本选项。
- 任务表已为优先级、管理状态和运行状态提供低饱和语义色；颜色不是唯一识别方式。

## 需要确认的产品边界

### 底层枚举与展示配置（已确认）

用户确认这里的可增删改对象是任务管理状态。任务管理状态允许新增、重命名和删除符合条件的自定义状态；优先级和 Coding Agent 运行状态不开放底层值增删，继续保留各自固定业务语义。

优点：用户可以按自己的交付流程维护任务阶段，运行状态仍忠实反映系统事实，P0 至 P4 仍保持稳定含义。

缺点：三组设置的能力不完全对称，界面必须清楚解释只有任务管理状态支持真正增删。

用户拒绝“内置状态不可删除”的方案，明确要求任务状态在编辑能力上等同，不区分内置状态与自定义状态。

这与当前产品行为存在冲突，仍待确认“等同”是否只指增删改、名称、颜色和排序等配置权利相同，还是连默认状态、首发自动迁移、未完成筛选和终态清理等业务语义也全部取消。当前代码中的特殊语义包括：

- 新任务需要一个默认管理状态。
- 任务首发成功时会从“待开始”自动进入“开发中”。
- “已完成”和“已取消”共同定义“未完成”筛选的排除范围。
- 进入“已完成”或“已取消”会触发任务终态清理。

### 状态与系统角色分离（已确认）

- 所有任务管理状态都拥有完全相同的新增、修改、删除、改色和排序能力，不保留不可删除的内置状态。
- 现有的新任务默认状态、任务首发后状态、点击完成／取消后的效果、未完成筛选和终态清理全部保持，不重新设计这些行为。
- 不新增一套要求用户维护的“系统角色”设置界面。
- 状态名称和颜色变化不影响其当前承接的系统行为。
- 删除承接现有系统行为的状态时，用户选择的替代状态在迁移已有任务的同时接续原状态行为，避免现有功能失效。

优点：用户真正拥有状态集合，同时不需要理解或维护额外设置，现有任务自动化保持原样。

缺点：删除正在承接现有行为的状态时，替代迁移需要同时更新任务和行为绑定，必须保证整体成功或整体不变。

### 配置作用域（已确认）

- 每个项目独立拥有任务管理状态集合、顺序、颜色和系统角色指派。
- 全局设置保存一套新项目默认状态模板；创建新项目时复制模板，之后成为项目自己的配置。
- 修改全局模板不自动追改已有项目，避免项目进行中途被其他项目的流程调整影响。

优点：不同项目可以使用不同交付流程，已有项目的筛选、统计和自动流转保持稳定。

缺点：需要统一调整多个已有项目时必须逐个修改，或另行提供明确的批量应用能力。

### 颜色配置（已确认）

- 每个任务管理状态只保存一个由用户选择的主色。
- Zeus 根据主色自动派生浅色和深色主题下可读的低饱和背景、文字和边框，不要求用户分别配置三套颜色。
- 同一状态颜色统一用于任务列表标签、创建任务与编辑状态下拉框、任务详情和状态设置预览。
- 状态文字始终保留，颜色不作为唯一识别方式。

优点：颜色配置简单，全入口一致，并能集中保证主题适配和文字可读性。

缺点：高级用户不能分别微调背景、文字和边框；自动派生可能与输入主色存在轻微视觉差异。

### 删除与历史任务迁移（已确认）

- 删除未被任何任务使用的自定义管理状态时可以直接删除。
- 删除正在被任务使用的管理状态时，用户必须先选择一个替代状态。
- Zeus 先把引用原状态的任务统一迁移到替代状态，迁移成功后再删除原状态，不产生无状态任务。

优点：历史任务始终有明确状态，筛选和统计不会因为删除选项而漏数据。

缺点：删除使用中的状态需要多一步选择，批量迁移失败时必须保留原状态并允许重试。

### 颜色范围

尚待确认颜色配置作用于任务列表标签、任务详情和创建／编辑下拉框中的哪些入口，以及颜色是全局配置还是支持项目覆盖。

### 删除后的历史数据

若用户确认需要真正删除可选值，必须继续确认已有任务正在使用该值时的迁移目标、禁止删除规则和恢复默认策略，不能静默把数据变为空值。
