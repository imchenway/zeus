# ZEUS-0114 未登录状态优化

## 任务信息

- 任务类型：优化
- 现状：网页登录完成后，网页显示“打开 ChatGPT”，但 Zeus 专属 Codex 的登录验证实际上已经成功。
- 预期：待用户确认。
- 当前阶段：实现完成；静态、构建和测试包验证通过，真实网页登录往返待界面控制能力恢复后验收。

## 已确认事实

1. Zeus 在任务推送弹窗发现 Codex 未登录后，通过 `account/login/start` 启动官方 ChatGPT 浏览器登录。
2. 当前请求显式携带 `useHostedLoginSuccessPage: true` 和 `appBrand: 'chatgpt'`，因此认证完成页把后续动作表达为打开 ChatGPT，而不是返回 Zeus。
3. Zeus Renderer 每 800 毫秒读取一次权威账号状态；一旦 `signedIn=true`，就会保留原模型、工作区、权限和补充信息，并自动继续创建会话。
4. 当前网页文案错误不代表认证失败，也不代表 Zeus 需要用户点击“打开 ChatGPT”才能完成登录。
5. 本机 `codex-cli 0.147.0` 生成的 app-server 协议中，`appBrand` 只允许 `codex` 或 `chatgpt`，没有 `zeus` 或自定义品牌值。
6. 关闭托管成功页会进入 Codex 自带的本机完成页。该页面会显示“已登录，可以关闭标签”，但仍提供“打开 Codex”并尝试打开 `codex://threads/new`，不能直接回到 Zeus。
7. OpenAI 公开文档没有说明 `useHostedLoginSuccessPage`、`appBrand` 或第三方产品自定义登录完成页的能力；当前判断来自本机真实协议和二进制页面内容，不把未公开能力假设为可用。

## 真实链路

1. 用户在 Zeus 点击“登录并继续”。
2. Zeus 请求 Codex app-server 创建登录任务并取得 HTTPS 登录地址。
3. Electron Main 复验 HTTPS 地址后交给系统浏览器。
4. 用户在官方网页完成认证。
5. Codex app-server 写入 Zeus 专属 Codex 账号状态。
6. Zeus 轮询读取到账号已登录，自动继续原任务推送。
7. 外部网页仍按 `chatgpt` 品牌显示“打开 ChatGPT”，造成用户误以为还需要进入另一个产品。

## 方案比较

### 方案 A：认证成功后自动激活 Zeus，并在原弹窗内明确收口（推荐）

做法：保持官方系统浏览器认证；Zeus 检测到权威账号已登录后，自动把 Zeus 窗口带回前台，在原弹窗短暂显示“登录成功，正在继续创建会话”，然后继续既有流程。外部网页不再承担 Zeus 的完成引导。

优点：

- 不读取、代理或改写认证凭据，保留官方登录安全边界。
- 用户不需要理解或点击错误的“打开 ChatGPT”。
- 不依赖未公开的第三方品牌或自定义回跳协议。
- 与当前自动继续创建的实现一致，改动集中且可回退。

代价：

- 系统浏览器中的官方成功页仍然存在，Zeus 无法安全替第三方网页关闭标签。
- 自动激活应用可能打断用户正在浏览器中进行的其他操作，需要只在本次登录任务仍有效且账号首次转为已登录时触发一次。

### 方案 B：把成功页品牌从 ChatGPT 改成 Codex

做法：继续使用托管成功页，只把 `appBrand` 改为 `codex`。

优点：

- 文案从“打开 ChatGPT”变为“打开 Codex”，与底层 Codex 认证更接近。
- 改动很小。

代价：

- 用户操作的是 Zeus，不是 Codex App；产品归属仍然错误。
- 可能唤起 Codex App，反而增加一次错误跳转。

### 方案 C：关闭托管成功页

做法：使用 Codex 自带的本机登录完成页。

优点：

- 页面明确提示账号已经登录、可以关闭标签。
- 不再展示“打开 ChatGPT”。

代价：

- 页面仍提供“打开 Codex”，并可能自动尝试 `codex://threads/new`。
- 仍然不能回到 Zeus，且可能制造 Codex App 被意外唤起的问题。

### 方案 D：由 Zeus 代理或改写 OAuth 完成页

做法：接管回调页面或自行托管带 Zeus 深链的成功页。

优点：

- 理论上可以完全控制“返回 Zeus”的文案和动作。

代价：

- 需要侵入官方认证回调，扩大凭据、回调校验和升级兼容风险。
- 当前协议没有正式提供该扩展点，Codex 升级后容易失效。
- 为一个完成页文案问题引入新的认证安全边界，收益不匹配风险，不建议采用。

## 已确认决策

1. 已确认：登录成功后，Zeus 自动回到前台并继续原操作；只允许本次有效登录首次成功时触发一次，避免重复抢占窗口。
2. 已确认：自动回到前台后先显示“登录成功，正在继续”，再进入原会话创建进度；不增加二次确认按钮。
3. 已确认：打开官方登录页前提前说明“完成登录后无需点击网页中的其他按钮，Zeus 会自动返回并继续”。
4. 已确认：把登录完成回交沉淀为 Zeus 发起 Codex 浏览器登录的统一行为；当前只接入真实存在的任务推送入口，后续入口复用同一规则，不在本任务虚构或扩大新入口。

## 已确认的共享理解

- 登录继续由官方网页与 Codex app-server 完成，Zeus 不代理凭据、不改写 OAuth 回调页面。
- 打开网页前明确提示完成后无需点击网页中的其他产品按钮。
- 当前有效登录任务首次读取到权威登录成功时，Zeus 自动回到前台；取消、超时、失败和过期任务不得触发。
- 回到 Zeus 后先显示“登录成功，正在继续”，再自动恢复原配置并继续会话创建，不增加二次确认。
- Zeus 不关闭系统浏览器标签，也不主动打开 ChatGPT 或 Codex。
- 登录完成回交作为统一能力沉淀，当前只接入任务推送。
- 验收必须区分静态检查、测试包和真实 `Zeus Test.app` 浏览器登录往返。

## 领域边界

- “网页登录完成”只表示官方认证网页已经完成授权。
- “Zeus 登录就绪”表示 Zeus 从 Codex app-server 权威读取到专属账号可用。
- “登录流程完成”表示 Zeus 登录就绪已经被当前登录任务接收，并继续用户发起的原操作。
- “登录完成回交”表示 Zeus 在当前有效登录任务首次成功时自动回到前台并继续原操作；重复轮询、过期任务或用户已经取消的登录不得再次抢占窗口。
- 网页上的“打开 ChatGPT”或“打开 Codex”不是 Zeus 登录流程的必要步骤，不能作为 Zeus 成功判定。

## 当前结论

问题根因不是账号验证失败，而是第三方完成页承担了错误的产品收口。实现保留官方认证链路，把完成反馈和回到工作现场的责任收回 Zeus。

## 实现结果

1. Electron Main 新增“激活发起请求窗口”能力，只接受当前受信 Renderer，不能由调用方指定其他窗口；复用既有窗口恢复、显示和聚焦逻辑。
2. Preload 和 Renderer 桥接层只暴露无参数激活方法；非 Electron 预览环境安全降级，不伪造激活成功。
3. 新增统一的 Codex 登录完成回交函数，在每个异步边界复验当前登录请求。用户取消、超时或新登录替代旧请求后，不再激活窗口或继续旧操作。
4. 任务推送弹窗在打开网页前和等待期间说明无需点击“打开 ChatGPT”或“打开 Codex”；权威账号状态成功后，先展示“登录成功，正在继续”，再恢复原配置并创建会话。
5. 窗口激活失败只记录本地错误，不把已经成功的认证改写为失败，也不阻断原任务继续。
6. 保留 `useHostedLoginSuccessPage: true` 和 `appBrand: 'chatgpt'`，没有用“打开 Codex”替换错误跳转，也没有接管官方 OAuth 页面。

## 设计取舍

优点：用户不再依赖网页上的错误产品按钮；认证凭据和回调仍由官方链路管理；过期请求和非受信窗口不能触发焦点抢占。

代价：官方网页标签仍需用户自行关闭；成功后 Zeus 会主动切回前台一次；本次只接入现有任务推送入口，其他未来入口需要显式复用统一回交函数。
