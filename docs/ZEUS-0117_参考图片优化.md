# ZEUS-0117 参考图片优化

## 任务目标

参考用户提供的 Codex 文件编辑授权截图，优化 Zeus 会话底部的文件修改审批卡片。目标是让用户一眼看清“谁要做什么、会改哪些文件、可以选择多大授权范围”，不改变 app-server 的真实审批协议和服务端安全复验。

## 现状判断

- Zeus 已支持 `accept` 与 `acceptForSession`，不需要新增假的“会话级允许”能力。
- 原卡片使用“文件变更 + 影响说明 + 纯文本预览 + 当前模式”的纵向结构，文件目标不够突出。
- 关联式文件审批只在请求中携带 `itemId`，真实路径位于对应 `fileChange` 条目的 `changes` 中；只读请求本身会丢失界面展示所需的路径信息。
- `Escape` 在现有安全规则中不会自动拒绝审批，而是提醒用户明确选择；参考图中的快捷键提示不能直接照搬。

## 方案与取舍

### 采用

- 使用铅笔图标与“编辑文件”建立动作身份。
- 使用“是否允许 Zeus 编辑以下文件？”作为稳定的决策问题。
- 把文件路径放进独立的低对比边框区域，目录降噪、文件名加深；最多直接展示四项，其余显示数量。
- 保留“允许一次”主按钮和向上展开的授权菜单；文件会话级决定显示为“允许所有编辑”，并用信息图标说明真实范围。
- 从当前会话的真实 `fileChange` 条目读取关联路径；路径未到达或无法复验时只保留拒绝、取消，避免用户授权一个看不见的目标。
- 当前权限模式继续显示在卡片头部，避免视觉对齐导致安全上下文丢失。

优点：文件目标和授权范围更易扫描，参考图的层级得到保留，同时没有放宽协议或路径门禁。

代价：路径条目尚未随实时状态到达时，允许按钮会暂时不可用；卡片比参考图多一个低噪音权限模式，因为 Zeus 需要持续表达真实安全状态。

### 不采用

- 不把产品主体写成 ChatGPT，界面继续使用 Zeus。
- 不展示假的 `Escape` 拒绝快捷键。
- 不把 `acceptForSession` 扩大解释为对所有未知新文件永久放行。
- 不复制 Codex 私有代码、品牌资源或内部样式变量。

## 实现记录

- `PendingRequestSurface` 接收关联文件路径并在文件审批中渲染结构化路径列表。
- `SessionWorkspace` 从当前会话权威条目中解析与请求 `itemId` 对应的文件变更路径。
- 文件路径不可见时收紧可用决定，只提供失败关闭操作。
- 样式继续使用会话页现有语义变量，覆盖浅色、深色、窄窗口和键盘焦点状态。
