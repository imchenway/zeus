# ZEUS-0118 需要能看到实际的运行耗时

## 任务信息

- 类型：优化
- 当前阶段：实现与验证完成
- 用户证据：项目命令页“执行历史”详情当前展示“状态 / 超时 / 退出码”，其中“超时 3600s”是配置上限，不是本次实际运行耗时。

## 现场事实

- `CommandRun` 已持久化 `startedAt` 与 `endedAt`，不需要新增数据库字段即可计算实际耗时。
- 命令真正启动时写入 `startedAt`；成功、失败、超时、取消、拒绝及 Zeus 重启中断时均写入 `endedAt`。
- Renderer 对选中的运行中记录每秒重新读取详情，具备实时刷新耗时的现有机制。
- 当前执行详情固定为三列：状态、超时、退出码；执行历史列表只展示创建时间与状态。
- 现有窄窗口断点会把详情指标改为单列，增加指标时仍可沿用现有响应式结构。

## 已确认领域口径

- “超时上限”：命令定义对单次执行允许的最长时间，是配置，不是结果。
- “实际耗时”：从命令真正开始执行到结束的时间差；运行中使用当前时间减开始时间并持续刷新，结束后使用结束时间减开始时间并固定。
- 已确认：等待用户确认不计入实际耗时；从未启动就被拒绝的记录显示“未启动”。
- 已确认：实际耗时同时进入左侧执行历史列表与选中记录的执行详情。

## 方案比较

### 方案 A：详情与列表都展示实际耗时（推荐）

- 优点：浏览历史时无需逐条点开即可比较耗时；详情中又能明确区分结果耗时与超时上限。
- 缺点：左侧列表信息密度上升，需要控制时间、耗时与状态三者的排布。

### 方案 B：只在执行详情展示实际耗时

- 优点：改动和视觉噪音最小，直接解决截图中的语义缺口。
- 缺点：比较多条历史记录时需要逐条打开，执行历史的扫描效率较低。

## 待用户逐项确认

1. 展示范围：已确认选择“详情与列表都展示”。
2. 时间口径：已确认从 Runtime 真正启动时开始，排除等待确认时间。
3. 展示精度：已确认自适应到秒，使用 `12s`、`2m 08s`、`1h 02m 08s` 格式；不足一秒显示 `0s`。
4. 超时信息：已确认保留并重命名为“超时上限”。

## 已确认共享理解

- 左侧执行历史列表和右侧执行详情都显示实际耗时。
- 实际耗时从 Runtime 真正启动开始，运行中逐秒增长，结束后冻结。
- 等待用户确认不计时；从未启动的记录显示“未启动”。
- 使用自适应到秒格式：`12s`、`2m 08s`、`1h 02m 08s`。
- 详情保留超时配置，并把“超时”改为更准确的“超时上限”。
- 直接使用现有 `startedAt / endedAt` 计算，不新增重复持久化字段。

## 实现结果

- `CommandCenterPanel` 新增独立耗时文本组件，只在运行中按秒刷新自身，避免整个命令页面因计时器持续重绘。
- 实际耗时直接使用现有 `startedAt / endedAt` 计算，没有新增数据库字段或重复状态。
- 执行历史列表在创建时间后展示“耗时”；执行详情新增“实际耗时”，原“超时”更名为“超时上限”。
- 结束记录固定使用 `endedAt - startedAt`；运行中使用当前时间；没有 `startedAt` 的记录显示“未启动”；无效时间显示 `—`。
- 详情指标桌面布局由三列调整为四列，窄窗口继续沿用现有单列断点；耗时数字使用等宽数字，减少逐秒刷新时的视觉跳动。
- `CONTEXT.md` 已补充“命令实际耗时”领域词，明确排除确认等待和超时上限。
