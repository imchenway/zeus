# ZEUS-0123 为什么 Zeus 需要申请这么多权限

## 任务信息

- 类型：优化
- 用户现象：macOS 连续询问 Zeus 是否允许访问“下载”“文稿”，并反馈还出现“音乐”等目录授权。
- 目标：Zeus 自己管理的数据不依赖 macOS 受保护的公共目录；只有用户明确选择项目、附件、导入导出位置或要求 Agent 访问该目录时，才由系统询问对应权限。

## 结论

截图不是 Zeus 自己设计的授权弹窗，而是 macOS“隐私与安全 > 文件与文件夹”的目录级保护。Apple 明确把桌面、文稿和下载等位置作为可单独控制的文件夹；音乐等标准媒体目录也有独立能力边界。

本次静态审计确认：

1. Zeus 的签名 entitlement 没有申请下载、文稿、音乐、照片、影片或“所有文件”权限，只有 Electron 运行所需的 JIT、无签名可执行内存和关闭动态库校验三项能力。
2. 内置浏览器却把 macOS 系统“下载”目录作为默认下载位置，并在保存任意浏览器设置时主动创建该目录。这会把本来属于内置浏览器的普通数据路径扩大成系统受保护目录访问。
3. 项目目录、会话附件、任务附件和导入导出仍可能位于文稿、下载或音乐目录。对这些路径的访问是用户明确选择后的业务能力，不能靠屏蔽系统弹窗来伪装成功；拒绝后应按真实权限失败处理。
4. 没有发现 Zeus 主动调用相机、麦克风、照片或 Apple Music API。若“音乐”权限再次出现，需结合触发时正在打开的项目路径或 Agent 命令确认；仅凭现有截图不能把它归因于媒体功能。

Apple 说明：

- [控制 Mac 上文件和文件夹的访问权限](https://support.apple.com/guide/mac-help/control-access-to-files-and-folders-on-mac-mchld5a35146/mac)
- [macOS App Sandbox 文件访问说明](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox)

## 实现方案

### 私有化内置浏览器下载目录

- 新增受 Zeus 管理的 `browserDownloads` 数据路径。
- 分层资料目录使用 `artifacts/browser-downloads`；仍连接旧执行宿主时使用兼容的 `browser-downloads`。
- 新安装和无历史配置的内置浏览器默认下载到该目录，不再默认接触系统“下载”文件夹。
- 历史浏览器配置若仍等于旧版系统默认“下载”目录，会自动切换到新的 Zeus 私有目录。用户之后仍可在设置中明确改回任意绝对路径。
- 保存浏览器的其他设置时不再重复创建下载目录，避免“只改开关也触发文件夹授权”；只有用户明确修改下载路径时才准备新目录。

优点：普通启动、打开设置和保存无关浏览器选项不再需要系统“下载”目录权限；下载产物仍位于清晰、可追溯的 Zeus 资料目录。

代价：升级后旧默认位置中的既有文件不会自动搬走；这是为了避免在修复权限问题时反过来读取受保护目录。用户明确把下载目录设为系统“下载”目录时，保存设置仍可能出现合理的 macOS 授权。

### 不采用的方案

1. 给签名 entitlement 增加下载、音乐等目录权限。
   - 优点：已授权后访问更直接。
   - 缺点：扩大应用能力，不能解释具体业务需要，也与“减少权限”目标相反。
2. 捕获并忽略权限错误。
   - 优点：界面可能少显示一次错误。
   - 缺点：项目、附件或下载会真实失败，属于隐藏故障，不可接受。
3. 禁止用户选择受保护目录。
   - 优点：不会触发对应系统授权。
   - 缺点：Zeus 将无法管理位于文稿、下载等常用位置的真实代码库，破坏核心开发工作流。

## 权限边界

| 场景 | 是否应访问受保护目录 | 产品行为 |
| --- | --- | --- |
| 启动 Zeus、打开或保存普通设置 | 否 | 只使用 Zeus 私有资料目录 |
| 内置浏览器使用默认目录下载 | 否 | 写入 `browserDownloads` |
| 用户把下载目录改成系统“下载”等路径 | 是，用户明确配置 | 保存新路径时交给 macOS 决定 |
| 用户选择项目、附件或导入文件 | 是，用户明确选择 | 只访问所选路径，拒绝后返回真实失败 |
| Agent 主动访问项目外目录 | 仅在任务确有需要并经过现有权限流程时 | 不新增静默全盘权限 |
