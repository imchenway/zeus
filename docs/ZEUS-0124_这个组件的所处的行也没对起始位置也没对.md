# ZEUS-0124 思考摘要行位置与起始位置缺陷

## 任务信息

- 任务标题：这个组件的所处的行也没对，起始位置也没对
- 任务类型：缺陷
- 现状：截图中的活动思考摘要位于对话内容列左侧，并出现在前一组已完成活动与后一组运行中命令之间。
- 预期：用户未提供明确坐标和纵向归属规则，需把确定的水平缺陷与待确认的纵向展示规则分开处理。
- 复现步骤：用户未提供；附件现场来自 `ZEUS-0120` 会话的一轮运行过程。

## 现场证据

1. 红框组件是 `SessionReasoningSummary`，正文来自 Codex JSONL 的 `reasoning.summary`，不是 Zeus 固定加载文案。
2. 截图文案 `Preparing candidate creation with model connections` 对应原生会话事件：思考摘要于 `2026-08-07T06:06:14Z` 到达，后续命令于 `2026-08-07T06:06:24Z` 开始。
3. 当前投影按原生事件顺序保留每轮最后一条思考摘要，所以截图中“思考摘要在上、后续命令在下”与数据时间线一致，不是事件乱序。
4. 对话内容通用规则为直接子项设置最大宽度和水平自动边距；思考摘要自身规则在后方使用 `margin: 0`，同等优先级下覆盖水平自动边距，因此组件退回到滚动区左侧。

## 根因

### 起始位置

`session-reasoning-summary` 把四个方向的外边距全部重置为零，误伤通用消息列提供的水平居中规则。修复应只重置纵向外边距，保留通用行的水平自动边距，不能通过写死像素左边距补偿。

### 所处行

当前实现把思考摘要视为独立时间线项，并保留其原生事件位置。用户截图要求“所处的行也没对”，但尚未说明目标是：

1. 继续按事件顺序独占一行；或
2. 把每轮最新思考摘要移动到该轮当前活动的最末行，作为持续更新的状态行。

两种规则会直接改变长任务过程记录的阅读顺序，不能从“起始位置”缺陷中推导。

## 方案与取舍

### 方案一：保留原生时间顺序，只修正内容列对齐

- 优点：忠实反映“先思考、后执行命令”的真实顺序，改动最小，不会让历史过程看起来倒序。
- 缺点：当后续命令持续执行时，当前摘要会留在命令上方，不一定符合用户对“当前状态行始终在最末端”的视觉预期。

### 方案二：每轮摘要固定跟随该轮最新活动

- 优点：当前处理意图始终靠近最新活动，长任务中更容易看到。
- 缺点：视觉顺序不再等于原生事件顺序；摘要可能从原位置跳到命令下方，历史回看时会产生“先执行、后思考”的错觉。

## 已确认规则

- 用户确认：最新且正在运行的思考摘要必须位于本轮最底部，符合从上到下读取当前进度的视觉习惯。
- 只移动活动轮次的最新思考摘要；已经结束的历史轮次继续保留在各自时间线位置，不统一收拢到会话底部。
- 水平起始位置继续复用与助手正文、命令活动相同的内容列，不写死像素偏移。
