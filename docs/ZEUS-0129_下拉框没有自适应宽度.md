# ZEUS-0129 下拉框没有自适应宽度

## 任务信息

- 任务类型：优化
- 任务标题：下拉框没有自适应宽度
- 实施范围：共享 `ZeusSelect` 浮层，不修改触发器宽度、任务表列宽或业务选项数据。

## 问题与根因

截图中的任务状态下拉浮层宽度与窄触发器相同，选项文字被 `.zeus-select-option-label` 的省略规则裁切。第一轮修复虽然把浮层设为 `max-content` 后读取宽度，但选项行仍为 `inline-size: 100%`，文字列仍为 `minmax(0, 1fr)`，因此父级固有宽度测量仍会被当前窄宽度反向限制。后续字体、尺寸观察或重复布局只会让宽度延迟变化一小段，形成用户看到的“几秒后才改了下宽度”，但仍不能稳定得到最长选项的完整宽度。

## 已确认契约

- 浮层至少与触发器等宽，并按本次打开时的完整选项集合自适应宽度。
- 浮层完成不可见测量后再展示，首次可见时就是最终宽度；任何先窄后宽或延迟横向跳动都视为失败。
- `popoverMinWidth` 继续表示最小宽度，不新增公共属性。
- 浮层最大宽度受视口安全边界限制；达到上限时允许文字省略。
- 触发器和业务布局不随浮层变宽，浮层继续通过 portal 固定定位。
- 不允许选项换行或出现横向滚动；现有上下展开、滚动同步、键盘和焦点行为保持不变。
- 修复覆盖全部共享 `ZeusSelect`，不为任务状态单独增加页面样式。

## 实现记录

- `ZeusSelect` 打开时先保持浮层不可见，进入内部测量态，临时解除选项行百分比宽度、文字裁切和弹性网格列约束，并用隐藏文字节点补齐搜索行的内容宽度。
- 测量完成后恢复普通布局，再按触发器宽度、最小宽度、完整内容宽度和视口上限一次性应用最终宽度与水平坐标；用户首次看到的就是最终尺寸。
- 本次打开期间保留已测得的最大内容宽度，搜索过滤不会让搜索浮层横向跳动；重新打开时重新测量。
- 共享样式只在内部测量态解除裁切，正常显示时继续禁止换行和横向滚动，列表仅允许纵向滚动。
- `DESIGN.md` 同步更新 Select 的 portal、宽度和视口契约。

## 取舍

- 优点：在共享原语内一次修复所有下拉场景，不需要为任务表、详情、设置和弹窗分别增加 CSS 例外，也不会撑开业务布局。
- 代价：首次打开需要一次同步、不可见的内容测量；选项很多时测量成本随当前完整选项数增长。浮层可能明显宽于触发器，极长内容达到视口上限后仍会省略。
