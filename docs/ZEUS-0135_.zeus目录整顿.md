## 对用户两个问题的结论

### 约 2.37 GiB 旧根留着干嘛

旧根长期没有保留价值。它唯一合理的用途是目录迁移过程中的短期回滚源，不能继续作为永久副本。

当前数据库仍有 `4,129` 个受管路径值指向旧根，其中包括终端原始日志、变更快照、命令产物、附件授权和原生会话路径；这些引用对应的 `4,126` 个文件与 `3` 个目录在当前 `.zeus` 都有镜像。副本演练逐文件比较大小和 SHA-256，全部一致。因此正确处理不是“继续留着”，也不是运行中直接删除，而是：停机、迁移当前权威根、重绑路径、完整性校验、记录回滚快照，然后物理回收旧根。

### 目录重新梳理

正式顶层固定为六类，业务模块不得继续在根目录自行加文件：

```text
.zeus/
├── data/       # 数据库、配置、授权密钥、Local Server 日志
├── artifacts/  # 附件、变更快照、Runtime 日志、命令脚本与产物
├── providers/  # Codex、Pi 的原生 Home
├── backups/    # 数据库回滚快照、配置导入备份、旧根回收记录
├── runtime/    # 执行宿主、更新、迁移清单、回收隔离区
└── profile/    # Electron Profile 与 Zeus Browser 状态
```

旧平铺布局只在检测到旧执行宿主仍存活时用于兼容连接；宿主退出后的下一次启动必须迁移，不再把兼容状态当成最终方案。

## 方案与取舍

### 目录迁移

优点：根目录职责固定；Electron 缓存不会再与业务数据库混在一起；执行宿主、更新器和浏览器状态都消费同一登记表；以后清理可以按所有者和生命周期判断。

缺点：绝对路径已经进入数据库，升级必须离线重绑；迁移期间需要额外保留一份当前数据库快照，会短暂增加约 `390 MiB` 占用。

### 旧根回收

优点：镜像逐文件校验后，旧根可以真正物理删除，直接回收约 `2.31 GiB` 实际文件字节；不会继续让两个根相互漂移。

缺点：删除不可逆，所以必须以迁移清单、数据库完整性、零受管旧引用和执行宿主退出作为硬门槛；应用启动不会偷偷自动删除旧根，只允许显式维护流程执行。

### 备份收口

优点：配置备份不再包含插件运行程序、缓存和安装暂存；迁移成功并产生最新数据库回滚快照后，移除已取代的旧数据库备份。副本演练释放 `880,952,682` 字节。

缺点：只保留最新迁移前数据库快照，不再支持回到更早的历史数据库形态；这是用可理解的单一回滚点换取空间确定性。

### Runtime 日志保留与缓存清理

优点：`logRetentionDays` 真正执行；无任务归属、未收藏、已归档或删除并到期的会话先隔离七天；设置页能分别重建代码图谱和清理 Electron 网络缓存。

缺点：日志隔离宽限期内仍占空间；网络缓存清理会产生重新下载成本，但不会清 Cookie、登录状态或站点授权。

## 实施记录

- `ZeusDataLayout` 改为六类分层布局，同时保留只读的 `legacy-flat` 兼容布局和按数据库路径反推布局的底层入口。
- Desktop 启动前执行目录准备；检测到平铺数据库且宿主仍运行时保持兼容，宿主退出后执行带数据库快照和反向文件移动记录的迁移。
- Electron `userData` 指向 `profile/electron`；业务数据根独立传给 Local Server、执行宿主、更新器和资源 Broker。
- 迁移器只重绑明确的路径列和结构化资源字段，不改会话正文、终端正文、补丁或历史命令输出；多行文本即使以绝对路径开头也不会被误判为路径。
- 旧根受管文件先与权威根镜像逐一比较大小和 SHA-256；任一缺失或不一致都会在移动正式文件前终止。
- 数据库路径更新放在事务中；提交后再次执行 `quick_check` 和 WAL checkpoint，仍有受管旧引用时整体失败。
- 旧根回收必须匹配已提交迁移清单、当前数据库健康、两个根均无执行宿主、受管旧引用为零；删除前先改名隔离，失败时恢复原路径。
- 配置导入按用户条目粒度处理 `plugins`，排除 `.plugin-appserver`、`cache`、`.remote-plugin-install-staging`、`.tmp` 和 `.DS_Store`，备份写入恢复清单。
- 日志保留采用 `.retention-quarantine/<transaction>` 和 `pending/committed` 清单，已提交事务七天后才物理删除。
- 设置页把代码图谱投影和 Electron 网络缓存拆成两个动作，网络缓存只调用 `clearCache()`。
