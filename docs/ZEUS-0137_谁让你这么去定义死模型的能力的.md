# ZEUS-0137：移除图片能力前置门禁

## 任务目标

任务推送不再依据 Zeus 本地维护的模型图片能力判断是否允许携带附件。图片是否可用由实际运行内核和模型服务商决定；如果不支持，应在新会话中显示真实运行失败。

## 根因

任务推送弹窗使用 `attachmentInput` 作为附件选择和提交门禁，服务端又把 Codex 固定标记为支持、Pi 固定标记为不支持。Pi 原生推送接口还没有接收附件参数，因此单纯移除按钮禁用会造成附件静默丢失。

## 实施决策

- 删除任务推送模型契约和服务端模型映射中的 `attachmentInput` 能力字段。
- 保留任务附件、父任务附件的服务端路径解析、可信根校验、父任务上下文版本校验和去重逻辑。
- Codex 继续使用原有结构化附件输入；Pi 任务推送将图片读取为图片输入，非图片附件以可信路径引用追加到模型上下文，并保存附件元数据。
- Pi 运行时统一声明可以尝试文本和图片输入，不读取本地 `imageInput` 状态关闭图片入口。底层模型或服务商负责返回支持性错误。
- Pi 运行时错误通过已有失败轮次和会话失败展示链路呈现。附件缺失、路径越权、上传引用未解析等安全或资源错误仍在运行前拒绝。
- 为避免 Pi SDK 同步失败先于协调器登记轮次，运行时错误事件延后一轮微任务投递。

## 范围边界

本任务只调整原生“推送到新会话”链路，不改变普通会话输入框和旧版非 Codex 运行链路的既有限制。图片能力档案仍可作为诊断信息存在，但不得参与本链路的附件选择、提交或运行时输入限制。

## 取舍

优点是模型能力更新无需等待 Zeus 更新固定能力表，用户可以直接得到模型的真实反馈。代价是模型拒绝图片时可能在会话创建后失败，图片转为 Base64 会增加内存和传输开销；Pi 对非图片附件使用路径引用，模型需要通过工具读取文件。
