# ZEUS-0138 代码交付不绑定会话并支持多次提交推送

## 任务结论

代码交付操作不再绑定活动会话，也不把任务分支推送当作合入闸门。用户可以在同一会话和同一任务工作区内按需要多次提交、多次推送、再次提交新变化；界面的 `busy` 只防止同一请求重复点击，不代表提交或推送次数限制。

## 行为规则

- 提交、推送、合入、回收和丢弃不因活动会话数量而被服务端拒绝。
- 活动会话继续写入时，界面显示非阻断提示：本次提交只包含当前已经落盘的内容，后续变化可以再次提交。
- 停止活动会话保留为独立操作，不再是提交、推送或合入前置步骤。
- 任务分支推送是协作和备份动作。任务分支只有本地提交时仍可创建合入候选；合入远端目标时继续刷新并校验目标分支，不读取旧远端记录，也不强制覆盖远端。
- 回收、丢弃以及可能在来源分支交付后回收 worktree 的合入操作，在活动会话存在时先提示风险；用户确认后才执行。
- 冲突、脏工作区、Git 锁、目标分支并发变化、远端非快进、远端刷新失败和远端 SHA 校验失败继续显示真实错误，不自动停止会话、不自动强推、不伪造成功。

## 实现范围

- 桌面端 `TaskGitReviewModal` 和 `TaskGitMergeModal` 移除活动会话与任务分支远端校验对按钮和 readiness 的阻断。
- 本地服务端移除提交、推送、合入、回收和丢弃路由的活动会话写入校验；合入开始和最终确认只保留本地任务 HEAD、目标分支 HEAD、远端目标刷新与真实 Git 安全检查。
- `activeConversationCount`、`remoteVerified` 和 `remoteRefreshError` 仍作为事实状态返回和展示，不新增提交次数、推送次数、会话绑定或迁移字段。
- 任务生命周期终态清理、嵌套 worktree 先子后父、通用高风险 Git 操作策略保持不变。

## 优点与代价

优点：提交和推送回到真实 Git 功能，适合边写边提交、分阶段推送和多人协作；远端临时不可用时仍能保留本地提交现场。

代价：活动会话可能在提交后继续写入，用户需要再次提交；回收、丢弃或来源分支交付可能影响仍在写入的 worktree，因此必须认真阅读风险提示。远端刷新失败时，不能使用缓存状态代替权威远端结果。
