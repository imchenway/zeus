# ZEUS-0141 模型回复期间会话列表保持底部可见

## 任务目标

修复模型流式回复期间，会话列表在用户已经位于底部时不能持续显示最新内容的问题。

## 产品边界

- 用户停留在底部时，模型新内容持续自动跟随，最新内容保持可见。
- 用户主动向上阅读历史后，停止自动跟随，继续显示“返回最新消息”提示。
- 点击“返回最新消息”或发送新消息后，恢复底部跟随。
- 不修改 provider、Reducer、数据库、消息排序或流式正文分块策略。

## 根因

- 会话列表原本使用平滑滚动执行自动跟随。平滑滚动产生的 `scroll` 事件会被统一当成用户滚动处理，回复增长较快时可能把跟随状态误切为历史阅读状态。
- `ThreadItemView` 的自适应流式正文会在子组件定时提交可见文本。父级只监听 provider 的 `transcriptRevision`，因此子组件提交后高度变化可能没有再次触发底部定位。

## 实现记录

- 将滚动控制器中的显式最新内容请求抽象为 `onExplicitLatestRequest`，发送消息和“返回最新消息”共用恢复跟随状态。
- `ConversationTranscript` 统一使用即时定位处理自动跟随，并在布局提交阶段处理 transcript 更新。
- `ThreadItemView` 在可见流式文本提交后调用父级回调，覆盖自适应分块造成的异步高度变化。
- 保留现有底部距离阈值和历史阅读提示逻辑；不新增 CSS 视觉组件。

## 验证记录

- 依赖：执行 `pnpm install --offline --frozen-lockfile` 成功；安装过程只报告既有 workspace bin 警告和被忽略的构建脚本提示。
- 静态检查：`git diff --check`、变更文件 Prettier 检查、`pnpm lint`、`pnpm typecheck`、`pnpm build` 均通过。
- 测试包：`pnpm package:mac` 通过，生成 `dist/test/mac-arm64/Zeus Test.app`；包内 `CFBundleIdentifier` 为 `dev.hypha.zeus.test`，`codesign --verify --deep --strict` 通过。
- 独立 Renderer：使用从现有测试数据库只读备份得到的独立用户数据目录启动测试身份，数据库 `PRAGMA quick_check` 为 `ok`。打开已有会话后，初始最新消息位于底部且未显示提示；通过真实界面向上滚动“对话记录”后，辅助功能树出现“返回最新消息”按钮，截图也显示该提示；点击按钮后提示消失，最新消息重新位于底部。
- 会话切换：从已有会话切换到另一条会话成功，目标会话正文和发送区正常展示，未观察到界面崩溃。
- 流式阻断：尝试从项目级新会话和已有工作区会话提交真实流式验收消息时，独立运行环境均返回“Zeus 专属 Codex 尚未登录。请先完成登录，再创建会话。”，因此无法取得真实 Provider 流式增量、底部距离连续采样、自适应分块延迟提交和后续流式跟随证据。该阻断不影响上述 Renderer 历史阅读分支证据，也不将静态检查或打包结果冒充为流式验收。
