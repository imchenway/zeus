# ZEUS-0143 代码交付弹窗误报任务工作区不存在

## 任务目标

修复代码交付、提交和推送弹窗在关闭后保留上一任务瞬态状态的问题。为新任务打开弹窗时，只允许展示和请求当前任务所属工作区；服务端现有任务、项目和工作区归属校验保持不变。

## 现场与复现

截图中的弹窗标题属于 CSS 项目的 `ZEUS-0036`，但分支区域显示了 Zeus 项目任务 `ZEUS-0102` 的 `zeus/ZEUS-0102-task-01`。只读核对正式数据库后确认，两条任务工作区记录的持久归属均正确，没有发生数据库串写。

复现链路：

1. 为任务 A 打开代码交付、提交或推送弹窗，读取任务 A 的工作区与文件。
2. 关闭弹窗；组件仍保留任务 A 的工作区、选中文件、差异和错误等 React 状态。
3. 为任务 B 再次打开同一弹窗；新任务加载完成前，旧状态先参与渲染和副作用。
4. Renderer 使用“任务 B ID + 任务 A 工作区 ID”请求文件差异，服务端归属校验返回 `ZEUS_TASK_WORKSPACE_NOT_FOUND`。
5. 随后的有效加载不会可靠清除旧请求留下的全局错误，因此界面底部持续显示英文报错。

## 根因与修复

`TaskGitMergeModal` 与 `TaskGitReviewModal` 长期挂载在应用壳层，组件自身只在关闭时返回空界面，没有卸载持有状态的组件实例。按任务变化执行的加载副作用虽然会请求新快照，但不能阻止同一渲染周期中的旧状态先触发文件差异或冲突请求。

修复采用 keyed 子实例边界：

- `TaskGitMergeModal` 只在打开且任务存在时挂载有状态内容，并以任务 ID 作为 key。
- `TaskGitReviewModal` 以任务 ID、入口模式和首选工作区 ID 组成上下文 key。
- 关闭、切换任务或切换提交与推送入口时，React 卸载旧实例；现有副作用 cleanup 同时使旧异步回调失效。
- 两个弹窗补充 `ZEUS_TASK_WORKSPACE_NOT_FOUND` 的简体中文恢复提示，用于工作区确实被外部回收或删除的真实情况。
- 本地服务端 `resolveTaskWorkspaceRequest` 不修改，跨任务工作区请求仍然返回 404。

优点：状态生命周期与任务身份一致，首次加载不再显示或请求上一任务数据，两个同构入口一次收口。

代价：关闭弹窗会清除未持久化的文件选择、临时反馈和未保存界面草稿；持久 Git 提交、工作区和合入记录不受影响。
