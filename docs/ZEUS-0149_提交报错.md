# ZEUS-0149 提交报错

## 任务结论

代码交付提交前的 Prettier 调用已改为使用当前 Zeus 进程的 Node 运行时直接启动项目本地 Prettier JavaScript 入口，不再执行依赖外部 `node` 命令的 `node_modules/.bin/prettier` shell 包装器。

## 问题证据

- 复现任务工作区中的 `node_modules/.bin/prettier` 是 pnpm 生成的 shell 脚本，脚本最后执行 `exec node .../prettier.cjs`。
- 在不包含 Node 安装目录的 PATH 下直接运行该脚本，实际得到：`line 20: exec: node: not found`。
- Zeus 的代码交付由 Electron Node 宿主执行；该宿主自带可用的 `process.execPath`，但从 Finder 启动时不保证外部 Node 命令出现在 PATH 中。

## 处理方案

- 保留任务工作区和同仓库主工作区的本地 Prettier 查找顺序。
- 从本地 Prettier 包的 `bin` 字段解析 JavaScript 入口；pnpm shell 包装器只作为发现入口，不再作为执行入口。
- 通过 `process.execPath` 启动 Prettier；当前进程是 Electron 时向子进程传递 `ELECTRON_RUN_AS_NODE=1`。
- 保留原有 `--write`、`--check`、`.prettierignore`、选中文件范围和失败阻断提交语义。

优点：不依赖用户是否从终端启动 Zeus，也不改变项目实际使用的 Prettier 版本；普通 Node 环境和 Electron 环境共用同一套调用方式。

代价：需要本地 Prettier 包仍然存在且能解析其 `bin` 入口；依赖缺失或包结构损坏时会继续明确阻断提交。
