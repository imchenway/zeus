# ZEUS-0150 点击代码交付直接显示旧冲突

## 任务目标

修复任务详情点击“代码交付”后，被历史未解决冲突直接带入三方编辑器，导致用户无法先进入代码交付主界面查看或切换其他任务分支的问题。

## 现场与根因

当前弹窗打开时会同时读取任务工作区和历史合入记录，并主动寻找任意一条 `conflicted` 或 `pending_local_sync` 记录：

1. 把该记录对应的工作区强制设为当前选中分支；
2. 把该记录直接写入当前合入状态；
3. 只要记录仍为冲突态，就用三方冲突编辑器替换整个代码交付主界面。

因此，旧冲突既抢占了入口页面，也抢占了默认分支。另一个分支并非没有代码，而是分支列表和差异主界面被旧冲突页面遮住了。

## 产品边界

- 每次从任务详情打开“代码交付”，首屏都必须是代码交付主界面。
- 历史冲突仍是需要保留的真实 Git 现场，不能删除、自动放弃或伪装成已解决。
- 主界面要在对应分支上明确显示待处理冲突，并提供由用户主动触发的“继续处理冲突”入口。
- 进入冲突编辑器后要能返回代码交付主界面；返回只切换界面，不写文件、不暂存、不合入。
- 新合入操作当场产生冲突时，可以直接进入冲突编辑器，因为这是用户刚刚明确触发的动作，不属于打开弹窗时的历史状态恢复。

## 方案与取舍

将“存在可恢复合入记录”和“当前是否打开冲突编辑器”拆成两个状态。持久合入记录继续决定按钮、风险提示和恢复能力；只有用户点击继续处理，或本次合入刚刚产生冲突时，才打开冲突编辑器。

优点：代码交付入口保持稳定，用户能先查看所有任务分支和代码差异；旧冲突现场与安全门禁完整保留。

代价：恢复历史冲突需要多点击一次，但这是可见、可撤销的界面导航，不会误触 Git 写操作。

不采用“打开弹窗时自动选中最近冲突分支”：它会再次让历史异常状态改变用户当前上下文，无法解决另一个分支被遮挡的问题。

不采用“忽略或删除旧冲突记录”：这会丢失隔离合入工作区和未保存的处理现场，违反冲突失败时保留可恢复现场的安全边界。

## 实现计划

- 弹窗初始化默认选择第一个可用任务工作区，不再让历史冲突记录抢占默认分支。
- 增加仅属于当前弹窗实例的冲突编辑器可见状态，弹窗重新打开时恢复为主界面。
- 在合入步骤中展示历史冲突数量和显式继续入口。
- 冲突编辑器提供“返回代码交付”，保留右上角关闭能力。
- 分支列表展示真实的“待处理冲突”或“待同步”状态。
- 完成静态检查、构建和可行的真实渲染验证；未完成的桌面 GUI 场景单独说明。

## 当前进度

- 已完成问题链路定位和方案确认。
- 已完成界面状态拆分：历史冲突不再抢占首屏和默认分支，主界面提供显式恢复入口，冲突页可以返回主界面。
- 历史冲突对应的合入方式继续沿用持久记录，避免恢复旧 `squash` 候选时被界面默认的 `merge` 覆盖。
