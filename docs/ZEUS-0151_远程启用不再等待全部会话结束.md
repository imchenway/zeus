# ZEUS-0151 远程启用不再等待全部会话结束

## 任务问题

设置页启用“Zeus 会话远程接管”时，只要任意 Codex 运行时世代还有活动轮次或待答请求，服务端就拒绝启用，界面要求用户等正在运行或等待回答的会话结束。

## 根因

`codexRuntimeGenerationManager.enableRemoteControl()` 在创建远程执行宿主前，对所有已存活运行时世代做了全局忙碌拦截。这个拦截与同一管理器已有的世代排空能力重复，并且把“不能迁移进行中的请求”扩大成了“不能启用新宿主”。

运行时管理器已经具备安全分流能力：

- 正在执行或等待回答的线程继续绑定原执行宿主；
- 新线程和已空闲线程进入新的远程宿主；
- 旧宿主在活动轮次和待答请求都清空后自然回收；
- 不会把原请求跨宿主重放。

## 修复决策

移除启用远程接管前的全局忙碌拦截，直接创建远程执行宿主，沿用已有的线程固定与世代排空逻辑。设置页同步说明：启用不会中断当前工作，但启用前已在进行的轮次会先留在原宿主，完成后的后续轮次才进入远程宿主。

优点：用户无需为启用远程功能停止或等待无关会话，新工作可立即使用远程宿主。

代价：启用时已在原宿主上运行或等待回答的当前轮次，在自然排空前不会出现在新远程环境中。

## 变更落点

- `packages/ai-runtime/src/codexRuntimeGenerationManager.ts`：取消启用前的全局活动会话拦截，保留原世代的线程固定和排空。
- `apps/desktop/src/renderer/settings/CodexRemoteControlSettings.tsx`：明确立即启用与旧轮次延后接管的边界。
