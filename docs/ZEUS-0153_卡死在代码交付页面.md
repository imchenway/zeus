# ZEUS-0153 卡死在代码交付页面

## 任务目标

修复打开“代码交付”后长期停留在空白页面、所有操作和关闭入口都不可用的问题。代码交付首屏只依赖本机 Git 信息，远端网络或凭据异常不得阻塞本地查看、提交和合入。

## 现场与根因

截图中的任务分支数量为零、来源分支显示为“—”，右上角和底部关闭按钮同时禁用。这不是“任务没有代码”的空状态，而是弹窗仍处于初始化加载状态。

当前 `GET /api/tasks/:taskId/git-workspaces` 在读取每个任务工作区时仍会自动执行 `git fetch`。SSH、代理、网络或凭据交互长时间不返回时，整个接口无法完成。桌面端又把初始化读取当成不可中断的全局忙碌操作，因而同时禁用所有关闭入口，最终形成用户无法退出的阻断页面。

这也违反了既有产品规则：打开代码交付、读取工作区和本地合入都不应访问远端；只有用户明确点击推送时才允许连接远端。

## 修复方案与取舍

- 工作区读取移除自动远端刷新，只读取本地命名分支、本机保存的远端跟踪引用、提交和工作区状态。
- 初始化期间展示明确的“正在读取本机 Git 信息”，不再把尚未返回的数据渲染成任务分支为零的业务页面。
- 初始化读取失败时展示真实错误和“重新读取”入口。
- 初始化读取属于只读动作，允许用户随时关闭弹窗；提交、合入、冲突保存和推送等写操作期间继续禁止关闭，避免用户误判操作结果。

优点：远端不可达不再阻塞代码交付；加载、失败和重试状态可理解；用户始终可以退出只读等待。

代价：代码交付首屏中的“已推送”只表示本机远端跟踪引用的已知快照，不保证服务器当前仍一致。真正推送时仍会刷新远端并执行非快进保护与提交号校验。

## 安全边界

- 不执行提交、合入、推送、强制推送、变基或远端分支删除。
- 不放宽提交、合入和推送期间的重复操作保护。
- 不使用缓存分支绕过真正推送前的远端校验。
- 不读取或改写正式 Zeus 用户数据，不启动生产身份 `Zeus.app`。
