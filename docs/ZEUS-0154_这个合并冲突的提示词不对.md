# ZEUS-0154 这个合并冲突的提示词不对

## 任务目标

将代码交付冲突页的“AI 处理”从“只读生成 JSON 冲突草稿”改为“打开可见会话并完成本地合入”：

- 点击后立即跳转到本次冲突处理会话；
- 会话明确要求 AI 将当前任务分支本地合入创建任务时记录的来源分支（当前现场为 `main`），并处理全部冲突；
- 合入只更新本地目标分支，不执行 `git push`；
- 是否推送 `main` 继续由用户在代码交付主界面单独决定。

## 问题根因

现有链路把“AI 处理”定义成只读草稿生成器：

1. Renderer 把当前文件的未解决冲突序列化为带 Git marker 的文本。
2. Local Server 只截取冲突块，用只读权限创建会话。
3. 提示词强制模型只返回 `resolutions` JSON，禁止修改文件和 Git 写操作。
4. 接口长轮询等待最终回答，解析 JSON 后才回填中间草稿；界面不跳转会话。

因此就算模型正确理解代码，也只能输出机器协议文本，不能完成用户真正要的本地合入。

## 方案与边界

### 可见的合入会话

点击“AI 处理”后，服务端立即创建持久会话并返回会话 ID，Renderer 关闭代码交付弹窗并导航到该会话。不再等待模型返回 JSON，不再将回答解析为中间编辑区草稿。

优点：用户可直接看到 AI 的检查、修改、权限请求和最终结果，也可在同一会话里继续沟通。

代价：跳转后不再在三栏界面内同步回填 AI 草稿；需要回到代码交付查看最终本地合入状态。

### 隔离工作区内可写，由 Zeus 完成安全收尾

AI 的工作目录继续是当前 `TaskIntegration` 的隔离 integration worktree。会话改为可写，允许读取仓库、修改冲突文件、执行必要检查并暂存解决结果。AI 不直接推送，也不直接改写用户主工作区。

轮次结束后，Zeus 复用已有链路：

1. 复验任务分支和目标分支 HEAD 没有变化；
2. 确认所有冲突已解决并生成 merge 或 squash 提交；
3. 只在目标分支本地工作区安全时同步合入结果；
4. 若主工作区较脏或 HEAD 已变化，保留 integration worktree 和持久记录，不覆盖用户现场；
5. 不调用任何远端推送接口。

优点：AI 真正处理整次合入，同时继续使用 Zeus 已有的防覆盖门禁和可恢复现场。

代价：模型轮次完成不代表一定能同步到 `main`；如果冲突未解决、目标分支变化或本地工作区不安全，Zeus 必须保留现场并报告真实原因。

## 实现计划

- 用“完成本地合入”短提示词替换 JSON 冲突块协议；不再把整份中间草稿复制进提示词。
- 创建会话前把当前三栏草稿写入隔离 integration worktree，保留用户已做出的选择；该动作不执行 `git add`、不生成提交也不更新目标分支。
- 冲突 AI 会话改为 `auto` 可写权限，仅把 integration worktree 作为代码写入根目录。
- 接口创建会话后立即返回；每次会话轮次结束都尝试执行本地合入收尾，首轮未完成时可以在同一会话继续处理。
- Renderer 改为刷新会话列表、关闭代码交付弹窗并打开新会话。
- 同一合入记录正在由 AI 处理时复用原会话，避免重复点击创建并行写入会话。
