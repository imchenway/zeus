# ZEUS-0156 这么简单的冲突魔法棒都不会处理

## 任务目标

修复代码交付冲突页中魔法棒命中率低、部分确定性合并结果错误、冲突块处理完成后缺少连续引导的问题，并保留所有 Git 写入保护。

## 已确认现状

- IDEA 与 Zeus 都不会自动处理“共同基线同一点、两侧分别插入不同内容”的冲突，因为无法从三方事实确定两段内容的先后顺序。
- Zeus 当前使用正则切词与自写差异算法，不等同于 IDEA 的三方词级比较；连续中文被整段视为一个词，跨行与标点边界匹配能力不足。
- 当前差异长度乘积超过 `200000` 时会退化成整块删除和整块插入。运行探针显示，首尾互不覆盖的修改在 200 个空格分隔词时可以处理，达到 224 个词后被误判为无法处理。
- 忽略空白重试存在错误成功：共同基线为 `x x`，两侧分别为 `x  Y x` 与 `x Y x` 时，当前实现会生成重复的 `x  Y Y x`。
- 左右两侧通过“选入 / 忽略”处理最后一个冲突块后，块状态已经是 `resolved`、未处理数量已经为零，但已解决块仍保留在块数组中；界面继续显示三栏代码，准备好的当前文件完成态不可达。
- 初次 IDEA 对齐只完成了解析器直调和静态、构建、打包验证；之后冲突文档重构替换了差异实现。现有记录没有证明当前实现完成过真实桌面冲突页的连续操作验收。

## 用户确认

- 魔法棒保持确定性边界，不把同点不同内容插入按猜测顺序拼接。
- 先修复错误成功、恢复中等长度冲突能力、补齐中文、换行、标点和空白处理，并让无法处理的原因可见。
- 冲突处理使用三段完成状态：单块完成后进入下一个未处理块；当前文件全部处理后显示“保存该文件并继续”；最后一个冲突文件保存后进入冲突收尾确认。
- “当前文件冲突已处理”只表示内存草稿没有待处理块，不得写成“全部合并完成”；保存前不写文件、不执行 `git add`。

## 方案与取舍

### 确定性三方差异

恢复不依赖二维矩阵的差异路径，避免中等长度文本被整块降级；连续书写文字按可比较字符切分，其他标识符保持词级切分。严格比较失败后可以忽略空白重新比较，但相同语义插入只能保留一份，禁止把空白差异变成重复代码。

优点：覆盖真实中文文档、代码、配置和跨行文本，避免魔法棒长期处于不可用状态。

代价：差异匹配与边界调整复杂度提高；需要业务判断的重叠修改仍必须保留给用户。

### 可解释的自动合并能力

确定性解析除成功结果外，还返回无法处理原因，例如同点不同插入、重叠修改、共同基线不可用或内容过大。工具栏继续只在存在安全结果时启用，并向用户说明剩余块为什么不能自动处理。

优点：用户能区分安全拒绝与算法能力限制，后续可以对真实失败类型进行复盘。

代价：界面需要承载一条简短原因摘要，不能只显示统一的“无可自动合并项”。

### 三段完成状态

每次处理冲突块后自动选择下一个未处理块；当前文件未处理数量归零时，用持续可见的完成状态替代已解决块的三栏视图，并提供“查看完整文件”和“保存该文件并继续”。保存后若仍有冲突文件则自动进入下一文件，最后一个文件保存后沿用现有冲突收尾确认。

优点：用户始终知道当前块、当前文件和整个合入分别完成到哪一步，可以连续完成多文件处理。

代价：当前文件处理完成后仍需一次明确保存；这是保留草稿审查和禁止隐式写盘的必要成本。

## 安全边界

- 魔法棒、左右选入、忽略和手工编辑只更新 Renderer 草稿。
- 当前文件存在未处理块或残留冲突标记时禁止保存。
- 保存当前文件仍由既有受控接口写入隔离 integration worktree 并暂存。
- 不自动提交、合入、推送，不放宽目标分支提交和工作区状态复验。
- 不新增或恢复单元测试体系；验证使用静态检查、构建、运行探针和必要的 `Zeus Test.app` 真实检查。
