# ZEUS-0157 启用远程接管报错

## 任务状态

- 阶段：修复完成，静态、接口和独立测试包验证通过；真实界面验收仍有下述缺口。
- 类型：缺陷。
- 用户现象：启用 Zeus 会话远程接管时，官方 Codex Remote Control 报错，缺少 `/Users/david/.zeus/providers/codex/packages/standalone/current/codex`。
- 用户未提供预期和复现步骤；本任务按“已为 Zeus 准备官方独立版时可启用，未准备时在点击前展示准确恢复入口”收口。

## 已确认根因

当前机器同时存在两项真实事实：

1. `/Users/david/.local/bin/codex` 是官方独立安装版入口，实际落在 `/Users/david/.codex/packages/standalone`，版本为 `0.146.1`；
2. Zeus 为隔离配置、认证、会话和插件，给执行宿主注入了 `CODEX_HOME=/Users/david/.zeus/providers/codex`。

普通 `codex --version` 和 `codex app-server` 可以直接运行所选可执行文件，因此普通检测会显示 Codex CLI 可用。`codex remote-control start` 不同：官方守护进程要求从当前 `CODEX_HOME/packages/standalone/current/codex` 的固定入口启动和更新。Zeus 独立 `CODEX_HOME` 中没有这一安装记录，所以“普通 CLI 可用”和“Remote Control 可用”被错误地当成了同一项能力。

官方当前环境变量说明也明确：`CODEX_HOME` 同时决定配置、认证、会话和独立版包元数据；`CODEX_INSTALL_DIR` 只决定用户可见的 `codex` 入口，独立版包缓存仍位于当前 `CODEX_HOME/packages/standalone`。因此原错误中的默认命令只会安装到默认 `~/.codex`，不能保证修复 Zeus 独立目录。

## 修复决策

### 独立探测

设置页分别展示普通 Codex CLI 与 Remote Control 独立版状态。Remote Control 只认可 Zeus 当前 `CODEX_HOME` 下由官方安装器登记的固定入口，不再因为 PATH 中存在另一个 `codex` 就显示为可启用。

优点：检测口径与官方守护进程真实要求一致，用户不会点击后才看到内部固定路径报错。

缺点：同一台机器已有默认 `~/.codex` 独立版时，Zeus 仍需要自己的独立版登记，占用一份额外程序空间。

### 准确恢复命令

缺失时展示并允许复制带 `CODEX_HOME` 和 `CODEX_INSTALL_DIR` 的官方安装命令。安装目录位于 Zeus 自己的 Codex Home；Zeus 不执行该命令、不自动登录，也不改写用户的默认 `~/.local/bin/codex`。

优点：恢复动作不会污染普通终端使用的可见 CLI 入口，也不会把 Zeus 会话、认证和插件退回默认 `~/.codex`。

缺点：用户仍需在终端明确执行官方安装，并完成 Zeus 专属 Codex 登录；这是外部依赖和账号授权的必要边界。

### 固定入口启动

独立版准备完成后，Remote Control 世代直接使用 Zeus `CODEX_HOME/packages/standalone/current/codex`。普通本地 app-server 仍遵守用户显式 CLI 路径和 PATH 探测；远程启用后，新会话和空闲会话进入官方固定入口，活动会话继续按既有世代排空规则留在原宿主。

优点：保留 Zeus 数据隔离、官方守护进程更新语义和进行中会话安全边界，不需要伪造软链接或借用其他 Home 的守护进程。

缺点：普通与远程世代可能暂时使用不同的可执行入口，运行时状态必须继续按世代而不是单一全局进程判断。

## 实现落点

- `packages/local-server/src/index.ts`：生成 Remote Control 独立版快照、准确安装命令和固定入口；启用远程前执行真实可执行权限检查。
- `packages/ai-runtime/src/codexAppServerManager.ts`：远程启动失败时根据当前 `CODEX_HOME` 给出匹配 Zeus 独立目录的恢复命令，不再无条件重复默认安装命令。
- `apps/desktop/src/renderer/apiClient.ts`：接收独立版能力快照，并兼容升级交接期间尚未返回新字段的旧执行宿主。
- `apps/desktop/src/renderer/settings/CodexRemoteControlSettings.tsx`：在点击启用前展示独立版状态、固定入口或可复制安装命令；缺失时禁用启用与配对。

## 验证结果

- `pnpm exec prettier --check`、`git diff --check`、`pnpm lint`、`pnpm typecheck` 和 `pnpm build` 通过。
- `pnpm package:mac` 通过，仅生成 `dist/test/mac-arm64/Zeus Test.app` 和对应测试 DMG；Bundle ID 为 `dev.hypha.zeus.test`，`codesign --verify --deep --strict` 通过，未生成仓库产线身份 `Zeus.app`。
- 使用临时隔离数据根调用真实本地服务：缺失固定入口时，状态接口返回当前 Home 的安装命令；启用接口以 `409 / ZEUS_CODEX_REMOTE_CONTROL_STANDALONE_REQUIRED` 拒绝，且未启动远程宿主。
- 在同类隔离根中临时提供可执行固定入口，并注入不启动官方守护进程的记录器：启用接口返回 `200`，两次就绪检查都使用同一固定路径和 `remoteControl: true`。临时资源在探针后已清理。

## 验收缺口

- 独立 `Zeus Test.app` 中执行宿主已启动，仪表盘和设置本地接口都返回 `200`，但 Renderer 长时间停在启动标识页，无法进入设置页点击缺失态、复制按钮和启用门禁。本次不把打包成功或接口成功冒充为 GUI 验收通过；该测试实例已关闭。
- 本轮不执行官方安装命令，不改变当前机器登录和远程授权状态。因此真实安装后守护进程启动、手机配对和回答回流仍需人工验收。
