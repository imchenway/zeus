# ZEUS-0159 多 Git 仓时推送任务和代码交付时都特别慢

## 任务目标

- 任务类型：优化。
- 现状：项目包含多个 Git 仓库时，打开任务推送和代码交付需要长时间等待，真正创建多仓任务工作区的耗时还会随仓库数累加。
- 预期：不改变本地优先、显式远端操作、真实 Git 安全校验和失败回滚语义，去掉重复仓库读取，并让代码交付首屏不再等待未选中仓库。

## 基线诊断

### 任务推送

- `discoverGitRepositories` 以串行递归方式扫描目录。
- 发现仓库时已读取 Git 上下文和状态，同一次能力组装又重新读取仓库上下文和工作区审查。
- `getTaskWorkspaceReview` 内部再次调用 `getGitRepositoryContext`；单次上下文读取本身包含多个串行 Git 子进程。
- 真正创建任务环境时再次递归发现仓库，并且按仓库串行创建 worktree。

### 代码交付

- 打开弹窗时对每个任务工作区一次性读取仓库上下文、分支比较、本机未提交变化、远端跟踪提交和完整差异摘要。
- 分支比较、分支 HEAD 和工作区审查各自重复读取同一仓库上下文。
- Renderer 首屏只显示一个选中仓库，但未选中仓库的完整 review 和 diff 仍在首屏前执行。

## 安全与产品边界

- 保留当前本地优先规则：打开任务推送、创建会话、读取代码交付都不自动 `fetch`。
- 远端刷新和任意推送仍由用户显式触发；继续禁止强制推送，并保留非快进保护和推送后远端 SHA 校验。
- ADR-0009 的“有远端时自动刷新”与 2026-08-08 后的当前实现、ZEUS-0136 产品规则存在冲突。本任务只做性能优化，不借机改变当前可见行为。
- 快照只在单次请求或弹窗生命周期内复用，不做跨启动持久缓存。任何 Git 写操作仍在服务端重新校验归属、分支、HEAD 和工作区状态。

## 优缺点

优点：

- 去除同一请求中对同一仓库的重复 Git 子进程，性能收益可直接随仓库数放大。
- 代码交付可先展示真实持久工作区列表，再按用户当前对象读取实时 Git 事实。
- 没有用降低校验强度、使用过期远端事实或伪造成功换取速度。

代价：

- 用户首次切换到未读取的仓库时需要等待局部详情。
- 多仓准备需要显式处理独立路径与父子路径的调度、失败回滚和日志可解释性。

## 多仓批量提交与推送补充要求

2026-08-10 用户补充指出：同一任务分支包含十多个仓库时，不应只能在左侧逐仓切换后反复提交和推送。

本任务同步增加以下能力：

- 保留单仓文件勾选、单仓提交和重复推送。
- 增加“提交全部有变化仓库”：对本次快照中每个存在未提交变化的工作区分别创建本地 commit，使用用户当前确认的提交说明。
- 增加“推送全部已提交仓库”：处理已配置远端的任务工作区，逐仓复用非强制推送、分叉保护和远端 SHA 校验；已经同步的分支仍执行真实刷新与校验，不依赖旧缓存判断跳过。
- 批量结果按仓库返回 `succeeded / skipped / failed`；成功的仓库不因其他仓库失败而回滚，失败项可单独重试。
- 不把多个独立 Git 仓库伪装成跨仓原子事务；批量运行前和结果区都明确说明可能部分成功。

优点：一次确认即可完成常见的多仓提交或推送，且仍能看到每个仓库的真实结果。

代价：Git 没有跨仓原子提交与推送，因此网络、凭据或分支并发变化可能导致部分成功；用户必须根据逐仓结果重试失败项。

## 验证记录

### 性能基线与结果

使用 `scripts/benchmark-zeus-0159.mjs` 在同一台机器、隔离临时目录中构造 1、4、8 个兄弟仓库。每个仓库包含大文本变化和二进制变化；修改前口径按原调用链执行“发现上下文与状态，再次读取上下文和完整 review”，修改后执行一次发现快照并直接复用。每组交替顺序执行三轮并取中位数。

| 仓库数 | 修改前中位数 | 修改后中位数 | 降幅 | 修改前 Git 命令 | 修改后 Git 命令 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 290.2ms | 30.4ms | 89.5% | 29 | 8 |
| 4 | 388.2ms | 81.0ms | 79.1% | 116 | 32 |
| 8 | 561.2ms | 155.2ms | 72.3% | 232 | 64 |

8 个独立仓库的 worktree 准备三轮中位数从串行 936.7ms 降至受控并行 275.8ms，降幅 70.6%。以上是隔离本机 Git 测量，不代表带网络、Provider 或用户真实大仓历史后的绝对耗时。

### Git 与接口场景

- `scripts/verify-zeus-0159-git.mjs` 通过：工作区索引只返回文件统计且不生成 hunk；选中文件接口生成真实 hunk；重命名路径统计正确；父仓和嵌套子仓按依赖顺序准备并按子仓优先回收。
- 同一脚本在 4 仓并发准备中主动让 1 仓失败：失败前已有 3 仓完成准备，统一清理后残留任务分支 0、残留 worktree 0。
- 本地裸仓远端验证通过：首次推送和重复推送均通过远端 SHA 校验；制造远端独有提交后，普通推送以 `ZEUS_TASK_REMOTE_DIVERGED` 阻断，没有强制覆盖。
- `scripts/verify-zeus-0159-api.mjs` 使用真实 Local Server 和隔离 SQLite：轻量索引返回 3 仓，单仓详情只返回目标仓库；批量提交得到 2 成功、1 冲突失败，两个成功提交没有回滚；批量推送得到 1 成功、1 无远端跳过、1 远端失败，成功项远端 SHA 与本地 HEAD 相同。
- 任务推送的数据库写入仍位于全部 worktree 准备成功之后；仓库准备异常路径在写入任务环境前执行清理。由于完整会话创建还依赖真实 Provider，本次没有用假 Provider 把静态顺序检查冒充端到端会话验收。

### 隔离 GUI 验证

使用独立 `ZEUS_USER_DATA_DIR` 启动本任务产出的 `Zeus Test.app`，没有启动正式 `Zeus.app`：

- 代码交付打开后立即显示 3 个仓库；首个仓库完成详情读取，另外两个显示“尚未读取”。
- 首个仓库只在选中后读取已提交文件和单文件差异；切换第二个仓库后读取其详情，切回首个仓库继续使用弹窗内缓存。
- 临时让第三个仓库的 Git 根不可用后，该仓库显示“读取失败”；切回已读取仓库仍可查看文件和差异，错误没有阻塞其他仓库。
- 退出测试包后已删除本次临时用户数据和临时仓库。没有执行任务代码提交、推送或合并。

### 验证缺口

- 未使用真实 ChatGPT/Codex Provider 创建会话，因此不把构建、脚本或 GUI 读取验证描述成 Provider 验收。
- 远端验证使用本机裸仓和不可用文件远端，覆盖成功、重复推送、SHA 校验、无远端、远端失败和分叉保护；没有使用真实托管平台账号复现凭据过期或服务端权限策略。
- GUI 已验证渐进加载、切换缓存和错误隔离；批量接口已真实执行，但没有在 GUI 中再次制造未提交变化并点击批量按钮，避免为了截图重复改写验证仓库。批量按钮的渲染与调用链由类型检查、构建和真实接口结果共同覆盖。
- 本次不修改 ADR-0009；其自动远端刷新口径仍与当前本地优先规则冲突，后续如要统一必须作为独立产品决策处理。
