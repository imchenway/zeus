# ZEUS-0164 模型生成图片未显示

## 任务目标

修复 Codex 已成功生成图片，但 Zeus 会话只显示模型文字、无法显示图片的问题。生成图需要作为独立会话内容按正文宽度展示，点击后进入现有 Zeus 图片预览；历史会话中的同类图片需要自动恢复。

## 已确认根因

- 原始 Codex JSONL 已记录成功的 `image_generation_end`，并保存了 `result`、`saved_path` 与真实 PNG 文件。
- app-server 向 Zeus 投影的条目类型为 `imageGeneration`，但 Zeus 的 `ConversationItemType` 白名单不包含该类型，最终被错误保存为 `error`。
- 会话资源归一化不识别 `imageGeneration.savedPath`，Codex 的 `generated_images` 目录也不属于普通附件信任根，因此没有生成 `conversation_resources` 记录。
- Renderer 只渲染受控会话资源或历史 `payload.images`，当前条目两者均不存在，所以图片消失，并额外出现“本轮错误”。
- 当前复现会话的生成文件真实存在；缺陷位于 Zeus 的类型映射、资源授权与渲染链路，而不是模型没有生成图片。

## 已确认方案

- 新增真实条目类型 `imageGeneration`，成功生成不再降级为错误，也不折叠进普通工具活动。
- 新事件持久化前移除图片 `result` 的大体积 base64，只保留状态、提示和受控路径等必要元数据；历史原始负载不主动清理，但不得继续发送给 Renderer。
- 只允许当前会话访问 `$CODEX_HOME/generated_images/<providerThreadId>` 中的真实普通图片文件，禁止跨会话目录、符号链接越界和任意本地 URL 直出。
- 生成图复用现有 `ConversationResource`、懒加载预览和受控打开链路；不新增第二套文件读取接口。
- 历史迁移只重新分类能够精确识别的 `payload.type === imageGeneration` 条目，随后通过受控资源回填恢复图片。
- 图片按正文宽度展示；生成中显示可读状态，文件缺失或无权访问时明确降级，不伪造成功。

## 设计取舍

生成图沿用 Codex 的预览图归属方式，保留在 Provider 的 `generated_images` 目录，不复制到 Zeus 会话附件目录。

优点：会话可以直接显示模型生成结果，不重复占用磁盘，也不产生两个文件生命周期。

代价：Provider 文件被外部清理后，历史图片只能显示文件不可用；如果图片需要成为项目资产，仍需显式复制到项目目录。

## 授权边界

- 生成图目录不能并入普通附件信任根；授权必须同时绑定 Codex 生成图根、当前 Provider 会话 ID 和实际文件路径。
- 路径必须通过真实路径解析，目标必须是当前会话目录内的普通文件，并且类型可识别为图片。
- 预览和打开继续由 Local Server 依据持久资源的 `allowedRoot` 二次复验，Renderer 不直接读取 `file://` 或任意 data URL。
- 文件不存在、目录不匹配或校验失败时不建立资源记录，并在界面中显示真实不可用状态。

## 实施记录

- 存储层已新增 `imageGeneration`，并增加精确历史迁移：只把负载类型同为 `imageGeneration` 的旧 `error` 条目改回真实类型，原始历史负载不删除。
- Local Server 已增加独立生成图授权输入，不与任务附件、浏览器批注和会话附件的普通信任根合并。授权同时校验 Provider 会话目录、真实路径、普通文件、扩展名和图片文件头。
- 新实时条目在持久化前采用必要字段白名单，移除 `result`；历史快照返回 Renderer 前执行同一过滤，但数据库内已有 base64 保持原样。
- 启动资源回填和实时资源同步均可从受控 `savedPath` 建立现有图片附件资源；缺失、跨会话、越界、伪装类型和无权限路径均不建立资源。
- Renderer 已增加独立生成图行：生成中显示进度，成功按正文宽度懒加载，支持键盘聚焦并点击进入现有 Zeus 预览；完成但无有效资源时显示“生成图片文件不可用”，Provider 失败仍按“本轮错误”展示。
- 普通图片附件、Markdown 图片、`imageView` 和资源卡仍走原有路径，不受生成图专用展示影响。
