# ZEUS-0165 会话环境卡片、代码页按钮与计划展示修复

## 任务目标

修复宽屏环境卡片定位错误、任务详情与环境卡片重叠、浏览器打开后环境按钮无法展开、代码页模式按钮无法点击，以及计划正文没有直接显示的问题。

## 根因与取舍

### 环境卡片

- 常驻卡片原先绝对定位在头部操作按钮的零宽锚点上，位置依赖头部内边距，无法稳定表达正文右上留白。
- 发布后的真实界面进一步暴露出：卡片起点只参考会话头部下缘，没有把紧随其后的会话运行摘要栏计入布局，因此会覆盖 Token 用量、缓存命中率；摘要栏展开后，固定偏移还会继续覆盖完整运行详情。
- `forceCollapsed` 同时承担“取消常驻”和“禁止展开”，导致浏览器打开后虽然出现环境按钮，点击仍无法显示卡片。
- 任务详情抽屉由应用层管理，会话卡片此前不知道详情状态，因此没有互斥关系。

本次把“强制收起”和“完全隐藏”拆开：浏览器、计划、源码预览和变更审查只取消常驻，仍允许用户主动弹出；任务详情打开及关闭动画期间完全隐藏卡片。优点是状态语义明确并保留主动查看能力，代价是应用层需要向会话工作区传递一个内部布尔状态。

针对会话运行摘要栏的补充规则是：摘要栏保持完整横向空间，常驻环境卡片挂在所有顶部状态内容之后，并保留 `16px` 间距。卡片位置跟随摘要详情的实际高度，不使用固定 `46px` 偏移。优点是折叠、展开及其他顶部状态都能自然避让；代价是顶部状态越多，环境卡片越靠下。

### 代码页模式按钮

代码模式工具栏位于窗口顶部 `56px` 透明拖拽层范围内，却没有加入顶部交互控件的层级规则，点击被拖拽层截获。本次只提升工具栏交互层，不改源码、图谱和命令的状态逻辑。优点是改动小且保留窗口拖拽区域，代价是新增顶部工具栏仍需遵守同一层级契约。

### 计划正文

`plan` 条目已经持久化，“实施此计划？”也能引用对应条目，但会话投影把所有非用户、非最终回答条目都归入“已处理”折叠区。计划是交给用户审核的最终产物，不属于过程信息，因此本次将它从处理过程分组中排除，继续复用现有计划摘要组件独立展示。

## 实现范围

- 环境卡片保持 `300px` 宽，距顶部状态区下缘和右边缘各 `16px`，只允许纵向滚动；长来源名称使用省略显示。
- 会话运行摘要栏及其展开详情保持整行宽度；常驻环境卡片必须跟随顶部状态区实际高度下移，不能依赖固定高度猜测位置。
- 任务详情状态通过内部属性传给会话工作区；隐藏期间不清空已加载的工作区快照。
- 浏览器等右侧工作面打开时，环境按钮可以正常展开弹出卡片。
- 代码页模式工具栏加入顶部交互层规则。
- 实时和历史快照共用的会话投影不再把计划条目折叠进处理过程。
