# ZEUS-0167 打开 HTML 附件失败

## 文档状态

- 任务类型：缺陷；
- 当前阶段：实现与静态、构建、隔离启动验证已完成，等待真实故障会话点击验收；
- 当前结论：已修正历史资源回填根目录，并为 Review 建立独立的受信变更文件打开协议；任务 worktree 中的 HTML 不再依赖 Renderer item 资源投影是否完整；
- Git 边界：未执行 `commit`、`push`、`merge` 或 `revert`。

## 用户提供的现状

1. 会话内的交互式架构图无法点击打开预览；
2. 选择通过 Chrome 等外部浏览器打开时也报错；
3. 屏幕截图中的 HTML 位于 `docs/ZEUS-0166_远程安装隔离方案图.html`；
4. 变更审核页面显示两条错误：
   - `无法取得此变更文件的受信打开权限。`
   - `The captured recovery snapshots do not reproduce the provider patch.`

## 已确认的产品与领域边界

- **会话资源**是打开本地文件的受信凭据；Renderer 不能只凭 diff 中的路径直接打开任意文件。
- **资源打开目标**是用户选择的去向。本地 HTML 的既定目标包括 Zeus 内置浏览器、系统默认应用、Finder 和复制路径。
- **执行轮次变更集**负责 Review、Undo 和 Reapply。恢复快照不可验证时，应禁止不安全的 Undo / Reapply，但不应自动等价为“当前真实文件不可只读打开”。
- 所有打开动作仍必须复验会话、项目、资源归属，项目根包含关系、符号链接逃逸、文件存在性和 Main 进程发送方；修复不能绕过这些安全边界。

## 修改前的实现

### 会话资源生成

- Local Server 会从 provider `fileChange` item 的 `changes[]` 中归一化项目内文件路径；
- 归一化成功后，资源持久化项目、会话、轮次、项目相对路径、绝对路径和允许根；
- Main 进程打开前会向 Local Server 重新读取资源打开意图，并再次校验真实路径没有越出允许根。

### 变更审核页打开文件

`SessionWorkspace.openTurnChangeFile` 修改前执行：

1. 从变更文件取得 `newPath / oldPath`；
2. 只在 Renderer 当前会话 item 的 `resources` 中，按“与变更集属于同一轮次 + 项目相对路径相同”寻找会话文件资源；
3. 找不到时直接显示“无法取得此变更文件的受信打开权限”；
4. 只有找到资源后，才会继续进入 Zeus 内置浏览器、系统默认应用或其他打开目标。

因此截图中的两种打开方式共用同一个前置失败点，不是 Chrome 和 Zeus Browser 各自发生了不同故障。

### 恢复快照错误

- `The captured recovery snapshots do not reproduce the provider patch.` 由变更恢复快照与 provider diff 无法相互验证时产生；
- 该状态用于阻止不可证明安全的 Undo / Reapply；
- 该状态不是本地 HTML 文件的只读打开授权。

## 初步失效链

```text
provider fileChange / 历史会话恢复
  -> 变更集可以展示 diff
  -> Renderer 当前 item 资源中没有找到同轮次同路径的文件资源
  -> Review 页在 Main / Local Server 复验前提前失败
  -> Zeus 内置浏览器与系统默认浏览器都无法收到打开请求
```

### 根因补充

- 实时会话资源归一化使用会话运行上下文中的 `projectLocalPath`，任务会话中该路径是任务 worktree；
- Local Server 启动时的历史资源回填却固定使用 `project.localPath`，它通常是项目主目录；
- 当 HTML 只存在于任务 worktree 时，历史回填无法在项目主目录解析该文件，并可能用空结果替换原 item 的资源记录；
- Review 当前没有自身的受信变更文件打开协议，因此无法从这种资源投影缺失中恢复。

## 待用户逐项确认

1. 已确认：同时覆盖“模型消息中的 HTML 资源卡或链接”与“Review 中的 HTML 变更文件”；
2. 已确认：本地 HTML 的主点击遵循现有“本地网页默认目标”用户设置；
3. 已确认：Review 只打开当前工作区真实文件，不把历史恢复快照作为可交互 HTML 运行；
4. 已确认：恢复快照错误与 HTML 打开解耦，本任务不修改 Undo / Reapply 的快照捕获机制。

## 已确认决策

### 2026-08-10：HTML 打开入口范围

用户确认本缺陷同时修复两类入口：

- 模型消息中的 HTML 资源卡或链接；
- Review 中的 HTML 变更文件。

两类入口应复用同一条受信打开链路，但不因此绕过 Main / Local Server 的权限复验。

### 2026-08-10：本地 HTML 的主打开目标

用户确认本地 HTML 的主点击继续遵循已有“本地网页默认目标”设置：

- 设置为 Zeus 内置浏览器时，在当前会话右侧打开；
- 设置为外部浏览器时，交给系统默认浏览器；
- “打开方式”菜单的单次选择不改写用户默认设置。

### 2026-08-10：Review 打开的文件版本

用户确认 Review 的“打开文件”只指向当前工作区真实文件：

- 文件当前存在时打开当前版本，即使该文件在这一轮之后又被修改；
- 重命名文件按变更集当前状态解析现路径；
- 文件当前不存在时明确提示，不伪造预览；
- 历史恢复快照只用于可证明安全的 Undo / Reapply，不作为可执行 HTML 打开。

这意味着 Review 保留的历史 diff 可能与打开后看到的当前文件不同；两者分别表达“这一轮改了什么”和“工作区现在是什么”。

### 2026-08-10：恢复快照问题的任务边界

用户同意按建议继续：

- HTML 的只读打开与恢复快照的可逆性判定解耦；
- 恢复快照异常不得再阻止当前真实文件的受信只读打开；
- 快照不可验证时，Undo / Reapply 仍保持禁用或失败状态，不降低数据恢复门禁；
- 快照捕获与 provider patch 无法互验的根因不在本缺陷中修复，必要时单独立项。

## 共同理解草案

### 目标

恢复会话中本地 HTML 的完整受信打开链路，使消息资源入口和 Review 文件入口都能进入用户选择的真实打开目标。

### 必须满足

1. 模型消息中已登记的本地 HTML 资源可以点击打开；
2. Review 中的 HTML 变更文件可以点击打开；
3. 主点击遵循已有“本地网页默认目标”设置；
4. “打开方式”可以单次选择 Zeus 内置浏览器或系统默认应用，且不改写默认偏好；
5. Review 打开的是当前工作区真实文件，不是恢复快照；
6. 重命名按当前变更集状态解析路径，文件不存在时给出可理解的局部错误；
7. 不受信、越出项目根、符号链接逃逸或来自非受信窗口的请求继续拒绝；
8. 快照异常不阻止只读打开，但仍阻止不可证明安全的 Undo / Reapply。

### 明确不包含

- 不修复恢复快照捕获或 provider patch 互验问题；
- 不执行历史 HTML 快照；
- 不放宽本地路径受信根、符号链接和 Main 发送方复验；
- 不执行 Git 提交、推送、合并或回退。

## 方案方向对比

### 只修正 Renderer 投影

- 优点：改动较小，可恢复当前既有打开链路。
- 缺点：Review 仍隐式依赖 item 资源在 Renderer 中的完整性；历史恢复、事件顺序和资源投影漂移仍可能再次使入口失效。

### 为 Review 提供受信的变更文件打开意图

- 优点：权限来源与变更集归属一致，Renderer 不需要自行发明或拼接路径权限，对历史会话更稳定。
- 缺点：需要增加 Local Server / Main 的显式协议，并处理删除、重命名、后续修改与符号链接越界等状态。

### 同时修正投影与 Review 授权协议

- 优点：既恢复消息资源的完整性，又让 Review 拥有符合自身归属的受信入口，对当前与历史会话都更稳定。
- 缺点：改动面和回归范围最大，需要真实 Zeus Test 会话同时验收资源卡、Review、Zeus Browser 和系统默认应用。

## 已确认实现方案

选择“同时修正投影与 Review 授权协议”，但 Review 协议不为 Renderer 暴露绝对路径：

1. 历史会话资源回填改用会话执行根；执行根不可恢复时不用项目主目录猜测任务文件。
2. Local Server 增加变更文件当前打开意图，输入只包含项目、会话、轮次、变更集和变更文件身份。
3. Local Server 复验所有归属，根据变更集当前状态选择 `oldPath / newPath`，再用会话执行根解析真实文件。
4. 文件不存在、处于 Undo / Reapply 中间态、越界或符号链接逃逸时，Local Server 返回明确错误。
5. Electron Main 获得受信打开意图后，复用现有打开目标探测、真实路径复验、Zeus Browser、系统默认应用与外部编辑器适配。
6. Renderer 的 Review 入口直接传递变更身份与打开目标，不再扫描当前 item 资源并自行匹配路径。
7. 源码行预览通过同一变更身份请求 Local Server 的受信预览，不为复用旧端点写入临时持久化资源。

### 方案优缺点

- 优点：修复真实根因；当前与历史会话共用权威执行根；Review 不再依赖 Renderer 投影完整性；不放宽路径安全边界；不产生临时资源数据。
- 缺点：协议跨越 Local Server、Main、preload 和 Renderer；需同时检查消息卡回填、Review 主打开、行号预览、重命名与文件缺失错误。

## 实施结果

1. Local Server 新增从“项目相对路径 + 会话执行根”生成受信文件打开意图的统一能力；
2. 历史资源回填改为使用会话执行根；无法恢复任务会话执行根时跳过回填，不再退回项目主目录猜测；
3. Local Server 新增 Review 变更文件的打开意图与预览接口，逐级复验项目、会话、轮次、变更集和文件归属；
4. Review 根据变更集状态选择当前路径：已撤销时使用旧路径，其他稳定状态使用新路径；Undo、Reapply 和快照捕获中间态拒绝打开；
5. 真实路径解析继续检查允许根、符号链接逃逸、文件存在性和普通文件类型；
6. Electron Main、preload 与 Renderer 增加变更文件打开协议，并复用既有 Zeus Browser、系统默认应用、Finder、复制路径和外部编辑器目标；
7. Review 主打开与源码行预览不再扫描 Renderer item 资源，也不再因历史资源投影缺失提前报错；
8. React 侧把异步打开过程保持在用户点击处理函数中，没有增加额外监听或副作用状态。
