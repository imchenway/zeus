# ZEUS-0169 会话缺陷

## 任务信息

- 任务类型：缺陷。
- 现状：模型已经发起普通用户询问，但 Zeus 没有显示问题选项；用户在底部自由输入后，Zeus 自动创建了另一条会话。
- 预期：问题选项必须显示在原会话；等待回答时只保留专用问答区；任何失败都不得静默改变会话身份。
- 复现频率：用户在 2026-08-11 确认短时间内连续发生五次。

## 用户确认

用户明确要求移除“需要恢复”状态。这里不是隐藏文案，而是同时移除它作为用户可见会话状态、整会话写入门禁和自动承接会话触发器的产品语义。

确认后的规则：

- Provider 接收结果不确定只约束对应消息不得自动重发，不锁死整个会话。
- 连接异常由后台重连处理，不把会话改成“需要恢复”。
- 原会话无法继续时保留当前输入并说明失败；只有用户点击明确的新建入口才能创建另一条产品会话。
- 普通用户询问存在时，专用问答区替换普通 composer；回答继续提交到原请求和原会话。

优点：单次协议、连接或发送异常不会让整段会话无法工作，也不会发生无感分流。

代价：消息结果真正不确定时不能自动重发；未知询问结构不能猜测回答，只能结束当前异常轮次并显示局部错误。

## 根因链

`Provider request_user_input 新增 isBlocking`

→ `Zeus 旧字段集合严格相等校验失败`

→ `问题请求未进入待回答状态`

→ `整会话被标记 recovery_required`

→ `普通输入区被替换为新会话输入区`

→ `用户发送后自动创建另一条会话`

## 实施范围

1. 保留核心字段与答案结构校验，接受类型合法的可选 `isBlocking`。
2. 询问结构真正无效时只失败当前请求和轮次，不再暂停整会话或后续队列。
3. 前端不再把 `recoveryRequired` 作为粘滞全局错误、写入门禁或新会话输入区触发器。
4. 原会话 composer 保留草稿；待回答询问出现时仍由专用问答区暂时替换。
5. 结果不确定的历史 submission 继续保持消息级不可自动重发，避免重复副作用。
