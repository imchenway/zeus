# ZEUS-0170 推送会话样式优化

## 任务信息

- 任务标题：推送会话样式优化
- 任务类型：优化
- 现状：任务首发弹窗的工作区选择项中，选中的单选按钮没有可见圆点，单选按钮也没有与两行文案整体垂直居中。
- 预期：选中项显示蓝色圆点、强调色卡片边框和轻强调色背景；radio 与标题、说明组成的完整文案块垂直居中。

## 当前阶段

- 阶段：开发与验证完成。
- 按项目流程使用 `grilling` 与 `domain-modeling`，确认前不进入设计和实现。
- 既有领域词汇已经覆盖本次范围：`直接目录模式`、`Worktree 模式`、`任务首发`。本次不新增同义词，也不修改业务行为。

## 已确认事实

1. 截图对应 `TaskModelPushModal` 中的工作区模式选择，不是会话协作模式、权限模式或模型选择。
2. 两个选项仍使用同名原生 `input[type='radio']`，选中值和切换逻辑正常，本次现象可以由样式层完整解释。
3. 全局 `.macos-ai-app :where(input, select, textarea)` 规则把 radio 重置为 `appearance: none`，并赋予文本输入框的背景、边框、阴影、宽度和内边距。
4. 当前 `.task-model-push-mode-choice input` 只覆盖尺寸、外边距和内边距，没有恢复圆形轨道与选中圆点，因此选中 radio 仍为空心。
5. 当前选项卡使用 `align-items: flex-start`，radio 只在顶部增加 `2px` 外边距，不能与由标题和说明组成的完整文案块垂直居中。
6. 既有 `TASK_20260710_001` 已记录过同类全局输入样式污染；本次应继续采用局部、受控的 radio 样式边界，不能放宽业务逻辑或改动全局输入框体系。
7. 首轮真实打包界面验证进一步确认，原有选中态引用了项目中未定义的 `--zeus-accent-primary`，所以选中边框、背景和圆点声明失效；当前产品实际强调色事实源是 `--zeus-product-accent`。

## 已确认决策

1. 选中态采用“单选按钮蓝色圆点 + 卡片强调色边框 + 轻强调色背景”。
2. 垂直居中以“radio 与标题、说明组成的完整文案块整体居中”为准。

## 实施范围

- 已确认只修复任务首发弹窗中的工作区模式选择，不在本任务中重做全局 radio 原语或顺带调整其他页面的单选控件。

## 实施结果

1. 在任务首发弹窗范围内显式恢复 radio 的圆形外框与选中圆点，避免继续继承文本输入框的全局重置结果。
2. 选中卡片统一使用 `--zeus-product-accent`，并增加轻强调色背景；未选中卡片保持原有中性样式。
3. 卡片改为围绕完整文案块垂直居中，radio 不再依赖固定顶部偏移。
4. 补齐悬停、按下、键盘焦点、禁用和减弱动态效果样式，同时保留并发确认复选框原有尺寸规则。
5. 没有修改工作区模式的状态、分支创建、推送或登录业务逻辑。

## 方案方向与取舍

推荐在任务首发弹窗内局部恢复 radio 的圆形轨道、选中圆点、键盘焦点和禁用态，并让卡片内容按整体中线对齐。

优点：

- 选中状态不再只依赖卡片边框，用户可以直接从 radio 本身识别结果。
- 两行说明和单行标题都能保持稳定的整体对齐。
- 修改范围只覆盖任务首发弹窗，不会影响普通文本输入框、复选框或会话页。

代价：

- 选中项同时具有圆点、边框和轻背景三重反馈，视觉存在感会比当前更强。
- 需要分别核对浅色、深色、跟随系统、键盘焦点和窄窗口状态，不能只按当前浅色截图验收。
