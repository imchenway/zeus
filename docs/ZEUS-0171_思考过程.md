# ZEUS-0171 思考过程

## 任务信息

- 任务标题：思考过程。
- 任务类型：优化。
- 现状：上一轮把两条“正在思考”收敛成了一条，但真实思考摘要和工具活动出现后仍错误保留占位；过程字号、已回答问题的颜色层级和普通答复正文观感仍未对齐。
- 预期：同一活动轮次只展示一个可信过程状态；会话页与任务会话抽屉使用同一套清晰、可读的会话排版。

## 现场与代码事实

1. 两条“正在思考”来自同一个 `showThinking` 派生状态，不是 Provider 重复发送。
2. 当前活动轮次已经在 `SessionTurnDuration` 内渲染一条 `TranscriptThinking`，会话记录底部仍根据同一状态无条件补画第二条。
3. 可读思考摘要使用独立的 `13px`，工作活动标题使用 `13px`，活动中的最新一项和展开项使用 `12px`，与会话工作区 `14px` 基准形成过细字号层级。
4. 系统字体与 `14px` 基准只绑定 `.session-codex-parity-v1 .ai-workspace`。普通会话页满足该祖先关系；任务会话抽屉通过 Portal 挂载，内部 `session-workspace-root` 绕过该规则并继承根页面字号。
5. 历史任务 ZEUS-0124 已确认：只移动活动轮次的最新思考摘要，历史轮次继续保留原时间线位置。本任务不推翻该规则。
6. 用户在上一轮改动后的正式应用中补充了当前截图：活动轮次已经出现多段过程说明、工具活动和思考摘要，底部仍显示一条“正在思考”。这证明上一轮只完成了数量去重，没有完成真实反馈接替占位。
7. 快照水合每次发现活动轮次都会递增 `feedbackEpoch`，并且只把状态为 `in_progress` 的条目算作可见反馈。已完成工具活动和已落盘思考摘要仍在界面可见，却不能收敛占位。
8. 已回答询问的问题文字单独使用主文字色和 `590` 字重，周围过程内容使用次要灰色，因此问题标题显得突兀。
9. 普通答复正文当前为系统字体、`14px`、`400` 字重和 `rgb(34 37 41)`；用户提供的 Codex 参考图在相同阅读场景下显得更大、更深、更扎实。

## 已确认领域口径

- **思考摘要**是运行内核提供的阶段性可读说明，保留原文和原始语言。
- **思考占位状态**只在活动轮次尚未出现新思考摘要、工作活动或回答时提供临时反馈。
- “思考过程”是任务标题，不把不可见的完整模型推理冒充成可展示内容。

## 用户确认

1. 会话页与任务会话抽屉统一使用系统字体。
2. 普通答复正文与可读过程内容统一为 `15px`；思考摘要、过程说明和工具活动继续使用次要灰色，只有耗时等元信息保留 `11–12px`。
3. 同一活动轮次最多显示一条“正在思考”，位置在当前轮次末尾。
4. 一旦出现真实思考摘要、工具活动或回答，由真实内容接替占位，不再并排保留“正在思考”。
5. 确认进入实现与验证，不扩展为其他页面的全局字体重做。
6. 已回答询问的问题使用次要灰色并保留加粗，不再用主文字黑色抢占层级。
7. 普通答复正文单独使用略深的答复正文色并保持常规字重；不把过程内容一起改黑。

## 实施方案

### 单一思考占位

- 继续从当前会话状态派生是否需要占位，不新增 React 同步状态。
- 活动轮次已经进入可见轮次结构时，只在该轮次内部渲染占位。
- 活动轮次尚无可见行时，才在会话记录底部使用兜底占位。
- 快照水合只在活动轮次切换或快照首次确认询问已回答时递增 `feedbackEpoch`，不再因普通快照刷新重复制造等待反馈状态。
- 快照按最新询问回答时间判断后续真实反馈；回答后的思考摘要、过程说明、工具活动或回答即使已经完成，也能收敛 `visibleFeedbackEpoch`。
- 实时事件继续通过现有 `feedbackEpoch / visibleFeedbackEpoch` 收敛占位，不用 CSS 隐藏重复节点。

优点：展示数量与活动轮次事实一致，屏幕阅读器也不会重复播报同一状态；不增加状态同步和恢复负担。

代价：需要同时覆盖“已有轮次行”和“轮次尚无可见行”两条渲染路径，不能简单删除底部兜底。

### 统一会话排版根

- 把系统字体与 `15px` 可读正文基准同时绑定到 `ai-workspace` 和 `session-workspace-root`，使普通会话页与 Portal 抽屉消费同一规则。
- 普通答复正文使用独立的 `--session-answer-text` 语义色和常规字重；浅色主题略微加深，深色与跟随系统暗色继续复用主文字色。
- 思考摘要、过程说明、工作活动标题、活动最新项和活动展开项继承可读正文尺寸，但继续使用次要灰色。
- 已回答询问的问题与过程内容使用相同灰色，通过加粗表达问题标题层级。
- 轮次耗时、技能标签和技术详情继续作为 `11–12px` 元信息，不放大为正文层级。

优点：两个入口的可读内容不再随 DOM 挂载位置变化，正文与过程反馈具有稳定阅读节奏。

代价：工作活动区域会比当前占用更多垂直空间，长任务的信息密度略有下降。
