# ZEUS-0173 检查更新页显示百分比进度

## 任务目标

修复 macOS 原生更新窗口在 Homebrew 已输出真实下载量与总量时，仍只显示不确定进度条、不显示百分比的问题。

## 已确认产品边界

- 下载阶段以 Homebrew 实际输出的已下载量和总量为进度事实，例如 `Downloading 59.5MB/158.6MB`。
- 原生更新窗口只显示由真实下载量计算得到的整数百分比，例如 `37%`；不同时显示容量文本。
- 进度条与同一份真实比例同步，不使用定时动画或阶段权重估算。
- Homebrew 信息更新、完整性校验和尚未读到可靠下载比例时，继续使用不确定进度且不显示数字。
- 不改变 Homebrew 预取、SHA-256 校验、用户确认后安装和重启的现有链路。

## 根因

- Homebrew 在伪终端中持续刷新 `Downloading 已下载量/总量` 文本。
- Node.js 子进程的 `data` 事件不保证一次提供完整一行；数字、单位或分隔符可能落在两个数据块中。
- 现有代码只对单个当前数据块执行正则解析。输出被分块时无法取得 `downloadedBytes`，控制器因此只发送不确定进度状态。
- 仅修复终端文本分块仍然不够可靠：Homebrew 使用光标移动、同步更新和就地重画终端进度，后续 Homebrew 格式变化仍可能让文本解析失效。
- Homebrew 下载的真正落盘事实是目标缓存旁边的 `.incomplete` 文件；文件大小与发布清单总大小可以直接形成真实百分比，不依赖终端显示格式。
- 原生 AppKit 窗口已支持确定进度和文本，问题不在原生控件。

## 实施计划

1. 为 Homebrew 下载输出保留有界滚动缓冲，对跨数据块的完整内容执行进度解析。
2. 继续复用发布清单中的可靠总大小作为精确上限，并保留 Homebrew 输出总量的兼容回退。
3. 将下载状态文本收敛为真实整数百分比，不修改其他阶段。
4. 执行格式检查、`pnpm lint`、`pnpm typecheck`、`pnpm build`和 `pnpm package:mac`；再使用独立原生进度辅助程序核对真实百分比文本和进度条。

## 方案优缺点

- 优点：百分比直接来自 Homebrew 实际下载事实；修复范围小，不改变安全校验和安装交易。
- 缺点：下载刚开始、Homebrew 更新信息和完整性校验期间没有可靠比例，因此不会全程持续显示数字。

## 阶段状态

- `grilling` 已完成：用户确认只显示真实整数百分比，并确认按上述边界开始实现。
- `domain-modeling` 已核对：本任务仍属于已有的“更新预取”与“非阻断更新进度窗口”，不新增领域术语或 ADR。
- 当前阶段：开发与隔离验证完成，等待后续真实公开 Cask 下载验收。

## 实现结果

- Homebrew 下载子进程新增 4 KiB 有界进度输出缓冲，同时合并伪终端的标准输出与标准错误进度片段。
- 解析现在基于完整滚动缓冲，可以识别跨多个 `data` 事件的 `59.5MB/158.6MB`。
- 下载进程存活期间每 100 毫秒读取一次 `${cachePath}.incomplete` 的真实文件大小；发布清单提供总大小时，即使 Homebrew 不输出任何可解析文本，也能持续得到真实百分比。
- 相同的已下载量和总量不重复向原生窗口发布，避免无意义刷新。
- 下载阶段的 `progress` 和 `progressText` 由同一比例派生，文本仅为向下取整并限制在 0–100 的百分比。
- 原生百分比文本使用 12 号等宽中等字重和次要文本色，在进度条下方右对齐，与 Homebrew 将下载数据放在终端行尾的扫读方向一致。

## 验证结果

- 分块 Homebrew 替身演练：通过。在 `/tmp` 隔离目录中把 `Downloading 59.5MB/158.6MB` 故意拆成三次输出，服务恢复出 `62,390,272 / 166,304,154` 字节并计算得到 `37%`；随后缓存大小与 SHA-256 复验通过。未调用真实 Homebrew Cask 升级。
- 无终端进度的缓存落盘演练：通过。Homebrew 替身不输出任何容量或百分比，只把 `.incomplete` 文件写到 `370 / 1000` 字节；服务仍发布了 `37%`，随后完整缓存大小与 SHA-256 复验通过。
- 本机真实 Homebrew 现场核对：发现 `Zeus-0.2.36-arm64.dmg.incomplete` 真实存在且已写入 `128,192,512` 字节，证明新增落盘进度通道覆盖用户截图中的实际 Homebrew 下载机制。本轮没有继续或重启这次真实下载。
- 变更文件 Prettier 检查：通过。
- `pnpm lint`：通过。
- `pnpm typecheck`：通过。
- `pnpm build`：通过，原生 `ZeusUpdateProgress` 成功生成。
- `pnpm package:mac`：通过，只生成 `dev.hypha.zeus.test` 的 `Zeus Test.app` 与测试 DMG。
- 打包签名复验：通过。`Zeus Test.app` 和包内 arm64 `ZeusUpdateProgress` 均通过 `codesign --verify`。
- 全仓 `pnpm format:check`：未通过，报告 28 个本任务未修改文件的已有格式差异；本任务的两个 TypeScript 变更文件已单独通过 Prettier。
- 原生辅助程序协议启动：通过。实际进程成功接收 `progress=0.37` 和 `progressText=37%` 并保持运行。
- GUI 可见验收限制：`computer-use` 可以读取已登记的 Zeus 和 Zeus Test 应用，但无法枚举没有独立 App bundle 身份的 accessory 辅助进程，因此本轮没有取得可复核的原生窗口截图。静态、协议运行和打包证据不替代后续真实公开 Cask 下载 GUI 验收。
- 第一轮验证仅证明了简化终端文本和原生状态协议，没有证明用户真实 Homebrew 现场一定会产生百分比；之前将其报告为“已完成”不准确。本次返修以 `.incomplete` 真实落盘文件补齐该缺口。
