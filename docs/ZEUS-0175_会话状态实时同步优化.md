# ZEUS-0175 会话状态实时同步优化

## 当前阶段

实现和静态、构建、测试包门禁已完成；真实会话状态变化的桌面交互验收未完成。

## 真实运行窗口约束

- 用户明确要求：存在外接屏幕时，测试窗口不得在主屏幕打开。
- 启动任何 `Zeus Test.app` 前必须先只读识别当前屏幕拓扑和外接屏坐标，并保证测试窗口从首次创建起就落在外接屏。
- 无法可靠保证窗口位置时，停止 GUI 验收并如实记录缺口，不得在主屏尝试后再移动。

## 用户现场

- 任务类型：优化。
- 现状：多个会话状态展示位置没有及时刷新。
- 截图一显示会话列表中多条会话的活动指示。
- 截图二显示任务表“运行状态”列中同时存在“运行中”、“等待新指令”和“未启动”等投影。
- 预期：状态发生变化后立即自动刷新。

## 已核对的领域边界

- 项目词汇已有“会话列表展示状态”：它是会话当前生命周期的只读投影，后台会话进入响应、等待用户、等待批准、完成、失败、暂停或排队时都必须自动更新。
- “会话列表展示状态”不是任务管理状态，也不是会话行的选中状态。
- 任务表“运行状态”是最近关联会话生命周期的只读汇总；点击只负责打开对应会话抽屉，不应承担刷新职责。
- 本任务不应用会话运行状态改写任务管理状态。

## 根因结论

- Local Server 会把会话轮次、队列、交互请求和错误等领域事件通过 WebSocket 广播，并为会话事件补全项目与会话身份。
- Renderer 收到生命周期事件后，会重新读取对应会话的轻量元数据，并更新任务会话或项目对话快照。
- 全局会话列表事件订阅当前只建立一次 WebSocket；连接关闭后没有自动重连，也没有重连后的权威快照校准。
- 当前打开的会话控制器拥有独立重连链路，但后台会话列表和任务表仍依赖上述全局订阅；这会导致同一会话在不同位置的投影分裂。
- 当前同时存在服务端轻量快照、已连接会话控制器状态和 Renderer 会话实时状态缓存。
- 任务表会优先使用 Renderer 缓存的会话运行状态；如果该缓存没有随新的权威快照收敛，旧值可能覆盖已更新的服务端状态。
- 根因是全局事件链缺少断线恢复，同时 Renderer 运行状态缓存没有在批量权威快照到达时统一收口。只修任务表映射不能解决会话列表、抽屉和标题区的同源分裂。

## 待用户逐项确认

1. 已确认：“立即自动刷新”覆盖同一会话在会话列表、任务表运行状态、任务会话抽屉和当前会话标题区的所有生命周期投影。
2. 已确认：同一任务有多条会话时，任务表继续按“会话阶段更新时间最新的关联会话”汇总，不改为“任意一条运行就显示运行中”。
3. 已确认：实时事件连接断开时自动重连，重连成功后立即读取当前项目完整会话快照校准；正常连接期间不增加固定轮询。
4. 已确认：正常连接下，“立即”的可验收延迟上限为一秒。

## 用户确认结论

- 用户已确认上述需求边界完整，允许进入设计、实现和验证。
- 正常连接下的状态投影一致更新上限确认为一秒。

## 实施设计

1. API Client 提供单一全局事件订阅，监听连接关闭与错误，使用有上限的指数退避重连。
2. 本机服务重连前先通过 Electron Main 刷新服务地址和凭据，避免重启后永久连接旧端口。
3. 每次收到 `server.connected` 后，App 立即读取当前项目的会话分组快照，同时校准项目对话、任务会话与 Renderer 投影缓存。
4. 每个生命周期事件仍只读取对应会话的轻量元数据，并对当前打开会话与后台会话使用同一权威收口。
5. 连接或快照校准未完成时，以可读文字和非颜色状态指示展示“正在同步会话状态”，并在减少动态效果下停止旋转动画。

## 当前取舍判断

- 事件驱动同步的优点是延迟低、无需持续请求；缺点是断线或漏事件后可能长时间保留旧投影。
- 低频快照校准的优点是能在事件链异常后自愈；缺点是增加本机请求和数据查询，不能代替正常实时事件。
- 只修任务表映射的优点是变更小；缺点是会保留会话列表、抽屉和标题区之间的状态分裂，不符合本任务的多处不一致现场。

## 实施结果

- API Client 增加可取消的全局事件订阅：首次连接失败或连接关闭后自动重试，退避上限为四秒；本机服务重启后先刷新地址与凭据。
- 每次实时连接成功后读取当前项目完整会话分组，并把服务端元数据同时写回项目会话、任务会话、会话树状态和任务表运行状态缓存。
- 生命周期事件仍按单会话轻量刷新，但不再跳过当前打开会话，避免控制器状态与列表状态长期分裂。
- 断线和快照校准期间保留最后已知状态，并显示“正在同步会话状态”；校准失败继续按最多八秒的退避自动重试。
- 同一任务的汇总规则保持不变，仍取 `stageUpdatedAt` 最新的关联会话，不改写任务管理状态。

## 真实运行验收缺口与窗口约束事故

- 只读屏幕检查确认当前有三块屏幕：主屏为横向外接屏，另有内建屏和竖向外接屏。
- 本轮尝试在隔离 `ZEUS_USER_DATA_DIR` 中预置竖向外接屏指纹后启动测试包，但 Electron 未匹配该指纹，日志明确返回 `primary-fallback`，测试窗口仍落到主屏；发现后立即终止了本任务进程，未触碰其他 worktree 的测试实例。
- 这次启动违反了用户“外接屏存在时测试窗口不得在主屏打开”的明确约束。后续不得再依赖预置指纹推测窗口落点；在应用提供启动前可验证的目标显示器参数之前，本任务不再启动 GUI。
- 因此不能宣称真实会话状态变化、一秒收敛或断线提示已经通过桌面交互验收；当前通过项仅覆盖静态检查、构建和测试包健康。
