# ZEUS-0176 环境信息卡片优化

## 任务目标

优化会话工作区中的环境信息卡片，增加命令执行入口和代码审查入口。

## 当前阶段

实现与验证完成。

## 已核对事实

- 环境信息卡片当前同时展示会话执行目录、Git 分支、工作区变更、代码交付和会话来源。
- 卡片中的“变更”会打开既有任务 Git 审查界面，属于当前已有的快速代码变更审查能力。
- 卡片中的“代码交付”会进入既有代码交付主页面，负责查看变更、提交、合入和推送，不应与代码审查入口混为一条动作。
- 项目命令能力当前位于“代码 → 命令”，复用命令中心的命令定义、权限确认、运行历史、日志、产物和停止能力。
- 项目自由对话可能没有关联任务工作区，但仍可能存在项目与会话执行目录；入口可用边界需要由用户确认。

## 待确认决策

无。

## 已确认决策

### 命令执行入口

点击后进入当前项目的完整命令中心，也就是“代码 → 命令”模式；不在环境信息卡片内直接执行命令，也不打开自由 Shell 终端。

优点：复用既有命令定义、项目权限、逐次确认、风险提示、运行历史、日志、产物和停止能力，不形成第二套执行链路。

缺点：点击后会离开当前会话视图，用户需要再返回会话继续阅读或输入。

### 代码审查入口的能力类型

“代码审查”用于启动真实 AI 审查，不复用现有“变更”按钮的只读 Git 差异查看能力。

优点：入口能直接产出正确性、风险和验证缺口等审查意见，与“变更”和“代码交付”的职责明确区分。

缺点：它会创建或推进真实模型执行并消耗资源，因此仍需继续确认会话归属、审查范围、权限和启动门禁。

### AI 审查会话归属

点击“代码审查”后新建一条独立的 AI 代码审查会话，不把审查提示作为当前开发会话的下一条消息。

优点：审查结论与开发过程分开保存，便于独立阅读、回看和继续追问。

缺点：同一任务会增加一条关联会话，并且需要明确复用当前开发现场的范围与运行配置。

### AI 审查范围

默认审查当前会话实际执行环境相对其冻结来源基线的完整代码变化，包含已提交、已暂存、未暂存和未跟踪文件；不自动扩展到同一任务开发线中的其他仓库环境。

优点：已经提交的任务代码不会漏审，同时范围仍与用户点击入口时看到的环境卡片一致。

缺点：未跟踪生成物可能带来噪音，审查提示需要先识别并说明排除项；多仓任务需要在各自环境中分别发起审查。

### AI 审查权限

新建审查会话继承当前开发会话的权限配置，不固定为只读，也不在启动前增加权限选择。

优点：审查会话与当前开发现场能力一致，用户后续要求进一步核查或修复时不必重建会话。

缺点：审查会话具备写权限时可能改变被审对象；默认审查提示必须明确只分析和报告、不主动修改代码，界面也不能把“继承权限”表达成“会自动修复”。

### AI 审查启动门禁

点击“代码审查”后先打开启动确认面板，不立即创建会话或派发模型。面板展示审查范围、实际模型和继承的权限，用户再次确认后才创建并启动独立审查会话。

优点：用户能在产生模型消耗、并以可能可写的权限进入工作区前核对真实影响，避免误触。

缺点：从环境信息卡片到审查结果之间增加一次确认操作。

### 执行环境复用事实

现有任务会话创建接口支持使用来源会话身份复用其持久化任务环境，因此独立审查会话无需新建、复制或切换 worktree。当前通用创建链路不会自动继承来源会话的完整模型配置，模型规则仍需明确实现。

### AI 审查模型

启动确认面板默认继承当前开发会话的模型、推理强度和服务档位，并允许用户在确认启动前调整；权限配置继续直接继承，不在该面板中调整。

优点：默认延续当前任务的真实模型选择，同时允许为独立审查临时选择更合适的模型能力。

缺点：确认面板需要展示模型、推理强度和服务档位控件，复杂度高于只显示确认摘要。

### AI 审查提示

首轮使用固定的全面风险审查提示，只分析和报告，不主动修改代码。审查覆盖正确性、业务边界、安全、性能、并发、可维护性、项目规范一致性和验证缺口；每条明确发现包含严重级别、文件位置、事实证据、影响和修复建议。没有明确问题时仍说明审查范围与残余风险。

优点：审查结果具有稳定结构，能直接支持开发会话后续修复和人工复核。

缺点：相较只查阻断问题，会消耗更多审查时间和模型上下文。

### 入口校验边界

命令执行和代码审查入口始终可点击，不新增前端资格判断、隐藏规则或禁用规则。代码审查点击后直接进入已确认的启动面板；用户确认后由现有后端基于真实会话现场执行，无法复用环境时返回真实错误。

优点：用户路径直接，环境信息卡片不承担服务端事实判断，也不会因前端快照未加载或暂时失败错误拦截能力。

缺点：缺少真实执行现场的少数会话会在用户确认启动后才得到失败反馈，而不是在卡片阶段提前阻止。

### 入口布局

“命令”和“代码审查”作为两个紧凑操作行放在环境信息卡片的本地目录、分支信息之后，代码交付之前；常驻卡片与收起弹层复用同一组件，因此入口位置和行为一致。

优点：先展示当前现场，再提供基于现场的操作；“变更”“代码审查”“代码交付”保持三个独立职责。

缺点：卡片操作行增加后纵向长度变长，窄窗口可能需要在卡片内部滚动。

## 实现结果

### 命令入口

- 新增始终可点击的“命令”操作行。
- 点击后切换到当前会话所属项目的“代码 → 命令”完整工作台。
- 导航继续经过既有工作区离开确认，不复制命令运行、确认、日志、产物和停止协议。

### 代码审查入口与确认面板

- 新增始终可点击的“代码审查”操作行。
- 点击后打开确认面板，不立即创建会话。
- 面板展示单仓审查范围和继承权限；模型、推理强度、服务档位按当前会话预填并允许调整，权限只读展示。
- 用户确认后，前端通过已有持久化接受信封发送带 `code_review` 来源的创建请求，并在服务端接受后切换到新会话。

### 服务端真实现场校验

- 服务端根据来源会话重新读取任务环境和精确仓库工作区，不接受前端自报路径或扩大仓库范围。
- 新会话复用来源会话的环境标识，并把会话工作区固定为来源会话对应的单个仓库。
- 服务端重新核对模型、推理强度、服务档位和模型归属，并强制审查权限与来源会话当前权限一致。
- 固定审查提示覆盖冻结来源基线之后的已提交、已暂存、未暂存和未跟踪变化；要求只分析报告，不修改、提交、推送、合入或回退。
- Codex 与 Pi 两条现有模型执行链路都支持审查会话；长审查提示只发给模型，会话正文展示简短的用户动作说明。

## 约束

- 不在卡片内复制命令执行、Git 审查或代码交付流程。
- 命令执行继续服从既有权限确认、风险确认、运行日志和审计规则。
- Git 写操作继续服从既有服务端校验与安全门禁。
- 本任务不创建或恢复单元测试体系；实现后的验证按静态检查、构建、测试身份打包和必要的真实运行证据分别记录。
- 检测到外接屏时，任何 `Zeus Test.app` GUI 验收窗口只能放在非主屏，禁止在用户主屏打开；若无法可靠识别或固定到外接屏，则停止 GUI 验收并记录缺口。
- 不生成、启动或操作生产身份 `Zeus.app`。
