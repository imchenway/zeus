# ZEUS-0178 提交代码不因空白格式阻断

## 背景

用户在代码提交时收到以下错误，导致本地提交无法创建：

```text
提交前 Git 空白检查失败：
docs/adr/0003-knowledge-governance-and-hybrid-retrieval.md:28: new blank line at EOF.
docs/api/knowledge-admin.md:45: new blank line at EOF.
```

`new blank line at EOF` 只表示正文结束后新增了多余空行，不表示 Markdown 内容损坏、Git 仓库损坏或存在未解决合并冲突。Git 可以报告这类空白问题，但普通提交工具没有义务把它升级为禁止提交。

## 已确认边界

- 普通代码提交不再因为 Git 空白格式报告被 Zeus 硬拦截。
- 项目显式声明 Prettier 时，仍沿用现有自动格式化能力。
- 未解决的 Git 合并冲突继续阻止提交。
- 项目自身的 Git hook、远端 CI 和 Zeus 发布门禁不在本次修改范围内。
- 本任务不执行 Git commit、push、merge、revert 或发布。

## 方案与取舍

移除 `commitTaskWorkspace` 中对暂存内容执行的强制 `git diff --cached --check`。选中文件仍按原流程格式化、暂存并创建本地提交；工作区冲突状态仍在提交入口最前方检查。

优点：用户可以像在 IDEA 或 Git 中一样完成普通本地提交，不必为不影响内容语义的末尾空行中断工作。

缺点：没有自动格式化能力的项目可能把空白问题写入本地提交，后续仍可能被仓库自身 hook、CI 或发布流程拒绝。

不采用“只忽略文件末尾空行、继续阻止其他空白问题”，因为这仍把 Git 的格式提示变成 Zeus 自己的硬门禁，不能解决普通提交责任越界的问题。

## 实施记录

- 已定位硬门禁位于 `packages/git-core/src/index.ts` 的 `commitTaskWorkspace`。
- 已确认未解决冲突使用 `review.conflictFiles` 独立阻断，不依赖空白检查。
- 已移除普通提交中的 `git diff --cached --check` 调用及对应错误转换。
- 已在 `CONTEXT.md` 补充“代码提交格式整理”，明确它不等同于 Git 冲突或发布门禁。

- `pnpm lint`：通过。
- `pnpm typecheck`：通过。
- `pnpm build`：通过；Vite 仅报告既有的大分块体积提示。
- 真实代码提交：未执行。项目约束禁止智能体自行创建 Git 提交；当前结论由实现检查、类型检查和完整构建支持。
- `pnpm package:mac`：通过，生成并完成签名结构校验的独立身份 `Zeus Test.app` 与测试 DMG；未启动应用，因此不代表真实提交界面已经完成 GUI 验收。
