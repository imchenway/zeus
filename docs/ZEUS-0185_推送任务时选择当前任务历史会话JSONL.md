# ZEUS-0185 推送任务时选择当前任务历史会话 JSONL

## 任务信息

- 任务类型：优化。
- 现状：任务推送到新会话时，已经可以从父任务上下文和关联任务上下文中逐项选择既有会话，但当前任务自身的历史会话没有选择入口。
- 预期：任务推送时可以选择当前任务之前会话的真实 JSONL 文件路径，并沿用父任务、关联任务会话的选择、复验和发送规则。

## 当前阶段

- 阶段：开发、静态检查、构建和测试身份打包已完成；真实 GUI 与 Provider 发送验收待具备隔离数据样本和可用账号时补充。
- 已完成 `grilling` 与 `domain-modeling` 的规则读取，并核对现有任务文档、领域语言、推送弹窗、共享首发布局和服务端复验链路。
- 用户已确认共同理解：当前任务正常关联到的既有会话都进入“当前任务历史会话信息”，可以由用户选中并随本次任务首发发送，不增加任务状态、会话状态或归档状态门禁。

## 已核对事实

1. 当前任务内容和当前字段附件会自动进入任务首发，但当前任务历史会话不在能力快照和提交选择中。
2. 父任务与关联任务的会话均由服务端按任务归属列出，默认不选，用户逐项勾选；已归档会话仍可展示。
3. 会话只有在 Provider 返回真实路径，且该路径是存在、可读取、非符号链接的普通 JSONL 文件时才可选择。
4. 提交时服务端会重新构建上下文快照并复验会话 ID、任务归属和 JSONL 路径；弹窗打开后事实变化会阻止创建会话并要求刷新。
5. 选中会话不会把 JSONL 正文复制到首条消息，只会把服务端复验后的绝对路径写入首发布局，并把所在目录加入本轮只读资源根。
6. 当前首发布局已经支持在“当前任务”区块内写入 `conversationPaths`，但现有能力快照和请求契约从未给该字段提供当前任务历史会话选择结果。

## 已确认术语

**当前任务历史会话信息**：
用户在任务首发时从当前任务已存在的会话中逐项选择的会话 JSONL 文件路径；它只补充本次新会话的首条输入，不复用或改写历史会话，也不展开复制会话正文。

建议避免使用“传入 JSONL 文件内容”，因为现有真实契约传入的是经服务端复验的文件路径，模型按需读取原文件。

## 已确认决策

### 当前任务历史会话信息的位置与顺序

- 所选路径直接写入当前任务区块现有的“会话文件路径”段。
- 名称统一为“当前任务历史会话信息”。
- 首发顺序固定为“当前任务 → 当前任务历史会话信息 → 补充信息 → 父任务上下文 → 关联任务上下文”。

优点：复用现有布局数据结构，预览和 Provider 输入顺序直观，不拆分或重复当前任务内容。

代价：当前任务正文会比过去多一段路径列表；选择多条长路径时首发预览会变长。

### 推送弹窗的选择方式

- “当前任务历史会话信息”只展示当前任务既有会话，不提供“选择当前任务”复选框。
- 每条会话默认不选并逐项勾选，不提供全选，不记忆上次选择。
- 当前任务内容和当前字段附件继续按既有规则自动进入首发，不受历史会话选择影响。

优点：用户只决定要补充哪些历史会话，不会把“当前任务是否发送”变成一个可误关的开关，并与父任务、关联任务的会话逐项选择保持一致。

代价是历史会话很多时需要逐项操作，不能一键全选。

### 历史会话候选范围与顺序

- 完全沿用父任务、关联任务的候选范围，按创建时间从早到晚展示当前任务全部既有会话。
- 候选包含已归档会话和仍在运行的会话；界面标明归档状态。
- 只要服务端复验后的真实 JSONL 路径可用，就允许选择，不因归档或运行状态额外阻断。

优点：三类会话选择规则一致，用户也能主动把正在推进的并行会话作为背景信息。

代价：仍在运行的会话 JSONL 可能继续追加内容，执行模型稍后读取时看到的内容可能比提交瞬间更多；本能力冻结的是经过复验的路径，而不是 JSONL 文件内容副本。

### 不可用历史会话的展示

- JSONL 路径不可用的历史会话仍显示在“当前任务历史会话信息”中，但复选框禁用。
- 界面直接说明“路径未返回、不是普通 JSONL 文件、文件缺失或不可读取”等真实原因，不把不可用会话静默隐藏。

当前服务端会在以下情况判定 JSONL 不可用：

1. Provider 没有为会话返回并持久化原生会话文件路径，例如旧式会话、原生 thread 尚未成功建立，或创建早期失败。
2. 已记录的路径不是绝对路径，或者文件名不是 `.jsonl` 后缀。
3. 路径指向符号链接；为避免通过链接越过真实资源边界，不能作为普通 JSONL 文件发送。
4. 路径已经不存在、当前进程无权读取，或者解析真实路径失败。
5. 路径存在，但目标不是普通文件，例如变成了目录。

会话正在运行、已经结束或已经归档本身都不代表 JSONL 不可用；只要上述文件复验通过就可以选择。

优点：用户能区分“当前任务没有历史会话”和“存在历史会话但 JSONL 不可传入”，也与父任务、关联任务现有表现一致。

代价：不可用会话较多时列表会更长；需要通过禁用样式和原因文案保持可扫描性。

### 提交复验

用户打开推送弹窗并选中历史会话后，提交继续复用父任务、关联任务现有的服务端复验，确保最终发送的仍是该任务关联会话的真实 JSONL 路径，不增加额外业务门禁。

优点：弹窗预览、用户选择和实际 Provider 输入保持一致，同时不限制正常关联会话。

代价：文件在弹窗打开后真实失效时，仍需刷新选项，不能发送不存在的路径。

## 实施范围

1. 能力快照增加当前任务既有会话选项，并纳入同一任务上下文修订值。
2. 推送弹窗增加“当前任务历史会话信息”，只提供会话逐项选择。
3. 提交请求携带所选当前任务会话 ID，服务端按当前任务归属重新解析真实 JSONL 路径。
4. 所选路径进入当前任务首发布局，预览、待创建工作面、Provider 输入和持久消息共用同一快照。
5. 刷新上下文时保留仍然有效的当前任务历史会话选择。

## 实现记录

1. 共享首发输入增加当前任务 `conversationPaths`，当前任务区块使用“当前任务历史会话信息”标签，父任务和关联任务继续使用“会话文件路径”。
2. 任务首发能力快照增加 `currentConversationOptions`，直接从 `task_id` 对应的全部既有会话生成，顺序和归档范围复用父任务、关联任务链路。
3. 推送弹窗增加单列“当前任务历史会话信息”选择区，每条会话独立勾选，不增加任务开关、全选和持久记忆。
4. 提交请求增加 `currentConversationIds`；服务端重新按当前任务候选解析会话 ID，只接受复验后的真实 JSONL 路径，并将目录加入本轮只读资源根。
5. 弹窗预览、即时首发工作面、Provider 派发和持久用户消息继续共用同一任务首发布局；上下文刷新会保留仍可用的当前任务会话选择。
