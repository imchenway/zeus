# ZEUS-0188 状态栏样式优化

## 任务信息

- 任务类型：优化
- 当前阶段：实现完成；静态、构建、测试身份打包与隔离启动检查通过，真实菜单栏点击视觉验收受桌面控制服务阻塞
- 用户目标：菜单栏用量浮窗四周不再出现截图中的黑色硬边，外缘参考用户补充截图中的浅灰细边与柔和环境阴影
- 安全边界：不修改 Git 历史或远端；不新增或恢复单元测试体系；真实运行只使用独立身份和独立数据目录的 `Zeus Test.app`

## 历史与领域边界

- 本任务延续 `ZEUS-0182` 已实现的“菜单栏 Zeus 入口 + 菜单栏用量浮窗”路径，不重新引入 Zeus 主窗口顶部统计入口。
- 本次只处理浮窗外缘与阴影归属，不改变菜单栏 Zeus 图标、配额卡片等内部描边、配额、Token、费用估算的数据来源、信息层级、加载状态和底部动作。
- 项目既有文档已将该界面称为“菜单栏用量浮窗”；用户补充的外缘参考图已经确认本任务对象是该浮窗，不是代码编辑器底部状态栏。

## 已核实的现状

1. Electron Main 创建的是 `360 × 520`、透明、无边框窗口，并启用了 macOS 原生窗口阴影 `hasShadow: true`。
2. Renderer 根容器四周保留 `8px` 透明内边距，内容面板另外绘制两层 CSS 阴影：`0 17px 42px / 25%` 与 `0 2px 8px / 12%`。
3. 根节点和窗口视口设置了 `overflow: hidden`，内部 CSS 阴影超过透明内边距后会在窗口边界被裁切。
4. 用户截图中的深色外缘与这条“双重阴影 + 视口裁切”链路一致；它不是统计卡片普通 `border`，仅把描边设为透明无法消除。

## 已确认决策

### 浮窗外缘层级

用户确认：保留轻柔悬浮层级。外缘目标为连续的低对比浅灰细描边，阴影与描边分离并向外柔和扩散；不得出现贴着窗口边界的黑色硬圈。优先移除内容面板的两层 CSS 重阴影并保留 macOS 原生阴影，在真实测试包中对照参考图；若系统阴影本身仍形成深色硬边，则改为受控的低透明度 CSS 环境阴影并扩大透明安全区，最终以外缘效果而不是具体阴影来源验收。

优点：消除被视口裁切形成的黑色硬边；继续保留浮窗与背景的层级感；不影响内部信息布局与交互。

缺点：原生阴影的最终强度由 macOS 控制，必要时需要切换为自绘阴影并调整透明安全区，真实 GUI 验收不可省略。

已放弃的备选：同时关闭 CSS 阴影和 macOS 原生阴影。

优点：浮窗外缘最干净，不会出现任何阴影色带。

缺点：浅色背景上浮窗与后方内容的层级变弱，容易显得贴在页面中；需要依赖现有细描边维持边界。

## 已完成实现

1. 菜单栏用量浮窗外缘新增独立的 `--usage-edge` 语义变量，不再复用内部指标分隔线 `--usage-line`。
2. 浅色外缘使用中性深色 `13%` 透明度，深色与跟随系统深色外缘使用白色 `14%` 透明度，形成连续低对比细描边。
3. 删除内容面板原有 `0 17px 42px / 25%` 与 `0 2px 8px / 12%` 两层 CSS 重阴影，消除阴影超出 `8px` 透明安全区后被窗口边界裁切形成黑色硬圈的来源。
4. Electron Main 的 `hasShadow: true` 保持不变，浮窗悬浮层级继续由 macOS 原生窗口阴影提供。
5. 菜单栏 Zeus 图标、浮窗内部卡片描边、内容结构、数据请求、加载与错误状态和底部动作均未修改。

优点：改动只作用于浮窗外缘，根因链路被收敛，内部信息层级与交互无回归面扩大。

缺点：原生阴影的可见强度仍由 macOS 决定；没有真实菜单栏截图时不能断言不同系统外观下已经完全贴合参考图。
