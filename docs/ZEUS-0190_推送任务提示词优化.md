# ZEUS-0190 推送任务提示词优化

## 当前阶段

- 用户已确认需求边界，实现、静态检查、独立测试包和真实打包 Renderer 检查均已完成。
- 隔离测试实例没有 Zeus 专属 Codex 登录态，因此没有实际发起 Provider 首轮；这一缺口不以模拟结果替代。
- 本任务不执行 Git commit、push、merge 或其他历史与远端写入。

## 用户反馈

当前任务首发会把空字段写成“未提供”，把任务类型与标签作为正文发送，并把“现状 / 预期”等内容字段标题显示为 `11px` 元数据字号。用户要求：

1. 没有内容的字段不显示，也不发送“未提供”；
2. 内容字段标题不再使用过小字号；
3. 任务类型与标签不需要推送。

## 已确认决策

### 全链路使用同一精简内容

推送预览、Provider 实际收到的首条输入、发送后的用户消息和重开后的历史消息必须共用同一任务首发布局，不允许只改可见界面。

优点：用户预览与模型输入可以直接对账，不会出现界面隐藏但模型仍收到旧字段的差异。

代价：共享布局属于持久提交事实，历史兼容和 Renderer 展示需要同时核对，不能只修改一个组件。

### 空字段按文字与附件共同判断

- 字段没有文字且没有附件时，字段标题与“未提供”一起省略；
- 字段文字为空但存在附件时，附件本身属于有效内容，保留字段标题并发送附件；
- 当前任务、父任务和关联任务使用同一规则。

优点：不会因文字为空误删真实截图或文件，也不会用占位文案放大空信息。

代价：布局生成需要先汇总字段附件再判断字段是否有效，不能只对字符串做过滤。

### 任务类型与标签不进入首发

- 任务类型继续决定需求、缺陷或优化当前使用哪些内容字段，但不作为正文发送；
- 标签文字和标签附件都不进入首发；
- 标签与标签附件仍完整保留在任务详情中，本任务不删除或迁移任务数据；
- 当前任务、父任务和关联任务使用同一规则。

优点：任务管理元数据不再干扰模型阅读，首条消息更接近用户真正写下的工作内容。

代价：模型不再直接看到任务分类与标签；需要影响执行的信息必须写入内容字段或本次补充信息。

### 内容字段标题提升为小节标题

“需求描述 / 现状 / 预期 / 复现步骤”等字段标题在推送预览和会话消息中统一使用 `15px` 半粗小节标题，不再使用 `11px` 元数据层级。正文密度保持不变。

优点：内容结构更容易扫描，字段标题与正文形成明确层级。

代价：长任务消息会略微增加纵向视觉重量，需要同时检查窄窗口与多上下文区块。

## 现状证据

- `packages/shared/src/taskPush.ts` 的 `activeTaskFields()` 为每个空字段和空标签生成“未提供”，并把标签加入所有任务区块。
- 同文件的 `appendTaskBlockParts()` 无条件写入 `任务类型`，因此纯文本提示和 Provider 输入都会携带类型。
- `TaskModelPushModal.tsx` 与 `ThreadItemView.tsx` 都渲染 `block.taskTypeLabel` 和全部 `block.fields`。
- `styles.css` 与 `session.css` 都把内容字段标题设为 `11px`。
- 标签附件当前随 `activeTaskFields()` 进入有效字段集合，不能只删除标签文字而继续无语义地发送附件。

## 实施规划

1. 在共享任务首发布局中只保留当前类型下含文字或附件的内容字段，排除标签与标签附件，并停止生成“未提供”。
2. 在共享纯文本与结构化输入中停止输出任务类型，保持标题、有效内容字段、补充信息、手选上下文和会话路径的既有顺序。
3. 推送预览和会话消息停止渲染任务类型，并把字段标题提升到 `15px` 小节标题。
4. 核对标签与标签附件仍保留在任务数据和任务详情中，只从首发布局过滤。
5. 执行格式检查、`git diff --check`、`pnpm lint`、`pnpm typecheck`、`pnpm build` 和 `pnpm package:mac`；只生成独立身份 `Zeus Test.app`。
6. 在隔离数据目录中检查推送预览与已发消息的空字段、附件字段和标题层级；无法取得真实 Provider 或 GUI 证据时单独报告缺口。

## 验证记录

### 实现结果

- 共享任务首发布局只接收当前任务类型下有文字或字段附件的内容字段；完全空字段不再生成标题和“未提供”。
- 任务类型、标签与标签附件从当前任务、父任务和关联任务的首发布局中统一排除；原始任务数据与任务详情不变。
- Provider 输入、纯文本回退、推送预览、乐观消息、持久消息和历史消息继续读取同一布局快照；没有增加 Renderer 单侧隐藏逻辑。
- 只有附件而没有文字的内容字段继续保留标题和附件；空文字不再渲染空正文节点。
- 推送预览与会话消息的内容字段标题统一为 `15px`、`650` 字重和 `22px` 行高。

### 共享布局探针

通过仓库现有 `tsx` 运行共享布局构造器，核对以下边界：

- 优化任务的非空“现状”文字与现状附件保留；
- 空“预期”存在附件时保留字段标题和附件，字段文字为空；
- 标签文字与标签附件均不进入布局；
- 纯文本输出不包含任务类型、标签和“未提供”；
- 内容完全为空的缺陷任务只保留任务标题，字段数组为空。

### 真实打包 Renderer 检查

使用临时数据目录 `/tmp/zeus-0190-gui.rp5BDx` 启动本任务生成的 `Zeus Test.app`，创建隔离项目和优化任务，并从真实任务详情打开“推送到新会话”弹窗。检查结果：

- 预览文本只有任务标题、“现状”和真实现状正文；
- 预览范围内不存在任务类型、标签和“未提供”；
- “现状”计算样式为 `15px / 650 / 22px`；
- `1240 × 820` 与模拟 `720 × 820` 渲染视口都没有页面级横向溢出；
- 窄视口预览仍保持相同文本与字号；
- 控制台只有 Chromium 对 `file://` 页面中 `meta` 形式 `frame-ancestors` 的既有提示，没有本次改动引起的应用异常。

桌面验收服务启动失败，因此本轮使用 Electron 打包应用自身的调试接口读取真实 DOM 与计算样式；它证明打包 Renderer 的实际渲染结果，但不等同于鼠标、键盘或辅助功能树验收。
