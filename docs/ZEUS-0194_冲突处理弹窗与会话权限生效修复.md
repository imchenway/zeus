# ZEUS-0194 冲突处理弹窗与会话权限生效修复

## 任务类型

缺陷。

## 用户反馈

- “选择本次冲突处理权限”弹窗的选中控件、页面层级和整体视觉过于粗重。
- 用户选择“自动”或“完全访问”后，所选权限实际没有生效到打开的冲突处理会话。
- AI 已经在隔离合并工作区处理冲突但没有形成合入提交时，代码交付页仍显示旧的“冲突未处理”状态。
- 用户未提供目标图、预期文案或复现步骤；原始截图显示当前弹窗使用大面积选项卡、放大的空白原生单选控件、强蓝描边和过大的主按钮。

## 当前阶段

实现与静态、构建、打包、隔离运行检查已完成。真实冲突点击、两种权限四层对账和弹窗视觉验收仍受当前自动化环境限制，未冒充为已完成。

## 已核实现状

### 已有领域口径

- “AI 冲突处理会话”是专用于修改和暂存隔离合并工作区的可见会话，不是普通任务开发会话。
- 用户每次点击“AI 处理”都新建一条冲突处理会话；不得复用、续接或重新打开旧冲突处理会话来代替本次新建。
- 该入口只允许“自动”和“完全访问”，不提供无法完成冲突处理的只读模式。
- “自动”表示项目工作区可写并按需审批；“完全访问”表示不受沙箱限制且不逐次审批。
- AI 不执行提交、目标分支更新或远程推送；这些边界不因完全访问而取消。

### 权限传递链

- Renderer 的 `TaskGitConflictWorkspace` 保存用户选择，并通过 `TaskGitMergeModal` 和 API Client 把 `permissionMode` 发给冲突会话接口。
- Local Server 会拒绝缺失、非法或只读权限；新建 Codex 或 Pi 冲突会话时会把所选权限写入会话。
- Codex 协调器会把“自动”映射为隔离工作区可写和按需审批，把“完全访问”映射为完全访问和不逐次审批。

### 已确认缺陷

同一合入记录已经登记冲突处理会话时，接口会直接返回旧会话，不比较、不更新也不拒绝本次请求携带的权限。界面仍让用户重新选择并显示“以自动权限开始”或“以完全访问权限开始”，实际却可能打开另一种权限的旧会话。

这使界面选择、会话持久权限和当前轮执行权限不再是同一事实，属于功能缺陷，不只是显示问题。

同时，复用旧会话本身已经违反用户此前确认并在本轮再次确认的产品口径：任何一次“AI 处理”点击都必须创建新会话。旧任务文档 `ZEUS-0154` 曾记录“重复点击复用原会话”，该旧实现事实被本次明确决策取代，不再作为当前需求依据。

代码交付页的合入记录刷新接口当前只返回数据库中持久的 `state` 和 `conflictFiles`，没有读取隔离合并工作区最新的 Git 未解决索引。AI 按提示修改并 `git add` 后，真实 Git 状态可以已经没有未解决项，但数据库仍保留启动合入时的冲突文件列表，因此页面继续显示“冲突未处理”。

AI 提示词明确禁止智能体执行 `git commit`；现有服务端会在 AI 轮次完成后尝试由 Zeus 自动复验、生成合入提交并同步本地目标分支。允许多条冲突处理会话并行后，任一轮次先完成就自动提交并可能回收共享隔离工作区，会与仍在运行的其他会话发生生命周期冲突，旧自动收尾方式不能原样保留。

## 已确认决策

### 每次新建冲突处理会话

- 每次用户完成权限选择并点击开始，服务端都创建新的 Zeus 会话身份、Provider 原生会话身份和首轮提交。
- 每条新会话同时创建自己独占的隔离合入现场，不与旧会话共享文件或 Git 暂存区。
- 本次选择的权限直接写入这条新会话及其下一轮配置，并用于首轮 Provider 权限映射。
- 旧冲突处理会话继续保留为可查看历史，但不复用、不续接、不改写权限，也不被本次入口重新打开。
- 已有活动冲突处理轮次时，也允许立即并行创建新会话和新隔离现场，不停止旧轮次、不阻止本次新建。

优点：每次用户选择、会话身份和首轮实际权限严格一一对应，不会把旧上下文或旧权限带入本次处理。

代价：同一冲突可能产生多条历史会话和多份隔离现场；服务端必须按会话追踪执行与收尾，并安全回收不再有效的现场。

### 活动会话仍允许并行新建独立现场

- “AI 处理”不因旧冲突处理会话处于排队、执行或等待状态而禁用。
- 新会话拥有独立会话身份、首轮提交、所选权限、任务事件和隔离合入现场；不同会话不共享文件或 Git 暂存区。
- 服务端不能再用以主合入记录为键的单一会话槽表示所有 AI 操作；必须逐会话追踪运行和收尾状态。
- 某条会话完成后，Zeus 只复验它绑定的隔离现场。首个仍匹配最新目标与任务基线、已无未解决冲突的结果可以生成合入提交并推进代码交付状态。
- 一项结果已经完成本地合入后，其他会话不得再次覆盖该结果；会话历史继续可见，失效的隔离现场在对应轮次停止后安全回收。

优点：用户可随时用新的权限或新的上下文重新发起处理，不被旧轮次阻塞，同时避免并行会话互相覆盖文件与暂存区。

代价：需要为每条会话准备独立现场，状态编排、事件归属、磁盘占用、结果复验和回收复杂度明显提高。

### 每会话独立隔离并自动完成本地合入

- 每次“AI 处理”都从当前合入记录冻结的目标基线、任务基线和合入方式创建新的隔离现场，再把新会话的执行目录绑定到该现场。
- AI 只修改并暂存自己的隔离现场，仍不得执行 commit、目标分支更新或 push。
- 轮次完成后，Zeus 读取该现场的真实 Git 未解决索引；无未解决项且两端基线仍有效时，由 Zeus 自动生成合入提交并安全同步本地目标分支。
- 成功、仍有未解决项、目标已变化、已有其他会话先完成合入和本地目标暂不可同步必须形成不同结果，并立即回写代码交付页。
- 隔离现场只是安全执行边界，不是用户需要管理的产品对象，也不能成为处理结果停留的终点。

优点：隔离机制真正覆盖并行场景，处理结果、会话权限和合入提交可以按会话追溯，代码交付页不再依赖旧冲突列表猜测状态。

代价：需要新增会话与隔离现场的一一对应关系；多份现场增加磁盘占用，失败和失效现场必须按可恢复边界回收。

### 代码交付页实时显示主合入结果

- 代码交付主流程只显示当前合入记录的真实状态，例如仍有冲突、AI 处理中、正在生成合入提交、已合入、等待本地同步或失败。
- 不向用户暴露“候选晋升”“过期候选”等内部编排概念，也不增加需要用户管理的候选列表。
- 隔离现场 Git 状态、AI 轮次状态或本地合入结果变化时，已打开的原生代码交付窗口实时刷新；不得要求用户关闭重开或继续展示数据库中的旧冲突文件列表。
- AI 轮次完成但仍有未解决项时，主流程继续显示真实冲突数量与失败说明；Zeus 已自动完成本地合入时，主流程直接显示已合入或本地待同步。

优点：用户一眼能看到代码交付是否真正推进，不需要理解内部隔离现场的生命周期。

代价：服务端必须把会话完成、Git 复验和合入结果可靠投影成单一主状态；诊断细节需要从对应会话和错误信息查看。

### 权限选项使用紧凑单选列表

- 两个权限选项继续上下排列并允许整行点击，保留名称和一行影响说明。
- 使用紧凑单选标记、轻量中性表面、细描边、字重和低对比强调色表达选中状态。
- 删除当前大尺寸空白单选框、整卡强蓝描边和大面积蓝色选中底色。
- 弹窗标题、说明、选项和动作区按 Zeus 表单弹窗密度收紧；底部按钮复用全局 `Button` 的 32px 表单动作尺寸。
- 选中状态必须同时具有可见标记和 `checked` 语义，不能只靠颜色。

优点：仍可完整解释两种权限，视觉更接近克制的 macOS 工具，不再像两张巨型设置卡。

代价：选中反馈比当前强蓝卡片更克制，必须确保浅色、深色、高对比和键盘焦点下仍清晰可辨。

### 当前弹窗完成完全访问确认

- 选择“完全访问”后不再打开第二层风险弹窗；当前权限弹窗的说明、选项和开始动作共同构成明确确认。
- 选择“自动”时，开始按钮使用普通主操作语义。
- 选择“完全访问”时，同一按钮切换为全局危险操作语义，并明确写出“以完全访问权限开始”。
- 取消、Escape 和遮罩关闭都不得创建会话或保存权限；只有点击当前选中模式对应的开始按钮才提交。

优点：风险差异可见，同时避免连续两层弹窗打断用户。

代价：当前弹窗必须完整承担风险说明、键盘焦点、危险状态和提交中防重复点击，不能依赖后续确认兜底。

### 权限按四层一致验收

每次分别选择“自动”和“完全访问”创建新冲突处理会话后，必须对账以下四层：

1. 权限弹窗提交的选中值。
2. 新会话输入区或权限控件展示的实际会话值。
3. SQLite `conversations.permission_mode` 及该会话下一轮配置中的持久值。
4. Provider 首轮实际采用的 sandbox 和审批策略：“自动”为隔离工作区可写与按需审批，“完全访问”为完全访问与不逐次审批。

任一层不一致都判定缺陷未修复；界面、静态代码、数据库或构建产物中的单层证据不能替代完整验收。

优点：可以证明用户选择真正作用于新会话和首轮执行，不再把显示值当成权限事实。

代价：完整验收依赖可用的真实模型、持久冲突现场、独立测试数据和 Provider 事件证据；环境不满足时必须明确报告运行验收缺口。

## 计划确认结果

关键产品决策、领域词汇、视觉方向和新增持久表计划已经用户逐项确认；以下计划已按确认范围执行。

## 实施计划

### 数据与恢复

1. 增量新增 AI 冲突处理运行表，保存运行身份、主合入记录、会话、首轮提交、独立隔离路径、冻结的目标与任务提交、状态、结果提交和错误；不修改或搬迁已有 `task_integrations` 记录。
2. 新增存储 Repository，按会话读取运行记录，并在本机服务重启后恢复仍活动的会话与隔离路径绑定。
3. 状态只表达内部恢复与收尾，不进入普通产品文案；历史旧会话没有运行记录时继续只读可见，不参与新入口复用。

优点：会话、权限、执行目录和收尾结果可以可靠对账，应用重启后不会靠标题猜测路径。

代价：增加一张表和一套生命周期；必须处理旧数据无记录、路径缺失和孤立 worktree 的降级。

### 独立隔离现场与新会话

1. 删除冲突接口“存在旧操作就直接返回旧会话”的分支。
2. 每次请求使用新的运行身份从主合入记录冻结的两端提交重建隔离 merge 或 squash 现场，并把当前界面草稿写入对应冲突文件。
3. 新建 Codex 或 Pi 会话时把 `cwd`、可写根和本次权限绑定到该独立路径；成功创建后持久关联运行记录。
4. 任一步失败时不留下伪会话成功状态；可恢复现场记录失败原因，并按安全边界回收未被活动会话占用的路径。

优点：满足任何时候点击都新建且允许并行，同时消除共享文件和 Git 索引竞争。

代价：每次点击都要重新准备合入现场，启动成本和磁盘占用高于复用单一 worktree。

### 自动提交与交付状态

1. 按会话处理轮次完成事件，只复验该会话绑定的独立现场。
2. 无未解决项且主合入仍匹配冻结基线时，由 Zeus 生成本地合入提交并同步目标分支；本地目标工作区不安全时保留结果并进入待同步。
3. 主合入已由另一会话完成或两端基线变化时，当前结果不再覆盖，并记录可读失败原因。
4. 成功、待同步和失败都更新主合入记录或运行记录，并广播任务代码交付变化事件。

优点：隔离区不再成为结果终点，代码交付页与真实 Git 结果闭环。

代价：并行完成存在竞争，需要以数据库状态和 Git SHA 双重校验保证只有一个结果生效。

### 原生交付窗口与权限弹窗

1. 原生交付窗口订阅任务代码交付变化事件并重新读取工作区与合入记录；不增加固定轮询。
2. 权限弹窗改为紧凑单选列表，修复全局输入样式污染，复用 `ModalPortal` 和全局 `Button`；自动使用主按钮，完全访问使用危险按钮。
3. 保留 Escape、遮罩取消、焦点约束、提交中防重复、浅色、深色、窄窗口、键盘和 reduced-motion。

优点：状态及时、视觉克制，且不新增第二套控件或风险确认。

代价：需要打通 Local Server 实时事件到第二 Renderer 的刷新路径。

### 验证

1. 不新增或恢复单元测试；执行定向格式检查、`git diff --check`、`pnpm lint`、`pnpm typecheck`、`pnpm build` 和 `pnpm package:mac`。
2. 只使用 bundle ID 为 `dev.hypha.zeus.test` 的 `Zeus Test.app` 与独立数据目录，建立真实隔离 Git 冲突和至少两次 AI 处理新会话。
3. 分别选择自动与完全访问，对账弹窗值、会话界面、SQLite 和 Provider 首轮权限。
4. 验证 AI 解决并暂存后 Zeus 自动生成本地合入提交，已打开的代码交付窗口无需关闭即可显示已合入或真实失败原因。
5. 验证并行新会话拥有不同会话 ID、Provider 身份和执行路径，且不能覆盖已生效结果。

## 暂不改动的边界

- 本任务开发过程中不自行执行仓库的 Git commit、push、merge、revert 或历史修改；产品运行链路在用户点击“AI 处理”后，可以按已确认流程由 Zeus 自动生成本地合入提交并同步本地目标分支。
- 不改变 AI 冲突处理会话的禁止提交和禁止推送边界。
- 不新增或恢复单元测试、组件测试、DOM/CSS 契约测试或 TDD 流程。
- 不生成或启动生产身份 `Zeus.app`；后续如获确认，只使用独立身份和独立数据目录的 `Zeus Test.app` 做真实运行验收。

## 实施结果

### 新会话与独立隔离现场

- 冲突处理接口不再返回旧冲突会话；每次请求生成新的运行身份、会话身份和首轮提交身份。
- 每条运行记录冻结目标提交和任务提交，并记录独立合入路径、状态、结果提交和错误。
- Codex 的执行目录、可写根和 Pi 的执行目录都绑定到本次独立现场；请求携带的权限直接传入本次新会话。
- 会话恢复优先按运行记录定位独立现场；历史旧会话仍保留原有只读兼容查找。
- 已完成或已取代的会话只保留历史记录，独立现场被回收后不会退回普通任务工作区继续写；失败且现场仍存在的会话才允许继续处理。

### 权限生效

- Codex 会话创建时写入 `conversations.permission_mode` 和下一轮设置；首轮继续由既有权限映射生成 sandbox 与审批策略。
- Pi 会话补齐下一轮设置持久化，当前权限和下一轮权限保持一致；自动模式继续对写操作发起审批，完全访问不逐次审批。
- 只读模式仍在冲突处理接口被拒绝，不扩大本入口权限范围。

### 自动合入与并发收尾

- AI 轮次完成后只复验该会话绑定的独立现场，再由 Zeus 生成合入提交并安全同步本地目标分支。
- 同一主合入的多条会话按主合入身份串行收尾，避免几乎同时结束时使用旧状态互相覆盖。
- 第一条有效结果推进主合入；后续结果标记为已取代并清理自己的独立现场，不会覆盖已完成结果。
- 成功、待本地同步和失败都会保存状态并广播代码交付变化事件；已打开的交付窗口收到事件后重新读取真实状态。

### 权限弹窗

- 弹窗改用全局 `ModalPortal`，尺寸与间距收紧。
- 两个权限选项改为紧凑单选列表，使用真实 `checked` 状态、可见圆点和键盘焦点，不再使用大空白控件与整卡强蓝描边。
- 自动模式使用主按钮；完全访问使用危险按钮。取消、遮罩和 Escape 不提交，处理中禁止重复提交。
