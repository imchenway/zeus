# ZEUS-0197 任务首发内容预览完整可见

## 当前阶段

- 用户已确认“单一滚动”和“创建异常完整收口”两项交互边界，代码实现与静态、构建、打包验证已完成。
- 本任务不执行 Git commit、push、merge、revert 等历史或远端写入。

## 用户反馈

“推送到新会话”弹窗中的“将发送的任务内容”无法完整、顺畅地查看。用户截图显示，首发内容预览位于弹窗正文末尾，只露出顶部，并出现独立滚动条。

后续真实操作还暴露出更严重的问题：点击“创建新会话”后，弹窗永久停在“正在创建”，关闭、取消和全部配置项同时被锁死。

## 代码事实

- 弹窗正文 `.task-model-push-body` 已使用 `overflow-y: auto`，承担整份表单的纵向滚动。
- 首发内容预览 `.task-push-layout` 又使用 `max-block-size: 420px` 与 `overflow: auto`，形成第二层滚动容器。
- 预览包含任务标题、有效内容字段、附件、所选会话路径和本次补充信息，来自同一份任务首发布局快照；当前问题属于预览阅读交互，不是 Provider 输入丢失。
- 生产环境 ZEUS-0215 的能力读取成功，但数据库中没有对应工作区、会话或幂等请求记录，说明卡死发生在 Renderer 创建准备阶段，真实创建请求尚未发出。
- `continueTaskModelPush` 原先先把状态设为 `submitting`，再构造首发预览和待处理工作面；这段同步准备没有异常收口，一旦失败便会永久保留锁定态。
- 真实创建请求原先位于界面导航、会话选择、历史地址替换和滚动之后；任何前置界面异常都会让任务创建请求根本无法发出。

## 领域口径

- 本任务统一称该区域为“任务首发内容预览”。
- “本次补充信息”只是任务首发内容预览中的一个可选组成部分，不能代指整个预览。

## 已确认决策

建议取消任务首发内容预览自身的纵向滚动，让预览按真实内容完整展开，只保留弹窗正文这一条纵向滚动；底部确认区继续固定可见。

优点：阅读顺序连续，不需要在两层滚动区之间切换，任务内容能逐段完整核对。

代价：长任务会拉长弹窗正文的总滚动距离，但不会撑出视口，也不会遮挡底部操作。

超长标题、正文、附件名称和会话路径在预览可用宽度内软换行，不保留预览内部横向滚动条，也不通过省略号隐藏首发正文。

创建流程采用“准备成功后再锁定”的边界：首发请求、预览和待处理工作面全部构造成功后，才进入“正在创建”并切换到会话工作面；准备失败则保留全部表单配置、显示脱敏后的真实错误，并立即恢复关闭、取消和重试。

本地待处理态建立后立即发出真实创建请求，再执行界面导航；任务创建不再依赖后续界面操作成功。

优点：当前异常不会再形成无出口的永久锁死，其他创建前异常也遵守同一恢复契约。

代价：创建态会比点击动作晚一个同步准备阶段，但该阶段只做本地数据构造，不引入网络等待。

## 实施范围

- 移除任务首发内容预览的最大高度和内部滚动。
- 为超长任务标题和正文补齐任意位置软换行。
- 将创建锁定态延后到本地准备完成之后，并统一收口创建前同步异常。
- 不修改任务首发布局快照、Provider 输入、字段顺序、附件协议或底部固定操作区。
