# ZEUS-0199 更新完成后启动错误版本

## 用户现象

Zeus 每次完成更新并立即重启后，可能启动旧版本。截图中的“关于 Zeus”显示实际进入了 `0.1.20`，与本次刚完成的更新目标不一致。

## 用户确认口径

点击“立即重启”后，必须启动本次刚刚更新成功的 Zeus。不得让 macOS 按 bundle ID 从多份同身份应用中自行选择，也不得回退启动其他旧版本。

## 现场与代码证据

- 当前 `/Applications/Zeus.app`、Homebrew 安装登记和正在运行的正式进程均为 `0.2.38`，说明当前现场已恢复到一致状态。
- `homebrewUpdateService.ts` 在安装后只复验 Homebrew 的版本登记和 App 目标路径，没有读取目标 App 自身的版本与 bundle ID。
- `UpdateProgressPanel.swift` 等待旧主进程退出后执行 `open -b dev.hypha.zeus`。`-b` 只按 bundle ID 解析应用，不能保证启动本次刚安装的精确 App 路径。
- 历史任务 `TASK_20260803_007_Zeus正式版版本漂移诊断.md` 已记录：macOS 曾把同一生产 bundle ID 解析到 worktree 旧包；旧进程取得单实例锁后，再打开正式应用也只会唤起旧窗口。

## 根因

安装目标和重启目标没有使用同一份身份事实。Homebrew 已知本次实际管理的 App 路径，但重启时丢弃了这个路径，只把 bundle ID 交给 macOS 重新选择，因此可能启动同身份的旧应用。

## 修复设计

1. Homebrew 安装完成后读取目标 App 的 `Info.plist`，复验精确路径、bundle ID、短版本号和构建版本均与本次更新一致。
2. 安装服务把已经复验的 App 路径和目标版本返回给更新控制器。
3. 原生更新辅助程序等待旧主进程退出后，再次复验该精确 App 路径的 bundle ID 与目标版本，并通过精确 App URL 启动。
4. 删除按 bundle ID 启动的路径，禁止 macOS 在多份 Zeus 中自行选择。

优点：安装与重启共用同一个更新目标，直接消除启动旧版本的歧义。

代价：目标 App 的身份或版本不一致时会停止重启并报告错误，不再用其他同身份应用兜底。
