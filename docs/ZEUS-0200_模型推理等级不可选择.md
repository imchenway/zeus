# ZEUS-0200：模型推理等级不可选择

## 当前阶段

已把模型能力配置从“用户手工声明”调整为“Zeus 自动识别、用户只读查看”，并完成格式、静态门禁、构建与独立测试包验证。真实 Electron GUI 与第三方 API 尚未验收。

## 用户反馈

在“自定义兼容供应商”中配置第三方 Codex 模型时，推理等级只能看到 `off`。继续要求用户选择思考开关、推理等级字段格式、图片输入和工具调用能力，会把供应商协议差异转嫁给普通用户。

## 原因

- `/models` 通常只返回模型 ID，不能单独证明该渠道接受哪些推理参数。
- 旧界面把新模型初始化为“未验证 + `off`”，又要求用户手工把能力改为“支持”。
- 旧版“推理等级”是逐字过滤的受控文本框，输入尚未形成完整枚举值时会立刻被重置，因此正常键入不可用。
- 不同接口的思考参数结构并不统一，不能让用户自己选择 `reasoning_effort`、`reasoning.effort`、`thinking.type` 或 `enable_thinking`。

## 产品边界

### 用户负责

- 选择连接模板，或填写自定义 OpenAI 兼容地址。
- 填写连接名称、API Key 和模型 ID。
- 决定连接与模型是否启用。

### Zeus 负责

- 根据连接模板决定协议字段格式。
- 根据内置模型目录识别上下文窗口、最大输出、推理等级与图片输入。
- 把 Zeus 的统一推理等级映射为当前协议实际发送的值。
- 用真实运行结果覆盖目录结论，并保留证据来源。
- 无可靠证据时显示“待检测”，不要求用户猜测。

### 证据含义

- **模型目录**：证明 Zeus 当前内置目录对该模型的已知描述，不代表第三方转发渠道已实测通过。
- **渠道模板**：证明 Zeus 知道该供应商的参数结构，不代表具体模型一定支持全部能力。
- **运行探针**：真实请求成功或失败形成的渠道级证据，优先级最高。

## 实现方案

### 自动能力档案

Zeus 直接读取当前 Pi 运行内核随包提供的模型目录，不再为截图中的三个模型套一组手工枚举。每个模型独立读取自己的 `thinkingLevelMap`，因此不支持的空档不会出现在会话选择器中。

模型目录按接入渠道隔离：DeepSeek、百炼、Kimi、Z.AI 分别使用对应供应商目录，自定义兼容渠道使用通用 OpenCode 目录。即使模型 ID 相同，也不会跨渠道复用参数格式或能力结果。

目录中已知模型会自动带出：

- 模型显示名称、上下文窗口和最大输出。
- 可用推理等级及默认等级。
- 是否支持图片输入。

目录没有提供工具调用结论时保持“待检测”，不会让用户手工选择，也不会冒充已验证。

优点：能力来源统一，可随运行内核目录更新；用户无需理解供应商字段名；模型之间的等级差异不会被抹平。

缺点：第三方渠道可能修改同名模型的实际能力，因此目录结论仍需要运行结果校准；目录未知的新模型会暂时显示“待检测”。

### 只读设置界面

模型卡片只保留启用开关和删除入口。显示名称、速度标签、思考格式、推理等级、默认等级、工具调用和图片输入的手工控件全部移除，改为三个只读能力摘要：推理、工具调用、图片输入。

优点：用户只处理连接本身，设置流程更短，避免错误声明污染运行配置。

缺点：目录识别错误时不能在普通设置页临时强行覆盖，需要由真实探针或后续高级诊断入口纠正。

### 旧配置迁移

旧界面产生的 `manual` 能力声明不再参与运行。Zeus 会在读取和保存时将其降级为“待检测”，再由模型目录、连接模板或真实探针重新生成能力档案。

## 当前模型结果

截图中的 `gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna` 均能从当前 Pi 模型目录命中各自档案。当前 Pi 目录为它们暴露 `low / medium / high / xhigh / max`，不暴露 `off / minimal`；图片输入由模型目录标记为支持，工具调用仍等待当前第三方渠道的真实运行证据。

默认推理等级由 Zeus 自动选择：`gpt-5.6-sol` 使用 `low`，其余已知模型优先使用 `medium`；没有 `medium` 时依次选择 `high`、`low`、`off`，最后才回退到该模型的第一个可用档位。
