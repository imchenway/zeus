# ZEUS-0201 第三方模型会话错误与身份修复

## 当前状态

已完成代码实现与静态、构建、隔离打包验证。按已确认范围，没有扫描或改写历史会话。

## 已确认的产品边界

- 模型供应源或运行内核返回错误后，原执行轮次必须进入失败终态，并在原会话时间线显示经过脱敏的真实原因。
- Zeus 不根据本地图片能力档案预先拒绝图片；是否接受图片由实际接口决定，接口返回的错误照常显示。
- 模型连接 ID 与模型 ID 共同构成模型选择身份。连接展示名、裸模型名和列表顺序都不能替代该身份。
- 本次只修复后续新轮次，不扫描或改写历史会话。

## 真实问题证据

2026-08-12 检查 ZEUS-0094 的两条 Pi 会话后确认：

- 第三方 `gpt-5.6-sol` 返回 HTTP 400，原因是接口接受 `none`，但 Zeus 通过 Pi 发送了 `off`。Pi JSONL 已保存 `stopReason=error` 与完整错误正文，Zeus 数据库却把轮次和提交都记成完成。
- DeepSeek `deepseek-v4-flash` 收到图片后返回 HTTP 400，原因是该接口只接受文本。Pi JSONL 同样保存了错误，Zeus 会话只投影用户消息，未显示失败原因。
- 会话输入区把已经持久化的“连接 ID + 模型 ID”降成裸模型名；当 Codex 与第三方连接存在同名模型时，界面按列表顺序误显示 Codex。

根因不是模型没有返回，而是 Zeus 未把 Pi 的空正文错误消息转换成公共失败终态，并且客户端在恢复输入区设置时丢失了模型连接身份。

## 实现方案

### 失败终态

Pi 适配层把 assistant `message_end(stopReason=error)` 规范化为 `runtime_error`，保留错误代码、原始原因和运行状态。现有会话失败卡继续负责脱敏、分类和恢复建议。

优点：所有 Pi 模型供应源共用同一失败闭环，HTTP 400、认证、限流和网络错误不会再伪装成成功。缺点：已经被错误记成完成的历史轮次不会自动修复，这是本次明确接受的范围限制。

### 推理关闭值兼容

OpenAI 兼容协议中的关闭档位从界面语义 `off` 映射为接口值 `none`；其他推理档位保持原值，未支持档位继续省略。

优点：修复实际第三方接口拒绝 `off` 的问题。缺点：极少数非标准接口若只接受自定义关闭值，仍需在模型连接能力配置中继续扩展协议映射。

### 模型选择身份

客户端与服务端都优先按复合模型 ID 精确匹配；裸模型名只用于兼容“全目录唯一命中”的旧数据，出现多个同名模型时不再猜测。任务首发工作面从创建起就携带正确的 Agent、连接和模型身份。

优点：同名 Codex、官方直连、第三方中转以及同一渠道下的不同账号不会互相串选。缺点：存在撞名且只保存裸模型名的旧偏好不会再自动命中，需要用户重新选择一次明确连接。
