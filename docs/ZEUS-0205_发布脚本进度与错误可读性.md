# ZEUS-0205 发布脚本进度与错误可读性

## 当前阶段

- 阶段：实现与静态门禁完成
- 状态：代码、文档、构建和测试身份打包已完成；因当前三屏环境无法保证测试窗口首次创建于非主外接屏，未启动 GUI
- 用户期望：百分比进度在同一行更新；进度和报错必须能让用户看懂

## 已核对事实

1. `packages/terminal-core/src/index.ts` 的 `normalizeTerminalChunk` 将所有回车符 `\r` 改为换行符 `\n`。Git 等命令使用回车符覆盖当前进度行，因此当前公共 Runtime 日志链路会把每次百分比更新拆成新行。
2. `packages/ai-runtime/src/index.ts` 对每个 stdout/stderr chunk 独立做文本关键词判断。`done` 或 `completed` 会追加“检测到完成输出”，`failed` 或 `error` 会追加“检测到错误或失败输出”。这些提示只是片段关键词命中，不是命令或发布阶段的权威结果，所以会重复、抢占注意力，甚至与最终退出码冲突。
3. `scripts/release-all.mjs` 的通用捕获函数默认把 Git/GitHub 只读命令限制为 30 秒。命令超时时直接抛出 `spawnSync` 的原始错误，因此用户只看到 `spawnSync git ETIMEDOUT`，看不到失败阶段、实际命令、超时时长、发布是否已产生写入，以及是否可以安全重试。
4. 用户提供的日志中，远程 tag 已被 fetch 到本地，但这不能单独证明后续版本写入、提交、push、GitHub Release 或 Homebrew Tap 已经发生。

## 已确认决策

### Runtime 实时进度行使用公共终端语义

- 决策：修复所有 Generic shell Runtime，不只在发布脚本中特判 Git 输出。
- 产品语义：命令通过回车覆盖的百分比属于同一条“Runtime 实时进度行”，不展示为多条独立日志。
- 明确边界：只处理原始命令已经输出的百分比覆盖行；不新增整体发布百分比，不按阶段或历史耗时估算百分比。
- 优点：发布、Git、下载和其他终端命令共享一致行为，不需要为每条脚本重复打补丁。
- 代价：公共终端采集、实时展示、历史回放和导出必须共用同一语义，需要防止展示正常但审计日志仍重复。

### 发布输出分为阶段摘要与原始详情

- 决策：主视图先展示发布阶段摘要，原始工具输出作为可展开、可导出的发布原始详情保留。
- 发布阶段摘要：说明正在做什么、当前可验证进度、成功或失败的影响范围，以及用户下一步。
- 发布原始详情：保留 Git、GitHub CLI、Node 和校验工具的真实输出，未知错误仍可排查。
- 优点：默认信息层级清楚，同时不丢失排障证据。
- 代价：发布脚本必须显式暴露阶段边界和错误上下文，Runtime 界面必须支持两层信息，不能只改一句文案。

### 网络超时按操作安全性有限重试

- 决策：只读网络操作遇到临时超时时自动有界重试；远程写入只有在可以复验幂等结果时才续跑，否则停止并说明已完成范围。
- 只读操作：每次重试都必须展示当前阶段、本次超时上限、当前次数和总次数。
- 写入操作：先查标签、分支、Release、资产和 Tap 等外部事实，只有可以证明没有重复副作用时才继续。
- 优点：可自动吸收短暂网络抖动，又不会无条件重复远程写入。
- 代价：每个远程写入阶段都需要独立的外部事实复验和恢复规则，实现复杂度高于简单重试。

### 不再展示片段关键词猜测状态

- 决策：移除用户可见的 `AI Runtime 输出状态：…检测到…输出`，不做去重后保留。
- 权威结果：命令层只以真实进程退出状态为准；发布层只以发布编排明确产生的阶段摘要为准。
- 原始证据：`done`、`failed`、`error` 等工具输出继续保留在发布原始详情中，但不另外触发用户可见结论。
- 优点：消除重复、误判和“先显示完成，最后又失败”的冲突。
- 代价：等待输入等交互必须依靠明确协议或真实运行时状态，不能继续依赖文本扫描。

## 当前不做

- 不执行真实发布、提交、push、merge 或其他远程写入。
- 不以关键词命中冒充发布成功或失败结论。
- 不新增或估算整体发布百分比。

## 实现结果

### 公共 Runtime 终端语义

- `packages/terminal-core/src/index.ts` 保留独立回车符，并新增终端可见文本投影；同一逻辑行内的连续回车更新只保留最终内容。
- `packages/ai-runtime/src/index.ts` 不再为 stdout/stderr 片段追加 `AI Runtime 输出状态`。原始输出继续保存，命令结果只由真实进程状态决定。
- Runtime 抽屉、xterm 视图与命令运行详情统一使用连续文本，不再把每个 chunk 强制渲染成一行。
- Renderer 直接依赖轻量 `@zeus/terminal-core`，避免为了文本投影把整套 Node Runtime 打入前端包。

### 发布阶段与错误说明

- `scripts/release-all.mjs` 在本地检查、读取稳定版、同步远端、生成说明、准备提交、本地门禁、安全推送和公开发布前输出明确阶段。
- 顶层失败输出固定包含“阶段、原因、影响、下一步、技术详情”，并根据恢复状态说明本地提交、main、GitHub Release 与 Homebrew Tap 的已知影响范围。
- 子阶段输出改为直接传递原始 stdout/stderr，保留回车覆盖进度；内部产物标记仍转换为用户可读文案。
- 命令中心从原始日志中提取发布失败摘要；完整日志继续作为原始详情保留。

### 网络恢复边界

- Git fetch、Git 远程引用、GitHub 发布事实与 GitHub CLI 登录检查使用 60 秒单次上限、最多 3 次的只读重试；重试文案显示阶段、次数和单次上限。
- `main` push 不做无条件重试。返回异常后先读取远程 main：已是目标提交才安全续跑，否则停止并明确说明不会盲目重复推送。
- 后续重新运行 `pnpm release` 继续依赖既有恢复状态与外部事实复验，不把超时当作写入失败或成功的证明。
