# ZEUS-0208 思考过程轮次耗时入口位置优化

## 任务目标

调整会话中“已处理……”轮次耗时入口的位置，使运行过程和最终回复形成自然的自上而下阅读顺序。

## 现状与根因

- `SessionTurnDuration` 同时承载轮次耗时和过程内容的展开、收起。
- 入口是原生 `details` 的 `summary`，当前始终排在过程内容之前，所以模型仍在工作时，“已处理……”也显示在思考摘要、命令和工具活动上方。
- 最终回复独立渲染在 `SessionTurnDuration` 之后；完成态入口已经自然位于回复正文上方。

## 已确认产品规则

1. 模型思考和执行过程中，思考摘要、命令和工具活动在上，“已处理……”位于本轮过程内容最底部。
2. 模型回复完成后，过程默认收起，“已处理……”位于模型回复正文上方。
3. 用户展开历史过程时，过程从“已处理……”下方展开，模型回复正文自然向下顺延。
4. 普通会话页和任务会话抽屉共用同一规则。

优点：运行中耗时成为过程收尾，完成后入口紧邻最终结果，展开方向与用户操作预期一致。

代价：运行态与完成态使用不同的视觉顺序，需要明确依赖轮次活动状态，不能只使用一套固定排列。

## 实现方案

- 保留 `details / summary` 的原生展开语义、键盘操作和现有状态管理。
- 只在活动轮次中使用网格顺序把过程正文排在入口上方，并把间距移到过程正文底部。
- 完成轮次继续使用入口在前、展开内容在后的默认顺序，最终回复仍由既有会话投影自然排在整个过程区之后。
- 不修改 Provider、Reducer、耗时计算、消息投影、滚动跟随或持久化协议。
