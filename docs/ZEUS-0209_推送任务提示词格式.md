# ZEUS-0209 推送任务提示词格式

## 当前阶段

- 用户已确认视觉与提示词格式边界，实现、静态检查、构建和独立测试包已经完成。
- 内置浏览器没有成功返回本机组件核对页，完整桌面界面与真实 Provider 仍未动态验收。
- 本任务不执行 Git commit、push、merge、revert 或其他历史与远端写入。

## 用户反馈

任务首发中的“现状 / 预期”等字段名称与任务标题在粗细和大小上接近，无法快速看出字段隶属于哪个任务。用户要求通过缩进或格式调整拉开层级，并补充确认字段名称末尾可以显示全角冒号。

## 已确认事实

1. 推送预览与已发送消息分别由 `TaskPushLayoutPreview` 和 `TaskPushMessageContent` 渲染同一份任务首发布局快照。
2. 两处字段名称都被显式设置为 `15px / 650 / 22px`，任务标题没有独立排版规则，因此标题与字段名称缺少稳定层级。
3. Provider 纯文本构造器已经使用“字段名称：”格式；缺失全角冒号的是结构化预览和会话消息，不是模型收到的纯文本。
4. 既有 `ZEUS-0190` 为解决 `11px` 过小问题把字段名称提升到 `15px`，本任务不能退回难以阅读的元数据层级。

## 已确认决策

### 字段名称降级并缩进

- 任务标题固定为 `17px / 650 / 24px` 的主标题层级。
- 字段名称调整为 `13px / 550 / 19px` 的次级标签层级，使用次要文字颜色。
- 字段名称、附件和正文作为一个整体，相对任务标题缩进 `12px`。

优点：字号、字重、颜色和位置共同表达归属，长任务中也能快速扫描任务区块。

代价：字段内容少 `12px` 可用宽度，窄窗口和长路径必须核对软换行与溢出。

### 字段名称显示全角冒号

- 内容字段、当前任务历史会话信息、父任务或关联任务会话文件路径、补充信息的可见名称都以全角冒号结尾。
- 推送预览与已发送消息使用相同格式。
- Provider 纯文本已经带全角冒号，保持现有文本、字段顺序和附件位置，不重复添加冒号。

优点：字段名称与后续内容的关系更明确，也与模型实际收到的纯文本格式一致。

代价：字段名称比原来多一个字符，极窄宽度下会略微提前换行。

## 实施范围

1. 为推送预览和会话消息中的任务标题增加显式主标题样式。
2. 统一两处字段段落的标签层级、缩进和间距。
3. 为两处结构化渲染的字段名称补齐全角冒号。
4. 不修改任务首发布局数据、Provider 字段顺序、附件位置、上下文选择或任务内容。

## 验证计划

- 对改动文件执行 Prettier 检查与 `git diff --check`。
- 执行 `pnpm lint`、`pnpm typecheck` 和 `pnpm build`。
- 条件允许时生成独立身份 `Zeus Test.app`，核对浅色、深色、窄窗口下的推送预览与已发送消息。
- 静态检查、构建和打包结果分别记录，不冒充真实 Provider 或完整桌面验收。

## 实施结果

1. 推送预览和已发送消息中的任务标题都使用显式 `17px / 650 / 24px` 主标题样式。
2. 两处字段段落统一缩进 `12px`，字段名称改为次要文字色与 `13px / 550 / 19px`，字段内部间距收紧为 `4px`。
3. 内容字段、会话信息和补充信息的结构化可见名称全部补齐全角冒号。
4. 已发送消息中的当前任务会话段恢复领域既定名称“当前任务历史会话信息：”；父任务和关联任务仍显示“会话文件路径：”。
5. Provider 纯文本构造器没有重复改写；一次性共享布局探针确认其仍按“任务标题 → 现状：→ 正文 → 预期：→ 正文”输出。
