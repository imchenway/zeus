# ZEUS-0210 引导消息右对齐修复

## 任务现象

用户在模型回复期间发送“引导”后，引导消息虽然仍使用用户气泡样式，却显示在会话正文左侧，与普通用户消息的右对齐规则不一致。

## 需求确认与领域口径

- 引导消息统一称为“用户中途引导”：它是用户补充给当前执行轮次的用户消息，不是过程说明、工具活动或下一轮队列消息。
- 活动轮次继续按真实时间顺序穿插展示过程内容与用户中途引导，不为修正视觉而改变消息顺序。
- 用户中途引导无论位于会话外层还是当前轮次过程区，都必须保持用户消息的右对齐视觉语义。

优点：用户可以通过位置直接区分自己的输入与模型过程，且现有引导生命周期、时间顺序和轮次折叠规则保持不变。

代价：当前轮次过程区是独立网格容器，需要显式维护其中用户消息的水平对齐规则。

## 根因

普通用户消息是会话正文纵向弹性容器的直接子项，使用 `align-self: flex-end` 靠右。活动轮次会把除首条消息外的实时条目放入 `.session-turn-duration-body`，该容器使用网格布局以保持过程时间线。

用户中途引导进入这个网格后，`align-self` 只作用于纵向轴；过程区的通用子项规则又清除了水平外边距，导致气泡按网格默认起点落在左侧。消息角色和数据投影没有发生错误。

## 修复方案

- 保留用户中途引导在活动轮次过程区中的真实时间位置。
- 对过程区的直接用户消息设置 `justify-self: end`，在网格水平轴恢复右对齐。
- 清除嵌套过程区内重复的会话外层水平边距，避免右侧出现双重留白。
- 不修改消息状态、Provider 身份关联、队列、轮次投影或完成后的折叠收口。

### 真实运行边界

本轮没有启动测试包。目标是 Electron 原生会话工作面，普通浏览器无法提供真实本机桥接和 Provider 引导状态；用静态页面或 Vite 页面截图会形成伪验收。当前工具也不能在应用首次创建窗口前可靠保证窗口位于非主屏外接显示器，因此按桌面验收边界停止 GUI 操作。

尚缺一条真实活动轮次中的引导消息往返证据：发送引导后，气泡应在“已处理”展开区域内保持右对齐；轮次完成收口后仍保持用户消息身份和时间顺序。静态检查、构建、打包和签名均不能替代这项真实 GUI 验收。
