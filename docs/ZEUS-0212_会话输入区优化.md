# ZEUS-0212 会话输入区优化

## 当前阶段

第二轮交互收口已完成并通过独立 `Zeus Test.app` 真机验收：权限、计划、速度与上下文图标按要求去除方形底色，速度改为标准 / Fast 直接切换，并统一项目 + 会话类型记忆。

## 问题判断

现状的主要问题不是单个颜色、圆角或阴影，而是信息层级失控：模型、推理强度、服务档位、权限、计划、发送方式、运行操作和实际档位说明全部挤在输入区主层级，导致输入本身不再突出。

## 已确认的产品语义

- Enter 默认把后续消息加入队列。
- 排队消息以紧凑列表出现在输入框上方；“引导”属于具体排队消息，不在输入框常驻。
- 速度、权限、计划改成有状态图标；悬停或键盘聚焦时显示完整文案。
- 权限模式和计划模式放在工具栏左侧；上下文占用、速度模式、完整模型名称和推理强度放在右侧。
- 模型触发器和模型菜单不得以省略号截断模型名称；窄窗口通过自然换行保留完整信息。
- 输入区底部不再展示“请求 Fast / 实际标准”等速度说明；速度的下一轮选择只由闪电状态表达。
- 速度图标左侧固定展示上下文占用圆环；真实口径为运行内核最近一次报告的当前输入上下文除以模型上下文窗口，不使用累计 Token 用量代替。
- 尚无真实上下文数据时展示灰色空环；75% 起使用警示色，90% 起使用危险色，超过 100% 时圆环封顶但明细保留真实比例。
- 鼠标悬停或键盘聚焦圆环时展示占用百分比、已用/容量和剩余量；完整 Token 账本仍保留在会话运行摘要栏。
- 输入区随内容自然收紧，多行输入和附件继续按内容增长，不固定追求某个总高度。
- 外观采用细描边和轻阴影，避免当前双重厚重阴影。

## 方案优缺点

优点：输入主次更清楚；运行时操作更少；发送方式与具体消息绑定；窄窗口更容易保持稳定；异常信息仍能被发现。

缺点：图标方案要求颜色、图形和提示文案共同工作；首次使用者需要一次悬停或聚焦才能看到完整名称；不支持 Fast 的模型只能使用标准速度。

## 实施记录

- 活动会话输入区移除常驻“排队 / 立即引导”，Enter 固定按队列提交；已有队列消息继续提供真实“引导”操作。
- 权限模式以只读、盾牌自动、红色填充盾牌完全访问和完整辅助名称呈现；完全访问无方形底，确认流程保持不变。
- 计划模式改为带开启/关闭状态的灯泡图标；开启时呈现金黄色与一次灵光闪烁，减少动态效果偏好下关闭动画。
- 速度闪电点击后直接在标准 / Fast 间切换，不再打开菜单；Fast 为金色填充闪电且无方形底，不支持 Fast 的模型禁用闪电并通过提示说明原因。
- 新建会话与已有会话共用左右分组规则，避免两种入口产生不同心智模型。
- 移除输入区底部全部速度档位状态文案，避免把下一轮选择与当前轮运行状态的时间差误读为 Fast 未生效。
- 新会话、已有会话、模型配置与任务推送都只提供标准 / Fast；旧“跟随 Codex”记忆读取时迁移为标准，新选择按项目和任务开发、冲突处理、代码审查、项目普通会话类型分别记忆。
- 输入区降低固定最小高度并减轻阴影，多行输入与附件仍按内容自然增长。
- 新增上下文占用圆环组件：活动会话读取运行内核真实 `last.inputTokens / modelContextWindow`，新建会话展示稳定的灰色空环；圆环位于速度图标左侧且无方形底。
- 圆环在 75% 与 90% 两个阈值切换警示和危险状态；悬停、键盘聚焦与读屏均能取得占用明细或无数据说明。

### Fast 语义核对

Fast 不是伪造状态。Zeus 从 Codex `model/list` 的真实模型能力中读取服务档位，只在模型明确报告 `fast` 或 `priority` 时允许点亮，并将相应 `serviceTier` 传给 `thread/start` / `turn/start`。标准速度会明确传入空档位，不再提供“跟随 Codex”。官方说明也确认 Fast 是受支持模型上的真实加速能力，会提高处理速度并增加用量：<https://learn.chatgpt.com/docs/agent-configuration/speed>。

旧“请求 Fast，实际：标准”来自把下一轮选择和当前 / 上一轮运行状态并排比较的时间差，不足以证明 Fast 失败。本轮移除该常驻状态行，并保留 Provider 参数的真实传递。

待继续的动态覆盖：

- 隔离数据目录中的 Zeus 专属 Codex 未登录，最小首条消息被产品明确拒绝并保留草稿。用户授权后，已通过真实任务推送流程打开“登录并继续”，Zeus Test 进入“官方登录页已打开 / 等待登录”状态。
- 自动化切换到官方认证页时触发平台安全边界，当前会话不得继续操作该 URL。因此活动轮次默认排队、队列项“引导”和停止按钮仍缺少本轮真机动态证据；需要用户在已打开的官方页面完成认证后再继续同一隔离实例。
- 同一原因也使真实上下文占用数值、75% 警示态和 90% 危险态缺少本轮真机数据证据；当前只确认了真实无数据状态。没有通过修改数据库或伪造 Provider 事件制造占用值。
- 这项缺口没有使用伪造会话、浏览器页面或静态样稿替代；代码继续复用既有真实队列消息与引导能力。
