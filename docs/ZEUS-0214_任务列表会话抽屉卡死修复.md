# ZEUS-0214 任务列表会话抽屉卡死修复

## 当前阶段

已完成根因确认、修复实现、静态门禁、构建、独立测试包校验和隔离真实应用启动检查。目标抽屉场景仍需一个已登录的 Zeus 专属 Codex 完成真实任务首发；本次隔离身份未登录，因此没有擅自扩大账号访问，也没有用生产身份或模拟数据替代该项验收。

## 用户反馈

从任务列表点击有真实来源会话的运行状态后，右侧“任务会话”抽屉长期停留在“正在打开会话…”，无法显示对应会话。

## 已确认产品边界

- 运行状态入口继续打开当前任务页上层的完整交互会话抽屉，不改回会话页跳转。
- 抽屉必须打开运行状态所依据的同一条真实会话，保留消息、输入、询问、审批和停止能力。
- 保留任务首发从创建操作到真实会话的无闪烁原位接管，不能为了修抽屉删除稳定导航身份。
- 打开失败统一进入应用级错误弹窗；抽屉只保留不含技术原文的不可用状态和重试入口，不允许无限加载。

优点：任务列表现场和任务首发无闪烁接管同时保留，失败也有明确恢复路径。

代价：抽屉必须同时维护稳定导航身份与真实会话身份，不能继续把两者都当作普通 `conversationId` 使用。

## 根因

1. 任务首发创建后，当前界面中的投影会话同时拥有稳定导航身份和真实会话身份；这是无闪烁接管所需的既有契约。
2. 任务表使用投影会话生成运行状态和点击目标，但抽屉打开函数重新从原始会话快照取对象。原始对象没有稳定导航身份，因此选择状态被写成真实会话 ID。
3. 当前选中会话解析使用投影会话，并在对象存在稳定导航身份时只匹配该身份，不再接受真实会话 ID。
4. 结果是抽屉目标已经存在，但当前选中会话解析为 `null`。抽屉渲染把该状态无条件解释为“正在打开会话…”，且没有超时、失败或重试出口，因此永久卡死。
5. 最小状态复现中，真实会话 ID 被写入选择状态、投影会话保留 `task-push:*` 导航身份后，当前解析结果为 `null`，抽屉就绪条件为 `false`。

这不是服务端请求未返回或会话内容加载过慢。主要受影响的是当前应用进程内刚推送、并已由真实会话接管但仍保留稳定导航身份的任务会话；没有导航别名的普通历史会话通常不命中。

## 修复设计

1. 抽屉从任务表使用的同一份投影会话中解析目标，不再退回原始快照重新解释身份。
2. 抽屉目标显式保存稳定导航身份与真实会话身份；就绪判断只使用稳定导航身份，服务端读写继续使用真实会话身份。
3. 正常会话没有单独导航身份时，以真实会话身份作为稳定界面身份，保持现有行为。
4. 若本地身份在一次界面提交后仍无法收敛，停止 loading，显示中性不可用状态和重试入口，同时把脱敏错误交给全应用错误弹窗。
5. 不新增或恢复单元测试、组件测试、DOM/CSS 契约测试和 TDD 流程。

## 实现结果

- 任务表点击入口改为从 `projectedTaskConversationChoices` 解析目标，确保与运行状态使用同一份会话投影。
- 抽屉目标分开保存任务身份、真实会话身份和稳定导航身份；抽屉就绪条件按稳定导航身份收敛，服务端交互仍使用真实会话身份。
- 打开目标缺失或一次界面提交后仍无法收敛时，抽屉进入“暂时无法打开这条会话”状态，并提供“重新打开”入口；技术错误继续交给现有应用级错误弹窗。
- 没有新增或恢复单元测试、组件测试、DOM/CSS 契约测试和测试脚本。
