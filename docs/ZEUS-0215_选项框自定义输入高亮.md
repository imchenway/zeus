# ZEUS-0215 会话交互细节优化

## 任务目标

- 已回答的普通用户询问中，自定义回答结果应与预设答案使用同一选中高亮，让用户一眼确认实际提交的答案。
- 会话标题旁的任务状态应与任务列表、任务详情一样可下拉修改，并复用同一业务逻辑。

## 已确认口径

- 自定义回答结果是当前问题的真实选中项，不是预设选项下方的普通附注。
- 整个自定义回答使用与预设答案一致的绿色轻背景、绿色描边、勾选图标和“已选择”文字。
- 保留“用户选择”标识，用于区分自定义回答与 Provider 提供的预设答案。
- 不改变 `request_user_input` 提交协议、回答内容、附件交付或敏感答案脱敏语义。

## 方案取舍

优点：

- 预设答案与自定义回答使用同一选中语义，扫读更直接。
- 同时使用颜色、勾选图标和文字，不依赖单一颜色表达状态。
- 复用已有选中答案结构与样式，不新增第二套高亮规则。

代价：

- 自定义回答从紧凑纯文本变为完整选中行，会增加少量纵向高度。

- 已移除原先把自定义回答展示为普通附注的结构和死样式。

## 阶段二：会话标题任务状态下拉

### 已确认口径

- 任务列表、任务详情和会话标题旁的任务状态是同一项业务能力，必须复用同一项目配置、事实源与修改逻辑。
- 会话标题下拉可选择项目配置中的全部任务状态，包括完成和取消。
- 状态修改继续执行统一的保存、冲突处理、忙碌保护和终态工作区清理确认，不在会话标题入口增加旁路。
- 单独修改状态不自动恢复、归档或停止会话；恢复指定归档会话仍使用既有独立动作。

### 方案取舍

优点：

- 三个状态入口语义一致，项目自定义名称、颜色、顺序与终态角色无需重复维护。
- 复用现有下拉的键盘交互、焦点反馈和浮层定位，避免标题栏形成第二套控件。

代价：

- 标题栏新增可聚焦操作控件，窄窗口中超长任务标题会更早省略。

### 实现结果

- 会话任务投影携带当前项目的完整状态选项，标题栏把只读状态标签升级为紧凑下拉。
- 新入口直接调用列表和详情共用的 `updateTaskManagementStatus`，没有新增状态写入协议。
- 保存期间三个入口共用忙碌态，避免重复提交；状态更新后继续由任务快照刷新所有入口。
