# ZEUS-0216 会话右侧工作面 Cmd+W 关闭

## 任务状态

- 当前阶段：实现与真实运行验收完成；
- 用户确认时间：2026-08-12；
- 目标：右侧会话上下文工作面活动时，`Cmd+W` 关闭当前内容标签，不再误关 Zeus；焦点不在右侧时保留 macOS 关闭窗口语义。

## 已确认语义

- 会话右侧的浏览器、源码预览、计划和轮次审查共用“会话上下文工作面”，但关闭目标是其中当前活动的内容标签；
- 浏览器存在多个标签时，`Cmd+W` 只关闭当前标签；关闭最后一个标签后右侧工作面自然收起；
- 源码预览、计划和轮次审查当前各只有一个内容标签，关闭后右侧工作面收起；
- 键盘焦点或最近一次明确操作位于右侧工作面时，右侧标签为关闭目标；焦点回到会话、输入框或其他左侧区域后，`Cmd+W` 继续关闭 Zeus 当前窗口；
- 仅仅显示着右侧工作面不代表它处于活动状态，避免用户在会话输入时误关后台内容。

优点：同一快捷键遵循当前活动层级，浏览器、源码、计划和审查形成一致心智，同时保留 macOS 原生窗口关闭行为。

代价：`Cmd+W` 的结果取决于当前焦点；浏览器页面由独立渲染表面承载，必须与 Zeus Renderer 共同维护可信的活动状态。

## 根因

应用菜单的 Window → Close 直接使用 Electron 原生 `close` 角色。该角色在右侧 Renderer 或内置浏览器页面处理按键之前消费 `Cmd+W`，因此无论右侧工作面是否活动，最终都会关闭整个 Zeus 窗口。

## 实现范围

- 把 Window → Close 改为显式 `Cmd+W` 路由：右侧活动时向当前 Zeus Renderer 发送关闭标签意图，否则调用当前窗口关闭；
- Renderer 只上报受限的 `active + kind`，Main 通过发送窗口复验并按窗口保存，不接受任意窗口标识；
- 会话工作面通过焦点和指针捕获区分左右活动层级；内置浏览器网页位于独立 `WebContentsView`，Main 额外读取其真实焦点，避免页面操作无法经过 React DOM 时误判；
- 浏览器复用现有关闭标签链路，继续保留最后一个标签关闭后收起右侧工作面的既有语义；源码预览、计划和轮次审查复用统一工作面关闭链路；
- 窗口级关闭继续进入现有未保存变更和退出保护，不建立旁路。

本项是可回退的快捷键与焦点路由，不满足难以回退的架构决策条件，因此不新增 ADR。
