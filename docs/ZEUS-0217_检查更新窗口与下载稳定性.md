# ZEUS-0217 检查更新窗口与下载稳定性

## 任务目标

统一返修 macOS 原生更新窗口的检查、发现更新、下载、校验、等待重启、安装、完成和失败状态，同时降低 Homebrew 临时故障直接中断下载的概率。

## 现状与根因

- 原生窗口固定为 `440 × 210`，状态切换只隐藏控件、不重新计算内容高度，因此失败和完成状态底部残留大块空白。
- 次要按钮在约束不足时被横向拉伸，主次操作比例失衡。
- 百分比单独放在进度条下方，阶段文字、真实比例和进度条没有形成一组信息。
- 窗口没有最小化和缩放能力，左上角黄色、绿色系统按钮因此呈禁用状态。
- 失败态把 Homebrew 命令和退出码直接作为主说明，既难读，也掩盖“当前 App 未替换、工作可以继续”的产品结论。
- Homebrew 缓存定位等只读命令只执行一次；临时环境、网络或锁冲突会立即把整个预取过程切到失败状态。

## 已确认产品边界

- 红色按钮关闭并隐藏窗口，后台更新预取继续；黄色按钮真实最小化；绿色按钮真实缩放，不能只改变按钮颜色。
- 所有更新阶段复用同一个非阻断原生窗口，只切换标题、说明、进度和操作，不反复创建不同弹窗。
- 窗口默认按当前内容收紧高度；失败详情展开或收起时同步调整，禁止为其他阶段预留空白。
- 下载阶段在进度条上方同一行显示阶段文字和真实整数百分比；只有已下载字节与可靠总大小同时存在时才显示数字。
- Homebrew 信息更新、校验和安装等没有可靠比例的阶段只显示阶段文字与不确定进度，不估算百分比。
- 失败态默认只显示用户可处理的摘要；Homebrew 命令、退出码和原始错误进入“查看详情”，展开后可以复制。
- 失败态主操作为“重试”，次操作为“关闭”；关闭窗口不取消后台已经开始的预取。
- 更新检查、Homebrew 信息刷新、缓存定位和下载遇到临时失败时自动重试两次，并复用 Homebrew 已写入的缓存；安装动作不自动重试。
- 更新重启继续遵守精确 App 路径、bundle ID 和版本复验，不回退到按 bundle ID 启动其他 Zeus。

## 领域模型核对

本任务继续使用 `CONTEXT.md` 中已有的“Homebrew 托管升级”“更新预取”“待安装更新”“非阻断更新进度窗口”“更新重启目标”和“当前运行版本”。视觉布局、错误详情折叠和有限重试属于既有概念的表现与恢复策略，不新增领域术语，也不满足新增 ADR 的必要条件。

## 方案优缺点

- 优点：所有阶段形成连续、紧凑的原生体验；系统窗口按钮具备真实能力；临时失败不再立刻打断用户；默认错误信息可读，诊断证据仍可展开和复制。
- 缺点：窗口需要维护内容自适应与用户缩放两套尺寸行为；真实故障会因两次重试稍晚出现；安装失败仍需用户明确重试。

## 实施范围

1. 重构 `UpdateProgressPanel.swift` 的窗口能力、状态布局、按钮约束、进度信息行和失败详情区。
2. 扩展 Main 到原生辅助程序的状态协议，区分用户摘要与技术详情。
3. 在检查、Homebrew 信息刷新、缓存定位和下载链路增加两次有限重试，不改变安装交易。
4. 完成格式、静态检查、构建、测试身份打包和可行的隔离真实窗口验收。

## 阶段状态

- `grilling` 已完成：用户逐项确认了系统窗口按钮、自动重试、百分比布局、失败详情和统一窗口边界。
- `domain-modeling` 已完成：复用既有应用更新术语，不新增 `CONTEXT.md` 条目或 ADR。
- 当前阶段：开发、静态检查、测试身份打包和无窗口协议演练完成；真实可见 GUI 验收受显示器护栏阻断。

## 实现结果

- 原生面板改为标准可关闭、可最小化、可缩放窗口；红、黄、绿三个系统按钮都对应真实窗口能力。
- 内容区改为四边约束与状态驱动的自适应高度，状态变化和失败详情展开时保持窗口顶部位置稳定，不再沿用固定 `440 × 210` 高度。
- 操作区使用弹性空白承接剩余宽度，主次按钮保持 `30px` 高和最小可读宽度，不再把次按钮拉满整行。
- 下载阶段新增同排的阶段文字与右侧真实整数百分比，使用同一比例驱动原生进度条；其他阶段只显示阶段文字与不确定进度。
- 失败协议拆分为用户摘要与 `technicalDetail`。原生窗口默认收起技术详情，展开后使用可选择的等宽文本区，并提供复制动作。
- 失败主次操作收敛为“重试 / 关闭”；关闭会隐藏窗口并保留控制器后台任务语义。
- Release 检查、`brew update`、Cask 信息读取、`brew --cache` 和 `brew fetch` 增加两次有限重试，延迟分别为 `400ms` 与 `1200ms`；`brew upgrade` 不进入重试封装。
- 辅助窗口被最小化后再次执行“检查更新”会真实恢复窗口，不会因 `isVisible` 仍为真而留在最小化状态。

## 验证结果

- 变更 TypeScript 与任务文档 Prettier：通过。
- 原生辅助程序单独编译：通过。
- `pnpm lint`：通过。
- `pnpm typecheck`：通过。
- `pnpm build`：通过；保留既有的大 chunk 警告。
- `pnpm package:mac`：通过，只生成 `0.3.0`、`dev.hypha.zeus.test` 的 `Zeus Test.app` 与测试 DMG。
- 测试 App 深度签名：通过；包内 `ZeusUpdateProgress` 为 arm64 Mach-O，独立严格签名校验通过。
- 原生状态协议无窗口演练：依次接收检查、`37%` 下载、带技术详情的失败和退出状态，进程退出码为 `0`。
- 隔离 Homebrew 重试演练：`update`、Cask `info`、缓存定位和 `fetch` 均故意在前两次返回临时失败、第三次成功；四项调用次数均为 `3`，最终进入 `updating → downloading → verifying` 并通过缓存 SHA-256 校验。演练没有执行安装命令，临时探针文件和目录已经逐项删除。
- 本机 `brew --cache --cask imchenway/tap/zeus` 当前只读复核成功，因此用户截图中的失败不能归因于该命令在当前 Homebrew 版本中永久失效；有限重试用于覆盖当时的临时失败，技术详情用于保留再次发生时的真实原因。
- GUI 护栏检查发现当前有三块在线屏幕，其中存在非主外接屏。产品辅助窗口当前首次展示会居中到主屏，无法保证首次出现就在非主外接屏，因此本轮没有启动任何可见测试窗口，也没有把协议、构建或签名结果冒充 GUI 验收。
- 没有生成、启动、替换或修改生产身份 `Zeus.app`，没有执行正式 Homebrew 升级。
