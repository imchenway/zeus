# ZEUS-0221 支持目标模式

## 当前阶段

实现与静态门禁已完成，独立身份真机已完成入口和目标草稿验收；真实 Provider 目标自动续跑仍需专门联调。

## 原始需求

- 支持目标模式。
- 参考 Codex App 的实现。

## 已核实事实

### Codex 产品语义

- 官方文档把 Goal 定义为“长时间工作的持久目标”：它跨轮次保持，围绕可验证的停止条件自动继续工作。
- 官方操作覆盖设置、查看、编辑、暂停、恢复和清除目标；目标文本非空且最多 4,000 字符。
- 当前本机 `codex-cli 0.147.0` 将 `goals` 标记为稳定且已启用能力。
- 当前 app-server 协议原生提供 `thread/goal/set`、`thread/goal/get` 和 `thread/goal/clear`，并发送 `thread/goal/updated` 与 `thread/goal/cleared` 通知。
- 原生目标状态为 `active / paused / blocked / usageLimited / budgetLimited / complete`，同时提供已用 Token、已用时间与可选 Token 预算事实。
- Goal 绑定原生 thread，不是 `default / plan` 之外的第三种协作模式。

### Zeus 实现前基线

- Zeus 当前只有 `default / plan` 两种会话协作模式，并按会话保存下一轮配置。
- `CodexAppServerManager` 尚未暴露目标读写接口，`CodexNativeConversationCoordinator` 也尚未处理目标更新和清除通知。
- 目标自动续跑会在一个 turn 完成后发起下一个 turn。Zeus 当前在每个 `turn/completed` 后立即投影为空闲或完成关注状态，这与持续目标的整体生命周期不一致。
- 本机安全策略禁止自动读取 `com.openai.codex` 的实时界面，因此当前只能使用官方文档、当前本机 CLI 能力和 app-server 生成协议取证，不宣称已完成 Codex App 实机视觉对照。

## 候选领域定义

### 目标

绑定一条原生模型会话的持久执行契约，包含唯一目标、停止条件、生命周期状态和用量事实；激活时允许 Provider 跨多轮自动续跑。

用户已确认正式术语为“目标”，不再称为“目标模式”或第三种工作模式；该术语已写入根目录 `CONTEXT.md`。

## 待决策

无。需求范围与产品语义已经确认。

## 已确认决策

1. 首批按 Codex 原生能力接入完整生命周期，覆盖创建、查看、编辑、暂停、恢复、清除及全部原生状态，不交付只能启动的半成品。
2. 正式术语为“目标”；它不是第三种工作模式，可与普通或 PLAN 协作模式组合。
3. 新会话和已有会话都支持创建目标。新会话必须先建立真实原生 thread，再成功绑定目标，然后启动首轮；绑定失败不得静默退化为普通会话。
4. 目标沿用 Codex 原生单一 objective 文本，不拆分独立停止条件字段；界面引导用户在同一文本中写清目标、边界、验证方式和停止条件，只强制校验非空与 4,000 字符上限。
5. 首批不提供 Token 预算输入，创建普通目标时不擅自设限；仍读取并展示 Provider 返回的可选预算、已用 Token 和 `budgetLimited` 状态。
6. 只有 Codex 验证达成停止条件时才进入“已完成”；用户不能手工改写为完成，主动结束使用“清除”。
7. 暂停或阻塞的目标只能由用户显式“恢复”；普通消息可补充上下文，但不自动重启跨轮续跑。
8. 界面同时提供 Codex 用户熟悉的 `/goal` 命令和可发现的“目标”按钮，两个入口打开同一目标面板。
9. 目标建立后，在会话输入区上方常驻紧凑目标栏；目标栏展示状态、摘要、真实已用时间、真实用量与当前必要动作，点击后展开完整面板，不伪造进度百分比。
10. 清除尚未完成的目标必须二次确认，明确说明清除会停止后续自动续跑、不可直接恢复，但保留会话和目标历史证据。
11. 清除目标不隐式中断已经开始的当前轮次；当前轮继续完成，只停止后续自动续跑。用户需要立即停止时继续使用会话现有“停止”动作。
12. 活动目标只在目标完成、阻塞、账户用量受限或 Token 预算受限时产生关注状态和系统通知；中间每轮完成只是目标进展，不产生“已完成”假终态和重复通知。
13. 目标入口只在当前 Agent 和当前 app-server 明确支持原生 goals 能力时显示。Pi 或旧版 Codex 不支持时不显示死入口，仅在诊断区说明未验证、不支持或需升级。
14. 活动目标编辑时先暂停自动续跑，已经开始的当前轮继续完成；保存新目标后仍由用户显式恢复，禁止新旧目标并发驱动后续轮次。
15. 活动目标属于“仍有工作”；用户关闭 Zeus 界面后由独立执行宿主继续运行。退出时复用现有选择；若用户选择停止任务再退出，则暂停目标并停止当前轮，保留可恢复的目标。
16. 目标创建、编辑、暂停、恢复、关键终态和清除在会话时间线保留紧凑历史记录。当前目标仍以 app-server 为事实源；时间线只保存已发生事件的快照，清除后可审计但不能直接恢复。
17. 任务会话的目标完成不自动修改任务管理状态；一个任务可有多条会话和开发线，用户仍需审查结果、处理代码交付并显式改变任务状态。

## 当前建议及取舍

建议完整接入 Codex 原生 thread goal，但不把它扩展为第三种协作模式。

优点：语义、持久性、自动续跑和状态都与当前 Codex 原生能力一致；无需 Zeus 另造调度事实源。

代价：必须同时收口 app-server 接口、目标持久投影、轮次续跑、窗口退出保护、会话关注状态和界面操作；不能只加一个按钮即宣称完成。

## 已完成实现

### Provider 与执行宿主

- 在 Codex app-server 管理器中探测原生 goals 能力，并接入目标读取、设置和清除 RPC；旧版或未启用能力保持明确不可用。
- 运行时世代管理器把活动目标视为仍有工作，防止目标自动续跑期间旧 Codex 世代被提前排空；线程迁移或恢复时重新同步目标事实。
- 新会话严格按“建立原生 thread → 绑定目标 → 启动首轮”执行。目标绑定失败时不启动首轮，也不静默退化成普通对话。
- 停止任务再退出时，先暂停所有已投影的活动目标，再沿用现有中断流程处理当前轮次。

### 本机投影、审计与接口

- 增加当前目标投影与不可变目标事件时间线，记录创建、编辑、暂停、恢复、关键终态和清除。
- 当前目标以 Provider 返回值为事实源；读取和清除前都会重新核对原生目标，SQLite 只承担界面投影和历史审计。
- 新增已有会话的读取、创建或编辑、暂停、恢复和清除接口；未完成目标清除要求明确确认。
- 目标存在期间，普通回复、待审批事件和中间轮次结束只更新进度，不制造普通“未读/已完成”关注或系统通知；关键目标终态统一触发关注。
- 目标完成不会自动改变任务管理状态。

### 桌面界面

- 新对话和已有 Codex 原生会话都提供“目标”按钮；当前 Agent 或 app-server 不支持时隐藏入口，运行诊断展示真实能力原因。
- `/goal` 与按钮打开同一语义化目标面板，目标内容按 Unicode 字符计数并校验 1 至 4,000 字符。
- 面板覆盖创建、编辑、暂停、恢复、清除、真实用时、真实 Token 用量、可选预算和审计时间线。
- 当前目标在输入区上方显示紧凑目标栏，不伪造进度百分比；清除未完成目标展示二次确认和当前轮次继续执行的说明。
