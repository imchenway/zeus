# ZEUS-0222 打开 Git 页报错

## 任务类型

缺陷。

## 用户反馈

打开项目 Git 工作台后显示“无法读取项目 Git 现场”，技术详情为旧本机服务未注册
`GET /api/projects/:projectId/git/workbench`。

## 根因

项目 Git 工作台与任务执行在产品语义上没有依赖关系，但当前实现把两者的接口都放进了长生命周期执行宿主。新版 App 为了不中断旧版宿主中仍在执行的任务，会暂时复用旧宿主；新版 Renderer 随后向旧宿主请求新增的 Git 工作台路由，得到路由不存在的 404。

这不是仓库状态、任务占用或 Git 并发错误，而是 App 界面版本与项目 Git 接口版本被错误绑定到了可跨版本存活的任务执行宿主。

## 已确认边界

- 项目 Git 工作台必须独立于任务是否正在执行，打开后立即读取当前项目真实仓库。
- 不通过中断旧任务、强制关闭旧宿主或等待任务结束来恢复 Git 页面。
- Renderer 仍只能提交项目 ID、仓库 ID 和类型化 Git 动作，不能获得任意本机路径或任意命令执行能力。
- 执行宿主继续独占业务数据库写入；新的 Git 服务不直接读取或写入 SQLite。
- 浏览器开发入口可以保留本机 HTTP 路由作为降级，Electron 正式入口必须使用与当前 App 同版本的受信 Main 服务。

## 实施方案

把项目 Git 工作台的仓库发现、快照、提交详情、分支比较和白名单动作放到 Electron Main 随当前 App 启动的受信服务中。Main 只通过旧宿主早已存在的项目查询接口取得项目名称与本机根目录；随后从当前 App 包内的 `git-core` 发现真实仓库，并在每次动作前重新校验仓库仍属于该项目。

仓库 ID 由项目 ID 与仓库相对路径稳定派生，不向 Renderer 暴露绝对路径。独立 Repository Diff 窗口复用同一桥接，因此主 Git 页面和 Diff 页面不会再绕回旧执行宿主的新路由。

优点：正在执行的任务、等待交互和旧运行世代都不影响项目 Git 工作台；App 与 Git 接口天然保持同版本，且不产生第二个数据库写入者。

代价：Electron 与纯浏览器入口存在两种传输方式，必须让两者复用同一 `git-core` 事实与动作类型；项目 Git 服务需要在每次请求时重新发现并复验仓库，不能依赖旧宿主持久仓库记录作为授权。

## 当前阶段

已完成实施和验证，未执行 Git 提交、推送、合入、回退或远端写入。

## 实施结果

- 新增当前 App 内的项目 Git 工作台服务，仓库发现、工作区快照、提交详情、分支比较和白名单动作都由 Electron Main 执行。
- 新增受信 IPC 桥接；Electron Renderer 优先使用桥接，纯浏览器开发入口继续保留本机 HTTP 降级。
- 项目查询仍复用旧宿主长期存在的 `GET /api/projects/:projectId`，因此旧宿主只提供项目身份和根目录，不再承担新版 Git 工作台路由。
- 仓库 ID 由项目 ID 与相对路径稳定派生；每次读取或动作前重新发现并确认仓库归属，绝对路径不返回 Renderer。
- 主 Git 页面、提交详情、分支比较和独立 Diff 窗口使用同一份当前 App 服务，避免入口间出现不同版本语义。
