# ZEUS-0224 会话切换经常空白页

## 用户现场

- 用户从全局侧边栏切换会话后，左侧目标会话已经高亮，主工作区却只剩底部输入区和大面积空白。
- 截图中的目标会话位于 `css` 项目，侧边栏同时展示多个项目的会话。
- 用户描述该问题经常发生，不是单条会话历史为空。

## 已核对事实

- `ZEUS-000060` 已规定：本次运行中成功读取过的会话应先显示真实热缓存，再后台校准权威快照；首次读取没有缓存时应显示明确加载状态，刷新失败时也不能退回空白页。
- 当前侧边栏聚合展示所有项目的会话，允许用户直接点击其他项目下的会话。
- 当前 `selectNativeConversation` 只更新选中会话、任务详情和会话页导航，不同步更新当前项目。
- 当前 `resolveSelectedNativeConversationForProject` 又要求选中会话必须属于当前项目；跨项目点击后它会返回空值。
- 主工作区在没有解析出目标会话时退回新对话工作面，因此出现“左侧已选中目标会话、右侧却没有目标历史”的错位。
- 这条路径发生在热缓存接管之前，单纯扩大缓存或美化加载动画不能修复项目与会话身份不一致。

## 已确认领域口径

### 跨项目会话导航

点击其他项目下的会话时，当前项目与当前会话必须作为一次原子导航共同切换，不能只更新会话 ID 后沿用旧项目。

优点：全局侧边栏的跨项目会话入口保持可用，主工作区始终能按目标项目解析目标会话。

代价：一次会话点击会同时改变项目上下文；项目级任务、代码、Git 等页面状态需要继续按既有导航规则隔离，不能被旧项目状态冒充。

### 会话切换过渡

目标会话没有热缓存、必须首次读取权威历史时，主区暂时保留上一会话正文，不显示整页加载态，也不使用遮罩；底部只显示“正在加载”。

过渡期间的新输入已经归属刚点击的目标会话。用户可以继续输入和发送，但消息只进入目标会话的本地等待队列；只有目标会话身份与历史就绪后才能按原顺序提交，禁止发送到仍在画面中的旧会话。

旧正文中的审批、回答、重试、撤销等会话专属动作继续绑定画面中的旧会话，不改投目标会话；底部加载状态必须明确区分“旧正文仍可操作”和“新输入正在等待目标会话”。

优点：切换时不再出现大面积空白，用户可以继续工作，输入也不会误发到旧会话。

代价：短时间内会出现目标会话已选中、主区仍展示旧正文的视觉过渡；底部加载状态必须足够明确，旧正文中的审批、回答、重试等会话专属动作不能借目标会话身份执行。

## 用户决策

- 用户已确认上述范围并要求直接实现。
- 目标会话首次加载期间，底部只显示“正在加载”，不增加整页遮罩或大面积占位。

## 目标读取失败

目标会话加载失败时，继续保留旧正文和目标会话草稿；底部从“正在加载”切换为可读失败说明与重试入口。目标排队消息保持原身份和顺序，不发送、不丢弃，也不改投旧会话。

优点：目标选择和输入现场不会被一次读取失败打断，用户仍可处理旧正文中的真实会话动作。

代价：失败期间页面同时承载旧正文和目标草稿，状态文案与操作归属必须始终可见，不能只靠左侧高亮或颜色表达。

## 实施结果

1. 点击全局会话后，目标项目与目标会话现在同一次更新，不再出现“左侧选中、右侧被旧项目过滤”的空白工作面。
2. 目标会话已有真实热缓存时直接接管；没有热缓存时保留上一会话正文，旧正文的审批、回答、重试等动作继续归属旧会话。
3. 过渡期间底部显示目标会话输入区和“正在加载”；加载失败改为底部失败说明与重试，旧正文不清空。
4. 目标会话未就绪时的新消息按原顺序写入目标会话本地等待队列，并持久化独立的幂等身份；只有目标身份与权威历史就绪后才顺序提交。
5. 目标工作面在过渡结束前后保持同一 React 身份，避免就绪时重建控制器中断正在释放的等待消息。
