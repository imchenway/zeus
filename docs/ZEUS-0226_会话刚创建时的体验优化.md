# ZEUS-0226 会话刚创建时的体验优化

## 当前阶段

- 用户已确认产品边界，实现、静态检查、构建和独立测试包验证已经完成。
- 真实任务推送与 GUI 验收受同 bundle ID 的其他任务测试实例和外接屏首次落点门禁阻断，未冒充完成。
- 本任务不新增或恢复单元测试，不执行 Git commit、push、merge、revert 等历史或远端写入。

## 用户反馈

任务刚推送到新会话时，首发内容已经立即出现，但其中的图片显示为“图片预览不可用”文件卡；创建进度又位于输入区下方，不像 Codex 那样紧跟当前会话内容表达“正在连接”。

## 已确认事实

1. 任务首发工作面已经复用发送中图片组件，并把当前任务附件传入本地首发消息，不需要等待 Provider 回放才具备展示条件。
2. 当前任务附件保存在 Zeus 的任务附件受信目录，普通会话输入附件保存在另一套会话附件受信目录或使用授权引用。
3. 发送中图片组件只调用会话输入附件预览入口。该入口会按安全边界拒绝任务附件路径，于是有效任务图片被错误降级为“图片预览不可用”。
4. Main 进程已有任务附件预览入口，会复验路径必须位于任务附件受信目录，不需要开放任意本机路径或 `file://`。
5. 任务首发工作面已有真实创建状态、失败原因和重试动作，但状态当前位于 composer 下方，与正在阅读的首发消息距离过远。

## 已确认产品边界

- 创建状态从底部移动到首发消息下方，不在两个位置重复显示。
- 创建进行中统一显示“正在连接”；真实会话接管后提示立即消失，不延伸为模型“正在思考”。
- 创建失败在同一位置显示真实原因和重试，不跳页、不清空首发内容与输入现场。
- 有效任务图片在首发消息内直接显示缩略图；只有文件确实缺失、损坏或不属于受信目录时才降级为错误卡片。
- 图片展示只复用现有任务附件与会话附件两条受信预览入口，不修改 Provider 输入、任务附件存储或资源授权边界。

优点：连接反馈贴近当前会话内容，图片不再因预览入口选错而显示错误；同时保留现有本机资源安全边界。

代价：发送中图片展示需要兼容两类受信附件来源；创建失败信息进入会话滚动内容后，长首发消息需要依靠既有自动跟随保持可见。

## 实施方案

1. 发送中图片先使用会话输入附件预览；未命中且存在本机路径时，再使用任务附件预览。两条入口都由 Main 进程复验各自受信范围。
2. 把创建状态交给会话记录组件，在本地首发消息之后渲染；移除 composer 下方的旧位置。
3. 创建态使用连接图标和“正在连接”文案；创建请求失败复用既有原因和重试动作，真实身份已建立但首次快照连接失败时也留在原位并提供“重新连接”。
4. 状态变化继续参与会话最新内容跟随，并补齐浅色、深色、窄窗口和减少动态效果所需样式。

## 验证边界

- 执行改动文件格式检查、`pnpm lint`、`pnpm typecheck`、`pnpm build` 和 `git diff --check`。
- 条件允许时执行 `pnpm package:mac`，只生成 `Zeus Test.app`，并核对 `dev.hypha.zeus.test` 身份。
- 真实界面验收必须使用本任务测试包、独立用户数据目录，并保证窗口首次出现在非主外接显示器；无法满足时明确记录缺口。
- 静态检查、构建、打包和签名不能冒充真实任务推送或 Provider 接管已经通过。

## 实施结果

1. 发送中图片先请求会话输入附件预览；未命中且资源拥有本机路径时，再请求任务附件预览。两条入口继续分别复验会话附件授权和任务附件受信目录。
2. 有效任务图片不再因误走会话附件入口而显示“图片预览不可用”；文件真实缺失、损坏或越过受信目录时仍保留安全降级。
3. “正在连接”已经移到会话记录内的首发消息下方，使用轻量连接图形和脉冲反馈；系统减少动态效果时关闭动画。
4. 真实会话接管后连接提示消失；创建请求失败在原位显示原因和重试，真实身份已建立但首次快照连接失败时在原位显示“连接失败 / 重新连接”。
5. composer 下方的旧创建提示已移除，不形成两个重复状态区；状态变化继续触发现有最新内容跟随。
6. 领域词汇“任务首发工作面”已同步修订为“首发消息后原位表达真实连接进度”。这项选择更贴近用户正在阅读的内容，代价是长首发内容需要依赖既有自动跟随保持状态可见。
