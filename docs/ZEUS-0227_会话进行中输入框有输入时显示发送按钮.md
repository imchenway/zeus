# ZEUS-0227 会话进行中输入框有输入时显示发送按钮

## 任务目标

修复活动轮次中输入框已有可提交内容、回车实际可以发送，但右下角仍固定显示停止按钮的问题。输入区主操作必须与当前可执行动作一致。

## 现状与根因

- 活动轮次期间，Enter 已经固定按队列提交，形成下一轮队列消息。
- 右下角按钮只按轮次是否活动选择：活动时无条件显示停止，非活动时显示发送。
- 因此输入文字、附件或浏览器批注后，键盘可以提交但指针主操作仍表达中断，用户容易误以为消息无法发送。

## 已确认的产品规则

- 活动轮次且没有可提交内容：显示停止按钮。
- 活动轮次且存在非空文字、待提交附件或浏览器批注：显示发送按钮。
- 点击发送与 Enter 使用同一个队列提交入口，不把输入内容直接改成当前轮引导。
- 存在草稿时不同时展示发送和停止；连续两次 Escape 仍可中断当前执行。
- 非活动轮次沿用发送按钮，空内容时禁用。

## 方案优缺点

优点：输入内容后主按钮立即表达真实可执行动作；鼠标与键盘语义一致；不需要新增第二个按钮或额外发送方式选择。

代价：活动轮次存在草稿时停止按钮不直接可见；用户需要清空草稿或使用连续两次 Escape 停止。

## 实施范围

- 输入区根据“活动轮次”和“存在可提交内容”共同选择发送或停止按钮。
- 复用现有发送、队列和中断回调，不修改服务端接口、队列生命周期或 Provider 协议。
- 在项目词汇表中新增“会话输入区主操作”，并在设计契约中记录按钮选择规则。

## 非目标

- 不改变 Enter 默认排队和队列项“引导”能力。
- 不新增常驻发送方式切换或同时展示两个主操作。
- 不修改停止请求、轮次终态、附件提交和浏览器批注协议。
- 不新增或恢复单元测试、组件测试、DOM/CSS 契约测试。
- 任务实现阶段未经用户授权，不自行执行 Git 提交、推送、合并或回退。
