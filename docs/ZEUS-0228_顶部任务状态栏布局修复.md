# ZEUS-0228 顶部任务状态栏布局修复

## 任务信息

- 任务类型：缺陷
- 当前阶段：实现完成；静态、构建、测试身份打包、隔离启动和打包 CSS 渲染验证通过，真实任务会话受隔离 Codex 未登录阻塞
- 用户现状：会话标题栏中的任务管理状态选择器横向占满标题行，任务标题和右侧操作被挤压、裁切
- 修复边界：只调整会话标题栏的任务管理状态入口布局，不改变任务状态数据、保存流程、项目配置或 Coding Agent 运行状态

## 现状与根因

1. 截图对应 `SessionWorkspace` 的会话标题栏，不是菜单栏用量浮窗或任务列表工具栏。
2. 该入口是任务管理状态选择器，和任务列表、任务详情共用项目状态配置与 `managementStatus` 事实源。
3. 通用 `ZeusSelect` 为表单场景默认声明 `inline-size: 100%`，会话标题栏虽然尝试把业务实例设为自动宽度，但通用触发器仍使用百分比宽度；在当前级联与弹性布局中，选择器获得了整段可用空间。
4. 结果不是数据错误，而是通用表单控件宽度契约泄漏到紧凑标题栏场景。

## 已确认方案

会话标题栏的任务状态选择器按当前状态内容收紧，并设置标题栏场景的最大宽度；状态名称过长时只在触发器中省略，完整状态仍可在下拉菜单和可访问名称中读取。空间不足时优先省略任务标题，状态入口和右侧必要操作保持可用。

优点：

- 改动只作用于会话标题栏，不改变任务列表、任务详情和其他表单下拉框。
- 任务状态仍紧跟任务标题，符合既有信息层级和状态修改契约。
- 长状态不会再次吞掉整行，右侧操作不再被推出可视区域。

缺点：

- 极长的项目自定义状态名在关闭状态下可能显示省略号，需要展开菜单查看完整文字。
- 标题栏可用宽度极窄时，任务标题仍会先被省略；这是保留状态操作和右侧快捷操作的明确优先级。

已放弃方案：修改通用 `ZeusSelect` 的默认宽度为内容宽度。

优点：可以从全局消除类似的标题栏拉伸。

缺点：设置、表单、任务详情和批量操作依赖选择器填满容器，修改全局默认值会扩大回归范围。

## 验收口径

- 任务管理状态选择器紧跟当前任务标题，不再占满整行。
- 普通长度状态完整显示；超长状态只在触发器内省略，不造成标题栏横向溢出。
- 任务标题和右侧操作不重叠、不被状态选择器推出可视区域。
- 下拉仍可通过鼠标和键盘打开，状态选项、颜色和保存行为不变。
- 项目自由对话不新增任务状态；任务管理状态与 Coding Agent 运行状态继续保持独立。

### 打包 CSS 渲染与交互

- 临时本地页面按产品最终顺序加载打包后的会话 CSS 和通用产品 CSS，并使用会话标题栏真实类名与 `ZeusSelect` DOM 结构；该页面只用于验证浏览器级布局，不冒充真实任务会话。

- 点击状态控件后，“待开始、开发中、测试中”三个选项正常出现，证明触发器没有因宽度修复失去交互。
