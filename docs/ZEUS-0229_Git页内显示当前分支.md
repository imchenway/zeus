# ZEUS-0229 Git 页内显示当前分支

## 任务类型

需求。

## 用户反馈

项目 Git 工作台顶部在项目身份与 Git 操作之间存在空白区域，当前分支只在“本地变更”和“日志”的仓库内容中出现，无法从工作台顶部直接查看全部分支并执行分支操作。

用户期望参考 IDEA 的分支入口：顶部常驻显示当前分支；展开后显示当前项目目录中真实发现仓库的本地与远程分支，并可对分支执行相关操作。

## 已核对事实

- `ProjectGitRepositorySnapshot` 已包含当前分支、本地分支、远程分支、远端、标签和工作区状态，数据来自当前本机仓库快照。
- 项目 Git 工作台已经支持签出、本地分支创建、安全删除、比较、合入、变基和远端拉取等白名单动作。
- “日志”页已有按仓库分组的本地与远程分支树，以及围绕“选中分支”和“当前分支”的 IDEA 语义上下文菜单。
- 当前缺口主要位于工作台顶部：`project-git-toolbar` 只显示项目身份和远端或通用操作，没有常驻分支触发器。
- Zeus 项目可能包含多个真实 Git 仓库；旧设计已经确认不使用一个虚假的全局当前仓库覆盖多仓语义。单仓可以直接显示当前分支，多仓需要在入口中表达各仓分支是否一致，并在浮层内按仓库操作。

## 领域边界

- 本功能属于“项目 Git 工作台”的仓库分支操作，不属于任务推送的“来源分支”，也不改变任务开发线或代码交付状态。
- IDEA 只作为功能范围、对象关系和操作方向参考；视觉继续使用 Zeus 当前的类 macOS 产品语言。
- 所有分支和操作结果必须来自真实 Git 现场；动作完成后重新读取对应仓库快照。

## 已确认决定

### 分支行的左键语义

采用“选择分支后展开显式操作”：单击分支先展示签出、比较、合入、变基等与当前分支方向明确的动作，只有点击具体动作才执行 Git 写入。

优点：与用户提供的 IDEA 参考一致，避免浏览分支时误切换；现有分支上下文菜单和白名单动作可直接复用。

代价：切换分支需要两步操作，比单击分支立即签出多一次点击。

不采用“单击非当前本地分支立即签出”。该方式切换更快，但误触会直接改变工作区，在存在本机修改时也更难预判影响。

### 弹层范围

用户确认按提供截图覆盖完整 IDEA 范围，而非只显示分支。顶部弹层需要包含搜索、Update Project、Commit、Push、新建分支、按标签或 revision 签出，以及 Recent、本地分支、远程分支和 Tags 分组。

优点：常用 Git 查看和操作集中在当前分支入口，和用户提供的对象关系一致。

代价：这不再是局部展示修复；标签与 revision 签出、游离提交状态、搜索结果和动作禁用原因都需要补齐真实语义。

### 标签与 revision 签出

允许按 Git 原义签出标签或具体提交并进入游离提交状态。顶部使用标签名和短提交号明确显示当前位置；依赖当前命名分支的 Pull、Push 等动作不沿用普通分支默认值，并提供“从当前提交新建分支”。

优点：保留完整 Git 与 IDEA 语义，用户可以直接检查历史版本。

代价：游离状态中新提交不自动归属于任何命名分支；界面必须持续提示并提供建立分支的恢复动作。

## Update Project

- Update Project 面向当前项目全部真实仓库，不只更新当前选中仓库。执行前逐仓展示当前本地分支、跟踪远端和可执行状态，执行后逐仓展示成功、冲突或失败。
- 更新策略对齐 IDEA，提供 Merge、Rebase 和 Reset to Remote 三种，并把本次选择统一应用到全部可执行仓库。
- Merge 为首次默认值；后续记住当前项目上次使用的策略，但每次执行前仍显示并允许修改。
- Merge 和 Rebase 分别对应获取后合并和获取后变基。Reset to Remote 会丢弃本地分支尚未包含在跟踪远端中的提交，必须列出逐仓影响并使用独立危险确认。
- 存在未提交变化时采用 Smart Update：逐仓建立带本次操作身份的真实 Git Stash，更新后逐仓恢复。恢复冲突时保留 Stash 和冲突现场，结果不能冒充完整成功。

优点：多仓更新范围和策略与 IDEA 心智一致，同时保留每个真实仓库的执行结果和本机变化。

代价：一次 Update Project 可能部分成功；Smart Update 恢复阶段可能产生冲突，Reset to Remote 还需要额外影响预览和危险确认。

## 分支、标签与 revision 签出

- 分支行单击只展开动作；用户点击“签出”后才执行。
- 签出可能覆盖未提交变化时只提供 Smart Checkout：先创建真实 Git Stash，签出后恢复；不提供 Force Checkout 直接丢弃文件。
- 允许签出标签或任意可解析 revision 并进入游离提交状态。顶部以标签名和短提交号显示；Pull、Push 等依赖当前命名分支的默认动作禁用，并提供“从当前提交新建分支”。
- 任意 revision 必须由服务端用 Git 解析并限制为当前仓库对象，Renderer 不能把文本拼成任意命令。

优点：签出行为完整且不静默覆盖未提交工作，标签和历史提交可以真实检查。

代价：Smart Checkout 恢复可能冲突；游离状态需要持续可见，用户在创建命名分支前不能沿用普通分支的同步动作。

## Recent 与搜索

- Recent 从每个仓库的 Git reflog 提取最近签出的唯一分支或标签，不只记录 Zeus 内的点击；仅保留当前仍能解析的引用。
- 搜索同时覆盖动作名称、本地分支、远程分支、标签和可解析的 revision 输入；选择动作只进入对应确认或表单，不因搜索结果获得焦点就执行写操作。
- 单仓按 Recent、本地分支、远程分支和 Tags 分组；多仓沿用既有共同分支和按仓库操作口径，顶部明确显示仓库分支一致或分歧。

优点：最近项与真实 Git 使用历史一致，用户可以用一个入口定位动作和引用。

代价：reflog 可能包含已经删除或失效的历史，读取后需要复验；多仓搜索结果必须重复显示仓库归属，列表更长。

## 顶部动作复用

- Commit 打开现有本地变更提交路径，提交真实已暂存内容；多仓分别创建提交，不伪装成一个跨仓提交。
- Push 打开现有多仓推送弹窗，逐仓展示本地分支、目标远端分支和待推送提交。
- New Branch 以当前 HEAD 为起点，创建前校验 Git 合法分支名；游离状态下它也是把当前位置纳入命名分支的恢复入口。
- 所有当前禁用或仅跳转日志页的占位动作必须删除或改成真实能力，不能因视觉存在就宣称可用。
