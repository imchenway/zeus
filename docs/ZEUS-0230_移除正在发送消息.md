# ZEUS-0230 移除正在发送消息

## 当前阶段

- 2026-08-15 针对“怎么没生效”补充排查：已确认正式 `Zeus.app 0.3.11` 包内不存在旧文案，但上一版源码仍然只按部分状态组合隐藏投递反馈，没有从渲染规则上完整移除正常发送过程提示。
- 补充修复改为正常投递过程一律不渲染独立反馈，仅保留发送失败、结果待确认和持久记录确认。
- 真实任务推送在隔离身份的官方 Codex 登录门禁前停止，未把部分 GUI 检查冒充为 Provider 链路通过。
- 本任务不新增或恢复单元测试，不执行 Git commit、push、merge、revert 等历史或远端写入。

## 用户现象

任务首发内容已经立即出现在会话记录中，下方同时显示“正在发送消息”和“正在连接”。两条正常过程提示相邻出现，重复表达消息尚未由真实会话接管，增加了视觉噪音。

## 已核对事实

1. “正在发送消息”来自乐观用户消息的局部投递反馈；“正在连接”来自任务首发工作面的会话创建状态，两者不是同一组件。
2. 乐观用户消息已经即时展示本地受信的文字和图片，普通发送提示不是确认用户输入可见性的唯一载体。
3. 同一投递反馈还承载引导中、消息已接收、结果待确认和明确失败等不同状态；整体删除会损失异常恢复和结果不确定性提示。

## 已确认产品边界

- 移除所有正常消息投递阶段的独立过程提示，包括普通发送和引导投递，不再依赖具体状态枚举。
- 保留会话创建的“正在连接”、真实轮次的“正在启动处理 / 正在思考”、持久记录确认、发送失败和结果待确认。
- 保留发送状态的数据与调度语义，只调整普通过程态的可见反馈，不修改 Provider 输入、队列、幂等或失败恢复行为。

优点：消除截图中重复且短暂的过程提示，首发消息和连接反馈保持清晰。

代价：用户点击发送到服务端接受之间的极短时窗不再有独立文字说明；但消息正文已经立即出现，后续连接、处理和异常状态仍会接管反馈。

## 补充现象：首发消息重复闪烁

任务推送到新会话后，首条消息会在真实会话建立和 Provider 回放期间闪烁、重复渲染数次。用户确认产品规则：本地提交、真实会话建立和 Provider 回放属于同一个可见消息节点，只允许在原位补齐状态与资源。

### 根因

1. 本地乐观首发消息原本单独渲染在 transcript 尾部；Provider 接管后又移入正式时间线，消息在两个渲染分支之间迁移。
2. 同一业务消息的 React key 原本直接采用内部条目 key；乐观条目被 Provider 条目替换时，key 会从本地复合身份变成 Provider 会话、轮次和条目的复合身份，React 因而卸载并重建整条消息。
3. 结构化任务首发布局虽然会由本地服务和会话协调层保存、回投，但接管中间快照仍可能只携带通用消息负载。布局短暂缺失会让用户消息从任务字段布局退化到通用 Markdown；图片组件随整条消息重建后也会重新读取预览。这些是闪烁的放大因素，不是最初原因。

### 已确认方案

- 任务首发乐观消息从一开始就进入正式时间线投影，不再先在独立尾部分支绘制。
- 用户消息的可见 key 使用稳定的客户端用户消息标识；Provider 技术条目 key 继续作为状态事实，但不再决定 React 消息节点身份。
- Provider 快照或完成事件接管用户消息时，如果中间负载暂未携带任务首发布局或待提交附件展示，则沿用同一客户端消息已有的展示数据；Provider 返回对应权威字段后仍以权威字段为准。
- 失败、结果待确认和持久记录确认继续原位呈现；普通发送与引导投递的正常过程都不再呈现独立反馈。

优点：整条首发消息不会因技术身份接管反复卸载，结构化字段、Markdown 子树和已加载图片可以在原消息节点中连续更新。

代价：界面展示身份与 Provider 条目身份需要分开理解；Reducer 必须在用户消息接管时显式保留少量展示字段，不能再把最终 payload 作为无差别整包替换。

## 实施方案

在会话记录的局部投递反馈入口按用户可感知结果收口：正常 `pending`、引导投递和其他正常中间状态都不渲染反馈；只有发送失败、结果待确认和持久记录确认继续复用现有组件。该修改不再依赖 `delivery` 或具体队列状态的组合。

优点：正常发送过程不会因新增投递类型或状态枚举而重新露出提示。

代价：引导消息交给当前回复的短暂过程不再单独显示；但消息正文已在时间线中，失败和不确定状态仍会接管。

## 实施结果

0. 2026-08-15 补充修复：不再以 `status === 'pending' && delivery !== 'steer_now'` 作为隐藏条件，改为只有失败、结果待确认和持久记录确认才允许渲染投递反馈。
1. 普通发送和引导投递的正常中间状态都不再渲染消息级投递反馈，中英文“正在发送消息 / Sending message”已经从生产组件移除。
2. 持久记录确认、发送失败和结果待确认继续使用既有反馈组件；任务首发“正在连接”与真实轮次状态保持不变。
3. 只调整 Renderer 可见反馈，不修改消息状态、队列、Provider 请求、幂等和失败恢复。
4. 领域词汇“发送中消息”已同步为：普通发送阶段不形成独立提示，其他真实状态继续表达。
5. 任务首发乐观消息从首次展示起就进入正式时间线；Provider 接管时不再从独立尾部分支迁移到另一套消息分支。
6. 用户消息 React key 改为稳定客户端消息身份；Provider 会话、轮次和条目 key 变化只更新消息数据，不再替换整条可见消息节点。
7. 快照、持久 submission 和 Provider 完成事件接管用户消息时，会按同一客户端消息身份保留尚未被权威负载替代的任务首发布局与附件展示；实时事件同时兼容 `clientId` 和 `clientUserMessageId`。
8. 领域词汇新增“首发消息可见身份”，明确本地提交、真实会话建立和 Provider 回放是同一界面消息节点。
