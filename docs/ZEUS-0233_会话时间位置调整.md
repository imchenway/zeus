# ZEUS-0233 会话时间位置调整

## 任务目标

把完成轮次的耗时从最终回复上方移回该轮底部，并使用独立按钮承担历史过程的展开与收起。

## 已核对事实

- `SessionTurnDuration` 当前同时显示“已处理……”并通过原生 `details / summary` 控制过程展开，两个产品语义被绑定在同一入口中。
- 活动轮次通过 CSS 调整顺序，使过程内容位于实时耗时上方；完成轮次恢复为耗时入口在过程和最终回复之前。
- 最终回复、计划等终态输出独立于过程分组渲染，因此仅调整原有耗时组件内部顺序无法把完成耗时放到最终输出之后。
- 普通会话页和任务会话抽屉共用 `ConversationTranscript`，本任务应在共享结构中一次修正。

## 已确认产品规则

1. 运行中保持“可读思考摘要和工作活动 → 实时轮次耗时”的顺序。
2. 完成且存在过程内容时，在原耗时入口位置显示“查看思考过程”按钮，最终输出显示在其后，固定轮次耗时显示在本轮最底部。
3. 用户展开后，顺序为“收起思考过程”按钮、过程内容、最终输出、固定轮次耗时。
4. 完成但没有可展示过程内容时，不显示空的展开按钮，只显示最终输出和底部耗时。
5. 失败或没有普通最终回复的轮次，轮次失败、变更等真实终态内容仍位于耗时之前，确保耗时是该轮视觉收尾。

优点：时间只表达处理时长，按钮只表达查看过程；最终回复成为完成轮次的阅读主体，历史过程仍可按需查看。

代价：完成轮次需要由会话时间线共同决定展开入口、终态输出和耗时的位置，不能继续由单个 `details` 包住全部内容。

## 领域口径

- “轮次耗时”是单次执行轮次的真实处理时长，不承担交互。
- “轮次过程展开入口”是完成后查看可读思考摘要和工作活动的独立按钮，不代表可以读取运行内核未公开的完整推理。
- 旧的“轮次耗时入口”同时承担两种语义，本任务不再使用该名称。

本项是可回退的会话展示与交互调整，不满足难以逆转的条件，因此不新增 ADR。

## 实现范围

- 将完成态过程展开从 `SessionTurnDuration` 拆为独立按钮组件。
- 活动轮次继续由耗时组件承载过程内容并把实时耗时放在过程末尾。
- 完成轮次由会话时间线在最后一个真实输出和轮次产物之后追加固定耗时。
- 保留中英文文案、键盘按钮语义、可见焦点和减少动态效果支持。
- 展开入口使用原生按钮，关联受控过程内容并同步展开状态；命中区不小于 `24px`。
- 不修改 Provider、Reducer、耗时算法、持久化协议、消息排序事实或滚动控制器。

## 实现结果

- `SessionTurnDuration` 只负责计算和展示轮次耗时；活动轮次仍把过程内容放在实时耗时上方。
- 新增独立 `SessionTurnProcessDisclosure`，完成且存在过程内容时显示“查看思考过程 / 收起思考过程”。
- 完成轮次的过程入口继续位于原红框位置；最终回复、计划、文件变更卡或失败卡按真实顺序展示后，轮次耗时作为该轮最后一项。
- 没有可展示过程内容时不会生成过程按钮。
- 展开按钮使用原生按钮、可见文字、`aria-expanded`、`aria-controls`、持久挂载的隐藏内容、可见焦点和 `24px` 最小命中高度；箭头动画在系统减少动态效果时关闭。
- 普通会话页和任务会话抽屉继续复用同一 `ConversationTranscript`，无需分别维护两套规则。
