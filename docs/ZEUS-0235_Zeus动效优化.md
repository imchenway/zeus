# ZEUS-0235 Zeus 动效优化

## 任务目标

改善会话消息、页面与组件切换时生硬、类似 PPT 跳切的观感，在不干扰长时间研发工作、不掩盖真实加载状态的前提下，建立克制且一致的 Zeus 动效语言。

## 当前阶段

设计与实现已完成。用户已确认全应用覆盖、明显接近 Codex、壳层稳定切换、动效接管和本轮直接实现；静态门禁、打包与隔离真机降级路径已验收。

## 用户原始反馈

- 现状：很多会话消息气泡、页面、组件间的切换非常死板，看起来像卡顿的 PPT 切换。
- 预期：为会话消息气泡、页面和组件的出场与切换增加适当的过渡与动效，可参考 Codex 的体验，由 Zeus 形成自己的设计。

## 已确认的代码事实

- Zeus 已有基础动效时长与缓动变量，并非完全没有动效。
- `WorkspaceDrawer` 已拥有进入、退出、遮罩和 reduced-motion 降级流程。
- 会话页已有标题、最新轮次、Markdown 内容块、图片、思考态和排队消息等局部动画。
- 当前动效分散在全局样式、交互原语和会话页样式中，尚未形成覆盖页面切换、内容增删与状态切换的统一分层规范。

## 已确认决策

### 首轮范围：全应用一次覆盖

用户选择首轮覆盖全应用。这里的“全应用”指全部高频可见状态变化与层级切换，不代表每个元素都必须播放入场动画：

- 覆盖项目主工作面、设置页、会话切换、消息与过程项、列表内容增删、抽屉、弹窗、浮层、折叠展开和异步状态反馈。
- 终端流、代码正文、差异内容、图谱拖拽等高密度连续更新区域默认不逐项播放空间动画，避免视觉噪音和渲染负担。

优点：一次形成完整、统一的产品感，页面与局部组件不会继续割裂。缺点：改动面和真实运行验收范围较大，必须依赖统一原语和分层规则，不能逐页随意补 CSS。

### 默认强度：明显接近 Codex

用户选择默认动效应明显接近 Codex 的可感知节奏：内容分块进入、页面状态连续变化、组件层级关系清楚。Zeus 仍排除弹跳、夸张缩放、长距离滑动和历史内容反复重播。

优点：能够显著消除当前硬切换和 PPT 跳页感，形成更完整的产品反馈。缺点：比极克制方案更容易产生视觉疲劳，必须按层级限制持续时间、触发频率和同时运动的元素数量。

### 页面模型：壳层稳定、内容编排

用户选择应用侧栏、项目工具条等方向锚点保持稳定，只让发生变化的工作面进入；抽屉、详情等更深层对象使用明确方向表达层级，不做整页交叉闪动或整页横向滑动。

优点：用户不会在导航时丢失位置，页面仍有明显的连续感。缺点：需要区分壳层、工作面和深层浮层，不能只给单一根节点套一个通用动画。

### 沿用既有会话内容规则

- 实时自然语言内容按现有自适应追赶规则分块显现。
- 完成答案和历史答案完整直出，不在每次打开会话时重播实时生成或逐项入场动画。
- 命令、文件、工具结果和其他高密度结构化内容直接更新，只在新对象首次形成时提供一次轻量状态反馈。

### 响应优先：新交互接管旧动效

用户快速连续切换页面或会话时，新内容立即挂载，正在执行的旧动效取消或从当前视觉状态衔接，不排队等待完整播放。

优点：动效不会引入操作延迟，快速导航仍然跟手。缺点：实现必须管理中断和卸载时机，不能只依赖一次性 CSS 入场动画。

### 本轮交付：设计并直接实现

用户要求本轮完成统一动效规范、全应用代码落地、项目静态门禁和真实 `Zeus Test.app` 运行验收，不拆成只交设计方案的前置轮次。

优点：设计与真实产品行为在同一轮闭环，能及时发现纸面方案与渲染现场的差异。缺点：任务范围较大，必须分层实施与旁路记录证据，不能以局部页面完成代替全应用覆盖。

### 验收边界

- 浅色、深色与跟随系统主题。
- 至少一个窄窗口断点。
- 键盘焦点和系统减少动态效果。
- 长会话、快速连续导航、列表增删与异步状态切换。
- 使用 `dev.hypha.zeus.test` 身份、独立用户数据目录的 `Zeus Test.app` 做真实运行检查；静态检查、构建和打包结果分别陈述。

## 动效设计

### 设计主张

Zeus 的方向锚点保持稳定，变化内容以“从环境中聚焦出来”的方式进入：透明度从低到高，工作面使用 8–10px 纵向位移，深层面板使用 10–14px 水平位移。避免弹跳、长距离滑动、模糊滤镜和大面积缩放。

### 时间层级

| 层级 | 时长 | 适用对象 | 优点 | 缺点与控制 |
| --- | ---: | --- | --- | --- |
| 即时反馈 | 120ms | hover、active、selected、状态色 | 跟手、不会拖慢操作 | 变化较轻，只用于已有对象状态 |
| 新对象进入 | 180ms | 新任务、新会话、实时内容块、局部提示 | 新增关系清楚，接近 Codex 分块节奏 | 只播放一次，历史恢复不重播 |
| 工作面切换 | 240ms | 任务、Git、源码、图谱、命令、会话、设置分类 | 明显消除硬切换，又不移动稳定壳层 | 快速切换时必须由新动效接管 |
| 层级浮层 | 220ms 进入；160–180ms 退出 | 弹窗、抽屉、菜单 | 清楚表达覆盖层级 | 不允许延迟焦点与数据；退出只在壳层可安全保留时播放 |

统一使用 expo 风格 ease-out `cubic-bezier(0.22, 1, 0.36, 1)`；退出采用更短的 ease-in。循环加载只允许旋转或低对比脉冲，不伪装真实进度。

### 场景矩阵

| 场景 | 进入 | 退出/切换 | 不应发生 |
| --- | --- | --- | --- |
| 项目主工作面 | 工作区 240ms 淡入 + 轻纵移 | 旧工作面立即卸载，新工作面接管 | 侧栏、顶部工具条整页飞走 |
| 源码/图谱/命令模式 | 当前模式面板 220–240ms 聚焦进入 | hidden 面板不播放离场 | 编辑器内容逐行飞入 |
| 设置分类 | 内容列 220ms 淡入 + 轻纵移 | 左侧设置导航保持稳定 | 整个设置窗口闪白 |
| 会话切换 | 目标会话工作面进入；未加载时保留既有正文与目标输入坞 | 新选择立即接管旧选择 | 历史消息逐条重播 |
| 实时消息与过程项 | 沿用现有语义分块显现 | 完成后保持稳定 | 打字机动画、路径逐字符增长 |
| 新任务/新会话 | 仅新 ID 行 180ms 进入 | 删除直接收敛；不阻塞列表 | 初次加载全部列表排队入场 |
| 弹窗 | 遮罩淡入，内容轻上移并微缩放收口 | 只有具备关闭保留态的壳层播放退出 | 焦点晚于动画到达 |
| 抽屉 | 沿用右侧位移与遮罩淡化，统一时间变量 | `animationend` 驱动卸载并有兜底 | 瞬时消失或整页横移 |
| 浮层/菜单 | 锚点方向的 140–160ms 淡入与轻缩放 | 120ms 收口 | 首帧尺寸跳动、触发器布局变化 |
| loading / error / empty | 局部状态 160–180ms 进入 | 不遮盖已有真实数据 | 用动画假装百分比或完成 |
| reduced-motion | 立即呈现最终状态 | 立即收敛 | transform、循环装饰、will-change |

### 实现结构

- 全局动效 token 与关键帧放入应用样式根层；交互原语只消费语义时长，不由业务页重写。
- 工作面依赖真实挂载/显示状态播放，不通过修改 React `key` 强制重建页面，避免丢失编辑器、滚动与会话本地状态。
- 新任务与新会话通过稳定 ID 集合识别，只给本次真实新增对象标记一次进入态。
- 弹窗补齐统一进入动效；现有抽屉和浮层保留可安全执行的退出生命周期。
- 不新增依赖，不引入另一套动画框架；会话既有 Framer Motion 只继续负责已经存在的连续分栏进度。

优点：变更集中、可审计，能覆盖全应用主要感知断点，同时保留真实状态和 React 局部现场。缺点：无法安全保留关闭态的旧业务弹窗仍以即时卸载为主，若未来要求所有弹窗完整退出，需要把 open/closing 生命周期统一上提到原语层。

## 实现结果

- 在交互原语层新增 120ms、180ms、240ms、220ms/170ms 四级语义时长及统一进出缓动，工作面、面板、对象、侧向层级和弹窗共享同一套关键帧。
- 项目任务、Git、项目设置、源码/图谱/命令模式、会话工作面、设置内容列、内联状态、批量栏、交互坞、浮层、折叠内容、弹窗与现有抽屉均接入相应层级。
- 新增稳定 ID 识别能力，仅给运行期新增的项目、任务、会话和会话内容标记一次进入态；首次读取历史列表和重新打开历史会话不逐项重播。
- 会话消息原有默认入场已改为显式新增态触发，最新消息的较明显进入效果也只在真实新增时播放。
- 快速导航继续即时替换内容，没有新增等待队列，也没有通过 React `key` 强制重建工作面，因此不会为动效丢失滚动、编辑器或局部表单状态。
- `prefers-reduced-motion: reduce` 下取消新增空间动画、变形与状态过渡，内容直接呈现最终状态。

优点：产品节奏从零散页面特效变为统一语言，真实新增和历史恢复的语义明确，且没有引入新运行依赖。缺点：本轮没有为所有旧业务弹窗补造关闭保留态，因此部分弹窗仍是“统一进入、即时退出”；如果后续要完整离场，需要逐个确认焦点恢复和卸载生命周期。

## 约束

- 动效只表达对象进入、退出、状态变化和层级关系，不伪装网络或模型进度。
- 减少动态效果模式下取消空间位移和循环装饰，仍保留可读的状态变化。
- 不复制外部品牌资源或实现源码；会话页仅在既有任务级例外范围内参考 Codex 的可见节奏。
- 不新增 Vitest、组件测试或 CSS 契约测试；后续验证使用项目规定的静态门禁与必要真实运行检查。
