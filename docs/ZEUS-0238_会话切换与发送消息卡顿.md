# ZEUS-0238 会话切换与发送消息卡顿

## 用户现场

- 每次点开会话时，消息区看起来都会重新加载，连续切换会话不流畅。
- 每次发送消息时，界面会短暂只显示用户消息，随后整段历史再次出现，产生明显闪烁。
- 用户目标不是美化加载动画，而是让已经显示过的真实会话正文保持连续稳定。

## 已核对的既有产品口径

- `CONTEXT.md` 已把“会话热缓存”定义为本次应用运行期间成功读取过的真实会话快照；切回会话时先展示缓存，再在后台读取权威状态校准。
- `ZEUS-000060` 已明确：后台校准可以继续，但不得在校准前清空已读取正文，也不得让切回会话表现成整页重新加载。
- `ZEUS-0224` 已明确：目标会话首次没有热缓存时保留上一会话正文；目标身份与历史就绪后再切换，不能用空白页代替过渡。
- 因此需要区分两个事实：后台重新核对权威快照是当前设计行为；用户看见正文重载或闪烁是缺陷。

## 当前代码事实

- 每个 `ConnectedSessionWorkspace` 控制器启动时都会连接事件流，并调用 `loadNativeConversation` 读取一次完整权威快照。
- 已查看会话可以从 `nativeConversationHotCacheRef` 取得真实热缓存；控制器会先用该状态构造消息区，再执行后台校准。
- 发送消息会先加入 Renderer 所有的乐观用户消息；服务端接受后，控制器再次读取完整会话快照，把乐观消息与持久消息对账。
- 快照水合会重建消息字典和顺序，再保留尚未出现持久身份的乐观消息；这条路径直接影响发送瞬间的正文稳定性。
- `ZEUS-0224` 新增的首次切换过渡使用两个会话工作面：旧正文工作面和目标输入工作面。目标就绪后再收为单一工作面；该生命周期需要继续核对是否产生控制器二次启动或投影短暂回退。
- 任务首发会话还保留一份只含首发现场的本地状态；权威控制器不可见时会回退显示这份状态。若控制器在普通发送过程中被重新判为不可见，就会出现“先只看到首发用户消息，再恢复全部历史”的现象。

## 已确认产品边界

- 命中热缓存后立即稳定显示真实正文，并继续执行静默后台校准；校准不得重建、清空、遮挡消息区或改变滚动位置。
- 发送时保留全部历史正文，新用户消息立即出现在底部，并按稳定消息身份从本地发送中状态原地交接为持久消息。
- 修复覆盖全部可继续发送的原生会话，包括项目会话、任务会话以及 Codex、Pi 共用的 Renderer 状态链路，不做单会话或单渠道特判。
- 真实发送失败继续保留失败消息、可读原因并恢复输入；不能用无条件清空输入或延迟显示消息掩盖错误。

## 精确根因

- `ConnectedSessionWorkspace` 直接把可选的 `controllerEnabled` 放进控制器身份依赖；首次切换过渡使用 `undefined`，过渡结束后的正式工作面传入 `true`，语义相同却会重建目标控制器并再次读取权威快照。
- 工作面只把 `transportState=ready` 视为权威控制器可见；后台连接、水合或重连期间即使已经持有完整快照，仍会回退到 `localState`。任务首发会话的 `localState` 只包含首发现场，因此会短暂只显示第一条用户消息。
- 快照对账会用 Provider item 身份替换乐观消息 key，同时为全部历史 item 创建新对象；同一条新用户消息会更换 DOM 身份，未变化的历史 Markdown 也会重新渲染。

## 方案取舍

- 采用控制器启用语义归一化、已有完整快照优先展示、用户消息稳定可见身份和未变化历史 item 引用复用。
- 优点：切换与发送都不再离开完整正文；后台校准、远程同步和失败恢复继续保留；新消息不重复、不换位。
- 代价：快照水合需要比较新旧 item 并复用等价对象，状态归并逻辑比简单整表替换更严格。
- 不采用完全跳过后台读取：虽然切换读取更少，但会引入远程回复、审批和宿主恢复状态过期问题。
- 不采用 CSS 遮挡、延迟显示或固定动画：它们只能隐藏闪烁，不能阻止控制器重建和历史 Markdown 重算。

## 实施结果

1. `controllerEnabled` 现在先归一为明确布尔语义；`undefined` 与 `true` 不再让同一目标会话在切换过渡结束时重建控制器或重复启动水合。
2. 控制器只要已经持有与当前会话匹配的完整快照，连接、后台水合、重连和失败提示期间都继续展示该快照；任务首发本地状态不再覆盖完整历史。
3. 用户消息按 `clientUserMessageId` 继承发送前的稳定可见 key；Codex 的 `clientId` 与 Pi 的 `clientUserMessageId` 都能原地匹配，Provider item 到达后只更新同一条消息，不更换气泡 DOM 身份。
4. 权威快照水合会比较新旧历史 item；内容、状态、资源和身份均未变化时复用原对象与消息顺序，等价快照不再增加正文 revision，历史 Markdown 不会因为后台校准整段重算。
5. 真实消息变化、远程消息、审批、运行状态和失败恢复仍按权威快照更新；本次没有取消后台校准，也没有削弱发送失败与结果不确定保护。
