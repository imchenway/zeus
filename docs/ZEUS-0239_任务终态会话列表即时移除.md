# ZEUS-0239 任务终态会话列表即时移除

## 当前阶段

实现、静态检查、整仓构建和测试身份打包已完成；受测试窗口首次落点约束，真实界面动效验收未执行。

## 用户现场

- 任务变成已完成或已取消后，左侧关联会话仍停留在列表中。
- 只有重新打开 Zeus 后，这些会话才会消失。
- 会话退出列表时需要明确但克制的动效。

## 已确认边界

1. 任务从非终态进入项目配置的完成或取消状态时，全部关联会话退出左侧活跃会话树。
2. 本窗口修改状态时选择后立即乐观移除，不等待本机请求完成。
3. 保存失败、版本冲突或用户取消终态清理确认时，会话带动效回到真实排序位置，并显示既有失败原因。
4. 当前正在查看的关联会话只从左侧树退出；主工作区保留完整历史并进入终态只读，不自动跳回任务详情。
5. 任务列表单项、批量状态修改、任务详情、会话标题和外部实时更新使用同一规则。
6. 多条会话同时在约 160ms 内淡出并收起，其他行平滑补位；减少动态效果开启时直接更新。
7. 任务详情继续展示归档关联会话，不受左侧活跃树收口影响。

## 领域口径

- “活跃会话树”只包含未归档会话，是导航集合，不是任务全部会话历史。
- “当前查看会话”是工作区当前对象，可以已经归档并处于只读状态。
- “任务终态”由项目任务状态配置承担完成和取消系统角色的状态决定，不能写死状态名称。

## 根因

- 任务会话历史接口为了支持终态详情，合并返回未归档和已归档记录。
- 左侧会话树直接复用该历史集合，没有再次按归档状态执行活跃成员资格判断。
- 任务终态清理直接把关联会话写为归档，只广播 `task.updated`；Renderer 的会话缓存没有随终态任务统一收口。
- 重启后重新读取权威快照才排除这些旧投影，因此表现为“重开 Zeus 才消失”。

## 实施设计

1. 从项目配置解析每个任务的完成和取消角色，把已确认终态任务与本窗口乐观终态任务组成会话树隐藏集合。
2. 左侧树同时排除显式归档会话和隐藏集合所属任务的会话；会话工作区继续保留独立的当前查看对象。
3. 统一任务管理状态保存入口负责开始乐观移除，并在取消、冲突或失败时撤销；批量和各单项入口自然复用该入口。
4. `task.updated` 实时刷新任务后，终态集合自动变化，从其他窗口或入口发生的状态变更也能收口。
5. 当前查看会话所属任务进入终态时保存为归档焦点，并把只读门禁前移到乐观阶段。
6. 会话树使用列表退出与布局补位动效，减少动态效果下禁用动画。

## 取舍

### 选择后立即乐观移除

- 优点：用户选择终态后立即得到明确反馈，慢清理不会让旧会话继续挂在列表里。
- 缺点：失败时必须恢复会话行，会出现一次可解释的回弹。

### 当前会话保留只读工作区

- 优点：列表事实即时正确，又不打断用户阅读历史。
- 缺点：当前只读工作区可能暂时没有对应的左侧选中行。

### 在列表模型统一收口

- 优点：单项、批量、会话标题和实时更新不需要分别补丁，历史接口仍可服务终态详情。
- 缺点：必须清楚区分导航集合与历史全集，不能继续把同一数组无条件复用于所有界面。

## 验收口径

- 任一入口把任务改为完成或取消后，关联会话无需重启 Zeus 即从左侧退出。
- 本窗口操作在状态选择后立即开始移除；失败或取消时会话恢复且原因可见。
- 当前会话内容不跳走，写入入口立即关闭；任务详情仍能打开归档历史。
- 外部终态事件到达后，同样触发列表退出。
- 动效为同时淡出、收起和补位；减少动态效果下没有位移与补间动画。
- `pnpm lint`、`pnpm typecheck`、`pnpm build` 与 `git diff --check` 分别记录，不把静态结果冒充真实界面验收。
