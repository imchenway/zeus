# ZEUS-0240 选项框与权限授权操作同行

## 任务目标

修复普通用户询问把“跳过 / 提交”单独放到底部一行、命令与文件权限请求把授权动作单独放到底部一行，以及分裂授权按钮文字段和箭头段高度不一致的问题。

## 已确认口径

- 普通用户询问的“上一个 / 跳过 / 继续或提交”统一称为行尾操作区。
- 权限请求的“拒绝 / 允许 / 授权范围”复用同一行尾操作规则。
- 行尾操作区在主窗口允许的全部宽度内始终与当前输入、最后一项答案、文件目标或命令内容同行，不响应式换到下一行。
- 操作按钮保持完整文字、既有键盘语义和不小于 `28px` 的命中高度；分裂授权按钮的文字段与箭头段使用同一固定高度。
- Zeus 主窗口最小宽度从 `360px` 调整为 `640px`。这是 macOS 逻辑宽度，兼容常见 12/13 英寸笔记本，并允许在 `1280px` 逻辑宽度屏幕上左右半屏使用。

## 方案与取舍

采用结构化同行布局，不用负边距或绝对定位把底部按钮视觉拖回上一行。输入、文件目标或命令预览使用可伸缩内容区，操作区固定在右侧；权限菜单仍以真实协议决定可用项，不改变允许范围。

优点：操作位置稳定，输入与决策对象形成一条清晰阅读线；询问和权限请求使用一致心智；分裂按钮不再出现高度错位。

代价：主窗口不能缩到 `640px` 以下；较长文件路径仍需单行省略，命令预览继续在自身内容区内处理长文本，不能挤压按钮。

## 验证记录

- 指定格式化范围通过 Prettier 检查，`pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac` 均成功；`windowState.ts` 只改动既有排版中的一个宽度常量，未机械重排整份旧文件。
- 打包产物为本任务的 `dist/test/mac-arm64/Zeus Test.app`，bundle ID 为 `dev.hypha.zeus.test`，`codesign --verify --deep --strict` 成功。
- 使用生产 `session.css` 和等价结构在 `640px` 窄宽页面复验：普通“其他”输入、无“其他”选项、密文自由输入的操作都与当前内容同行；文件和命令授权的“拒绝 / 允许一次 / 下拉箭头”同行，三个授权按钮均为 `28px` 高。
- 使用独立 `ZEUS_USER_DATA_DIR` 启动任务构建。预置 `360px` 历史窗口宽度后，真实主窗口恢复为 `640 × 560`；恢复日志为 `matchKind=exact-id`、`targetDisplayId=5`、`actualDisplayId=5`，首次出现于非主外接屏且无需二次纠正。
- 隔离资料中没有能自然触发真实 Agent 询问或授权的会话，因此本次没有把静态构建、窄宽页面复验或普通任务页截图描述成 Provider 端到端通过。真实请求的提交、键盘操作、深色主题仍待有可复现的 Provider 请求时补验。

静态检查、构建和打包成功只证明对应阶段，不代替真实 Electron 目标界面验收。
