# ZEUS-0241 顶部状态卡优化

## 任务信息

- 任务类型：优化
- 当前阶段：实现与验证完成
- 用户问题：菜单栏用量浮窗只在打开后等待数据刷新；“今日官方 Token”长期显示 0；用户已配置多个模型供应源，但浮窗只表达 Codex
- 安全边界：未修改 Git 历史或远端；未新增或恢复单元测试体系；真机只使用独立身份和独立数据目录

## 已核实的当前事实

1. 该界面的项目领域名称是“菜单栏用量浮窗”，不是窗口内顶部状态栏或代码编辑器状态栏。
2. Renderer 只读取 CodexUsageSummarySnapshot，本机服务接口是 /api/codex/usage-summary，公开类型的 providerId 固定为 codex。
3. DeepSeek、百炼、Kimi 和智谱等 OpenAI Chat Completions 兼容连接已可通过 Pi Agent 运行，但当前没有进入 Codex 专用量账本与菜单栏汇总。
4. 浮窗在首次挂载和每次获得焦点时请求摘要；官方用量请求会串联 Codex App Server 账户、usage 和 rate limits 读取。隐藏期间浮窗不主动订阅用量变化，因此用户点开后才触发慢刷新。
5. “今日官方 Token”从 Codex 官方 dailyUsageBuckets 中用本地日期做精确字符串匹配；只要官方返回了日桶数组、但其中没有与本地“今天”同名的桶，代码就显示 0。这会把“今日桶缺失或时区口径不一致”误表达为“今日确实用了 0”。
6. 当前同屏混合了三类不同事实：Codex 订阅配额、Codex 官方账户活动、Zeus 本机 Codex 会话估算。文案虽有“官方”和“仅 Zeus”，空间层级仍容易让人误以为是同一数据源。

## 同类产品调查事实

- CodexBar 按供应源展示会话、每周和每月窗口，并附重置倒计时；供应商公开时再展示积分、支出和本地成本扫描。多供应源使用切换，不把不同口径硬加总。
- Byte Pulse 顶部先切换 Claude、Codex、Cursor、Copilot 和 Gemini；主区展示当前窗口、每周窗口、重置时间与消耗节奏，辅以短趋势线、七日柱和 Token/费用表。
- Tally 明确区分个人订阅模式与 API 模式：前者关注限额窗口和重置时间，后者关注输入、输出、缓存 Token 与费用。
- Limit Bar 将菜单栏定位为“一眼判断是否还能开始下一次长任务”，只展示当前与每周两个窗口、余量和重置时间，后台刷新，供应源不可用时不猜数。

## 已确认决策

### 多供应源信息架构

菜单栏用量浮窗采用“全部 + 供应源切换式详情”。默认“全部”以逐供应源摘要列表同时展示已配置且可用的模型供应源；点击摘要行或切换到 Codex、DeepSeek、百炼等具体供应源后，主区展示该供应源的真实详情。不同供应源的配额、Token 或费用不硬加总。

优点：用户不筛选也能扫视全部供应源；不同供应源的数据口径可以保持诚实；单个详情的信息密度稳定；后续新增供应源无需把全部字段扩成更宽的对比表。

缺点：“全部”只能比较每家最关键的摘要，不能同时展开所有明细；切换入口和摘要行都需要表达数据可用、过期和异常状态。

“全部”摘要行固定表达供应源身份、最关键余量或本地用量、最近重置时间以及更新时间；点击行进入对应供应源详情。没有可比官方配额的 API 供应源必须明确显示本地统计口径，不用本地 Token 冒充订阅余额。

### 供应源详情字段

具体供应源详情按真实计量方式自适应：

- 订阅型供应源优先展示当前限额窗口、较长期限额窗口、剩余比例和重置时间；供应源确实公开积分或支出时才追加对应事实。
- API 型供应源优先展示 Zeus 本地今日 Token、近 7 日 Token、调用轮次、缓存命中率和估算费用；没有供应端账单 API 时必须标记为 Zeus 本地统计或估算。
- 供应源缺少某项事实时显示“不可用”或省略非关键项，不从另一种口径借数补位。

优点：Codex、DeepSeek、百炼等可以各自展示真正有决策价值的数据；不会让整齐的字段外观掩盖数据来源差异。

缺点：不同供应源详情结构不会完全一致；组件与接口必须支持能力驱动字段，而不是复用一张写死的 Codex 卡片。

### 数据刷新

采用事件驱动与 60 秒后台校准组合：

1. 每个供应源持久保存最近成功快照；菜单栏浮窗打开时立即显示快照，不等待网络或 Agent Runtime 启动。
2. Zeus 本地会话 Token、轮次和费用估算由真实用量事件立即更新快照。
3. 官方订阅限额或外部账户数据在后台最多每 60 秒校准一次；供应源主动事件到达时可以提前刷新。
4. 每个供应源独立合并并发请求、执行失败退避和限流处理；多个窗口不得各自启动重复轮询。
5. 刷新失败继续显示最近成功快照，并同时显示“更新于”与离线或过期状态；没有成功快照时才显示空态。

优点：打开浮窗可以秒显，日常用量变化接近实时；供应源短时故障不会让整个卡片退回加载态。

缺点：常驻应用会产生少量后台请求；多供应源需要独立的缓存、新鲜度和退避策略。

### 图表层级

三类图表全部保留，但按供应源能力和问题分层，不在每个供应源中强行堆满：

- 小圆环只表达当前供应源最紧迫的一项余量，作为快速风险信号。
- 横向进度条表达订阅型供应源的当前与较长期限额窗口，同时显示剩余比例和重置时间。
- 细折线表达消费节奏，例如相对稳定消耗速度是偏快、正常或偏慢；没有可证明的时间序列时不显示。
- 七日迷你柱状图表达 API 型供应源或 Zeus 本地统计的每日 Token / 费用变化；没有足够历史时展示真实空态，不补零柱。

优点：圆环、限额、节奏和每日趋势各自回答不同问题；信息丰富但不会把菜单栏浮窗做成完整统计后台。

缺点：不同供应源可见的图表组合会不同；折线需要明确基线和时间序列来源，不能仅用两个瞬时值猜测趋势。

### 估算点数

菜单栏用量浮窗移除“估算点数”。该值只是 Zeus 根据本地 Codex Token 和内置价格目录折算的理论 Credits 消耗，不是官方积分余额、真实扣费或剩余额度，放在快速摘要中容易造成误解。

供应源真实返回积分余额时，可以明确显示“官方积分余额”；Zeus 自行估算的 Credits 只允许留在完整统计页，并继续标注估算口径、价格日期和覆盖率。

优点：去掉低价值且容易误读的数字；官方余额与 Zeus 估算不再混淆。

缺点：用户无法在菜单栏浮窗快速查看理论 Credits 消耗，需要进入完整统计页。

### 估算费用

所有具体供应源详情保留费用估算，但字段统一改名为“近 7 日估算费用”，并明确标注“Zeus 本地估算”。它根据各供应源近 7 日的本地 Token 账本、实际模型和带日期价格目录分别计算；不在“全部”摘要中形成跨供应源费用总数。

没有匹配价格或费用覆盖率为零时显示“暂无价格”，不得显示 $0；部分 Token 可估价时需要在完整统计页继续展示费用覆盖率。

优点：用户可以在每个供应源详情中感知近 7 日理论成本；统一的时间范围有助于对比。

缺点：它不是供应源实际账单；Zeus 必须维护 Codex 之外各供应源的可信价格目录和历史费率快照。

### 今日 Token 口径

菜单栏供应源详情的主字段统一改为“今日 Zeus Token”，按本机当前日界线和该供应源已进入 Zeus 本地账本的真实 Token 汇总。它只覆盖 Zeus 内使用，不代表用户在其他客户端的账户总量。

Codex 等供应源若能提供日期口径可证明的官方日桶，可以另行显示“账户今日 Token”辅助项；当天桶缺失或时区无法证明时显示“不可用”，不得再将缺失强制回退为 0，也不得用今日 Zeus Token 冒充官方账户数据。

优点：所有供应源拥有一致、可解释的今日用量；修复当前假零问题；本地会话事件可以即时更新。

缺点：用户在其他客户端使用同一账户的 Token 不进入“今日 Zeus Token”；账户级今日总量只能在供应源提供可靠事实时补充。

### 缓存命中率

每个具体供应源详情固定保留“缓存命中率”字段。能够取得输入 Token 与缓存读取 Token 的供应源显示“缓存读取 Token ÷ 输入 Token”的真实比例；供应源或当前协议不提供缓存分类时显示“供应源未提供”，不得显示 0%。

“全部”摘要列表不展示缓存命中率，避免每行信息过载。

优点：供应源详情结构稳定；用户可以持续查看缓存效率信号。

缺点：部分供应源会长期显示“供应源未提供”，占用少量浮窗空间。

### 打开时的供应源选择

菜单栏用量浮窗记住用户上次明确选择的“全部”或具体供应源，下次打开直接恢复该视图。上次供应源已禁用、删除或不再可见时回退到“全部”，不按最近会话或最紧迫配额自动改选。

优点：高频查看同一供应源少一次操作；“全部”同样可以作为长期选择。

缺点：直接恢复具体供应源时不会先展示其他供应源摘要，需要依靠供应源切换入口表达其他供应源的异常状态。

### “全部”列表的供应源范围

“全部”只包含 Zeus 本地用量账本历史上曾记录至少一次真实 Token 的供应源。满足条件后持续显示，不因今日、近 7 日或近 30 日用量为零而自动消失；只配置、停用或仅有官方配额但从未在 Zeus 产生真实用量的供应源不进入日常总览。

优点：总览只保留用户真实使用过的供应源，列表稳定且噪音较少。

缺点：刚配置但尚未使用的供应源不可从“全部”总览发现；其连接和账户状态仍需在完整统计或设置中查看。

## 实现结果

### 数据链路

1. 新增统一的供应源用量摘要，只从本机用量账本发现供应源；Codex 与 `pi:连接 ID` 使用同一套逐供应源汇总结构，但保持订阅与 API 两种展示口径。
2. Pi SDK 每个助手消息返回的 input、output、cacheRead、cacheWrite 和 reasoning Token 在轮次结束时聚合写入账本；供应源 ID、连接 ID、模型、项目、会话和轮次身份完整保留。
3. 第三方供应源当前没有可信的 Zeus 价格目录，因此账本明确写入“无价格覆盖”，浮窗显示“暂无价格”，不把 SDK 中未配置价格产生的零费用冒充真实 $0。
4. Codex 官方日桶缺少本地当天日期时，摘要返回不可用，不再回退为 0。
5. Codex 官方配额由本地服务单例后台每 60 秒刷新并持久化最近成功快照；浮窗的统一摘要接口只读取缓存和本机账本，不再在打开路径等待 Codex Runtime 与官方接口。
6. Codex 或 Pi 用量事件到达后发布用量变化事件；浮窗订阅事件并静默重读摘要。并发读取在 Renderer 内合并，多个窗口不会重复发起同一轮读取。

### 浮窗界面

1. 顶部增加“全部 + 供应源”切换，并持久保存最后选择；供应源不可见时回退“全部”。
2. “全部”按供应源逐行展示，不计算跨供应源 Token、配额或费用总数；订阅行优先展示最紧迫余量，API 行展示今日本地 Token。
3. 订阅详情显示最紧迫余量圆环、各限额窗口进度条和重置时间；API 详情以今日 Zeus Token 为主指标。
4. 所有详情保留今日或七日 Token、缓存命中和七日估算费用的固定紧凑指标；没有缓存分类显示“供应源未提供”，没有价格显示“暂无价格”。
5. 有本地日桶时显示近七日迷你柱状图；没有真实日桶时显示空态。没有可证明时间序列，因此未伪造消费节奏折线。
6. 菜单栏已移除“估算点数”；只有供应源真实返回时才显示“官方积分余额”。
7. 最近成功摘要和最后选择保存在 Renderer 本地存储中，首次绘制即可显示；随后再静默读取本地服务新快照。
