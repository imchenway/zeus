# ZEUS-0242 全选与终端日志复制优化

## 任务目标

收紧 Zeus 普通界面的文字选择范围，避免用户在弹窗或工作区空白处触发整页文字选中；同时让命令中心的终端日志保留局部选择能力，并提供一键复制。

## 现状与代码事实

- 应用根容器没有定义通用的文字选择边界，Chromium 会把标题、字段标签、占位文字和按钮文字都当作普通网页文本，因此从空白处发起的全选会横跨整个弹窗。
- 当前只有少数局部交互区使用 `user-select: none`，未形成“应用界面不可选，正文与代码可选”的统一规则。
- 命令中心的 `CommandRunLog` 使用独立 `<pre class="command-run-log">` 展示终端日志，有自身滚动容器，但没有复制按钮，也没有明确限定选区语义。
- 命令中心为了避免无上限渲染，最多展示 2,000 条、4 MiB 的日志；超出部分依然保存在 Runtime 日志中。
- Runtime 设置抽屉已有“复制当前日志”能力，但命令中心的执行详情未复用这一交互。

## 正在确认的产品边界

- 无；用户已确认进入实现。

## 已确认决策

- 采用全应用统一的“界面文字选择边界”：普通界面、弹窗 chrome、工具栏、字段标签和按钮默认不可选；输入控件、会话正文、代码、差异和终端日志等真实内容区明确可选。
- 空白处不承担内容选择语义；从空白处发起的选择不应横跨整个 Zeus 界面。
- 终端日志的一键复制使用“本次运行完整日志”：复制该次运行到点击时已经持久化的全部内容，不受当前视口、前端分页和 4 MiB 展示预算影响。
- 复制文本使用与终端面板一致的可读输出，不附带每块时间和输出流前缀。
- 日志面板右上角常驻“复制全部日志”紧凑按钮，复制中、成功、失败与过大在原位反馈。
- 可读输出超过 32 MiB 时拒绝剪贴板写入，不截断、不伪造成功，引导使用完整日志导出。

## 实现设计

1. 在最后加载的原语层为 `.macos-ai-app` 和 body portal 根设置默认不可选，再为输入、`contenteditable`、保真正文、Markdown、代码、差异与日志设置显式可选。
2. 命令日志在鼠标松开时复验浏览器选区，把跨出日志容器的端点夹回正文边界；这是对 Chromium 尚未实现 `user-select: contain` 的产品侧补偿。
3. 在 Local Server 增加按命令运行身份读取完整日志的受信接口，从持久 Runtime 日志按序读取，不接受 Renderer 传入任意会话或文件路径。
4. 服务端以流式状态累加独立回车、换行与退格语义，最终文本超过 32 MiB 立即返回可识别的过大错误；不把巨型原日志一次性拼成中间字符串。
5. `CommandRunLog` 增加独立标题工具栏、原生复制按钮和 `aria-live` 状态；点击时才读取完整日志，不改变当前每秒轮询与展示组件。
6. 剪贴板优先使用 Electron 受信桥并核对写入结果，仅在桥不可用时回退 Web Clipboard API；任一路径失败都不显示已复制。

## 候选方向

### 方向 A：应用壳默认不可选，显式内容区恢复可选（推荐）

普通 chrome、弹窗、工具栏、标签和按钮不参与文字选择；输入控件、会话正文、代码、差异和终端日志等真正需要复制的区域显式恢复。

优点：语义接近 macOS 生产力应用，能从根上消除整页蓝色选区，又不丢失真正内容的复制能力。

代价：需要盘点并明确标记可选内容区，如果遗漏，某个正文区会暂时无法鼠标选文。

### 方向 B：只修创建任务弹窗和命令日志

优点：改动范围最小，对其他页面的既有选文行为影响少。

代价：同类的网页式整页选中仍会在其他弹窗和工作区出现，无法建立统一的 App 交互质感。
