# ZEUS-0243 快捷键交互逻辑

## 任务状态

- 当前阶段：实现与静态验证完成，真实快捷键 GUI 验收未完成；
- 用户于 2026-08-13 确认接受本文建议的关闭优先级；
- 截图中的界面定义为“应用主窗口内的附件预览模态层”，不是独立 macOS 窗口。

## 根因

- Electron 原生菜单把 `CommandOrControl+W` 显式绑定到“关闭”动作；
- 当前分流只识别会话右侧上下文工作面。右侧活动时关闭当前标签，否则直接调用当前 Electron 窗口的 `close()`；
- 附件预览是 Renderer 内的 HTML `dialog`，它只消费 `Escape` 产生的 `cancel` 事件，以及遮罩点击和右上角关闭按钮；
- 附件预览没有向 Main 进程上报“当前有可关闭的前台层”，也没有在 Renderer 内拦截 `Cmd+W`。因此按键会落到原生菜单的窗口关闭分支。

## 为什么看起来是“整个 Zeus 退出”

- `Cmd+W` 先关闭的是 Zeus 当前 macOS 窗口，不是附件预览层；
- 如果这是最后一个窗口，测试身份会直接进入应用退出；其他身份还会受“后台运行”设置影响；
- 所以用户感知为“关一张图，却把 Zeus 整个关了”。

## 已确认的交互决策

建议把 `Cmd+W` 定义为“关闭当前最前台的可关闭对象”，优先级为：

1. 最上层可关闭模态层；
2. 当前活动的会话右侧内容标签；
3. Zeus 当前 macOS 窗口。

优点：符合用户对“关闭当前所见内容”的预期，不会因为预览层是 HTML `dialog` 而暴露实现差异。

代价：需要统一管理应用内可关闭层的顺序，避免每个弹层分别监听同一快捷键而出现重复关闭。

该决策已获得用户确认。它是可回退的快捷键路由，不满足难以回退的架构决策条件，不新增 ADR。

## 实现设计

- Main 进程继续作为原生 `Cmd+W` 的唯一入口，避免 Renderer 与原生菜单同时处理一次按键；
- Renderer 只上报当前窗口是否存在最上层可关闭模态层，Main 按发送窗口复验并逐窗口保存；
- `Cmd+W` 命中模态层时，Main 只向该 Renderer 发送一次关闭意图，不再继续关闭右侧标签或窗口；
- 附件预览复用自身已有的关闭和焦点恢复链路，`Escape`、遮罩点击和右上角关闭行为不变；
- 模态活动状态在打开、关闭、组件卸载和窗口销毁时收敛，不把过期状态留给下一次 `Cmd+W`。

优点：原生菜单仍是单一快捷键入口，关闭次序可审计，且不会一次关闭多层。

代价：Main 与 Renderer 之间需要多一组受信 IPC 状态和关闭通知；共享 `ModalPortal` 和两个原生附件预览已接入，未来若新增不使用这两类原语的模态层，仍需显式注册。

## 实现结果

- 新增 Renderer 共享可关闭层注册表，按注册顺序只关闭最上层对象；
- `ModalPortal` 统一自动注册，覆盖现有创建、删除、推送、Git、权限、更新等模态层；
- 任务附件图片预览和任务推送补充附件图片预览使用原生 HTML `dialog`，已单独接入同一注册表；
- 模态层忙碌并禁止关闭时，`Cmd+W` 只被当前层消费且不执行关闭，不会穿透到右侧标签或窗口；
- Main 进程只接受已登记 Zeus 窗口的模态活动状态，窗口销毁时清理记录；
- 会话右侧标签的既有关闭路由和窗口未保存变更保护保持不变。
