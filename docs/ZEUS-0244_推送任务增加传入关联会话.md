# ZEUS-0244 推送任务增加传入关联会话

## 任务信息

- 任务类型：优化。
- 现状：推送任务弹窗在当前任务没有返回会话候选时直接隐藏“当前任务历史会话信息”，用户无法判断功能不存在、候选尚未产生，还是关联会话没有被正确读取。
- 预期：推送任务时固定展示当前任务关联会话入口，可以逐项选择当前任务的任何正常关联会话作为本次新会话上下文。

## 当前阶段

- 阶段：实现、静态检查、构建和测试身份打包已完成；真实关联会话 GUI 选择与 Provider 首发验收未执行。
- 已完成 `grilling` 与 `domain-modeling` 的澄清和确认流程。
- 已核对 `CONTEXT.md`、`DESIGN.md`、ZEUS-0185 主任务文档及当前能力快照、弹窗、提交复验和首发布局代码。

## 已确认产品边界

### 固定术语

本能力继续使用已有领域名称“当前任务历史会话信息”：用户在任务首发时从当前任务已经存在的会话中逐项选择会话 JSONL 文件路径；它只补充本次新会话的首条输入，不复用或改写历史会话，也不展开复制会话正文。

### 候选范围

- 当前任务正常关联的全部既有会话都进入候选。
- 包含仍在运行和已经归档的会话，不因会话阶段或归档状态增加业务门禁。
- 每条会话默认不选，由用户逐项选择；不增加全选和选择记忆。
- JSONL 路径不可用的会话继续显示，但禁止选择并说明真实原因。

优点：用户可以完整选择当前任务已有工作背景，且与父任务、关联任务的会话规则一致。

代价：运行中的 JSONL 仍可能继续追加；本能力冻结并传入的是经过复验的文件路径，不是提交时刻的内容副本。

### 空态呈现

- “当前任务历史会话信息”在推送弹窗中始终显示。
- 当前任务没有任何关联会话时，显示明确空态，不再直接隐藏整个入口。
- 空态说明此处会出现什么，以及需要先产生当前任务会话才会有候选。

优点：用户可以区分“当前没有候选”和“功能没有加载”，截图中的功能不可发现问题得到直接解决。

代价：没有历史会话的任务也会增加一个固定区块，弹窗纵向长度略有增加。

### 安全与发送边界

- Renderer 只提交所选会话 ID，不提交可直接信任的本机路径。
- Local Server 提交时重新校验会话仍归属于当前任务，并确认路径为真实、绝对、可读、非符号链接的普通 JSONL 文件。
- 所选路径进入当前任务首发布局的“当前任务历史会话信息”段，并把所在目录加入本轮只读资源根。
- 当前任务内容和有效字段附件继续自动发送，不增加“是否发送当前任务”开关。

优点：入口可用性提升不放宽现有本机资源边界，预览和实际 Provider 输入继续共用同一快照。

代价：会话文件在弹窗打开后失效时会阻止创建，并要求刷新后重新确认。

## 已核对代码事实

1. `resolveTaskPushCurrentConversationState` 已通过 `conversations.listAllByTask(task.id)` 按创建时间列出当前任务全部未归档和已归档会话。
2. 能力快照已经提供 `currentConversationOptions`，表单和提交请求已经携带 `currentConversationIds`。
3. Local Server 已按当前任务归属重新解析选择，并复验真实 JSONL 路径。
4. 预览、即时首发工作面、Provider 输入和持久用户消息已经共用包含 `conversationPaths` 的任务首发布局。
5. 当前直接可见的缺口是 `TaskPushCurrentConversationPicker` 在候选数组为空时返回 `null`，导致整个入口消失。

2. 增加中英文空态文案和对应的低噪音样式。
3. 保留现有逐项选择、不可用原因、提交复验和首发布局链路，不新建第二套协议。

## 实现记录

1. `TaskPushCurrentConversationPicker` 不再在候选为空时返回 `null`，因此“当前任务历史会话信息”成为推送弹窗中的固定区块。
2. 有候选时继续复用既有原生复选框逐项选择；运行中、已归档和不可用原因的展示规则不变。
3. 没有候选时显示中英文空态，说明当前任务尚无关联会话，以及会话建立后可以在这里选择为后续推送上下文。
4. 空态使用现有 Zeus 表面、边框和文字语义 token，并使用文字和状态语义表达，不依赖颜色传达结果。
5. 未修改 `currentConversationOptions`、`currentConversationIds`、服务端会话归属与 JSONL 复验、任务首发布局和 Provider 输入协议。
