# ZEUS-0245 代码交付页按文件分组多仓操作

## 任务目标

代码交付页以整条任务开发线的文件变化为主体，不再要求用户先选择一个仓库，才能查看文件并执行一次提交、合入或推送。

## 已确认的产品口径

### 文件主导的交付工作面

- 参考 IDEA 的提交窗口，把一条任务开发线中的变化文件放在同一棵树中，并按 Git 仓库分组。
- 仓库组和文件都提供勾选；打开页面时默认选中全部可交付仓库和未提交文件，用户可以取消本次不处理的范围。
- 点击文件直接查看该文件差异，不需要先切换仓库。
- “本机未提交”和“已提交成果”继续分开展示，避免把工作区干净误解成没有代码成果。

优点：用户以实际代码变化为中心审查，多仓任务不再反复切仓；默认全选符合常见提交窗口习惯。

代价：页面需要渐进读取多个仓库的真实文件清单；仓库数量和文件数量很多时，树的滚动与状态反馈必须保持清晰。

### 三个独立 Git 动作

- 保留“提交”“合入”“推送”三个独立按钮，不把远端写入隐藏在一键流程中。
- 提交作用于勾选的未提交文件；跨仓选择时，每个仓库分别产生本地提交。
- 合入作用于勾选的仓库组，把各自任务分支分别合入创建任务开发线时记录的来源分支。
- 推送作用于勾选且已经完成本地合入的仓库组，分别推送各自来源分支。
- 文件选择不能表达部分合入或部分推送；这两个动作始终以仓库分支和提交为边界。

优点：提交范围精确到文件，同时保留 Git 对合入与推送的真实边界；远端动作仍由用户显式触发。

代价：同一棵树同时承载文件级提交选择和仓库级交付选择，需要通过层级、按钮文案和状态说明避免误解。

### 非原子批量结果

- 多个独立 Git 仓库不伪装成跨仓原子事务。
- 每次批量动作逐仓返回成功、跳过和失败；成功仓库不因其他仓库失败而回滚，失败项允许保留现场后单独重试。
- 合入出现冲突时保留对应仓库的冲突现场，其他仓库的成功结果继续有效。

优点：符合真实 Git 能力，长任务可以保留已完成成果。

代价：用户可能面对部分完成状态，页面必须明确下一步，而不能只显示一个笼统失败提示。

## 实施范围

- 代码交付 Renderer：统一文件树、仓库与文件选择状态、跨仓差异定位、三个批量动作和逐仓结果。
- Local Server：优先复用现有逐仓提交、合入和来源分支推送接口及其真实 Git 复验，不降低安全门禁。
- 样式：交付窗口调整为文件树、差异和操作区三栏，保留独立原生窗口与小窗口降级。

## 安全与范围边界

- 不自动执行提交、合入或推送；每个动作仍由用户点击对应按钮触发。
- 不强制推送，不绕过远端分叉、提交变化、来源分支变化和冲突检查。
- 不创建或恢复 Vitest 等单元测试体系；验证使用格式检查、lint、typecheck、build、测试身份打包与必要真实运行。
- 不启动或修改生产身份 `Zeus.app`；真实运行只能使用当前任务产出的 `Zeus Test.app` 和独立用户数据目录。
- 未经用户明确要求，不执行本仓库的 git commit、push、merge 或 revert。

## 实现结果

- 代码交付左侧改为任务开发线下的统一文件树，先按任务分支、再按 Git 仓库组织文件；“本机未提交”和“已提交成果”展示整条开发线的总文件数。
- 可交付仓库和未提交文件首次读取后默认全选；仓库组复选框控制合入与推送范围，未提交文件复选框只控制提交范围。
- 点击任意仓库中的文件会切换真实工作区身份并读取对应文件差异，不再要求先进入仓库详情页。
- 提交、合入和推送保留为三个独立按钮：提交按所选文件逐仓创建提交；合入和推送按所选仓库分别执行。
- 每次跨仓动作显示逐仓成功、跳过、待处理和失败结果。已有冲突或本地同步现场的仓库不会重复发起合入，其他仓库仍可继续。
- 多仓详情读取使用并行请求并在页面中逐仓呈现加载或失败状态；派生计数、仓库索引和选择集合在 Renderer 内集中计算，避免在文件行中重复线性查找。
