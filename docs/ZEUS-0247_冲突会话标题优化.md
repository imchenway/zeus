# ZEUS-0247 冲突会话标题优化

## 任务目标

把冲突处理会话的展示标题统一为：

`冲突处理：<任务名称>`

当前标题包含任务分支和来源分支，侧栏宽度有限时会优先截断真正有辨识度的任务信息。

## 已核对事实

- 新冲突会话的持久标题由本机服务根据任务分支和来源分支拼接。
- 项目侧栏、会话页标题、项目搜索和归档会话列表共用 `conversationDisplayTitle` 生成展示标题。
- 旧数据中同时存在“冲突处理：……”与“本地合入：……”两类冲突会话标题。
- 会话所属任务的当前名称已经随会话列表和会话工作区数据提供，不需要从分支名反推任务名称。

## 已确认口径

- 新建冲突会话的持久标题写为“冲突处理：当前任务名称”。
- 新旧冲突会话在所有统一展示入口都使用“冲突处理：当前任务名称”。
- 任务名称修改后，展示标题随当前任务名称更新；不批量改写历史会话记录。
- 分支方向继续保留在冲突会话正文和代码交付上下文，不再塞入侧栏标题。
- 普通任务会话仍显示任务名称，不受本次变更影响。

优点：标题更短，冲突用途和所属任务一眼可辨；历史、新建、归档入口保持一致，任务改名后也不会继续显示旧名称。

代价：侧栏标题不再直接展示任务分支和来源分支；需要进入会话正文或代码交付页查看分支方向。

## 实施计划

1. 调整本机服务的新冲突会话标题生成规则，并保留旧标题识别能力。
2. 调整统一展示函数，把新旧冲突标题投影为当前任务名称。
3. 更新领域词汇和设计契约，执行格式、类型、静态检查、构建与差异检查。

## 验证边界

- 不新增或恢复单元测试、组件测试或 DOM/CSS 契约测试。
- 本任务不修改 Git 历史，不执行 commit、push、merge 或 revert。
- 静态检查和构建只证明代码门禁通过，不冒充真实 Electron 界面或 Provider 链路验收。

## 实施结果

- 新建冲突处理会话直接使用任务名称生成持久标题，不再接收分支名作为标题输入。
- 统一展示函数识别现行“冲突处理：”以及历史“本地合入：”前缀，并使用会话所属任务的当前名称生成展示标题。
- 项目侧栏、会话页标题、项目搜索和归档会话列表继续复用同一展示函数，因此无需分别维护文案规则。
- 本机服务继续精确识别各类历史分支标题，避免旧冲突会话在恢复执行目录时失去兼容性。
- 普通任务会话仍只显示当前任务名称；项目普通会话没有任务归属时继续显示自身标题。
