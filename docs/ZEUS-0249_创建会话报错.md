# ZEUS-0249 创建会话报错

## 当前阶段

- 已完成现场诊断、产品边界确认、代码修复、静态门禁、构建和独立测试包校验。
- 本任务不新增或恢复单元测试，不执行 Git commit、push、merge、revert。
- 真实 GUI 与 Provider 验收必须使用本任务 `Zeus Test.app`、独立用户数据目录和外接屏首次落点门禁；静态检查不能替代真实运行结论。

## 用户现象

任务“接入钉钉 CLI”选择直接目录模式后，首发工作面显示“会话创建失败”，详情称 app-server 未创建真实会话并建议检查连接。

## 现场证据

1. 生产只读数据库中已经存在精确会话 `conversation_37aa3bc2fbb468ce5bd6bc8a` 和首条提交 `conversation_submission_c852361543bd049c618ea937`，幂等请求已返回 HTTP 202 并持久接受。
2. 首条提交上下文为项目目录 `/Users/david/cckg`，且 `bypassConcurrency=true`，所以本次失败不是并发已满。
3. 提交在 Provider RPC 前进入 `paused/recovery_required`，真实错误为 `ZEUS_NATIVE_CONVERSATION_WORKTREE_UNAVAILABLE`；会话没有 Provider thread 或 turn。
4. 该任务明确选择直接目录模式，因此没有 `task_environments` 或 `task_workspaces` 是正常产品事实。
5. 服务端统一执行现场复验却要求所有任务会话必须拥有 workspace，错误地把直接目录模式当成 Worktree 丢失；Renderer 随后又把真实原因覆盖成连接类泛化错误。

## 已确认产品边界

- 直接目录模式使用所属项目当前真实 `localPath`，不创建也不要求任务环境、分支或 Worktree 记录。
- 直接目录或 Worktree 是会话生命周期内的明确执行现场身份，不能仅根据“是否缺记录”临时猜测。
- Worktree 模式继续要求精确环境和仓库工作区；缺失、越界或不可恢复时失败关闭，绝不回退项目根目录。
- 修复前已持久接受的直接目录首发，只在同时满足任务首发布局、无工作区身份、持久目录精确等于所属项目目录时兼容恢复。
- 原失败发生在 Provider RPC 前，用户点击重试时恢复原会话和原首条提交，不另建会话、不重复发送。

优点：直接目录恢复为真实可用能力，同时不削弱 Worktree 隔离；当前失败现场也能沿用原幂等身份恢复。

代价：执行现场模式需要随提交持久保存并在后续消息中延续；旧数据只能采用严格兼容条件识别，不能无条件放行所有缺少 workspace 的任务会话。

## 实施范围

1. 原生任务会话的持久执行上下文增加直接目录与 Worktree 模式身份，任务首发、代码审查、冲突处理、历史引用和本地 API 启动均显式传递对应语义。
2. 直接目录复验只接受所属项目当前存在的真实目录，并同步为会话 cwd 与可写根；Worktree 继续执行原有环境、目录边界、分支和恢复检查。
3. 会话执行根解析同步识别直接目录，不再把其资源打开与执行现场投影为空。
4. 对修复前这类 Provider RPC 尚未开始的直接目录失败，队列恢复允许把原提交重新排队；其他无线程且结果不确定的暂停状态继续拒绝自动重试。
5. 任务首发重试读取持久提交错误，只对上述安全失败调用原会话恢复，再读取真实 Provider 线程；其他原因展示真实错误，不再统一误导为连接失败。
