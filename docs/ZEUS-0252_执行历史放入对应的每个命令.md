# ZEUS-0252 执行历史放入对应的每个命令

## 目标

移除项目命令页底部混合所有命令的公共执行历史，把执行历史归还给对应命令，并通过居中弹窗查看完整记录与详情。

## 现状证据

- `CommandCenterPanel` 在命令定义列表下方渲染单一公共“执行历史”，不同命令的运行混在同一列表。
- 页面左侧选择执行记录，右侧展示状态、实际耗时、超时上限、退出码、终端日志、停止操作和产物。
- 项目接口已经返回执行记录的 `commandId` 与 `projectId`，可以基于真实归属筛选，不需要修改存储结构或伪造映射。
- 原命令中心设计契约要求执行历史内联展示，本任务明确覆盖该旧规则。

## 已确认产品口径

- 项目命令页移除底部公共执行历史。
- 每条命令增加独立的“执行历史”时钟按钮，不把整行或命令内容区变成隐含点击入口。
- 点击历史按钮打开居中弹窗，按“命令 + 当前项目”筛选执行记录。
- 弹窗保留现有完整布局：左侧执行记录，右侧状态、耗时、日志、停止和产物详情。
- 用户确认运行后自动打开该命令的历史弹窗，并选中新执行，继续实时展示日志。
- 全局命令在项目页只展示当前项目中的执行；全局设置页仍只维护定义，不提供跨项目历史汇总。

## 领域边界

- `命令执行` 是一次具体运行的持久快照。
- `命令执行历史` 是同一命令在当前项目中的多次命令执行集合。
- `执行详情` 只描述一条命令执行，不等同于执行历史。

## 方案取舍

### 采用方案

命令行使用独立历史按钮，历史与详情复用同一个 ModalPortal 弹窗，并继续使用既有项目执行记录接口在 Renderer 按 `commandId` 过滤。

优点：历史归属清楚，运行、编辑、删除与查看历史互不冲突；保留实时日志、停止和产物能力；不改数据库与服务端协议，修改范围最小。

缺点：命令行会增加一个操作按钮；全局设置页不能跨项目审计同一全局命令。

### 未采用方案

- 点击整行打开历史：命中范围大，但容易让用户误以为点击命令会直接运行。
- 弹窗只展示历史列表：界面更轻，但查看日志和产物需要额外层级。
- 跨项目汇总全局命令历史：审计范围更完整，但需要项目筛选、项目身份展示与新的信息架构，超出本任务。
