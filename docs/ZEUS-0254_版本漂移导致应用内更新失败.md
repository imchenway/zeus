# ZEUS-0254 版本漂移导致应用内更新失败

## 任务目标

让 Zeus 菜单中的更新入口与终端 Homebrew 升级使用同一条安装语义，在应用实际版本和 Homebrew 管理收据暂时漂移时安全收敛，并避免为更新增加冗余、耗时或低性能步骤。

## 现场结论

- 2026-08-13 诊断时，日常正式应用 `/Applications/Zeus.app` 和实际运行主进程为 `0.3.2`。
- Homebrew 管理收据仍为 `0.3.1`，公开 Cask 目标为 `0.3.3`。
- 现有应用更新入口在调用 Homebrew 下载前，强制要求应用实际版本与 Homebrew 收据版本相等，因此以 `app=0.3.2 cask=0.3.1` 失败。
- 终端 `brew upgrade --cask imchenway/tap/zeus` 直接使用 Homebrew 收据判断升级起点，所以显示 `0.3.1 → 0.3.3`；它与应用更新入口使用同一个底层安装工具，但没有经过 Zeus 的额外相等门禁。
- 当日终端升级完成后，应用包、Homebrew 收据和公开目标均已收敛为 `0.3.3`；新主进程来自 `/Applications/Zeus.app`。该结果证明当前 Cask 可以完成收敛，不证明 Zeus 的漂移恢复入口已经修复。

## 已确认产品规则

- “应用内升级”统一称为“Zeus 编排的 Homebrew 升级”，不设计第二套 App 替换方式。
- 已存在目标 Zeus Cask 收据时，应用实际版本与管理收据不同属于可恢复的安装版本漂移，不再直接报成“不是 Homebrew 管理”。
- 漂移恢复仍须复验当前日常正式应用的精确路径、bundle ID、应用版本、目标 Cask、公开清单和目标版本；身份或路径不一致时继续阻断。
- Homebrew 继续负责下载、替换 App 和写入管理收据；Zeus 负责用户决策、进度、安全校验、安装后收敛验证和精确重启。
- 安装成功必须以应用包版本、Homebrew 收据和公开目标版本三者一致为准。
- 完全没有 Zeus Homebrew 收据的手动 DMG 安装暂不自动接管，后续如需切换管理方式必须另行确认。

优点：终端和应用入口使用同一安装心智，部分升级或手动覆盖形成的收据漂移可以自动恢复，同时继续保护错误路径和错误身份。

代价：不能再用简单的版本字符串相等作为唯一前置门禁，需要明确区分可恢复漂移与真正的安装身份冲突。

## 性能事实与约束

- 当前准备阶段无条件执行一次 `brew update`，随后才读取 Cask；即使本机 Cask 已与公开清单一致，也会先承担一次可变时长的 Homebrew 更新。
- 当前约 159 MB 的 `0.3.3` 安装包在本机完整 SHA-256 读取约 `0.33` 秒，一次 `brew info` 约 `0.57` 秒。它们不是本次长时间等待的主要来源，网络下载和无条件 `brew update` 才是主要可变成本。
- 同一缓存安装包目前会在准备完成后和正式安装前重复执行完整摘要复验；需要在不降低产物完整性边界的前提下判断是否去重。
- 用户已明确要求：升级速度必须有保障，不得加入耗时、冗余或低性能步骤。
- 性能承诺必须区分可控本机开销与不可控网络下载；不能承诺固定下载时长，也不能用删减身份、摘要或安装后版本复验来伪造速度提升。

## 已确认性能口径

- 先读取本机 Cask，只有它与公开清单不一致时才执行 `brew update`。
- 保留下载完成后的一次独立 SHA-256 完整性复验；用户点击安装时，缓存文件设备、inode、大小、修改时间或状态变更时间任一改变才重新计算摘要。
- 命中有效缓存且本机 Cask 已对齐时不执行网络刷新，直接进入已准备状态；实际网络下载耗时只展示真实进度，不纳入固定时长承诺。
- Homebrew 自身的 `--require-sha` 安装校验继续保留，不能用减少安全复验伪造性能提升。
- 下载临时文件的大小轮询从每 `100ms` 一次降为每 `500ms` 一次；Homebrew 终端输出仍按事件实时解析，降低下载期间无必要的磁盘查询。

优点：正常缓存路径跳过网络刷新和重复整包读取，下载期间磁盘轮询量降低 80%，同时继续保留公开清单、Zeus 摘要和 Homebrew 摘要三层边界。

代价：本机 Cask 过期时会先读取一次本地信息，再执行必要的 `brew update`；缓存文件元数据被其他进程触碰后，即使字节未变也会重新读取整包摘要，这是安全优先的有界退化。

## 实现结果

- 更新准备阶段先以禁止自动刷新的 `brew info` 读取本机 Cask；版本、下载地址和 SHA-256 已与公开清单一致时跳过 `brew update`。
- Cask 失配时才刷新 Homebrew 信息，刷新后仍严格复验 Tap、目标版本、下载地址、摘要和 App 安装位置。
- 不再要求 Homebrew 管理收据版本等于当前 App 版本；只要收据存在，当前 App 的精确路径、bundle ID、短版本和构建版本均可信，就允许交给 Homebrew 收敛。
- 完全没有目标 Cask 收据时继续拒绝自动接管；Cask 指向其他 App 路径、当前 App 身份异常或公开清单不一致时继续阻断。
- 准备阶段完整校验缓存后保存文件身份；安装前文件无变化时不重复计算 SHA-256，发生变化时重新完整复验，不接受只看大小的缓存。
- 安装后继续要求 Homebrew 收据、目标 App 路径、bundle ID、短版本和构建版本全部等于公开目标版本，再交给原生辅助程序精确重启。
