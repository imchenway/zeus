# ZEUS-0261 菜单栏用量浮窗数据与主题修复

## 任务信息

- 任务类型：缺陷修复
- 当前阶段：实现与验证完成
- 用户现象：菜单栏用量浮窗长期停留在加载骨架，同时显示“暂时无法更新用量”；Zeus 主应用已经切到浅色，浮窗仍保持深色
- 关联历史：延续 `ZEUS-0241` 已确认的多供应源用量语义，不重新设计信息架构

## 已核实事实

1. 本任务对象的统一名称是“菜单栏用量浮窗”，不是主窗口顶部状态栏。
2. 浮窗首次读取失败且没有最近成功快照时，界面同时绘制错误提示和加载骨架，顶部仍显示“正在读取用量”，因此失败被误表达成持续加载。
3. 用量总览为了取得供应源名称，调用了会逐个读取 API Key 配置状态的模型连接接口；钥匙串读取失败或迟滞会拖累整份本地用量总览。
4. 浮窗外观只使用首次挂载时读取到的应用设置。应用外观变化后，Main 进程只通知代码交付窗口，没有通知已创建的菜单栏用量浮窗。
5. 当前生产执行宿主版本为 `0.2.38`；对统一 `/api/usage-overview` 路由返回 HTTP 404，而旧版 `/api/codex/usage-summary`、`/api/codex/usage-analytics?range=7d` 和 `/health` 均返回 HTTP 200。新版浮窗连接旧宿主是本次“完全出不来数据”的直接根因。

## 已确认产品语义

读取失败采用分层降级：

- 有最近成功快照时继续展示快照，并明确提示“上次成功结果”和可重试操作。
- 没有最近成功快照时直接展示明确失败态和重试操作，不再保留加载骨架。
- 用量总览只读取本地用量账本与非敏感连接元数据，不读取 API Key 或其他钥匙串凭据。
- 浮窗的浅色、深色、跟随系统设置与 Zeus 应用外观保持实时一致。
- 旧执行宿主缺少统一用量路由时，不强制终止正在执行的旧宿主；只读其已有 Codex 七日统计并明确标记“仅 Codex 兼容”，安全交接到新宿主后自动恢复全部已记录供应源。

优点：短暂故障不会清空仍有参考价值的数据；首次失败不会伪装成永久加载；打开用量浮窗不再触碰凭据；主应用与浮窗视觉语义一致；升级期间不打断旧宿主中的活动工作也能读取真实 Codex 数据。

缺点：最近成功快照可能已经过期，必须持续显示新鲜度；外观实时同步需要增加一条独立窗口通知链；旧宿主存活期间无法汇总它从未提供的第三方供应源，首次兼容读取需要约三秒。

## 实现结果

1. 统一用量服务改为读取模型连接的非敏感元数据，不再为了供应源名称读取钥匙串中的 API Key 状态。
2. Renderer 请求统一用量路由得到 404 时，读取旧宿主已有的 Codex 七日统计并规范化为用量总览；快照携带供应源覆盖范围，界面明确说明当前只覆盖 Codex。
3. 无最近成功用量快照且读取失败时，内容区展示明确失败说明和重试按钮；有快照时继续显示快照，并保留失败提示和新鲜度。
4. Main 在应用外观或语言变化后同步通知已创建的菜单栏用量浮窗；Renderer 即时切换浅色、深色或跟随系统外观。
5. 状态提示使用固定网格行承载，成功、兼容提示和失败提示增减时不会挤占主内容或底部操作区。

## 当前结论
