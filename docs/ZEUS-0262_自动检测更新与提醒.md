# ZEUS-0262 自动检测更新与提醒

## 任务目标

Zeus 自动发现公开稳定版更新。存在新版本时，应用内持续展示可操作的更新提示，并在更新包预取、校验完成后按现有桌面通知偏好提醒用户。安装与重启继续由用户明确决定。

## 已核对的现状

- macOS 应用菜单与设置页已经可以手动检查真实发布清单。
- `HomebrewUpdateController` 已编排检查、Homebrew 预取、校验、用户确认后安装和精确重启。
- 原生更新窗口是非阻断窗口；关闭窗口只隐藏界面，不取消后台预取。
- 更新包预取完成后已经具备桌面通知能力，但当前只有用户手动进入更新链路才会触发。
- 全局项目侧栏底部当前只有“设置”入口，适合承载跨页面持续可见的软件更新状态。
- 当前本机 Codex App 使用 Sparkle，实测自动检查间隔为 `86400` 秒；OpenAI 官方文档没有公开这一间隔。Zeus 因当前发布频率更高，用户明确选择更短周期。

## 用户确认的产品边界

1. 自动更新检查始终开启，不提供关闭开关。
2. 自动检查间隔为一小时。下次检查时间以上次完成检查的时间加一小时计算；频繁重启不重复请求，睡眠错过时恢复后补查一次。
3. 用户手动检查成功后重新计算自动检查周期，避免紧接着重复自动请求。
4. 自动检查只读取轻量发布清单；发现新版本后才自动进入 Homebrew 更新预取。
5. 发现新版本后，全局侧栏底部在“设置”上方立即出现独立更新行，持续表达发现新版、下载中、下载失败和等待重启。
6. 点击更新行恢复现有非阻断原生更新窗口，不新增第二套下载、安装或重启界面。
7. 只对明确的临时下载错误额外自动重试两次，间隔为一分钟和五分钟；Homebrew 缺失、Cask 归属错误、校验失败等结构性错误立即停止。
8. 安装永远由用户点击“立即重启”触发，安装失败不自动重试。
9. 更新预取和校验完成后只发送一次系统通知；通知仅在 Zeus 不处于前台且现有桌面通知总开关开启时发送。
10. “稍后”只关闭原生窗口，不清除更新提醒；提示持续保留到完成升级。
11. 正式应用默认运行自动调度。`Zeus Test.app` 只有在显式测试更新源开启时才运行，禁止测试身份误碰生产 Cask。

## 方案设计

### 更新状态事实

Main 进程维护单一更新调度与 Homebrew 任务，向受信 Renderer 只投影用户可见状态：

- `idle`：当前没有需要提示的更新。
- `available`：已确认新版本，准备进入预取。
- `preparing`：正在更新 Homebrew 信息、下载或校验。
- `ready`：更新已经预取并校验，等待用户决定重启。
- `failed`：自动预取停止，保留可读原因与手动重试入口。

状态必须携带当前版本、目标版本、阶段说明和更新时间。Renderer 不自行读取发布源、运行 Homebrew或推断版本。

### 调度与节流

- 应用完成启动后异步判断是否到期，不阻塞主窗口和执行宿主恢复。
- 自动检查完成时间持久化到当前 Zeus 用户数据目录，跨重启继续节流。
- 应用持续运行时按到期时间调度；从睡眠恢复后如果已经到期，只补一次检查。
- 同一时刻只允许一个检查、预取或安装操作，手动入口复用同一控制器。
- 同一目标版本的预取完成通知持久去重，应用重启和状态恢复不得重复通知。

### 应用内提示

- 更新行位于全局侧栏底部、“设置”上方，使用原生 `button`，整行可点击。
- 图标只作辅助，状态名称和目标版本使用可见文字表达，禁止只用颜色或圆点表达。
- 更新阶段变化使用礼貌级动态播报；按钮保持不小于 24×24 CSS 像素的命中区、可见键盘焦点和明确可访问名称。
- 浅色、深色、跟随系统、窄窗口和减少动态效果复用现有 Zeus 语义样式。

### 失败边界

- 临时下载错误允许受控重试；重试等待期间更新行展示真实等待状态。
- 结构性错误、完整性校验失败和安装失败不进入后台循环。
- 自动检查失败不弹系统通知，也不打断当前工作；用户手动检查继续通过原生窗口展示真实失败。
- 任一失败都不得替换当前 App、自动打开下载页或退出 Zeus。

## 方案优缺点

### 优点

- 高频发布平均约半小时被发现，不依赖用户记得打开设置或菜单。
- 更新状态跨页面持续可见，系统通知被关闭或清除后仍有应用内入口。
- 自动预取减少用户决定重启后的等待时间，安装仍保留明确确认。
- 自动和手动路径共用同一发布事实、Homebrew 任务与原生窗口，不产生两套状态。

### 缺点

- 始终开启意味着用户无法关闭每小时发布清单请求和发现新版后的后台下载，在计费网络或磁盘紧张环境中控制较弱。
- 高频检查每天最多产生二十四次轻量请求。
- Homebrew 不可用或当前正式 App 不归指定 Cask 管理时，更新提醒会进入失败状态，需要用户处理环境问题。
- Main、Renderer、持久状态与原生窗口必须保持一致，状态恢复复杂度高于纯手动检查。

## 实施结果

1. 新增 Main 进程自动更新调度器。正式应用启动十五秒后判断是否到期，此后以上次完成时间加一小时调度；系统从睡眠恢复时只在到期后补查。
2. 调度状态原子持久化到 Zeus 数据根的更新目录，记录上次完成时间、当前提示、同版本通知去重和停止自动预取的失败版本；频繁重启不会重复检查。
3. 自动检查发现新版后复用唯一 `HomebrewUpdateController` 后台预取。明确的网络中断、限流、服务端暂时错误和超时按一分钟、五分钟重试；结构性错误、校验失败与安装失败不循环。
4. 预取完成后，只有 Zeus 不在前台、现有桌面通知开关开启且系统支持通知时才推送；没有真正发送通知时不错误登记为已通知，后续到期检查仍可补发。
5. Main 通过受信窗口 IPC 投影提示状态。Renderer 在全局侧栏“设置”上方显示独立可点击更新行，覆盖发现新版、下载中、等待重试、下载失败和等待重启；点击恢复现有原生更新窗口。
6. 更新行具备可见文字、目标版本、完整可访问名称、礼貌级状态播报、键盘焦点和减少动态效果降级，不以颜色作为唯一状态信息。
7. 设置页手动检查成功后通知 Main 重置一小时调度时钟；菜单更新、自动检查、后台预取、重试、安装和重启继续由同一控制器串行化。
8. `Zeus Test.app` 默认不运行自动调度；只有显式开启隔离测试更新源时，才接受测试清单、测试 Homebrew 替身和缩短的测试调度参数。

- `pnpm install --frozen-lockfile --offline`：通过，锁文件未修改；安装时只有尚未构建的工作区 CLI 软链接提示，后续完整构建通过。

- 产物身份复核：`CFBundleDisplayName=Zeus Test`，`CFBundleIdentifier=dev.hypha.zeus.test`。

### 隔离后台链路

- 使用独立数据根、本机回环发布清单、系统临时目录内的 Homebrew 替身和一秒测试首查间隔启动本任务测试包，没有读取生产发布源或生产 Cask。
- 回环服务只收到一次 `GET /manifest.json`；持久状态记录 `lastCheckCompletedAt`，确认调度完成一次后按完成时间节流。
- Homebrew 替身返回目标版本 `0.3.4`，隔离缓存中的十七字节产物通过大小和 SHA-256 复验；持久提示终态为 `ready`、进度为 `1`、目标版本为 `0.3.4`。
- 实例正常关闭后执行宿主日志记录 `final_quit`，没有触发安装、替换 App、正式身份重启或 Provider 登录。
- 隔离数据、回环清单和 Homebrew 替身已整体移入废纸篓 `/Users/david/.Trash/zeus-0262-gui-20260813-174200`，仍可恢复。

### 真实 GUI 缺口

- 当前主外接屏 ID 为 `3`，另有非主外接竖屏 ID `5`。首次启动前误把窗口状态写在数据根，而应用实际从 `profile/electron/main-window-state.json` 读取，导致日志明确显示 `matchKind=first-launch`、`targetDisplayId=3`、`actualDisplayId=3`。
- 发现首帧落到主屏后已立即终止本任务实例，没有继续读取、点击或截图界面，也没有再次启动。按项目护栏，本任务不宣称侧栏提示、原生窗口恢复和系统通知已完成真实 GUI 验收。
