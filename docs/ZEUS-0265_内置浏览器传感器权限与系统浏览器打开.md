# ZEUS-0265 内置浏览器传感器权限与系统浏览器打开

## 任务背景

用户在 Zeus 内置浏览器打开阿里云帮助页时看到“Allow sensors?”审批卡，只有“拒绝”和“允许一次”，并指出按住 `Cmd` 点击网页链接时应使用 macOS 系统默认浏览器打开。

## 2026-08-13 现状核对

- `BrowserHost.configureSession()` 把网页申请的所有浏览器权限统一转成 `web_permission` 审批；允许结果只写入当前进程内存，应用重启后不会保留。
- `BrowserWorkspace` 对 `web_permission` 只展示“拒绝”和“允许一次”，所以用户无法形成稳定的站点选择。
- 当前网页新窗口请求由 `setWindowOpenHandler()` 无条件改成 Zeus 新标签，没有区分 `Cmd` 修饰键或浏览器打开意图。
- Agent 访问站点与网页访问设备能力是两类不同权限。前者已有按站点持久允许与阻止；后者不应复用 Agent 站点授权。

## Codex 对照证据

- [OpenAI Browser 文档](https://learn.chatgpt.com/docs/browser)说明：Agent 首次访问站点默认询问，允许与阻止站点可在浏览器设置中管理；提交信息、购买、修改权限等高影响动作另行确认。
- 本机已安装 ChatGPT/Codex 桌面应用 `26.803.61601`（bundle ID `com.openai.codex`）的发行代码显示：其内置浏览器会话只允许安全剪贴板写入权限，其他网页权限直接拒绝。因此 `sensors` 在当前 Codex 实现中不会形成用户审批卡。
- 官方文档没有承诺网页传感器权限的内部策略；本任务把本机发行包视为当前产品行为证据，不把它扩大解释为长期公开契约。

## 已确认领域边界

“内置浏览器传感器边界”指网页仍可正常打开、阅读、滚动、登录和批注，但拿不到设备方向、加速度、陀螺仪或环境光等传感器数据。它不等于禁止访问站点，也不等于 Agent 的站点访问授权。

用户已确认与 Codex 对齐：Zeus 对 `sensors` 直接拒绝、不提示、不提供按站点例外。确实依赖传感器的网页改用系统默认浏览器。

优点：消除无业务价值的重复打断，保持最小授权，并与当前 Codex 行为一致。

缺点：依赖设备姿态或环境光的网页在 Zeus 内置浏览器中功能不完整，需要转到系统浏览器。

用户已确认系统浏览器修饰点击规则：网页正文中的 HTTP(S) 链接普通点击继续在 Zeus 打开；按住 `Cmd` 点击时，目标地址交给 macOS 当前默认浏览器，Zeus 当前页不跳转。该规则不指定 Safari、Chrome 等具体应用，也不扩展到 `mailto:`、`javascript:`、文件地址、中键或 `Shift + 点击`。

优点：保留 Zeus 内置浏览器的连续浏览和批注现场，同时提供符合 macOS 使用习惯的明确外部打开入口。

缺点：外部页面脱离当前 Zeus 会话和 Agent 可见浏览现场；用户若要继续让 Agent 操作该页面，需要回到 Zeus 内置浏览器。

## 待确认

- 无。用户已确认双方形成完整共同理解，任务于 2026-08-14 进入实现阶段。

## 实现阶段

- 只把 `sensors` 从通用网页权限审批中分流为静默拒绝；摄像头、麦克风、定位等其他权限继续使用既有审批。
- 网页预加载层只识别鼠标左键加 `Cmd` 的 HTTP(S) 链接意图，并立即阻止 Zeus 页内导航；Main 进程重新解析、校验 URL 后才交给 macOS 默认浏览器。
- 只有 Chromium 标记为真实用户输入的点击事件才允许触发系统浏览器；网页脚本构造的伪 `Cmd` 点击不能冒充用户操作。
- 普通链接点击与网页自身的新窗口请求继续使用 Zeus 内置浏览器标签。
- 不扩展到中键、`Shift + 点击`、`mailto:`、文件或脚本地址。
- Electron 运行时会把该权限报告为 `sensors`，但当前 Electron 42 TypeScript 联合类型没有列出该值；实现按运行时字符串精确比较，不扩大其他权限范围。

## 验证记录

### 静态门禁与构建

- 新 worktree 缺少依赖时执行 `pnpm install --frozen-lockfile --offline`，安装通过且未修改锁文件。
- `pnpm lint`、`pnpm typecheck`、`pnpm build` 均通过；Vite 仅保留已有的大分块提示。
- 首次构建发现 Electron 42 的 TypeScript 权限联合类型没有 `sensors`，因此按运行时字符串精确比较；修正后构建通过。
- `pnpm package:mac` 通过，生成独立身份 `Zeus Test.app`；`CFBundleIdentifier` 为 `dev.hypha.zeus.test`，签名指定要求校验通过。

### 真实 GUI

- 只启动本任务 `dist/test/mac-arm64/Zeus Test.app`，使用独立 `ZEUS_USER_DATA_DIR`；启动日志确认窗口首次落在非主外接显示器 `displayId=5`，没有启动或替换生产 `Zeus.app`。
- 在本机回环验收页实际调用加速度计和陀螺仪：页面显示 `accelerometer: denied`、`gyroscope: denied`、`sensor: NotAllowedError`，界面未出现传感器审批卡，证明传感器拒绝不会打断浏览。
- 自动化曾用网页脚本构造 `metaKey=true` 点击验证外部打开链路，结果确实打开系统默认 Chrome 且 Zeus 原页不跳转；这同时暴露了伪事件冒充用户的问题，因此最终实现增加 `isTrusted` 门禁。
- 重新打包并启动最终 `Zeus Test.app` 后，再次发送同一伪点击：页面确认事件已发送，Zeus 仍停留原页，本机服务只收到 Zeus 对原页的请求，没有 `/target` 请求，也没有再打开系统浏览器，证明最终包已拒绝网页脚本冒充用户操作。
- 当前本机界面自动化只能发送按键组合或鼠标点击，不能保持 `Cmd` 按下同时发出物理左键点击。因此最终物理 `Cmd + 左键` 仍需人工复核，不能把等价事件或静态检查冒充为该项真实 GUI 通过。
