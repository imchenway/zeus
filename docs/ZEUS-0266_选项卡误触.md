# ZEUS-0266 选项卡误触

## 任务目标

修复用户正在普通会话输入框打字时，普通用户询问突然出现并聚焦第一个答案，后续空格被原生按钮解释为点击、从而误选并提交首项的问题。

## 现状与根因

- 阻塞式普通用户询问出现时，底部普通会话输入框会被专用交互区替换。
- `RequestUserInputPanel` 首次挂载后会自动聚焦第一个预设答案。
- 预设答案使用原生 `button`。浏览器会把聚焦按钮上的空格解释为激活操作，因此用户连续输入的后续空格可能点击首项。
- 旧的 ZEUS-0082 修复只隔离了询问内部自由输入控件中的按键冒泡，没有覆盖“普通会话输入中途异步出现询问”的焦点切换时序。

## 已确认的产品口径

- 询问首次出现后保留固定一秒答案快捷键保护期；期间所有答题快捷键都不选择、不提交，也不在保护期结束后补发。
- 保护期结束后，只有无修饰键的 `1`、`2`、`3` 直接提交对应预设答案。
- 上下方向键移动答案焦点，Enter 提交当前聚焦答案。
- 空格、字母、标点和其他按键聚焦在预设答案上时不选择、不提交；原生按钮的空格激活必须被显式阻止。
- Tab 继续移动焦点；Escape 继续只在询问自由输入状态中安全退出编辑并保留草稿。
- 文字输入控件中的空格和普通字符继续正常编辑，不受预设答案白名单限制。
- 鼠标点击是明确选择，从卡片出现起立即有效，不等待一秒。
- 卡片继续自动聚焦第一个答案，不调整询问协议、回答内容、提交忙碌态或自由输入行为。

## 方案取舍

优点：

- 空格不再利用原生按钮默认行为误选首项。
- 数字、方向键和 Enter 在异步切换瞬间都有一秒缓冲。
- 保留数字直提、方向键导航、Enter 确认、Tab 可达和鼠标即时操作。
- 只修改预设答案的键盘边界，不影响询问自由输入和 Provider 协议。

代价：

- 固定一秒是时间保护，不是用户意图证明；持续输入超过一秒后再按 `1`、`2`、`3` 仍可能直接提交。
- 想立即用键盘回答的用户需要等待一秒；鼠标用户不受影响。
- 仅 `1`、`2`、`3` 保留数字直提，更多答案不再通过数字键直接选择。
