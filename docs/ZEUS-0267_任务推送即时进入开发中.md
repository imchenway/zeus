# ZEUS-0267 任务推送即时进入开发中

## 任务目标

用户确认任务推送后，处于项目默认状态的任务和新会话从第一帧起直接位于项目“推送后状态”（默认显示“开发中”），不再先创建“待开始”分组、随后跨组跳动。

## 根因

- Renderer 会先创建本地首发工作面和侧边栏会话行，再异步等待真实会话结果。
- 会话分组读取任务当前管理状态，因此待开始任务的本地会话行首次出现时仍在“待开始”。
- 即使服务端稍后更新状态，实时事件也只能让会话再次移动到“开发中”，无法消除第一帧跳动。

## 当前规则

1. 只有任务仍处于项目默认状态时，确认推送才进入项目推送后状态；默认配置对应“待开始 → 开发中”。
2. 测试中、待验收、阻塞、已完成、已取消和项目自定义的其他状态保持原值，不自动回退或重开。
3. Renderer 在插入本地首发会话前投影推送后状态，任务列表、任务详情、会话标题和侧边栏分组读取同一投影。
4. Local Server 在现有任务推送请求中持久化状态，不新增任务推送专用接口，也不增加后台状态同步重试。
5. 服务端写入前重新读取任务；如果用户在推送准备期间已修改状态，不覆盖人工选择。
6. 状态变化记录任务事件、审计和 `task.updated` 实时事件，使本地投影最终收敛为持久事实。
7. 开发中表达用户已经确认开工，不证明 Provider 首轮成功；会话创建失败继续由当前会话工作面表达，任务状态不自动回滚。

## 方案取舍

采用“同一推送请求持久化 + Renderer 首帧投影”。

- 优点：侧边栏不会短暂创建“待开始”分组，所有可见状态入口即时一致；不依赖旧执行宿主可能缺少的附属路由。
- 缺点：Provider 随后失败时任务仍保持开发中，需要用户根据实际计划决定是否手动调整状态。

不恢复独立状态同步接口、后台重试和“状态未同步”警告。

- 优点：会话创建只有一个权威请求，升级兼容面和失败组合更小。
- 缺点：状态持久化与任务推送共用服务端链路，无法作为独立动作单独重试。

## 实现范围

- `apps/desktop/src/renderer/App.tsx`：对仍处于默认状态的首发任务投影项目推送后状态，并供任务列表、会话标题、任务详情和侧边栏分组复用。
- `packages/local-server/src/index.ts`：在任务推送准备完成、Provider 创建开始前持久化“默认状态 → 推送后状态”，记录事件、审计并广播实时更新。
- `CONTEXT.md`、`DESIGN.md`：恢复并收敛当前任务推送状态语义。
