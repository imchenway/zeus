# ZEUS-0269 新任务首次附件预览修复

## 任务状态

- 当前阶段：已完成实现与真实界面验收；
- 问题对象：新任务创建成功后自动打开的第一次任务详情；
- 用户已确认：加载中需要显示真实进度并自动出图，真实失败需要显示脱敏原因并可原位重试；
- 安全边界：继续只读取 Zeus 任务附件受信目录，不放宽任意本机路径或 `file://`，不修改模型发送协议。

## 现象

新任务创建弹窗中图片可以正常预览；创建成功后自动打开任务详情时，图片缩略图退化为文件图标，点击放大后显示“无法预览”。关闭整个任务详情并重新打开，同一图片又可以正常查看。

本任务统一称该状态为“任务详情首次附件预览失败”。不能称为“任务附件不可用”，因为附件已经保存并关联成功，重新打开后也可以读取。

## 已核对事实

- 本次附件位于 `/Users/david/.zeus/artifacts/task-attachments` 受信目录；
- 文件是可读取的 `880×306` PNG，大小 `23,425` 字节；
- 数据库已保存附件路径、名称、图片类型、字段归属、MIME 和大小；
- 创建弹窗使用当前内存中的 `data:image/...` 即时预览；
- 持久化时主动剔除即时预览，只保存资源元数据，避免把大段 base64 写进任务 JSON；
- 任务详情通过 Main 进程的任务附件预览入口按受信路径重新读取图片；重新打开详情可以成功，证明路径校验和预览入口可用。

## 根因

`TaskAttachmentPreviewList` 的预览 effect 同时依赖整个 `props`、已加载集合、加载中集合和失败集合。第一次任务详情挂载后，组件发起图片回读并把路径加入加载中集合；该状态更新以及创建流程后续的父级状态变化会立即清理 effect，把本次请求标记为取消。

请求成功返回后因为已取消而被丢弃，`finally` 也不会移除加载中标记，所以当前详情实例始终没有可用图片源。关闭详情会卸载这份错误状态；重新打开后的组件实例处于稳定流程，因而可以成功显示。

## 已确认方案

1. 预览请求只由图片资源身份和预览入口可用性驱动，不再依赖整个 `props` 或请求自身更新的状态集合；
2. 普通父级重渲染不得取消仍然有效的图片回读，只在组件卸载或同一路径被新一轮重试替代时丢弃旧结果；
3. 放大层在图片仍在读取时显示“正在加载图片预览”，成功后原位切换为真实图片；
4. 预览入口返回不可用或读取抛错时显示脱敏、可行动的失败说明，并提供原位重试；
5. 继续由 Main 进程复验路径属于任务附件受信目录，不把任意本机路径交给 Renderer。

优点：第一次打开与重新打开行为一致；加载中、真实失败和资源关联三个事实不再混淆；失败可以在原位置恢复。

代价：附件预览组件增加明确的异步状态和重试动作，需要同时维护中英文文案与读屏动态反馈。

## 不采用方案

- 把 `previewUrl` 持久化进数据库：可以绕开回读，但会显著放大任务 JSON，并复制附件二进制事实；
- 放宽 Renderer 读取任意 `file://`：改动表面简单，但破坏本机资源受信边界；
- 仅让用户关闭后重新打开：没有修复首次失败，也把内部竞态转嫁给用户。
