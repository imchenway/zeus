# ZEUS-0271 新用户安装后的任务推送引导

## 任务目标

说明新用户安装 Zeus 后，在没有登录 Zeus 专属 Codex、也没有配置第三方模型连接或项目默认模型时，执行“推送到新会话”的当前真实交互；同时确定更完整的首次 Codex 接入引导。

## 术语边界

- “没有配置模型”指没有配置第三方模型连接或项目可用模型集，不等于 Zeus 没有可选模型。
- Codex App Server 报告的 Codex 模型属于内置可发现模型，不要求用户先在 Zeus 设置中创建模型连接。
- “Zeus 专属 Codex 登录”只认证 Zeus 独立 `CODEX_HOME`，不会读取、复制或覆盖 Codex App 的账号状态。
- “Codex 安全配置导入”只导入普通偏好、全局指令、规则、提示词、技能和用户插件，不导入账号、密钥或历史会话。

## 实施前已有交互

### 正常前提

用户已经创建项目与任务，Codex App Server 可以启动并报告至少一个可用 Codex 模型，但 Zeus 专属 Codex 账号未登录，也没有配置第三方模型连接。

### 用户路径

1. 用户在任务详情点击“推送到新会话”。
2. Zeus 打开当前任务的推送弹窗，先显示“正在连接 app-server 并读取可用模型…”。此时只读取能力，不创建会话或执行轮次。
3. 服务端把 Codex App Server 报告的 Codex 模型与项目允许使用的第三方模型合并。没有第三方模型时，Codex 模型仍然存在；Zeus 优先使用项目记忆、项目默认模型或第一个真实可用模型，因此“没有配置模型”通常不会单独阻断推送。
4. 弹窗自动选中一个真实 Codex 模型，并展示工作区、模型等级、速度、工作模式、权限、补充信息、附件、历史上下文和首发预览。没有成功记忆时权限默认“只读”。
5. 因当前模型需要 OpenAI 认证且 Zeus 专属 Codex 未登录，弹窗原位显示“Zeus 专属 Codex 需要登录”，说明账号与 Codex App 隔离，也不会复制登录信息。底部主操作从“创建新会话”改为“登录并继续”。
6. 用户点击“登录并继续”后，Zeus 请求 Codex App Server 生成官方 ChatGPT 登录地址；Electron Main 复验 HTTPS 后交给系统浏览器。弹窗进入“等待登录…”状态，可执行“取消登录”，不能重复提交。
7. 用户在官方网页完成登录。网页可能显示“打开 ChatGPT”，但该按钮不是 Zeus 登录完成条件；Zeus 每 800 毫秒读取一次权威账号状态。
8. Zeus 读取到账号已登录后，自动回到前台，短暂显示“登录成功，正在继续”，保留原模型、工作区、权限、补充信息和附件。
9. 约 900 毫秒后，Zeus 自动继续原推送，不要求用户再次确认。只有此时才建立待处理工作面并发出真实会话创建请求。
10. 服务端在创建产品会话、任务工作区和首轮提交前再次刷新账号状态。若登录有效，创建新会话并进入会话工作面；若登录已经失效，拒绝创建并返回稳定的登录错误。Renderer
    随后撤销未接纳的乐观工作面，恢复原导航、模型、工作区、权限、补充信息和附件，并继续同一登录流程，不留下失败会话。

### 当前失败与降级

- Codex App Server 和第三方模型目录都没有可用模型时，能力接口返回“当前项目没有可用的 Codex 或 Pi 模型”，弹窗显示错误且不能创建；这与“未配置第三方模型”不是同一状态。
- 官方登录页无法打开、登录等待超过五分钟或用户取消时，推送弹窗和已填写内容保留，不创建会话或任务工作区。
- 选择已经就绪的 Pi 模型时，不经过 Codex 登录门禁。
- 当前任务管理状态不会因为创建会话自动改变；“推送到新会话”只负责创建会话和首轮输入。

## 当前体验判断

### 已经合理的部分

- 登录门禁发生在创建前，不会先制造一条注定失败的会话。
- 模型配置和账号登录被正确区分；新用户无需为了使用 Codex 先配置第三方 API。
- 登录在任务推送现场完成，用户的任务上下文与表单配置不会丢失。
- 登录完成自动继续，减少重复确认；服务端仍做第二次权威复验。
- Zeus 专属账号与 Codex App 账号物理隔离，不复制认证文件。

### 实施前缺口

- 当前没有完整的首次安装统一向导；任务推送弹窗承担的是就地登录引导。
- 用户选择 Codex 登录时，当前不会询问是否导入 Codex App 的已有配置。
- 现有设置页虽然支持安全配置扫描、预览、导入、备份和失败回滚，但导入结果固定标记 `restartRequired=true`，界面要求重启 Zeus 后新会话才使用配置。
- 当前配置导入接口没有触发新的 Codex 运行时世代，因此尚不能在不重启 Zeus 的情况下保证本次新会话使用刚导入的配置。

## 已确认目标交互

1. 不增加首次启动强制向导；继续在用户第一次执行任务首发时做就地引导。
2. 用户第一次选择 Codex 的“登录并继续”后，Zeus 先检查 Codex App 配置导入预览。
3. 没有安全可导入项时直接进入官方登录，不展示空询问。
4. 有可导入项且此前没有询问过时，展示一次“是否导入 Codex App 配置”。明确列出将导入和跳过的内容，并说明不会导入账号、密钥或历史会话。
5. 用户选择“暂不导入”后直接登录并继续；后续重新登录不重复询问，仍可在设置中主动导入。
6. 用户选择导入后，复用现有安全导入事务；导入成功后不要求重启整个 Zeus，而是激活新的 Codex 运行时世代。
7. 新任务和空闲会话进入新世代并使用新配置；正在执行或等待用户答复的会话保留在旧世代，完成后旧世代自然排空。
8. 新世代就绪后继续官方登录；登录完成后自动恢复原任务推送，不增加第二次确认。

## 推荐界面文案

标题：`使用 Codex App 的配置？`

说明：`Zeus 可以把 Codex App 的普通偏好、指令、规则、提示词、技能和用户插件复制到 Zeus 专属目录。本操作不会导入账号、密钥或历史会话。`

主操作：`导入并继续`

次操作：`暂不导入`

导入成功：`配置已导入，正在为新会话启用…`

世代就绪：`配置已启用，正在打开 Codex 登录…`

## 方案优缺点

### 推送时就地引导并热切换运行世代（已确认）

优点：

- 只在用户明确要使用 Codex 时出现，不阻挡浏览项目或整理任务。
- 首个 Codex 会话就能使用用户已有配置，不需要重启和重新定位任务。
- 复用现有配置导入安全边界与运行世代排空能力。
- 运行中的旧会话不中断，不迁移审批或重复执行工具调用。

代价：

- 需要持久记录“是否已经询问过”，避免账号过期后重复打扰。
- 配置导入成功与配置运行生效必须分成两个真实状态。
- 需要为运行世代管理器增加显式配置刷新入口；仅再次调用相同身份的 `ensureReady` 不会创建新世代。
- 新世代启动失败时，配置文件已经导入但尚未用于新会话，界面必须保留可重试状态，不能伪造已生效。

### 首次启动统一向导（未采用）

优点：第一次推送前即可完成所有准备。

缺点：会阻断只想浏览、建项目或整理任务的用户，也把外部账号授权提前到尚无使用意图的时刻。

### 导入后重启 Zeus（未采用）

优点：复用当前 `restartRequired` 契约，实现简单。

缺点：中断任务推送现场，需要额外持久恢复草稿和导航，首次使用链路明显变长。

## 实现结果

- 任务推送登录链路会在首次选择 Codex 登录时读取配置导入预览；只有存在安全可导入项时才询问。
- 询问结果保存在当前 Zeus 用户数据的本地偏好中。选择“暂不导入”或导入成功后都不再重复询问；仍可在设置页主动导入。
- 推送弹窗增加配置检查、导入确认、导入中和启用重试状态，并明确展示将导入项与跳过项。
- 配置导入成功后，服务端显式创建并激活新的 Codex 运行世代；新世代未就绪时不会继续创建会话，而是保留“重试启用”入口。
- 新任务使用新世代；旧世代中已活动的轮次、待回复与待处理请求保留原绑定，完成后自然排空。
- 设置页导入复用相同的热切换语义，启用失败时可单独重试，不会重复导入配置文件。
- 配置预览失败不作为登录的新阻断点；安全导入本身失败则保留弹窗与原推送内容。
