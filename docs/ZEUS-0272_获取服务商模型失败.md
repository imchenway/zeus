# ZEUS-0272 获取服务商模型失败

## 当前状态

已完成需求澄清、真实端点诊断、代码实现、窄服务层验证、静态门禁、全量构建和独立测试身份打包。本次未启动 GUI，未读取正式 Zeus 的 API Key 或用户数据。

## 现状与证据

- 用户已保存自定义模型连接，服务地址为 `https://81.70.81.85:23100/v1`，模型目录路径为 `/models`。
- 点击“获取模型”后界面只显示 `fetch failed`，无法判断是超时、连接拒绝、证书、TLS 还是地址协议错误。
- 不带 API Key 的只读握手检查确认：该端口不接受 HTTPS，Node `fetch` 返回 `ERR_SSL_PACKET_LENGTH_TOO_LONG`。
- 相同端点通过 `http://` 可到达，并在缺少凭据时正常返回 HTTP 401；因此本次真实根因是把明文 HTTP 端口配成了 HTTPS。
- 服务层 `fetchModelIds` 只为 15 秒主动超时和 HTTP 响应建立了产品错误，其他 `fetch` 异常被原样抛出，Renderer 因此收到底层 `fetch failed`。

## 已确认范围

- 将模型目录请求中的地址协议不匹配、TLS 或证书失败、主机解析失败、连接拒绝、连接中断和超时转换为稳定错误码、简体中文原因与恢复建议。
- 识别到“HTTPS 地址实际连到明文 HTTP 端口”时，明确建议核对端口；若服务只支持明文 HTTP，由用户把服务地址改为 `http://` 并重新保存。
- 不自动从 HTTPS 降级到 HTTP，不绕过现有明文 HTTP 风险确认，不关闭 TLS 证书校验。
- “获取模型”与“服务诊断”复用同一模型目录请求，两个入口使用同一套错误事实。

## 方案取舍

优点：用户可以根据真实失败阶段自助恢复，截图中的地址协议错误不再被压成无意义的 `fetch failed`；同时不会为了可连通而静默降低传输安全。

缺点：Zeus 只能依据底层错误判断最可能的失败类型，不会替用户修改服务端 TLS 或自动切换协议；使用明文 HTTP 时仍需用户显式修改并确认风险。

## 实现计划

1. 在模型连接服务中提取受控的底层错误信号，不向界面暴露堆栈或任意错误正文。
2. 按地址协议、TLS/证书、解析、建连、中断和超时分类，输出稳定产品错误。
3. 执行格式、`pnpm lint`、`pnpm typecheck` 和 `pnpm build`，并如实记录验证边界。

## 实现结果

- 模型目录请求现在会沿 `Error.cause` 链只提取受控的错误码和分类信号，不向 Renderer 透传堆栈或底层错误正文。
- `ERR_SSL_PACKET_LENGTH_TOO_LONG` 和 `ERR_SSL_WRONG_VERSION_NUMBER` 等明文端口误用 HTTPS 的典型信号会转换为 `ZEUS_MODEL_CATALOG_HTTPS_PROTOCOL_MISMATCH`，文案要求先核对端口，仅在服务确实只支持明文 HTTP 时由用户改为 `http://` 并重新保存。
- 不可信证书链、证书主机不匹配、证书过期、主机无法解析、连接拒绝、建连超时、连接中断和其他 TLS 失败都有独立稳定错误码与恢复建议；未知网络错误使用不暴露内部细节的统一提示。
- 现有 HTTP 状态错误、15 秒主动超时和模型目录结构错误继续保留原有产品错误语义；无效 JSON 收口为“模型目录没有返回有效的 JSON”，不再直出解析器错误。
