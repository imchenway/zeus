# ZEUS-0274 思考过程的文字样式

## 任务信息

- 任务类型：优化。
- 现状：已完成轮次展开后的过程说明使用了接近最终答复的深色；进行中的过程说明观感偏小；顶层工具调用文字与正文大小不稳定；部分状态图标与首行文字存在垂直错位。
- 当前阶段：已完成实现、静态门禁、隔离打包与真实界面验收。

## 已核对事实

1. 已完成与进行中的自然语言内容都属于“过程说明”，不属于最终答复。
2. `.session-thread-item-assistant .session-markdown` 直接设置了答复正文颜色，优先于过程说明父层继承的灰色，导致已完成过程说明显示偏黑。
3. 会话可读正文基准为 `15px`；过程说明和顶层过程行应消费同一字号，但样式文件前部仍保留多处 `14px` 声明，只靠末尾覆盖维持结果。
4. 截图中的绿色完成图标属于思考摘要。摘要行使用顶部对齐，`19px` 图标没有按 `15px × 1.5` 的首行行盒居中，因此产生轻微上偏。
5. 命令、路径、输出、耗时和技能标签是技术明细，不属于本次放大的正文层级。

## 已确认领域与验收边界

- 已完成与进行中的过程说明统一使用 `15px`，并使用与工具活动相同的次要灰色。
- 思考摘要、工具调用汇总、进行中工具项和展开后的工具项标题统一归为“顶层过程行”，字号与会话正文同为 `15px`。
- 状态图标与第一行文字垂直居中；多行内容不把图标移动到整段文字中部。
- 最终答复颜色与字号不变；命令、路径、输出、耗时和技能标签继续保持 `11–12px`。
- 普通会话页和任务会话抽屉复用同一规则；浅色、深色和跟随系统主题均消费现有会话语义色。

优点：活动态与完成态切换时不再跳字号或跳颜色；过程说明、工具标题和图标形成稳定的阅读基线。

代价：顶层过程行回到正文尺寸后会略微增加纵向占用；技术明细仍保持较小字号，需要展开后按次级信息阅读。

## 实施方案

1. 让过程语义色直接复用工具活动的次要文字色，并把颜色声明落在过程 Markdown 节点上，避免被最终答复选择器覆盖。
2. 使用同一个可读字号变量约束过程说明和全部顶层过程行，不按活动状态分叉。
3. 让思考摘要图标容器使用首行行盒高度，在容器内居中图标；保持多行摘要顶部锚定。
4. 不修改消息投影、Provider 协议、过程展开行为或技术明细样式。

1. 过程语义色改为直接复用 `--session-text-muted`，并且同时覆盖过程容器内的 Markdown 节点，不再被最终答复深色要求抢占。
2. 已完成与进行中过程说明、思考摘要、工具调用汇总、进行中工具项和展开后的工具项标题统一消费 `15px` 可读正文基准。
3. 思考摘要图标容器改为首行行盒高度，图标在首行内居中，多行摘要仍然保持顶部锚定。
4. 命令、路径、输出、耗时和技能标签未改；最终答复与 Provider 协议未改。
