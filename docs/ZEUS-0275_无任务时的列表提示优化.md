# ZEUS-0275 无任务时的列表提示优化

## 任务目标

修复任务列表在横向列超出窗口时的空态偏移，让真实无任务和筛选无结果的提示都以当前可见列表区域为基准居中，并收敛中英文空态文案。

## 历史与已确认决策

- 延续 `docs/TASK_20260729_004_任务空状态视觉修复与升级发布.md` 的无容器空状态，不恢复独立白色面板、阴影或装饰卡片。
- 继续保留顶部唯一“新任务”主操作，真实无任务时不在空态里重复放置按钮。
- 真实无任务与筛选无结果使用两套事实文案；后者保留清除筛选和查看全部状态的恢复动作。
- 历史会话已选定真实无任务标题为“为项目添加第一项任务”。

## 根因

1. 空状态和表头处于同一个 CSS Grid。表头按所有任务列设置了大于窗口的最小宽度，空状态的 `100%` 因此按整张宽表而不是可见区计算，窗口越窄越向右偏。
2. 后续样式把任务工作台改回内容高度，空状态没有获得表头下方的剩余高度，无法做稳定的垂直居中。
3. `860px` 以下的共享断点把任务页分成了“自动高度 + 剩余高度”两行，但页面只有一个工作区子项，窄窗口因此把下半屏留给了空的第二行。
4. `760px` 以下会隐藏任务表头，但空列表仍保留“表头 + 内容”两行，空态因此落在第一行并视觉偏上。

## 实施方案

- 让任务页在所有断点都只保留一行主工作区，工具条之外的列表行使用全部剩余高度。
- 空列表显式使用一列网格：表头保持真实列宽并可横向滚动，空状态使用可见宽度和剩余高度。
- `760px` 以下表头隐藏时，空列表改为单行，不再为已隐藏的表头预留空间。
- 真实无任务文案改为“为项目添加第一项任务 / 集中管理需求、缺陷与优化，随时掌握任务进展与执行状态。”
- 筛选无结果改为“当前视图没有匹配任务”，明确它是当前视图结果，不是项目没有任务。

## 优缺点

优点：

- 居中基准与用户真实看到的列表区域一致，不受隐藏在窗口右侧的列宽影响。
- 文案表达任务页用途，不再像字段说明或数据库空值。
- 不改变任务数据、筛选模型、创建入口和表头列宽。

缺点：

- 窄窗口中表头仍需要横向滚动才能查看所有列；这是保留可读列宽的必要代价。
- 标题更准确直接，高级感来自排版、留白和语义克制，不使用品牌化口号。
