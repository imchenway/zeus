# ZEUS-0279 会话升级后消息重复且无法继续

## 用户现场

退出 Zeus、完成升级并重新打开后，历史会话出现三类异常：

- 同一轮用户输入和模型回复重复显示；
- 历史条目的时间线顺序看起来错乱；
- 在原会话发送“继续”失败，输入虽然保留，但会话无法继续处理。

## 正式现场只读证据

本轮只读检查 `/Users/david/.zeus/data/zeus.db` 和对应 Provider JSONL，没有启动、停止或改写正式 Zeus。

- 现场会话真实线程为 `01a000f4-2915-7d23-b4d1-a3cc46eddee4`，JSONL 文件仍存在于 Zeus 专属 Codex Home。
- 原轮次真实身份为 `01a000f4-2a09-7001-bc76-e42b354c89a5`，已完成且保留完整用户消息、过程消息和最终回答。
- 实时事件首次按真实 Provider item 身份 `msg_* / rs_*` 写入；升级恢复又把同一批内容按兼容快照身份 `item-1` 至 `item-11` 写入。
- 同一最终回答因此存在两份 item：一份真实 `msg_*`，一份兼容别名 `item-11`；两份正文完全相同。
- “继续”提交明确失败，Provider 返回 `no rollout found for thread id ...`。
- 对应 rollout 文件实际存在，说明错误不是历史文件丢失，而是升级后的内嵌 Codex 进程没有在 Zeus 专属 Codex Home 中查找。
- 正式 Zeus 的 stdio app-server 由 Zeus 专属二进制启动，但它拉起的 daemon 实际落在 `/Users/david/.codex`；这进一步证明内嵌链路丢失了 Zeus 专属 `CODEX_HOME`。

## 根因

### 内嵌运行时丢失 Codex Home

旧独立 execution-host 在启动子进程时显式注入 `CODEX_HOME`。升级后 Local Server 改为由 Electron Main 内嵌持有，但新链路只把 `codexHome` 传到业务服务，没有继续把它注入 Codex app-server 子进程。

结果是：数据库仍绑定 Zeus 专属目录中的真实线程，新的 Codex 进程却到父进程默认目录查找 rollout，最终把一个真实存在的线程误报为不存在。

### 兼容快照身份变化造成重复持久化

部分 Codex 版本在读取旧 JSONL 时，不再返回实时事件里的 `msg_* / rs_*` 身份，而是重新生成 `item-N` 兼容身份。Zeus 原逻辑只按 Provider item ID 去重；身份变化后即使轮次、类型、状态、阶段和正文全部相同，也会被当成新消息再次写入。

其中 reasoning 兼容项还可能把相邻多个真实 reasoning 项合并成一个 `item-N`，因此只比较单条正文不足以完整收口历史重复。

## 修复方案

### 固定 Codex 持久目录

- Codex app-server manager 增加固定 `codexHome` 配置。
- 每个 Codex 子进程启动时显式注入同一个绝对路径 `CODEX_HOME`。
- 多运行世代 manager 创建新 app-server 时继续沿用同一 `codexHome`。
- Desktop 内嵌 Local Server 和直接创建 Local Server 的路径都显式传入当前数据布局的 `codexHome`。

优点：退出、升级和运行世代切换后都能继续读取同一批真实 JSONL、登录和 Provider 状态。

代价：运行期间不能把一个 manager 热切换到另一套 Codex Home；切换资料目录必须重新创建运行时，这与现有数据根边界一致。

### 严格识别兼容别名

- 只对形如 `item-N` 的兼容身份执行别名判断。
- 必须同时满足同线程、同轮次、同类型、同状态、同阶段和正文无损相等，才认为已有真实条目。
- reasoning 允许用相邻、未匹配的真实 reasoning 项按空行连接后与兼容项逐字比较，以覆盖 Provider 的合并投影。
- 新的恢复快照命中真实条目后不再写入兼容别名。
- 对历史上已经写入的别名，在 API 快照中同时抑制对应 item 和 message，不直接删除数据库记录。
- 没有真实对应身份的 `item-N` 继续保留，不能仅凭命名猜测为重复。

优点：现有受影响会话升级后立即恢复单份时间线，同时保留原始数据库证据；新恢复过程不再继续放大重复。

代价：历史数据库中已经产生的别名记录仍保留，只在产品快照中收口；如需物理清理，必须另做带备份和完整性校验的数据迁移。
