# ZEUS-0280 连接外部供应商模型报错

## 当前状态

已完成请求角色兼容修复。根据用户最新确认，供应商拒绝单次模型请求时只显示警告，原会话继续可用；会话状态、界面和系统通知均已按该语义收口。

## 现状

用户通过 Pi Agent 调用外部 OpenAI Chat Completions 兼容模型时，请求立即返回 HTTP 400：

```text
Failed to deserialize the JSON body into the target type:
messages[0].role: unknown variant `developer`, expected one of `system`, `user`, `assistant`, `tool`
```

Zeus 已把该错误正确收口为 `ZEUS_PI_MODEL_REQUEST_FAILED`，但实际请求没有进入模型执行。

## 根因

Zeus 注册外部模型时没有声明 `supportsDeveloperRole`。Pi 对推理模型默认把系统指令投影为 `developer` 消息，而当前供应商兼容端点只实现了通用的 `system / user / assistant / tool` 角色集合，因此在解析第一条消息时直接拒绝请求。

这不是模型 ID、思考深度或用户消息内容错误。失败发生在供应商反序列化请求阶段，模型尚未开始推理。

## 修复方案

所有由 Zeus 用户配置并通过 Pi `openai-completions` 调用的外部模型，明确设置 `compat.supportsDeveloperRole = false`。Pi 保留原系统指令内容，只把首条指令角色从 `developer` 改为 `system`。

不按 DeepSeek、百炼或单个模型 ID 增加厂商分支，也不在收到 400 后自动重放。自动重放可能造成重复扣费或重复工具副作用，而且无法证明供应商是否已部分接收请求。

## 方案取舍

优点：`system` 是当前外部 Chat Completions 共同基线，可以同时兼容 DeepSeek、中转网关、本地模型服务和其他只实现标准四角色的端点；内容、会话身份、工具协议和推理等级保持不变。

缺点：即使某个外部端点支持 `developer`，Zeus 也会使用兼容性更广的 `system`，不能利用两种指令角色的优先级差异。当前 Pi 会话只注入一份受 Zeus 控制的系统指令，因此不会丢失指令正文；如果后续确实需要两种角色并存，应把角色支持纳入连接能力档案，而不是按模型名称猜测。

## 影响范围

- 影响后续新建和恢复的 Pi 外部模型会话请求。
- 不改变 Codex 官方模型和 DeepSeek 官方 Responses 路由。
- 不改写历史消息，也不自动重发本次已经失败的用户消息。
- 不改变 API Key、安全审批和工具调用链路；错误详情继续脱敏保留，用户可见严重度改为警告。

## 单轮错误产品语义

用户进一步明确：外部供应商拒绝本轮模型请求时，只需要给出警告信息，不能终止会话。

实现采用“轮次结果”和“会话可用性”分离：

- 当前请求仍以失败结果落盘，保留脱敏后的错误代码、供应商状态和原始原因，不能伪造成模型已经成功响应。
- Pi 原生会话和 Zeus 产品会话恢复为 `ready / open`，输入区立即可继续使用。
- 会话阶段保持“可用”，关注状态使用普通未读提醒，不显示失败图标；系统通知显示“模型请求未完成，会话可以继续”，不再显示“会话失败”。
- 警告卡标题改为“本轮请求未完成，会话可以继续”，使用警告色和非阻断状态语义。
- 已失败请求不自动重放；用户修正配置后明确重新发送，避免重复扣费和工具副作用。

优点：参数、认证、限流和供应商临时异常不会破坏已有上下文，用户可以在同一会话继续处理。缺点：数据库仍保留失败轮次用于审计，代码必须明确区分“本轮失败”和“会话失败”；真正不可恢复的运行内核或安全错误仍需要失败关闭。

## 验证结果

- 本地协议探针：通过。使用构建后的真实 Pi 驱动向本机 OpenAI Chat Completions 兼容端点发送推理模型请求，捕获到角色顺序为 `system, user`，请求中不含 `developer`，轮次以 `agent_settled` 正常结束。
- `pnpm lint`：通过。
- `pnpm typecheck`：通过。
- `pnpm build`：通过，15 个工作区项目和桌面 Renderer、Main、preload 完成构建；只有既有的大分块提示。
- `pnpm package:mac`：通过，生成 `dist/test/mac-arm64/Zeus Test.app`、测试 DMG 和 blockmap。
- 测试包身份与签名：`CFBundleDisplayName=Zeus Test`、`CFBundleIdentifier=dev.hypha.zeus.test`，严格签名校验通过。
- 测试 DMG：`hdiutil verify` 校验通过。
- 会话状态运行探针：失败轮次和提交均保留 `failed`，但会话仍为 `open / ready`，阶段为 `ready`，关注状态为 `unread`。
- 系统通知运行探针：模型请求错误显示“Zeus 模型请求未完成”，真正的会话级错误仍显示“Zeus 会话失败”。
- 本轮没有启动测试包，没有关闭、接管或复用其他任务的 `Zeus Test.app`。
