# ZEUS-0281 点击归档报错

## 问题与影响

用户点击侧边栏会话的归档按钮后出现两类错误：

1. Codex 会话提示 `no rollout found for thread id ...`。会话 JSONL 和 Zeus Provider 数据库中的 thread 实际存在，但当前嵌入式宿主启动的 Codex App Server 没有固定使用 Zeus 独立 `CODEX_HOME`，因此错误地到用户默认 Codex 目录查询。
2. Pi SDK 会话提示 `Codex native conversation was not found.`。该会话虽然复用了 `codex_native` 产品传输类型，但 `agentKind` 是 `pi`；归档接口只按传输类型判断，误把 Pi 会话交给 Codex 协调器。

这两个问题还会影响归档恢复和任务重开时的会话恢复。单独隐藏侧边栏记录无法解决问题，也会破坏原生会话的恢复能力。

## 现场证据

- 报错的 Codex thread 在 Zeus 会话库、Zeus Provider 状态库和对应 JSONL 路径中均可查到，排除“会话文件已经丢失”。
- 当前正式应用为内嵌 Local Server 架构；旧独立执行宿主会把 `CODEX_HOME` 注入子进程，新内嵌路径创建运行时世代管理器时遗漏了这项固定环境。
- 报错的“语音模型接入”会话记录为 `transportKind=codex_native`、`agentKind=pi`、`agentTransport=sdk`，而归档路由无条件调用 Codex 归档协调器，错误文本与 Codex 协调器的身份校验完全一致。

以上现场核查均为只读，没有修改正式应用数据库、Provider 数据或会话文件。

## 实现方案

### Codex 数据目录

- Codex App Server 管理器新增宿主固定运行环境，并在每次子进程启动时合并。
- 固定运行环境优先于动态模型 Provider 环境，保证模型连接不能覆盖 `CODEX_HOME`；`PATH` 和外部 Agent 目录仍由宿主按既有规则显式设置。
- 运行时世代管理器把固定环境传给每个新世代，避免热切换后再次回退。
- Electron 内嵌宿主和 Local Server 自持运行时都显式传入 Zeus 数据布局中的 `CODEX_HOME`。

优点：已有 thread 不需要迁移或复制，归档、恢复、续聊和热切换都回到同一真实数据源。代价：修复要在应用重启并使用新构建后生效，当前已运行的旧进程不会被就地改写。

### Pi 会话归档

- 原生会话归档、恢复和任务重开统一先按 `agentKind` 分派：Codex 继续调用 Provider 的 `thread/archive` 与 `thread/unarchive`；Pi 使用 Pi 协调器维护 Zeus 本地归档状态。
- Pi 归档前检查活动 run、未完成 turn、排队或派发中的 submission、待处理请求和待审批工具；存在任何活动工作时返回明确的“会话仍在进行”冲突，不强制隐藏。
- Pi SDK 没有独立的 Provider 归档接口。归档只切换 Zeus 持久记录并卸载内存上下文，保留原生 session ID、JSONL 路径、失败状态和消息；恢复后下一次发送按原路径恢复 session。

优点：Pi 不再误调用 Codex，失败或空闲会话可以正常归档并完整恢复。代价：Pi 的归档状态由 Zeus 单侧持有，不能像 Codex 一样与外部 Provider 客户端共享归档列表；这是 Pi SDK 当前能力边界。
