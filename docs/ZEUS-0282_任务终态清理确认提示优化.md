# ZEUS-0282 任务终态清理确认提示优化

## 用户反馈

任务标记为“已完成”或“已取消”前，原生确认框把全部影响挤在一段粗体正文里，按钮只显示 `Cancel / OK`。用户很难快速判断哪些内容会永久删除、哪些内容会保留，以及两个按钮分别会做什么。

## 产品边界

本任务只优化危险确认的表达和交互，不改变已经确认的任务终态规则：

- 存在未提交、未跟踪内容、冲突或活动会话时，仍只询问一次。
- 取消后保留工作现场，不修改任务状态。
- 确认后停止并归档关联会话，清理物理 worktree，再修改任务状态。
- 已提交代码、本地与远端任务分支、会话消息和代码交付记录继续保留。

## 实现方案

- 用 Zeus 统一的 `ModalPortal` 危险确认面替代浏览器系统 `window.confirm`。
- 标题直接说明最终动作和目标状态。
- 把“归档会话”和“永久删除未提交文件”拆成可扫描的影响列表，并对不可恢复项使用危险语义色。
- 单独说明已提交代码、任务分支和交付记录不会删除。
- 取消按钮改为“先保留现场”，危险按钮改为“清理并标记为‘目标状态’”。
- 默认焦点落在保留现场按钮，支持 Escape 取消、Tab 焦点循环和 `alertdialog` 辅助技术语义。

优点：用户能先看清不可恢复影响，再根据动作明确的按钮作决定；默认焦点也降低误删概率。

缺点：自定义确认面比系统确认框多一套界面代码，需要继续遵守 Zeus 的弹窗样式和键盘交互约束。
