# ZEUS-0283 全应用错误统一弹窗

## 任务目标

全应用禁止把运行异常、服务端错误和技术原文直接输出在当前页面，统一使用错误弹窗承载；弹窗默认显示简明说明，并允许用户主动查看详情。

## 范围判断

本任务统一的是“操作已经发起但没有完成”的错误，包括读取、保存、打开、连接、提交、Git 操作、资源处理和渲染器异常。

以下内容保留在原控件附近：

- 必填、格式、重复名称等表单纠错；
- 危险操作确认和权限范围说明；
- 会话失败记录、Git 冲突、只读、不可用等需要长期存在的业务状态。

这样做的优点是用户能在原输入位置立即修正，历史状态也不会因关闭弹窗而消失。代价是界面仍会出现少量“失败、冲突、不可用”状态词，但它们不再承载瞬时异常原文。

## 发现的问题

- 主工作区、设置、会话、资源卡片、Git 工作台和任务弹窗各自输出错误横条，位置和文案不一致。
- 菜单栏与独立 Git 窗口拥有独立 React 根节点，不能只在主窗口挂一个弹窗出口。
- 渲染器启动失败会直接替换根节点文本，错误边界会占满整个窗口。
- 部分错误通过 `title`、屏幕阅读器专用节点或详情块继续暴露原始信息，即使视觉上不明显也不符合统一出口。

## 实现设计

### 统一出口

新增 `ApplicationErrorDialog`：

- 业务组件通过 `useApplicationErrorDialog` 上报当前失败；非 React 启动链通过 `reportApplicationError` 上报；
- 主窗口、菜单栏窗口和独立 Git 窗口各挂载一个 `ApplicationErrorDialogHost`；
- 错误按出现顺序排队，同一标题和详情不重复入队；
- 弹窗复用 `ModalPortal`，支持 Escape、遮罩关闭、焦点接管和窄窗口布局。

### 信息层级

- 标题：指出失败操作，例如“Git 操作失败”；
- 摘要：说明 Zeus 没有完成操作，不显示技术原文；
- 详情：用户展开后显示 ISO 时间、组件或操作来源、脱敏后的原始信息；
- 恢复：渲染器致命错误提供“刷新窗口”，普通错误关闭后回到保留现场。

### 安全边界

详情输出前统一遮蔽 Bearer 凭据、`sk-` Key、API Key、Token、密码、Secret 及查询参数中的对应值。普通页面不再用 `title`、隐藏可访问节点或内联 `<details>` 绕过该出口。

## 涉及模块

- 应用入口与错误边界；
- 项目源码、命令中心和 Git 工作台；
- 会话连接、审批、消息编辑、附件与资源打开；
- 任务列表、任务详情、模型推送和 Git 审核/交付；
- 浏览器、用量、远程接管和导入设置；
- 菜单栏用量窗口与独立 Git 窗口。

## 优缺点

优点：

- 用户在任何功能里看到同一种错误交互；
- 错误不再挤压页面或打散当前布局；
- 技术信息按需查看，默认文案更易理解；
- 集中队列、去重和脱敏，后续维护只需改一个出口。

缺点：

- 弹窗会中断当前操作，并发错误需要逐个关闭；
- 自动加载型资源连续失败时可能形成队列，因此必须配合去重；
- 字段校验若误接入全局出口会失去定位，实施时必须持续守住范围边界。
