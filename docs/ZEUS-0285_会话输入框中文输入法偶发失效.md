# ZEUS-0285 会话输入框中文输入法偶发失效

## 当前阶段

已完成根因收口、代码修复、静态检查、构建、测试身份打包和隔离应用运行验证。受桌面自动化无法切换 macOS 全局输入源的限制，原生拼音候选框的真实选词链路仍需人工回归一次。

## 原始问题

- 会话输入框偶尔无法使用中文输入法输入中文。
- 当前恢复方式是按 `Cmd+W` 关闭窗口后重新打开。

## 现状证据

- 会话输入框已经监听 `compositionstart / compositionend`，并在组合期间阻止 Enter 发送；问题不是单纯缺少发送快捷键判断。
- 已有会话输入框的 `value` 直接绑定整条会话状态。每次输入变化都会同步更新外部 store，并同步写入本地草稿存储。
- 会话运行快照、队列、交互请求、模型配置和轮次状态都会让同一工作面重新渲染。中文输入法尚在拼音组合阶段时，外部状态回写与 textarea 原生组合值存在竞争窗口。
- 新建会话输入框已经使用组件本地状态，风险明显低于已有会话输入框；本次不改会话、队列或 Provider 协议。

## 根因与决策

根因收口为已有会话 composer 把“输入法正在组合的临时文字”和“已经确认的持久草稿”当成同一个实时事实。中文输入法组合期间，每个中间值都经过外部会话状态和同步存储再回到受控 textarea；后台状态刷新一旦在该窗口插入，就可能打断 Chromium 与 macOS 输入法的组合上下文。

采用本地组合缓冲：

- 普通输入继续即时更新会话草稿。
- `compositionstart` 后只更新 composer 本地显示值，不写外部会话状态。
- `compositionend` 或组合期间失焦时，把 DOM 最终值一次性写入会话草稿。
- Enter 判断同时识别标准 `isComposing` 和 Chromium 输入法收尾值 `keyCode 229`。

优点：输入法组合过程不再经过会话快照和同步存储往返，修复点集中在输入边界，不改变消息发送和恢复协议。

代价：没有完成选词的半成品拼音不会即时跨窗口保存；选词完成或失焦后仍按原规则持久化。
