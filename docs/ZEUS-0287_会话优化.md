# ZEUS-0287 会话优化

## 用户现场

1. 活动轮次已经展示转圈的思考摘要或工具过程时，消息流末尾仍追加“正在思考”，同一处理状态出现两次。
2. 第一次点开没有热缓存的会话时，历史消息和用户消息会短暂播放整批入场动画，看起来像正文闪烁。

## 根因

- 最新思考摘要的可见状态由整个轮次是否活动决定；即使对应 Provider 条目已经完成，只要轮次仍在执行，摘要仍显示活动图标。通用存续状态却只检查条目的原始状态，因此又补出一行“正在思考”。
- 消息入场 Hook 在空壳首次渲染时完成初始化。权威历史稍后一次性水合后，全部历史 ID 都被误判为本轮新增消息，并触发淡入和位移动画。

## 实施口径

- 当前轮次已经有带活动图标的可读思考摘要时，该摘要就是唯一的持续处理反馈，不再同时显示通用“正在思考”。真正没有可见过程内容的活动空档仍保留“正在思考”。
- 会话首次权威快照到达前，消息 ID 只作为初始基线收集；首次历史批次不播放入场动画。权威快照就绪后新增的真实消息继续保留既有入场反馈。

## 优缺点

优点：

- 同一时刻只保留一个明确的处理状态，过程区更安静。
- 首次打开长会话不再让整段历史和用户气泡同时淡入、位移。
- 不取消后台权威校准，也不影响后续真实新消息的轻量动效。

代价：

- 活动轮次的最新思考摘要会继续承担持续处理语义，直到出现新的可见过程或轮次结束。
- 首次快照到达前产生的本地乐观消息不播放入场动画，以换取从创建期到权威历史接管时的稳定显示。
