# ZEUS-0289 Ultra 智能体事件与会话面板修复

## 任务目标

- 修复 Codex Ultra 多智能体协作事件被错误显示为“本轮错误”的问题。
- 在会话右侧显示当前会话派生的智能体，并允许打开每个智能体的独立会话。
- 交互语义对齐 Codex：区分进行中与已完成智能体，智能体线程只读查看，不混入主会话正文。

## 现状证据

- 截图中的红色错误项实际是状态为 `completed` 的 `collabAgentToolCall` 和 `subAgentActivity`。
- 本地会话记录中对应轮次没有 `error_json`，说明它们不是 Codex 轮次错误。
- Zeus 当前只允许旧的会话项类型，未知类型会统一降级为 `error`，因此 Ultra 更频繁触发协作事件时会集中暴露该问题。
- 已经落库为 `error` 的完成项不会被现有快照对账覆盖，需要同时补上历史记录纠正能力。

## 方案与取舍

### 事件分类

将 `collabAgentToolCall` 和 `subAgentActivity` 纳入原生会话项类型，不再降级为错误；这两类协调事件不在主会话时间线重复展示，而是作为右侧智能体面板的数据来源。

对 Codex 后续新增、Zeus 尚未识别的会话项统一保留为中性的 `providerEvent`，不再默认伪装成错误；只有协议明确给出 `error` 或状态为失败时才进入错误展示。

- 优点：消除当前伪错误，也降低 Codex 协议继续扩展时再次出现同类问题的概率；主会话更聚焦，智能体状态有稳定归属。
- 缺点：尚未适配的新事件只能先按通用运行活动展示，后续仍需根据真实语义补充专属界面；协调事件的原始 JSON 不再默认出现在正文，需要通过持久化记录排查底层协议。

### 智能体面板

右侧面板按“进行中 / 已完成”分组。点击智能体后，在同一右侧区域只读打开其独立线程，并提供返回列表操作。智能体数据由 Codex 原生 `thread/list` 与 `thread/read` 提供，而不是复制或拼接本地主会话。

智能体入口和权威子线程列表预读不再依赖主会话实时连接成功。即使事件 WebSocket 暂时失败，只要本地 Codex 状态仍可读取，用户仍能打开右侧智能体面板；没有派生智能体的原生 Codex 会话明确显示 0 个线程，不再用“隐藏入口”混淆“功能不可用”和“当前没有数据”。

- 优点：保持 Codex 原生线程关系，支持子智能体独立审阅，也能覆盖嵌套智能体。
- 缺点：首次打开需要读取 Codex 状态库；Codex 服务暂不可用时只能展示明确的失败状态，不能伪造线程内容。
