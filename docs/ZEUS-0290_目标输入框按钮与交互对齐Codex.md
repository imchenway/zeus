# ZEUS-0290 目标输入框按钮与交互对齐 Codex

## 原始需求

- 目标相关的输入框按钮和交互完全错误。
- 预期参考 Codex。

## 当前阶段

实现和验证已完成，未执行 Git 提交、推送或远端发布。

## 已确认事实

- Codex 的目标是绑定原生会话的持久目标，不是 `default / plan` 之外的第三种协作模式。
- 官方 Codex 目标入口以 `/goal` 为核心：`/goal <objective>` 创建或更新，`/goal` 查看，`/goal pause`、`/goal resume`、`/goal clear` 管理生命周期。
- Zeus 已接入原生 `thread/goal/set`、`thread/goal/get`、`thread/goal/clear`，本任务不需要另造 Provider 协议。
- 当前 Zeus 把“目标”做成输入框工具栏文字按钮，点击后无条件打开一张包含说明、指标、时间线和全部动作的大面板；新会话也使用同一弹窗保存目标草稿。
- 当前实现把创建入口、状态查看、编辑和生命周期管理混成一个弹窗路径，输入框本身没有进入目标输入状态，因此用户在输入区无法直接理解“接下来输入的是目标”。
- 本机安全边界拒绝自动读取 `com.openai.codex` 实时界面，本任务不会把未取得的逐像素视觉证据写成已验证；可核对证据来自官方 OpenAI 文档、既有 Zeus 目标协议和当前仓库实现。

## 本次交互契约

1. 输入框中的目标入口使用紧凑图标按钮，不再常驻展示“目标”文字抢占工具栏宽度。
2. 没有当前目标时，点击入口直接把 composer 切入目标输入状态；输入框承担目标正文编辑，主操作明确变为创建目标。
3. 目标输入状态必须有可见模式标识和退出动作；`Escape` 先退出目标输入状态，不得直接中断正在运行的普通轮次。
4. 目标输入为空时主操作禁用；创建中阻止重复提交；失败保留目标正文。
5. 新会话在目标输入状态提交时，仍严格执行“建立原生 thread → 绑定目标 → 启动首轮”，不得先发送普通消息再补目标。
6. 已有目标时，输入框入口表达真实目标状态；点击进入紧凑管理面，不把创建目标重新伪装成普通模式切换。
7. `/goal` 空命令与按钮进入同一目标输入或查看状态；`/goal <objective>` 直接使用命令后的正文创建或更新目标，避免先清空输入再要求用户重复填写。
8. 暂停、继续和清除继续复用原生目标生命周期；清除未完成目标保留二次确认，当前轮次不被隐式中断。
9. PLAN 与目标保持正交：目标输入状态不改写 `default / plan`，保存目标后仍使用用户原本选择的协作模式。

## 取舍

优点：目标创建发生在用户正在操作的输入区，按钮、正文和主操作语义一致；已有目标仍保留完整生命周期和审计能力；Provider 协议和持久事实不变。

代价：composer 需要维护一段仅用于目标草稿的瞬态状态，并明确处理普通草稿与目标草稿的切换；无法读取 Codex 实时界面时，视觉只能按官方语义和 Zeus 已有 Codex 会话设计基线收敛，不能宣称逐像素一致。

## 实现结果

- 新会话和已有会话的目标入口统一为 32 像素图标按钮，不再使用常驻文字药丸按钮。
- 无目标时点击入口直接进入目标输入；输入框、占位文案、计数、退出按钮和主提交动作同时切换，不再先打开大弹窗。
- 普通消息草稿、附件和结构化上下文在目标输入期间只隐藏不丢失；目标输入期间停止接收附件粘贴和拖放，退出后恢复普通输入。
- 目标草稿在退出后保留，再次进入可以继续编辑；创建失败同样保留正文，创建中禁止重复提交。
- 目标输入里的 `Escape` 由 composer 优先消费，只退出目标输入，不进入会话中断确认。
- 已有目标时图标呈现激活态，点击继续进入原有管理面，暂停、继续、清除、未完成清除确认和时间线能力不变。
- 新会话创建继续执行“建立原生 thread → 绑定目标 → 启动首轮”；目标输入已退出时，暂存目标不会随普通消息误提交。
- `/goal`、`/goal <objective>`、`/goal pause`、`/goal resume`、`/goal clear` 与按钮使用同一组目标动作；PLAN 选择不被目标输入改写。
- 尚无目标时，`pause`、`resume`、`clear` 这些生命周期保留词不会被误建成目标正文。
- 样式只使用会话语义变量，浅色、深色和系统主题沿用同一套主题映射。
