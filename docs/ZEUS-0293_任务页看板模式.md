# ZEUS-0293 任务页看板模式

## 任务目标

在任务页增加“列表 / 看板”一级视图。看板按当前项目的真实任务字段动态分组，支持主分组、子分组、筛选、排序、卡片配置、分组统计、条件颜色和可持久化拖动排序；任务内容修改继续复用既有版本冲突、终态清理、任务事件、审计和实时同步规则。

## 净室实现边界

- 参考 Notion 看板公开可观察的布局和交互，不复制其源码、商标、字体、品牌色或专有素材。
- 界面继续使用 Zeus 语义 token、任务领域字段和原有详情组件。
- 不引入 Notion 数据库、权限、自动化或多人协作模型。
- 不生成 mock 任务或占位业务图片；预览只读取任务已经关联且可受控读取的真实图片附件。

## 已确认设计

- 一级视图默认列表并按项目记住；原“层级 / 平铺”仅属于列表布局。
- 看板默认按项目管理状态分组，状态名称、颜色、顺序全部来自项目配置。
- 排序按项目、布局、分组、子分组和任务出现位置持久化；标签分组允许同一任务出现于多个真实标签组。
- 跨组拖动会修改对应任务字段；派生字段只允许列内排序。
- 详情默认右侧抽屉，并可切换居中预览或工作区全页。
- 拖动同时提供键盘操作、实时播报和“移动到”菜单。

## 数据库迁移

- 迁移号：`20260815_0001_task_board_schema`，幂等执行且不写入 seed 业务数据。
- `task_board_views`：每项目一行，保存清洗后的配置 JSON、修订号和创建/更新时间。
- `task_board_positions`：主键为项目、布局键、分组、子分组、任务；保存稀疏整数位置。`idx_task_board_positions_lane` 支持按泳道和序号读取。
- 布局键由“主分组:子分组”组成；切换布局不会覆盖其他布局的历史排序。
- 正常插入使用相邻序号中点或边界间隔；只有相邻位置无空间或泳道序号不完整时，才以 `1024` 间隔重排目标泳道。

## 接口和并发契约

- `GET /api/projects/:projectId/task-board`：读取项目配置、修订和位置。
- `PATCH /api/projects/:projectId/task-board`：携带 `expectedRevision` 和设置增量；冲突返回 `409`、最新修订和看板快照。
- `POST /api/projects/:projectId/task-board/moves`：携带任务更新时间、看板修订、来源/目标泳道和前后锚点。
- 移动状态、标签和父任务时，服务端通过既有任务领域接口执行真实更新，继续产生任务事件、审计和实时通知。
- 状态终态移动继续要求工作区清理确认；标签只替换来源标签；父任务继续校验同项目、最大三级、自身引用和循环依赖。
- 执行状态、分支状态和任务来源属于派生字段，跨列请求返回 `ZEUS_TASK_BOARD_DERIVED_GROUP_READ_ONLY`。
- 属性排序启用时，同泳道手工移动返回 `ZEUS_TASK_BOARD_SORT_ACTIVE`；跨泳道仍允许修改真实属性。
- 服务端用完整项目任务重建目标泳道，筛选界面只传可见锚点，因此未显示任务的相对顺序不会被丢弃。

## 前端结构和性能

- `TaskWorkspace` 保留共享两行工具栏；列表与看板是互斥工作区。看板使用 `React.lazy` 动态导入，`@dnd-kit/core` 和 `@dnd-kit/sortable` 只进入看板异步脚本块。
- 看板派生层以稳定出现位置 ID 表达标签多选卡片，使用 `Map` / `Set`、`useMemo` 和记忆化卡片组件；列使用 `content-visibility` 和固有尺寸避免整板同步布局。
- 指针传感器设置移动阈值，触控使用短按延迟；横向列容器和纵向子组泳道分别滚动，拖动时显示独立浮层和目标轮廓。
- 设置保存或移动冲突时，App 读取服务端最新快照；看板恢复拖动前状态并通过实时播报说明失败，不留下伪更新。
- 卡片打开方式写入项目看板配置；三种详情都复用 `TaskDetailPaneContent`，不复制详情业务逻辑。

## 视觉重做

- 采用开放冷白画布，列保持等高细轨道；取消整列状态色背景、粗彩色边框和大面积色块。
- 状态色只出现在列头圆点与卡片左侧细线，用于快速定位，不与卡片正文争夺视觉注意力。
- 卡片统一中性表面、细边框和轻阴影；任务编号使用弱化等宽文字，优先级、类型和标签保留紧凑属性块。
- 卡片“移动到……”从占满整行的原生下拉收成悬停或键盘聚焦时出现的箭头入口，仍保留原生选择框、读屏名称与等价移动能力。
- 分组、子分组、隐藏和拖动使用 Phosphor 图标，不再使用 `⠿`、`−` 等文本字符模拟图标。
- 移除看板内部第三层命令条，“看板设置”并入任务页右上角的视图动作，与“列表 / 看板”切换相邻。

优点：首屏层级从“工具条和列容器”回到任务本身，跨列扫描更快，长时间使用的色彩疲劳明显降低。

代价：列色不再形成大面积区域识别；隐藏和移动等低频控件默认降低可见度，需要悬停、聚焦或触控环境才完整显现。

## 取舍

优点：任务阶段、优先级、类型、标签和父子关系可以在同一工作面直接维护，视图状态与任务事实保持一致。

代价：多选标签会形成多个卡片出现位置；筛选与属性排序同时存在时，需要使用稳定锚点和修订号避免覆盖其他窗口的排序；新增拖拽依赖会增加看板按需加载包体。
