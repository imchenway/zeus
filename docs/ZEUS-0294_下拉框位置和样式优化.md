# ZEUS-0294 下拉框位置和样式优化

## 任务目标

- 修复新会话顶部项目、分支下拉框相对父容器定位导致的打开位置错误。
- 统一项目、分支、模型和推理强度入口的下拉浮层、搜索框、选项行和焦点样式。
- 删除菜单壳层与选项列表同时滚动造成的双滑块。
- 复用现有 `ZeusSelect`，不再为会话页维护第二套搜索、定位、键盘和滚动实现。

## 现状与根因

- 项目和分支入口由 `NewConversationExecutionContext` 使用绝对定位的业务弹层，浮层仍处于会话输入区的布局和裁剪上下文中。
- 模型和推理强度由 `ComposerDropdown` 使用另一套绝对定位菜单；菜单壳层和内部选项列表都可能纵向滚动，因此长模型列表出现两条滑块。
- 两套业务弹层分别绘制搜索容器和输入焦点状态，又叠加应用全局输入框状态，形成截图中的多重边框和焦点环。
- 全局 `ZeusSelect` 已实现 portal 固定定位、上下展开、首帧最终宽度、搜索、分组、键盘、焦点恢复和单一列表滚动，但上述入口没有复用。

## 实施决策

- `ComposerDropdown` 收敛为 `ZeusSelect` 的会话页薄封装，只保留触发器图标、紧凑尺寸和会话工具栏布局差异。
- 新会话项目和分支入口直接使用 `ZeusSelect`；项目路径进入真实搜索文本和选项文案，分支占用状态继续保留不可用原因。
- “创建并检出新分支”作为分支列表中的明确操作项，选择后打开现有原生表单语言的模态弹窗；创建、检出和错误链路不变。
- 下拉浮层统一只让 `zeus-select-listbox` 纵向滚动，popover 壳层和搜索行不再各自生成滚动条。

## 方案取舍

优点：

- 三类入口共享同一定位和交互事实，修复位置、样式与双滑块后不再由页面级实现各自漂移。
- 搜索、方向键、Escape、Tab、焦点恢复、分组和视口边界统一获得现有原语能力。
- 删除重复状态和事件监听，后续修改下拉框只需要维护一个实现。

代价：

- 项目选项从业务自绘的两行图标布局收敛为标准单行选项，长路径在视口上限处省略，完整内容由可访问名称和搜索继续覆盖。
- 新建分支从菜单内嵌输入改为独立小弹窗，多一次明确的表单层切换，但避免把任意表单能力塞进通用下拉原语。
