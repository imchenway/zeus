# ZEUS-0296 点击开发计划没有在右侧预览

## 问题现象

会话中的开发计划已经正常显示为计划卡片，但点击卡片右上角的“在右侧打开”后，右侧没有显示计划正文。

## 根因

同一份计划在本地持久化和供应商事件中存在两套标识：本地记录 ID 与供应商事件 ID。原实现点击计划时优先保存本地记录 ID，随后又遍历当前会话条目，用本地记录 ID 或供应商事件 ID 重新查找计划。

实时事件合并会把计划收敛到供应商事件对应的渲染条目，本地记录 ID 不保证继续存在。此时右侧上下文已经进入“计划”状态，但无法重新找到计划条目，所以只能打开没有正文的右侧空壳。

## 修复方案

- 右侧计划工作区改为保存 `NativeSessionItemBuffer.key`。这个 key 是当前渲染状态的稳定索引，也是 `state.items` 的真实键。
- 点击计划、判断卡片是否已在右侧打开、读取右侧计划正文，三处统一使用同一个 key。
- 右侧直接从 `state.items[key]` 获取原计划对象，不复制计划正文，因此流式更新和持久化回放仍共用同一份数据。

## 方案权衡

### 优点

- 消除本地记录 ID 与供应商事件 ID 切换造成的查找失败。
- 修改范围只落在会话展示层，不改变计划持久化、事件协议和历史数据。
- 不新增计划副本，右侧预览能继续跟随同一计划条目的内容变化。

### 缺点

- 右侧预览仍依赖当前会话状态中的计划条目；如果计划条目被真正删除，预览不会保留离线副本。这符合当前右侧工作区“展示当前会话内容”的产品边界。

## 验收口径

1. 打开包含已完成开发计划的会话。
2. 点击计划卡片的“在右侧打开”。
3. 右侧出现计划工作区并显示所点击计划的完整正文。
4. 左侧计划卡片收起为计划入口；关闭右侧后恢复卡片展示。
5. 不影响会话浏览器、智能体、源码预览和变更审核等其他互斥右侧工作区。
