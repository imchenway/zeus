# ZEUS-0296 开发计划右侧预览返修

## 问题现象

开发计划正文已完整显示在会话时间线，但点击“在右侧打开计划”后，右侧只打开工作区空壳，没有正文。历史、归档或只读会话中还会直接丢失这个只读入口。

## 返修根因

早期修复把右侧计划保存为 `NativeSessionItemBuffer.key`，再由外层 `SessionWorkspace` 从 `state.items` 中二次查找。该方案只覆盖当时的实时计划条目。

后续 Snapshot V2 将 PLAN 持久化在轮次快照中，`ConversationTranscript` 会通过 `projectPersistedTurnPlans` 在正文切片内临时还原计划。这类计划可以在左侧正常渲染，却不一定存在于外层 `state.items`。点击后虽然进入 `plan` 工作区，但按 key 二次查找必然得到空值，所以右侧没有正文。

同时，打开计划被错误地与编辑、发送等写操作共用 `transcriptInteractionsEnabled` 门禁，导致历史、归档和只读会话不能打开本地只读预览。

最近的会话切片重构还在 `createConversationTranscriptStateSelector` 中清空了 `planImplementationRequests`，而历史计划投影正使用该列表判定轮次计划是否为正式产物。这会让只存在于 Snapshot V2 轮次中的计划无法重新投影。

旧文档中“稳定 key 可以跨切片查询”的前提已经不成立，不再作为当前方案。

## 实施方案

- `SessionContextWorkspace` 的计划状态直接保存用户点击的完整 `NativeSessionItemBuffer`，右侧直接渲染该对象，不再从外层状态切片二次查找。
- 正文区域接收“当前打开计划”，依次按 `key`、`providerItemId`、`localItemId`、`itemId + turnId` 判断是否为同一计划，兼容历史水合和规范化过程中的换键。
- 打开计划是只读本地操作，不再受 `historyOnly`、归档或只读门禁影响；编辑、发送、变更审核等既有权限不变。
- 外层工作区资源切片不再保留计划正文，避免整个工作面因计划数据变化而无关重渲染。
- 正文切片保留它已经使用的 `planImplementationRequests`，让 Snapshot V2 轮次计划能被识别为正式产物；其他切片仍按原规则裁剪。
- 不修改服务 API、数据库、Provider 协议、历史数据、计划卡片样式、下载、复制或反馈能力。

## 方案权衡

### 优点

- 消除跨状态切片换键和条目缺失造成的空壳，右侧使用的就是用户实际点击的完整计划。
- 活动与历史会话共用同一条本地只读预览路径，权限边界更准确。
- 外层工作区不再订阅计划正文，减少无关重渲染。

### 缺点

- 面板打开期间不会吸收计划完成后异常发生的正文改写；关闭后重新打开即可取得最新对象。
- 计划对象只存在于当前组件生命周期，不持久化；切换会话仍按既有逻辑关闭右侧工作区。

这个权衡成立的前提是打开按钮只在计划完成后出现，正常流式增量不会在面板打开后继续写入。

## 验收口径

1. 活动及历史会话点击“在右侧打开计划”。
2. 右侧立即出现计划工作区，并包含所点击计划的完整首尾正文。
3. 左侧计划卡片切换为计划入口；关闭右侧后恢复完整计划卡片。
4. 浏览器、源码、变更审核与计划继续共用唯一右侧工作区，互相打开时替换而非叠加。
5. 可见点击未完成时必须明确标记，不以 lint、typecheck、build、打包、启动或健康检查替代。
