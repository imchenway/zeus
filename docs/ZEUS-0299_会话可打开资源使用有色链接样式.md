# ZEUS-0299 会话可打开资源使用有色链接样式

## 任务目标

- 让会话正文中已经通过受信资源链确认可打开的文件、源码位置和网页链接，稳定显示为 Codex 式蓝色行内引用。
- 保留文件类型图标、行号、悬停下划线、键盘焦点和打开失败状态。
- 不把普通路径、日志、命令或无法取得资源权限的 Markdown 文本伪装成可点击链接。

## 现状与根因

- `ConversationInlineResource` 已把可打开资源渲染为语义按钮，资源归一化、Main 进程复验和打开路由均已存在。
- `session-inline-resource` 也已声明蓝色文字、透明背景和紧凑行内尺寸。
- 会话工作区后续存在通用 `button { color: inherit; min-block-size: 28px; }` 规则。该规则包含元素选择器，优先级高于原资源类选择器，因此最终把资源按钮重新染成正文色并撑高行盒。
- 这属于样式优先级问题，不需要放宽资源识别或本地文件权限。

## 实施决策

- 把资源基础规则收窄为 `button.session-inline-resource`，与通用按钮规则具有相同优先级，并利用现有样式顺序恢复资源自己的蓝色和紧凑尺寸。
- 保持不可用资源为正文色；只有真实 `ConversationResource` 才进入蓝色按钮样式。
- 保持现有 `--session-accent`、深浅主题、hover、focus-visible 和错误色，不引入 Codex 品牌 token 或复制外部品牌资源。

## 方案取舍

优点：

- 改动只作用于会话行内资源，不会改变输入区、工具栏、确认按钮或其他业务按钮。
- 蓝色继续表达“已经可打开”，视觉含义与真实权限一致。
- 同时恢复行内尺寸，避免文件引用抬高普通正文行。

代价：

- 选择器明确依赖当前语义元素是 `button`；以后若组件改成其他交互原语，需要同步调整选择器。
- 未识别或已失效的资源仍保持普通正文色，用户不能仅凭文本猜测它可打开；这是受信资源边界的必要限制。
- 内置浏览器现在在网页加载完成前就返回“已打开”；后续自动化如需操作页面内容，必须依据 `loading` 状态或显式等待目标元素，不能把标签已创建误当成页面已加载。

## 验证口径

- 工程门禁：`pnpm lint`、`pnpm typecheck`、`pnpm build`、`git diff --check`。
- 渲染核对：真实生产 CSS 下，可打开文件/网页资源使用蓝色，图标与文字同色，hover 出现细下划线，键盘焦点可见；不可用资源保持正文色。
- 真实应用验收只能使用独立身份 `Zeus Test.app` 与独立用户数据目录，不启动或修改正式 `/Applications/Zeus.app`。
