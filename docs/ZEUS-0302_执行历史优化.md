# ZEUS-0302 执行历史优化

## 目标

改善命令执行历史在大屏上的阅读空间，并收敛终端日志复制按钮的视觉层级，不改变执行记录、完整日志读取、剪贴板校验和产物预览协议。

## 现状证据

- 执行历史弹窗宽度上限为 `1080px`，双栏内容区高度上限为 `600px`；大屏上路径、长日志和产物区仍需要在较小区域内频繁滚动。
- 日志复制入口使用带文字的全局按钮原语；命令页尝试改成透明工具条样式，但后加载的原语样式会恢复明显底色和边框，成功后形成突兀的“已复制”胶囊。
- 现有复制语义仍正确：按运行身份重新读取本次运行完整日志，只有剪贴板写入成功后才进入成功态。

## 已确认产品口径

- 弹窗采用“适度放大”，不改成近全屏工作台。桌面最大宽度约从 `1080px` 提高到 `1320px`，主内容高度同步增加约 20%；窄窗口继续自适应单栏。
- 历史列表、执行详情、实时日志、停止操作和产物全部保留，不改信息架构。
- 复制入口改为 `28px` 纯图标工具条按钮；默认为复制图标，复制中为忙碌图标，成功为勾选，过大或失败为警告图标。
- 成功勾选保留约两秒后恢复复制图标；成功、失败和日志过大仍通过可访问名称、悬停提示与 `aria-live` 表达完整状态。

## 方案取舍

### 采用方案

只扩大执行历史弹窗的响应式上限，并把日志复制改为独立图标操作。

优点：改动集中在执行历史组件与样式，能直接利用更多大屏空间，同时保留日志读取和剪贴板的已验证安全边界。

缺点：弹窗仍不是全屏，极长日志继续使用局部滚动；纯图标入口需要悬停才能看到完整文字说明。

### 未采用方案

- 近全屏弹窗：阅读空间最大，但会弱化轻量弹窗的层级，用户已明确选择适度放大。
- 带文字透明按钮：操作含义更直接，但占用更多水平空间，用户已明确选择纯图标。
- 成功勾选保持到切换记录：成功状态更持久，但同一日志再次复制的入口语义不够清楚。

## 实施记录

- 2026-08-15：完成强制需求澄清与共同确认；不新增领域词汇或 ADR。
- 2026-08-15：执行历史弹窗改为 `1320px` 宽度上限、`720px` 内容高度上限，并继续受视口安全边距与窄窗口单栏规则限制。
- 2026-08-15：终端日志复制改为独立纯图标按钮，补齐忙碌图标、两秒成功恢复、失败图标、可见焦点和减少动态效果分支。
