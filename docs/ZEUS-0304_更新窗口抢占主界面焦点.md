# ZEUS-0304 更新窗口抢占主界面焦点

## 用户现场

- Homebrew 下载更新期间，macOS 原生更新窗口持续展示下载进度。
- 用户所说的“抢占主界面光标”已确认是更新窗口反复拿走键盘输入焦点，不是移动鼠标指针。

## 已确认代码事实

- `UpdateProgressPanel.swift` 的 `applyState` 在进度状态包含 `present` 时调用 `showPanel()`。
- `showPanel()` 对已可见窗口执行 `panel.makeKey()`，并始终执行 `NSApp.activate(ignoringOtherApps: true)`。
- Homebrew 下载进度会持续发布状态，因此更新窗口可在用户已回到 Zeus 主窗口后再次成为键盘主窗口。
- 上述 AppKit 调用可以解释键盘焦点和窗口激活被抢占；它们本身不会移动鼠标指针。

## 与已有产品契约的冲突

- `CONTEXT.md` 将“非阻断更新进度窗口”定义为不锁定 Zeus 主窗口、不暂停用户输入和执行轮次。
- 更新窗口持续抢占键盘焦点，虽然没有用模态层锁死主窗口，但会直接打断用户在主窗口的输入，与该契约冲突。

## 待用户确认的产品语义

1. 已确认“抢占光标”指“更新窗口反复拿走主窗口的键盘输入焦点”，不是鼠标指针被移动。
2. 已确认用户显式打开更新窗口时允许它获得一次键盘焦点，后续进度刷新只更新内容、绝不再激活窗口。
3. 已确认用户切回 Zeus 主窗口或其他应用后，更新窗口保持原有层级，不再被进度事件带回前台。

## 候选方向与取舍

### 只在用户显式打开时获得一次焦点（推荐）

- 优点：点击更新提醒、菜单检查更新或通知时，操作结果立即可见且可用键盘操作；下载刷新不会打断主界面输入。
- 缺点：需要明确区分“用户要求显示”和“后台状态刷新”，原生辅助程序协议会增加少量语义。

### 更新窗口从不获得键盘焦点

- 优点：对主界面输入干扰最小。
- 缺点：用户显式点击更新入口后仍需再点一次窗口才能用键盘操作，与 macOS 对显式打开辅助窗口的常见反馈不一致。

## 实现结果

- 原生更新辅助程序把窗口显示拆成两种明确动作：`show` 是用户显式打开，允许激活一次；`state` 是被动状态刷新，只更新内容与首次可见性。
- 已可见或已最小化的更新窗口收到进度刷新时，不再执行应用激活、成为键盘主窗口、恢复最小化或再次置前。
- 手动检查更新与侧边栏更新入口在发布当前状态后只调用一次显式显示；后续检查、下载、校验状态继续走被动刷新。
- 精确重启失败发生在旧 Zeus 已退出之后，仍允许主动展示恢复信息，避免失败提示隐藏在其他窗口后方。
