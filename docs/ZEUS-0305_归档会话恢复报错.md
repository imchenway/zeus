# ZEUS-0305 归档会话恢复报错

## 当前阶段

已完成现状核对、需求确认、实现、工程门禁和隔离恢复验证。

## 用户反馈

- 用户在“设置 → 缓存与数据 → 已归档会话”点击恢复后，顶部显示 `No archived rollout found for thread id ...`。
- 用户确认：底层原生会话已经可用时，Zeus 应自动核对并恢复；只有原生会话真实缺失或损坏时才报错。

## 正式现场只读证据

- 目标 Zeus 会话记录为 `transport_kind=codex_native`、`agent_kind=codex`、`provider_state=archived`、`archived=1`。
- 会话记录保存的 Provider thread ID 与截图一致，Provider JSONL 真实存在，内容没有丢失。
- 对应 JSONL 位于 Codex 的活动 `sessions` 目录，不在 `archived_sessions`；因此 Provider 当前不接受 `thread/unarchive`。
- Zeus 归档审计已经存在，说明当前异常是“会话归档状态漂移”，不是会话删除或文件缺失。

以上核查只读取正式数据库、日志索引和文件元数据，没有修改正式数据库、Provider 文件或用户会话。

## 根因

恢复编排只读取 Zeus 持久的 `providerState=archived`，随后无条件调用 Provider `thread/unarchive`。当同一 Provider thread 已经位于可续接状态时，Provider 会准确返回“找不到已归档 rollout”，但 Zeus 没有继续核对该 thread 是否已经可读取和续接，于是把可安全收敛的状态漂移显示成恢复失败。

既有 ZEUS-0281 修复了 `CODEX_HOME` 漂移和 Pi 会话误走 Codex 协调器，但没有覆盖 Zeus 归档投影与 Provider 当前线程状态已经分叉的情况。

## 确认方案

1. 正常情况继续先调用 `thread/unarchive`。
2. 只在 Provider 明确返回“找不到已归档 rollout”时，允许继续复用原 Provider thread ID 做原生续接。
3. 续接成功后继续读取同一 thread 的权威快照，并复验两次返回的 thread ID；全部成功才把 Zeus 本地状态收敛为未归档。
4. 历史轮次补齐遇到无效或越出会话执行根的文件路径时，继续拒绝该文件资源，但允许同一 thread 的其余消息和状态完成恢复；实时文件变更不放宽。
5. 其他取消归档错误、续接失败、线程缺失、历史补齐错误或快照读取失败继续原样失败，并保留已归档记录供重试。

优点：截图中的会话可以通过原“恢复”按钮自愈，不需要手改数据库、复制 JSONL 或创建承接会话；一条已被安全边界拒绝的历史文件资源不会永久锁死整条会话。代价：恢复时多两类窄错误分类；Provider 错误文字未来变化时需要同步更新分类；越界文件记录不会提供文件卡、撤销或重新应用能力。

## 安全边界

- 不创建新产品会话或 Provider thread。
- 不移动、复制、删除或改写 JSONL。
- 不重发任何用户消息。
- 不把无效、越界的历史文件路径接纳为变更集或可打开资源。
- 不改变任务管理状态、任务工作区或 Git 状态。
- 设置页恢复、任务重新打开和失败补偿继续复用同一恢复编排。

## 验收口径

- Provider thread 正常归档时，恢复仍完整执行 `thread/unarchive → thread/resume → thread/read`。
- Zeus 记为归档但 Provider thread 已经可用时，恢复跳过唯一可忽略的“找不到已归档 rollout”错误，并在续接和权威读取成功后恢复 Zeus 会话。
- 历史补齐中的无效、越界文件路径仍被拒绝，但不会阻断同一会话的其余历史和状态恢复。
- Provider thread 真实缺失或任一后续复验失败时，恢复继续报错，Zeus 会话保持归档。
- 不新增或恢复单元测试体系；验证使用静态门禁、构建和隔离运行探针。
