# ZEUS-0306 会话排队消息与阻塞询问布局修复

> 后续修订：ZEUS-0313 已确认普通用户询问应固定在会话底部交互坞、位于会话记录滚动区之外。本文“紧跟当前过程末尾”的内容保留为当时实施事实，当前有效口径见 `docs/ZEUS-0313_选项卡位置固定.md`。

## 当前阶段

用户已确认产品口径；实现、静态门禁、构建、独立测试包和可达范围内的真实运行检查已完成。隔离身份没有可用 Provider 会话，活动轮次排队与真实询问布局仍缺少目标状态的图形界面验收。

## 用户现场

1. 输入框发送消息后，新轮次会预留约三分之二对话区高度的回复占位，最新消息没有稳定显示在底部。
2. 活动轮次期间发送的下一条消息同时进入会话记录并出现在后续消息区，提前污染真实对话顺序。
3. 普通用户询问固定在底部交互坞，新轮次回复占位仍然保留，两者叠加形成大块无意义空白。
4. 后续消息区默认收起，用户无法直接看到刚刚排队的完整内容。

## 已确认口径

- 会话空闲时发送的消息立即进入会话记录，并自动显示到最新内容。
- 会话进行中发送的消息在 Provider 真正接收前不进入会话记录，只显示在输入框上方的后续消息区。
- 后续消息区默认展开；多条消息全部可见，并继续支持编辑、删除、排序和引导。
- 当前回复结束、Provider 真正接收队列消息后，该消息才迁入会话记录，并自动显示到最新内容。
- 阻塞询问卡紧跟当前过程末尾，保留正常内容间距，不再被空白回复占位压到窗口底部；普通输入框仍由询问卡替换。
- 用户主动向上滚动后停止自动跟随，并保留“返回最新消息”入口。

## 方案取舍

优点：

- 会话记录只表达 Provider 已接收的真实输入，排队状态不会冒充已发生的对话。
- 队列内容靠近输入区且默认可见，发送结果和后续管理路径清楚。
- 询问与产生询问的过程连续阅读，不再保留无用途的大块空白。

代价：

- 队列消息被 Provider 接收时会从输入区上方迁移到会话记录，需要保持同一客户端消息身份避免重复或闪烁。
- 多条长队列消息默认展开时会占用更多输入区上方空间，用户可按需手动收起。

## 实施结果

- 会话记录在渲染前根据权威队列身份过滤尚未被 Provider 接收的乐观用户消息；活动轮次发送的后续消息不再先闪入时间线。
- 后续消息区初次出现和队列清空后再次出现时默认展开；用户在同一批队列存在期间手动收起后不会被普通刷新强行展开。
- 队列消息正文不再截断为 96 个字符，展开区保留原始换行并允许长内容自然换行；队列内部继续有界滚动。
- 队列从 `queued` 进入 `dispatching` 但尚未取得 Provider turn 时继续留在后续消息区；取得真实 Provider turn 后才迁入会话记录。
- 明确发送和新 Provider turn 开始时改为自动定位最新内容，删除原先约占对话区三分之二高度的新轮次空白占位。
- 普通用户询问移入会话记录滚动区末尾，普通输入区仍被询问卡替换；询问首次出现时自动进入最新内容视图。命令、文件、权限、MCP 和计划实施确认继续保留既有底部交互坞布局。
- 队列消息取得 Provider 事实后继续复用同一个客户端消息身份，既有持久队列、编辑、删除、排序、引导和失败恢复协议未改动。

## 新增现场：回答批注回显与评论框

### 用户现场

- 回答批注发送后，用户消息只显示 `Response annotations (1)` 和“1 条注释”，看不到被选中的原文与用户评论。
- 点击“添加到对话”后出现的评论框固定在窗口右下角，没有跟随本次选区或编号锚点，而且尺寸过大。

### 当前代码事实

- 每条回答批注的结构化数据仍完整保存原回答项、文字偏移、被选中文字和可选评论；Provider 可读序列化也包含“选中文字”和“用户评论”，数据没有在发送阶段丢失。
- 用户消息正文在没有普通输入文字时使用英文数量占位，消息下方的上下文回显也只读取批注数量，因此真实内容被显示层隐藏。
- 选区快捷条和编号锚点都使用选区几何位置；评论框却由样式固定在视口右下角，组件没有接收或计算本次选区锚点。

### 领域口径

- “回答批注”由原回答位置、被选中的“引用”和用户填写的“评论”共同组成。
- 发送后的用户消息必须直接展示每条引用与评论；数量只能作为辅助标题，不能代替内容。
- 评论框属于回答批注的本地编辑浮层，不是全局表单或会话消息。

### 已确认交互边界

- 评论框锚定鼠标松开后形成的选区末端或用户重新点击的编号锚点，并在窗口滚动、缩放时重新计算；不持续追随指针移动。
- 发送后的用户消息逐条展示被选中的回答引用和用户评论；数量只作为辅助标题。
- 删除英文 `Response annotations (N)` 数量占位，回答批注只发送时使用简体中文展示标题。
- 评论框采用紧凑桌面浮层，自动避让视口边缘；引用在编辑浮层中限行预览，发送后的引用与评论完整显示。

优点：编辑位置与批注对象连续，输入时浮层保持稳定；发送后的消息能直接还原用户真正交给模型的上下文。

代价：超长引用会增加发送后用户消息的高度；编辑阶段只预览前三行，完整原文仍保存在批注数据和发送后消息中。

### 实施结果

- 回答批注编辑器不再使用窗口右下角固定边距；它从结构化回答锚点恢复选区末端坐标，滚动和缩放时重新计算，并根据可用空间在上方或下方显示。
- 编辑器宽度收紧到最多 `300px`，内边距和按钮高度同步缩小；引用最多预览三行，评论输入从两行开始并限制纵向扩展。
- 用户消息回显逐条展示回答引用和用户评论，发送后的引用与评论不截断；代码评论数量仍保留原有辅助摘要。
- 新提交只使用“回答批注”或“代码评论”作为结构化消息展示标题；历史 `Response annotations (N)`、`Code comments (N)` 和新标题都会在存在结构化上下文时隐藏，避免标题与完整批注重复。
- Provider 输入、结构化回答项身份、文字偏移、失败回填和排队恢复字段保持不变。
