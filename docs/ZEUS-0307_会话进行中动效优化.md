# ZEUS-0307 会话进行中动效优化

## 背景

ZEUS-0288 在 2026-08-15 的提交 `4c4b4a7f0b47b3c3e40a2cacd84217c351fc0df0` 中加入了流式 Markdown 容器底部的蓝色短线。它用于替代文本增量反复触发的入场动画，方向正确，但最终视觉脱离正文，容易被理解为没有刻度的进度条。

本任务保留“明确表示会话仍在工作”的产品价值，将其改为正文末尾光标，并统一会话内其他高频加载状态。功能范围只涉及桌面端会话渲染层，不修改 Provider、持久化结构、服务端协议或用户内容；真机验收另修正了一个阻断全新隔离数据库启动的既有迁移调用顺序。

## 已确认设计

- 同一轮正文只有一个“会话活动焦点”，最终回答流式输出优先于仍未终止的旧过程；其他阶段按 Provider 时间线中最后一个运行条目接管。
- 主动等待用户批准、等待输入、暂停、失败、已完成和历史内容保持静态。
- 工作色由主题强调色与次要文字色混合为低饱和蓝灰，呼吸周期为 1800 毫秒，低亮度阶段保留停顿。
- 段落、标题和列表在最后安全文本节点显示 `12×2px` 圆角光标；未闭合代码块和表格显示慢速骨架，结构完成后在块末尾显示光标。
- 思考、工具、计划和图片保留原有文字或语义图标，只让当前焦点的外层容器呼吸；冷加载、重连、提交、浏览器和子代理使用同色系骨架、细环或状态点。
- 减少动态效果时停止循环、扫光、旋转和缩放，保留静态状态标记及文字。

### 取舍

优点是状态焦点稳定、视觉噪声更低，光标与正在增长的内容形成直接关系；独立的功能型加载仍能及时反馈操作结果。代价是活动焦点必须由 React 根据真实条目状态推导，不能仅靠 CSS 对所有 `active` 节点同时播放动画。

## 实现记录

- `ConversationTranscript` 直接从当前轮条目推导内部 `SessionMotionFocus`，不新增持久状态或副作用同步；组件只接收 `motionActive` 布尔值。
- `ThreadItemView` 为流式 Markdown 标记最后一个安全段落、标题或列表项，并用 CSS 伪元素绘制光标；代码块、表格及没有安全锚点的内容使用块后降级光标。装饰光标不写入 Provider 正文或复制内容。
- 会话 CSS 末尾建立最终生效的工作态变量、呼吸、扫光和细环规则，删除 ZEUS-0288 的悬空蓝线及其关键帧，不整理无关历史样式。
- 推理、活动、计划步骤和重连图标只动画外层容器；提交、上下文读取、浏览器标签和子代理加载共用统一细环或呼吸节奏。
- 真机 Provider 轨迹发现流式骨架的三条占位线会被浏览器计为三个循环实例；最终改为三条静态轮廓、骨架外层统一呼吸，使未闭合结构也严格只有一个循环实例。
- 开发态样例通过 `/qa/session-styles.html?motion=1` 同时提供浅色、深色、单焦点、未闭合结构、冷加载和功能型加载真实 DOM。
- 为解除全新隔离测试目录的启动阻断，将 Agent 会话身份迁移提前到 Codex 用量身份迁移之前；后者会读取前者创建的 `conversations.model_source_id`。该调整只修正既有迁移依赖顺序，不新增字段或改变 Provider 协议。

### 开发态 DOM 证据

- 当前回答列表的最后安全节点带 `data-streaming-tail-anchor="true"`，降级光标带 `aria-hidden="true"`。
- 活动焦点的计算动画数量为 1；已经失去焦点的推理与工具条目计算动画均为 `none`。
- 最终 CSS 只让 `motionActive` 对应的计划、推理、工具图标或流式正文在轮次正文内循环；正文外的计划进度停靠条与其他功能型加载保持各自语义图形。
- 未闭合代码块和表格的骨架外层分别计算为唯一 `session-working-breathe`，三条内部占位线均为 `animation: none`；冷加载仍使用慢速扫光；提交、浏览器、子代理和重连分别保留细环、状态点或外层呼吸。
- 计划与图片样例是两个相互独立的组件状态，不代表同一轮正文同时存在两个活动焦点；单轮约束以 `motion-single-focus` 真实会话正文为验收边界。

### 真实 Provider 轨迹

- 第一轮完成“思考 → 过程说明 → 终端读取 → 最终回答 → 完成”，最终回答为“根目录 package.json 的 name 是 zeus，version 是 0.3.15。”。
- 为让工具阶段可稳定采样，后续使用 `sleep 3` 和 `sleep 5` 的无写入命令；运行时 `.session-activity-item-icon` 外层的计算动画为 `session-working-breathe`，同轮循环实例数为 1。

### 真机边界

最终启动命令显式移除了开发终端继承的 `ELECTRON_RUN_AS_NODE`，并设置 `ZEUS_USER_DATA_DIR=/tmp/zeus-0307-gui.RAuZHK`。进程参数确认 Electron profile 位于该隔离目录。首次新库启动暴露 `migrateCodexUsageLedgerSchema` 早于 Agent 身份迁移执行、读取尚不存在的 `model_source_id`；调整顺序后同一隔离目录完成初始化，迁移登记和数据库快速检查均正常。

验收使用测试包窗口的 DevTools 协议读取真实 DOM、计算样式、媒体偏好和截图；Zeus 内置浏览器仍用于打开验收页面并核对语义树，但其标签报告视口为 `0×0`，因此没有把空截图当作视觉证据。所有有效截图来自同一个已确认在外接屏上的测试应用真实渲染目标，视口为 `1240×820` 或窄窗口模拟的 `560×820`。

官方安装器按应用给出的命令把 Codex CLI `0.147.0` 安装到隔离 `CODEX_HOME`。安装器曾附带向用户级 `.zprofile` 写入该临时目录 PATH；该三行安装器标记块已经精确移除并复核，不保留全局终端配置污染。用户明确批准后，通过系统 Chrome 中已有 OpenAI 登录态为该隔离目录完成 OAuth；没有复制主 Zeus 的账号文件、密钥、历史会话或生产用户数据。

在定位 `ELECTRON_RUN_AS_NODE` 影响前，系统启动方式曾短暂打开同一任务构建的 `Zeus Test.app`，但没有继承指定的隔离目录，因窗口落在主显示器而立即终止；该次尝试不计入验收。它仍使用测试身份及默认测试 profile，没有启动生产 `Zeus.app`，遗留的测试 profile 未做破坏性删除。
