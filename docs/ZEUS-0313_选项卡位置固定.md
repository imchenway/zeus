# ZEUS-0313 选项卡位置固定

## 当前阶段

产品口径、领域词汇和 Renderer 布局归属修改已完成；格式、静态检查、构建、测试包身份和隔离启动均已通过。隔离身份没有可运行的模型供应商或已登录 Provider，因此真实询问交互仍保留动态验收缺口。

## 用户现场与根因

- 普通用户询问显示在会话记录末尾，因此会随着历史消息一起滚动，无法稳定停留在底部。
- `SessionWorkspace` 把 `request_user_input` 作为 `ConversationTranscript` 的尾随内容传入，并用请求身份强制消息区滚到最底部。
- `session.css` 另有一条只适用于“交互坞是时间线子节点”的覆盖规则，使普通用户询问与其他阻塞交互使用了不同布局归属。
- 这与既有“底部交互坞不得进入会话记录滚动内容”的总设计契约冲突。

## 已确认产品口径

- 用户口中的“选项卡”统一称为“底部交互坞”。
- 普通用户询问、计划实施确认、命令、文件、权限和 MCP 请求都固定在会话底部，位于会话记录滚动区之外。
- 底部交互坞出现时替换普通会话输入区，不同时保留两个主操作区。
- 会话记录独立滚动；长询问只在底部交互坞内部滚动，不用固定或悬浮定位覆盖消息。
- 请求解决后，已回答询问记录继续按答案提交时间进入会话时间线。

## 实施范围

- `SessionWorkspace` 不再为普通用户询问建立时间线专用分支，所有阻塞请求统一通过现有底部交互坞渲染。
- `ConversationTranscript` 删除尾随交互属性、请求身份引用和交互出现时的强制滚动副作用。
- `session.css` 删除交互坞作为时间线子节点时的专用覆盖，保留既有底部宽度、最大高度、内部滚动、安全区和窄窗口规则。
- 后端、Provider 响应协议、持久化结构、队列状态和公开 API 不变。

## 方案取舍

优点：待处理交互的位置稳定，滚动历史不会移走当前主操作，也不会通过悬浮层遮挡消息。

代价：长询问会压缩会话记录可视高度，用户需要在交互坞内部滚动查看全部内容。
