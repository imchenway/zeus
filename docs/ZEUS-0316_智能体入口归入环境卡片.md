# ZEUS-0316 智能体入口归入环境卡片

## 任务目标

- 将会话顶部工具栏中的“智能体”入口移动到环境卡片。
- 只有当前会话已经确认存在派生智能体线程时，才显示该入口。
- 保留现有右侧智能体列表、独立线程读取和自动展开能力，不新建第二套智能体状态。

## 现状与问题

旧入口只判断前端是否具备智能体读取接口，没有判断当前会话是否真的存在智能体。因此普通会话也会显示数量为 0 的入口，用户点击后可能得到“智能体读取失败”，把功能能力误当成了当前会话事实。

环境卡片已经集中承载执行目录、分支、变更、命令和代码交付等会话现场信息。智能体属于当前会话的执行环境信息，继续占用顶部常驻工具栏会增加噪音，也与“没有真实来源时不展示业务数据”的设计约束冲突。

## 方案与取舍

以主会话协调事件和权威子线程列表合并得到的线程数量作为显示门槛：数量大于 0 且读取能力存在时，在环境卡片内显示“智能体”行；数量为 0、尚未确认或读取失败时不显示。这里的“大于 0”表示主智能体已经派生至少一个子线程，即会话已经进入多智能体协作，而不是要求至少两个子线程。

- 优点：入口只反映真实会话事实；普通会话不会再因误点触发无意义的读取错误；顶部工具栏更克制。
- 缺点：权威列表预读失败且主会话没有留下协调事件时，即使底层存在历史子线程，入口也会保持隐藏；这是宁可暂不展示，也不伪造可用性的保守降级。
- 取舍：沿用现有子线程预读和协调事件投影，不增加额外探测请求，不执行或检查任何外部 AI CLI。

## 实现范围

- `SessionWorkspace.tsx`
  - 删除顶部工具栏的智能体按钮。
  - 将已合并去重的智能体线程数量和打开右侧工作面的动作传给环境卡片。
- `SessionQuickActionsCard.tsx`
  - 增加按真实线程数量条件渲染的智能体快捷操作行。
  - 点击后继续打开既有 `SubagentWorkspace`，不复制列表或线程状态。
- `session.css`
  - 删除顶部智能体按钮不再使用的专属样式，保留右侧智能体工作面的交互样式。
