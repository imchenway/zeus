# ZEUS-0318 登录与配置导入独立弹窗

## 任务目标

修复任务推送中把账号登录、Codex 配置导入和推送表单堆叠在同一个长弹窗的问题；同时修复官方网页登录完成后流程被 ChatGPT 成功页收口、没有稳定回到 Zeus 的体验。

## 根因

1. `TaskModelPushModal` 同时渲染推送字段、登录提示、配置导入预览和两套动作，导致三个不同用户决策共享正文滚动区与底部按钮。
2. 登录请求显式启用了托管成功页并声明 `appBrand: 'chatgpt'`，因此外部完成页把后续动作表达为 ChatGPT，而不是用户实际发起操作的 Zeus。
3. Zeus 虽然轮询到权威账号状态后会激活窗口，但只激活一次；外部成功页如果在账号回执后继续导航，可能再次抢回前台。

## 实现

- 推送表单只保留本次会话配置和“登录并继续 / 创建新会话”。
- 新增独立登录弹窗，覆盖配置检查、等待官方网页、登录成功和返回 Zeus；取消后回到原推送表单。
- 新增独立配置导入弹窗，只展示允许导入、跳过、导入中、启用和重试；“暂不导入”进入登录，“返回”恢复原推送表单。
- 两个子步骤复用 `ModalPortal` 与全局 `Button`，同一时刻只渲染一个模态面；原推送表单状态继续保存在 `App`，切换不会丢失模型、工作区、权限、补充信息或附件。
- 关闭 Codex 托管产品成功页，保留官方网页登录与 app-server 账号状态作为权威认证链路。
- 登录成功时先激活 Zeus，展示成功反馈后再次激活，再继续创建会话，覆盖浏览器完成页的尾随导航竞态。

## 方案取舍

### 独立分步弹窗并由 Zeus 收口（采用）

优点：每个弹窗只有一个决策；登录与配置迁移不会淹没推送表单；失败或取消后原填写内容仍在；完成后回到实际发起操作的产品。

代价：流程会顺序切换弹窗；系统浏览器标签不能由 Zeus 安全代关；真实回跳仍需用隔离测试身份完成官方网页登录往返验证。

### 保持一个长弹窗（不采用）

优点：组件数量少，所有内容表面上都在一个容器里。

缺点：账号授权、文件复制与会话创建互相混淆；按钮含义随滚动区内容变化；截图中的信息密度和滚动距离不可接受。

### 自建 OAuth 回调页（不采用）

优点：理论上可以完全控制浏览器完成页。

缺点：会扩大凭据、回调校验和协议升级风险；当前 app-server 协议没有 Zeus 品牌或第三方自定义成功页契约，不应为界面收口接管官方认证。
