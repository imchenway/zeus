# ZEUS-0324 推送任务选择已有任务分支继续

## 任务目标

推送任务到新会话时，Worktree 工作方式必须允许用户明确选择：

1. 创建新的任务分支与独立任务环境；
2. 选择该任务当前已存在且可写的任务分支，继续使用原任务环境与 worktree。

## 现状核对

- 本机服务已经支持通过 `environmentId` 恢复当前未关闭的任务环境，并会重新挂载该环境内缺失但仍可继续的 worktree。
- 当前任务推送能力没有返回已有任务环境，Renderer 请求类型也只允许 `direct / create`。
- 推送弹窗因此只能配置来源分支和新分支，无法触发服务端已有的 `existing` 路径。

## 产品与领域边界

- `TaskEnvironment` 代表一次任务推送形成的完整执行环境；单仓时对应一个任务分支，多仓时包含同一次推送的全部仓库任务分支。
- 继续已有任务分支会创建新会话，但复用原 `TaskEnvironment`、worktree、cwd 和分支，不复用旧会话线程。
- 多仓任务环境必须整体复用，不能只挑其中一个仓库，否则会让会话 cwd 与可写根缺失其余仓库。
- 已回收的环境不再展示；含已合入或已放弃仓库的环境不可继续。
- 已有活动可写会话的环境展示为暂不可用，提交时服务端仍再次复验，避免弹窗打开后状态变化造成并发写入。
- 界面展示真实分支和仓库名称，不把内部 `TaskEnvironment ID` 作为用户文案。

## 方案与取舍

能力接口返回当前任务的已有环境摘要，包含真实仓库、任务分支、来源分支、可用状态和不可用原因。Worktree 区域增加“创建新的任务分支 / 继续已有任务分支”选择；选择继续时隐藏新分支配置，直接提交 `workspace: { mode: 'existing', environmentId }`。

优点：复用关系与持久 cwd 一致，用户可以为同一开发线开启新的会话，且不会重复创建同名分支。

代价：多仓任务环境按整体选择，不能在一次会话里混合“部分旧分支 + 部分新分支”；活动写入结束前也不能开启第二条可写会话。

## 验证口径

- 定向格式检查与 `git diff --check`。
- `pnpm typecheck`、`pnpm lint`、`pnpm build`。
- 检查无历史环境、单仓环境、多仓环境、活动写入、已关闭成员和提交前状态变化。
- 静态检查和构建不替代真实 `Zeus Test.app` 的弹窗、键盘、主题、窄窗口与真实分支复用验收。

## 验收边界

- 本轮没有启动或修改正式身份 `Zeus.app`，没有执行 Git 提交、推送、合入或历史改写。
- 为避免执行未由用户选择的外部 Agent，本轮没有真实发起模型任务；因此服务端真实 Provider 首发与已存在任务分支往返仍属于动态验收项。
- 测试包构建与签名成功只证明可打包，不替代弹窗在浅色、深色、窄窗口、键盘操作及真实多仓数据下的 GUI 验收。
