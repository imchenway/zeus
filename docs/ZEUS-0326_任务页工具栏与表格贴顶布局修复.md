# ZEUS-0326 任务页工具栏与表格贴顶布局修复

## 现状

任务页在高窗口中把搜索框、新任务、状态筛选、视图动作和任务表格分散到不同高度，控件之间出现数百像素无意义空白。任务列表没有成为首屏主角，和 `DESIGN.md` 已规定的“两行主工具条后直接进入表头”相冲突。

## 根因

`task-table-workbench` 是占满任务工作区高度的 CSS Grid。列表模式把工具条和任务列表都放进自动高度轨道，但没有声明纵向内容分布方式。Grid 默认的 `align-content: normal` 会在容器存在剩余高度时拉伸自动轨道：

- 第一条自动轨道把两行工具条拉高，搜索/新任务与状态筛选/视图动作被分别推向远离的位置；
- 第二条自动轨道承载任务列表，少量任务上方和下方继续出现无意义空白；
- 窗口越高，错误越明显，因此普通开发窗口可能不易暴露，外接屏或全屏窗口会直接失控。

这不是任务数据、表格行高或搜索框定位问题，继续增加固定高度、绝对定位或视口比例只会在其他窗口尺寸制造新的漂移。

## 决策

在任务表格工作台的最终布局规则中增加 `align-content: start`，让列表模式的自动高度轨道按真实内容高度从顶部依次排列。

优点：

- 两行工具条恢复为连续的紧凑区域，表头紧随其后；
- 不引入固定像素总高度，宽屏、高屏和普通窗口遵循同一布局；
- 不改变任务数据、筛选、表格列、看板状态或持久化协议。

代价：

- 任务较少时，剩余画布会自然留在表格下方；这是开放工作区的正常留白，不再用拉伸控件填满。

## 边界

- 看板模式继续使用 `auto minmax(0, 1fr)`，看板主体仍占据剩余高度；
- 空任务状态继续由更具体的 `:has(.task-list-empty)` 规则使用拉伸布局，以当前可见列表区为基准居中；
- 本次不调整工具条文案、功能分组、列宽、行高和侧边栏。

## 验收目标

目标动线：进入项目“任务”页，不滚动即可看到紧凑的两行工具条及紧邻的任务表头。

- 高窗口中第一行只包含左侧搜索和右侧新任务；
- 第二行紧接第一行，左侧为状态快捷筛选，右侧为视图与列动作；
- 表头紧接第二行，不再悬在页面中腰；
- 有数据列表、空态、看板和窄窗口不发生裁切或错误拉伸；
- 通过 `pnpm lint`、`pnpm typecheck`、`pnpm build`，并单独记录真实渲染检查结果。

## 实施记录

- 2026-08-18：确认根因是自动 Grid 轨道在高窗口中被剩余空间拉伸，不是任务数据或单个控件定位错误。
- 2026-08-18：在任务表格工作台最终规则中加入 `align-content: start`，保持空态和看板的既有专用布局。

## 剩余风险

- 本次修复只改变 Grid 纵向内容分布，不包含颜色、主题 token 或动效逻辑；浅色真实界面已验收，深色与跟随系统主题未逐一截图。
- 外接竖屏窗口宽度为 `1240px`，覆盖用户截图的高窗口问题；`760px` 以下断点依赖既有响应式规则，本次没有在真实 App 中重新调整窗口到最窄宽度。
