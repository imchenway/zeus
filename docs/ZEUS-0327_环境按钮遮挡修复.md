# ZEUS-0327 环境按钮遮挡修复

## 任务目标

修复会话右侧浏览器工作面打开时，点击顶部“环境”按钮后环境信息卡片被浏览器网页遮挡的问题。

## 根因

- 环境卡片属于 Renderer DOM，普通 CSS 层级只能在 Renderer 内部排序。
- 浏览器网页由 Electron `WebContentsView` 承载，是独立于 Renderer 的原生子视图，天然显示在 Renderer DOM 上方。
- 浏览器标签栏、地址栏和工作面壳层仍属于 Renderer DOM，但右侧工作面使用 `z-index: 33`，标题栏使用 `z-index: 31`。环境卡片自己的高层级被限制在标题栏的层叠上下文内，无法越过右侧工作面。
- 因此只提高环境卡片自身的 `z-index` 无法解决遮挡；只隐藏原生 `WebContentsView` 也无法解决浏览器壳层遮挡。

## 方案与取舍

环境弹层打开时同时处理两类层级：

- 通过现有 `BrowserWorkspace.suspended` 通道暂时隐藏原生网页视图；弹层关闭后恢复原生网页视图。
- 只在环境弹层可见期间把会话标题栏提升到右侧工作面之上，让环境卡片越过浏览器标签栏与地址栏；关闭后恢复原层级。

浏览器标签、网址、页面进程和页面状态不销毁。

优点：

- 直接处理真实层级边界，卡片不会再被原生网页遮挡。
- 同时覆盖浏览器标签栏、地址栏和原生网页两类遮挡，不依赖单一 `z-index` 或单一暂停通道。
- 不改变环境卡片的位置、尺寸、键盘关闭和外部点击关闭行为。
- 不关闭浏览器标签，不触发页面重新加载，也不新增第二套 BrowserHost 协议。

缺点：

- 环境弹层打开期间，网页内容暂时不可见，网页占位区显示 Zeus 自身表面。
- 环境弹层打开期间标题栏临时高于右侧工作面；关闭后立即恢复既有层级。
- 原生视图的隐藏与恢复需要经过现有 IPC，极慢设备上可能存在极短的切换延迟。

## 实现范围

- `SessionQuickActionsCard.tsx`
  - 向会话工作区同步环境弹层的真实可见状态。
  - 常驻环境卡不触发浏览器暂停，仅顶部按钮唤起的弹层触发。
- `SessionWorkspace.tsx`
  - 记录环境弹层可见状态。
  - 浏览器拖动调整尺寸或环境弹层打开时，共用 `BrowserWorkspace.suspended` 暂停原生网页视图。
  - 把弹层可见状态写到标题栏数据属性，作为 DOM 层级切换的唯一依据。
- `session.css`
  - 弹层打开时把标题栏从 `z-index: 31` 临时提升到 `35`，高于右侧工作面及其调整把手；关闭后自动恢复。

## 验收路径

会话页打开浏览器工作面 → 点击顶部“环境” → 环境卡片完整显示在浏览器工作面之上 → 点击卡片外部或按 `Escape` 关闭 → 原网页恢复且标签、网址与页面状态保持不变。
