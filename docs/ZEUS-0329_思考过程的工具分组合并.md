# ZEUS-0329 思考过程的工具分组合并

## 任务目标

把思考过程中连续出现的非命令工具活动（MCP、网页搜索、图片查看、文件变更、动态工具等）合并为同一个活动组，不再逐条显示“已使用 1 个工具”。命令类活动继续与命令合并，思考摘要继续作为分组边界。

## 现状与根因

- `ConversationTranscript.projectTranscriptRows` 已把连续命令活动合并为一个 `SessionActivityGroup`，最多 32 条。
- 非命令工具进入投影时仍执行“先 flush、push 当前项、再 flush”，因此每条工具都成为独立组；长任务中会堆叠大量“已使用 1 个工具”行。
- 思考摘要当前会中断一批活动，但每次中断后两侧的工具仍各自独立成组，进一步放大过程噪音。
- `activitySummary` 已支持“已使用 N 个工具”的口径，但从未收到多条非命令工具，因此数量一直为 1。

## 实现口径

1. 连续的非命令工具活动合并进同一个活动组，最多 32 条；仍不得与命令活动混合计数。
2. 思考摘要、命令活动、非操作条目、已回答询问和轮次切换继续作为分组边界。
3. 失败的工具活动在当前组收口并截断，后续工具重新开组。
4. `contextCompaction` 有独立摘要口径，`providerEvent` 属于技术事件，两者继续独立成组，不参与普通工具合并。
5. 活动组摘要复用现有 `activitySummary`，连续工具自然显示“已使用 N 个工具”；进行中仍显示“正在使用 N 个工具”。

## 方案取舍

采用方案的优点：思考过程中的工具活动从“每条一行”收敛为“一个阶段一个组”，纵向噪音显著降低；命令与工具边界、失败边界和上下文整理语义保持不变。

采用方案的代价：同一组内不同工具会共享一个摘要，用户需展开才能逐条查看具体工具；工具非常密集且超过 32 条时会重新开组。

未采用“整轮所有工具合成一个组”：会跨越思考摘要、失败和不同活动生命周期强行合并，破坏真实执行顺序。本次只合并相邻且未被边界打断的工具。
