# ZEUS-0336 Git 本地变更页面布局缺陷

## 任务类型

缺陷。

## 用户反馈

项目 Git 工作台的“本地变更”页面在真实多仓项目和超长文本差异下出现整体布局失效：仓库名称被挤成逐字换行，分支名称覆盖后续内容，双栏差异的分隔位置逐行漂移，右侧提交栏平铺全部仓库后持续压缩主要审查区域。

## 已核对事实

- 页面使用三列固定下限布局：变更树、差异区和右侧提交栏至少需要约 `960px`，仓库较多时提交栏仍逐仓纵向平铺。
- 仓库标题把仓库名和完整分支名放在同一行，分支列按内容占宽，仓库名缺少省略约束，因此两段长文本会互相挤压。
- 双栏差异的每一行各自计算 `max-content` 列宽，所以每行的左右分界都可能不同；超长 HTML 或 CSS 行会形成阶梯状空白，并把另一侧推到远处。
- 小于 `1180px` 时现有样式直接隐藏提交栏，导致用户看得到变更却找不到提交入口。
- 既有设计契约要求本地变更按真实仓库与暂存状态分组，提交区位于底部并逐仓表达将创建的提交。

## 修复决定

### 仓库与分支身份

- 仓库名称作为第一层身份，分支作为第二行辅助信息；两者都保持单行并在空间不足时省略，完整值通过原生提示保留。
- 变更树只展示真实存在本地变化的仓库，不用零变化仓库填满审查列表。

优点：长仓库名和长分支名不再争抢同一行，用户先识别仓库、再识别分支。代价：每个仓库标题从一行增加为两行，单个仓库分组会多占少量高度。

### 双栏差异

- 左右代码面板固定各占可用宽度的一半，不再由某一行的文本长度决定分界。
- 两侧共用纵向位置并同步滚动，各自保留独立横向滚动；超长行不换行、不覆盖另一侧。
- 差异块标题分别在两侧显示，保证横向滚动后仍能理解当前块位置。

优点：分界稳定、行号对齐，超长单行不会破坏整页。代价：查看超长行需要在对应半栏内横向滚动，左右横向位置不会被强制绑在一起。

### 提交区

- 提交区回到底部并横跨变更树与差异区，不再占用右侧主审查宽度。
- 只列出确实存在已暂存文件的仓库及数量；没有暂存内容时显示真实空状态并禁用提交按钮。
- 窄窗口继续保留提交区，仓库摘要必要时局部横向滚动，不隐藏核心操作。

优点：中央差异获得完整宽度，仓库再多也不会把提交按钮推到视口外。代价：多个仓库同时有暂存内容时，底部摘要需要横向浏览。

## 验收范围

- 多仓项目中的仓库名、分支名、文件树均不逐字换行或互相覆盖。
- 双栏视图的中线从顶部到底部固定，长 HTML/CSS 行只在所属半栏横向滚动。
- 统一视图保持可用，模式切换不丢失差异内容。
- 有暂存内容时底部逐仓显示数量并可打开现有提交弹窗；无暂存内容时提交按钮禁用。
- 宽屏和窄屏都能看到变更树、差异区和提交入口；浅色、深色、系统主题继续消费现有语义色。

已完成实现、静态检查、构建、独立测试身份打包和真实多仓运行核对。未执行 Git 提交、推送、合入、回退或远端操作。

## 实现结果

- 变更仓库列表只投影有本地改动的仓库；进入“本地变更”时自动选中第一个有变更的仓库和有效文件。
- 文件在“未暂存 / 已暂存”之间移动后，保持文件选中并自动切换差异来源，避免暂存操作后跳到不相关文件。
- 双栏差异改为两个固定半宽、独立横向滚动的代码面板，并保持纵向滚动同步。
- 提交区横跨页面底部，只统计真实存在已暂存文件的仓库；零暂存时保留空状态并禁用提交。
