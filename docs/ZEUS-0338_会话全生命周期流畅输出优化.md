# ZEUS-0338 会话全生命周期流畅输出优化

## 用户现场

- 从侧边栏点击会话开始，标题、历史消息、输入区和状态反馈存在卡顿、闪现与分段出现。
- 会话消息加载后的逐步输出仍有明显的停顿感，当前动效没有形成连续、稳定的阅读节奏。
- 用户要求覆盖“点击会话、消息加载、进行中输出、完成收口”的完整生命周期，而不是只调整某一个加载图标。
- 第二轮真实现场显示：当前思考摘要（例如 `Formatting and typechecking code`）会在新进度到达后生硬移动到过程区底部；正在思考的圆圈停止旋转，正在执行命令的图标呼吸也会反复停顿。

## 当前诊断

1. `App.tsx` 仍以会话身份作为 `ConnectedSessionWorkspace` 的 React `key`。每次切换都会卸载并重建标题、正文、输入区、快捷操作和监听器，已有常驻工作区能力没有真正生效。
2. `SessionWorkspace` 的标题在每次重挂载时播放整块入场；若取消重挂载，现有实现又会先保留旧标题 180ms 再换成新标题。两条路径都违背“目标身份立即出现”的契约。
3. `ConnectedSessionWorkspace` 在每个会话状态增量上重新创建完整 `actions` 对象和资源回调。`ThreadItemView` 即使使用 `memo`，也会因函数属性和批注数组身份变化而让历史消息重新渲染。
4. 流式正文每次可见增量都同步读取滚动高度、标记位置并执行 `elementFromPoint`，在主线程上形成强制布局；长会话和 Markdown 重算会与该布局读取竞争同一帧。
5. 冷加载骨架位于正文之外，快照到达时骨架直接卸载、正文直接挂载，缺少稳定的同一内容舞台，容易形成高度突变和闪现。
6. 历史消息没有使用浏览器的离屏渲染隔离，长会话首次切入仍会为屏幕外的大量消息支付布局和绘制成本。
7. 当前思考摘要使用 Provider item 身份作为 React `key`；Provider 用新 item 更新同一轮摘要时，旧节点被卸载，新节点在最新时间线位置重新挂载，形成明显跳位。
8. 命令实时行把 `updatedAt` 和状态写入 DOM `key`，每次进度事件都会重建节点并重启动画；全局单焦点规则又会在命令成为最新活动时关闭思考圆圈的旋转。
9. 呼吸关键帧包含较长停驻区间，且活动图标未显式提升为合成层；主线程处理流式 Markdown 和布局时，视觉上更容易呈现为停顿而非连续呼吸。

## 本次方案

### 常驻工作区，只重建会话控制器与正文身份

- 移除普通会话工作区外层的会话 `key`，保留标题、输入区和主布局 DOM。
- 会话变化时由 `useSessionController` 按新身份同步创建控制器；正文组件按会话身份重建，确保滚动、实时新增标记和读屏追踪不会串线。
- 会话级右侧工作面、目标输入和临时错误在绘制前重置，避免上一会话状态闪入下一会话。

优点：切换不再经历整页卸载与空白首帧，输入区和主布局保持稳定。  
代价：必须显式管理会话级临时状态，不能继续依赖 React 卸载自动清空。

### 目标标题立即接管，动效只表达新身份

- 标题直接从当前会话事实派生，不再保存旧标题等待退出计时器。
- 会话身份变化时只让新标题内容做轻量透明度与短距离入场，不延迟目标标题和状态出现。

优点：点击后的身份反馈即时，同时保留连贯的方向感。  
代价：不再展示旧标题的完整退出过程；快速连续切换时优先保证事实与响应速度。

### 稳定回调与批注投影

- 连接动作按控制器身份缓存，执行时读取控制器最新状态，避免闭包迫使每个增量重建函数。
- 资源、目标、智能体和会话操作按真实会话身份缓存。
- 回答批注一次按消息分组，未变化的历史消息获得稳定数组引用。

优点：流式增量主要更新当前增长消息，历史 Markdown 不再陪同重算。  
代价：回调必须只依赖明确的控制器和会话身份，新增动作时要维护依赖边界。

### 异步可见性观察与离屏渲染隔离

- 使用 `IntersectionObserver` 异步观察最新内容标记，滚动处理只读取滚动距离，不再在每个增量上执行命中检测。
- 历史消息与轮次块使用 `content-visibility: auto` 和保守的固有高度占位，让屏幕外内容跳过布局与绘制。
- 当前活动内容、包含焦点的内容和正在入场的内容关闭离屏跳过，保证输入、展开和流式反馈可靠。

优点：减少主线程同步布局，长历史切换和持续输出更稳。  
代价：浏览器使用估算高度维持离屏滚动范围；极端超高消息首次滚入时仍可能发生小幅滚动校准。

### 同一舞台完成冷加载接管

- 冷加载反馈放入会话正文舞台，使用稳定最小高度和低噪音呼吸；快照到达后由真实内容原位接管。
- 不对整份历史消息播放逐项入场，也不让正文容器整体做大幅位移。

优点：加载到正文不再像两个页面互相替换。  
代价：首次且无热缓存的会话仍需等待权威快照，只能改善真实等待期间的连续性，不能伪造已有消息。

### 活动行保持身份，位置变化交给合成层

- 当前轮次的思考摘要改用“轮次级”渲染身份。Provider 即使创建新的 reasoning item，界面也把它视为同一条实时状态，只更新文字和位置，不再卸载后从底部重建。
- 当前轮次的过程行使用轻量布局过渡；思考摘要从命令之间移动到最底部时，由原位置连续移动到目标位置。
- 命令实时行不再把 `updatedAt` 写进 DOM `key`，进度事件只更新内容，不再反复重启图标动画。

优点：解决现场中“Formatting and typechecking code 突然跳到底部”和命令反馈反复闪停的问题。

代价：活动轮次增加少量合成层；范围只覆盖当前轮次，历史内容仍保持静态，避免长会话长期占用图形资源。

### 思考旋转与命令呼吸按真实状态独立运行

- 活动思考的缺口圆圈只要状态仍为 active 就持续匀速旋转，不再依赖“最新单一焦点”。
- 活动命令的图标只要命令仍未结束就持续呼吸；呼吸关键帧移除长停驻区间，并把周期改为连续的缓入缓出。
- 旋转和呼吸都作用于稳定的 HTML 包裹层，并声明合成提示；系统确实开启“减少动态效果”时仍按无动画契约停用。

优点：思考和命令可同时表达各自仍在进行，且主线程繁忙时更不容易出现视觉停顿。

代价：当前轮次最多同时出现思考旋转与命令呼吸两种循环反馈；为控制噪音，完成项和历史轮次不播放循环动画。
