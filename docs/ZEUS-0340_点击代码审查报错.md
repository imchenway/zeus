# ZEUS-0340 点击代码审查报错

## 当前阶段

## 用户现象

点击会话环境卡片中的“代码审查”并确认后，Zeus 弹出“代码审查启动失败”。错误详情只有“代码审查会话未被接受，请查看当前错误提示”，没有真实失败原因和可执行恢复方式。

## 根因

### 真实错误被二次包装覆盖

1. `App.startNativeConversation` 已经捕获本机 API 的真实失败，并把脱敏后的原因写入任务会话加载状态。
2. 该函数随后只向 `SessionCodeReviewDialog` 返回 `false`。
3. 审查弹窗无法取得原错误，只能再次生成“未被接受，请查看当前错误提示”。
4. 全应用错误弹窗最终显示的是这句二次包装，用户无法判断是模型、登录、执行宿主还是 Worktree 现场不可用。

### 不支持的现场仍暴露可点击入口

- 代码审查服务端契约要求来源会话同时具有精确的 `environmentId`、`workspaceId` 和真实 Worktree；审查提示依赖该 Worktree 的冻结来源提交，并且只读运行、写入根为空。
- 环境卡片此前对项目对话、直接目录会话、Worktree 仍在读取或精确 Worktree 已丢失等状态都无条件开放“代码审查”。
- 项目对话或直接目录会话点击后必然进入服务端拒绝路径；任务存在其他 Worktree 时，Renderer 还可能用回退工作区展示错误审查范围。

## 方案与取舍

### 强行让直接目录支持代码审查

优点：所有会话都可以点击入口。

缺点：直接目录没有持久化的冻结审查基线；多仓项目也没有唯一来源仓库。临时使用当前 HEAD 会漏掉已经提交的任务变化，自动选择仓库还可能审错范围，因此不采用。

### 只对精确任务 Worktree 开放，并回传真实错误

优点：审查仓库、冻结基线和只读边界都可证明；合法 Worktree 启动失败时，统一弹窗直接显示脱敏后的真实原因，不再让用户寻找不存在的“当前错误提示”。

缺点：项目对话和直接目录会话仍不能直接发起代码审查；用户需要先从 Worktree 任务会话进入。若后续要支持直接目录，必须先持久化会话创建时的仓库与基线身份，而不是在点击时猜测。

本任务采用第二种方案。

## 实现范围

1. `SessionQuickActionsCard` 只把来源会话精确 `workspaceId` 对应的 Worktree 交给代码审查弹窗，不再回退任务的其他工作区。
2. 项目对话、直接目录、Worktree 加载中和精确 Worktree 不可用时禁用入口，并在原说明位置展示具体原因。
3. 新增结构化失败结果，代码审查启动链把本机 API 的真实脱敏错误交还给 `SessionCodeReviewDialog`。
4. 代码审查错误只由审查弹窗进入全应用统一错误出口，避免同一失败先后出现“本地操作失败”和“代码审查启动失败”两个弹窗。
5. 普通新会话兼容结构化失败结果，不能把失败对象误判为已接受并清空输入。
