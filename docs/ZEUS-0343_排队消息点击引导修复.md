# ZEUS-0343 排队消息点击引导修复

## 问题

排队消息气泡为所有普通排队消息展示“引导”按钮。实际上服务端只允许当前队首消息引导，非队首消息点击后会被拒绝；连接层又把这个拒绝静默处理，因此界面看起来像点击失效。

## 处理方案

- 仅当消息位于队首、会话处于活动回复阶段，且当前回复已经准备好接受引导时启用“引导”。
- 非队首消息保留按钮但置灰，并提示先将消息上移到队首；不绕过既有队列顺序。
- 队首尚未准备好时提示当前回复暂不可引导。
- 引导请求失败交给统一应用错误弹窗，保留服务端返回的可脱敏错误信息。
- 继续使用排队消息自身的稳定 `submission.id`，不通过内容模糊匹配消息。

## 取舍

优点是界面动作与服务端队首契约一致，用户能知道下一步怎么做，失败也有明确反馈。代价是非队首消息不能直接引导，必须先调整顺序；这是保持阻塞队首和自动发送顺序所必需的约束。

## 变更范围

- `QueuedConversationMessages`：增加队首可用条件、引导状态和失败提示。
- `SessionWorkspace`：引导动作不再被通用后台操作封装静默吞错。
