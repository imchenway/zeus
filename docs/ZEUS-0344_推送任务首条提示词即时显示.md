# ZEUS-0344 推送任务首条提示词即时显示

## 问题

推送任务后，待创建会话中的首条提示词已经写入本地 pending 会话状态，但真实会话创建请求在同一个点击任务中立即启动。后端创建、主进程调度和大上下文请求序列化可能占用首帧渲染窗口，导致提示词仍然需要等待较长时间才出现在对话框。

同时，提交路径已经先生成任务推送布局，却又重新构建一次纯文本提示词，造成不必要的同步计算。

## 处理方案

- 直接从已生成的任务推送布局投影纯文本提示词，避免重复构建任务上下文。
- 先完成 pending 工作面、导航和首条用户消息的状态提交，再通过一帧加零延迟定时器启动真实会话创建。
- 保留真实创建在后台进行的行为；首帧只依赖本地 pending 会话，不等待服务端接受或 Provider 建立。

## 取舍

优点是用户确认后可以先看到完整首条提示词，后端会话创建失败仍可在同一工作面反馈和重试。代价是实际创建请求最多延后一帧，后台创建的完成时间可能略晚；这是把首屏可见性置于网络和 Provider 初始化之前的必要代价。
