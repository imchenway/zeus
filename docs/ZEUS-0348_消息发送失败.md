## 任务目标

`thread ... already has an active writer` 的问题。不得通过删除 writer 锁、强制结束进程、自动重发历史失败消息或修改正式数据规避。

## 根因

`CodexRuntimeGenerationManager` 把“Provider turn 已终态”等同于“thread 可以迁移”。但 Codex app-server 的 writer 所有权并不随 turn 终态释放：只要原进程仍加载该 thread，它就继续持有 writer 锁。

同时，世代激活只比较全局 `activeEntry`，不会复用仍然存活的同配置进程。其他会话切换到 DeepSeek 后，再回到官方 Codex 会新建第二个官方 app-server；`startTurn` 随即尝试把已空闲的 thread `resume` 到新进程，新进程因此被原持锁进程拒绝。

排空实现还存在一个竞争窗口：它在进程真正关闭前先删除 `entriesByThread` 映射。此时到达的新消息会立即在当前世代恢复同一 thread，也可能在原 writer 尚未释放时碰撞。

## 实施设计与取舍

1. 运行世代以命令路径、外部 Agent Home、Remote Control、Provider 和进程环境组成兼容身份。普通激活优先复用最近使用且仍存活的兼容进程；显式
   `activateFreshGeneration` 继续强制创建新世代。
2. 新建 thread 前先选择与模型来源匹配的运行世代。官方 Codex 不再误入 DeepSeek 进程，自定义 Responses thread 仍固定使用携带对应连接环境的本地隔离进程。
3. thread 一旦绑定进程，`resumeThread`、`startTurn`、Goal 写操作和归档继续路由真实 owner；turn 终态不再触发跨进程抢占。
4. thread 写操作持有进程租约，`thread/start`、恢复、发送或 Goal 写入尚未返回时不得排空对应进程。世代排空期间保留 thread 所有权映射，并保存关闭 Promise。只有底层进程完全关闭后才删除映射；同时用 thread 级串行链保证恢复和重新绑定只执行一次。
5. Provider 身份与 owner 不一致时直接返回领域错误，不把同一原生 thread 静默交给错误连接。

优点：新会话在其他模型会话并行切换时仍可连续发送；不会重复创建可复用世代；不重放用户输入，也不破坏 writer 真实性。

代价：进程排空瞬间到达的首次写操作需要等待进程完整退出；同一 thread 在 owner 存活期间保持进程亲和性。该亲和性只约束 app-server 进程，不改变产品会话、模型或用户上下文。

不采用删除锁、强制杀进程、固定延时重试或历史消息自动重发。前两者会破坏其他真实会话，后两者无法证明 writer 已释放，并可能产生重复副作用。
