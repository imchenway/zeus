# ZEUS-0352 引入数字员工

## 当前阶段

首版纵切实现与非交互运行验收已完成。领域模型、耐久事实、命令接口、自动化调度、执行编排和桌面配置入口已经贯通；真实桌面页面的点击、视觉和交互验收因当前 Computer Use 原生管道不可用而保留为未验。

## 原始需求

1. 内置产品、前端、开发、测试、部署等角色，并允许用户自定义数字员工。
2. 支持按业务领域组合岗位，例如“CSS 测试”“PIM 产品”。
3. 数字员工可配置 Skill、提示词等能力和行为内容。
4. 任务指派给数字员工后，由员工自动处理。
5. 可配置员工自动探索、捞取、执行与交付任务。
6. 可为员工配置自动化任务。

## 已核实的现状

- Zeus 的“任务”已经拥有项目、类型、父子/关联关系、管理状态、Agent 运行状态，以及 `allowCodeChanges`、`allowTests`、`allowGitCommit` 等任务级权限。
- Zeus 的“产品会话”及其“目标”可以承载一次工作执行；目标绑定单条 Provider 原生会话，允许跨轮自动续跑，但不负责跨任务找活、认领和排班。
- Zeus 当前界面里的“智能体”表示一条会话派生的运行线程，不是跨任务存在的员工身份。
- 命令中心已具备全局/项目命令、参数、风险标记、逐次确认、执行记录、日志与产物，但它不是任务池或员工调度器。
- 当前任务启动主要来自用户显式操作或 API 调用；尚未发现数字员工身份、能力组合、任务认领策略、定时自动化或跨任务后台调度事实。

因此，不能把现有“智能体”“目标”“任务模板”中的任意一个直接改名为“数字员工”。这样会混淆工作主体、执行载体和工作定义，也无法表达长期配置、授权与审计。

## 候选领域模型

以下术语已经确认，并已同步写入工作管理领域词汇表：

### 数字员工

长期存在、可配置、可授权、可分派且可审计的工作主体。它描述“谁以什么规则工作”，不拥有 Provider 原生线程，也不等于某次会话。

建议由以下配置组合产生，而不是新增固定的 `product/frontend/developer/test/deploy` Agent 枚举：

- 岗位：产品、前端、开发、测试、部署等职责基线。
- 领域：CSS、PIM 等业务知识与项目范围。
- 能力配置：允许使用的 Skill、Provider/模型、提示词、命令和工具。
- 工作策略：可接受的工作来源、筛选条件、并发上限、优先级与静默时段。
- 权限策略：只读探索、修改代码、执行检查、提交、推送、合入、部署及任务状态变更的独立授权。

优点：岗位与领域可以自由组合，新增业务员工不需要改枚举或数据库结构；运行时可以替换而员工身份保持稳定。

缺点：必须处理配置版本、能力兼容、权限冲突和历史执行可追溯性，首版实现面明显大于新增一个 Agent 下拉项。

### 工作指派

把一个明确任务交给某个数字员工的业务事实。指派只决定责任主体和采用哪一版配置，不表示已经建立会话、已经开始执行或已经交付。

优点：可以把任务管理状态、排队状态和真实运行状态分开，失败重试或换 Provider 时不会丢失责任关系。

缺点：需要单独定义接受、拒绝、撤回、转派、并发冲突和重复指派规则。

### 工作来源

向数字员工提供“可评估工作项”的受控来源，例如 Zeus 任务池、用户配置的定时任务、代码仓库扫描结果或外部系统。来源只发布候选，不直接绕过策略启动副作用。

优点：可扩展新的项目与外部系统，同时保留来源、筛选和幂等证据。

缺点：来源越开放，误认领、重复执行、凭据暴露和不可控成本越高。

### 自动化规则

由触发器、筛选条件、目标数字员工、执行预算、权限策略和人工闸门组成的版本化规则。定时只是触发器之一，不应与“数字员工”本身绑定成一个 Cron 字符串。

优点：同一员工可以同时接受人工指派、任务池认领和定时巡检；规则可暂停、审计和独立修改。

缺点：需要可靠调度、幂等、漏跑/补跑、时区、并发和故障恢复语义。

### 工作执行

一次指派或自动化触发产生的可审计执行实例。它引用任务、数字员工配置版本、授权快照和产品会话，并记录认领、启动、等待、阻塞、产出和终止证据。

优点：能够回答“哪位员工、按哪版配置、为何启动、做了什么、交付到哪里”。

缺点：需要新增跨工作管理、会话编排和执行资产的稳定契约，不能由 Renderer 直接拼接状态。

## 推荐的系统边界

建议由“工作管理”上下文拥有数字员工、工作指派、工作来源、自动化规则和工作执行的业务事实；会话编排只负责建立并驱动产品会话；Agent Runtime 仍只负责 Provider 能力和原生身份；执行与资产保存命令、日志、附件、变更集及交付结果。

优点：复用现有任务、会话、目标、命令和交付链路，避免数字员工成为一个可绕过安全边界的超级 Agent。

缺点：需要版本化命令和领域事件连接多个上下文，不能用一张员工表加后台定时器快速完成。

## 首版范围

首版交付“全局员工模板 + 项目员工配置 + 人工指派 + Zeus 内部任务池 + 已分配项目内自主探索 + 用户显式创建的自动化规则 + 逐动作授权的端到端交付”。外部系统主动捞取作为后续受控工作来源。

优点：覆盖“员工配置、任务自动处理、自动找活、自动化任务、端到端交付”的完整产品主线，并通过项目范围和逐动作授权保持最小权限。

缺点：首版的探索只发生在已分配项目，不能宣称已从外部业务系统自主找活；端到端动作需要分别建设可恢复、可审计的执行门禁，无法用单一“完全自动”开关代替。

## 已确认的产品决策

### 1. 自动找活的工作来源

- A：首版只使用 Zeus 内部任务池和用户显式创建的定时自动化；仓库与外部系统后续接入。推荐，边界最清晰。
- B：首版同时支持 Zeus 任务池、代码仓库探索和已安装连接器；每个来源必须单独授权与配置。
- C：允许员工自行决定从哪里探索工作。自主性最高，但成本、权限与误操作风险不可控，不建议。

已确认：使用“Zeus 内部任务池 + 自主探索”。自主探索仅限员工已分配项目中的任务、代码和文档，并以只读方式发现、提出或创建候选任务；不得扫描其他项目、本机任意目录或未逐项授权的外部系统。

优点：保留员工主动发现工作的能力，同时以项目分配形成最小读取范围和清晰来源证据。

缺点：跨项目问题与外部业务信号不会自动进入任务池，后续需要增加显式连接器来源或跨项目授权。

### 2. 自动交付权限

- A：自动探索、认领、执行和形成交付候选；提交、推送、合入、部署及任务终态仍由用户确认。推荐。
- B：可按员工逐项授权自动提交和推送，但合入、部署及任务终态仍需确认。
- C：可按员工授权端到端自动交付，包括合入、部署和任务终态。需要更强审批、回滚、环境和发布治理。

已确认：首版支持端到端自动交付，但采用逐动作显式授权。数字员工分配到项目时，`提交`、`推送`、`合入`、`部署` 和 `结束任务` 权限默认全部关闭，用户可分别开启；开启后允许员工在满足目标位置、环境与前置门禁时自动执行。

优点：可以真正实现无人值守交付，同时按项目和动作维持最小权限；开发员工无需自然继承部署权限。

缺点：必须为每种副作用定义明确接收位置、幂等身份、前置门禁、结果未知处理、失败停止和回滚/恢复策略，不能复用一个笼统的“完全访问”开关。

### 3. 组织与复用方式

- A：全局员工模板，分配到项目时产生项目配置；项目可覆盖领域、Skill、提示词和权限。推荐。
- B：每个项目独立创建员工。隔离最强，但重复配置多，跨项目员工与统一治理较弱。
- C：只有一套全局员工直接服务所有项目。维护简单，但难以表达项目差异和最小权限。

已确认：采用“全局员工模板 + 项目配置”。模板沉淀可复用的岗位、领域、Skill、提示词、Provider/模型和默认工作策略；分配到项目后形成独立数字员工配置，允许覆盖这些内容，并独立配置探索范围、自动化和逐动作交付权限。

优点：产品/前端/开发/测试/部署等基线可以统一维护，又能组合出“CSS 测试”“PIM 产品”等项目员工；项目权限不会随模板更新被意外放大。

缺点：模板更新与项目覆盖之间必须提供可见的继承、差异和升级语义，不能静默覆盖已经运行的员工配置。

2026-08-25 曾误选“全局员工直接服务”，用户随即明确撤回；该误选不构成产品决策。

### 4. 自动化触发方式

已确认：首版同时支持手动立即运行、一次、每天、每周、固定间隔和项目事件触发。项目事件至少覆盖任务创建、任务状态或内容变化以及项目代码变化；同一来源事件必须以稳定身份去重，并受员工并发上限和风暴抑制约束。

优点：既可表达周期巡检，也能在真实业务事实变化时及时工作；自主探索可以按计划或项目事件启动，而不需要无限后台循环。

缺点：必须持久保存调度水位、事件匹配和去重结果；批量导入或频繁代码变化可能形成触发风暴，需要合并窗口与背压。

## 当前不应假设的内容

- 不把固定岗位写成不可扩展的 Agent 类型枚举。
- 不把 Codex 子线程或目标直接当成员工身份或任务池调度器。
- 不因配置了 Skill 或提示词，就默认获得对应工具、凭据或副作用权限。
- 不把“任务已完成”与代码已提交、已推送、已合入或已部署画等号。
- 不在结果未知或缺少真实执行证据时自动重发、自动交付或标记成功。

## 首版已知边界

- Skill 配置当前作为会话的明确能力指令传入，运行时会核对实际可用性；它不是独立的工具安装器或工具访问控制列表，不能因填写 Skill 名称就假设工具已经安装或获得凭据。
- 自主探索由服务端固定为只读、关闭 Runtime 网络并只选择当前项目的任务上下文和工作区；当前 Provider 沙箱没有“仅允许读取某个项目目录”的独立文件读取 ACL，因此还需依赖数字员工指令禁止扫描其他本机目录。不能把这一点描述成操作系统级读取隔离。
- 首版不读取外部业务系统或未授权连接器；跨项目找活、连接器来源、静默时段、预算上限和自动生成独立候选任务仍属于后续扩展。
- 桌面端首版可创建、启停、立即运行和删除自动化；底层接口支持带版本的规则更新，但界面尚未提供已有规则的完整编辑器。
