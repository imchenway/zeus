# ZEUS-0356 目标执行期间消息发送失败

## 任务目标

修复 Codex 原生目标执行期间普通消息被误判为可立即派发，随后在 `thread/resume` 超时并显示“消息发送失败”的问题。普通发送保持 FIFO 排队；用户点击队首“引导”时仍精确 steer 当前 turn。

## 现场证据与根因

- 正式 SQLite 与 Provider JSONL 的只读副本显示，目标自主 turn 从北京时间 07:24 持续到 16:35。
- 两条失败消息分别在 09:37、11:49 创建，均没有 `provider_turn_id`，Provider JSONL 中也不存在对应用户输入。
- 第二条消息发生在目标暂停约 7 秒后；暂停只阻止后续目标推进，未结束已经开始的 turn。
- 当时 Zeus 没有投影该自主 turn，本地运行态错误地保持 idle，恢复路径先执行 `thread/resume`，最终超时。
- 当前主线已经能从 `turn/started` 投影没有 submission 的目标自主 turn，但重连、Execution Host 重启和事件缺失路径仍然先 resume、后读取权威状态。

## 已确认设计

- 恢复顺序改为 `thread/read` → 有界 turn 对账 → 必要时 `thread/resume` → 再次读取确认。
- Provider active 时投影准确 turn ID，普通消息只入队；目标暂停不隐式 interrupt 当前 turn。
- 断连活动 turn 使用每线程唯一的只读观察器，按 1、2、5、15 秒退避；连续三次读取失败后安全进入恢复态。
- 普通消息等待当前 turn 结束后只派发一次；队首“引导”继续使用准确 `expectedTurnId` 调用 `turn/steer`。
- 不修改正式数据，不自动重放历史失败消息，不删除锁或强制结束进程。

## 设计取舍

- 优点：以 Provider 权威状态消除误 resume，覆盖在线、重连与宿主重启路径，并保留现有队列/steer 审计身份。
- 代价：断连恢复后可能增加最多约 15 秒的排队观察延迟，并产生低频本地 app-server 读取。
- 不自动暂停目标；如果真实 Provider 不提供用户队列先于下一轮目标推进的窗口，则按外部协议限制报告，不用破坏性手段规避。

## 真实 Provider 与独立测试包验收

- 测试包：`dist/test/mac-arm64/Zeus Test.app`，Bundle ID `dev.hypha.zeus.test`；资料根为 `/private/tmp/zeus-0356-gui.kPWGuu`，未复制正式 SQLite、配置或历史 JSONL，只使用隔离 Provider 会话。
- 启动时没有其他 `Zeus Test.app` 实例；三块显示器在线。窗口首次创建日志确认 `targetDisplayId=3`、`actualDisplayId=3`、`corrected=false`，位于非主外接屏。
- 两轮全新 Provider thread 均把没有 Zeus submission 的自主目标 turn 投影为 active，`clientSubmissionId: null`；普通发送返回 202 并以 `current_turn` 原因进入 FIFO，没有“消息发送失败”。
- 第二轮最终包中，队首“引导”只发出一次 `turn/steer`，携带当前 turn `01a02f4d-f26f-7c61-a116-b14b6ed122e6`。调用在客户端超时，但 Provider JSONL 随后出现同一 client id 的用户消息；Execution Host 重启后，恢复先执行两次 `thread/read`，确认两个 Provider turn 均终态后才执行一次 `thread/resume`，并由精确消息身份把 submission 收口为 completed。
- 第一轮中相反场景为 Provider JSONL 没有引导内容；该场景暴露了按 turn ID 误判完成的缺口。补丁后仓库外协议演练确认消息保持 `paused/recovery_required`，不自动重发。
- Provider 在首个目标 turn 于 `15:49:37.220Z` 完成后，于 `15:49:37.223Z` 启动下一轮，仅有约 3ms 间隔；第一轮也只有约 5ms。真实 Provider 因此没有提供“队列先于下一轮自主目标推进”的稳定写入窗口，无法完成“自然终态后普通队首抢先发送”的正向验收。按已确认边界停止在此外部协议限制，不中断 turn、不删除锁、不修改正式数据来规避。
- 暂停目标继续只阻止后续目标推进；第二轮当前 turn 自然完成，下一轮已开始后收到暂停并自然完成。没有把暂停误当成当前 turn 已终止。
- 测试 SQLite `PRAGMA quick_check=ok`；第二轮两个 Provider turn 各只有一条本地 turn 记录，没有重复 turn。正式 Provider 线程、正式数据库和两条历史失败消息均未修改或重放。
- 桌面包、窗口位置、真实 Provider、Core 公共命令、SQLite 与 Provider JSONL 已验收。由于 Computer Use 的本机控制管道在当前环境不可用，发送/暂停/引导动作使用渲染层正式命令构造器通过公开 Core API 执行；没有取得真实鼠标点击及错误提示视觉消失的 GUI 证据，此项按证据等级保留为未验。
