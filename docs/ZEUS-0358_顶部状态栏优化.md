## 已确认目标

1. 历史用量找不到当前模型连接时，不再伪造“已删除供应源”名称，而是展示可追溯的 `sourceId`，保留历史账本。
2. “全部”页的 Codex 主数值展示“今日 Zeus Token”；计划类型和配额降为副文案。
3. Codex 详情分开“Zeus 本地统计”与“Codex 账户统计”；移除官方积分余额，配额仅保留一处紧凑摘要。
4. 七日图固定为七个自然日槽位，“今日”与“近 7 日”成组展示，缺失数据不伪造为零。

## 已核实根因

1. `usageOverviewService` 在账本 `providerId` 找不到当前连接元数据时，把名称硬编码为“已删除供应源”，随后 Renderer 把该名称同时投影到页签、顶部身份和总览行。
2. Codex 总览行只要存在限额窗口，就使用剩余百分比覆盖今日 Token。
3. Codex 详情同时绘制配额大卡、圆环和限额窗口行，相同 67% 被重复表达。
4. 日图只渲染返回的日桶数量并使用平均分散布局，缺失日会改变横轴位置；近 7 日合计放在图表右上角，容易被误认为最后一日数值；当前信息高度还会使日期标签被底部操作区裁切。

## 实施决策

- 历史来源继续参与用量统计，可见名称改为真实连接标识；紧凑页签使用首尾特征，列表和悬停信息保留完整标识。
- Codex 详情用本地今日 Token 作为主卡，近 7 日本地 Token、缓存命中率和近 7 日估算费用作为紧凑指标；账户日桶只进入独立的 Codex 账户图表。
- 配额仅投影最紧迫的一个窗口，保留百分比与重置时间；不再绘制大卡、圆环或多行列表。
- 官方日桶缺失保持未知；Zeus 本地数据仅在采集开始后的无记录日表达为零，采集开始前仍表达为缺失。

优点：统计来源清晰，配额不重复，历史来源可追溯，图表的日期位置稳定。

缺点：真实连接标识不如人工名称友好；本地与账户两套口径会增加少量信息密度。通过缩略标识、完整悬停信息、固定日槽和明确分区缓解。
