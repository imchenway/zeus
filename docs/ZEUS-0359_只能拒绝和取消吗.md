## 代码结论

### Renderer

- `PendingRequestSurface` 只有在文件路径已经可见时才保留允许决定；`filePaths.length === 0` 时主动收紧为失败关闭决定。
- `SessionWorkspace.linkedFileApprovalPaths` 通过请求 `itemId` 关联当前会话中的 `fileChange` item，再从 `changes[].path` 读取文件路径。
- 本次请求 payload 只有 `threadId`、`turnId`、`itemId`、`startedAtMs`、`reason`、`grantRoot`，路径不在请求本体中。因此卡片渲染时若关联 item 路径尚未进入 Renderer 状态，就会显示截图中的“详情不完整”。

### Local Server

- `hasAuditableFileApprovalTarget` 不仅要求路径存在，还要求路径经规范化与真实路径检查后位于当前项目执行根内。
- 本次目标位于 `/tmp`，不在 ZEUS-0002 执行环境根内；即使前端直接放出“允许”按钮，服务端也必须拒绝该允许响应。
- 因此不能通过单纯恢复按钮绕过服务端审计。

## 根因分层

1. 已证实的业务边界：本次真实目标位于项目外，按当前安全策略不可授权。
2. 已证实的界面条件：Renderer 未取得可展示的关联文件路径，因此进入失败关闭状态。
3. 尚未完全复原的时序：当前耐久数据保存了最终 `fileChange.changes`，但没有保留卡片出现瞬间 Renderer 内存态；不能仅凭最终行断言是 Provider 未及时发送、实时投影漏发或 Renderer 漏合并。
4. 明确的体验缺陷：界面把“目标尚不可见”和“目标位于项目外”统一写成“审批详情不完整”，没有让用户知道这次实际请求的是 `/tmp` 文件。

## 修复路线与取舍

### A. 保留项目边界，补齐服务端审计结果投影（推荐）

由 Local Server 统一解析关联文件路径并输出“目标列表 + 审计状态 + 禁止原因”，Renderer 只展示该权威结果：

- 项目内且可审计：展示“允许一次 / 允许所有编辑 / 拒绝 / 取消”；
- 目标未到达：显示“文件目标尚未同步完成”，只保留拒绝和取消；
- 项目外目标：展示真实路径并明确写“项目外文件不可授权”，只保留拒绝和取消。

优点：不降低安全边界；前后端不会各自推导不同结论；用户能看见真实目标和准确原因。

缺点：本次 `/tmp` 文件仍不能被允许；需要扩展 Pending Request 的服务端投影契约，而不是只改文案。

### B. 增加任务私有临时目录授权域

只允许 Zeus 显式登记、具备任务归属和生命周期的临时目录；审批时仍做 realpath、归属和符号链接逃逸检查。

优点：可以支持本次本地 GUI 验收夹具等临时文件场景。

缺点：扩大现有“仅项目内”安全边界；必须补齐目录创建权威、任务归属、清理、恢复和审计语义，不能把任意 `/tmp` 直接视为安全。

### C. 仅在前端恢复允许按钮（不采用）

优点：改动最小，表面上立即出现允许入口。

缺点：服务端仍会拒绝本次目标，形成假按钮；若同步放宽服务端则会失去项目路径门禁，存在越界写入风险。

## 本轮实施决定

采用路线 A，保持“只允许当前项目内可审计文件”的安全边界：

- Pending Request 新增服务端权威 `fileApproval` 投影，包含审计状态和目标路径；
- 项目内可审计目标恢复“允许一次 / 本会话允许”；
- 项目外目标展示真实路径和准确边界说明，仍只提供拒绝或取消；
- Provider 根范围授权显示独立原因，不与目标未到达混为一谈；
- 文件路径晚于审批请求到达时，通过 `conversation.request.changed` 关键事实事件刷新审批状态。

暂不采用路线 B。其优点是可覆盖任务私有临时夹具，缺点是会扩大授权域并要求新增目录归属、生命周期和符号链接逃逸审计；这不是修复当前误导交互的必要条件。

## 实现结果

- `nativePendingRequestProjection` 对文件审批增加 `fileApproval` 权威投影：`auditable`、`outside_project`、`provider_root_scope`、`unavailable`。
- `hasAuditableFileApprovalTarget` 与 Renderer 共用同一份服务端 realpath 审计结论；界面不再自行推导项目边界。
- 请求创建时立即携带审计投影；`fileChange` 的 started、patchUpdated 或 completed 事件晚到时，广播耐久级别为 `critical_fact` 的 `conversation.request.changed`。
- HTTP Pending Request 水合也使用相同投影；任务执行根不可用时返回 `unavailable`，不得回退主项目路径伪造可授权状态。
- Renderer 对项目内目标展示“允许一次 / 本会话允许”；项目外、Provider 根范围和暂未同步分别展示准确原因，并保留已知真实路径。
