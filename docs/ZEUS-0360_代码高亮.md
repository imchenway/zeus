# ZEUS-0360 代码高亮

状态：实现完成；已完成隔离数据下的全类入口真实 GUI 验收。

## 需求与确认范围

- 现状：所有文件内容界面需要语法高亮，不能只覆盖代码编辑器。
- 覆盖：代码区文件、会话源文件预览、Turn Changes、Project Git Diff、任务审查/交付 Diff、任务冲突聚焦与完整文件模式。
- 不覆盖：日志、命令输出、普通 Markdown 代码块、图片和二进制文件。
- 未识别的文本文件保持纯文本；不为满足“有颜色”而使用可能误判的正则着色。

## 实施方案

- 在 `@zeus/shared` 维护单一文件语言识别入口，主进程、本地服务和渲染器共用，消除重复映射。
- 使用 CodeMirror 6/Lezer 的真实语法解析器，编辑器和静态文件界面使用同一套语言注册与主题变量。
- 静态高亮和 CodeMirror 编辑器按需加载；语言模块使用 Promise 缓存，文件切换时丢弃过期结果。
- Diff 对每个可见 hunk 的旧侧、新侧分别解析并回填到原行，保留增删背景、行号、评论、滚动和操作控件。
- 冲突编辑器使用透明 textarea 叠加只读高亮层，输入、选区、可访问文本和保存语义继续由 textarea 承担。

## 取舍

- 优点：多行字符串和注释等语法可以正确解析；所有文件入口一致；未知类型不会假高亮；不新增后端文件读取协议。
- 缺点：增加语言运行时分块，首次打开某类文件会先显示纯文本再补齐颜色；Diff 被省略 hunk 之外的语法状态无法完全恢复；新增语言需要显式维护注册表。
