# ZEUS-0368 项目设置内容优化

## 当前阶段

需求、实现、静态门禁、独立测试包和本机 API 读写已完成；由于 Computer Use 当前缺少必需的 `node_repl` 信任服务，原生窗口点击与截图验收仍保留为未验。

## 原始需求

1. 图 1 的旧“项目配置”抽屉内容不再需要。
2. 图 2 的仓库状态、代码图谱摘要及其操作区不再需要。
3. 图 3 的项目数字员工“模型”“推理强度”“服务层级”应使用下拉选择，不应允许任意文本。
4. 修改员工配置时，“保存员工配置”必须始终可见。

## 已核实的实现现状

- `WorkspaceView.tsx` 在进入“项目设置”时先渲染仓库状态、代码图谱摘要和两组项目操作，然后才渲染数字员工。
- `openProjectSection()` 进入“项目设置”时会自动打开 `config` 抽屉，因此图 1 不只是静态内容，还是当前导航的默认行为。
- `ProjectDigitalEmployeesPanel.tsx` 中这三项字段是自由文本框，未消费项目已有的 Provider 模型能力目录。
- 保存按钮位于整个长表单之后；项目员工主从区只设置最小高度，没有可视高度上限，导致操作栏随整页长内容落到首屏之外。

## 实现决策与取舍

### 项目设置聚焦数字员工

- 决策：项目设置页直接进入数字员工，移除图 2 区域及图 1 抽屉入口，同时取消进入页面时自动打开旧配置抽屉。
- 优点：减少与“代码”页重复的仓库/图谱信息，用户进入项目设置即可管理项目数字员工。
- 缺点：项目元数据、共享可写目录和旧项目配置暂时失去此 UI 入口。本次只移除界面入口，不删除底层数据、命令或读写契约。

### 三级联动下拉选择

- 决策：从当前项目的真实会话能力目录读取可用模型，按员工 Runtime 过滤；选定模型后，推理强度和服务层级仅展示该模型公布的能力。
- 优点：避免错别字、不受支持的组合和跨 Runtime 模型混用；与任务推送的模型身份保持一致。
- 缺点：Provider 尚未就绪或项目没有可用模型时，下拉框只能选择“跟随项目/模型默认”，不再允许用文本绕过能力目录。

### 保存操作栏常驻

- 决策：项目员工主从区使用受可视高度约束的内部滚动，只让表单滚动，保存/停用/移除操作栏留在右侧编辑区底部。
- 优点：任意字段修改后都能立即保存，不用滚动整页寻找入口。
- 缺点：长表单需在右侧区域内独立滚动；窄屏会退回纵向布局，避免过度压缩。

## 验收边界

- 不新增或恢复 Vitest/单元测试。
- 静态门禁使用 `pnpm lint`、`pnpm typecheck`、`pnpm build`。
- 真实运行只允许生成并启动 `Zeus Test.app` (`dev.hypha.zeus.test`)，使用本任务独立 `ZEUS_USER_DATA_DIR`，且首窗口必须从创建起位于非主外接屏。
- 真实 GUI 至少验证：进入项目设置不再打开旧抽屉；图 1/图 2 内容不显示；三项下拉按 Runtime/模型联动；修改字段时保存按钮仍可见；保存后刷新可读回。

## 2026-08-28 实现与静态门禁

### 已完成修改

- `WorkspaceView.tsx` 的项目设置工作区已收缩为 `ProjectDigitalEmployeesPanel`；仓库状态、图谱摘要、扫描/查看变更、编辑/配置/更多操作及旧项目抽屉不再渲染。
- `openProjectSection()` 进入项目设置时只清理旧抽屉状态，不再读取或打开旧项目配置；冷启动的初始配置数据也不再将抽屉设为 `config`。
- 项目数字员工同步只读加载 `loadCodexConversationCapabilities(projectId)`，模型按 `agentKind` 过滤并复用统一供应商/模型展示；模型改变时清空上一模型的推理强度和服务层级，避免跨模型残留。
- 模型下拉保留“跟随项目默认”；推理强度和服务层级保留“跟随模型默认”，选定模型后才可选择其真实能力。历史旧值不受当前模型支持时会显示为禁用的“当前值不受支持”，不伪造成可用选项。
- 项目员工主从区已改为受可视高度限制的内部滚动；右侧表单独立滚动，操作栏保留在编辑区底部。
