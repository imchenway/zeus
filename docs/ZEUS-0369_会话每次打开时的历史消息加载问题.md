# ZEUS-0369 会话历史按需续载与闪烁修复

## 目标

会话打开或切回时默认定位到最新消息，只展示权威尾页与可信连续缓存；仅当用户真实向上阅读到顶部时请求更早历史。修复必须消除重复分页 I/O，不能只隐藏“正在读取更早消息…”提示。

## 已确认根因

1. 权威快照水合会用最新尾页的分页游标覆盖热缓存中已经推进的历史游标，但旧历史正文仍被保留，导致同一页在后续打开时再次读取。
2. 顶部历史哨兵在首帧定位到最新消息之前即启用；短内容或定位过程可直接与哨兵相交，从而在没有用户读取意图时自动触发分页。
3. 分页提示只跟随单页 `loading` 状态挂载和卸载，连续分页时会逐页闪灭；缓存还可能保留离开会话时的瞬时 `loading/error`。

## 已确认取舍

- 权威尾页与缓存的已加载序列范围连续或重叠时，合并最新内容并保留缓存的最深历史游标与 `hasMore`。
- 无法证明范围连续时，以权威尾页为准并丢弃深层显示缓存，避免形成静默时间线缺口；代价是用户需要再次向上续载。
- 不恢复上次阅读位置；打开会话仍定位最新消息。
- 不修改数据库、Local Server 路由、分页游标编码、48 条首屏预算、缓存容量或 `onLoadEarlierHistory` 签名。

## 补充实施：长消息只显示预览

### 已确认根因

- Snapshot V2 为控制首屏体积，只把模型历史正文的前 2,048 个字符放进 `content.preview`，完整正文由 `contentHandle` 分页提供。
- Renderer 原来把这个有界预览直接投影成 `completed` 消息；`onLoadV2Content` 虽已从 Workspace 传到 Transcript，但普通消息行没有消费它，因此用户看到的是被当成最终结果的半条消息。
- 后续权威尾页或历史分页仍可能再次携带同一条 2,048 字符预览；如果直接普通水合，会把已经读取的完整正文重新覆盖回预览。

### 修复内容

- 可见的 Snapshot V2 `model_history` 截断项会自动读取完整正文；控制器按字符游标串行读取全部页，并校验会话、结构代次、正文类型、offset、总字符数和总字节数。
- 同一正文句柄的并发请求在控制器内合并；会话切换、结构代次变化或游标不前进时拒绝合并旧响应。
- 完整正文使用独立 reducer action 合并，不复用快照分页 action，避免完整正文读取意外改写轮次状态、事件水位或历史游标。
- 读取成功后记录 `v2ContentCompleteHandle`；同一正文 revision 的权威尾页、水合页和热缓存重放会继续保留完整正文，新句柄仍由新权威内容接管。
- 结构化用户消息的完整内容会重新投影为可见正文，并保留附件、任务布局和会话上下文，不把原始 JSON 显示给用户。
- 读取期间显示“正在读取完整消息…”；失败时明确提示“消息未完整加载”并提供重试。截断预览统一带省略号，不再伪装成完整消息。
- QA 页面新增长消息现场，覆盖自动补全、两页拼接、失败重试、重复挂载不重复读取和结尾标记展示。
