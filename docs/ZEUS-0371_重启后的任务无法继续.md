# ZEUS-0371 重启后的任务无法继续

## 目标

停止活动工作并退出后，Zeus 必须继续沿用原会话和原 Provider thread，不重放退出前的旧轮次。若退出时 Provider 尚未确认旧 turn 终态，则持久等待并自动收口；只有确认原线程空闲后，才派发用户在重启后新提交的消息一次。

## 现场证据

- 受影响会话：`conversation_c4fe8bb38bb379becd5e3c29`。
- 原 Provider thread：`01a045fb-de13-7393-935d-1cf9bfccb88f`。
- 原 submission 已为 `failed`，但同一 Provider turn `01a045fb-de8b-7951-abbe-32591272660d` 仍处于活动状态。
- 停止回执为 `requestedTurnCount=0`、`providerOutcomeUnconfirmed=true`；原因是退出计划只扫描 `dispatching/active` submission，没有纳入未终态本地 turn。
- 本地退出收口把 turn 标记为 `interrupted` 并把会话写成 `ready`，但 Provider 仍为 active。
- 重启后新“继续”消息被保存为新的未送达 submission；历史投影把同 ID 的本地终态 turn 改回 `running`，随后安全门禁将新消息暂停为 `recovery_required`，界面显示泛化错误“当前操作未完成，请稍后重试。”
- 正式数据库与正式 Provider thread 仅作只读取证；后续真实写入验收只使用独立资料根与新建隔离会话。

## 已确认状态机

```text
退出请求
  -> 中断计划 = 未终态 turn ∪ 活动 submission，按 thread/turn 去重
  -> Provider 中断命令进入统一命令账本
  -> 最多 8 秒核对精确 turn 是否终态
     -> 已终态：本地 interrupted，conversation ready
     -> 未确认：本地 interrupted，conversation paused，provider_stop_pending

重启 / 水合 / 新消息
  -> 读取原 thread 与 turn 历史
     -> 精确旧 turn 已终态：恢复 ready，派发唯一的新 submission
     -> 精确旧 turn 仍 active：按 1/2/5/15 秒退避，幂等中断并复核
     -> thread 缺失、身份不符或出现未知 active turn：recovery_required，禁止重建与自动重发
```

## 持久语义与兼容

- 不新增数据库表或迁移。
- `provider_stop_pending` 复用 submission 的 `paused_reason`、turn 的错误载荷、conversation 的 `provider_state=paused`、Provider 命令账本和恢复事件。
- 退出前已取消的 submission 保持 `cancelled`，不会恢复或重放。
- 只允许恢复重启后新建、尚未携带 `providerTurnId` 的 submission；沿用其原 `clientUserMessageId`、幂等键和执行快照。
- 历史兼容识别要求同时满足：存在退出时取消且携带 `ZEUS_FORCED_QUIT_INTERRUPTED` 的 submission、本地同 ID turn 已终态、Provider 报告该 turn active、存在退出后未送达的新 submission。兼容路径以退出回执时间为恢复水位，不使用稍后才写入的本地 turn 完成时间；普通意外重启仍观察原活动 turn，不得自动中断。

## 取舍

- 采用自动收口后续发。优点是用户无需理解内部恢复机制，且不会重复发送；缺点是 Provider 长时间不确认终态时，新消息会等待。
- 不阻止退出。优点是退出不会永久卡死；缺点是需要把未确认状态可靠持久化并在下一代进程恢复。
- 不默认手动恢复。优点是常规瞬时故障可以自动完成；缺点是必须严格区分精确旧 turn 与未知活动 turn，后者必须失败关闭。

实现说明：

- 停止中断目标改为未终态 turn 与 `dispatching/active` submission 的并集，以 `providerThreadId + providerTurnId` 精确去重。
- Codex 中断统一进入 Provider 命令账本；已接纳回放只使用账本中的精确 session/turn 身份继续只读核对，禁止再次写出。
- 退出终态确认窗口上限为 8 秒。未确认目标在 turn 错误载荷中记录 `providerStopPending=true`，会话保持 `provider_state=paused`。
- 新增独立 `codexProviderStopRecoveryApplication`，负责重启、会话水合、新消息和用户“重新核对”入口；退避为 1/2/5/15 秒。
- 恢复应用只把停止时间之后、无 `providerTurnId` 的新 submission 从 `provider_stop_pending` 恢复为原队列；退出前的 `cancelled/failed` submission 不参与恢复。
- 历史投影遇到“本地用户停止终态 + Provider 同 ID active”时保留本地终态，不再改写为 `running`。
- `provider_stop_pending` 界面使用固定说明“正在确认上次运行已停止，确认后将自动继续”；明确恢复失败时显示“重新核对”和“取消消息”。

## 验收不变量

- 停止回执必须包含精确旧 turn。
- 旧 turn 最终为 `interrupted`。
- Provider thread ID 始终不变。
- 重启后新消息仅有一条本地 submission、一条 Provider 用户消息和一个新 turn。
- thread 缺失、身份不符或未知 active turn 时，禁止猜测、重建线程或自动重发。
