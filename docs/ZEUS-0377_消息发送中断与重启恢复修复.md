## 用户反馈

Zeus 突然出现全部会话消息无法发出；应用重启后，多数会话恢复，但部分既有会话继续显示“当前操作未完成，请稍后重试”，无法发送新消息。用户进一步明确：完整重启仍可替换 Core，但只允许在展示活动工作影响并由用户明确确认后停止，不能把“重启”静默等同于“停止会话”。

## 已确认现场根因

### 全局消息发送失败

1. 正式 Zeus Provider 使用 Codex CLI `0.150.1`，模型预算回退要求 `models_cache.json.client_version` 与当前 CLI 版本完全一致。
2. Computer Use 的 `node_repl` 配置把正式 `/Users/david/.zeus/providers/codex` 作为 `CODEX_HOME` 传给工具子进程。
3. `node_repl` 启动了 ChatGPT 内置 Codex `0.150.0-alpha.8`；该进程打开正式 Provider 的状态、日志、队列数据库，并持续用 `client_version=0.150.0` 覆盖共享模型缓存。
4. 2026-08-28 19:45 的三条消息均在 Provider 写入前以 `ZEUS_CONTEXT_MODEL_WINDOW_UNAVAILABLE` 失败。重启只暂时由正式 CLI 刷新缓存，不能消除后续再次覆盖。

### 重启后部分会话无法继续

1. “自动化需求”会话原 turn 停在 `request_user_input`，Provider JSONL 没有终态。
2. 19:46:39 的完整重启流程执行 `execution_host.stop_active`，停止一个活动 turn 并关闭一个等待回答请求；这不是用户点击会话内停止按钮。
3. 正式 0.3.69 的 `app.asar` 尚未包含主线 ZEUS-0371 的 `provider_stop_pending` 恢复状态机，因此重启后新消息被保存为本地 `recovery_required`，没有写入 Provider。
4. 现场已经积累 `继续` 和三条 `？？？`，均无 `providerTurnId`；这些历史消息不得自动全部重放。

## 实施决策

1. 为受管工具子进程建立独立 Codex Home，不复制或借用正式 Provider 的认证、会话、状态数据库和模型缓存。
2. 模型上下文预算在 Codex generation 初始化时一次性解析并绑定，不在每次发送时重新读取可被其他进程改写的共享文件。
3. 完整重启发现活动工作时必须显示精确数量和中断影响，默认取消；只有用户明确确认后才调用停止命令并安排重启接力。
4. 沿用主线 ZEUS-0371 的原 thread/turn 停止核对。单条、明确未写入 Provider 的恢复消息可在确认终态后续发一次；多条消息保持暂停，逐条由用户重试或取消。
5. 已有 Provider 写入或送达结果不确定的消息继续禁止自动重发。

### 优缺点

- 工具 Home 隔离可以消除跨进程写污染；代价是依赖共享 Provider 认证的旧工具会独立失败，不能再以污染正式状态作为隐式回退。
- generation 级预算让活动世代不受外部缓存变化影响；代价是模型能力变化需要激活新世代。
- 重启确认消除静默中断；代价是存在活动工作时完整重启多一步确认，且不承诺活动 Core 的无损热替换。
- 多条未发送消息逐条处理可以避免重复催问；代价是用户需要手动处理队首消息。
