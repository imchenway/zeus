# ZEUS-0381 会话提示文案

## 目标

打开包含长消息的会话时，系统必须自动取得并展示完整正文。瞬时连接中断、请求超时或 Execution Host 换代由 Controller 自动恢复，会话中不展示“正在读取完整消息…”“消息未完整加载。”或“重试”，也不要求用户承担恢复操作。

## 现场与根因

- 工作树：`/Users/david/hypha/.zeus-worktrees/zeus-e2e-oBLuqT/66bca5978b922f06fad6/ZEUS-0381`
- 分支：`zeus/ZEUS-0381-task-01`
- 基线：`441b7adcece99d52d6888a23a71cc29000ed71e4`
- 开始处理时工作树干净，任务分支与本地 `main`、`origin/main` 位于同一提交。
- Snapshot V2 首屏只携带有界预览，完整正文句柄指向同一条不可变 `conversation_model_history` 记录；Renderer 通过本地 API 分页读取全文。
- 原实现把一次本地读取异常或连接代次变化直接当成最终失败，并由消息组件展示失败状态与“重试”。这把系统内部可恢复故障错误地转嫁给了用户。
- `LocalApiTransport` 已有一次连接刷新重试，但第二次失败、分页中途失败或读取期间 Host 换代仍会向 Renderer 抛错，因此只改提示文案或只隐藏错误不能解决根因。

## 方案与取舍

### 采用：Controller 自动收敛，消息组件无读取状态

- 同一正文句柄只保留一个恢复任务，避免重渲染导致并发重复读取。
- 每轮从第一页重新分页，继续校验 schema、会话、结构代次、offset、字符数和 UTF-8 字节数；只有完整校验通过才合并进会话状态。
- 连接代次变化立即按新现场重新读取；其他瞬时异常按 250ms、500ms、1s、2s、5s 退避，之后维持 5s 间隔，直到正文补全、消息不再需要该句柄、会话销毁或 Controller 释放。
- Controller 释放时主动唤醒并终止等待，避免后台恢复任务泄漏。
- 消息组件只负责在可见长消息首次出现时启动恢复，不渲染加载、失败或重试控件。

优点：用户看到的是最终完整消息，不需要理解本地分页机制或手动重试；连接刷新和 Host 换代不会形成伪失败；完整性约束没有因自动重试而放宽。

缺点：如果底层历史记录本身损坏或持续不可访问，Controller 会在后台低频重试，不能凭空伪造缺失正文。这类情况应作为存储或 Runtime 完整性故障处理，而不是在单条消息下提供用户重试按钮。

### 不采用：隐藏失败提示但仍只读取一次

优点：改动最小。

缺点：只消除了可见症状，正文仍可能永久停留在截断预览，违背“杜绝读取失败”的产品要求。

### 不采用：保留“消息未完整加载”和“重试”

优点：实现简单，用户可以主动再次发起请求。

缺点：把本地可恢复故障和恢复责任交给用户；用户可能把截断预览误认为最终回答，也可能需要反复点击。

## 实施记录

### 阶段 1：纠正产品语义

- 根据会话注释，废弃“正常读取静默、失败时提示并允许重试”的旧方案。
- 将目标收口为“系统自动恢复并最终呈现完整正文”，消息时间线不出现任何正文读取状态或恢复入口。

### 阶段 2：Controller 恢复与渲染收口

- `useSessionController.ts` 将正文分页改为同句柄去重的自动恢复循环；每次重试重新读取当前 Snapshot、连接代次和结构代次，并从 offset 0 开始。
- 保留原有所有响应归属、分页推进、总字符数、总字节数和最终组装完整性校验。
- `ConversationTranscript.tsx` 移除消息级 loading/error/retry 状态，只触发 Controller 恢复任务。
- `session.css` 删除不再使用的消息读取状态和重试按钮样式。
- 浏览器 QA 增加“一次瞬时失败后由系统自动恢复”的真实组件现场。
