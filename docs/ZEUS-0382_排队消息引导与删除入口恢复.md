# ZEUS-0382 排队消息引导与删除入口恢复

## 用户现场

- 当前回复仍在运行时，用户在底部输入框按 Enter 发送“还在继续没？”。
- 消息以“排队中”气泡进入会话时间线，但气泡没有删除入口，也不能显式引导给当前回复。
- 用户提供的现场截图中，输入区仍显示停止按钮，说明当前轮次尚在执行；排队气泡本身只显示状态和正文。

## 已确认根因

- 服务端仍保留按稳定 `submission.id` 删除排队消息和把队首消息引导给当前活动轮次的能力。
- Renderer 控制器仍保留 `deleteQueuedSubmission` 与 `sendQueuedNow`，`SessionWorkspace` 也仍创建对应 action。
- 2026-08-23 为修复历史会话与计划持久化回归时，旧 `QueuedConversationMessages` 管理组件被删除，排队正文改为时间线中的单一用户气泡。
- 正常 `queued` 气泡只获得普通消息的复制操作；`ConversationTranscript` 仅在失败或恢复场景传递“重试/取消”，没有把正常排队消息的引导、删除等操作迁入气泡。
- 因此本次不是 Provider 不支持引导，也不是消息没有落库，而是新投影表面丢失了正常队列操作入口。

## 产品决定与取舍

### 发送语义

- 当前轮次运行时，Composer 的 Enter 继续默认保存为下一轮排队消息。
- 不把整个消息气泡设置为单击即引导。这样可以避免用户选择文本、打开附件或误触气泡时直接改变 Provider 执行。
- 在唯一的排队气泡上提供明确的“引导”与“删除”操作；消息不再复制到第二个队列面板。

优点：保留“下一轮再处理”和“补充给当前轮”两种不同意图；操作对象与可见消息身份一致；不会恢复重复投影。

缺点：用户需要点击明确按钮，不能通过点击气泡任意位置快速引导；这是为降低误发送风险保留的一次显式确认。

### 引导边界

- 仅普通 `queued` 消息允许引导。
- 仅真实队首允许引导，不能绕过更早的 `queued`、`paused` 或 `failed` 提交。
- 仅当前轮次处于活动状态、连接就绪，且 `startedTurnId === activeTurnId` 时允许引导。
- 计划确认等不可变控制提交不允许编辑、删除、排序或引导。
- 引导请求以原 `submission.id` 调用现有 `sendQueuedNow`，不按正文模糊匹配，也不先创建第二条 `steer_now` 消息。

### 删除边界

- 仅尚未交给 Provider 的普通排队或暂停消息允许删除。
- `dispatching`、`steering` 和不可变控制提交不提供删除，以免把已经进入外部副作用窗口的消息伪装成本地可撤销。

## 验收目标

1. 活动回复期间按 Enter 后，消息只出现为一个“排队中”用户气泡。
2. 排队气泡清楚提供“引导”和“删除”入口，键盘也能聚焦并触发。
3. 点击“引导”后，同一消息身份进入“引导中”，不会复制出第二条排队消息；最终以 Provider 权威事件进入当前轮次。
4. 点击“删除”后，未发送消息从时间线和权威队列中同时消失，不触发 Provider 发送。
5. 非队首、当前轮次尚未就绪、正在引导和不可变控制消息展示与真实协议一致的不可用原因。
6. 静态检查、构建或打包不能替代真实 Provider 轮次中的图形界面验收。
