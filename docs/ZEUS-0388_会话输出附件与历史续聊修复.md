# ZEUS-0388 会话输出附件与历史续聊修复

## 任务目标

- Snapshot V2 冷历史必须恢复 `delivery=assistant` 的助手交付附件，不要求用户展开处理过程。
- 运行中任务内未归档、可续接的空闲原生会话必须允许输入、添加附件、调整下一轮配置并发送。
- 历史正文仍保持只读；归档、任务结束、显式只读、不可续接与 `recovered_unsent` 待确认场景继续阻止发送。
- 普通 `imageView`、截图和调试图片仍属于处理过程，不提升为助手交付物。

## 现场证据

### 正式数据只读核对

- 正式会话：`conversation_efcc5035ab708c6c72103674`。
- Provider 线程：`01a04b4d-842e-7340-89f4-7ab623641acc`。
- 所属任务 `ZEUS-0380` 当前为 `running`，会话未归档、Provider 状态为 `ready`，相关轮次已完成。
- 原始三张原型图已写入 `conversation_resources`，来源项类型为 `imageGeneration`，资源展示数据包含 `delivery=assistant`。
- 最近一次“重新附上”输出被投影为三个普通 `imageView` 项，没有交付资源；本任务不把它们自动提升为最终附件。

### 代码根因

- `conversationSnapshotV2` 的资源可用性只有总量布尔值，资源分页 DTO 没有下发 `delivery`。
- 冷历史首屏不主动读取助手交付资源；对应 `imageGeneration` 过程项未进入模型正文时，也没有可承载资源的展示项。
- `SessionWorkspace` 将 `historyOnly` 直接计入 `interactionReadOnly`，虽然外层已经接好首次发送、附件和下一轮配置动作，输入框仍被统一置为只读。

## 已确认设计

- Snapshot V2 增加助手交付物可用性和资源 `delivery` 元数据，旧缓存缺字段时按无交付物处理，不升级结构代次、不迁移数据库。
- 仅在会话声明存在助手交付物时读取现有资源分页；图片内容继续通过受控预览接口按需读取。
- 缺少来源过程项时合成稳定的助手交付展示项；真实过程项稍后加载时合并资源并去重。
- 历史正文写操作与输入区写能力分离；首次发送沿用已有延迟连接与安全排队路径。

#### 根因与修正

1. 资源分页能正确合成 `imageGeneration/assistantDeliverable` 条目，但后续首屏权威快照水合只保留模型正文、活动项和过程项，没有保留带 `v2SyntheticAssistantDeliverableItemId` 的助手交付条目。因此交付物会在资源加载成功后被下一次对账删除；资源加载 effect 的相同尝试键又不会主动重试，界面最终保持“正文存在、附件消失”。
2. 历史输入门禁复用了 `sessionStateNeedsRealtime`，把 `conversationState=starting_turn` 等 Renderer 派生展示态直接视为仍有活动工作。正式会话的队列、请求、submission 和活动轮次均为空时，陈旧展示态仍能永久禁用输入框。
3. reducer 现在只对同时具备合成身份且仍含 `delivery=assistant` 资源的条目跨权威首屏对账保留；图片和文件均覆盖，普通过程图片不扩大为交付物。
4. 历史输入门禁改为只接受待处理请求、计划确认、活动队列、非终态 submission、活动轮次身份和非终态轮次快照；`conversationState` 仍用于实时连接与错误展示，但不再单独决定冷历史是否可输入。

优点：修正在现有资源与状态协议内完成，不迁移数据库、不改变 Provider、不扩大普通工具资源语义；真实处理中、归档、显式只读、不可续接、任务结束和待恢复消息继续 fail-closed。

缺点：已加载的合成助手交付物会一直保留到会话工作面卸载，当前协议没有“资源被服务端显式撤回”的事件；若未来支持撤回交付物，需要增加独立删除权威，而不能依赖首屏快照缺项推断删除。
