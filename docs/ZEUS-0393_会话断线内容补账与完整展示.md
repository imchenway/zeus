# ZEUS-0393 会话断线内容补账与完整展示

## 目标与边界

- 执行宿主重启后，重新对账仍在 Provider 中运行的 Codex 轮次，并恢复后续实时事件订阅。
- 用 Provider 官方持久历史补齐评论、思考摘要、工具过程和最终消息。
- 官方历史不包含断线期间的 `request_user_input` server request 时，只从当前会话已绑定的 rollout 中提取同一 Provider turn 的问题、选项和结果，写入既有 `conversation_process_items(kind='waiting')`。
- 没有当前执行世代真实 server-request ID 的恢复问题只读展示，不创建、替换或伪造可提交权限。
- 不新增数据库表，不依赖 ZEUS-0383，不新增单元测试。

## 已确认根因

目标会话本地持久内容停止于 `2026-08-29T03:51:09.396Z`，执行宿主随后收到 `SIGTERM`；绑定的 Codex rollout 在新宿主启动后仍继续产生评论和 `request_user_input`。现有打开会话同步在“本地仍有活动轮次”时先于执行世代对账返回，因此新宿主既没有补齐 Provider 水位，也没有重新订阅活动线程。

官方 Codex App Server 协议区分了只读历史与订阅恢复：`thread/read` 和 `thread/turns/list` 不会恢复线程或订阅后续事件，`thread/resume` 才会重新加载既有线程。`request_user_input` 的回答权限属于当前连接上的 server request，不能从 rollout 中伪造。

## 数据与权限契约

1. 打开会话时先执行当前宿主世代对账；只有同世代对账完成后，活动态门禁才可以跳过普通后台轮询。
2. 当前宿主尚未订阅、但 Provider 仍为活动态的线程执行一次 `thread/resume`，随后再次读取并投影权威状态。
3. 历史补账仍以 `thread/turns/list(itemsView='full')` 为正文来源；rollout 仅补充该接口缺失的 `request_user_input` 内容事实。
4. rollout 文件必须是会话已绑定的绝对 `.jsonl` 普通文件，且 `session_meta.payload.id` 必须精确匹配 Provider thread；只接受目标 Provider turn 的最小问题字段和匹配 `call_id` 的结果。
5. 恢复过程项使用稳定 `source_event_id` 幂等更新。真实实时请求到达时，由真实请求界面接管；轮次回答、中止或完成后，历史过程项同步收口。

## 实施记录

### 2026-08-29 · 实现阶段

- 已重新核对官方 App Server 协议。
- 会话打开同步不再用“本地仍有活动轮次”提前跳过执行世代对账；同一世代已经完成对账后，活动态门禁才跳过普通历史水位轮询。
- Provider thread authority 会区分“只读看到活动态”和“当前连接已经订阅”。新宿主对未订阅线程执行 `thread/resume`，并在恢复前后读取、投影 Provider 完整历史。
- 新增 rollout 最小证据读取器：只接受绑定线程、目标 turn、`request_user_input` 问题字段及匹配 `call_id` 的结果。恢复项不包含 server-request ID，也不进入回答 RPC。
- `TurnProcessProjector` 使用稳定 source event ID 幂等写入既有 `kind='waiting'` 过程项；回答、中止和轮次终态会把恢复项收口为完成态。
- Snapshot V2 为恢复询问增加经过白名单和长度门禁的结构化 `presentation`，避免完整问题和选项依赖 2,048 字符预览；未新增数据库表。
- Renderer 增加专用只读卡片，完整显示问题、全部选项和已恢复的非敏感结果。真实实时请求到达时按 Provider item、turn 和规范问题身份去重并接管。
- 只读恢复询问仍在等待时，Composer 禁止输入、附件和设置提交，但保留停止按钮；时间线不再显示虚假的“正在思考”。
- 优点：恢复内容与回答权限分离，正常实时路径不增加 rollout 依赖，同世代活动会话不会反复读取完整历史。代价：宿主世代切换时增加历史读取、`thread/resume` 和一次当前 rollout 扫描；rollout 不可用时继续失败关闭，不猜测问题内容。
