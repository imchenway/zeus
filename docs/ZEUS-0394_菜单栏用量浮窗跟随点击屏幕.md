# ZEUS-0394 菜单栏用量浮窗跟随点击屏幕

## 任务信息

- 任务类型：缺陷修复
- 当前阶段：实现、静态、构建与测试身份打包完成；已获授权提交并合入 `test`，独立三屏 GUI 验收等待其他任务实例释放测试身份
- 用户现象：在 A 屏点击 macOS 菜单栏 Zeus 入口后，用量浮窗经常出现在 B 屏或 C 屏。
- 用户目标：点击哪块屏幕的菜单栏 Zeus 入口，浮窗就显示在哪块屏幕；浮窗已显示时跨屏点击应直接迁移到新点击屏幕。
- 实施边界：只修复菜单栏用量浮窗的原生窗口定位与切换，不改 Renderer、IPC、用量数据、主窗口状态或公共接口。

## 已核实事实

1. 项目统一术语是“菜单栏 Zeus 入口”和“菜单栏用量浮窗”，不是主窗口内状态栏。
2. Electron `Tray` 的 `click` 事件直接提供本次点击对应的图标 `bounds` 与点击 `position`。
3. 现有左键回调丢弃这两个事件参数；浮窗经过异步创建后，定位函数重新读取全局 `tray.getBounds()`。
4. macOS 多显示器会在不同屏幕呈现同一菜单栏状态项，全局边界不代表用户刚刚点击的那一份，因此现有实现缺少“本次点击屏幕”这一事实来源。
5. 现有定位函数对目标显示器工作区的水平、垂直夹紧逻辑可继续使用，问题集中在目标显示器来源与跨屏切换分支。
6. 历史 ZEUS-0182、ZEUS-0261 均未完成真实菜单栏多屏点击验收，不能把当时的构建、打包或主窗口运行结果当作该行为已经通过。

## 已确认交互语义

1. 浮窗隐藏时，点击任一屏幕的 Zeus 入口后，在该屏幕显示。
2. 浮窗已在 A 屏显示时，点击 B 屏入口后直接迁移到 B 屏并保持显示。
3. 浮窗已在当前点击屏幕显示时，再次点击同屏入口关闭浮窗。
4. `Escape`、失焦关闭和右键原生应用菜单保持现状。

优点：每次定位以原生点击事件为唯一事实来源，不保存或猜测偏好屏幕，直接符合用户预期。

缺点：切换逻辑需要比较浮窗当前显示器与点击目标显示器，并为真实验收增加一条低频窗口定位日志。

## 实施方案

1. 左键事件发生时同步复制 `bounds` 与 `position`，作为不可变点击锚点传入异步切换流程。
2. 优先使用有效图标边界的中心解析目标显示器；边界异常时只回退到同一次事件的点击位置，不再读取 `tray.getBounds()`。
3. 先解析目标显示器，再按浮窗当前可见状态和所在显示器决定显示、跨屏移动或关闭。
4. 沿用目标显示器 `workArea` 夹紧规则，并在每次显示或跨屏移动后记录目标显示器、点击锚点和最终窗口边界。
