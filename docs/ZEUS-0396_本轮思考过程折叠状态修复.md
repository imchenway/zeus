## 用户现象

1. 当前实施轮次仍在思考和执行时，完整处理过程已经可见，但界面仍显示“收起处理过程”按钮。
2. Plan 轮次输出正式开发计划并点击“实施此计划”后，来源 Plan 轮次的过程会立即变成“查看处理过程”，与同一计划链仍在继续实施的产品语义不一致。

## 只读现场证据

- 截图文案对应会话 `conversation_9ce89e6c822eb442559ba117`。
- 来源 Plan 轮次 `conversation_turn_ef1d1eed3aee0d5f0c30cc59` 已完成并产出正式计划。
- `conversation_plan_actions` 中对应动作状态为 `implemented`，其 `submission_id` 精确指向后续实施提交。
- 当前实施轮次 `conversation_turn_2wGDK3BmoJzt` 仍为 `running`，且其 `client_submission_id` 与计划动作的 `submission_id` 完全一致。
- 因此可以使用持久身份重建“Plan 来源轮次 → 实施 submission → 当前轮次”，不需要通过正文是否为空猜测。

## 已确认产品契约

1. 正在运行且尚未进入正式输出的轮次，处理过程直接展示，不渲染“查看/收起处理过程”控件。
2. 最新待确认的正式 Plan 轮次保持展开。
3. 计划动作进入实施或修订后，只要关联 submission 仍在排队、派发、运行或等待，来源 Plan 轮次继续保持展开。
4. 来源 Plan 轮次仍使用完成态折叠控件，用户可在当前视图中手动收起；活动实施轮次没有该控件。
5. 关联实施轮次正常完成后，来源 Plan 和实施轮次都回到历史默认折叠态。失败或中断继续沿用现有终态规则。
6. 正式 Plan 是用户可见轮次输出；内部 `update_plan` 或非正式计划不能被误判为最终输出。

## 实施方案与取舍

- Renderer 从 `planImplementationRequests`、队列 submission 和轮次 `submissionId` 派生唯一计划连续链，同时归一本地与 Provider turn ID。
- 共享过程容器新增 `inline` 展示模式：保留 Snapshot V2 自动读取、加载与错误反馈，但不生成折叠按钮和对应 ARIA 属性。
- 优点：切换会话和重启后仍能从持久事实重建，不增加协议或另一套生命周期状态。
- 代价：计划实施期间会同时保留较长的 Plan 过程和当前实施过程，活动轮次也不再支持手动折叠。

- 渲染行为：正式 Plan 产出、待确认、实施排队/运行、切换会话恢复、正式输出开始及正常完成。
- 真实 GUI 只使用本任务独立 `Zeus Test.app`、`dev.hypha.zeus.test` 和独立 `ZEUS_USER_DATA_DIR`；其他任务占用测试身份时保留未验缺口，不关闭、接管或复用对方实例。

## 实施结果

- `ConversationTranscript` 从最新待确认计划动作，或其精确关联且仍在排队、派发、运行、等待的 submission/turn，派生唯一来源 Plan；turn 同时归一本地 `id` 与 `providerTurnId`。
- 正式 Plan 与正式回答共同作为轮次完成态输出；非正式 Plan 在进入轮次投影前仍由既有正式计划门禁过滤。
- `SessionTurnProcessDisclosure` 新增 Renderer 内部 `inline` 展示模式。该模式始终渲染过程正文并触发现有分页回调，保留加载和错误反馈，但不生成折叠按钮、`aria-expanded` 或 `aria-controls`。
- 当前过程行只在尚未出现正式输出且轮次仍活动时使用 `inline`；来源 Plan 保持历史 disclosure，并由计划连续链派生默认展开，因此实施期间仍可手动收起。
- 连续链结束时只清理来源 Plan 对应的临时展开覆盖；活动过程不再拥有手动折叠状态，也不再通过“活动过程已收起”生成孤立的“正在思考”兜底。
- 未修改公开 API、数据库、IPC、Snapshot V2 协议或持久字段，未新增或恢复单元测试。
