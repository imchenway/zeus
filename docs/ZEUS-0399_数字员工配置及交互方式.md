# ZEUS-0399 数字员工配置与任务执行交互优化

## 当前阶段

已完成配置契约、任务执行交互、单活动执行者约束、宽版与窄屏布局，并按产品纠正将数字员工统一为 Agent 身份。执行命令复用 Agent 会话的权限、沙箱和审批能力；项目固定部署命令仅作为显式能力保留。修正后的静态、打包与 GUI 结果见“验证记录”。任务分支开发期间未执行 commit、push、merge 或 revert。

## 已确认产品语义

- 系统模板、项目员工和单次 Agent 执行共用同一套基础配置：供应商分组模型、推理级别、服务速率、工作模式、权限模式、多个 Skill 和员工提示词。
- 模型是单一选择项，同时确定实际运行内核；不再单独选择供应商或 Runtime，避免无效组合。
- 项目员工配置是治理上限。单次执行只能收窄模型策略、推理级别、速率、Skill 和权限，不回写员工或模板。
- 每个任务同时只允许一个实际运行中的数字员工。已完成、待验收、失败和历史工作项继续完整保留。
- 任务基本信息区的“执行者”下拉只展示当前项目内已启用且主入口完整的员工。选择只打开配置弹窗，不立即产生副作用。
- 弹窗自动请求服务端权威预览，只保留“开始执行”或“停止并切换”一个最终动作。
- 数字员工只有 Agent 身份；执行命令是 Agent 的运行能力，不存在单独的 Command 员工或 Command 主入口。

## 实现结果

### 共用 Agent 配置

新增 `AgentExecutionConfigFields`，系统模板和项目员工直接复用，单次执行在相同字段上增加员工治理范围限制。模型选择复用正常会话的供应商分组、检索和文案规则；切换模型会同步更新 `agentKind`、默认推理级别和默认速率。服务速率显示能力目录名称，推理和速率选项随模型变化。

`SkillSelector` 增加允许身份过滤，并提供可搜索多选外壳。系统模板不再把多个 Skill 截断为单个，内置模板继续只读。项目员工保留模型允许集合、代码与验证权限、五项交付授权、部署命令能力和自动化配置；工作模式不再由运行时固定为 `default`。

新增只读 `GET /api/digital-employee-capabilities`。该接口只观察现有 Provider 状态并合并全局连接模型，不调用 Provider 启动或刷新；已保存但当前不可用的模型仍显示为不可用历史配置。系统模板不新增数据库字段或迁移。

从模板创建项目员工继续由存储层把模板模型、推理、速率、权限、工作模式、Skill 和提示词初始化为项目副本，并形成 Agent 的默认值和允许范围。

项目页已删除“入口类型”和“Command · 项目命令”。所有模板（包括部署数字员工）创建的项目员工均为 Agent。普通命令由 Agent 按权限调用；`deployCommandId` 仅在允许部署时作为可选项目能力展示。服务端拒绝新写入 `command` 入口；旧 `command` 或待选择记录读取时使用已有 Agent 配置并保留部署命令能力，下次保存自然写回 Agent，不新增数据库迁移。

### 任务详情交互

任务基本信息区新增“执行者”下拉，当前活动运行会显示员工和运行状态。任务工作驾驶舱移除旧“指派数字员工”按钮、可点击空状态和指派抽屉；协作、交付物、待办、证据及历史工作项保留。

单次执行弹窗提供：

- 只读员工身份、岗位、领域、Agent 运行方式和治理上限；
- Agent 的模型、推理级别、服务速率、工作模式、权限、允许 Skill 子集和本次提示词；
- 折叠的已验收交付物上下文选择；
- 服务端冻结后的入口、模型内核、Skill、权限和任务提示词布局；

配置变化后以 250 毫秒合并刷新权威预览，并丢弃陈旧响应。切换确认直接内联在同一执行弹窗中，列出全部待停止运行和耐久确认规则，不再调用 Electron 系统级 `window.confirm`。关闭弹窗不会改变当前运行和下拉展示。

### 服务端执行与切换边界

`TaskWorkPreviewSelection` 增加 `workMode`、`permissionMode` 和 `promptOverride`，预览增加冻结后的有效配置与 `promptPreview`。运行创建后从冻结入口读取真实工作模式。

`POST /api/tasks/:taskId/work-items` 接收 `replaceActiveWorkItems: [{ id, expectedRevision }]`，并在创建前重新解析预览、校验任务/员工修订和精确活动集合。以下越权由服务端拒绝：

- 模型不在员工允许集合，或当前不可用；
- 推理级别、速率不受模型支持或不在允许集合；
- Skill 不是员工允许集合的子集；
- 权限相对 `read-only → auto → full-access` 扩大。

切换按活动工作项逐个处理：当前 Agent 运行复用已有 turn interrupt；历史独立 Command run 仅在兼容停止时复用已有 run stop。每次外部停止得到耐久确认后才把对应工作项标记取消并保存。`prepared` 可直接本地取消；`dispatching` 尚未返回耐久会话身份时结果视为未知并禁止新启动。部分停止失败时已确认停止的项保持耐久取消，剩余项保持原状态，新员工不创建。

全部旧运行停止后，服务端会再次解析权威预览并确认活动集合为空，再冻结新运行；停止期间若员工配置、任务、能力目录或活动集合发生变化，新员工仍不会启动。

人工新建、失败重试、要求修改和自动化分配都检查同任务活动运行；自动化遇到现有执行者会明确失败，不静默抢占。

### 布局

任务侧边详情改用现有 `WorkspaceDrawer` 的 `wide` 能力，最大宽度约 920px；居中详情同样提升至 920px。执行弹窗最大宽度 920px，正文独立滚动，窄屏回落为单列和视口内全高布局。

## 取舍与优缺点

### 单一供应商分组模型选择

优点：与正常会话一致，模型身份天然包含供应来源和运行内核，不会保存无效组合。缺点：不提供先选供应商再选模型的二步筛选。

### 单任务单活动执行者

优点：执行者字段、切换、停止和自动化竞争的语义唯一，故障恢复可按真实运行核对。缺点：新交互不支持同任务并行启动多个员工；需要并行责任时应拆分任务或未来引入有真实依赖关系的编排。

### 单次覆盖只能收窄

优点：项目员工配置保持可信治理边界，执行弹窗不能临时扩大能力。缺点：需要先在项目设置扩充允许范围，才能在单次执行中使用更多模型或 Skill。

### 命令作为能力而非员工类型

优点：员工身份、配置和任务交互保持一套；命令复用会话权限、沙箱与审批，不产生互相冲突的授权模型。缺点：不能再把固定命令作为员工直接启动；历史独立 Command 工作项暂时仍需兼容展示和停止。

### 不新增存储迁移

优点：旧记录已有完整 Agent 配置和独立 `deploy_command_id`，读取投影即可纠正语义并保留能力。缺点：旧行会在下次保存时才把入口列物理写回 `agent`，期间数据库原始列仍反映历史模型。

- `pnpm lint`：通过。

- `pnpm build`：通过。现有 `markstream-react` pure annotation 和大 chunk 警告不影响构建结果。
- `pnpm package:mac`：通过；生成 `dist/test/mac-arm64/Zeus Test.app` 和测试 DMG，包身份为 `dev.hypha.zeus.test`，深层签名校验通过并满足 Designated Requirement。
- 临时数据库服务端集成探针：只读能力 GET 在读取时未调用 `ensureReady`；模型、推理、速率、Skill 和权限越权分别以 `ZEUS_TASK_WORK_*_NOT_ALLOWED` 拒绝；陈旧员工版本、任务忙和陈旧活动集合分别以 `ZEUS_TASK_WORK_PREVIEW_STALE`、`ZEUS_TASK_WORK_TASK_BUSY` 和 `ZEUS_TASK_WORK_ACTIVE_REPLACEMENT_STALE` 拒绝。
- Agent 身份存储探针：部署内置模板创建出的员工入口为 `agent`；显式写入 `command` 入口被 `ZEUS_DIGITAL_EMPLOYEE_COMMAND_ENTRYPOINT_UNSUPPORTED` 拒绝；原始旧行投影为 `agent/ready`，同时保留 `legacy_deploy` 部署命令能力。
- 历史兼容停止探针：旧 Command run 可经已有 stop 链路变为 `cancelled`，但当前员工新建和自动化路径不再创建独立 Command 工作项。
- 停止结果未知探针：Agent 已进入 `dispatching` 但没有耐久会话身份时返回 `ZEUS_TASK_WORK_STOP_OUTCOME_UNKNOWN`，旧项保持 `active/dispatching`，新员工未创建。
- 独立 GUI 启动：使用 `/private/tmp/zeus-0399-gui.Li0lkf` 独立数据根和当前打包的 `Zeus Test.app`；首个窗口按 `ZEUS_TEST_DISPLAY_ID=3` 落在非主外接屏，实际边界为 `x=-1268, y=268, 1240×820`。
- 配置 GUI：系统内置模板的模型、推理、速率、工作模式、权限、Skill 和提示词全部只读；自定义模板、项目 Agent 和单次执行展示同组公共字段。模型切换会联动推理和速率，已选 Skill 显示 `openai-docs` 名称而非原始 ID；“跟随模型默认”冻结预览不再偷用员工 `priority`。
- Agent GUI：无旧执行时选择员工，修改模型、推理、工作模式、权限和本次提示词，权威提示词预览自动刷新；点击一次“开始执行”后真实创建工作项并调用 Provider，但隔离 Provider 未登录，最终以 `ZEUS_CODEX_LOGIN_REQUIRED` 失败。
