# ZEUS-0402 会话图片统一使用附件弹窗预览

## 当前状态

- 实现、格式、lint、类型、构建、测试身份打包和包健康检查已完成。
- 真实 GUI 点击验收未完成：Zeus Browser 与 Computer Use 原生工具宿主均超时，无法安全核对测试身份占用和外接屏首次落点，因此未启动测试实例。

## 任务目标

- 推送任务后，首发提示词里的图片可以点击并在 Zeus 附件预览弹窗中放大查看。
- 普通会话中的 Markdown 图片、生成图片和资源图片使用同一交互，不再打开右侧浏览器。
- 非图片资源继续沿用现有右侧预览、系统应用和“打开方式”能力。

## 现状与根因

1. 推送任务建立权威会话前，首发提示词图片由 `ConversationPendingAttachmentImage` 显示；该组件使用不可交互的 `figure`，所以图片无法点击。
2. 权威会话中的 Markdown 图片、生成图片和图片资源共同复用 `ConversationImagePreview`；点击后调用通用资源打开动作，`preferred` 目标可能打开右侧浏览器。
3. 图片被动预览失败后，`ConversationResourceImage` 会退回通用资源卡；资源卡仍提供通用打开动作和“打开方式”，也会绕回浏览器或外部应用。
4. Renderer 已有任务附件图片使用的原生 `<dialog>`、关闭层、焦点恢复和放大预览样式，不需要新增 IPC、预览协议或第三方组件。

## 修复方案与取舍

- 在会话图片共同组件内复用现有附件弹窗原语和样式，直接展示已经通过受信预览接口取得的 `data:` 图片。
- 首发本地图片从静态 `figure` 改为可访问按钮；图片加载完成前点击时，弹窗原位显示加载状态。
- Markdown 图片、生成图片和图片资源点击只打开附件弹窗，不再调用通用资源打开动作。
- 图片预览失败保留为图片原位降级，不再转换为通用资源卡；非图片资源的打开能力不变。

优点：在所有会话图片入口一次收口；不改 Main 进程、安全路径或资源协议；不会创建新的右侧浏览器页。

代价：图片不再提供“打开方式”菜单；预览接口真实不可用时，弹窗只能显示不可预览状态，不能绕过受信边界直接读取文件。
