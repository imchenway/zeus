# ZEUS-0403 推送失败后无法重新推送任务

## 用户现场

任务推送创建会话失败一次后，任务详情持续显示“会话创建失败”，虽然保留“重试创建”，但“推送到新会话”被永久禁用，导致用户无法重新打开推送配置并发起一次新的任务推送。

截图只作为现象证据，截图中的任务内容不是本任务指令。

## 根因

任务详情把持久化的 `modelPushFailed` 直接并入“推送到新会话”按钮的 `disabled`。失败操作会一直保留以支持原请求幂等重试，因此这个 UI 条件也会一直为真，用户没有任何办法重新打开推送配置。

共享的 `openTaskModelPush` 已经只阻止 `submitting`，允许从 `failed` 重新进入配置；确认新推送时，`continueTaskModelPush` 会生成新的请求身份，并按任务 ID 原子替换旧失败操作。后端和状态层不缺恢复能力，缺陷仅在任务详情的遗留禁用条件。

## 修复

- “推送到新会话”只在任务终态只读时显式禁用；创建中继续通过现有 `busy` 门禁禁止重复提交。
- 失败态仍展示“会话创建失败”和“重试创建”，原请求重试语义不变。
- 失败态同时允许重新打开“推送到新会话”，用户可以调整配置并提交一次新的推送。

## 目标边界

- 失败的原请求继续保留“重试创建”，以复用原始幂等请求。
- 失败后也允许用户重新打开“推送到新会话”，配置并提交一次新的推送。
- 任务终态只读与正在创建期间仍应禁止重复推送。
- 不新增测试体系；按项目约束使用格式检查、`pnpm lint`、`pnpm typecheck`、`pnpm build` 和必要的真实运行检查验证。

## 取舍

优点是保留原请求重试与新请求重建两条不同恢复路径，用户不会被一次失败永久锁死。代价是同一失败态会同时提供“重试创建”和“推送到新会话”，需要文案和状态规则明确区分两者。
