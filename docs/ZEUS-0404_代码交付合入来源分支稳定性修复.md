# ZEUS-0404 代码交付合入来源分支稳定性修复

## 任务目标

修复代码交付页“合入来源分支”经常失败、逐仓结果又看不到真实失败原因的问题。保留本地合入、独立推送、逐仓非原子结果和 Git 数据保护边界。

## 现场证据与根因

- 用户截图显示逐仓结果为“失败 1”，但结果行只剩仓库名 `zeus`，右侧失败详情被长文本撑出可视区域。
- 2026-08-31 对正式数据库 `/Users/david/.zeus/data/zeus.db` 执行只读 `query_only` 查询，没有复制或改写正式数据。
- 当前命令回执中共有 53 次来源分支合入或收尾：43 次成功；10 次明确拒绝中，9 次均为“来源分支所在工作区存在未提交代码”，另 1 次为任务分支在冲突候选创建后继续推进。没有发现“结果未知”或随机网络错误。
- ZEUS-0345 曾在创建候选前把来源工作区“完全干净”设为硬门禁。该门禁比 Git 自身更严格：即使未提交改动与本次快进完全无关，也会直接失败，无法利用 Git 原生的安全保留能力。

## 修复原则

- 来源分支已检出且存在未提交改动时，仍由 Git 执行 `merge --ff-only`：无关改动由 Git 保留并正常完成快进；可能被覆盖的改动由 Git 拒绝，不自行覆盖或清理用户现场。
- Git 无法安全快进时继续保留隔离合入结果为 `pending_local_sync`，用户处理来源工作区后可从同一主按钮重试，不把候选成果丢失。
- 普通合入、手动冲突收尾和 AI 冲突收尾统一走同一规则，删除各调用方重复的“任意脏文件即失败”门禁。
- 逐仓结果使用可收缩、可换行的双列布局，长错误必须留在窗口内可读。

## 方案取舍

优点：消除无关脏文件造成的高频假失败；真正可能覆盖本地改动时仍由 Git 阻断并保留候选；所有合入入口共享同一安全语义。

代价：来源工作区可以在保留无关未提交改动的同时前进到新的来源提交，用户随后查看 `git diff` 时基线会变化；这是 Git 原生快进行为，不再采用“工作区必须绝对干净”的额外限制。

未采用自动暂存、自动提交或自动 stash：这些动作会改变用户未授权的来源工作区现场，也会引入额外恢复状态。
