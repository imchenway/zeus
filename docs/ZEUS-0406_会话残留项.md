# ZEUS-0406 会话残留项

## 当前阶段

- 已完成 Renderer 共享终态收口修复和现有 QA 夹具扩展。
- 定向运行断言、`pnpm lint`、`pnpm typecheck`、`pnpm build` 和 `pnpm package:mac` 已通过。
- 未执行 Git commit、push、merge 或 revert；Zeus 内置浏览器打开 QA 页两次超时，因此真实 DOM/视觉验收仍未完成。

## 用户现象

同一轮已经输出“已本地合入 main”，界面显示“已处理 5分50秒”，输入框也已恢复可继续对话，但完成内容下方仍单独显示英文内部思考摘要 `Confirming explicit merge requirement`。

## 产品契约

1. 运行中且尚未开始正式输出的轮次，当前处理摘要可以直接显示。
2. 正式输出到达或轮次进入完成态后，过程内容统一归入“查看处理过程”，默认折叠。
3. 完成态不能继续留下看似进行中的孤立摘要；Provider 原始英文过程文案也不应脱离过程容器成为主时间线正文。

优点是主时间线只保留用户消息、明确结果和必要异常，完成结果不会被内部状态干扰；代价是历史处理过程需要用户主动展开查看。

## 只读证据

- 截图对应会话为 `conversation_97da417648c3f12cf66eb86b`。
- 本地轮次 `conversation_turn_ae4b3729cb6e2b84817f58c8`、Provider 轮次 `01a055b5-6540-7cc0-87f9-0fd1182ed9fa` 均已在 `2026-08-31T02:51:36Z` 完成。
- 残留文案来自同一轮 Provider reasoning item `rs_0b002232ef4484ac016a94eadc1d4087d086fa90b276b1279a`；Provider item、`conversation_process_items` 和模型历史中的对应记录均为 `completed`。
- 正式回答 item `msg_0b002232ef4484ac016a94ec3438d887d082e0d215fe567d16` 与残留 reasoning 使用同一 Provider turn，且已明确标记 `final_answer + completed`。
- `conversation.turn.completed` 在正式回答完成后正常进入同步事件流，因此不是 Provider 仍在执行，也不是 Core 缺少轮次终态。

## 诊断结论

这是 Renderer 终态收口缺陷，不是 Provider 还在执行。用当前 `sessionReducer` 重放该会话 460 条同步事件后，轮次正常落在 `native_idle + completed`，说明持久数据与 Core 终态都正确。

实时路径仍有两个可以放大残留的缺口：

1. `conversation.turn.completed` 只把同轮的乐观用户消息收口为完成，没有把同轮尚为活动态的 reasoning、commentary 和工具项统一终结。行投影随后仍会从 item 状态推测“最新活动轮次”，因此一条未及时对账的 `in_progress` 项可以重新激活已完成轮次。
2. 终态和活动轮次按单个字符串比较；本地轮次 `conversation_turn_ae4b3729cb6e2b84817f58c8` 与 Provider 轮次 `01a055b5-6540-7cc0-87f9-0fd1182ed9fa` 是同一轮的两个合法身份。任一投影片段使用另一个身份，就可能绕过 `terminalTurnIds`。

另外，真实事件在正式回答 item `started` 时标记为 `final_answer`，但 20 条流式 `delta` 又标记为 `prework`，最后 `completed` 才恢复 `final_answer`。当前 reducer 允许阶段回退，会让会话在正式输出期间短暂重回 `active_prework`。

## 修复方案

优先只修改共享的 `sessionReducer.ts`：

1. 处理 `conversation.turn.completed` 时，同时归一本地 ID、Provider ID 和事件 ID；将全部身份写入 `terminalTurnIds`。
2. 把同一轮中仍为活动态的所有 item 统一收口为轮次终态，再清空匹配任一身份的 `activeTurnId`。这样 reasoning、commentary、命令和工具活动的所有下游投影都会同时收口。
3. item 阶段优先使用已建立的 `itemPayload.phase`；一旦进入 `final_answer`，不允许缺少正式阶段的流式 delta 将其降级回 `prework`。

这个方案的优点是在一个共享终态入口修复，实时、切换会话和重启恢复可共用同一语义；也不需要增加 CSS、英文字符串过滤或新抽象。代价是终态一旦到达，同轮迟到的过程 delta 将被忽略；这与“轮次完成后不能再恢复运行态”的现有产品契约一致。

## 实施结果

- `sessionReducer.ts`：快照水合和实时 `conversation.turn.completed` 都写入本地/Provider 轮次身份；终态事件把同轮活动 item 收口，并将其 `turnId` 归一为 Provider 身份。
- `sessionReducer.ts`：已终结 item 新增 `interrupted` 语义，防止中断轮次的迟到 delta 重新激活过程。
- `sessionReducer.ts`：正式回答 item 一旦进入 `final_answer`，后续标记为 `prework` 的流式 delta 不再降级会话阶段。
- `session-styles.tsx`：`ExecutionPhasePreview` 现在从“本地活动轮次 + Provider 完成事件 + 残留 `in_progress` reasoning”现场经真实 reducer 生成完成态，并输出活动残留数与双身份收口证据。

React 夹具仍沿用现有组件与派生值，没有新增 effect、额外状态或新抽象。
