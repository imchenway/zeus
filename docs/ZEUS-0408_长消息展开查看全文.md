# ZEUS-0408 长消息展开查看全文

## 目标

会话中的长用户消息默认保持紧凑预览，但必须提供常驻、可点击的“展开全文”入口；展开后显示完整正文，并可再次收起。

## 现场与根因

- 用户截图中的灰色气泡是用户消息，正文末尾的省略号来自 Renderer 对超过 640 个字符的普通用户消息所做的 620 字符预览，不是 Provider、数据库或 Snapshot V2 丢失正文。
- `ThreadItemView` 已保存完整 `itemText`，也已有本地 `expanded` 状态；现有入口却位于仅悬浮显示的消息操作栏，并复用了表示宽度变化的斜向箭头图标。
- 同一斜向箭头在智能体消息上只切换正文宽度，在用户消息上才切换完整正文，图标语义不一致。截图已经证明该入口不足以让用户理解“可查看全文”。
- 任务推送消息使用结构化布局完整展示，不经过普通用户正文预览；本任务不为它增加无效的展开状态。

## 方案与取舍

### 采用：复用现有状态，增加常驻文字入口

- 普通长用户消息的截断正文下方显示“展开全文”；点击后用完整 `itemText` 重新渲染，入口变为“收起”。
- 入口使用原生按钮、`aria-expanded`、不小于 24px 的命中高度和明确的键盘焦点样式。
- 从悬浮操作栏移除用户消息的重复展开图标；时间、复制和最新消息编辑能力保持不变。

优点：入口语义明确且无需悬浮寻找；复用现有完整正文和状态，不新增弹窗、全文读取协议或依赖。

代价：长消息气泡会多占一行入口高度；展开全文后会增加当前会话的纵向滚动距离。

### 不采用：弹窗或独立全文面板

优点：不改变时间线高度。

缺点：阅读上下文被打断，需要额外焦点管理和关闭交互；现有正文已经在本地，无需第二展示面。

### 不采用：取消所有长消息预览

优点：不需要展开操作。

缺点：超长日志会长期占据时间线，降低会话浏览效率，与用户要求的“点击展开”不一致。

## 实施边界

- 仅修改会话 Renderer 与本任务文档。
- 不修改 640/620 字符预算、消息存储、Snapshot V2、Provider 输入或 Markdown 安全与复杂度上限。
- 不新增测试文件、依赖或新的通用抽象。
- 不执行 Git commit、push、merge 或 revert。

## 实施记录

- 普通长用户消息继续只在折叠态渲染 620 字符预览，完整正文仍复用同一条消息的 `itemText`。
- 截断正文下方新增常驻“展开全文”文字按钮；展开后显示完整正文并切换为“收起”，再次点击恢复预览。
- 用户消息操作栏移除重复且语义含混的斜向箭头；智能体消息原有的宽度展开按钮不变。
- 任务推送结构化布局和只用于投影会话上下文的占位消息不再进入普通长消息判定，避免出现点击后没有可见变化的伪入口。
- 实现复用既有 `expanded` 状态和函数式状态更新，没有新增 effect、组件、依赖或数据通道。
