# ZEUS-0410 代码无法提交

## 现象

项目 Git 工作台存在未暂存变化时，从顶部“提交…”或“操作 → 提交…”可以打开提交弹窗。弹窗只读取真实 Git 暂存区，因此仓库数显示为 0；即使已经填写提交说明，主按钮仍然禁用。

## 根因

提交执行本身与 Git 状态读取使用同一份真实暂存区，未发现暂存状态丢失。问题是三个提交入口没有共享同一项前置判断：本地变更页只在存在暂存内容时允许提交，但顶部两个入口无条件打开仅支持暂存内容的弹窗，形成无下一步的死路。

## 修复决定

- 所有提交入口统一经过同一个打开函数。
- 存在已暂存文件时，继续打开原提交弹窗并按仓库分别创建提交。
- 没有已暂存文件时，进入“本地变更”页，不再展示“提交 0 个仓库”的无效弹窗。
- 空状态明确说明“勾选左侧文件即可暂存”，让暂存到提交形成可操作闭环。
- 不自动暂存全部变化，也不新增第二套文件选择；提交范围继续完全等于真实 Git 暂存区。

## 优缺点

优点：消除无效弹窗，所有入口遵守同一提交能力判断；不会把用户尚未选择的文件静默加入提交。

缺点：用户仍需先完成一次显式暂存；本次不提供“一键暂存全部并提交”，避免在多仓项目中扩大提交范围。
