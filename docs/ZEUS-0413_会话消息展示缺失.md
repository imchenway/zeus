# ZEUS-0413 会话消息展示缺失

## 用户现场

- 会话中间存在一块空白，但继续向下滚动后，缺失的 assistant 最终回答立即出现。
- 用户提供的 rollout 为 `01a055e0-6018-74b2-a4be-4487d770392c`，共 109 行。
- rollout 第 15 行存在完整的 `assistant/final_answer`；第 22 行才是下一条用户消息，Provider 的 `item_completed(AgentMessage)` 与轮次完成事件也存在。

## 根因

消息没有在 Provider、JSONL、Snapshot 投影或 Markdown 过滤阶段丢失。问题位于 `ConversationTranscript` 的程序化贴底与虚拟窗口之间：

1. 自动跟随会直接修改真实滚动容器的 `scrollTop`。
2. 虚拟器此前只依赖后续 `scroll` 事件刷新自己的视口坐标。
3. Markdown、过程项和行高收敛时，浏览器可能已经把 `scrollTop` 钳制到相同数值；再次赋相同值不会产生新的滚动事件。
4. 真实视口与虚拟投影因此停留在不同帧，中间消息仍被 spacer 代替；用户滚轮改变坐标后触发重投影，消息才出现。

## 修复

- 将“滚动到最新位置”和“按真实容器坐标同步虚拟视口”收口为 `positionLatest`。
- 首次水合、本地提交、快速完成、活动轮次开始、持续高度收敛和“返回最新消息”统一走该入口。
- 保留用户滚动、历史阅读锚点和 48 行虚拟窗口上限，不修改 JSONL、Provider、Snapshot V2、Markdown 或数据库契约。

优点：在共享根路径一次修复所有自动贴底调用，用户不再需要滚轮唤醒缺失消息。  
代价：每次程序化贴底会额外调度一次有界虚拟窗口投影；既有动画帧调度会合并重复请求，不增加消息解析或 DOM 上限。

## 验证结果

- Zeus 内置浏览器打开仓库真实 `ConversationTranscript` 的 `?zeus0413=1` 验收页：首次定位距底部 `0px`；延迟增高、追加回答、发送新消息后仍为 `0px`，返回最新按钮保持隐藏。
- 用户上滚后距底部为 `156px`、稳定行为 `motion:send-history-7@-5028px`；追加回答后距离和稳定行均不变，证明修复没有破坏历史阅读态。返回最新后恢复距底部 `0px`。
- `pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac`、定向 Prettier 与 `git diff --check` 全部通过。
- 测试包为 `Zeus Test.app`，bundle ID 为 `dev.hypha.zeus.test`，签名结构校验通过。另一个任务的共享测试身份正在运行，因此本任务没有关闭、借用或启动桌面测试实例；也没有把浏览器夹具和测试包证据表述为真实 Provider 回放。
