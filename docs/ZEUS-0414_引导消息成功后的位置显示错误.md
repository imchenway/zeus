# ZEUS-0414 引导消息成功后的位置显示错误

当前状态：共享轮次投影修复、QA 场景、静态检查、构建和测试身份打包已完成；本地集成候选的全部冲突已语义解决并暂存，`MERGE_HEAD` 保留。候选创建后 `main` 已继续前进，因此当前仍是等待“代码交付”统一提交和合入的 merge-in-progress，不是已合入 `main`。真实 Provider 引导往返与最终 GUI 截图受现场独立测试实例占用和 Zeus 动态工具超时阻断，未计为通过。

## 用户现场与预期

- 当前轮次执行期间，用户先发送一条排队消息，再点击“引导”。
- 引导成功后，同一条用户消息被显示到该轮全部处理过程之后。
- 预期位置是用户实际引导发生的时间点：位于此前已经发生的过程内容之后、后续过程内容之前，并继续保持用户消息右对齐。

## 已确认产品口径

- 引导成功不会创建新轮次；它仍是当前 Provider turn 中的“用户中途引导”。
- 用户中途引导必须按真实时间顺序穿插在当前轮次处理过程中，不能因为状态从排队/引导中交接为成功而移动到整轮过程之后。
- 当前轮次完成后，中途引导继续属于该轮“已处理”内容；展开后保持原时间位置和用户消息视觉语义。
- 不按正文猜测归属，不复制消息，也不通过 CSS 伪造位置。

## 根因

`projectTranscriptTurnRows` 会先把同一轮次的过程行合并为一个 `turn_work` 顶层行，再把这个顶层行放在开场用户消息之后。阶段过程重构后，`isTurnProcessRow` 排除了所有用户消息：

- 首条用户消息排除是正确的，它是本轮开场消息；
- 后续同 turn 的用户消息实际是中途引导，也被一并排除；
- 因而整个 `turn_work`（包括引导前后的全部过程）先渲染，中途引导只能在其后作为顶层消息出现。

这不是 Provider 数据丢失、引导身份失败、虚拟列表漏绘或自动滚动问题，而是轮次行投影把“开场用户消息”和“中途用户引导”错误地采用了同一排除规则。

## 方案与取舍

- 保留每个 turn 的第一条用户消息为开场消息。
- 把同 turn 的后续用户消息纳入该轮过程时间线，沿用现有阶段切片和右对齐样式。
- 不修改 Provider、submission、队列、时间戳、虚拟列表或滚动控制器。

优点：只修共享行投影一次，活动态、完成态、实时事件和历史水合共用相同顺序；既有用户中途引导样式可以直接复用。

代价：轮次完成并收起“已处理”后，中途引导也随该轮过程折叠；这是既有“中途引导属于当前轮次过程”的产品口径，展开后仍完整可见。

未采用把 `turn_work` 拆成多个顶层块：它会恢复多个“已处理”入口，破坏当前单轮单入口的阶段摘要设计，改动范围也更大。
