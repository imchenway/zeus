# ZEUS-0416 会话底部上滚受阻

## 任务目标

修复会话停留在底部时，鼠标向上滚动需要重复多次才能正常阅读历史的问题。

## 现状与根因

- `ConversationTranscript` 在 `wheel` 事件中只登记短时的用户滚动意图，要等后续 `scroll` 事件的离底距离超过 `24px` 才把控制器切换为历史阅读态。
- 底部跟随的几何收敛循环可以在这两个事件之间继续写回 `scrollTop`；离底不超过 `24px` 时，`onScroll` 还会再次请求贴底。
- 结果是初始的向上滚动位移被程序贴底抵消，用户只能通过重复滚动或更大加速度逃离底部容差区。
- 虚拟列表的高度测量、稳定行补偿和历史分页只会唤醒同一贴底调度器，不是独立根因。

## 实施边界

- 复用现有两态滚动控制器，不新增滚动管理层或依赖。
- 向上鼠标滚轮属于明确的“离开最新内容”意图；第一次有效输入即暂停程序贴底，后续原生滚动不应被抵消。
- 向下回到底部、“返回最新消息”、本地发送后恢复跟随，以及异步高度变化的贴底收敛保持不变。

## 实施记录

- 在既有贴底收敛函数中增加用户滚动意图门禁：滚轮、触控、滚动条或键盘滚动正在发生时，立即结束本轮程序贴底，不再写回 `scrollTop`。
- `180ms` 意图窗口结束时，只有仍处于跟随态才重启贴底收敛；已越过 `24px` 门槛的历史阅读态保持用户位置。
- 不改控制器状态模型、虚拟窗口、历史分页和 CSS，不新增依赖。

## 取舍

- 优点：在用户意图的最早权威入口停止竞争，改动小，同时保留既有贴底和阅读锚点能力。
- 代价：真实滚动意图存续期间，最新内容跟随最多延后 `180ms`；未越过 `24px` 门槛时，意图结束后会立即补齐这次贴底。
