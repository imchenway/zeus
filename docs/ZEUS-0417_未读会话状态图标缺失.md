# ZEUS-0417 未读会话状态图标缺失

## 现象

任务推送创建的会话在服务端状态更新后，侧栏仍可能长期显示创建阶段的状态，导致运行、完成或普通未读等真实状态没有按既有状态表显示。

## 根因

任务推送被接受后，本地 pending 工作面会继续保留，以维持草稿、滚动位置和首发会话的稳定导航身份。会话列表合成此前无条件把 `pending.choice` 放在服务端列表之前，并过滤同 ID 的服务端会话，因此创建阶段保存的 `hasUnreadAttention`、`attentionKind`、阶段和运行状态会持续覆盖服务端权威状态。

## 修复

- 创建中、重试中或失败时，继续使用本地 pending choice。
- 任务推送已接受且服务端列表已出现同 ID 会话时，改用服务端 choice 作为会话状态事实。
- 从 pending 状态只保留稳定 `navigationId`，不再用旧的未读、关注类型、阶段或运行状态覆盖服务端数据。
- 继续保留已接受的任务推送工作面状态，不重建会话工作面。

## 状态边界

- 运行、待输入、待批准、失败、中断、完成继续使用 `ProjectConversationTree` 既有图标。
- 完成未读继续显示绿色完成图标；失败和中断继续显示各自图标。
- 只有普通未读显示既有 7px 蓝点。
- 不修改公开 API、数据库结构、`NativeConversationChoice` 类型、图标映射或 CSS。

## 取舍

优点是只修复状态来源，保留既有图标设计和任务推送工作面连续性。代价是 accepted 状态合成时必须显式保留稳定导航身份，避免服务端 choice 接管状态后触发工作面重建。
