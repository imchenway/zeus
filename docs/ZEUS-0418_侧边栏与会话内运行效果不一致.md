# ZEUS-0418 侧边栏与会话内运行效果不一致

## 现象

侧边栏会话图标持续转圈，标题栏也提供“停止控制”，但会话正文底部没有“正在思考”或当前处理过程，造成侧边栏与会话内状态不一致。

## 现场证据

- 附件 JSONL 共 2,808 行、约 71.5 MB，包含 1,466 条 `event_msg` 和 1,328 条 `response_item`。
- 实施轮次 `01a055fe-d27c-75e0-84de-385d412b3ac0` 于 `2026-08-31T04:05:58Z` 开始；附件截至 `05:40:19Z` 仍没有 `task_complete`。截图文件名时间对应约 `05:39:05Z`，当时前一条命令刚于 `05:39:03Z` 完成，下一条 reasoning 于 `05:39:07Z` 开始。因此侧边栏转圈表达的是真实运行态，不是陈旧状态。
- 该活动轮次在附件中已有 423 条命令、405 条 reasoning、30 条文件修改、26 条 Agent 消息和 23 条图片查看完成事件。最后一条用户可见 commentary 于 `05:35:11Z` 写入，之后持续发生工具和 reasoning 事件。
- 本地只读数据库中的同步事件表证明截图前后的 reasoning 与命令均及时入库，不存在 Provider JSONL 到 Zeus 持久层的摄取延迟或丢失。
- 截图时模型历史尾部 48 条记录中，37 条是工具调用配对，11 条是 reasoning，没有 commentary；完整处理过程则另存于 882 条过程记录中。
- 该轮次后来于 `05:45:51Z` 正常完成，说明附件只是执行中的截面。

## 根因

问题位于会话恢复投影，不在 Provider 或侧边栏状态来源：

1. Snapshot V2 的 `activeItems` 只读取 `status = 'in_progress'`。一个命令刚完成、下一条 reasoning 尚未开始的间隙里，活动轮次仍在运行，但 `activeItems` 可以为空。
2. 冷启动或重进会话只读取模型历史尾部 48 条；高频工具调用先占满额度，随后 Renderer 又丢弃工具调用行。截图时 48 条里有 37 条最终不会显示，最近的 commentary 已被挤出窗口。
3. 完整过程记录单独持久化，但只有在正文中已存在过程锚点时才会继续分页读取。恢复结果没有锚点时，已保存的 882 条过程不会自动出现在正文中。
4. reasoning 回退还有一个确定的零显示窗口：正文选择“最后一条 reasoning”渲染；若最后一条摘要为空，组件直接返回空。同时任意更早的非空 reasoning 因轮次仍活动而被判为“当前状态”，又会抑制独立的“正在思考”状态行。附件尾部正好出现了一条空 reasoning，可稳定满足这一条件。

因此答案是：过程内容没有从 JSONL 或数据库丢失，但大量已处理内容在会话恢复和显示投影中漏显。截图精确时刻的最后一条 reasoning 仍有文本，缺少当时 Renderer 内存快照，不能把第 4 点单独认定为截图瞬间的唯一触发条件；前 3 点已足以证明当前恢复边界会丢掉可见过程锚点。

## 修复建议与取舍

推荐在共享 Snapshot V2 恢复边界做最小闭环：

- 为活动轮次额外携带一个有字节上限的“最近可见过程”尾部，覆盖已完成的 commentary、reasoning 和过程记录，不再只依赖当前 `in_progress` 条目。
- 对模型历史先按可显示语义保留槽位，再应用 48 条上限，避免工具配对占满窗口后又被 Renderer 丢弃。
- Renderer 使用同一个“最后一条非空活动 reasoning”判断渲染和回退；没有可渲染摘要时必须显示独立的“正在思考”。
- 活动轮次已有过程水位但没有正文过程锚点时，自动读取一个有界过程页，不全量加载本次 882 条记录。

优点是从公共恢复入口修一次即可覆盖切换会话、冷启动和命令间隙，且保持首屏有界。代价是活动会话首屏增加一次小型查询和有限字节。仅把 48 调大虽然改动更少，但工具密集轮次仍会再次耗尽窗口；全量加载过程则会显著放大首屏，不建议。

## 修复实现

- Snapshot V2 的活动轮次投影继续复用既有最多 64 条、单项最多 2,048 字符和总响应 64 KiB 边界，但由“仅进行中条目”改为“最近的 prework 条目以及进行中的最终回答”。刚完成的 reasoning、命令、文件修改和阶段说明因此不会在下一条事件开始前消失。
- 活动投影保留每条 Provider 记录的真实 `in_progress`、`completed` 或 `failed` 状态；Renderer 不再把恢复出的已完成操作误画成仍在运行。
- Snapshot V2 结构代际更新为 `2026-08-31-conversation-snapshot-v2-active-turn-tail`，旧缓存不会与新活动尾部语义混用。
- 会话正文选择最后一条非空 reasoning 作为活动摘要，状态抑制也复用同一判定；若活动轮次只有空摘要，独立“正在思考”状态会继续显示。
- 没有提高模型历史 48 条上限，也没有全量加载 882 条过程；活动尾部先恢复当前现场，既有过程分页仍负责用户继续查看的完整记录。
