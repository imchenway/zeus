# ZEUS-0421 任务处理失败后会话输入框恢复

## 2026-08-31 诊断阶段

### 用户现象

- 会话轮次在执行命令后显示“处理失败”。
- 失败结果下方的会话输入框进入禁止输入状态，用户不能在原会话补充信息或继续处理。
- 产品要求：会话中的单轮处理失败不能把原会话输入区永久锁死。

### 目标流程

任务处理失败 → 保留本轮失败结果与真实原因 → 会话输入框仍可聚焦、输入和添加附件 → 用户明确提交下一条消息 → Zeus 先核对 Provider 线程处于安全空闲边界，再在原会话开启新一轮。

### 代码根因

1. Codex 轮次失败后，投影层同时把轮次和整个会话的 `providerState` 都设置为 `failed`。
2. 会话选择查询把 `providerState=failed` 固定投影为 `resumable=false`；`SessionWorkspace` 在已有快照时也把 `failed` 解释为不可续接。
3. `ConversationComposer` 与 `sessionSelectors` 已经允许 `conversationState=turn_failed` 编辑并发送，因而真正阻断来自外层“整个会话不可续接”门禁，而不是输入控件。
4. 服务端发送链路已经具备 Provider 线程权威读取与安全空闲边界校验，但历史投影在看到本地 `providerState=failed` 时会提前拒绝恢复，未使用这套已有能力。

### 实施边界与取舍

- 保留失败轮次、失败原因和失败关注状态，不把失败伪装成成功。
- `closed`、归档、显式只读、受管工作项与未知 Provider 写入窗口继续阻止续发。
- 失败会话只获得“可以发起明确续发”的资格；真正 Provider 写入前仍必须确认线程空闲且最近本地终态轮次能在 Provider 快照中对上。
- 不自动重放失败消息，不自动创建新会话，不新增依赖或测试文件。

优点：恢复原会话上下文，且不牺牲防重复写安全边界。缺点：失败后的首次续发需要额外读取 Provider 权威状态；若 Provider 无法证明安全空闲，提交会进入现有可见恢复状态而不会猜测发送。

- 本任务不执行 commit、push、merge、revert 或正式发布。

## 2026-08-31 实现阶段

1. 会话列表不再把 `providerState=failed` 投影为不可续接；`closed` 仍是永久不可续接。
2. 会话工作区已水合快照的门禁使用同一语义，失败轮次不再封锁 `ConversationComposer`。
3. Provider 历史投影复用现有 `snapshotConfirmsSafeResumeBoundary`：Provider 必须空闲、所有 Provider 轮次必须终态，且最近本地终态轮次标识必须匹配，才恢复派发。
4. 重启队列排空不再盲目跳过失败会话；它只处理用户已明确提交的持久化后续消息，并继续通过同一 Provider 权威边界校验。
5. 在现有 ZEUS-0388 真实组件 QA 页增加“失败轮次”夹具，未新增测试文件、依赖或抽象。

## 2026-08-31 补充诊断：Codex 模型容量失败未显示

### 现场事实

- 当前持久 Worktree 分支为 `zeus/ZEUS-0421-task-02`，基线 `HEAD=30526c8a`，已包含上述输入框解锁修复。
- 正式数据库最近 4 条 Codex 失败轮次全部使用 `gpt-5.6-sol`，Provider 原文均为 `Selected model is at capacity. Please try a different model.`，`codexErrorInfo=serverOverloaded`。
- 发生时间为 2026-08-31 14:42、14:51、15:36、15:37（Asia/Shanghai），分别对应“自动化的下拉框”、“任务处理失败”、“冲突处理：任务处理失败”和“上下文管理策略”会话。
- `conversation_turns.error_json` 完整保留了通用错误码 `ZEUS_CODEX_TURN_FAILED`、Provider 原文和 `serverOverloaded`；故障不在 Codex 事件摄取或 SQLite 持久化。
- 正式 v0.3.89 的 Snapshot V2 对同一失败轮次只返回 `hasError=true`，不返回失败对象；Renderer 适配器又固定投影为 `error=null`。
- 刚失败时的 `conversation.turn.completed` 实时事件也只广播终态，没有携带已落库错误；Renderer reducer 只保留旧轮次上已有的 `error`。因此无论实时到达还是重新水合，时间线都只剩“处理失败”。

### 根因与实施取舍

Snapshot V2 切换时只带上了失败布尔标记，遗漏了旧快照已有的失败分类、脱敏和可见投影。本阶段复用现有失败卡，但不经过全局错误翻译入口：

- Snapshot V2 轮次摘要恢复有界、脱敏的失败对象，实时终态事件复用同一投影；不暴露密钥、本机路径、堆栈或无界 Provider 载荷。
- `serverOverloaded` 仍映射为稳定的产品错误身份供分类使用；界面直接显示脱敏后的 Provider 原文，不翻译、不改写，也不向 DOM 直出内部错误码。
- 失败轮次仍保持 `failed`，不自动重放原消息；输入框继续使用上述已合入的“可明确续发 + Provider 权威边界校验”语义。

优点：Codex、Pi 与自定义模型的真实拒绝原因都能直接用于下一步判断，无需改表、迁移数据或自动重发。缺点：提示语言和措辞由 Provider 决定，不再保证 Zeus 文案一致；密钥、路径、堆栈与超长载荷仍必须脱敏或截断。

## 2026-08-31 补充实现与验证：失败原因可见

### 实现结果

- Snapshot V2 轮次摘要新增有界失败对象；实时 `conversation.turn.completed` 与 Provider 历史同步复用同一脱敏投影，Renderer 不再把失败详情固定丢弃为 `null`。
- `serverOverloaded` 稳定映射为 `ZEUS_CODEX_MODEL_AT_CAPACITY` 供分类使用，失败卡逐字显示脱敏后的 Provider 原文 `Selected model is at capacity. Please try a different model.`；失败轮次仍保持 `failed`。
- Pi 与自定义模型的 `runtime_error` 实时终态事件补齐同一个失败对象，避免只有刷新历史后才显示 Provider 原文。
- 失败卡按附件样式改为中性描边圆角条、感叹号图标与原文，并使用 `role="alert"`；不再复用会翻译或通用化错误的 `VisibleApplicationError`。
- 历史 `error_json` 的 SQLite JSON 读取改用惰性 `CASE` 守卫。损坏的旧错误 JSON 只降级为有界通用错误，不会因 `json_type` 对非法 JSON 求值而拖垮整个 Snapshot V2。
- 未自动重发失败消息、未新增迁移或依赖；失败后下一条消息仍由用户明确提交，并继续经过 Provider 权威空闲边界核对。
