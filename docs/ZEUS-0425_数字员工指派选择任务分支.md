# ZEUS-0425 数字员工指派选择任务分支

## 产品结论

人工指派数字员工时必须同时确认执行员工与代码现场。新员工始终创建独立会话，但可以继续任务已有的完整 `TaskEnvironment`，也可以创建新的任务分支。

默认规则如下：

- 当前执行者已绑定一个任务环境时，默认继续该环境；
- 否则只有一个可用环境时，默认继续该环境；
- 没有可继续的环境时，默认创建新的任务分支；
- 有多个可继续环境时不代替用户猜测，必须显式选择继续哪一个或新建；
- 无登记仓库的项目不展示伪分支选择，继续使用项目目录直连；
- 自动化与任务池保持独立工作项语义，显式冻结“创建新的任务分支”。

`TaskEnvironment` 是多仓任务的最小选择单位。界面展示环境内全部仓库、任务分支与来源分支，协议只提交 `environmentId`，不允许用裸分支名或只选择部分仓库。

优点：测试员工可以直接检查开发员工的真实 worktree，员工会话仍彼此独立；需要并行方案时仍可显式新建执行线。缺点：存在多个可继续环境时会增加一次人工选择，自动化暂不接力已有环境。

## 接口与持久化

人工预览选择增加 `workspace`：

- `{ mode: 'create' }`；
- `{ mode: 'existing', environmentId }`。

服务端无登记仓库时解析为 `{ mode: 'direct' }`。预览响应返回解析后的完整 workspace 快照，并将快照纳入 `previewSha256`，因此来源修订、建议分支名或已有环境选择变化都会使旧预览失效。

`task_work_runs` 通过前向迁移增加：

- `workspace_snapshot_json`：冻结直连、已有环境身份，或创建模式下的仓库清单修订、来源引用和建议分支名；
- `environment_id`：会话成功创建并核对后记录实际绑定的环境。

迁移不修改既有 `20260829_0001_task_work_v2` checksum。有关联会话且能确认环境的历史运行，从 `conversations.environment_id` 回填两列；无法确认的历史记录保留 `NULL` 作为旧运行兼容标记，首次恢复派发时只解析并冻结一次创建或直连快照。

## 执行边界

- `existing` 预览只接受当前项目、当前任务能力投影中的未关闭环境。
- 环境有活动写入者时默认不可用；只有全部活动写入会话都属于本次待替换的当前任务工作项，才允许显示和选择“停止后继续”。
- 切换执行者沿用原有顺序：精确校验活动工作项修订、耐久停止旧运行、重新解析预览并复验环境、确认没有遗留活动工作项、创建并派发新运行。
- 停止失败、正在派发但没有耐久会话身份、停止结果未知或复验失败时，不创建新员工工作项。
- 派发只使用运行中冻结的 workspace 快照，不重新计算 `01/02`。新会话接受后必须校验实际 `environmentId`：继续模式必须精确相等，新建模式必须存在，直连模式必须为空。
- 返工与重试优先使用前次成功记录的 `environmentId`；前次从未成功建立环境时才继续使用原创建快照。

## 界面实现

数字员工指派弹窗复用任务推送的任务环境能力与分支标签：

- 提供“继续已有任务分支”和“创建新的任务分支”；
- 多仓环境按整体列出全部仓库、分支和来源；
- 已关闭或被无关活动会话占用的环境禁用；
- 当前即将停止的数字员工独占环境时标记“停止后继续”；
- 多个可继续环境时不生成预览，直到用户作出选择；
- 任务轮询不会重置用户已经作出的 workspace 选择。
