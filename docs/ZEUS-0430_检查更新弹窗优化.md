# ZEUS-0430 检查更新弹窗优化

## 任务目标

当 Zeus 已有一个更新等待重启，但公开稳定版已经继续向前发布时，用户再次执行“检查更新”必须取得最新发布事实，允许直接准备最新版，不得只展示旧目标的“立即重启”。

## 现状与根因

- `HomebrewUpdateController.showOrCheck()` 把 `ready` 当成无需再检查的终态，用户从菜单或侧边栏再次打开时只重放待重启窗口。
- 自动检查在更新已安装到磁盘、但当前进程尚未退出时直接短路，同样无法发现更高版本。
- 待重启期间，磁盘 App 可能已经由 Homebrew 替换成中间版本，而旧进程仍在运行。原校验只接受进程版本，会把这个合法状态误报为 App 版本异常。

## 实施决策

1. `ready` 状态下的显式检查和周期检查都继续读取发布清单。
2. 最新版本与已准备更新的版本、SHA-256 同时相同时，复用现有缓存和精确重启目标；不重复下载或安装。
3. 发现不同目标时清除旧准备态，弹窗回到“下载更新”；自动路径则直接预取新目标。
4. 磁盘 App 版本必须等于当前运行版本或 Homebrew 已安装收据版本，且继续严格校验精确路径、bundle ID、短版本和构建版本。

## 方案取舍

- 优点：手动与自动更新共用同一状态机；不需要新按钮、新弹窗或第二套安装逻辑；相同产物仍复用已校验缓存。
- 缺点：用户在待重启态显式点击“检查更新”时会增加一次轻量发布清单请求；新目标预取失败后不再把旧目标冒充为最新版。

## 验收边界

- 使用隔离 Homebrew 替身覆盖“已准备 A，再检查发现 B”与“A 已安装到磁盘但旧进程未重启，继续准备 B”。
- 执行 `git diff --check`、定向 Prettier/ESLint、`pnpm typecheck`、`pnpm lint` 和 `pnpm build`。
- 如需 GUI 验收，只允许当前任务的 `Zeus Test.app`、`dev.hypha.zeus.test` 和独立 `ZEUS_USER_DATA_DIR`；首帧无法保证位于非主外接屏时停止。
- 不新增或恢复单元测试。

## 阶段状态

- 已完成任务文档、现有更新链路与根因核对。
- 已完成最小实现、静态门禁、全量构建和隔离行为验证。
- 未执行 Git commit、push、merge 或 revert。

## 实现结果

- 显式“检查更新”不再把 `ready` 当成终态，会重新读取发布清单。
- 周期检查不再因为已安装但未重启而短路，可继续发现并预取更高版本。
- 版本和产物 SHA-256 都未变时保留已准备产物与精确重启目标；发现新目标时才清除旧准备态。
- Homebrew 准备新版本前，磁盘 App 可以匹配当前进程版本或已安装收据版本；其他版本、错误路径或错误 bundle ID 仍会被拒绝。
