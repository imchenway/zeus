# ZEUS-0431 切换 Git 工作台不再重复显示全页加载

## 用户现场与目标

- 用户在同一项目内离开 Git 工作台后再次点击“Git”，页面都会先被“正在读取项目 Git 现场”全页加载态覆盖，切换显得卡顿。
- 目标是重复进入已成功读取过的 Git 工作台时立即显示真实页面；首次进入仍如实加载，用户主动刷新仍重新读取真实 Git 现场。

## 已确认根因

- `WorkspaceView` 只在当前项目区段为 `git` 时挂载 `ProjectGitWorkbench`；切到任务、源码、图谱或命令后，Git 工作台会被卸载。
- `ProjectGitWorkbench` 的仓库快照只存在组件本地状态。每次重新挂载都会从 `null` 开始，并再次调用 `loadProjectGitWorkbench`。
- 服务端读取会重新发现项目内仓库，并发读取每个仓库的状态、分支、提交和差异；全页加载态因此不是单纯动画，而是重复等待真实 Git 扫描。

## 实施决定

- 复用项目已有的“缓存先显示”模式：按客户端和项目隔离最近成功的 Git 工作台快照，重复进入同步恢复快照。
- 缓存只保留最近 3 个项目，且只存在当前 Renderer 进程内；不持久化，也不作为 Git 权威事实。
- 首次读取中的请求会合并，快速离开再返回不会再发起第二次相同扫描。
- 已有快照时不因页面切换自动扫描；工具栏“刷新”继续显式读取真实现场，所有 Git 动作完成后返回的仓库快照继续更新页面和缓存。
- `ProjectGitWorkbench` 按项目 ID 建立 React 身份，项目切换时不复用另一个项目的内部选择状态。

优点：同一项目重复点击 Git 直接显示完整工作台，不再闪回大面积白色加载页，也避免重复 Git 扫描。

代价：外部工具修改 Git 后，已打开过的页面不会仅因离开再返回而自动更新；用户需要点击现有“刷新”。Renderer 最多额外保留 3 份最近项目快照。

## 验证结果

- `pnpm typecheck`、`pnpm lint`、`pnpm build`、`pnpm package:mac` 均通过；构建仅保留既有的第三方注解与分包体积提示。
- `Zeus Test.app` 的 bundle ID 为 `dev.hypha.zeus.test`，严格签名校验通过。
- 使用独立用户数据目录启动当前任务测试包；首个窗口按要求落在显示器 3，启动日志确认目标与实际显示器均为 3。
- 在隔离数据中创建指向当前任务 worktree 的项目。首次进入 Git 完成真实读取后，切换到“任务”再返回 Git；返回后的首个状态快照耗时 81ms，已直接包含“项目 Git 工作台”，未出现“正在读取项目 Git 现场”。
- `git diff --check` 与目标文件 Prettier 检查通过。
