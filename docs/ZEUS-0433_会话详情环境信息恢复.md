# ZEUS-0433 会话详情环境信息恢复

## 任务目标

- 会话详情“环境”分组展示会话真实工作目录与该目录当前 Git 分支，不再无条件显示 `-`。
- 继续使用既有“会话执行现场”口径：目录来自持久会话执行上下文，分支来自该目录的只读 Git 查询；不从标题、提示词或任务名称猜测。
- 普通会话、任务 worktree、非 Git 目录和执行目录不可恢复的历史都保持同一失败关闭语义。

## 根因

- `ZEUS-000012` 已实现 `readNativeConversationExecutionContext()`，并把结果写入旧 V1 会话快照。
- ZARCH/Snapshot V2 重构退役了 V1 快照组装器，但新的 Snapshot V2 首屏没有接回执行现场投影。
- Renderer 的 `executionContext` 类型、适配后快照字段和会话详情展示仍然存在，因此工作目录与分支都落入“暂无数据”占位符。

## 方案与取舍

1. Snapshot V2 API 在读取有界首屏前，通过现有 `resolveNativeConversationExecutionRoot()` 解析会话权威执行根。
2. 复用 `getGitWorkingContext()` 只读查询该目录当前分支，并把执行现场纳入 Snapshot V2 字节预算。
3. Renderer 的 V2 适配器把该字段原样投影到现有 `NativeConversationSnapshot`，继续复用 `RuntimeDetails`，不新增 UI 分支或备用推断。

优点：在共享快照入口一次修复全部主会话；保留真实目录、实时分支和失败关闭边界；不增加存储表或第二套 Git 实现。

代价：打开会话详情时增加两次轻量只读 Git 子进程调用；分支反映快照读取时刻，外部切换分支后需刷新详情才会更新。

## 实现记录

- `conversationSnapshotV2Api.ts` 在首屏读取时请求执行现场；`localServerPlatformRoutes.ts` 复用 `resolveNativeConversationExecutionRoot()` 与 `getGitWorkingContext()`，不从会话标题或任务元数据猜测。
- `conversationSnapshotV2.ts` 把执行现场作为可选兼容字段纳入 Snapshot V2 的统一字节预算；旧调用方不提供该字段时保持原响应结构。
- `conversationSnapshotV2Adapter.ts` 原样投影 `executionContext`，现有 `SessionRuntimeDetails` / `RuntimeDetails` 自动展示工作目录和分支，没有新增组件或 CSS。
- 只读验证模式固定返回不可用执行现场，不解析持久正式路径、不访问正式 workspace/Git；`http-read-effect-policy.mjs` 将该端口归为 Git 读取，并登记 Snapshot V2 的失败关闭投影证据。
