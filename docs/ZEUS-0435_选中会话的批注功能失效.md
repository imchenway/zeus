# ZEUS-0435 选中会话的批注功能失效

## 用户现象

- 从侧栏选中一个已结束的空闲会话后，选中助手回答正文不再显示“添加到对话”批注入口。
- 同一会话的输入框仍可编辑，因此不是会话已归档或整个会话不可续接。

## 根因

空闲会话从侧栏打开时使用轻量的 `historyOnly` 模式。该模式已经允许输入框、附件和 `conversationContext` 草稿写入，但回答批注和右侧文件评论仍错用 `interactionReadOnly` 门禁。

结果是 `onContextDraftChange` 明明可用，`SessionWorkspace` 却没有把批注回调传给 `ConversationTranscript`；`ResponseSelectionActions` 因此直接处于禁用状态，而不是选区计算或浮层定位失败。

## 修复与取舍

- 复用输入框已有的 `composerReadOnly` 语义，统一派生 `contextDraftWritable`。
- 回答批注的新增、修改、删除以及普通文件/差异评论都使用这一门禁。
- 会话归档、显式只读、不可续接或任务级只读时，`composerReadOnly` 仍为真，批注不会被误解锁。

优点：批注与输入框本就共享同一份 `conversationContext` 草稿，权限语义恢复一致，不需要改选区算法、数据库或 Provider 协议。

代价：空闲历史会话仍保持 lazy 连接；用户真正发送批注时才升级为实时交互，沿用现有安全续接机制。
