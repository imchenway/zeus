# ZEUS-0441 会话详情排版优化

## 任务目标

- 会话详情按“会话、费用、性能、环境”四个分区展示。
- 会话分区固定为三行：模型配置、上下文与缓存、累计 Token。
- 费用和性能各保留一个高频指标；环境按工作现场、原生身份、MCP 启动三行展示。
- 继续复用真实运行事实、长值截断和复制反馈，不新增指标采集、存储字段或依赖。

## 已核对现状

- 主会话与 Subagent 共用 `RuntimeDetails`；一次修改可以保持两类详情一致。
- 现有快照已经提供模型、推理强度、实际服务档位、上下文、缓存、累计 Token、估算费用、最新输出速率及环境事实，本任务无需新增数据链路。
- 当前展开详情仍展示计费档位、费用完整性、价格目录与来源、首响、累计耗时、活动计数和代码改动，且“会话 / 费用”并排，信息密度高于本次预期。
- 服务档位存在用户选择、Provider 实际档位和用量计费档位三种事实；本次“速率”使用会话当前的 Provider 实际档位，标准档位显示“标准”，目录档位显示目录名称。

## 方案与取舍

1. 复用共享 `RuntimeDetails`，把每个目标行表达为独立描述列表，CSS 只负责行内自适应列数。
2. 摘要继续保留五项紧凑指标；展开后只展示用户指定字段，底层诊断事实不删除。
3. 工作目录、分支、线程 ID 与 JSONL 各占一个自适应单元；窄宽度自然堆叠，线程 ID 和 JSONL 继续复制完整原值。

优点：字段顺序稳定、扫描路径短；主会话与 Subagent 同步生效；没有新增状态、依赖或数据口径。

缺点：费用覆盖率、价格来源、活动计数、首响和代码改动不再能从会话详情直接查看；需要这些诊断信息时应另设诊断入口，而不是继续塞回高频详情。

## 实现记录

- `RuntimeDetails` 使用四个顺序分区；每个目标视觉行由独立描述列表表达，标签和值保持同行，窄宽度由行内 `flex` 按 DOM 顺序自然换行。
- 会话区只展示模型、推理强度、速率、上下文占用、缓存命中率及累计 Token；中文界面中 `priority / Fast` 统一显示为“快速”，标准档位显示为“标准”。
- Token 与上下文的可见值使用紧凑 K/M 单位，完整 Token 数继续保留在 `title` 与无障碍名称中。
- 费用只保留 API 等价费用估算，性能只保留最近输出速率；环境按工作现场、原生身份、MCP 启动三行展示。
- 删除的是 Renderer 展示与对应死格式化函数；费用覆盖、价格来源、活动、耗时和代码改动等底层事实仍保留，没有改动快照与 Provider 链路。

### 二次反馈修正

- 原实现把分区容器定义为“标题列 + 内容列”，与预期中“标题单独一行、指标在下一行”的层级相反；现统一改为单列，行内指标仍自适应排列。
- 黄色框来自已聚焦 `<summary>` 在按键后匹配 `:focus-visible` 时的 Chromium 默认轮廓，与 MCP 告警和快捷键业务状态无关。
- 普通显示模式改用左侧局部中性焦点标记，避免整条黄色矩形；强制高对比模式仍保留完整 `CanvasText` 轮廓。

### 三次反馈修正

- 缓存命中率错位的根因是每个视觉行仍使用 `auto-fit` 等宽网格；两个字段在宽屏上被分到相距很远的两列，看起来像跨行。
- 每个视觉行改为按内容宽度排列的 `flex` 布局，因此“上下文占用 / 缓存命中率”会紧邻显示，宽度不足时再按 DOM 顺序换行。
- 分区正文增加 16px 缩进与轻量层级线，标签降低视觉权重、真实值提高对比；环境的长值行仍保留两列自适应与省略。

优点：字段关联与文本预期一致，宽屏不会人为拉开短指标，且没有新增组件、状态或依赖。

缺点：极窄宽度下短指标会换行，不再强制对齐为等宽表格；这是为了保留字段顺序与可读性的明确取舍。
