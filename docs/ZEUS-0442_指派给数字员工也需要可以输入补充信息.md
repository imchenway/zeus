# ZEUS-0442 指派给数字员工也需要可以输入补充信息

## 当前阶段

2026-09-02 已完成验收反馈修复：“补充信息”现在与普通任务推送一样支持粘贴图片、文件和长文本，并且附件已进入服务端权威预览、摘要与运行快照。当前会话未为本轮启用 Computer Use，因此真实桌面粘贴操作仍是未验缺口；没有使用 AppleScript、坐标脚本或外部 Playwright 替代。

## 需求来源与真实语义

- 来源是本任务冻结清单中的优化需求：“指派给数字员工也需要可以输入补充信息”，任务描述为空且没有附件。
- `docs/contexts/work-management/CONTEXT.md` 将“工作指派”定义为管理者通过预览与确认，把任务中的一份明确责任交给数字员工；补充信息因此属于“本次工作项输入”，不是任务描述、员工能力配置或员工默认提示词。
- 指派次数、尝试次数和岗位名称不影响该语义；一次运行必须使用预览时确认的文本，重试必须继承同一冻结输入。

## 边界与取舍

- 复用普通任务推送已有的 `supplementalInfo` 语义和发送预览，不新建第二套消息或提示词系统。优点是用户心智、会话投影和 Provider 输入保持一致；缺点是本轮需同时修改 Renderer 与服务端契约。
- 文本在服务端去除首尾空白并限制为 20,000 字，参与权威预览哈希，并冻结到工作运行快照。优点是预览后不可静默替换、重试不丢失；缺点是修改内容需重新创建工作项，不支持在已运行会话上就地覆盖。
- 验收反馈证明“补充信息”包含附件，因此直接复用普通任务推送的剪贴板读取、长文本物化、附件卡片、请求类型与服务端附件复验。优点是两个入口的交互、受信路径和 Provider 输入完全同源；缺点是用户原文件在预览后被移动或改变时会失败关闭，不会静默改发其他内容。

## 验收标准

1. 选择数字员工后，“开始任务执行”弹窗可输入文本，也可在同一输入框粘贴图片、文件或长文本；已添加资源可预览、移除，可恢复的长文本可还原到输入框。
2. 文本或附件变化都会刷新服务端权威预览；“将发送的任务内容”能看到完整补充信息和附件元数据。
3. 创建时服务端重新解析输入并校验预览哈希；超过 20,000 字、超过 100 个附件、失效授权、路径越界、大小/类型/图片签名不匹配均失败关闭。
4. 首次派发会话与工作项失败后的安全重试都使用同一份冻结文本和附件输入。
5. 空补充信息与旧工作项保持兼容；不新增数据库列、前向迁移或附件依赖。
6. `pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac` 及必要的独立 `Zeus Test.app` 真实运行分层记录，不互相替代。

## 实现结果

- “开始任务执行”弹窗在只读员工身份之后新增可选多行“补充信息”，空白输入按空值提交，且明确不回写任务描述或员工提示词。
- 输入框现在直接复用 `useConversationInputResources`、`TaskPushSupplementalAttachmentCards` 和任务推送的附件合并/请求转换函数；原生剪贴板兜底、无路径截图物化、长文本转附件和附件卡片不再重复实现。
- Renderer 继续复用原有 250 毫秒合并预览与陈旧响应丢弃机制；补充信息改变会触发新的服务端权威预览。
- 服务端将规范化文本与经既有任务推送附件校验器验证的输入写入 `TaskWorkPreviewSelection`，与任务、员工、模型、Skill、权限、上下文和代码现场一起参与预览哈希。
- 创建时仅接受与当前输入完全匹配的预览，并把文本与附件输入分别冻结到 `entrypointSnapshot.supplementalInfo` / `entrypointSnapshot.supplementalAttachments`。首次派发与后续安全重试都从同一快照重放，不从 Renderer 临时状态重读。
- 旧工作项的快照没有该属性时保持原有提示内容；没有新增表、列、迁移或依赖。
