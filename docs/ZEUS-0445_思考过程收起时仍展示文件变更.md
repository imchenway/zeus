# ZEUS-0445 思考过程收起时仍展示文件变更

## 用户目标

- 完成轮次即使收起“查看处理过程”，仍显示该轮底部的文件变更卡。
- 展开或收起处理过程只影响思考摘要、命令、工具和逐条文件操作，不影响最终正文、文件变更卡、失败信息与处理耗时。

## 现状与根因

- `TurnChangeCard` 已位于 `SessionTurnProcessDisclosure` 外部，展示顺序本来就是“处理过程 → 最终正文/交付物 → 文件变更 → 处理耗时”。
- Snapshot V2 首屏只在轮次摘要中提供 `changeSetAvailable`，完整变更集需要按需读取。
- Renderer 目前只在用户展开处理过程时同时调用 `onLoadTurnArtifacts`。因此折叠状态没有取得变更集，卡片虽在折叠区外也没有数据可画；展开后取得数据，卡片才出现在底部。

## 修复决策

- 会话记录挂载且权威水合完成后，对 Snapshot V2 明确标记 `changeSetAvailable` 的最近完成轮次，顺序复用既有 `onLoadTurnArtifacts` 读取变更集。
- 变更集读取与会话资源读取允许并行，互不因另一类数据正在加载而提前退出，也不覆盖另一类分页的加载状态。
- 保留处理过程的延迟构建与按需分页，不把低层文件操作移到折叠区外。

优点：直接修复数据取得门禁，折叠和展开共享同一张权威变更卡；Snapshot V2 最近完成轮次上限仍为 2，不扩大历史页或新增协议。

代价：有文件变更的最近完成轮次会在会话可读后各发起一次变更集读取；这是展示用户交付结果所需的数据读取，不再等用户展开过程。

## 实现记录

- `ConversationTranscript` 从 Snapshot V2 最近完成轮次中读取 `changeSetAvailable`，会话进入可读态后按顺序调用既有 `onLoadTurnArtifacts`；不再把取得变更集绑定到处理过程的展开动作。
- `useSessionController` 允许资源页和不同轮次的变更集并行取得。仅加载变更集时直接合并到当时最新快照，不再回写旧的资源分页状态。
- 浏览器 QA 夹具增加“处理过程默认收起、轮次声明有变更集、资源与变更集同时读取”的现场，并记录变更集请求次数。
