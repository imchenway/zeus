# ZEUS-0445 思考过程收起时仍展示文件变更

## 用户目标

- 完成轮次即使收起“查看处理过程”，仍显示该轮底部的文件变更卡。
- 展开或收起处理过程只影响思考摘要、命令、工具和逐条文件操作，不影响最终正文、文件变更卡、失败信息与处理耗时。
- 补充反馈：修复后文件变更卡虽然能够自动出现，但显示仍有明显延迟。

## 现状与根因

- `TurnChangeCard` 已位于 `SessionTurnProcessDisclosure` 外部，展示顺序本来就是“处理过程 → 最终正文/交付物 → 文件变更 → 处理耗时”。
- Snapshot V2 首屏只在轮次摘要中提供 `changeSetAvailable`，完整变更集需要按需读取。
- 首轮修复前，Renderer 只在用户展开处理过程时同时调用 `onLoadTurnArtifacts`。因此折叠状态没有取得变更集，卡片虽在折叠区外也没有数据可画；展开后取得数据，卡片才出现在底部。
- 首轮修复虽然并行发起变更集与会话资源请求，却用同一个 `Promise.all` 等两者全部完成后才写回；多页资源较慢时，已经返回的变更集也无法投影。最近完成轮次之间还使用逐轮 `await`，较旧轮次同样会挡住当前轮。

## 修复决策

- 会话记录挂载且权威水合完成后，对 Snapshot V2 明确标记 `changeSetAvailable` 的最近完成轮次，并行复用既有 `onLoadTurnArtifacts` 读取变更集。
- 变更集读取与会话资源读取允许并行并各自立即写回，互不等待、互不因另一类数据正在加载而提前退出，也不覆盖另一类分页的加载状态。
- 保留处理过程的延迟构建与按需分页，不把低层文件操作移到折叠区外。

优点：直接修复数据取得门禁，折叠和展开共享同一张权威变更卡；Snapshot V2 最近完成轮次上限仍为 2，不扩大历史页或新增协议。

代价：有文件变更的最近完成轮次会在会话可读后各发起一次变更集读取；这是展示用户交付结果所需的数据读取，不再等用户展开过程。

## 实现记录

- `ConversationTranscript` 从 Snapshot V2 最近完成轮次中读取 `changeSetAvailable`，会话进入可读态后并行调用既有 `onLoadTurnArtifacts`；不再把取得变更集绑定到处理过程的展开动作，也不让旧轮次串行阻塞当前轮。
- `useSessionController` 让资源页和变更集各自处理成功或失败并立即合并到当时最新快照；慢资源不会推迟变更卡，任一请求失败也不会污染另一类分页状态。
- 浏览器 QA 夹具增加“处理过程默认收起、轮次声明有变更集、资源与变更集同时读取”的现场，刻意延迟首个资源页，并记录变更集是否先于慢资源完成投影。
