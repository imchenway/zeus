根因代码证据

已确认根因
  • turnProcessProjector.ts:76-103：thinking/tool block 只以 provider=pi 写入 process detail，没有 protocolFamily 或 stageId。
  • piNativeConversationCoordinator.ts:1266-1295：processProjector 在 message_end 文本摘要处理之前执行。
  • piNativeConversationCoordinator.ts:1388-1455：每次 assistant message_end 都使用 pi_message_${nativeRunId}，并在之后写入 text 摘要和 model history。
  • 因此同一 run 的多次模型续接缺少消息级稳定身份，且 reasoning/tool 与摘要的语义顺序无法由存储直接表达。

Snapshot 与 Renderer 证据

已确认事实
  • conversationSnapshotV2Adapter.ts:570-610：process item 被投影为统一 Renderer item，但当前没有协议和阶段字段。
  • ConversationTranscript.tsx:1720-1754：阶段按摘要出现顺序切分；第一条摘要接管前置 reasoning，后续摘要结束上一阶段。
  • ConversationTranscript.tsx:1948-1971：活动组使用摘要递增 ordinal 作为阶段身份，而不是 Provider 明确提供的 stageId。
  • 该算法对 Codex 现有事件顺序成立，但不能无损恢复 Anthropic message_end 内的 block 关系。

推荐接口与兼容边界

拟议方案
  • Anthropic assistant message 产生消息级 stageId/providerItemId：优先 message.id，回退 nativeRunId + event.sequence。
  • Pi process detail、provider item payload、model history content 同时写入 protocolFamily=anthropic_messages 与 stageId。
  • Snapshot V2 model-history/process/active-item 增加同名可选字段；旧记录通过 segment → execution snapshot 推导协议，通过同消息事件时间生成只读阶段回退。
  • Renderer 仅对 Anthropic 且存在 stageId 的项目启用显式归组；其他协议沿用现有时序。
  • redacted thinking 不展示原始载荷；error/aborted 不生成 final_answer；相邻摘要仅做规范化空白后的精确去重。
