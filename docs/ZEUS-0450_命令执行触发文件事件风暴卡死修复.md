# ZEUS-0450 命令执行触发文件事件风暴卡死修复

## 当前阶段

- 状态：根因修复与真实运行验收已完成。
- 父任务：ZEUS-0438「执行命令时 Zeus 经常卡死」。
- 目标：避免项目内批量文件写入通过隐藏的源码工作区拖死 Zeus，同时保留普通源码文件的外部变更同步能力。

## 现场结论

2026-09-03 10:22 的 `sh -lc pnpm release` 并没有卡在命令执行层。Runtime 与命令记录均在约 15 秒后以退出码 1 结束并完成落库，直接失败原因是 `gh auth status` 判定凭据失效。

同一时段的 macOS 日志显示 Zeus 先进入无响应状态，随后被强制结束并收到 `SIGKILL`；没有发现应用异常对应的崩溃报告。因此用户看到的“直接崩溃”在系统层实际是界面卡死后的强制退出。

根因位于源码工作区：

- 源码页通过 `hidden` 隐藏，组件和递归 `fs.watch` 仍持续运行。
- 发布脚本在项目内 `.tmp/zeus-release-isolated` 创建隔离副本并执行依赖安装，单次产生数万文件事件。
- 主进程原样把每个事件发送给渲染进程；渲染进程又为每个事件读取父目录并更新界面。
- 当前隔离发布目录累计约 14GB、71 万文件，是事件规模的放大因素，但本任务不删除这些历史数据。

这说明发布命令只负责触发高频写入，Zeus 没有约束隐藏工作区和文件事件才是产品根因。

## 实现方案

### 关闭隐藏源码工作区

只有当前处于源码模式时才挂载 `ProjectSourceWorkspace`。切换到命令或关系图模式会卸载组件并关闭原生监听器；再次进入源码模式时，继续通过已有偏好恢复已打开文件、展开目录和树宽度，并从磁盘重新读取内容。

优点：从生命周期上消除隐藏页面的后台监听和刷新。缺点：搜索词、滚动位置、光标位置等未持久化的临时界面状态会重置。现有离开确认继续保护未保存草稿，卸载时还会清除父级脏状态，避免后续导航被陈旧状态阻断。

真实运行首次复查发现，全局 `⌘1…5` 快捷键监听器曾持有旧的脏状态，能够绕过既有离开确认。现已让监听器随源码和任务表格脏状态更新，并让代码图谱入口同样先走统一离开确认。关系图切回源码时则先挂载源码工作区，再打开目标文件，避免卸载后的旧组件引用失效。

### 在主进程丢弃生成目录事件

递归监听回调在进入 IPC 前过滤路径中包含 `.git`、`.tmp`、`node_modules`、`dist` 或 `coverage` 的事件。这些目录仍可按需浏览，但外部变化不再实时刷新；重新打开时会读取最新磁盘内容。

优点：高频生成物事件不会占用主进程与 IPC。缺点：用户若主动浏览生成目录，需要重新打开才能看到外部变化。

### 合并剩余源码事件

渲染进程只接收会影响已加载目录或已打开文件的事件，并在 100 毫秒内按父目录和文件路径去重。同一时刻只执行一批读取；刷新期间到达的事件留给下一批处理。

脏草稿不会被磁盘内容覆盖，只标记存在外部变更；干净标签继续自动同步。该方案直接复用原生监听、现有目录读取和标签冲突语义，没有新增依赖、协议或公共数据结构。

## 明确边界

- 不修改命令生命周期、SQLite、控制心跳或发布流程，它们不是这次已确认的根因。
- 不删除或迁移现存隔离发布目录；存储清理需要独立授权和恢复策略。
- 不处理失效的 GitHub 凭据。
- 不新增单元测试、组件测试、DOM/CSS 契约测试、测试依赖或公共接口。

- `pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm package:mac` 全部通过。
- 真实 GUI 只使用当前任务生成的 `Zeus Test.app`，bundle ID 必须为 `dev.hypha.zeus.test`，并使用独立用户数据目录。

- 普通已打开源码文件发生外部修改时仍会自动刷新；切换工作区后源码目录和文件从磁盘重新同步，未保存内容不会静默丢失。
