# ZEUS-0452 异步提问与会话进度修复

## 范围与根因

本次在 `zeus/ZEUS-0452-zeus-computer-use-codex-02` 修复会话链路。原 `-01` 工作目录的 Computer Use 开发成果保留。

ZEUS-0452 的 `call_t8e9F1nFKaqcCN7PuKT1Tz5G` 与 ZEUS-0456 的 `call_zk1mwV4qbzDlPpLljma6yV3O` 均为 `delivery: async`、带 `questions` 的 `agentMessage`，同时携带 `phase: final_answer`。仅凭 phase 判断最终交付，使引导关闭、后续进度折叠。历史正文只持久化 phase，重开后仍然误判。原始 Provider 载荷保留了问题结构，可按消息身份恢复。

消息输出完成、需要回答、轮次结束是不同事实。分类统一为过程说明、中途问题、最终交付；轮次结束仍由正式结束事件决定。

## 已确认方案

- 实时接入、历史恢复、发送与队列统一读取分类。保留原始交付字段。
- 复用现有问题表单及消息提交、引导、送达确认链路。回答绑定原始问题和轮次；轮次已结束时保留草稿，由用户选择作为新消息发送。
- 中途问题独立可见，活动轮次最新过程保持展开。运行状态只使用正式事件，不使用正文关键词或计时器猜测。
- 历史修复按身份读取保留载荷，不改写生产库，不新增队列。

优点：新旧会话和不同发送入口语义一致。代价：需要贯通接入、存储、快照、表单及送达确认，不能仅修改按钮。

## 实施与验证记录

2026-09-05：代码实施、原始现场回放、隔离数据库运行检查及项目规定的四项检查已完成。真实界面与真实模型送达尚未验收，不能据此判定整个计划验收完成。

### 消息与显示

- `packages/shared/src/assistantMessage.ts` 提供共同分类入口。`delivery: async` 优先于 `phase: final_answer`；有完整问题结构时分类为中途问题，结构缺失时保留为过程说明，不猜测问题正文。
- 实时事件、历史投影、子会话、服务端引导门槛、输入框和时间线共同使用分类。原始 `phase`、`delivery`、`questions` 与计算后的分类一起保存。
- 异步问题独立展示并复用现有问题表单，选择后明确提交，支持自由输入；“稍后回答”只收起表单，不发送跳过请求。同步询问及审批的权限和校验保持原有语义。
- 活动轮次的最新过程持续展开，正式轮次结束后收起。运行状态读取连接、正式等待请求、上下文整理事件；能力启用要求由明确错误码 `ZEUS_COMPUTER_NOT_REQUESTED` 持久化，不从普通文字或耗时猜测状态。

### 回答、确认和竞态

- 回答携带原问题的 Provider 条目身份及所属轮次。服务端根据原始问题重新校验完整答案、生成模型输入，不能由客户端改写问题、伪造目标轮次。
- 回答复用现有提交、引导和命令回执链路。同一问题跨页面及重启保留稳定提交身份；不同内容的重复回答明确报错，不将旧回答的送达结果冒充为新回答结果。
- 引导请求成功只代表接收，精确匹配 `clientId` 的 Provider 用户消息才确认送达。对应用户消息进入模型历史，问题页单独按提交账本恢复答复状态，避免跨分页丢失关联。
- 原轮次结束或已经最终交付时，返回 `ZEUS_ASYNC_QUESTION_TURN_ENDED`，保留表单草稿。用户明确选择“作为新消息发送”后才走普通队列。未知送达结果沿用恢复机制，不自动重复写出。
- 隔离检查发现原有普通引导退回队列存在两个问题：派发中的提交不满足通用编辑条件；对账前后重复退回会重复尝试创建替代提交。修复了共用存储入口，仅允许明确拒绝的引导退回，并复用已经建立的替代身份。问题回答在该入口也禁止自动转到下一轮。

### 历史恢复

- 模型历史保存明确的 Provider 条目身份和消息元数据；旧记录通过既有消息身份映射读取保留的原始载荷，无生产数据改写或关键词猜测。
- 会话首屏、按轮次分页、历史尾页、活动尾部以及完成锚点都携带相同信息。异步问题不再被选作完成锚点。
- 重复完成事件不会重复添加助手历史或已确认的用户答复；迟到事件仍受原有轮次终态约束。
- 优点是共享分类及现有账本同时覆盖显示、发送和恢复，不新增队列或依赖；代价是必须贯通这些投影入口。旧记录如果没有可确认的原始结构，不能恢复出可信的可回答问题。
