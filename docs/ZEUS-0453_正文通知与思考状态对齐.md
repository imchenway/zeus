# ZEUS-0453 正文通知与思考状态对齐

## 已确认目标

- 过程说明、思考过程和摘要不产生系统通知或普通未读标记；正式正文继续提醒。
- “正在思考”的状态行与正文、工具行使用相同的左边界，不重复扣除容器留白。
- 保留审批、需要回答、失败、中断、完成及目标状态提醒，保留前台免打扰、同轮去重和历史恢复不补发通知的规则。

## 原因与实施

- Codex 原先在模型消息增量与完成事件上直接写入普通未读，没有排除过程说明；流式更新还会覆盖开始事件确定的阶段与分类信息。
- 流式更新现在保留已有阶段与消息元信息，仅正式正文的非空增量写入普通未读；缺少开始事件时，等待完成事件分类。完成入口同样只接受正式正文；完成事件省略阶段时，使用合并后的消息信息保留已知分类。
- Pi 复用已有工具调用阶段与正式正文分类，只在正式正文形成时写入普通未读。过程文本仍正常保存和展示。
- 系统通知继续消费同一份未读事实，不增加通知过滤分支或另一套状态。
- 状态行移除重复扣除的左右留白，保留圆点、字号、动画和无障碍状态提示。
- 不增加公开接口、数据库字段或配置，不清理历史未读，不修改 Git 历史或远端。

## 取舍

- 优点：从未读产生处统一修复，两种模型的通知与会话标记一致；直接修正已有样式，无额外布局层。
- 代价：过程更新不再主动提醒；缺少开始阶段证据时，正式正文提醒可能延迟至消息完成。
