# ZEUS-0456 新用户 Worktree 分支发现修复

## 根因与已确认目标

任务推送能力在查询只读改造后仅消费已登记仓库；项目创建不再登记仓库，也没有接入替代的后台发现入口。新用户及未登记仓库的旧项目因此拿到空清单，即使真实目录已有 Git 分支。

项目添加后立即在后台发现本地仓库；进入项目、修改项目目录及主动刷新共用同一发现流程。推送弹窗优先展示已登记仓库的真实分支，查询本身保持只读。

优点：项目创建不等待全目录扫描，新用户无需手动登记仓库；代价：需要持久维护发现状态，处理失败、目录变化及退出后的恢复。

## 实施约定

- 发现只读取本地目录和 Git；不拉取远端、不初始化仓库、不创建任务分支。
- 成功后完整替换仓库清单，保留同一路径的仓库身份；失败不清空旧清单。
- 未开始、进行中、完成和失败分别显示；只有完成后的空清单才表示没有仓库。
- 只恢复未完成的发现请求，旧项目进入时补扫；不增加目录监听或新的任务调度框架。
- 后台更新保留模型、工作方式、补充信息和仍有效的分支选择；创建前复验清单与实际引用。
- 仅在当前任务分支实施；不执行 Git 提交、推送或合入。

## 实施与验证记录

### 实施结果

- 项目创建与目录修改在原有命令事务中保存发现请求，事务提交后启动后台扫描；返回创建成功不等待仓库遍历。
- 新增 `POST /api/projects/:projectId/git/repositories/refresh`，沿用命令身份、幂等接纳与事务机制。进入项目和主动刷新共用此入口，同项目同目录的进行中请求合并。
- 发现记录保存在项目设置中，包含项目、对应目录、请求身份、状态、上次完整完成时间和错误。启动仅恢复进行中的记录，旧项目进入时补扫。
- 复用 `discoverGitRepositories` 及既有排除目录、六层扫描范围。目录或仓库读取失败会明确失败，不再返回不完整的成功清单；Git 状态读取关闭可选索引写锁，不产生扫描带来的索引刷新。
- 成功后在一个事务内替换仓库登记清单并保存完成状态，同一路径保留身份；失败保留上次清单。写回前同时核对项目当前目录和请求身份，退出中止遍历，防止旧目录及已退出实例写回。
- 能力查询增加 `repositoryDiscovery`，依旧只读。已登记仓库独立读取真实本地引用和本机已知远端引用；单仓不可读时显示不可用原因，其他仓库继续展示。项目目录已移走时，附件读取排除不可用根目录，使发现错误仍能显示，且不扩大附件访问范围。
- 推送弹窗监听既有实时事件，连接恢复后补读权威能力；只更新仓库相关信息并合并现有选择。仓库新增、移除或来源失效要求复核，失效来源要求重选，自定义新分支名、模型、补充信息、附件及上下文选择继续保留。
- 首次没有工作方式偏好时，发现 Git 后默认 Worktree；空项目后来发现 Git 同样适用。用户已选方式不会被覆盖，已默认 Worktree 的草稿也不会因仓库暂时为空而切回直接目录。
- 模型目录未就绪时仍显示仓库表单；模型后来就绪后，界面与提交入口使用相同模型来源。首次完整清单就绪前仅限制创建新 Worktree；既有环境和直接目录不受发现状态限制。
- 创建新环境继续验证清单修订和真实来源引用；清单变化会拒绝旧请求。没有新增远端拉取、目录监听、调度框架、数据库表或依赖，也没有修改已有任务环境。

后台扫描当前按项目串行执行，优点是限制磁盘竞争，代价是同时添加多个大项目时后面的发现需要排队。复用现有六层范围及排除规则，范围之外的仓库不会纳入清单。
