# ZEUS-0466 会话刷新误报修复

## 目标与现场

修复进行中会话因刷新读取时间差而误报失败。工作目录为 ZEUS-0466，分支为 `zeus/ZEUS-0466-task-01`，实施前工作区干净。

附件记录中的模型于北京时间 2026-09-07 16:46:46.436 正常完成回答，界面于 16:46:47.138 报告会话结构与消息尾页的事件进度不一致。本机运行日志也记录了同一界面错误。现有加载函数在两次独立读取之间发生更新时，连续三次尝试后会产生相同错误，已通过内存演练复现；原现场每次读取的具体编号未记录，不推断是哪几批更新相遇。

## 已确认方案

- 后台增加只读 `GET /api/projects/:projectId/conversations/:conversationId/readable-snapshot`，返回 `{ snapshot, history }`。先完成项目分支查询，再在同一 Core 中同步连续读取结构和消息，中间不加入异步等待或写事务。
- 结构最多 64 KiB、最近两轮摘要；消息最多 48 条、96 KiB。统计、队列、待回答问题和更早历史保持独立读取。
- 界面共用加载入口改用组合结果，删除连续三次重读。保留适配器的身份、结构和事件进度校验。
- 首次加载及重连从返回编号接续更新；发送后核对复用现有事件缓冲。刷新仅核对状态，不重发用户消息。
- 真实读取失败明确提示“会话内容暂时无法刷新”，详情保留脱敏原因。

优点：复用已有查询、编号和缓冲，修复覆盖所有模型，规则集中。代价：增加一个组合读取接口，需要同步调整客户端和现有验收探针。无需数据迁移或新依赖。

## 实施记录

- `packages/local-server/src/conversationSnapshotV2Api.ts`：新接口复用现有项目归属检查、结构查询与消息尾页查询，响应禁止缓存；分支查询完成后连续执行两次同步读取。
- `apps/desktop/src/renderer/features/conversations/conversationApiClient.ts`、`session/sessionTypes.ts`：接入组合响应类型和客户端方法，保留原分页接口。
- `apps/desktop/src/renderer/session/useSessionController.ts`：首次打开、重连和发送后核对共用组合读取，移除结构与尾页之间的三次重试；身份、结构代次和事件编号继续由原适配器检查。事件订阅编号、缺口补拉、发送后缓冲均复用原逻辑。
- `packages/shared/src/userFacingError.ts`：增加中英文刷新失败解释；即使发送后核对在外层包装了错误，也优先说明刷新失败，底层原因保留在脱敏详情中。发送结果未确认时，操作仍是检查状态，不变为重新发送。
- `scripts/verify-renderer-event-flow.ts`：仅同步已有探针的客户端方法与响应形状，未新增仓库验证脚本或依赖。

同步读取依赖当前由单个 Core 负责会话写入的架构：异步更新不能插入两次同步查询之间。此次未加入数据库写事务；若未来允许多个独立进程同时写同一会话库，需重新评估这一读取边界。
