## 合并决策

开始时共有 9 个变更文件，其中 `conversationCapabilityQueryApplication.ts` 有两个冲突块，其余 8 个文件已由 Git 自动合并。

1. 能力查询只调用 `readAccount({ cachedOnly: true })`，保留任务分支不等待 Provider 握手、不触发账号 RPC 的行为。
2. `ZEUS_CODEX_ACCOUNT_SNAPSHOT_UNAVAILABLE` 表示尚无缓存，账户保持未知，Codex 目录仍可供选择；实际请求仍执行认证。其他账号读取异常保留主分支的 Codex 不可用投影，独立供应商不受影响。明确未登录的缓存仍由现有前后端账号门禁处理。
3. 旧会话引用先确定 Codex 模型，再以明确的 Codex 来源调用共享运行预检。否则全局默认 API 模型可使预检提前返回，冷启动时拿不到旧会话所需的 Codex 目录。这是自动合并文件中的调用语义调整。
4. 任务分支既有 `verify-provider-isolation.ts` 原先用普通账号错误模拟账户未知，与主分支的异常禁用规则冲突。本轮仅将该输入改为真实的缓存缺失错误码，保留原有断言；主分支既有恢复边界脚本继续保留普通账号异常场景。未新增检查脚本，未执行脚本。

选定方案的优点：保留两侧有效行为，区分正常缺少缓存与真实异常，并在共享查询入口统一处理。代价：未知账号的认证结果要等实际请求返回；该行为沿用任务分支及现有账号门禁。直接保留主分支的占位账号禁用条件会阻断正常冷启动；全部忽略账号错误则会丢失主分支的异常状态，两者均未采用。
