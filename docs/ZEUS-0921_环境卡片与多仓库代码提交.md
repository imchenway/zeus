# ZEUS-0921 环境卡片与多仓库代码提交

## 需求与范围

- 修复环境卡片存在未提交文件却显示零，以及代码交付窗口遗漏对应代码的问题。
- Git 工作区的全局提交入口展示当前项目目录内的全部 Git 仓库，复用已有仓库文件树与逐仓提交能力。
- 普通目录、普通会话独立工作树、任务工作树分别保持真实目录范围，不依据命令 cwd 扩大写入范围。

## 已核对的事实

- 当前分支初始无改动，当前 docs 无既有主任务文档。
- 已读取项目内全部规范文件；当前实际存在 PROJECT-STYLE.md，AGENTS.md 规则由会话提供，未发现 CODE-GUIDELINES.md、DESIGN.md。
- SessionQuickActionsCard 只要存在 taskId，就调用任务工作树接口。普通目录任务没有独立任务工作树时，空记录被汇总成零，点击后也进入任务工作树交付页。
- ProjectGitWorkbench 已发现并导航多个仓库，但提交按钮的数量和窗口入参固定在当前仓库。
- RepositoryGitDeliveryContent 已支持多仓库选择、逐仓提交、差异和结果反馈，无需重建页面。
- 任务交付页展示当前分支全部仓库，环境卡片却只统计一个工作区，二者范围不一致。

- 项目卡片原来的行数统计不含未跟踪文件；任务工作树的服务端统计也遗漏新文件行数，存在只有新文件时仍显示 `+0` 的问题。

## 处理方案与取舍

- 普通目录统一读取项目 Git 快照；项目级原生交付窗口复用现有窗口服务、文件树、草稿和操作入口。独立工作树继续使用原绑定身份。
- Git 全局提交入口统计并展示项目内全部仓库；明确点击单仓或子树的入口保留范围限制。
- 任务工作树的卡片与交付页复用同一分支筛选，汇总全部可见仓库；读取不完整时不显示零作为成功结果。
- 项目卡片使用交付页已有的完整差异，并复用嵌套仓库占位过滤。任务工作树在共享读取中补入未跟踪文件的 Git 行数统计，不改变暂存、提交和推送行为。
- 普通项目会话保留会话级交付身份和后台组合操作；关联任务的普通目录使用项目级窗口，避免伪造独立工作树身份。
- 卡片继续保留同范围刷新时的已有快照，并复用项目文件变化、Git 操作和窗口返回的刷新通知。
- 优点：修复范围丢失，保留既有交互与权限边界，不新增扫描器或提交执行流程。
- 代价：项目级交付读取全部仓库，加载量随仓库数增加；逐仓操作不是跨仓库事务，可能部分成功，沿用逐仓结果反馈。
- 新文件统计增加只读 Git 调用，复用现有并发处理，最多并发 4 次、单文件限时 15 秒；二进制文件仍按 Git 行数语义处理，目录占位不递归读取。未进行性能实测。
- 不把截图中的历史文件更改数量当作当前 Git 状态；当前状态以真实仓库读取为准。

## 任务推送入口的进一步确认

- 用户明确补充：失败入口是任务推送时选择“在当前项目分支进行”，不是纯本地会话。当前界面对应“直接使用项目目录”，提示会影响当前项目和 Git 分支。
- 已沿创建链核对：TaskModelPushModal 保存 `workspaceMode: direct`；useWorkspaceDomainActions 提交 `source: task_push` 和 `workspace.mode: direct`。
- conversationApplicationOperations 对该模式不创建任务环境，并向首条执行上下文保存 `executionWorkspaceMode: direct`，但仍保留 taskId。任务没有独立工作树是该选项的正确行为，不是创建失败。
- 交付入口原先只判断 taskId，误将这条直接修改项目当前分支的会话导向独立任务工作树页面。当前修复先判断实际目录模式，因此此入口读取和交付当前项目各仓库的修改，与纯本地会话采用同一 Git 范围。
- 两种会话共享当前项目目录，交付展示的是这些仓库的当前修改，不以会话历史中的文件更改卡片隔离文件。
- 本轮仅补充来源链说明，无新增源码改动；不把静态调用链核对视为实机验收。
