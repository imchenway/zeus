# 新会话与任务推送配置记忆

## 需求与范围

- 新会话按所选项目恢复最近使用的模型及其配置；无项目会话使用独立记忆。
- 项目内按供应商和模型身份分别保存推理等级、上下文容量、速度、工作模式、权限及 Skill。推送任务切换模型时恢复该模型的选择。
- 项目会话、任务讨论、临时会话及任务推送共用桌面渲染端能力；macOS 和 Windows 使用相同实现。
- 不保存任务正文、附件、分支、历史会话选择和本次并发确认。运行时仍按现有服务端能力及权限规则校验。
- 用户确认任务推送和普通会话共用配置，以最近一次实际发送或确认推送的选择为准。

## 已核对的现状

- 任务推送使用浏览器本地存储按项目保存最后一套配置，但覆盖了之前模型的配置。
- 普通会话的偏好按操作类型全局保存，项目标识未参与存储；读取时速度固定为标准，新会话中切换项目不重新初始化。
- 无项目会话由独立的临时项目承载；新会话与任务讨论复用同一个输入组件。
- 推送的 Skill 选择和对话输入中显式引用 Skill 的数据通道不同，不能将 Skill 隐藏在未展示的请求里。

## 开源实现对照

- [Cline](https://github.com/cline/cline) 使用 Apache-2.0 许可证；其 [模型配置问题](https://github.com/cline/cline/issues/13696) 记录了不同模型共用推理等级导致切换后恢复错误，适合借鉴按模型保存的边界。代价是需要按项目和模型维护更多记录。
- [OpenCode](https://github.com/anomalyco/opencode) 使用 MIT 许可证；其 [项目模型记忆讨论](https://github.com/anomalyco/opencode/issues/6075) 记录了全局最近模型在多项目间互相覆盖的问题。项目隔离避免互相覆盖，但首次无记录时需要使用当前模型目录的默认选择。
- [Roo Code](https://github.com/RooCodeInc/Roo-Code) 使用 Apache-2.0 许可证；其 [配置说明](https://github.com/RooCodeInc/Roo-Code/blob/main/apps/docs/docs/features/api-configuration-profiles.mdx) 按模式及任务保存配置。此方式适合固定任务配置，但需要用户管理额外配置档；本需求不引入配置档及其依赖。
- [Continue 的配置说明](https://github.com/continuedev/continue/blob/main/docs/cli/configuration.mdx) 展示了显式选择、已保存选择和默认配置的优先级；其仓库已停止维护，仅作历史对照，不引入依赖。
- 本项目复用现有模型能力目录与本地偏好存储，不引入新依赖；本地记忆不跨设备同步。

## 实施

- 按项目保存最近模型，并按供应商与模型完整身份保存对应选项。无项目使用临时项目身份，不读取其他项目的记录。
- 读取同项目原有的推送选择；此前跨项目的普通会话全局记录没有可靠的项目归属，不能把它猜成无项目或某个项目的记忆。
- 新会话切换项目时恢复新项目的选择并保留正文和附件；同项目存在未发送草稿时保留草稿配置。新会话、普通会话、侧栏会话和任务推送切换模型时恢复该模型已确认的配置；接入新模型也使用同一规则。
- 任务推送确认后保存；普通会话首次发送、后续消息及侧栏首发受理后保存。无正文引用的单选 Skill 保持可见并可取消；正文单独引用一个 Skill 时记住该选择，多个 Skill 不猜测默认项。
- 侧栏提问初始仍继承来源会话；代码审查和冲突处理保留独立偏好。已有会话只在消息中显式引用 Skill，不在后台自动加入记忆的 Skill。任务推送的直接目录或工作树选择不改变普通新会话的工作区默认值。
- 记住的模型不可用时保留选择并要求重选；上下文容量不再受模型支持时提示并使用默认容量。

## 检查与未验证项

- `pnpm typecheck`、修改文件的 ESLint 静态规则检查及 `git diff --check` 通过。
- 用户要求不编写或执行测试；本任务未运行测试用例或测试脚本。
- macOS 和 Windows 使用同一桌面渲染端路径，均已按源码核对；实际交互、截图、窄窗口和两端实机行为未验证。
