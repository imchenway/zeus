# 取消 TDD 与单元测试体系

Zeus 不再采用 TDD，并整体退役现有 Vitest 单元、组件、API 与 DOM/CSS 契约测试体系，以消除持续编写、维护和反复执行测试的成本。项目后续以静态检查、构建、macOS
正式打包和真实运行检查作为交付证据；该决策会失去细粒度自动回归保护，但这是用户在了解现有测试投入与失败发现数据后明确选择的取舍。

## 边界

- 删除测试类、测试目录、测试脚本、测试框架依赖、测试配置、仅被旧测试调用的依赖替换入口，以及残留测试缓存。
- 保留类型检查、生产编译、构建、静态发布验收、正式 macOS 打包、真实接口联调和浏览器验收。
- 保留真实运行所需的进程组合接口、安全边界和浏览器自动化端口，不把生产扩展点误判为测试接线。
- 历史任务文档与 Changelog 中已发生的测试结果继续作为历史事实，但必须明确它们不是当前规则或门禁。

## 后果

优点是仓库不会留下无法运行的空测试体系或可误用的测试替身；缺点是未来若恢复自动化测试，需要重新安装框架、配置工具链并重建适合当前架构的接线。
