# ADR 0002：命令中心采用通用用户脚本模型

- 状态：已接受
- 日期：2026-07-28

## 背景

Vibego 已提供 Git 批处理、微信开发者工具和代理配置同步等命令入口。Zeus 需要对齐其命令管理体验，但这些脚本与单个用户的本机目录、工具安装和操作习惯强相关。如果将它们写成 Zeus 内置业务能力，会把用户环境耦合进产品，并扩大默认权限与发布包责任。

## 决策

Zeus 只实现通用命令定义、参数、确认、执行、审计、产物和远程入口。命令文本与脚本由用户提供：

- 全局命令可在任意当前项目根目录执行，项目命令只属于一个项目。
- 命令定义声明风险和参数，Zeus 负责权限门禁、逐次确认、环境变量注入、Runtime 会话、历史和产物边界。
- 产品及迁移不注入 Git、微信或 `agents-sync` 默认命令。
- 用户脚本位于 Electron 实际 `userData/command-scripts`，不随应用打包，不写入 SQLite 导出。
- 本次八条脚本是当前用户的配置交付，不改变上述产品默认。

## 优点

- 保持 Zeus 的领域边界稳定，不依赖 Vibego 或特定外部工具。
- 用户可以复用同一执行、安全、日志和 Telegram 能力管理任意脚本。
- 脚本升级、删除与产品发布解耦，避免应用更新覆盖用户资产。

## 代价

- Zeus 不能保证用户脚本本身正确，需要通过确认、权限、超时和审计降低风险。
- 脚本依赖由用户环境承担；跨设备导出命令定义后仍需单独迁移脚本。
- Telegram 只负责发现和执行，复杂定义维护仍需桌面端完成。

## 被否决方案

### 将八条命令做成 Zeus 内置业务能力

优点是开箱即用；缺点是硬编码本机工具、目录和外部副作用，产品默认权限过大，因此否决。

### 在导出中携带脚本内容

优点是迁移方便；缺点是可能外泄凭据、私有路径或公司脚本，并使导入成为代码分发通道，因此否决。
