# 升级期间执行宿主独立于界面生命周期

Zeus 的计划内升级采用界面与执行宿主分离的生命周期：已经开始的执行轮次继续绑定原运行时世代，新轮次由新世代承载，旧世代排空后退出。若新版不能安全连接既有执行宿主，则升级等待而不是中断、迁移或重跑未知状态的执行轮次；普通退出仍由用户决定任务继续或停止。

## 选择原因

等待全部执行轮次结束后再安装实现简单，但长任务会长期阻止用户使用新版；退出并恢复历史只能保存记录，不能保证执行继续；自动重跑又可能重复命令、文件修改或远程副作用。独立执行宿主是同时满足“新版立即生效”和“既有执行不中断”的唯一可靠边界。

## 结果

- 应用内升级负责完整的下载、校验、切换、安装、自动重开和重连。
- packaged App 通过 Main IPC 下载并校验产物；安装辅助进程在 Main 退出后原子替换 App，新界面成功回连宿主才提交完成状态。
- 普通草稿允许恢复；尚未提交的敏感回答只上报存在性且阻止安装，正文不得进入持久化升级数据。
- 新界面回连后，旧宿主必须以界面租约版本作为后续更新检查的当前版本，不能继续使用旧 App 包版本。
- 替换或回连失败只恢复旧 App 并重新打开旧界面，不中断执行宿主，也不回滚已经发生的执行事实。
- 旧宿主运行期间保留其 App 备份；宿主最终关闭后再由当前 Main 清理受控备份，避免删除仍在使用的执行代码。
- Homebrew 与 DMG 升级不得终止执行宿主，但自动重开不属于外部安装器保证。
- 多次连续升级允许保留多个排空世代，不设置会强制结束执行轮次的数量上限。
- 后台宿主崩溃、系统重启和断电不属于无损升级保证；未知执行状态进入恢复确认。
- 新界面必须先通过执行宿主协议兼容检查；不兼容时保留已下载版本并等待安全安装窗口。
