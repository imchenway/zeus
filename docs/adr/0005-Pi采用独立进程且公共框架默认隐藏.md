# Pi 采用独立进程且公共框架默认隐藏

Zeus 把 Codex 与 Pi 作为两套明确区分的 Agent。Codex 继续通过 Codex App Server 保留原生行为；Pi 未来通过 RPC 独立子进程承载多模型，不嵌入
Zeus 执行宿主。当前里程碑只搭公共框架，Pi 状态为 `framework_only` 且默认对普通用户隐藏。

## 选择原因

同进程 SDK 调用更直接，但 Pi 的内存、异常与依赖升级会和数据库写入者、Codex 管理及其他长任务共享影响范围。独立进程与 Codex
App Server 的隔离原则一致，也便于旧实例排空和新实例接管新任务。

当前没有真实 Pi 模型、安全扩展和恢复证据。直接显示 Pi 或四家模型入口会把“存在代码结构”误写成“已经支持”，与 Zeus 的真实数据原则冲突。

## 结果

- Pi 进程只由独立执行宿主管理，Renderer 与 Electron Main 不直接启动。
- 一个 Pi 工作进程同一时刻只绑定一个活动会话；并发通过受控进程池实现。
- Pi 使用独立配置和会话目录，不默认继承用户全局 Pi 扩展与凭据。
- Pi 的项目信任不视为沙箱；真实开放前必须实现 Zeus 工具拦截、确认、目录复验与脱敏。
- 公共能力使用 `supported / unsupported / unverified` 三态，并保存版本与真实证据。
- 普通 Agent 目录只返回已验证且明确可见的 Agent；`framework_only` 不能通过改一个 UI 开关直接开放。
- 当前不新增 Pi 依赖、进程、密钥、模型目录或用户入口。

优点是隔离故障、避免假支持，并为多模型提供清晰扩展点。代价是需要进程池、协议映射和双 Agent 长期维护；公共抽象在第一家真实 Pi
模型接入时仍可能调整。
