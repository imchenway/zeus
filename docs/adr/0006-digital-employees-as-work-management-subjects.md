# 数字员工属于工作管理而不是 Agent Runtime

数字员工采用“全局模板分配到项目后形成项目工作主体”的模型，由工作管理拥有身份、工作来源、指派、自动化、授权与工作执行事实；产品会话和目标只是执行载体，Agent Runtime 只提供 Provider 能力。这样既能组合“CSS 测试”“PIM 产品”等员工，又不会把运行线程误当长期组织身份或让 Skill、提示词隐式获得项目副作用权限。

## Considered Options

- 固定新增产品、前端、开发、测试、部署 Agent 类型：实现简单，但岗位和领域组合不可扩展，Provider 能力与业务身份耦合。
- 只有一套全局员工直接服务所有项目：复用简单，但难以表达项目差异和最小权限。
- 每个项目完全独立创建员工：隔离明确，但重复配置多，无法统一维护岗位基线。

## Consequences

- 模板本身不拥有项目访问权；项目数字员工独立保存能力覆盖、探索范围、自动化和逐动作交付授权。
- 提交、推送、合入、部署与结束任务默认关闭，只有项目数字员工的对应授权可允许自动执行。
- 工作执行必须固定配置与授权快照，并通过版本化命令连接会话编排和执行能力；Renderer 不直接调度 Provider 或 Git 副作用。
