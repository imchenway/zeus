# 代码交付远端完成与本地现场解耦

Zeus 的任务分支合入在隔离工作目录中完成，以远端目标分支提交校验成功作为代码交付完成条件。本地同名目标分支是否已经同步是独立状态；当它正被含未提交代码的工作区使用时，Zeus
保留整个本地现场，不移动分支引用，不自动暂存或恢复，只记录“本地待同步”。

任务分支自身不要求先推送到远端。本地任务分支已经提交且工作区干净时即可进入合入；推送任务分支只是可选的备份、协作和审查动作，最终交付只要求目标分支结果成功推送并校验。

## 选择原因

原实现要求项目主工作区必须检出目标分支并保持干净，导致与本次交付无关的本机未提交代码也会阻断远端合入。直接在脏工作区下移动分支引用会让工作区文件、索引和提交基线错位；自动暂存再恢复又可能制造额外冲突并改变用户现场。

隔离合入可以在不触碰主工作区的前提下得到确定结果。完成前再次检查本地目标分支基线，远端使用非强制推送并在成功后反查提交；远端出现非快进变化时会安全停止，避免强推或覆盖远端变化。

## 结果

- 查看、提交、推送和合入在同一交付窗口中分步呈现，每一步都由用户显式触发。
- 任务分支推送不构成合入门禁；没有远端任务分支时仍可使用本地提交完成交付。
- 任务分支已提交成果与本机未提交变化是两类不同差异，必须分开展示。
- 代码交付完成不再要求项目主工作区位于目标分支，也不要求其干净。
- 目标分支在准备或推送期间发生变化时拒绝完成，不自动 rebase，不强推。
- 本地目标分支可以安全更新时同步到交付结果；不能安全更新时保持原样并返回“本地待同步”。
- 应用必须分别保存远端结果提交和本地同步状态，不能把“远端已交付、本地待同步”写成交付失败或本地已更新。

优点是交付不再被无关的本机变化阻塞，同时保留用户现场和远端并发安全。代价是本地与远端目标分支可能短暂分离，需要新增清晰提示和后续同步入口。
