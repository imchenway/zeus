# Zeus 拥有 Harness 业务编排，Agent Runtime 只拥有执行循环

Zeus 将 Harness 定义为任务执行控制面：工作管理拥有工作执行、任务工作流、阶段指派、验收、返工与交付检查点；会话编排负责编译阶段上下文并建立产品会话；Agent Runtime 只负责 Provider 原生会话、Skill 投影、模型与工具执行循环。会话完成只能形成交付物候选，已验收阶段交付物才是跨阶段正式契约，外部副作用只能由最终交付检查点授权的版本化命令执行。

## Considered Options

- 由一个长期主管 Agent 在提示词中选择员工、推进阶段和决定交付：入口简单，但责任、权限、上下文和失败恢复不可审计，模型判断会成为业务事实旁路。
- 每个数字员工继续直接建立普通任务会话，并在会话完成后执行提交、推送、合入和部署：复用现有实现最多，但无法与阶段交付物、代码审查和验收门形成一致状态机。
- 由 Zeus 业务工作流拥有编排，数字员工负责阶段，Runtime 只执行单次 Agent loop：需要更多命令和快照，但能让人工、自动化、审查、返工和交付共享同一套权威事实。

## Consequences

- 每个阶段可以显式绑定项目数字员工，未配置时继承任务级工作指派；阶段尝试冻结员工、Skill、模型、权限、上下文和工作区事实。
- Skill 采用“阶段覆盖 > 员工默认 > 不加载”的确定性解析，只影响执行说明与资源投影，不参与权限计算。
- 会话终态与阶段验收、工作流完成、外部交付保持独立；数字员工编排器不得再以普通会话完成直接触发 Git、部署或任务终态。
- 代码审查使用独立只读会话，输入同时覆盖确认需求、已验收上游交付物、完整代码现场和真实验证证据；修改请求通过正式返工边创建新尝试。
- 所有工作流和阶段写入必须先进入 Work Management Command Envelope；写出后结果未知时失败关闭并等待原生或外部回执对账。
- 任务详情承担统一执行编排界面，Provider thread、原生 Skill 路径和内部状态表只作为按需证据展示，不成为用户必须操作的主流程。
