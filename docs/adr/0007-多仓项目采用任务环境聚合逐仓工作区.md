# 多仓项目采用任务环境聚合逐仓工作区

Zeus 将项目建模为可包含零到多个项目仓库的项目容器，并把一次任务开发线建模为聚合全部项目仓库工作区的任务环境。任务新建环境时由用户逐仓选择来源分支，全部仓库要么完整创建成功、要么回滚；同一任务再次推送默认复用既有环境，也允许显式新建。

项目容器下经用户登记的 `docs/` 等共享可写目录直接写回真实路径，不伪装成 Git 隔离内容；其他非 Git 内容默认只读。多个仓库无法形成真实的跨仓 Git 事务，因此代码交付逐仓记录结果，只有全部仓库已交付、放弃或确认无变化后才回收任务环境。

远端只承担可选的推送与协作能力，不是任务环境或本地合入的前置条件。无远端且原目标分支存在未提交改动时，Zeus 保留隔离合入结果并进入“等待本地同步”，不回收结果；用户清理原目录后可重新同步目标分支。

选择该结构是因为把项目容器误当作单一 Git 仓库会阻断无远端或多仓项目，而只在推送弹窗中绕过门禁会让后续提交、合入和回收继续使用错误仓库。代价是任务创建和交付界面需要逐仓状态，磁盘占用随项目仓库数量增长，并且共享可写目录不具备 worktree 的隔离与回滚能力。
