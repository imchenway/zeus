# 任务工作区采用远端权威基线与安全重建

有远端的仓库采用远端权威模式。创建任务工作区前必须成功刷新远端，来源只能选择该次刷新得到的远端分支，并冻结其精确提交；原工作区的已暂存、未暂存和未跟踪内容不进入任务工作区。没有任何远端的仓库保留本地模式，来源选择本地命名分支，默认同样不携带未提交内容，只有用户显式选择时才能带入。

远端权威模式进入代码交付前，任务分支的本地 HEAD 必须与刷新后的远端任务分支 HEAD 完全相同。最终隔离候选从刷新后的远端目标分支创建，只把当前任务
HEAD 合入一次，不先把目标分支合进任务分支，不执行 rebase，也不改写任务分支历史。候选推送前再次刷新远端；目标分支已经前进时废弃旧候选，按最新目标提交重新构建。

冲突处理期间如果目标分支前进，没有用户草稿时直接重建；已经保存用户草稿时保留草稿，但只有新旧冲突指纹相同时才回填，并要求用户重新确认。指纹不同的草稿不能自动套用到新冲突。

## 选择原因

旧流程从本地来源分支和本地目标分支创建工作区与合入候选，还会默认复制原工作区的未提交内容。这样会把“本机记录过期”“其他任务的脏现场”和“真正修改了同一段代码”混在一起，制造大量并非本任务本身导致的冲突。任务分支未推送也能直接交付，则让最终结果缺少可复查的远端任务提交。

远端刷新并锁定精确提交能消除过期基线和脏工作区带来的假冲突；只在最新目标上合入一次可以避免重复吸收目标历史。它不能消除两个分支真实修改同一段代码造成的业务冲突，但能把剩余冲突收敛为需要人工判断的真实冲突。

## 结果

- 有远端时，刷新失败直接阻断来源选择、任务创建、任务分支推送或目标合入，不能降级使用缓存远端记录。
- 远端任务分支缺失、领先或分叉时阻断合入；推送只允许普通非强制推送。
- 目标分支在候选创建后前进时，旧候选不能继续推送，也不能自动 rebase。
- 纯本地仓库继续支持本地来源和本地交付，不因缺少远端失去任务开发能力。
- 本地同名目标分支仍与远端交付结果解耦；只在本地工作区安全时快进同步。
- ADR-0006 中“任务分支推送不构成合入门禁”的规则，仅对纯本地仓库继续成立；有远端的仓库由本决策取代。

优点是显著降低过期基线、脏现场和重复历史造成的冲突，并为每次远端交付保留一致的任务分支证据。代价是创建和交付都依赖一次成功的远端访问，网络或凭据失败会更早阻断；目标分支活跃时可能需要多次重建并重新确认冲突。
