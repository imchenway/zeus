# 本机数据按所有者和生命周期治理

## 决策

Zeus 本机数据根固定使用六类顶层：`data` 保存核心事实与配置，`artifacts` 保存 Zeus 托管资产，`providers` 保存运行内核原生资产，`backups` 保存有明确恢复用途的备份，`runtime` 保存执行宿主、更新和迁移事务，`profile` 保存 Electron 与浏览器状态。

业务模块必须从 `ZeusDataLayout` 取得路径，不得直接在根目录拼接新文件。Electron 的 `userData` 只指向 `profile/electron`，不再等同于 Zeus 业务数据根。

旧平铺布局只用于连接仍存活的旧执行宿主。宿主退出后必须迁移：先创建当前数据库快照，再移动文件、重绑结构化路径、检查数据库完整性并提交迁移清单。外部旧根只有在清单包含逐文件镜像证据、数据库受管旧引用为零且没有执行宿主时，才允许显式物理回收。

备份不是永久堆放区。配置导入备份排除插件运行程序、缓存和安装暂存；最新目录迁移快照产生后，已被取代的旧数据库迁移备份可以删除。

## 后果

优点：目录职责能直接看懂；网络缓存、浏览器登录态、Provider Home、附件和数据库不会再混称“缓存”；迁移与删除都有明确证据和失败回滚；旧根能在安全门槛满足后真正释放空间。

缺点：升级需要一次停机迁移；迁移前会短暂多占一份数据库空间；只保留最新目录迁移回滚点，不继续保存多代数据库副本；应用不会在用户不知情时自动删除外部旧根，正式回收需要显式维护动作。

## ZEUS-0311 修订

统一会话迁移新增安全回退数据库、候选数据库、迁移状态与诊断文件，继续归属于 `backups` 和维护事务；完整工具结果归 `artifacts/conversation-tool-results`，目录 `0700`、文件 `0600`，数据库只保存随机句柄、相对路径、SHA-256 与有界投影。归档保留这些托管结果。本次不新增永久删除，降级必须恢复安全回退库，不能让旧版直接写新结构。
