# 远程普通消息采用原生轮次与增量检查点

Zeus 将非本机发起的 Provider turn 表达为没有本机 submission 的真实轮次，并以独立的逐会话 Provider turn 检查点补齐修复后的断线缺口。该方案不伪造本机提交，也不在重连时全量导入修复前历史，从而同时保留队列与恢复语义、稳定 Provider 身份幂等以及用户确认的历史边界；代价是需要把 turn 来源改为可空、增加检查点持久化和分页校准。

## 考虑过的方案

- 伪造本机 submission：迁移较少，但会污染队列、重发和恢复语义，因此拒绝。
- 每次全量导入 Provider thread：实现直接，但违背不补旧历史且长会话成本持续增长，因此拒绝。
- 只接入实时 `turn/started`：改动最小，但断线或重启仍会漏消息，因此拒绝。

## 后果

远程 turn 的 `client_submission_id` 允许为空；实时事件回执负责当前世代去重，跨世代断线补齐由逐会话 turn 检查点负责。检查点无法在 Provider 历史中定位时必须显式失败，不得按正文、时间或全量历史猜测恢复边界。
