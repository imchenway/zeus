# ADR 0014：产品会话持有统一历史并以运行分段切换模型

## 状态

已接受，2026-08-16。

## 背景

当前 `conversations.agent_kind` 把产品会话和 Provider 原生会话绑成同一身份，导致同一界面会话无法在 Codex 与 Pi 之间继续。两个 Native Coordinator 各自维护 submission、队列、恢复与用量，又导致排队配置不可变契约、上下文投影和处理过程展示不一致。

## 决策

- 产品会话成为时间线、模型历史、submission 和队列的唯一所有者。
- Codex thread 和 Pi session 只是产品会话下的运行分段。
- 只有运行时接受首个真实 turn 后，候选分段才可提升为当前分段。
- 跨分段连续使用由确认模型历史编译的便携上下文；超限时才使用目标模型压缩。
- 每次真实模型请求独立记录用量、费用和执行配置证据。
- 所有旧 Provider 会话在结构切换后 sealed，新引擎不再继续写入旧会话账本。
- 产品时间线、模型历史和实时同步分别使用独立单调序号，不使用时间戳推断因果关系。
- submission 正文、附件和执行意图在本地接纳后不可变；后续变更只能创建带原因和来源关系的 replacement。
- 队首失败、配置不一致或接受结果未知时暂停后续队列，不能通过重排或立即发送改变模型历史顺序。
- Codex 以 `turn/start` 返回的 turn 为接纳证据；Pi 以原生预检成功后的同步持久事务为接纳边界。
- 超长历史压缩是独立模型请求。Pi 使用目标 SessionManager 的原生压缩，Codex 使用目标模型的工具关闭临时 turn；压缩用量、过程和检查点单独保存。
- 目标窗口以 route 冻结时的持久模型元数据为准，自动能力目录不得静默覆盖；Pi 按该窗口缩放原生压缩保留量，Codex 临时压缩从 turn/item 事件收集摘要和用量，不依赖临时 thread 的历史列表能力。
- 配置证据按用户选择、Zeus 冻结、适配器序列化、运行时接纳和 Provider 回显分层保存。没有 Provider 回显时不得声称内部推理档位已确认。

## 优点

- 同一产品会话可在多运行内核间连续，不改变用户导航身份。
- 未发送、已接受和结果未知具有明确数据边界，可防止重复执行。
- 上下文、工具结果、处理过程和用量都有 Provider 无关的产品契约。

## 代价

- 需要一次性数据库候选迁移、安全回退备份与旧版写入围栏。
- 运行分段切换与崩溃恢复状态比单 Provider 会话更多。
- 超长历史跨分段时可能产生额外的上下文压缩费用。
- 同一产品会话内保留多个 sealed Provider 副本和完整工具结果，会增加本机磁盘占用。
- 为保证顺序，单个失败队首会阻止同会话后续提交，用户需要显式处理。

## 数据与恢复边界

- `conversations` 只持有产品身份；Provider thread/session 身份归运行分段。
- provisional 分段在首个真实 turn 被接受前不能取代 current 分段。
- Codex 请求写出后失联时保持 `outcome_unknown`。启动恢复只有在 provisional thread、原生 turn 和 `clientUserMessageId` 精确一致时补交事务，否则继续失败关闭。
- Codex 或 Pi 在原生 turn 产生前返回明确错误时属于“运行时明确拒绝”，不是 `outcome_unknown`：目标分段 abandoned、切换操作失败并结束、来源 current 不变，队首允许人工 replacement，禁止自动重发。
- Codex 只有在 `turn/start` JSON-RPC 帧成功写入后才越过未知结果边界；App Server 的 JSON-RPC error 回执始终是明确拒绝。
- Pi 的同步预检回调是进入 Agent run 前的强制接纳边界；缺失回调立即中止并按写入前失败处理。Pi 已接纳运行随本机进程终止后，重启只收敛为中断并保留历史，不自动重发。
- 重启恢复的状态收敛、恢复事件和持久警告必须共同落库；恢复事件使用运行分段、事件类型和结构化载荷作为统一证据，不保留与仓储写入协议不一致的旧列名。
- Codex 便携上下文使用 app-server v2 命名条目映射，可信清单与不可信历史正文分别编码；当前用户输入不得复制进 `additionalContext`，Zeus 内部操作信封不得发送给模型。
- 接纳事务同时完成来源封存、目标提升、submission/turn 绑定和时间线/模型历史序号分配。
- 旧库先生成可供旧版使用的安全回退副本，再构建候选库；同卷原子提升前必须收敛并归档旧 WAL/SHM 旁文件。
- 原子提升前失败与提升后校验失败是两个不同事实；迁移状态和维护文案必须明确正式数据库路径是否已经被替换。
- 新库关闭当前写入者后，触发器拒绝旧版继续写 `schema_migrations`。降级必须恢复安全回退库。

## 界面含义

- 成功切换模型不插入普通分段标记；用户仍看到一条产品会话时间线。
- 队列与正式 transcript 分开，只有运行时已接受的输入进入 transcript 和模型历史。
- 可读 reasoning 统一称为“思考摘要”，整轮事件集合称为“处理过程”；界面不宣称展示隐藏思维链。
- 上下文圆环只表达最后一次真实模型请求的输入 Token 与实际模型窗口，不能使用文件 KB/MB 或会话累计 Token 冒充。

## 替代关系

本 ADR 修订 ADR 0004 中“跨运行内核必须创建新产品会话”的约束，并修订 ADR 0013 中“运行路由在新会话创建时固定”的约束。ADR 0003 的普通无损升级原则保留，但本次会话存储结构切换作为明确的一次性例外。
