# 服务档位偏好归属项目模型配置

## 背景

速度选择原先保存在按项目和会话类型划分的界面本地存储中。同一模型从任务推送、项目会话、冲突处理或代码审查进入时可能得到不同结果，服务端也无法判断一条 Standard 是用户显式选择还是界面自动写入。

## 决定

Zeus 把 Standard 或 Fast 的显式选择作为项目与模型身份共同拥有的用户偏好，保存在后端项目配置中。模型身份由模型来源 ID 和模型 ID 共同组成；界面本地存储不再拥有速度偏好。没有记录时按 Standard 下发，但不自动创建记录。旧界面速度值不迁移，因为它不能证明用户曾经显式选择。

## 优点

- 任务推送、项目会话、冲突处理、代码审查和既有会话读取同一事实，跨入口与跨重启一致。
- 单模型专用更新接口可以原子覆盖并写审计，普通项目配置保存不会误覆盖偏好表。
- 同名模型通过来源 ID 区分，不会把不同 Provider 的能力和偏好混在一起。

## 代价

- 项目配置类型和接口需要扩展，并长期维护模型来源兼容与记录数量边界。
- Renderer 每个模型入口都要读取项目配置并只在用户显式操作时保存。
- 无法自动迁移旧速度值；用户首次使用新链路时会看到默认 Standard，需要重新显式选择 Fast。
