# 数字员工会话参与采用直接扇出

用户在产品会话中点名数字员工时，由会话编排直接为每位会话专家参与者建立独立专家执行和原生运行通道；默认 Agent 不充当主持人或转述者，也不把点名转换为工作指派或 Provider 子 Agent。同轮专家共享发送前冻结的会话水位并独立回复，下一轮才接收同轮其他专家的已确认结果。

## Consequences

- 专家身份、回复、审批、失败和恢复都能独立审计，产品会话仍是唯一用户可见的群聊历史。
- 只读或计划执行可以并行；可写或 Computer Use 执行必须按点名顺序串行。
- 会话编排需要支持多个执行通道、参与者投影和专家执行恢复，会增加 Provider 线程、上下文和持久化成本。
- 数字员工的工作权限、交付授权和任务 Skill 策略不进入会话参与；每轮运行设置以 Composer 冻结值为准。
