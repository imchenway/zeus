# ZARCH-013 Renderer 有界视口与热缓存

## 当前结论

会话正文使用稳定行 ID、变高前缀树和严格视口窗口，只挂载可见区域前后 900px 缓冲。基础投影硬上限为 48 行，活动、展开、键盘焦点与历史前插锚点是明确例外；过程、diff、工具正文仍只在展开时挂载。行高由 ResizeObserver 回写，测量缓存最多 384 条。

读取更早 Snapshot V2 历史前会冻结 cursor、首个可见稳定行与 viewport offset；页合并后优先按稳定行恢复滚动锚点，目标行已经从测量缓存淘汰时再使用冻结游标和 scrollHeight 差值兜底。热缓存普通会话最多 6 个，单项 8MiB、总量 32MiB；超过总量先淘汰普通会话，再淘汰最旧关键会话。缓存命中仍会按同一事件水位读取 Snapshot V2，缓存淘汰不等于历史丢失。

## 可重复探针

`pnpm exec tsx scripts/probe-transcript-viewport.ts` 已通过：100,000 行中段投影 21 行/23 slots，前插后 20 行，尾部 13 行，测量缓存 384 条；6 个约 6MiB 候选保留 5 个、31,460,430 bytes，低于 33,554,432 bytes 总上限。

## 收益与缺点

- 收益：DOM 与测量缓存不随历史长度线性增长，前插分页不会把用户从当前阅读位置拉走，热切换也不会复制大量完整会话。
- 缺点：变高估算在首次测量前可能有轻微位置校正；活动/展开/焦点例外会让极端人工展开场景暂时超过 48 行基础上限。
- 未验项：尚未用独立 Test 身份采集真实 100k DOM 数、heap 趋势、滚轮/键盘焦点和分页视觉现场；构建与内存探针不能替代 GUI 验收。
