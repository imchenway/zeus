# ZARCH-030～031 设置、导入与缓存命令纵切

## 结论

本纵切精确接管 10 个 Local Server mutation。项目配置、App Shell、Code Map 三个纯 SQLite 事实使用 `core_application`，业务事实与 accepted receipt 在同一耐久事务提交；Keychain、Runtime 日志保留、投影数据库清理和两类导入共 7 个入口使用 `external_operation`，先持久化稳定 child identity 与 write marker，再按 `failed_before_write`、`explicitly_rejected`、`outcome_unknown_after_write`、`accepted` 四态收口。结果未知后禁止盲目重发。

## 权威事实与派生边界

- `runtime.settings.logRetentionDays` 是唯一保留策略事实；文件隔离、日志删除和关联清理是可再次按该事实执行的派生操作，但本次公开命令仍以独立 external child 记录其结果，不能隐藏在 Core 提交后的回调里。
- `app.shell.settings.lastCacheClearAt` 是用户明确清理的 Core 事实；内存图缓存和 projection database 内容都是可重建派生物。两个兼容 URL 共享命令类型和 scope，不产生两套幂等语义。
- 数据库密码明文只存在于本轮 HTTP Body 与 Keychain 调用栈。Envelope/Inbox 只保存 input SHA-256；receipt、audit 和 result artifact 只保存非敏感结果。错误先按本轮密码精确替换，再执行全局脱敏并限制为 2 KiB。
- 设置导入先完成 App Shell、Runtime、Code Map、Telegram notification/security 的全部 normalize，并拒绝删除仍被任务或系统角色使用的管理状态；任何 Artifact、SQLite 或文件 mutation 都发生在计划完成后。
- 业务数据导入先严格验证所有数组记录、重复 ID、跨表引用、命令 token 冲突和本地项目路径；不再静默过滤坏记录。导入正文上限 32 MiB，正文写内容寻址 Artifact，receipt 只保留约束引用和小结果。

## Renderer 与重连

Renderer 每次用户意图只调用一次 `buildSettingsCommandRequest`，生成不可变 `{command,input}`。连接刷新最多复用同一个 `RequestInit` 和序列化 body，不会重新生成 command ID、operation identity 或正文摘要。旧缓存 alias 没有新的 UI 调用方，只保留协议兼容。

## 收益与缺点

收益：Core 设置不会再出现“业务已写但幂等回执丢失”的双写窗口；Keychain 和文件系统结果未知时不会自动重复删除或覆盖；导入失败不会留下前半段设置或业务记录；大型备份不膨胀 Command receipt；Runtime retention 和缓存清理的真实失败对调用方可见且可审计。

缺点：外部操作必须额外写 Inbox、Outbox、write marker、ArtifactRef 和 receipt，单次命令的固定 SQLite/文件 I/O 增加；32 MiB 导入需要完整 parse/validate 后再压缩写 Artifact，峰值内存高于流式导入；Keychain 写出后响应丢失会保守进入 recovery-required，用户不能直接用同一命令盲重试；两个缓存 URL 共用能力但仍增加一条公开审计清单。

## 验证与未验

`scripts/verify-settings-command-behavior.ts` 仅使用临时 SQLite、临时 Artifact 目录和 fake 外部端口，已验证：Core accepted replay 只写一次；故障时业务事实与 Inbox 一起回滚；1.1 MiB 导入正文通过 ArtifactRef 重放且 receipt 为 447 字节；四种外部结果状态可区分；unknown 只调用一次并阻断重发；密码明文不进入 command tables；`PRAGMA quick_check=ok`。`scripts/audit-command-side-effect-entries.mjs --require-settings-command-slice` 精确发现 7 External + 3 Core，全部为 integrated。

尚未验证真实 macOS Keychain、正式数据库、真实 Runtime 日志隔离目录、真实 projection database 清理和打包后的 Renderer 重连；这些不能由 fake port verifier 冒充。用户多设备 iCloud/Google 同步需求仍不明确，继续按 ZARCH-063 延后，本纵切没有新增任何云同步实现。
