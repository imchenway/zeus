# 工作管理

工作管理描述用户要完成的工作、工作发生的位置以及结果如何交付；它不拥有智能体内部执行历史。

## Language

**项目**：
一组长期工作、代码库、配置与任务的稳定归属单位。
_避免：仓库、目录、工作区_

**环境**：
项目下具有确定代码位置、分支和运行约束的工作现场。
_避免：项目、会话、终端_

**任务**：
具有明确目标、状态、优先级和关系的工作管理实体。
_避免：提交、轮次、命令_

**任务工作流**：
由用户或未来流程编排器显式创建的阶段路线及其关系快照；普通数字员工指派不创建工作流，独立工作项之间默认没有依赖。
_避免：模型路由、会话时间线、运行时调用图_

**任务执行编排**：
以任务工作流为核心，把工作执行、阶段指派、阶段尝试、验收门和交付动作组织成一条可恢复、可审计的任务执行契约。
_避免：超级 Agent、长会话、提示词流程_

**任务阶段**：
任务中具有明确目的、输入契约、输出契约和执行策略的工作单元。
_避免：任务状态、会话、模型、一次运行_

**阶段执行指派**：
明确某个任务阶段由哪个项目数字员工负责；未显式配置时可以继承任务级工作指派，但不得由模型隐式选择。
_避免：会话参与者、主管 Agent、模型路由_

**阶段尝试**：
任务阶段在一组冻结配置下的一次真实执行；重试、换模型或返工产生新的尝试。
_避免：轮次、任务事件、覆盖旧运行_

**阶段交付物**：
由某次阶段尝试产生、按版本保留且可被验收或驳回的任务结果，通过稳定资产引用承载完整内容。
_避免：聊天末条回复、运行日志、隐藏思维链_

**阶段验收策略**：
定义阶段交付物由人工、确定性门禁或独立审查结合门禁接受的版本化规则；会话完成和模型自评均不构成验收。
_避免：自动推进开关、会话终态、模型结论_

**阶段交接**：
上游阶段已验收交付物向下游阶段传递的稳定引用和必要摘要。
_避免：复制全部会话、扫描聊天猜测结果_

**数字员工接力**：
用户接受当前阶段交付物，并显式选择负责下一阶段的项目数字员工；它创建新的阶段执行指派，不覆盖正在运行或已经完成的员工快照。
_避免：改派当前员工、自动选人、复用同一会话_

**主任务文档**：
`/docs` 中与任务号精确匹配、未标记为补充材料且用于承载当前完整任务事实的首选文档。
_避免：展示型附录、长期记忆、rollout 摘要_

**任务关系**：
两个任务之间的父子、依赖或业务关联。
_避免：会话关联、Git 祖先关系_

**工作区**：
任务获准读取或修改的真实文件系统工作现场，可以是项目目录或隔离 Worktree。
_避免：项目、环境、终端目录_

**交付**：
任务结果进入目标分支、发布候选或其他已确认接收位置的业务记录。
_避免：完成状态、Git commit、推送_

**交付检查点**：
工作流完成并满足验收、目标和授权条件后，对一组明确外部交付动作形成的显式放行事实。
_避免：会话完成、模型判断、完全访问开关_

**数字员工模板**：
可跨项目复用的岗位、领域、能力与工作策略基线，本身不拥有任何项目访问权。
_避免：数字员工、任务模板、Agent 类型_

**数字员工**：
数字员工模板分配到项目后形成的稳定工作主体，拥有版本化能力配置和唯一主执行入口；岗位名称与指派次数不决定其行为。
_避免：智能体、目标、产品会话、Provider Worker_

**员工能力配置**：
项目数字员工的版本化执行契约，包含身份说明、Agent 或 Command 主入口，以及 Agent 的模型策略、Skill 策略和权限工具上限。
_避免：固定阶段、岗位枚举、Provider 工作模式_

**主执行入口**：
数字员工接受工作项时唯一允许采用的执行方式。Agent 入口创建独立产品会话；Command 入口引用命令中心定义且不创建模型会话。
_避免：部署授权、阶段类型、按岗位推断的行为_

**模型策略**：
Agent 员工的默认模型解析方式与允许显式覆盖的模型、推理强度和服务速率范围；实际解析值随运行冻结，不允许静默换模。
_避免：当前下拉框值、Provider 自动降级、员工路线_

**Skill 策略**：
Agent 员工允许使用的多个已安装 Skill 稳定身份集合。运行启动时冻结完整资源 Artifact 与只读快照目录，Runtime 只从冻结路径按需加载并记录实际启用项；Skill 不扩大权限。
_避免：单一默认 Skill、工具权限、完整资源注入_

**员工工作方式**：
项目数字员工被指派时由员工能力配置解析并冻结的执行契约；它不受指派次数、尝试次数、旧阶段位置或岗位名称影响。
_避免：固定任务阶段、尝试序号、隐藏交付链_

**工作指派**：
管理者通过“预览 → 创建”把任务中的一份明确责任交给数字员工。指派创建独立工作项，不表示运行成功、交付物已验收或任务已完成。
_避免：会话关联、任务状态、运行命令_

**工作项**：
管理者可见的一份独立工作责任，保存员工、来源、主入口和当前运行。多个工作项可在同一任务并存；只有真实流程关系存在时才建立依赖。
_避免：固定阶段、会话、指派次数_

**工作来源**：
向数字员工提供可评估工作项的受控来源，只发布候选工作，不直接授予副作用权限。
_避免：任意搜索、自动执行、任务模板_

**自动化规则**：
以触发条件、目标数字员工、工作内容和授权边界描述重复工作的版本化规则。
_避免：Cron 字符串、数字员工、运行脚本_

**工作执行**：
旧版数字员工执行记录的兼容术语。新的指派不再创建该记录；既有记录继续到终态后只读展示在证据中。
_避免：新工作项、新运行_

**工作运行**：
工作项的一次真实尝试，冻结员工修订、主入口、模型、Skill、权限与上下文清单，并且只引用 Agent `conversationId` 或 Command `commandRunId` 之一。
_避免：轮次、工作项、覆盖旧尝试_

**工作上下文包**：
一次运行的显式输入清单，只包含任务事实、附件、项目规则和管理者选中的已验收交付物版本/哈希；不自动传播完整会话或其他工作项产物。
_避免：聊天记录拼接、全任务广播、隐式共享内存_

**正式交付物**：
Agent 运行提交的版本化产物，由 Artifact 保存完整正文并以内容哈希校验。会话完成只产生待验收版本；接受后才成为可选上下文和工作项完成依据。
_避免：末条消息、摘要、会话完成_

**管理者决定**：
对补充信息、授权、交付物验收或返工、命令确认和未知结果处置的耐久待办与结果；通过稳定操作身份和预期修订避免重复执行。
_避免：会话输入框消息、隐藏审批、自动重发_
