# Zeus 0.1.15 更新内容

## 多仓项目可使用统一任务环境

- 项目设置现在可以扫描容器目录中的 Git 仓库，由你勾选真正需要参与任务的仓库，不会自动纳入所有扫描结果。
- 新建任务环境时，会为每个已登记仓库分别选择来源分支和任务分支；所有仓库全部创建成功后才会启动会话，任一仓库失败都会回滚本次环境。
- 多个仓库会按原有相对路径放入同一个任务环境，会话从环境根目录开始，可以在一次任务中同时处理前端、后端等独立仓库。
- 同一任务后续推送默认复用现有环境，也可以显式新建一套环境并重新选择各仓库的来源分支。
- 创建环境时会带入各仓库的暂存、未暂存和未跟踪文件；被忽略的文件仅按 `.worktreeinclude` 规则带入。
- 没有登记 Git 仓库的项目仍可直接使用项目目录，不要求选择分支，也不会创建 worktree。

## 写入范围更清晰

- 项目设置新增共享可写目录配置，可逐行登记 `docs/` 等需要直接写回真实目录的路径。
- 任务会话的写权限限定为各仓库工作区和显式登记的共享目录；项目容器中的其他非 Git 内容默认只读。
- 如果扫描到了尚未登记的仓库，创建任务环境前会提示先完成项目配置，避免误把容器目录当成唯一仓库。

## 代码交付支持逐仓完成

- 代码审查和交付窗口会显示仓库名称、相对路径与对应任务分支，多个仓库可以分别查看变化、提交、推送和合入。
- 远端仓库不再是任务开发和交付的前置条件。没有配置远端时，仍可创建本地提交并合入本地目标分支，只是不提供远端推送结果。
- 原目标分支存在未提交改动时，Zeus 会保留隔离的合入结果并显示本地同步状态；处理完原目录后可以重新同步。
- 只有全部仓库均已交付、放弃或确认没有变化后，任务环境才会整体回收。

## 正式应用与开发验收包分离

- 日常开发和验收打包现在统一生成独立的 `Zeus Test`，使用测试应用身份和独立用户数据目录，不再与正式 `Zeus` 共用 macOS 应用身份。
- 生产身份的 `Zeus.app` 只能由正式发布链路生成，并会在打包后核对应用名称、可执行文件和应用标识，降低 macOS 将旧验收包识别为正式应用的风险。

## 如何升级

本候选尚未公开发布。正式发布并完成 Homebrew Tap 同步后，可手动运行：

```bash
brew upgrade --cask imchenway/tap/zeus
```

也可以从对应的 GitHub Release 下载版本化安装包 `Zeus-0.1.15-arm64.dmg`。退出正在运行的 Zeus 后打开 DMG，并用新版本覆盖旧版本。

Homebrew 和版本化 DMG 都是手动升级方式，本版本不声明应用内自动安装可用。升级前请确认本机已经安装并登录兼容的 Codex CLI。

## 系统要求与已知限制

- 支持 Apple Silicon Mac，要求 macOS 13 或更高版本。
- Zeus 不附带 Codex；本机 Codex CLI 缺失、未登录或不支持所需能力时，相关 AI 执行不可用。
- 项目级 Git 状态、差异、快照和补丁页面暂不支持多仓或嵌套仓库；这些项目需要在任务的代码交付窗口中逐仓操作。
- 新建多仓任务环境会为所有已登记仓库创建 worktree，所需时间和磁盘空间会随仓库数量增加。
- 共享可写目录直接修改真实文件，不具备 Git worktree 的隔离与回滚能力。
- 提交或合入某个仓库前，需要先停止仍在写入该仓库工作区的活动会话，并处理已有冲突。
- 当前公开制品仍采用 ad-hoc 签名且未完成 Apple 公证，只能通过 Homebrew 或 DMG 手动升级。首次打开时，可能需要在 Finder 中右键 Zeus 并选择“打开”。
