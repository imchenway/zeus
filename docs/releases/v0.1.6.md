# Zeus 0.1.6 更新内容

## 会话队列恢复

- 修复上一个执行轮次已经在 Codex 侧结束，但 Zeus 仍把会话保留在暂停状态，导致新消息一直卡在“待发送”的问题。
- Zeus 现在会用恢复后的 provider thread 快照确认上一轮是否已经结束；事实完整时恢复为可发送状态并继续处理真正的新消息。
- provider 状态无法确认时仍保持安全暂停，不会猜测重放或重复创建执行轮次。

## 未发送内容保护

- 只有尚未取得 provider 执行轮次标识的排队或暂停输入才显示为“未发送内容”。
- 已经进入失败执行轮次的输入不再重复显示为“待发送”，避免用户误以为 Zeus 还会再次发送。
- 原会话无法安全继续时，未发送文字与附件会带入新会话草稿；新会话不会自动发送，仍需用户确认。
- 旧会话历史保持只读，不改写既有消息、执行轮次或 provider thread 身份。

## 如何升级

Homebrew：

```bash
brew upgrade --cask imchenway/tap/zeus
```

也可以下载 `Zeus-0.1.6-arm64.dmg` 手动升级。

从 `0.1.5` 升级仍属于用户确认后的手动安装。建议先停止或保存重要操作；正常退出 Zeus 仍会中断正在执行的轮次，不代表它会在应用退出期间继续后台运行。

## 系统要求与已知限制

- 支持 Apple Silicon Mac，要求 macOS 13 或更高版本。
- 当前发布包采用 ad-hoc 签名且未完成 Apple 公证，首次启动可能需要在 Finder 中右键 Zeus 并选择“打开”。
- 因缺少 Developer ID 签名和 Apple 公证，本版本不启用应用内自动安装；应用内检查更新仍会引导到 GitHub Release 下载页。
- provider 快照缺少可核对的终态执行轮次时，Zeus 会进入“需要恢复”，由用户把未发送内容带入新会话，不会自动重放。
- “仅附件”和多条未发送输入的草稿合并路径已通过静态检查与构建，但本次发布前未完成真实文件选择器交互验收。
