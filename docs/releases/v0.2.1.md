# Zeus 0.2.1 更新内容

## 在任务列表中直接处理会话

- 点击有对应会话的任务运行状态，会在任务列表右侧打开完整会话抽屉，不再跳转到会话页。
- 同一任务关联多个会话时，打开当前运行状态所依据的最近会话。
- 抽屉支持查看消息、继续输入、回答问题、审批和停止执行；历史只读会话仍保持只读。
- 关闭按钮、Escape 或点击遮罩均可关闭抽屉。关闭不会停止正在执行的会话，并会保留任务筛选、滚动位置和选中状态。
- “未启动”状态仍不可点击，也不会因此创建新会话。

## 自由输入不再误选答案

- 在询问的自定义答案或自由输入框中编辑时，数字键、方向键、空格和普通字符只用于编辑内容，不再触发外层选项快捷键。
- 多行输入中的 Enter 恢复为换行；单行敏感输入中的 Enter 也不会提交。发送答案必须点击明确的提交按钮。
- Escape 只退出输入焦点，并保留当前回答方式和完整草稿，不会跳过、关闭或提交询问。
- 焦点不在输入框时，原有的数字键和方向键选项导航仍然可用。

## 支持更多 Git 合法分支名

- 推送任务时，来源分支和任务分支改为遵循 Git 自身的分支命名规则，不再错误拒绝包含中文、`#` 等 Git 合法字符的名称。
- 修复覆盖任务工作区创建、分支差异查看、提交与推送以及后续合入流程，不只放宽推送入口。
- 来源分支仍必须是项目仓库中真实存在的本地分支；任务分支仍必须使用 `zeus/` 前缀。

## 会话恢复保留原任务现场

- 当消息恰好续发到已经结束的轮次时，明确未发送的内容会留在原会话并作为下一轮排队，不再把整条会话误判为必须恢复。
- 确实需要恢复时，Zeus 不再把原输入区静默替换成新会话输入区。只有用户明确选择创建承接会话后，才会出现相应输入区；普通 Enter 不会跨会话发送。
- 任务承接会话会复用或恢复原任务的持久工作区，不再退回项目主目录。原环境缺失、已回收或仍被活动轮次占用时，会拒绝创建以避免在错误分支执行。
- 任务工作区中的变更记录、撤销、重新应用和中断恢复统一使用会话的实际执行目录，减少将任务 worktree 内文件误判为目录外路径的情况。

## 如何升级

本候选尚未公开发布。正式发布并完成 Homebrew Tap 同步后，可手动运行：

```bash
brew upgrade --cask imchenway/tap/zeus
```

也可以从对应的 GitHub Release 下载版本化安装包 `Zeus-0.2.1-arm64.dmg`。退出正在运行的 Zeus 后打开 DMG，并用新版本覆盖旧版本。

Homebrew 和版本化 DMG 都是手动升级方式，本版本不声明应用内自动安装可用。升级前请确认本机已安装并登录兼容的 Codex CLI。

## 系统要求与已知限制

- 支持 Apple Silicon Mac，要求 macOS 13 或更高版本。
- Zeus 不附带 Codex；本机 Codex CLI 缺失、未登录或不支持所需能力时，相关 AI 执行不可用。
- 自由输入不能再按 Enter 快速提交，必须点击明确的提交按钮。
- 原任务环境缺失、已回收或仍在被活动轮次占用时，Zeus 不会把恢复会话回退到项目主目录，需要先处理工作区或活动轮次问题。
- 升级不会自动迁移或删除此前已经错误创建在项目主目录中的历史会话。
- 截至本草稿生成时，当前公开制品仍为 ad-hoc 签名且未经过 Apple 公证，只能通过 Homebrew 或 DMG 手动升级。首次打开时，可能需要在“系统设置 → 隐私与安全性”中选择“仍要打开”。

## 发布验证

- 当前处于 Release notes 草稿生成阶段；候选提交中的根包和桌面包版本仍为 `0.2.0`，尚未执行 `0.2.1` 版本写入、发布提交、正式打包或公开发布。
- 草稿通过后，编排器将写入根包和桌面包的 `0.2.1` 版本及本发布正文，并创建与候选范围绑定的发布提交。
- 随后将执行统一发布门禁，包括 Git 冲突残留与空白错误检查、本次变更文件格式检查、lint、类型检查、生产构建、设计验收矩阵和 AI CLI 适配探针。
- 正式打包后将检查应用身份、可执行文件和包内结构，确认未夹带 Codex CLI，并核对 `Zeus-0.2.1-arm64.dmg` 的完整性、文件大小、SHA-256、发布清单、签名与公证状态，以及 Homebrew Cask 的版本、架构和摘要一致性。
- 公开前将回验任务运行状态打开准确会话抽屉、抽屉内完整交互、关闭后保留任务列表现场且不停止执行，以及“未启动”状态不创建会话。
- 同时将回验自由输入中的数字键、方向键、Enter、Escape 和显式提交行为，并覆盖包含中文和 `#` 的真实合法分支在任务工作区创建、差异查看、推送和合入链路中的使用。
- 会话恢复回验将覆盖：已结束轮次的未发送内容留在原会话排队；创建承接会话需要明确操作；承接会话保留原任务工作区且不回退项目主目录；变更记录、撤销和重新应用使用同一会话执行目录。
- 本地门禁完成后，编排器将推送 `main` 并等待同一发布提交的 CI 结果，再创建并推送不可变的 `v0.2.1` 标签并触发 Release Workflow。
- Workflow 完成后还将回下载公开 DMG 和发布清单，核对 GitHub Release 正文、资产元数据、文件摘要、DMG 完整性与 Homebrew Tap Cask；以上均为草稿通过后的发布动作。
