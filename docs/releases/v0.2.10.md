# Zeus 0.2.10 更新内容

## 任务列表列调整更直观

- 可以直接拖动列标题调整列顺序；单击列标题仍用于排序，独立换位把手和键盘换列操作继续保留。
- 列宽分隔线现在会显示低对比度提示，并提供更容易命中的拖动区域。所有可调列均可在各自的可读下限与 `640px` 上限之间连续调整。
- 列顺序、列宽、显隐和排序继续保存在同一套任务表布局偏好中。
- “任务类型”改为只读彩色胶囊：需求为蓝紫色、缺陷为红色、优化为绿色，同时保留完整文字。

## 新任务工作区采用最新且干净的来源

- 对配置了远端的仓库，创建任务工作区前会先刷新远端，只显示本次刷新获得的远端分支，并从所选分支的精确提交创建任务开发线。
- 原项目目录中已暂存、未暂存和未跟踪的内容不会自动进入新任务工作区，避免把其他本机工作意外带入任务。
- 没有远端的纯本地仓库仍可创建任务工作区，默认同样不携带未提交内容；需要时可显式选择带入。
- 任务成果对比会固定使用创建工作区时的来源提交，不会因同名来源分支之后移动而改变比较基准。

## 推送与目标分支合入更安全

- 推送任务分支前会重新刷新远端。首次推送和正常快进推送仍受支持；同名远端分支已经领先或发生分叉时会阻止覆盖，不会执行强制推送。
- 配置远端的仓库必须先让本地任务分支与远端任务分支完全一致，才能合入目标分支。
- 合入候选从最新远端目标分支创建，只合入当前任务提交一次，不会先把目标分支合回任务分支，也不会自动改写任务分支历史。
- 最终交付前若目标分支已经前进，旧候选会被废弃并从最新目标提交安全重建。没有冲突草稿且重建后无冲突时会继续交付。
- 已有冲突草稿时，只有冲突内容保持一致才会恢复草稿，并要求重新确认；冲突内容发生变化时不会自动套用旧草稿。
- 纯本地仓库仍可在本地完成提交和目标分支合入。

## 如何升级

0.2.10 正式公开并完成制品回验后，可通过 Homebrew 手动升级：

```bash
brew upgrade --cask imchenway/tap/zeus
```

也可以在正式公开后下载版本化安装包 `Zeus-0.2.10-arm64.dmg`。退出正在运行的 Zeus 后打开 DMG，并用新版本覆盖旧版本。

Homebrew 和版本化 DMG 均为手动升级方式，本版本不声明应用内自动安装可用。

## 系统要求与已知限制

- 支持 Apple Silicon Mac，要求 macOS 13 或更高版本。
- Zeus 不附带 Codex；使用 Codex 模型仍依赖本机安装且兼容的 Codex CLI。
- 远端模式要求网络和 Git 凭据可用。远端刷新失败时，创建任务工作区、推送或目标合入会被阻止，不会退回缓存的远端分支记录。
- 两个分支真实修改同一段代码时仍可能产生冲突，需要人工判断；目标分支持续更新时，合入候选可能多次重建并要求重新确认冲突。
- 从旧数据目录升级且首次迁移未成功的用户仍可能看到空白项目列表。若历史数据位于 `~/Library/Application Support/@zeus/desktop`、当前 `~/.zeus` 为空，请先退出 Zeus 并备份两个目录；完整恢复需要同时保留附件、会话文件和命令脚本，不能只替换数据库文件。
- 0.2.10 正式制品的签名与公证状态将在制品生成后按发布清单核对；完成前不作 Apple 认证分发声明。

## 发布验证

- 草稿通过后，将把根包和桌面包版本从 0.2.9 写入 0.2.10，并以同一干净候选提交执行完整发布门禁。
- 门禁将检查冲突残留、空白与格式、ESLint、TypeScript、生产构建、验收矩阵和 AI CLI 适配，并生成正式 macOS 应用、`Zeus-0.2.10-arm64.dmg`、发布清单及 Homebrew Cask。
- 公开前将使用独立身份的隔离测试应用回验列标题换位、列宽调整、布局保存、任务类型胶囊，以及远端来源刷新、未提交内容隔离、任务分支一致性门禁、目标推进后的候选重建和冲突草稿确认。
- 正式生产制品将核对应用身份、包体健康和 DMG 完整性，并核对发布清单中的版本、架构、文件大小、SHA-256、签名及公证状态。
- 只有候选门禁和主分支 CI 通过后，才会创建不可变标签 `v0.2.10`、触发 Release Workflow、生成 GitHub Release 并同步 Homebrew Tap。
- 公开流程完成后，还将重新下载 `Zeus-0.2.10-arm64.dmg` 和发布清单，复验 DMG，并对账 GitHub Release 正文与资产、发布清单以及 Homebrew Cask 的版本、架构和摘要。
