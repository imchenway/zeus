# Zeus 0.2.11 更新内容

## 历史任务附件恢复可用

- 从旧数据目录迁移后，历史任务中仍指向旧位置的附件，可在“推送到新会话”时重新识别当前托管目录中的有效副本。
- Zeus 启动时会自动修复可验证的历史附件引用；修复不会改动任务内容及其业务更新时间，也不会删除或改写旧目录。
- 推送前会再次解析历史引用，因此迁移尚未写回或后来导入的旧任务也可使用当前托管副本。
- 只有资源名称、类型、大小和现有副本内容等信息能够安全对应时才会恢复。当前副本缺失或不一致时仍会阻止创建会话，并提示重新添加附件。

## 如何升级

0.2.11 正式公开并完成制品回验后，可通过 Homebrew 手动升级：

```bash
brew upgrade --cask imchenway/tap/zeus
```

也可以在正式公开后下载版本化安装包 `Zeus-0.2.11-arm64.dmg`。退出正在运行的 Zeus 后打开 DMG，并用新版本覆盖旧版本。

Homebrew 和版本化 DMG 均为手动升级方式，本版本不声明应用内自动安装可用。

## 系统要求与已知限制

- 支持 Apple Silicon Mac，要求 macOS 13 或更高版本。
- Zeus 不附带 Codex；使用 Codex 模型仍依赖本机安装且兼容的 Codex CLI。
- 自动恢复要求附件在当前 Zeus 托管目录中存在可验证副本。资源缺失、类型或大小不符、内容不一致以及符号链接等不受信资源不会被自动恢复。
- 首次启动可能需要读取历史附件以完成一致性检查；旧附件目录会保持原样，不会自动清理。
- 本次修复只处理历史任务的附件引用。如果旧数据没有完整迁移到当前数据目录，仅升级应用不能替代项目、附件、会话文件和命令脚本的完整恢复。
- 当前证据中的隔离测试包使用 ad-hoc 签名且未经 Apple 公证；0.2.11 正式制品的签名与公证状态将在制品生成后按发布清单核对。

## 发布验证

- 草稿通过后，将把根包和桌面包版本从 0.2.10 写入 0.2.11，并将已审阅的 Release notes 写入候选提交。
- 同一干净候选提交将执行冲突残留、空白与格式、ESLint、TypeScript、生产构建、验收矩阵和 AI CLI 适配检查，并生成正式 macOS 应用、`Zeus-0.2.11-arm64.dmg`、发布清单及 Homebrew Cask。
- 公开前将使用隔离应用和正式数据库副本回验历史附件恢复：确认有效引用迁移到当前托管目录、任务业务更新时间不变，并实际从历史任务向新会话推送附件。
- 还将使用缺少或不一致附件副本的隔离场景，确认 Zeus 不改写原引用、不会绕过受信目录校验，并继续阻止创建会话。
- 正式候选制品将核对应用身份、包体健康、DMG 完整性，以及发布清单中的版本、架构、文件大小、SHA-256、签名和公证状态。
- 只有本地发布门禁和候选提交的主分支 CI 通过后，才会创建不可变标签 `v0.2.11`、触发 Release Workflow、生成 GitHub Release 并同步 Homebrew Tap。
- 公开流程完成后，还将重新下载 `Zeus-0.2.11-arm64.dmg` 和发布清单，复验 DMG，并对账 GitHub Release 正文与资产、发布清单以及 Homebrew Cask 的版本、架构和摘要。
