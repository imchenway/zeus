# Zeus 0.2.25 更新内容

## 会话体验改进

- **新增会话右上角“环境”快捷卡片**：在会话标题右侧新增一个紧凑入口。你可以在卡片中直接查看当前会话的执行目录、Git 分支、工作区变更统计、待提交或待推送内容，以及当前会话的结构化来源（如附件）。卡片中的“变更”“提交或推送”和“比较分支”会直接进入既有的 Git 审查或代码交付流程，不会绕过原有安全门禁。
- **项目对话现在也可以手动归档**：此前只有任务会话可以归档，导致部分项目对话无法收纳。现在项目对话与任务会话统一支持归档，归档后可以在设置的“已归档会话”中查看，并显示“项目对话”标记。正在运行、排队或等待授权的会话仍不能归档，避免中断执行。
- **终态任务归档会话支持只读查看与一键重开**：当任务已完成或已取消时，其关联会话（包括已归档会话）依然可以打开并完整阅读历史记录，但默认隐藏输入框，不能编辑或重试。你可以在会话中点击“重新打开任务并继续”，此时只会重新打开当前选中的会话，任务会回到默认状态，其他历史会话保持归档。
- **文件编辑审批卡片重做**：当 Zeus 请求编辑文件时，审批界面会明确列出待编辑的文件路径（最多显示 4 个，更多文件会折叠），并给出“运行命令”“编辑文件”等清晰标题。权限模式会显示在右上角，“允许所有编辑”的说明也调整为更准确的范围提示，避免误以为会对所有文件免审。
- **命令日志自动跟随最新输出**：命令中心打开执行记录时，终端日志会直接定位到最新内容；如果命令还在运行，日志会持续自动滚动。当你主动上滚查看历史日志时，跟随会暂停，回到接近底部时再恢复。

## 稳定性与问题修复

- **修复会话输入框漂移**：点击“停止”后恢复输入框不再覆盖历史消息或跳到页面顶部，普通输入框与恢复输入框会保持在同一个底部位置。
- **修复侧边栏转圈状态误判**：项目没有进行中的会话时，侧边栏“会话”入口不再误显示转圈动画。之前历史会话的 `starting` 状态会被当作当前运行事实，现已改为综合权威运行状态。
- **修复发送消息后出现两条**：会话初始化时活动轮次的首次水合不再被误当成新轮次，避免重复显示。
- **修复引导消息后额外显示排队消息**：自动引导完成后，不再在下方多出一条排队记录。
- **修复无法查看会话中的文件**：会话中已添加的资源现在可以正常列出和打开，审批卡片也能从来源列表读取文件。
- **修复无法归档两个特定项目对话**：这些对话没有任务关联，之前归档入口被隐藏，现已恢复统一能力。
- **修复项目配置抽屉错误升级为全局错误**：工作区配置加载或保存失败时，错误只显示在对应抽屉内，不再出现在整个工作区顶部。
- **优化代码合并冲突处理**：冲突工作区中的自动合并按钮现在会显示可安全合并的数量，分析完成前不会误触发；手动编辑时不再强制重置滚动位置。
- **优化代码交付流程**：加载 Git 信息时有明确的加载与错误重试状态；“已合入”判定只基于当前任务 HEAD，同一分支的新提交可以再次交付。
- **优化图谱呈现**：当扫描结果只有 workspace package 节点时，系统架构图会回退到通用关系图而不是空的分层边界；图谱工具中的问答和历史列表改为按浮层宽度单列排版，不再被挤压成单字。
- **修复配置保存回退问题**：修改会话输入区配置后，即使不发送消息就切换会话，再切回也能保留刚才的选择，并会在后台同步到服务端。
- **其他**：任务优先级保存后不再一直显示“已保存”，改为仅显示冲突或失败状态；内置浏览器默认下载目录改为 Zeus 私有数据目录，普通设置操作不再触发 macOS 文件夹授权，减少不必要的权限申请；历史文件变更记录的不可用提示改为中文明确说明“缺少可安全撤销或重新应用的文件快照”。

## 如何升级

本次提供手动安装升级。

- **Homebrew**：如果之前通过 Tap 安装，可以运行：
  ```bash
  brew upgrade --cask imchenway/tap/zeus
  ```
- **DMG 手动安装**：下载并打开版本化磁盘映像 `Zeus-0.2.25-arm64.dmg`，将 Zeus 拖入“应用程序”文件夹。如果你已经在运行 Zeus，请先退出再替换。

当前正式制品仍为手动升级方式，尚未启用应用内自动安装；请留意后续发布通知。

## 系统要求与已知限制

- 最低系统版本为 macOS 13.0。
- 当前版本为 ad-hoc 签名且未公证的手动安装包，首次打开时可能需要右键“打开”以绕过 Gatekeeper。我们正在推进正式公证与自动更新。
- 快捷卡片中的“来源”列表只展示结构化资源（如附件），普通 URL 不会被收集。
- 已结束任务重新打开时，只会恢复当前选中的会话；如果需要精确选择，请先从任务详情打开目标归档会话，再执行重新打开。
- 归档会话的恢复能力依赖底层 Codex 线程状态；若线程已被外部删除，恢复后可能无法继续对话，仅保留本地记录。
