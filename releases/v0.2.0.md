# Zeus 0.2.0 更新内容

## 升级时继续原有会话

- 从上一版本手动升级时，仍在生成结果或执行操作的会话会继续由原宿主处理，不会被强制终止、自动重跑或重复执行已经完成的操作。
- 会话进入等待回答、等待选择或等待审批等可恢复阶段后，Zeus 会安全切换到新宿主，无需再等待固定的空闲时间，也无需让旧宿主一直存活。
- 切换后可以直接回答原来的问题或审批请求；Zeus 会在同一会话中继续处理，并重新校验涉及命令、文件或权限的操作。
- 交接过程中始终只保留一个数据写入者。新版本窗口、项目、任务和会话可以正常打开，上一版本已经支持的新建会话和任务推送等功能不再被整体禁用。

## 会话自动显示最新进展

- 打开或切换到已有会话时，会直接显示最新消息，不再停留在先前的历史位置。
- 发送消息后会立即回到底部，并持续显示随后新增的智能体内容。
- 主动向上滚动阅读历史时会暂停自动跟随，并保留“返回最新消息”入口；重新切换到该会话时会再次从最新消息开始。

## 已回答询问记录

- 回答普通询问后，问题和实际答案会作为一条默认折叠的记录保留在对话时间线中，可展开查看完整内容。
- 一次包含多个问题的询问只形成一条记录，展开后按原顺序显示全部问答。
- 已回答记录仅用于回看，不能再次提交，也不会伪装成一条新的普通用户消息。
- 敏感答案不会写入或回显到历史记录；相应位置只显示已经提交敏感回答。混合询问中的非敏感答案仍可正常回看。

## 如何升级

本候选尚未公开发布。正式发布并完成 Homebrew Tap 同步后，可手动运行：

```bash
brew upgrade --cask imchenway/tap/zeus
```

也可以从对应的 GitHub Release 下载版本化安装包 `Zeus-0.2.0-arm64.dmg`。退出正在运行的 Zeus 后打开 DMG，并用新版本覆盖旧版本。

Homebrew 和版本化 DMG 都是手动升级方式，本版本不声明应用内自动安装可用。升级前请确认本机已安装并登录兼容的 Codex CLI。

## 系统要求与已知限制

- 支持 Apple Silicon Mac，要求 macOS 13 或更高版本。
- Zeus 不附带 Codex；本机 Codex CLI 缺失、未登录或不支持所需能力时，相关 AI 执行不可用。
- 切回会话时始终从最新消息开始，不恢复上次离开前正在阅读的历史位置。
- 敏感回答只能确认已提交，不能从会话历史中查看或恢复原始内容。
- 升级时，仍在生成结果或执行操作的轮次会先由原宿主继续处理；到达可恢复阶段后才切换到新宿主。
- 截至本草稿生成时，当前公开制品仍为 ad-hoc 签名且未经过 Apple 公证，只能通过 Homebrew 或 DMG 手动升级。首次打开时，可能需要在“系统设置 → 隐私与安全性”中选择“仍要打开”。

## 发布验证

- 当前处于 Release notes 草稿生成阶段；候选提交中的根包和桌面包版本仍为 `0.1.21`，尚未执行 `0.2.0` 版本写入、发布提交、正式打包或公开发布。
- 草稿通过后，编排器将写入根包和桌面包的 `0.2.0` 版本及本发布正文，并创建与候选范围绑定的发布提交。
- 随后将执行统一发布门禁，包括 Git 冲突残留与空白错误检查、变更文件格式检查、lint、类型检查、生产构建、设计验收矩阵和 AI CLI 适配探针。
- 正式打包后将检查应用身份、可执行文件和包内结构，确认未夹带 Codex CLI，并核对 `Zeus-0.2.0-arm64.dmg` 的完整性、SHA-256、发布清单、签名与公证状态，以及 Homebrew Cask 的版本、架构和摘要一致性。
- 公开前将使用上一正式版宿主与当前候选应用回验：持续执行中的轮次不被中断或重跑；等待回答、选择或审批后安全切换到唯一新宿主；原会话可以继续作答；应用健康状态和数据库完整性正常。
- 同时将回验会话首次定位到最新消息、发送后自动跟随、主动上滚后暂停跟随、“返回最新消息”入口，以及单问题、多问题和包含敏感题目的已回答记录展示。
- 本地门禁完成后，编排器将推送 `main` 并等待同一发布提交的 CI 结果，再创建并推送 `v0.2.0` 标签并触发 Release Workflow。
- Workflow 完成后还将回下载公开 DMG 和发布清单，核对 GitHub Release 正文、资产元数据、文件摘要、DMG 完整性与 Homebrew Tap Cask；以上均为草稿通过后的发布动作。
