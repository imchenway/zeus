# Zeus 0.2.3 更新内容

## 会话输入始终可用

- 会话底部输入框在重新连接、后台刷新失败、等待结构化提问或审批、上一轮失败等状态下继续保持可见和可编辑。
- 结构化提问与审批卡片会显示在输入框上方；卡片仍负责对应交互，普通消息则按会话队列发送。
- 当原会话无法安全续接时，发送消息会自动建立承接会话，并沿用原任务中可验证的执行环境与工作区。用户不再需要先理解“恢复”状态或手动点击“新建会话”。
- 如果原任务执行现场无法验证，Zeus 会保留输入并说明失败原因，不会改用项目主目录发送。

## 更直观的冲突审阅

- 代码交付冲突页默认直接展示首个冲突块及必要上下文，不再从大文件第一行开始。
- 目标分支、合并结果和任务分支三栏会定位到同一冲突并联动滚动；可按冲突编号快速切换，也可按需展开完整文件。
- 大文件默认只渲染当前冲突附近的内容；完整文件改用轻量文本视图，减少首次展示和滚动时的界面负担。

## 更安全的冲突处理

- “合并简单冲突”改用三方差异组合，可合并发生在不同位置的插入、删除和修改，并在严格比较失败后尝试忽略空白差异。
- 同一位置的不同内容插入、相互重叠且结果不同的修改等歧义情况仍会保留，交由用户判断。
- 自动合并、人工选择和 AI 建议都只更新中间草稿，支持撤销；只有点击“保存结果并继续”才会写入文件。
- 新增独立的“AI 处理”入口，可使用该任务开发线已有的 Codex 或 Pi 模型，为当前文件剩余冲突逐块生成草稿和说明。AI 不会整份回写文件，也不会自动暂存、合入或推送。

## 如何升级

0.2.3 完成公开发布与制品核对后，可通过 Homebrew 手动升级：

```bash
brew upgrade --cask imchenway/tap/zeus
```

也可以从对应的 GitHub Release 下载版本化安装包 `Zeus-0.2.3-arm64.dmg`。退出正在运行的 Zeus 后打开 DMG，并用新版本覆盖旧版本。

Homebrew 和版本化 DMG 都是手动升级方式，本版本不声明应用内自动安装可用。

## 系统要求与已知限制

- 支持 Apple Silicon Mac，要求 macOS 13 或更高版本。
- Codex 执行仍要求本机安装、登录并保持兼容的 Codex CLI；Zeus 不会随应用安装 Codex CLI。
- AI 冲突草稿需要任务开发线中已有可用的 Codex 或 Pi 模型；没有可沿用的模型时，Zeus 会要求先选择模型，不会静默切换。
- 确定性合并和 AI 草稿都可能保留无法安全判断的冲突，最终结果仍需用户检查并保存。
- 本轮开发证据不包含真实桌面窗口中的完整点击、截图和大文件滚动手感复验；浏览器环境因缺少桌面桥接，不能替代该项验收。
- 0.2.3 的实际签名和公证状态将由正式发布清单记录。若正式制品仍未经过 Apple 公证，首次打开时可能需要在“系统设置 → 隐私与安全性”中选择“仍要打开”。

## 发布验证

- 本草稿通过后，发布编排器将把根包和桌面包版本写为 `0.2.3`，写入已审阅的 Release notes，并形成固定且干净的发布候选提交。
- 公开前将执行版本与正文一致性检查、冲突和空白检查、格式检查、lint、类型检查、生产构建、验收矩阵、AI CLI 适配探针及正式 macOS 打包。
- 功能回验将覆盖输入框在连接、结构化交互和恢复场景中的可用性，任务执行现场继承，确定性冲突组合及歧义保留，AI 只读草稿链路，以及真实桌面窗口中的冲突定位、编辑和大文件滚动。
- 发布门禁还将检查应用包结构与可执行文件、严格 codesign、DMG 完整性，以及发布清单、DMG 摘要和 Homebrew Cask 的版本与架构一致性；签名和公证状态以生成的正式清单为准。
- 本地门禁通过后，编排器才会推送 `main` 并等待对应 CI 成功，然后创建不可变的 `v0.2.3` 标签、GitHub Release，并同步 Homebrew Tap。
- 公开后还将重新下载 DMG 和发布清单，复核文件大小、SHA-256、`hdiutil verify`、Release 资产元数据、Release notes 与 Homebrew Cask；这些步骤完成前不视为发布结束。
