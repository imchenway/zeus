# Zeus 0.2.4 更新内容

## 更直接的项目工作方式

- 项目设置不再要求发现、勾选和保存 Git 仓库清单；项目的真实目录就是默认工作目录，设置中仅保留“共享可写目录”。
- 推送任务到新会话时，可以选择“直接使用项目目录”或“Worktree”。
- 直接目录模式不要求 Git，也不会创建分支或隔离目录，适合非 Git 项目或希望沿用当前现场的任务。
- Worktree 模式会在推送时自动扫描项目中的 Git 仓库，并分别创建任务分支和隔离目录。来源分支默认使用各仓库当前检出的本地分支，也可以在推送前逐仓调整；仓库处于 detached 状态时必须手动选择本地分支。
- 新项目首次推送时，发现 Git 仓库会默认使用 Worktree，否则默认使用项目目录；手动切换后，Zeus 会按项目记住选择。
- 直接目录中已有可写会话时，启动另一条可写会话前会明确提示并发修改可能互相覆盖，并要求确认。

## 多仓项目与共享目录

- 父仓库、子仓库和其他嵌套 Git 仓库可以作为独立工作区创建分支、审阅和交付，不再因为路径互相包含而要求用户取舍。
- 父仓库的变更审阅和提交会排除内部的独立子仓库，避免把子仓库内容误算进父仓库成果；任务目录回收时会先处理子仓库，再处理父仓库。
- 共享可写目录会在 Worktree 中直接引用项目里的真实目录，适合保存跨任务持续使用的文档和项目记忆；内容不会被复制，也不会随任务目录回收。

## 后续消息状态更清楚

- 尚未发送给模型的后续消息改为显示在输入区附近的紧凑列表，不再混入对话记录并伪装成已经发送的聊天气泡。
- 列表会说明真实等待原因和后续动作，例如等待当前回复结束、等待完成选择或审批、等待其他会话释放名额，或者因中断、连接和恢复状态而暂停。
- 等待条件解除后，后续消息会按顺序自动发送；需要人工恢复或确认的情况会显示对应操作。
- 后续消息仍可编辑、删除和调整顺序。当前回复执行期间，可使用“引导”把消息补充给当前回复，不会中断执行或另开一轮。
- 存在选择或审批时，待处理交互会显示在后续消息列表上方，使发送条件与界面位置保持一致。

## 如何升级

0.2.4 完成公开发布与制品核对后，可通过 Homebrew 手动升级：

```bash
brew upgrade --cask imchenway/tap/zeus
```

也可以从对应的 GitHub Release 下载版本化安装包 `Zeus-0.2.4-arm64.dmg`。退出正在运行的 Zeus 后打开 DMG，并用新版本覆盖旧版本。

Homebrew 和版本化 DMG 都是手动升级方式，本版本不声明应用内自动安装可用。

## 系统要求与已知限制

- 支持 Apple Silicon Mac，要求 macOS 13 或更高版本。
- Codex 执行仍要求本机安装、登录并保持兼容的 Codex CLI；Zeus 不会随应用安装 Codex CLI。
- 直接目录模式会直接读写真实项目，没有分支或 Worktree 隔离。即使确认并发继续，多条可写会话仍可能覆盖彼此的修改，变更归因和撤销能力也会相应降低。
- Worktree 模式要求项目扫描范围内至少存在一个 Git 仓库；Zeus 不会代替用户初始化仓库。自动发现最多扫描 6 层目录，并跳过常见依赖、缓存和构建目录。
- 共享可写目录不受 Worktree 隔离，也不会随任务回滚；多个会话同时写入时仍需自行协调。
- 嵌套仓库分别审阅、提交和交付，Zeus 不会自动替用户联动父子仓库的提交或推送。
- 等待并发名额时，当前界面统一说明为“等待其他会话完成”，尚不区分项目名额与全局名额。
- 当前公开安装包采用 ad-hoc 签名且未经过 Apple 公证。0.2.4 正式制品的实际状态将在发布门禁后写入发布清单；如果仍未公证，首次打开时可能需要在“系统设置 → 隐私与安全性”中选择“仍要打开”。

## 发布验证

- 本草稿通过后，发布编排器将把根包和桌面包版本写为 `0.2.4`，写入已审阅的 Release notes，并形成固定且干净的发布候选提交。
- 公开前将执行版本与正文一致性检查、冲突和空白检查、格式检查、lint、类型检查、生产构建、验收矩阵、AI CLI 适配探针及正式 macOS 打包。
- 功能回验将覆盖直接目录与 Worktree 的首次默认值和项目记忆、非 Git 项目、仓库自动发现、来源分支选择、并发写入确认、嵌套仓库隔离、共享目录引用及回收顺序。
- 会话回验将覆盖当前回复、选择、审批、并发名额、连接中断和恢复等状态下的等待说明，以及自动发送、引导、编辑、删除和排序操作。
- 发布门禁还将检查应用包结构与可执行文件、严格 codesign、DMG 完整性，以及发布清单、DMG 摘要和 Homebrew Cask 的版本与架构一致性；签名和公证状态以生成的正式清单为准。
- 本地门禁通过后，编排器才会推送 `main` 并等待对应 CI 成功，然后创建不可变的 `v0.2.4` 标签、GitHub Release，并同步 Homebrew Tap。
- 公开后还将重新下载 DMG 和发布清单，复核文件大小、SHA-256、`hdiutil verify`、Release 资产元数据、Release notes 与 Homebrew Cask；这些步骤完成前不视为发布结束。
