# Zeus 0.2.6 更新内容

## 推送仓库列表更准确

- 在 Worktree 模式下打开“推送到新会话”时，Zeus 不再把 `.tmp` 中的发布隔离副本或临时 Git 仓库列为项目仓库，避免要求用户为这些内部目录选择来源分支和新分支。
- 项目中的真实嵌套业务仓库仍会被分别发现，多仓项目的推送流程不受影响。

## 如何升级

0.2.6 完成发布门禁、公开发布和资产对账后，可通过 Homebrew 手动升级：

```bash
brew upgrade --cask imchenway/tap/zeus
```

也可以届时从 0.2.6 对应的 GitHub Release 下载版本化安装包 `Zeus-0.2.6-arm64.dmg`。退出正在运行的 Zeus 后打开 DMG，并用新版本覆盖旧版本。

Homebrew 和版本化 DMG 均为手动升级方式，本版本不声明应用内自动安装可用。

## 系统要求与已知限制

- 支持 Apple Silicon Mac，要求 macOS 13 或更高版本。
- Codex 执行仍要求本机安装、登录并保持兼容的 Codex CLI；Zeus 不会随应用安装 Codex CLI。
- `.tmp` 被统一视为项目内部的临时目录。用户主动存放在该目录中的业务仓库不会出现在推送仓库列表中。
- 当前公开安装包仍为 ad-hoc 签名且未经过 Apple 公证。0.2.6 正式制品的签名和公证状态将以发布门禁生成的清单为准；如果仍未公证，首次打开时可能需要在“系统设置 → 隐私与安全性”中选择“仍要打开”。

## 发布验证

- 本草稿通过后，发布编排器将把根包和桌面包版本写为 `0.2.6`，写入已审阅的 Release notes，并形成固定且干净的发布候选提交。
- 公开前将执行版本与正文一致性检查、冲突和空白检查、格式检查、lint、类型检查、生产构建、验收矩阵、AI CLI 适配探针及正式 macOS 打包。
- 功能回验将确认真实项目中的 `.tmp` 内部仓库不会进入推送列表，同时确认根仓库和真实嵌套业务仓库仍能正常发现；还将通过桌面推送弹窗检查最终用户可见结果。
- 制品门禁将检查应用包结构与可执行文件、严格 codesign、DMG 完整性，以及发布清单、DMG 摘要和 Homebrew Cask 的版本与架构一致性；签名和公证状态以正式清单为准。
- 本地门禁通过后，编排器才会推送 `main` 并等待对应 CI 成功，然后创建不可变的 `v0.2.6` 标签，由发布工作流创建 GitHub Release 并同步 Homebrew Tap。
- 公开后还将重新下载 DMG 和发布清单，复核文件大小、SHA-256、DMG 完整性、Release 资产元数据、Release notes 与 Homebrew Cask；这些步骤完成前不视为发布结束。
