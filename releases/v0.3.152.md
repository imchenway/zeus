# Zeus 0.3.152 更新内容

## 数字团队：从研发闭环扩展为通用协作

“数字团队”现在既可以是普通协作，也可以是研发流程：

- 默认按现有成员建立普通协作流程，从一位员工负责安排、汇总，或直接完成工作；即使项目里还没有配置成员，也可以先搭好流程，之后再指定员工。
- 新增“研发预设”，需要时再一键装配包含负责人规划、人工批准、并行开发、候选集成、核对成果与最终验收的完整研发流程。
- 节点职责说明统一改为“负责人规划 / 员工执行 / 核对成果 / 成果汇总”，不再默认所有团队都必须是 CTO 研发结构。
- 每个员工节点可以单独设置本次工作的模型、目标与技能等配置，不必再回到项目设置里逐个员工调整。
- 只有流程真正包含代码写入或代码集成时，开始协作前才会要求确认代码基线和授权范围；纯只读协作不再出现这层确认。
- 新增节点默认接到流程末尾，仍可手动改成并行；开始节点和结束节点由系统维护，不能误删。
- 人工确认会展示本步骤真正收到的上游成果；涉及代码时才额外展示当前候选版本。
- 任务里的新工作安排统一收敛到数字团队入口，旧配方和未启动的安排会导入为模板，已有运行记录保持原样。

## 任务状态更新与列表反馈

- 任务状态改为“先显示你的最后一次选择”：选择新状态后下拉框立即显示目标值并带保存提示，确认后回到服务器真实状态，失败会自动回滚。
- 保存中的加载反馈按任务独立，不再因为一行正在保存而把整个下拉框置灰；快速连续切换不会丢失最后一次选择。
- 自动化目录与收件箱会按本次触发在同一会话内实际处理的项目展示，而不再只显示首个项目。

## 自动化：可以不带项目运行

- 自动化新增“不使用任何项目”选项；此时只在 Zeus 临时工作区运行，不会读取或修改你的任何项目，并可读取个人 Skill 与 Plugin。
- 使用“追加原会话”时必须选择该会话所属的唯一项目，无项目或多项目请改用“每次新建一个会话”。
- 项目列表里不再出现 Zeus 临时工作区这类技术目录。
- 已暂停的自动化可以直接“立即运行”，无需先恢复。

## Codex 管理与设置页细节

- “检测更新”只检查版本，不再自动安装；Zeus 管理的 Codex 需要点击明确的“安装 x.y.z”按钮才会更新，由你自己安装的 Codex 会明确提示用原安装方式更新。
- 后台只做版本检测，不再在后台静默安装 Codex。
- 更新确认弹窗、用量页面和终端设置页的错误提示改为就地显示，不再弹出全局错误对话框。
- 用量价格说明更严谨：只有当费用只覆盖部分请求时才标注“部分”，价格覆盖率按可计费 token 计算，不代表费用占比；缺失日期的费用不再伪装成“真实账单下限”。
- 会话里被全部拒绝的文件修改会保留在那一轮，仍可查看局部原因与详情。
- 修复了应用在 Dock 和窗口中丢失图标的问题，打包版本也会在启动时显式设置图标。
- 会话过程折叠逻辑调整：运行中保留实时进展，完成后把中途说明统一收在模型回复正文上方，完成态的轮次默认收起。

## 如何升级

Homebrew 用户：

```
brew upgrade --cask imchenway/tap/zeus
```

也可以前往 [GitHub Releases](https://github.com/imchenway/zeus/releases) 下载 `Zeus-0.3.152-arm64.dmg`，结束工作并退出 Zeus 后，把新版拖入“应用程序”完成替换。当前公开制品为临时签名、未公证，因此需要手动升级；自动安装在签名、公证、版本兼容和安装位置等条件满足时才会启用。

## 系统要求与已知限制

- 需要 macOS 13.0 或更高版本。
- 当前公开发布包为临时签名且未公证，只能按上面的方式手动升级安装。
- 识别到最新版并不代表所有会话功能都已完成兼容验收。
- 更新 Codex 后如需重新连接，请先在“设置 → 模型供应商”中点击“重新连接 Codex”；Zeus 不会自动降级或用旧数据覆盖对话。
- 对于你自行安装的 Codex，Zeus 只做检测，不会代为更新或修改。
