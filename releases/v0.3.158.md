# Zeus 0.3.158 更新内容

## 数字团队改为全局团队

数字团队不再绑定单个项目，团队模板改为全局保存。你可以为一个团队配置数字员工、分工与依赖关系，然后用它发起任务并开始协作。

- 团队编辑器在未选择模板时提供独立的创建入口，创建后从“添加成员”按需加入数字员工，不再默认预置占位角色或员工。
- 起草团队时不再强制先关联项目；只有创建运行、选择运行项目时才需要项目。
- 成员节点引用全局数字员工模板，不再在团队节点里直接编辑项目数字员工。此前保存在项目下的旧团队模板仍会作为“旧项目模板”列出并继续可用。
- 首次新建团队时不再自动以某位员工填充流程，流程内容需要你明确配置。

## 任务与团队入口衔接

从团队页可以直接发起任务：点击“创建任务”会复用现有的新建任务表单，任务创建成功后自动带着所选团队进入该任务。

- 任务详情的顶栏改为显示任务编码，方便在多处任务界面之间准确对应。
- 任务讨论区提示更新为“开始任务讨论”“输入 @ 邀请数字员工参与”。
- 任务工作管理页去掉了顶部的固定页签，沟通、工作、成果和运行记录仍可通过原有入口按目的进入。

## 数字员工新增与指派收敛

数字员工的来源更集中，避免误用内置模板：

- 在项目中添加数字员工时，只能从你已创建的数字员工中选择；内置模板只在全局新增流程中出现，不再作为项目添加来源。
- 任务指派与团队分工只提供你明确配置的项目员工；由内置模板生成的旧项目副本不再进入新指派候选，历史工作视图仍可展示它们。
- 当尚无可用数字员工时，界面会提示先在设置中创建数字员工。

## 过程展示、模型验证与网络设置

- 会话处理过程只保留外层“查看处理过程”入口，展开后阶段分组直接显示每条阶段的操作数量与明细，不再有第二层“查看 N 项操作”折叠。长内容的展开动画会约束在可见范围内，长过程展开后可从头连续阅读。
- 模型连接的“服务诊断”改为“验证真实请求”：使用第一个已启用模型发送一次最小真实请求，可能产生少量用量；该结果用于确认请求可送达，图片输入与工具调用能力仍需分别验证。
- 网络设置中的连接检查拆成浏览器链路与模型宿主链路两条独立结果，任一条先返回即可先看到结论，不再因另一条超时而长时间等待。显示的是本次宿主启动时实际生效的代理配置，便于区分已保存但待重启生效的改动。
- 独立费用窗口的费用明细超过 8 行时固定为 8 行高度并支持纵向滚动，短列表按内容收缩。

## 如何升级

Homebrew 用户：

```sh
brew upgrade --cask imchenway/tap/zeus
```

也可以手动升级：从发布页下载 `Zeus-0.3.158-arm64.dmg`，退出当前 Zeus 后打开安装，将 Zeus 替换到“应用程序”目录。

## 系统要求与已知限制

- 本次公开制品为非公证（ad-hoc 签名）版本，只能通过上述 Homebrew 或手动下载 DMG 的方式升级，应用内自动安装不可用。
- 最低系统版本为 macOS 13.0。
- 网络代理配置保存后需要待任务结束、完全退出并重新打开 Zeus 才会生效。

## 发布验证

Zeus 的公开 Release 只在固定候选提交通过以下检查后才会创建：

- 类型检查、Lint 与构建通过；
- 桌面应用打包产出 arm64 制品；
- 数字团队工作流行为验证与渲染器事件流验证通过。
