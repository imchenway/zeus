# Zeus 0.3.170 更新内容

## 数字员工与团队协作

- 引入跨项目复用的「全局数字员工」：在设置中创建一次，即可在多个项目中引用。项目端只保存明确设置的差异，未覆盖的配置会跟随全局员工更新。
- 项目可以单独填写「项目补充要求」，用于记录当前项目的开发标准、流程或业务要求，与员工通用提示词分开保存，互不覆盖。
- 历史项目员工可以明确绑定到一个已创建的全局员工，随时「恢复全局配置」，也可以为单个项目单独调整员工能力。
- 员工能力改为分别授权：读取已确认经验、修改代码、执行验证，以及提交、推送、合入、部署、完成任务等管理动作可逐项开关，实际执行仍受任务授权约束。
- 员工经验建议在 HTTP 成功但存在冲突时保持「待处理」状态，不会隐式覆盖现行经验，并会在界面提示冲突原因。
- 数字团队流程新增项目级流程：可把当前编辑图「设为项目流程」，独立于全局模板维护；也可以从其他项目复制流程，复制时需明确映射员工和项目状态，来源运行、授权、成果与经验不会一起复制。
- 团队员工节点支持设置工作职责（规划 / 执行 / 验收 / 交付汇总）、执行方式、工作要求；验收节点需要填写必须通过的验收命令；完成标准与状态设置收进高级区域，状态选择来自当前项目的真实状态目录。
- 数字团队可配置缺陷修复员工与最多自动修复轮次，并可选是否自动接纳本项目的稳定方法与领域经验。
- 校验问题现在以简短的正文加「定位」按钮展示，不再把整段错误当作按钮，长文案在窄窗口下可折行。

## 自动化

- 自动化动作统一到「自动化」页面：员工自动化可在同一页面配置，原项目页的自动化入口改为跳转提示，已有规则、执行记录和排程保留。
- 自动化支持三类执行动作：普通会话、员工工作、处理项目任务。员工类动作只从已创建的数字员工中选择。
- 「处理项目任务」支持指定已有任务、使用事件任务、领取任务池任务或创建新任务；指定已有任务时只能选择一个目标项目，并会读取该项目的真实任务目录。
- 运行结果按项目逐条展示接纳进度：已接纳 / 尚未接纳 / 接纳结果待核对 / 未执行工作，并显示跳过的原因。多项目运行可以逐份选择查看哪一次真实执行。
- 运行收件箱可以从实际执行引用打开对应的工作会话、任务与成果或流程页面；被阻塞或结果待核对的运行，在仍有未接纳项目时提供「继续剩余项目」，沿原运行身份继续，不重跑已接纳的工作。
- 旧规则若需要用户明确核对任务选择，会在列表和编辑表单中提示，需要重选任务方式后才能保存。

## 任务、粘贴与其它改进

- 任务父子关系不再在客户端限制三级层级：父任务候选只排除当前子树，循环和同项目约束由服务端统一校验；层级切换失败时仅对明确的循环错误给出针对性提示。
- 修复粘贴附件时同一图片被重复导入的问题，任务创建、任务详情和会话输入统一使用同一份剪贴板文件读取逻辑。
- 数字员工与团队配置在窄窗口下更稳定：头像选择使用固定尺寸缩略图，按钮按完整按钮换行，长文本可折行，高级设置折叠展示。
- 员工执行配置中的推理级别、处理速度、工作模式和 Skills 收进「高级设置」，摘要会提示是否处于规划模式或已选 Skill 数量。

## 如何升级

- Homebrew：

  ```bash
  brew upgrade --cask imchenway/tap/zeus
  ```

- 手动升级：下载并打开 `Zeus-0.3.170-arm64.dmg`，将 Zeus 拖入「应用程序」替换旧版本。

当前公开制品为 ad-hoc 签名、未公证，因此请使用上述手动方式升级，应用内暂不提供自动安装。

## 系统要求与已知限制

- 系统要求：macOS 13.0 或更高版本。
- 当前公开制品未公证，首次打开可能需要按系统提示在「系统设置」中允许，或使用右键「打开」。
- 自动化中的「继续剩余项目」仅在运行被阻塞或结果待核对、且仍有未接纳项目时出现，已完成接纳的目标不会被重跑。
- 旧项目员工若未绑定全局员工，需要手动选择全局身份；自动化中待核对的迁移规则也必须重选任务方式后才能保存。
- 从其他项目复制流程时，若来源与目标项目的状态或员工无法自动对应，需要逐项手动映射后才能复制。
