# Zeus 0.3.172 更新内容

## 数字员工统一为全局身份

数字员工现在统一维护。你可以在设置中创建和管理全局员工，不再需要先在某个项目里添加一份员工配置。

迁移会自动完成：升级后，原先只存在于某个项目的员工身份与提示词会自动成为可用的正式员工，项目补充要求、已开启或关闭的经验偏好，以及当时已有的项目经验都会保留，不需要你重新确认或重新配置。正在执行或已经启动的工作仍使用原来的配置与权限，不受影响。如果同一个全局员工在多个项目里有各自不同的身份或提示词，这些差异会分别保留为独立员工。

## 直接在任务中选择员工

在任务的员工选择入口即可指派任一个正式全局员工开始工作，不再要求先手动把员工「添加到项目」。读取可指派列表和预览不会改动项目数据；只有在你实际发起工作后，该员工才会自动出现在所属项目的员工列表中。

项目设置中的数字员工页面现在只用于调整当前项目的补充要求和经验（memory）偏好，不再承担添加员工或确认旧配置的职责。缺少可运行模型时，任务中的入口会直接引导你前往模型配置。

## 旧项目流程与自动化继续使用原执行人

员工身份升级时，引用旧项目执行人的项目流程模板和自动化规则会按项目保留原执行人，不改变共享模板、其他项目或已冻结的历史运行。

自动化方面：迁移后规则仍指向原项目员工；已经接纳的工作继续占用原来的位置并正常结算；尚未开始的部分需要重新运行一次，因为原授权已随身份迁移失效。遇到这类情况时运行会给出明确说明，不能直接恢复。

## 如何升级

Homebrew：

```bash
brew upgrade --cask imchenway/tap/zeus
```

手动升级：下载 `Zeus-0.3.172-arm64.dmg`，打开后把 Zeus 拖入「应用程序」以替换旧版本。

当前公开制品未经公证，请使用上面的手动方式升级，应用内自动更新暂不可用。

## 系统要求与已知限制

- 系统要求：macOS 13.0 或更高版本，Apple Silicon（arm64）。
- 升级后首次启动会自动执行员工身份迁移；请等待其完成后再继续指派工作。
- 迁移后，自动化中尚未开始的旧目标需要重新运行；已接纳的工作会继续完成。
- 升级会保留项目补充要求、经验偏好和历史工作记录，但旧的「项目专属身份与提示词」不再作为可确认项展示。
- 公开制品未经公证，首次打开可能需要在系统设置中允许，或使用右键「打开」。

## 发布验证

公开 Release 只在固定候选通过以下检查后创建：

- 依赖安装与工作区构建通过（lint、typecheck、build）。
- 桌面应用打包成功，产出 arm64 DMG 并校验其文件名与版本号。
- 数字员工、工作管理与团队流程的行为验证脚本全部通过，覆盖身份迁移、直接指派、重复提交回执与既有工作结算。
- 版本号在根包与桌面包中一致，且与目标标签对应。

只有以上条件全部满足，才会创建对应版本的公开 Release（含 DMG 与 Homebrew cask）。
