# Zeus 0.3.176 更新内容

## 数字团队：开始研发流程更直接

在任务中使用带代码执行流程的数字团队时，不再需要单独勾选确认框。点击「开始研发」即表示授权本次任务：在隔离工作区中修改代码、运行检查并本地提交；未提交的修改不会被带入，推送、合入目标分支和发布不在授权范围内。相关说明会直接显示在启动按钮附近。

点击开始时，Zeus 会先保存当前分工，再用实际保存的修订版本启动协作，因此保存期间的继续输入不会影响本次启动内容。创建任务与开始协作现在共用同一提交边界：失败或修订冲突时会直接停止，而不会用旧模板启动另一轮。

## 数字团队：旧默认研发流程自动补齐岗位

此前由界面生成的默认三人研发流程，打开时会自动按当前真实员工补齐岗位职责与说明，无需再手动点击「配置研发分工」。显式设为只读的流程和用户自定义内容不会被覆盖；补齐只发生在草稿中，仍然需要保存或点击开始才会生效。

## 数字团队：会话与运行绑定更准确

任务详情与独立会话现在只显示实际绑定该会话的团队运行。切换会话时不会再短暂显示其他会话或任务的团队进度；返工后也仍能从原会话查看对应流程。任务详情则继续查看该任务的最新运行。

## 如何升级

- Homebrew 用户执行：`brew upgrade --cask imchenway/tap/zeus`
- 也可以从下载页手动下载 `Zeus-0.3.176-arm64.dmg`，打开后将 Zeus 拖入「应用程序」完成升级（当前公开制品为 ad-hoc 签名、未公证，需手动安装，应用内自动更新不可用）。

## 系统要求与已知限制

- 支持 macOS 13.0 及以上版本，本次发布的安装包为 Apple Silicon（arm64）。
- 数字团队的代码执行仅限当前任务的隔离工作区，从已提交版本开始，不包含未提交修改。
- 不包含推送、合入目标分支或发布操作；这些仍需按原有发布流程处理。

## 发布验证

公开 Release 仅在固定候选提交通过下列门禁后创建：

- Linux 端执行 `pnpm verify:publish --checks-only` 静态检查通过。
- macOS 端完整构建源码并打包通过。
- 两者均通过后，才创建公开 Release，并同步 Homebrew Cask；同步要求 Cask 指向该版本。
- 已发布的版本可通过只读回验入口核对：`VERIFY_PUBLISHED_ONLY=1 RELEASE_VERSION=<版本> RELEASE_COMMIT=<完整候选提交> pnpm release:publish`。
