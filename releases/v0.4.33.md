# Zeus 0.4.33 更新内容

## 多仓库项目共享会话工作树

当项目里包含多个 Git 仓库时，新建会话现在可以为每个仓库分别指定来源分支和工作树分支名。工作位置栏会显示仓库选择器，切换仓库只改变当前正在查看和编辑的对象，各仓库的选择会随同一次请求一起保存。

- 首次进入时会为所有仓库填充默认的会话分支名，你可以逐个仓库调整。
- 切换来源分支后，其余仓库的配置保持不变。
- 发送前会检查每个仓库的来源分支是否仍然可用、分支名是否符合任务分支前缀，而不是只检查当前展开的仓库。
- 如果项目仓库发生增减，会话会保留仍然存在的仓库配置，并为新增仓库补上默认来源。

## 会话工作区按仓库独立交付

多仓库会话的代码交付、文件预览和 Git 操作改为按具体仓库识别，不再把整个会话工作目录当成单一仓库。这样在包含多个仓库的会话里查看改动、预览文件和提交时，作用对象都对应到正确的仓库。

- 会话摘要会列出会话环境中实际存在、且已核验归属于原项目的各个仓库。
- 仓库身份与会话和项目内相对位置绑定，只有属于当前会话工作目录的仓库才会被接受。
- 已建好的单仓会话工作树仍按原有方式恢复。

## 空仓库与首次提交前的分支

对于尚未产生首次提交的仓库，当前分支现在会作为可选的本地来源显示，便于直接据此创建会话工作树；仅处于已检出状态的其他分支仍会标记为占用。

## 如何升级

Homebrew 用户：

```bash
brew upgrade --cask imchenway/tap/zeus
```

macOS 用户也可以下载 `Zeus-0.4.33-arm64.dmg` 手动安装。

Windows 用户请按系统架构选择安装包：x64 使用 `Zeus-0.4.33-win32-x64.exe`，ARM64 使用 `Zeus-0.4.33-win32-arm64.exe`。安装前请先退出 Zeus，再运行安装程序完成升级。

当前公开制品以手动升级方式提供，不依赖应用内自动安装。

## 系统要求与已知限制

- macOS：最低系统版本为 13.0。签名与公证状态以对应平台实际发布的安装清单为准；若系统提示来源或安全检查，请按发布清单说明处理。
- Windows：请根据系统架构选择对应的 EXE 安装包；签名与安全提示状态以对应平台实际发布的安装清单为准。
- 多仓库工作树要求项目内每个参与会话的仓库都能读取到可用的来源分支；项目仓库在创建会话前发生变化时，需要刷新后为每个仓库重新确认来源。

## 发布验证

公开 Release 仅在固定候选版本通过发布门禁检查后才会创建，检查内容包括版本配置与候选范围一致性、类型检查、构建与桌面打包、安装制品生成以及发布清单核验。只有在上述检查全部通过后，才会创建对应版本的公开 Release。
