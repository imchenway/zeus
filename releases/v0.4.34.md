# Zeus 0.4.34 更新内容

## 代码交付文件操作与变更列表

Git 交付文件树现在提供统一的文件操作菜单，可通过右键或键盘在文件、目录、仓库节点上触发，范围随当前节点确定，不受提交勾选影响。可执行的操作包括：

- 查看差异、在新窗口查看差异、跳转到源码。
- 对未跟踪文件执行“加入版本控制”。
- 将已跟踪文件“移动到变更列表”，可选用已有列表或新建列表；变更列表只是本机的文件分组，不会改变文件内容或 Git 暂存状态，删除文件或回滚后文件会回到默认列表。
- “删除”会把所选普通文件移入系统废纸篓或回收站，不会递归删除目录或子仓库。
- “回滚”会恢复到 HEAD 并丢弃暂存与未暂存修改；已暂存的新文件会被移除，首次提交前仅取消暂存并保留文件；存在冲突或文件状态已变化时会提示刷新后重试。

文件菜单在项目 Git 工作台和任务合并窗口的交付文件树中保持一致，操作完成后会重新读取真实状态。

## 项目源码切换工作目录

项目源码页顶部新增工作目录选择器，用于在项目目录和项目内已登记的 Git 工作树之间切换。列表来自实际 Git 登记，并区分项目目录、额外工作树与游离 HEAD；支持按工作树、分支或目录搜索。切换目录不会创建或检出分支，也不会改写文件，当前编辑根目录会随选择更新。

## 新会话中的多仓库分支操作

新建对话的工作树设置里，分支操作范围从单一仓库扩展为可选择全部仓库、同名分支分组或单个仓库：

- 分支下拉只显示所选范围内各仓库共同拥有的本地分支，远程分支同样按交集提供。
- 来源分支与工作树分支名在范围内按各仓库分别保存；来源不一致时显示为“多个来源分支”，可统一选择，分支名可输入统一值。
- 多仓库的检出、新建分支、合并和刷新远程分支按顺序执行，某一仓库失败时会说明已完成和未执行的仓库数量，并停止后续操作。
- 若目标分支已在其他工作树检出，会阻止重复检出。

## 如何升级

本版本仍为手动升级。

- macOS（Homebrew）：

  ```sh
  brew upgrade --cask imchenway/tap/zeus
  ```

- macOS（DMG 手动升级）：下载并打开 `Zeus-0.4.34-arm64.dmg`，将 Zeus 拖入“应用程序”覆盖旧版本。
- Windows：按系统架构选择 `Zeus-0.4.34-win32-x64.exe` 或 `Zeus-0.4.34-win32-arm64.exe`，先退出 Zeus，再运行安装程序完成升级。

当前公开制品为 ad-hoc、未公证构建，应用内自动安装不可用，请按上述方式手动升级；系统安全提示以各平台实际发布清单为准。

## 系统要求与已知限制

- macOS：最低系统版本为 13.0，提供 arm64 DMG。
- Windows：提供 x64 与 arm64 两种 EXE，请选择与系统架构匹配的安装包。
- 变更列表仅保存在本机当前项目范围内，不同工作目录的同名文件不会互相串组。
- 切换源码工作目录或执行回滚时，遇到冲突、文件状态变化或目录已不存在会提示刷新后重试。

## 发布验证

公开 Release 只有在固定候选先通过约定的发布门禁检查后才会创建。门禁包括：类型检查、构建、桌面打包，以及对应平台的签名与公证状态核对；任一检查未通过时不会创建公开 Release。
