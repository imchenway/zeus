# Zeus 0.4.50 更新内容

## 自动化部分派发异常更清晰，并支持恢复剩余项目

当一次自动化需要派发到多个项目时，如果部分项目未能接纳，或接纳结果需要核对，通知中心现在会把这次运行标记为受阻，只提醒尚未完成接纳的项目，并把已接纳的工作和冻结的任务身份保留在原运行中；已接纳的会话不会被误标为受阻。

对于这类可以继续的运行，通知卡片会提供“恢复剩余项目”按钮。恢复沿用原运行的触发身份和冻结目标，继续处理剩余项目，不会重新触发整次自动化，也不会重跑已经接纳的项目；若同一条自动化仍有其他在途运行，恢复会被阻止，以避免重叠副作用。

## 自动化规则与派发状态保持一致

当部分派发失败或接纳结果需要核对时，对应的自动化规则会随原运行一起暂停，并记录失败原因，避免有未完成的派发时放行后续运行。之后从规则列表把该自动化重新启用、或通过恢复完成剩余派发后，旧的派发异常会被清除，新的失败会重新产生独立的通知。

若运行因员工身份迁移导致原目标失效，恢复入口不会提供，需要重新运行尚未开始的部分。

## 如何升级

Homebrew 用户可执行：

```bash
brew upgrade --cask imchenway/tap/zeus
```

macOS 也可以手动升级：下载 `Zeus-0.4.50-arm64.dmg`，打开后将 Zeus 拖入「应用程序」，覆盖旧版本。当前公开制品仍为 ad-hoc、未公证的手动升级方式，请勿依赖应用内自动安装。

Windows 请按系统架构选择安装包，退出 Zeus 后再安装：

- x64 系统：`Zeus-0.4.50-win32-x64.exe`
- ARM64 系统：`Zeus-0.4.50-win32-arm64.exe`

## 系统要求与已知限制

- macOS：最低系统版本为 13.0；签名与公证状态、以及系统首次打开时的提示，以对应平台实际发布清单为准。
- Windows：按系统架构选择对应 EXE 安装包；安装前需退出 Zeus。
- 当前公开制品为 ad-hoc、未公证，仅支持手动升级，应用内自动安装不可用。
- 恢复仅针对存在明确剩余目标的部分派发；员工身份已迁移的情况需要重新运行尚未开始的部分，且同一自动化仍有其他在途运行时无法恢复。
