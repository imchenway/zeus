# Zeus 0.4.9 更新内容

## 输入建议更聚焦于用户意图

Zeus 在对话中生成或整理待发送消息时，会更直接地围绕你的目标和约束来组织提示词。生成内容以你作为发信人、AI 助手作为收信人的视角表达，保留原文引用与有效条件，并尽量沿用你的语言、语气和术语。当信息不足时，建议会围绕实际缺失的内容提出具体澄清，而不是重复已回答的问题或代为确认完成。

## 更细致的数据清理范围

Zeus 的生成数据清理支持更细的回收范围：除了整体回收工作树，还可以单独清理工作树中的依赖目录、构建输出和固定编译缓存，而不影响任务源码。执行清理时，如果路径仍与正在进行的任务、主项目或主仓关联，或目录内有未被忽略的内容，会保留该路径并在计划中说明原因。

## 更明确地放弃遗留源码

当确实需要放弃遗留工作树时，可以通过精确路径清单显式指定，而不必只依赖工作树是否干净。此时 Zeus 会核对正式任务状态、相关聚合环境以及嵌套的 Git 工作树登记，并在确认后一并回收；与未完成任务关联的路径不会被此方式删除。

## 如何升级

macOS（Homebrew）：

```bash
brew upgrade --cask imchenway/tap/zeus
```

macOS（DMG 手动升级）：下载 `Zeus-0.4.9-arm64.dmg`，打开后将 Zeus 拖入“应用程序”覆盖旧版本。

Windows：根据系统架构选择 `Zeus-0.4.9-win32-x64.exe`（x64）或 `Zeus-0.4.9-win32-arm64.exe`（ARM64），先退出正在运行的 Zeus，再运行安装程序完成升级。

当前公开制品若仍为 ad-hoc 签名、未完成公证，请按上述手动方式升级，应用内自动安装可能不可用。

## 系统要求与已知限制

- macOS：最低系统版本为 13.0，使用 arm64 DMG。
- Windows：提供 x64 与 ARM64 两种安装包，请按系统架构选择。
- 签名与系统提示以各平台实际发布清单为准；未公证的 macOS 构建可能触发系统安全提示，需要手动确认。
- 数据清理仅在满足占用检查与路径白名单条件时执行；在线模式只处理当前明确支持的类别，其余清理仍需离线进行。

## 发布验证

公开 Release 只有在固定候选通过既定的发布门禁检查后才会创建。门禁以校验和与产物清单为契约：构建与打包产出的制品需与候选提交一致，macOS 与 Windows 的安装包需覆盖对应架构，签名和公证状态以各平台发布清单记录为准。未通过门禁的候选不会生成公开 Release。
