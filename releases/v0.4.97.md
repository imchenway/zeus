## Antigravity 原生交互与用量展示

- 当 Antigravity 会话请求工具授权时，审批卡会显示具体工具名、参数内容以及涉及的文件路径；读取文件的请求会单独标注为读取操作，与编辑文件区分。
- Antigravity 会话现在可以弹出原生提问卡（单选、多选、补充输入和密码输入），选项与自由输入会按原生字段回写。
- 审批答复会等到确认写入原生会话后才生效；如果送达失败，卡片会显示已失效，不会自动重放可能已执行的操作。
- 权限模式会按本轮要求切换并确认；如果 Antigravity 无法切到所需模式，会提示当前会话无法切换，而不是带着旧模式发送。
- 工具执行结果与轮次结束分开呈现：轮次结束时仍无结果的工具会标记为未知结果，后台工具在此后返回的最终结果可以补齐该条记录。
- 模型思考摘要会作为过程条目显示；工具与回复前后的正文分段保持不变。
- 用量面板会区分供应商实际上报的 Token 分类，未上报的分类显示“未上报”，不会当作零值；上下文占用与模型上下文上限按原生上报值展示。

## 会话与运行时稳定性

- 升级 Pi SDK 依赖，新轮次的启动改为先等待原生预检与持久接纳回执，再放行模型请求；预检失败或超时会按固定错误码结束，不会重复发送。
- 插话与追加输入只作用于仍在执行的目标轮次；会话空闲后再次收到的排队输入会明确提示目标轮次已结束。
- 预检失败的原因会在交给界面前移除已配置凭据等敏感内容。

## 合入目标分支与流程图源码切换

- Git 交付面板中的“合入分支”改为“合入目标分支”，目标分支选择与复制按钮重新排版，多仓库时选项带仓库名区分。
- 流程图在预览与源码之间切换时保持原有宽高与按钮位置，源码区域在图表位置内滚动，短图也保留可读的源码高度。

## 如何升级

Homebrew 用户可执行：

```bash
brew upgrade --cask imchenway/tap/zeus
```

macOS 手动升级：下载 `Zeus-0.4.97-arm64.dmg`，退出正在运行的 Zeus 后打开 DMG 并替换应用。

Windows 手动升级：按系统架构下载 `Zeus-0.4.97-win32-x64.exe`（x64）或 `Zeus-0.4.97-win32-arm64.exe`（ARM64），退出 Zeus 后运行安装程序。

当前制品按手动升级方式安装；在签名与公证状态以本次各平台实际发布清单为准之前，不应依赖应用内自动安装。

## 系统要求与已知限制

- macOS：要求 macOS 13.0 或更高版本，安装包为 arm64 DMG；系统安全提示与签名状态以 macOS 发布清单为准。
- Windows：提供 x64 与 ARM64 两种 EXE，请按系统架构选择；SmartScreen 等系统提示以 Windows 发布清单为准。
- Antigravity 用量按轮次上报：输入与输出缺失时会显示“未上报”而不是估算；若使用较早的 Antigravity CLI，部分交互卡（原生提问、Auto 审查）可能不可用。
- Antigravity 会话中，工具在轮次结束后才返回的结果只补齐原轮次的既有记录，不会改变已经结束的轮次状态。
- Git 合入目标分支选择依赖当前仓库可读的分支列表；分支列表不可用时选择器会被禁用。
